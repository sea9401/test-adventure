# 슬롭 UI 방지 기준

슬롭 UI는 어색하거나, 자리에 맞지 않거나, 목적 없이 붙었거나, 어디서 본 듯 획일적인 UI다. 원인은 AI를 썼다는 사실이 아니라 결과물을 맥락에 맞게 다듬지 않은 데 있다. 요소마다 "이게 없으면 플레이어가 무엇을 잃는가?"에 답할 수 있어야 하고, 답이 없으면 넣지 않는다.

이 게임의 기준 언어는 이미 있다. 새 스타일을 발명하지 말고 이어 쓴다.

| 필요 | 쓸 것 |
|---|---|
| 패널·카드·인셋 배경 | `src/components/ui/surfaces.ts`의 `SURFACE_CARD`/`SURFACE_INSET`/`SURFACE_ACCENT` (또는 `Card`, `Inset`) |
| 배경 이미지 위 반투명 헤더 | `SURFACE_FROSTED` / `HeaderPanel` (유일한 반투명 예외) |
| 화면 상단 제목 줄 | `SubViewHeader` |
| 뒤로 가기 | `BackButton` (인라인 자작 금지) |
| 버튼·선택지 | `Button`/`buttonClassName`, `ChoiceButton` |
| 탭 | `TabBar` |
| 빈 상태·오류·안내 | `EmptyState`, `LoadErrorBanner`, `StatusBanner` |
| 아이템 종류 라벨 | `ItemTypeChip` |
| 글꼴 | 기본 Geist(`font-sans`/`font-mono`). 새 글꼴 금지 |

가장 비슷한 기존 화면(`src/adventure/v2/*View.tsx` 등)을 먼저 찾아 구조·간격·클래스를 재사용한다.

## 10가지 단서와 적용 규칙

### 1. 아무 데나 들어간 그라데이션
- 그라데이션은 재질·빛·희귀도 연출에만 쓴다(프로필 꾸미기, 등급 광택 등). 버튼·카드·페이지 배경에 "밋밋해서" 넣지 않는다.
- 카드 위·옆의 얇은 강조 띠도 여러 색 그라데이션 대신 의미 색 한 가지로 쓴다(전투=로즈, 선택=인디고, 보상·재화=앰버). 전쟁 화면의 아군→분쟁→적 스펙트럼은 예외.
- 보라↔파랑·보라↔분홍 네온 그라데이션, 글자 그라데이션(`bg-clip-text text-transparent`)은 쓰지 않는다.
- 기존 코드에 그라데이션이 있다는 사실은 새 그라데이션의 근거가 아니다.

### 2. 의미 없이 뒤섞인 색
- 기존 의미를 따른다: 선택/탭 = 인디고, 강조 패널·재화·보상 = 앰버(`SURFACE_ACCENT`), 위험/실패 = 빨강, 성공/회복 = 초록, 스킬·문장·마법 = 바이올렛, 아이템 등급 = 등급 색.
- 항목 구분을 위해 카드마다 다른 색을 칠하지 않는다. 구분은 아이콘·이름·배치로 한다.
- 다크모드에서 `dark:bg-{색}-900/950` 같은 유색 면을 넓게 깔지 않는다(`darkSurfaceAudit.test.ts`가 잡는다). 다크는 중립 표면 + 색 테두리/글자. 작은 상태 배지(`px-1.5 py-0.5`)의 유색 면은 기존 관례라 허용. 선택된 선택지 카드의 `dark:bg-*-950`도 `ChoiceButton`과 같은 관례라 허용.
- 바이올렛은 스킬·문장 계열 의미로만 쓴다. 푸시아·핑크 네온은 코스메틱 외에는 쓰지 않는다.

### 3. 필요 없는 배지·깜박임
- 배지는 같은 화면 안에 실제로 다른 상태가 있을 때만 붙인다. 모든 행이 같은 값이면 정보가 아니다.
  - 좋은 예: 등급, 다른 장비와 구분되는 "장착", 새로 얻은 항목, 안 읽은 우편 수.
  - 나쁜 예: 기능명 옆 "NEW/BETA" 장식, 항상 켜진 "진행 중", 검증 안 하는 "인증됨".
- `animate-pulse`/`animate-ping`/`animate-bounce`, `infinite` 애니메이션은 지금 행동해야 할 때(보상 수령 가능, 보스 등장)만, 행동하면 사라지게. 로딩 스켈레톤의 pulse는 허용. `motion-reduce:` / `prefers-reduced-motion`을 존중한다.

### 4. 반복되는 알약·카드 모양
- 모든 라벨을 `rounded-full px-*` 알약으로 감싸지 않는다. 목록은 줄·구분선, 표는 표, 선택지는 `ChoiceButton`처럼 용도에 맞춘다. 아바타·점·진행 바의 `rounded-full`은 정상.
- 카드 안에 카드를 겹치지 않는다. 카드 안 하위 영역은 `SURFACE_INSET` 한 단계까지.

### 5. 이모지 남용
- 버튼·제목·메뉴·안내문에 픽토그램 이모지(✨🎉🔥🚀💰🎁 등)를 새로 넣지 않는다. 아이콘은 `public/images/` 아트나 기존 아이콘 컴포넌트를 쓴다.
- 기능 기호로 이미 쓰는 `✓ ✗ ★ ✕ ☰ ⚠`는 허용. 채팅 등 플레이어 입력은 예외.
- 요리 재료·물고기·길드 교역품처럼 데이터 카탈로그의 기존 이모지 아이콘 체계는 유지한다(오너 결정). 새 카탈로그를 만들 때는 이 체계를 따르되 UI 크롬에는 넣지 않는다.

### 6. 어긋난 정렬
- 아이콘·숫자는 글자와 맞춘다(`flex items-center` + 아이콘 크기 고정, `shrink-0`). 숫자 열은 `tabular-nums` + 오른쪽 정렬.
- 목록 행의 이름·수치·버튼이 행마다 어긋나지 않게 grid 열 폭을 고정하고, 긴 한국어 이름은 `truncate`/`min-w-0`.
- 긴 이름, 큰 숫자(1,000,000), 빈 상태, 모바일 폭(360px 전후)을 확인한다. 터치 대상은 40px 이상.

### 7. 상투적인 글꼴·기술 장식
- Inter·JetBrains Mono·Poppins 등 새 글꼴을 들이지 않는다.
- `//`, `>_`, `</>`, `[SYSTEM]` 같은 코드 장식을 게임 UI에 넣지 않는다.

### 8. 개발 대화에서 새어 나온 문구
- 작업 요청·설계 문서의 표현을 화면에 옮기지 않는다. 플레이어는 개발 경위를 알 필요가 없다.
  - 나쁜 예: "v2", "신규 20종 장비", "리워크된 ○○", "관리자 요청으로 추가", "새로워진 인벤토리", 내부 변수명(`cumLevel`, `spec`).
  - 좋은 예: "사냥에서만 얻을 수 있습니다"처럼 실제 규칙을 플레이어 말로.
- 매뉴얼·도움말은 간결하게, 자주 바뀌는 수치는 코드 상수를 import해 자동 반영한다.

### 9. 획일적인 글래스모피즘
- `bg-white/40`, `bg-zinc-900/70` 같은 반투명 패널, `backdrop-blur` + 흰 테두리 + 그림자 조합을 새로 만들지 않는다. 배경 그림이 텍스트 뒤로 비치면 안 된다.
- 반투명은 `SURFACE_FROSTED` 헤더와 모달 뒤 딤(scrim)처럼 기능적 이유가 있을 때만. 칩·배지, hover 색조, 이미지·캔버스 위 오버레이도 허용.
- 화면 전체를 어두운 테마로 고정한 화면(격자 던전 등)은 최상위 래퍼에 불투명 배경을 줘서 라이트 모드 페이지 배경 위에서도 글자가 읽히게 한다.
- 잠긴·비활성 카드에 컨테이너 전체 `opacity-*`를 걸지 않는다. 배경은 불투명하게 두고 글자·아이콘 색으로 표현한다. 버튼의 `disabled:opacity-*`는 허용.

### 10. 홍보 문구·과장
- 기능 화면을 랜딩 페이지처럼 쓰지 않는다. "강력한", "완벽한", "새로운 차원의", "한 단계 업그레이드", "지금 바로 경험하세요", "모험을 더욱 풍성하게" 금지.
- 화면 제목 아래 플레이버 부제를 붙이지 않는다. 부제는 제목만으로 모자란 기능 정보가 있을 때만.
- "환영합니다, OO님 ✨" 대신 바로 쓸 정보(현재 상태·남은 시간·받을 보상)를 보여준다.
- 버튼은 동사로 짧게("받기", "장착", "판매"), 설명은 숫자와 단위로. 플레이버 텍스트에 하이픈·마크다운을 쓰지 않는다.

## 작업 절차

1. **목적 먼저**: 이 화면에서 플레이어가 하려는 일 1~2개와 필요한 정보를 적는다. 요소마다 그 목적에 기여하는지 본다.
2. **기존 재사용**: 위 표의 공용 컴포넌트·토큰과 가장 비슷한 기존 화면을 찾는다.
3. **구현**: 새 색·그라데이션·애니메이션·배지·반투명을 넣을 때마다 위 규칙의 근거를 한 줄로 댈 수 있어야 한다.
4. **검수**:
   - `bash .claude/skills/anti-slop-ui/scan.sh` (기본: 커밋 전 변경분, 인자로 범위 지정 예: `HEAD~3`, `origin/main`). 결과는 후보일 뿐이니 하나씩 판단한다.
   - `npx vitest run src/components/ui/darkSurfaceAudit.test.ts src/components/ui/surfaces.test.ts`
   - 라이트/다크, 모바일/PC에서 최상위 래퍼와 중첩 카드 사이로 배경 이미지가 새지 않는지 확인한다.
5. **보고**: 무엇을 뺐는지(장식·배지·문구)도 짧게 적는다.

## 검수 체크리스트

- [ ] 패널·카드 배경은 `SURFACE_*` 토큰이고 불투명하다(프로스티드 헤더 제외)
- [ ] 모든 배지·태그가 같은 화면의 다른 상태와 구분되는 정보를 준다
- [ ] 색이 기존 의미(바이올렛=스킬·문장 등)를 따르고 다크모드에 유색 면을 넓게 깔지 않았다
- [ ] 그라데이션·blur·그림자에 재질 표현이나 기능적 이유가 있다
- [ ] 새 픽토그램 이모지·코드 장식·새 글꼴이 없다
- [ ] 문구에 "v2"·개발 경위·홍보성 수식어·플레이버 부제·인사말이 없다
- [ ] 아이콘·숫자·열 정렬이 모바일/PC 모두에서 맞다
- [ ] 상시 반복 애니메이션이 없고 reduced-motion을 존중한다
- [ ] 비슷한 기존 화면과 나란히 놓았을 때 같은 게임처럼 보인다
