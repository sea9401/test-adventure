# 웹 접근성 수동 점검표

자동 axe 검사는 기계적으로 판단할 수 있는 WCAG 규칙만 다룬다. 이 점검표는 실제
키보드·확대·스크린리더 사용 경험을 반복 확인하기 위한 기록이다. 모든 자동검사와
수동 항목을 통과해도 법률 준수 인증이나 완전한 접근성 적합성을 의미하지 않는다.

## 점검 환경

- [ ] 데스크톱 Chromium 최신 안정 버전
- [ ] Firefox 최신 안정 버전과 NVDA
- [ ] macOS/iOS Safari와 VoiceOver
- [ ] 라이트 모드와 다크 모드
- [ ] 운영과 같은 프로덕션 빌드

점검일, 브라우저·보조기술 버전, 점검자, 발견 이슈 링크를 결과 기록에 남긴다.

## 공통 키보드 조작

- [ ] 마우스 없이 Tab과 Shift+Tab으로 모든 조작 요소에 도달한다.
- [ ] 첫 Tab에서 "본문으로 바로가기"가 보이고, 실행하면 현재 본문으로 이동한다.
- [ ] 포커스 순서가 화면의 읽기 순서와 일치하며 숨겨진 요소로 이동하지 않는다.
- [ ] 모든 링크와 버튼을 Enter로, 버튼·체크박스·선택 항목을 Space로 실행한다.
- [ ] 메뉴와 팝오버를 열고 닫을 수 있으며 Escape 동작이 일관된다.
- [ ] 모달을 열면 내부로 포커스가 이동하고 Tab이 모달 안에서 순환한다.
- [ ] 모달을 닫으면 모달을 연 버튼이나 링크로 포커스가 돌아온다.
- [ ] 라이트·다크 모드 모두에서 포커스 표시가 배경과 명확히 구분된다.

## 화면 확대와 재배치

- [ ] 브라우저 200% 확대에서 정보나 기능이 사라지거나 겹치지 않는다.
- [ ] CSS 320px 너비에서 가로 스크롤 없이 핵심 기능을 사용할 수 있다.
- [ ] 긴 한국어 이름과 시스템 글자 크기 확대에서도 버튼 문구가 잘려 의미를 잃지 않는다.
- [ ] 고정 헤더와 플로팅 채팅 버튼이 포커스된 컨트롤이나 마지막 콘텐츠를 가리지 않는다.

## 이름·구조·상태

- [ ] 페이지마다 내용을 대표하는 하나의 `<h1>`과 하나의 핵심 `<main>`이 있다.
- [ ] 아이콘만 있는 버튼의 스크린리더 이름이 동작을 구체적으로 설명한다.
- [ ] 같은 이름의 버튼이 여러 개면 각 대상이나 결과를 구분할 수 있다.
- [ ] 입력 안내와 오류가 해당 입력에 연결되고 오류 발생 시 인지할 수 있다.
- [ ] 로딩, 저장 성공, 실패, 보상 수령 결과가 시각 효과에만 의존하지 않고 읽힌다.
- [ ] 탭·토글·펼침 메뉴의 선택 및 열림 상태가 보조기술에 전달된다.
- [ ] 장식 이미지와 아이콘은 숨겨지고, 정보성 이미지는 목적에 맞는 대체 텍스트가 있다.
- [ ] 색상만으로 성공·실패·희귀도·선택 상태를 구분하지 않는다.

## 동작과 시간

- [ ] 운영체제의 동작 줄이기 설정에서 비필수 전환·펄스·자동 슬라이드가 억제된다.
- [ ] 동작을 줄여도 전투 결과, 알림, 선택 상태 등 필수 정보가 남는다.
- [ ] 자동 갱신이나 제한 시간이 있는 기능은 남은 시간과 갱신 결과를 확인할 수 있다.
- [ ] 깜박임이나 빠른 색 변화가 광과민성 위험을 만들지 않는다.

## 1차 핵심 흐름

### 로그인과 캐릭터 생성

- [ ] 아이디·비밀번호 로그인 영역을 펼치고 입력·제출·오류 확인을 키보드로 완료한다.
- [ ] 캐릭터 이름, 외형, 운영정책 동의를 스크린리더로 이해하고 제출한다.
- [ ] 사용 가능 이름과 제출 오류가 발생한 위치에서 즉시 안내된다.

### 메인 화면

- [ ] 전역 메뉴, 캐릭터 요약, 오늘의 모험, 공지, 랭킹 순서가 이해 가능하다.
- [ ] 메인 메뉴의 현재 위치와 펼쳐진 하위 메뉴 상태를 읽을 수 있다.

### 사냥터와 전투

- [ ] 전투 메뉴에서 사냥터를 열고 지역과 층을 선택할 수 있다.
- [ ] 잠금·도전·입장 가능 상태가 색상 외 텍스트로도 전달된다.
- [ ] 최근 사냥 결과와 전투 기록을 순서대로 읽고 원래 화면으로 돌아올 수 있다.

### 거래소

- [ ] 경매·판매·시세·내 거래 탭의 이름과 선택 상태가 구분된다.
- [ ] 필터와 정렬을 키보드로 바꾸고 적용 상태를 확인할 수 있다.
- [ ] 빈 목록, 로딩, 거래 성공·실패 상태를 스크린리더로 확인할 수 있다.

### 알림과 우편

- [ ] 전체·알림·우편 탭의 선택 상태가 전달된다.
- [ ] 받은 우편과 보낸 우편을 구분하고 우편 상세를 열고 닫을 수 있다.
- [ ] 수령 가능 보상, 수령 결과, 오류를 읽을 수 있으며 포커스가 사라지지 않는다.

## 2차 확장 흐름

### 인벤토리와 스킬

- [ ] 장착 슬롯의 부위, 아이템 이름, 강화 수치, 세트 여부와 빈 상태를 구분해 읽을 수 있다.
- [ ] 아이템 수량, 장착·잠금·도감 등록 상태가 색상이나 아이콘에만 의존하지 않는다.
- [ ] 도감 등록, 상세 보기와 인벤토리 탭을 키보드로 실행하고 현재 위치를 확인할 수 있다.
- [ ] 스킬의 학습·장착·강화 가능 여부와 부족 조건을 읽을 수 있다.
- [ ] 스킬, 강화, 스킬 패턴 탭의 선택 상태와 이동 순서가 명확하다.
- [ ] 스킬 의식 대화상자를 열면 내부로 포커스가 이동하고, 닫으면 실행 요소로 돌아온다.

### 마을과 생활

- [ ] 마을의 시설 링크를 화면 순서대로 탐색하고 현재 목적지를 구분할 수 있다.
- [ ] 농장 구획의 작물, 성장 상태, 남은 시간, 실행 가능한 작업을 각각 읽을 수 있다.
- [ ] 농장 일괄 작업과 새로고침의 대상 및 성공·실패 결과가 라이브 안내로 전달된다.
- [ ] 생활 조합 작업장의 탭과 생활 의뢰 하위 메뉴의 선택 상태가 전달된다.
- [ ] 재료 선택, 빠른 수량, 직접 입력, 필요량과 보유량을 키보드로 변경하고 확인할 수 있다.
- [ ] 제작·납품·도구 승급 결과와 부족 조건을 색상 외 텍스트로 이해할 수 있다.

### 길드

- [ ] 무소속 상태에서 창단 조건, 길드 이름 입력, 길드 탐색과 가입 신청 상태를 읽을 수 있다.
- [ ] 길드 검색 결과와 빈 목록, 로딩, 신청 성공·실패가 발생한 문맥에서 안내된다.
- [ ] 가입 후 길드 정보, 길드원, 토벌전, 시설과 관리 탭은 후속 점검 대상으로 기록한다.

### 환경 설정

- [ ] 각 설정 컨트롤의 이름, 현재 값, 설명과 저장 결과가 서로 연결되어 읽힌다.
- [ ] 콘텐츠 알림 표시 토글의 켜짐·꺼짐 상태가 보조기술에 전달된다.
- [ ] 동작 줄이기와 화면 효과 설정을 변경하면 비필수 애니메이션만 억제되고 정보는 남는다.
- [ ] 새로고침하거나 다시 방문해도 저장된 설정값을 확인할 수 있다.

### 채팅

- [ ] 플로팅 채팅 버튼의 이름과 새 메시지 상태, 펼침 상태가 구분되어 읽힌다.
- [ ] 키보드로 채팅을 열면 내부 조작 요소로 포커스가 이동하고 닫으면 열기 버튼으로 돌아온다.
- [ ] 채팅방 목록, 방 선택, 뒤로가기, 방 추가와 닫기 버튼의 이름이 구체적이다.
- [ ] 메시지 입력, 전송, 금칙어·네트워크 오류와 전송 성공 상태를 발생 위치에서 확인할 수 있다.
- [ ] Escape와 모바일 뒤로가기 동작이 현재 상세 화면, 방 목록, 채팅 닫기 순으로 예측 가능하다.
- [ ] 모바일 전체 화면 채팅에서 Tab과 Shift+Tab 포커스가 배경 화면으로 빠져나가지 않는다.

### 확대·리플로우와 보조기술

- [ ] 인벤토리, 스킬, 마을, 농장, 생활 작업장, 길드, 환경 설정과 채팅을 200% 확대해 사용한다.
- [ ] 각 2차 화면을 CSS 320px 너비에서 확인하고 가로 스크롤이나 가려진 조작이 없는지 점검한다.
- [ ] Firefox와 NVDA에서 제목, 랜드마크, 탭, 상태와 한국어 레이블의 읽기 순서를 확인한다.
- [ ] Safari와 VoiceOver에서 같은 흐름의 탐색 순서와 한국어 레이블 명확성을 확인한다.

## 3차 상태·권한 흐름

### 데이터가 채워진 성장·생활·거래 화면

- [ ] 재료와 장비가 있는 인벤토리에서 탭, 보유 수량, 장비 상태와 실행 버튼을 순서대로 읽을 수 있다.
- [ ] 생활 작업장의 가공 재료와 수량을 키보드로 선택하고 필요량, 보유량, 대성공 확률과 결과를 확인할 수 있다.
- [ ] 거래소 판매 화면에서 품목, 보유 수량, 판매 수량과 시작 입찰가의 입력 이름을 구분할 수 있다.
- [ ] 등록 가능·불가 상태와 성공·실패 결과가 색상에만 의존하지 않고 현재 문맥에서 안내된다.

### 가입한 길드

- [ ] 길드 정보, 길드원, 토벌전, 시설, 관리 탭을 키보드로 이동하고 선택 상태를 확인할 수 있다.
- [ ] 길드 현황과 기여도, 길드원 온라인 상태와 최근 활동 시간이 읽기 순서대로 전달된다.
- [ ] 시설별 상태, 열기와 재료 기부 버튼의 대상을 구분하고 부족 조건을 읽을 수 있다.
- [ ] 관리 화면의 가입 신청, 직책과 길드 설정 구조를 이해하고 위험 작업의 확인·취소 절차를 완료할 수 있다.

### 관리자 도구

- [ ] 관리자 메뉴 검색과 그룹별 탐색에서 현재 탭, 탭 설명과 보기 전용 상태를 확인할 수 있다.
- [ ] 운영 홈, 유저 관리, 공지·우편, 신고 관리, 전체 통계와 관리자 기록의 제목과 랜드마크가 일관된다.
- [ ] 조회 조건, 표 머리글과 각 행의 입력 이름이 연결되며 같은 종류의 입력도 대상을 구분할 수 있다.
- [ ] 보기 전용 상태에서는 변경 작업이 실행되지 않고 그 이유가 화면과 보조기술에 전달된다.
- [ ] 편집 가능 상태에서 삭제·제재·발송 등 위험 작업은 대상과 영향을 알리는 확인 절차를 거치며 취소 후 포커스가 돌아온다.

### 확대·리플로우와 보조기술

- [ ] 3차 대상 화면을 200% 확대하고 CSS 320px 너비로 줄여 표, 입력, 탭과 주요 버튼이 가려지지 않는지 확인한다.
- [ ] Firefox와 NVDA에서 상태가 채워진 화면, 가입 길드와 관리자 표의 읽기 순서 및 한국어 입력 이름을 확인한다.
- [ ] macOS/iOS Safari와 VoiceOver에서 같은 흐름의 탭 선택, 상태 변화와 확인 대화상자 안내를 확인한다.

## 4차 실제 사용 조건

### 거래소와 생활 작업장

- [ ] 라이트·다크 모드의 실제 브라우저 200% 확대에서 재료 품목명, 판매 수량, 묶음 전체 시작 입찰가와 등록 버튼이 겹치거나 잘리지 않는다.
- [ ] CSS 320px 너비에서 거래소 판매 카드가 문서 전체 가로 스크롤을 만들지 않고, 각 품목의 수량·가격 입력 이름을 구분해 읽는다.
- [ ] 가격을 비운 채 등록하면 현재 판매 화면에서 오류가 즉시 안내되고 어떤 입력을 고쳐야 하는지 이해할 수 있다.
- [ ] 생활 재료를 1회 가공하면 완성 품목과 수량이 NVDA·VoiceOver의 상태 메시지로 한 번에 전달된다.
- [ ] 최대 가공 확인창을 열면 제목과 실행량을 먼저 이해할 수 있고, 취소·Escape·배경 닫기 후 원래 최대 가공 버튼으로 포커스가 돌아온다.

### 길드 시설과 공용 알림

- [ ] 라이트·다크 모드의 CSS 320px 너비에서 길드 시설별 재료 기부 진행도, 보유량, 남은 수량과 범위 입력이 문서 전체 가로 스크롤 없이 보인다.
- [ ] 각 재료의 기부 수량 범위 입력과 감소·증가 버튼 이름이 대상을 구분하며, 키보드 방향키로 값을 바꿀 수 있다.
- [ ] 기부 폼을 닫으면 원래 “재료 기부” 버튼으로 포커스가 돌아오고 실제 기부는 확인하지 않은 상태에서 실행되지 않는다.
- [ ] 미읽음 알림이 10개 이상일 때 `9+` 배지가 라이트·다크 배경에서 읽히고, 배지 숫자 없이도 알림 버튼 이름으로 전체 개수를 확인할 수 있다.

### 실제 보조기술 기록

- [ ] Firefox 최신 안정 버전과 NVDA에서 거래소 오류, 가공 결과, 최대 수량 대화상자, 길드 기부 슬라이더와 포커스 복귀를 순서대로 확인한다.
