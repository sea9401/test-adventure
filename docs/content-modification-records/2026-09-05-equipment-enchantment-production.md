# 2026-09-05 장비 마법부여 운영 활성화 기록

## 기록 상태

- 상태: `recorded`
- 의미: 게임 내용 변경을 저장소에 기록했으며, 공식 내용수정신고 필요 여부는 운영자가
  후속 판단한다.
- 주의: 이 문서는 내부 변경 이력이며 공식 내용수정신고 접수 증빙이 아니다.

## 원인과 활성화 기준

- 장비 마법부여 도메인·서버 API·전투 및 보상 효과·대장간 UI는 이미 `main`에 포함돼
  있었다.
- 운영 빌드 설정에 `NEXT_PUBLIC_V2_EQUIPMENT_LIBERATION`이 없어 기본값 `false`로
  빌드됐고, 대장간 메뉴가 숨겨지며 API가 `404 not_found`를 반환했다.
- 운영 빌드 설정에 `NEXT_PUBLIC_V2_EQUIPMENT_LIBERATION=true`를 명시하고 회귀
  테스트를 추가한 새 `main` 산출물로 활성화한다.

## 운영 반영 내용

- 6티어 이상 장비의 대장간 마법부여 메뉴와 작업대 노출
- 최초 마법부여 및 재마법부여 API 활성화
- 마법부여 단계·옵션 줄 수·옵션 효과의 전투 및 보상 계산 활성화
- 폭풍 개량 장비는 기존 정책대로 마법부여 대상에서 제외
- 신규 DB 마이그레이션 없음

## 검증 기록

- 운영 설정 및 마법부여 관련 Vitest: 39개 통과
- Next.js production 빌드 성공, 612개 페이지 생성
- 운영 빌드의 마법부여 API가 비활성 플래그의 `404 not_found` 분기를 통과하는 것을
  확인
- 최종 PR 및 `main` push CI 실행과 불변 산출물 SHA는 GitHub Actions 기록으로
  보존한다.

## 운영 영향과 롤백

- `NEXT_PUBLIC_` 빌드타임 플래그이므로 활성화와 롤백 모두 새 운영 산출물 배포가
  필요하다.
- 롤백은 `.env.production` 값을 `false`로 바꾸거나 제거한 새 `main` SHA를 CI로
  검증한 뒤 운영 배포한다.
- 운영 배포는 런타임 교체 직전에 점검 모드를 켜며, 별도 해제 요청 전에는 점검 모드를
  유지한다.

## 공식 신고 후속 기록

현재 공식 신고 접수 참조는 없다. 운영자가 신고 또는 재등급분류가 필요하다고 판단하면
접수번호, 제출일과 신고 기록 위치를 이 절에 추가한다.
