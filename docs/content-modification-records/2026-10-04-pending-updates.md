## 변경 내용

### 화면 구성 개편

1. 화면 머리의 규칙 설명을 ? 도움말로 옮기고, 화면 안 보기 전환·빈 상태 바로가기·메뉴 잠금
   표시를 공용 부품으로 통일한다. 주 버튼 색을 하나로 맞춘다.
2. 문장 화면을 능력치 합계, 장착 칸, 보유 문장 순서로 바꾸고 칸을 눌러 바로 장착하게 한다.
   전투 프리셋·스킬 패턴·인벤토리·아레나·협동 보스·모험가 협회·생활 조합 작업장 화면을 정리한다.
3. 트로피·꾸미기의 미획득 항목을 접고, 성장의 신전 직업 행을 펼침으로, 낚시 상점·위험 해역,
   치료소·은행 버튼을 정리한다. 개척 노드·던전·낚시 위험 해역에 잠금 이유를 표시한다.
4. 화면 안 스태미나 카드는 사냥터에만 두고, 상단 스태미나 창에 회복 속도와 최대치까지 남은
   시간을 표시한다. 홈의 빈 위젯을 숨기고 체크리스트를 3개씩 보여 준다.
5. 채팅 버튼을 아래로 스크롤하는 동안 숨기고(키보드 포커스 시 다시 표시) 크기를 줄인다.
6. PC(1024px 이상)에서 인벤토리·모험가 협회·사냥터·퀘스트·거래소 둘러보기를 2단으로 보여 준다.

### 전투 기록

7. 출혈·중독처럼 누적되는 지속 피해의 전투 로그에 현재 스택 수를 함께 표시한다
   (예: "출혈(8)로 2329 피해", #750). 단일 스택인 화상은 기존 문구를 유지한다.

### 스킬 화면

8. 스킬 학습·장착 화면의 보유 스킬 목록을 피해 유형(물리 공격·마법 공격·출혈·중독·연소)으로
   좁혀 볼 수 있게 하고, 스킬 상세 배지에 같은 유형을 표시한다(#751). 분류는 스킬 데이터에서
   자동 판별하며, 해당 피해를 강화하는 패시브도 포함한다. 매뉴얼 스킬 섹션에 한 줄 안내를 더한다.
9. 스킬 목록 필터 라벨 글씨를 12px로 맞추고 디자인 예산 기준(12px 미만 글씨)을 1201에서 1199로 낮춘다.
10. 거래소 둘러보기 검색창을 별도 컴포넌트(`MarketplaceSearchInput`)로 분리한다. 화면 구성 개편의
    PC 2단 적용으로 `V2MarketplaceView.tsx`가 모듈 크기 예산(1,950줄)을 넘어 분리했으며 동작은 같다.
11. E2E 로그인 단계가 2026-10-04 00:00(한국시간)부터 켜진 만 14세 이상 확인 화면을 먼저 통과하도록
    공용 도우미(`e2e/support/signIn.ts`)를 추가한다. 연령 확인 기능은 이미 운영 중이며(10월 3일 배포,
    날짜 기준 시행), 시행 시각 이후 main에서도 로그인 E2E 13건이 같은 이유로 실패하는 상태였다.
    WebKit은 HTTP E2E 서버에서 Secure 확인 쿠키를 거부하므로, 같은 확인 API를 직접 호출해 서버가
    발급한 값을 테스트 컨텍스트에만 복사한다(기기 세션 쿠키와 같은 처리). 테스트 코드만 바뀐다.
12. 화면 구성 개편 후 로그인 접근성 E2E에서 드러난 두 가지를 고친다. 사냥터 목록의 도전 가능 여부
    문구(주황·초록)를 흰 바탕 대비 4.5:1 이상인 700 색조로 올리고, 생활 조합 작업장 상단 메뉴가 탭으로
    바뀐 데 맞춰 E2E 선택자를 버튼에서 탭으로 바꾼다.

## 검증 및 운영 영향

- 전투 규칙, 스킬 수치, 드랍·보상, 경제 수치, 확률은 바꾸지 않는다. 전투 골든마스터는 지속 피해
  로그 문구 1줄만 바뀌었다(#750).
- 화면·문구·전투 로그 변경이 플레이어에게 보이므로 `technical-only`가 아닌 내부 기록 상태로 배포한다.
- 신규 DB 마이그레이션, 의존성, 환경 설정, 배포 설정 변경은 없다.
- 세 작업 사이에 겹치는 파일은 없었다. 통합 후 디자인 예산 검사가 #751의 11px 라벨 1개로 초과해
  9번으로, PR 정적 검사의 모듈 크기 예산이 거래소 화면 1,957줄로 초과해 10번으로 해소했다.
- 로컬에서 `tsc --noEmit`, 전체 lint(오류 0, 기존 경고 3), 정적 검사 전부, `next build`, 전체 단위
  테스트(11,432건 통과)를 확인했다. 전체 실행 중 부하로 시간 초과난 4건(버전 확인 2, 밸런스
  시뮬레이션 2)은 단독 재실행에서 통과했다.
- 배포 전 PR CI와 정확한 main SHA의 전체 CI 및 운영 빌드 산출물을 확인한다. 기존 배포 워크플로가
  산출물 검증·전송 후 런타임 교체 직전에 점검 모드를 켜고, 배포 검증이 성공하면 이번 사용자 지시에
  따라 점검을 해제한다.
- 공식 신고 필요 여부와 제출 절차는 운영자의 후속 판단이며 현재 공식 접수번호는 없다.
