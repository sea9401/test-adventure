# 2026-11-16 장비 선택 잠금·유니크 전부 잠금(건의 #859)

- 상태: `recorded`
- 원본 브랜치: `feat/equipment-bulk-lock-859`.
- 사용자 요청: 건의 #859(유니크 일괄 잠금, 선택 아이템 일괄 잠금)를 반영한다(2026-11-16 오너 지시).
- 설계 문서와 구현 계획은 따로 두지 않았다(기존 선택 판매·비교 선택 흐름 안의 추가).
- 이 문서는 내부 변경 기록이며 공식 내용수정신고 접수 증빙은 아니다.

## 배경

일괄 판매(품질 기준 이하 판매, 미장착 전부 판매)는 장착·잠금·귀속 장비만 빼고 유니크까지 판다. 유니크를 지키는
수단은 잠금뿐인데, 잠금은 장비 상세에서 하나씩만 걸 수 있었다.

## 변경 내용

### 인벤토리 일괄 작업

1. 선택 잠금: 일괄 작업 메뉴에서 시작한다. 보고 있는 부위의 장비를 여러 개 고른 뒤 한 번에 잠그거나 잠금을 푼다.
   잠긴 장비와 장착 중인 장비도 고를 수 있다. 한 번에 고를 수 있는 수는 선택 판매와 같은 100개다.
2. 유니크 전부 잠금: 보고 있는 부위의 잠기지 않은 유니크 장비를 모두 잠근다(장착 중인 유니크 포함). 검색어나
   보기 필터와 관계없이 부위 전체에 적용된다. 버튼에 잠글 유니크 수를 표시하고, 없으면 누를 수 없다.
3. 선택 잠금은 선택 판매, 비교 선택과 동시에 켜지지 않는다. 부위 탭을 바꾸면 선택이 풀린다.
4. 잠근 장비가 없을 때의 안내 문구에 선택 잠금을 적었다.

### 안내서

5. 장비 항목에 선택 잠금과 유니크 전부 잠금을 적었다.

## 검증 및 운영 영향

- 판매 규칙, 장비 수치, 재화는 바뀌지 않는다. 잠금의 효과(일괄 판매·선택 판매 제외)도 그대로다.
- DB 마이그레이션, 세이브 형식, 배포 설정, 의존성 변경은 없다. 새 그림도 없다.
- API: `POST /api/v2/me/equipment/lock`이 `{ iid, locked }`에 더해 `{ iids, locked }`를 받는다. 한 요청에
  `MAX_BULK_LOCK_COUNT`(500)개까지 받고, 넘으면 `too_many_iids`, 목록이 잘못되면 `invalid_iids`(둘 다 400)다.
  그사이 사라진 장비는 건너뛰고 남은 장비만 바꾸며, 보유한 장비가 하나도 없으면 `not_owned`(400)다.
  응답에 잠금 상태가 실제로 바뀐 수 `changedCount`가 추가됐다. 기존 한 개 잠금 요청의 동작은 같다.
- 유니크가 한 부위에 500개를 넘으면 화면이 요청을 나누어 보낸다.
