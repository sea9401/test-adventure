# 2026-11-24 거래소 유찰 시 자동 인하 재등록

## 기록 상태

- 상태: `recorded`
- 원본 브랜치: `feat/marketplace-auto-relist`(`feat/coop-base-reward` 위에 쌓음).
- 사용자 요청(2026-11-24): "유찰 시 자동 인하 재등록 한번 봅시다." 2026-11-23의 `다시 올리기` 버튼에 이어지는 작업이다.
  첫 구현(30% 고정)을 본 뒤 "꼭 30%여야 하나, 값은 본인이 설정하게"라는 요청으로 인하 폭을 판매자가 정하게 바꿨다.
- 이 문서는 내부 변경 기록이며 공식 내용수정신고 접수 증빙은 아니다.

## 배경

`2026-11-23-marketplace-relist.md`의 조사에서, 유찰된 장비를 같은 가격으로 다시 올리면 13.6%만 팔리고
25% 넘게 낮추면 34.1%가 팔렸다. 유찰된 장비 3,566건 가운데 2,002건을 판매자가 손으로 다시 올리고 있었다.

## 변경 내용

1. 팔기 탭의 경매 설정에 `유찰되면 가격을 낮춰 한 번 더 올리기` 체크박스를 추가한다. 기본은 꺼짐이고, 켠 뒤에 등록하는
   모든 종류의 매물에 적용된다. 켜면 인하 폭(1~90%의 정수, 처음 값 30%)을 판매자가 직접 적는다.
2. 옵션을 켠 매물이 입찰 없이 끝나면 물품을 돌려주지 않고, 시작 입찰가를 정한 폭만큼 낮춘 새 매물로 같은 등록 시간만큼
   다시 올린다. 한 번만 다시 올라가고, 그때도 입찰이 없으면 기존처럼 물품이 돌아온다.
3. 다시 올라간 매물은 보통 매물과 같다. 입찰 전에는 취소할 수 있고, 가격 알림을 건 구매자에게는 새 매물로 알림이 간다.
4. 판매자에게는 유찰 알림 대신 "유찰되어 N골드로 다시 올렸습니다" 알림이 간다.
5. 옵션이 켜져 있다는 사실과 인하 폭은 판매자 본인의 매물 목록에만 표시한다. 구매자에게는 내려 주지 않는다
   (가격이 내려갈 것을 알면 입찰을 미룬다).
6. 1골드짜리처럼 더 낮출 수 없는 매물은 다시 올리지 않고 돌려준다.
7. 안내서의 거래소 항목에 설명을 추가했다.

## 구현 메모

- `marketplace_listings_v2`에 `auto_relist_left`(정수, 기본 0)와 `auto_relist_cut_pct`(정수, 기본 30) 칸을 추가했다.
  마이그레이션 `0194_marketplace_auto_relist.sql`.
- 유찰 정산(`/api/v2/cron/marketplace-expire`)에서 기존 매물을 `expired`로 닫고 같은 물품 스냅샷으로 새 매물 행을 만든다.
  가방 세이브를 건드리지 않으므로 물품은 늘 매물 한 건에만 묶여 있고, 판매자의 활성 매물 수도 그대로다.
- 거래 제한 계정의 매물과 점검 중 정산은 기존 처리(취소·건너뜀)가 먼저 적용된다.
- 경제 기록: `marketplace.auto_relist`(이전 매물 번호, 이전 가격, 새 가격, 인하 폭).

## 검증 및 운영 영향

- 실제 Postgres(임시 DB)에서 등록 → 유찰 → 인하 재등록 → 다시 유찰 → 물품 반환을 확인했다. 인하 폭 15%로 올린
  10,000골드 매물은 8,500골드로, 값을 적지 않은 매물은 7,000골드(30%)로 다시 올라갔고, 옵션을 끈 매물은 바로 돌아왔다.
  두 번째 유찰 뒤 재료 수량이 처음과 같아졌다. 0, 91, 소수, 문자열 인하 폭은 등록이 거절됐다.
- DB 마이그레이션이 한 건 있다(칸 두 개 추가, 기본값 0과 30). 배포 순서는 마이그레이션 먼저다.
- 로그인한 브라우저에서 체크박스를 눌러 보는 확인은 하지 않았다.
- 배포 뒤 볼 것: 옵션을 켠 매물 비율, 판매자가 고른 인하 폭 분포, 인하 폭별 낙찰률(손으로 다시 올린 경우 25% 이하 인하 13%,
  25% 초과 인하 34%), 전체 유찰 건수.
