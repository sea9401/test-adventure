# EXP 페이싱 개편 계획 (레벨 1→100)

> 배경: `docs/game-fun-audit.md` 2순위 — 중후반 페이싱 "대기=진행". 레벨 곡선이 극단적으로
> 백로딩(막판 20레벨이 전체의 ~60%)되어 자동전투와 곱해지면 막판이 순수 대기 벽.
>
> **✅ 구현 완료 (2026-05-22, #498).** 아래는 설계 기록 — 코드(`src/lib/leveling.ts`)가 현재 사양. Claude 분석 → Codex 2라운드 재검토로 수렴.
> 처음엔 "EXP 곡선 전면 재설계(단일 power 교체)"로 출발했으나, 2라운드 논의로
> **"유입(income) 밴드 배율 + 곡선 미세 완화"** 라는 더 안전한 해법으로 바뀜.

## 실측 — 현재 페이싱 (origin/main)

**곡선** (`src/lib/leveling.ts`):
- Lv1~34: `floor(120 * L^1.5)`
- Lv35~99: `floor((120/35) * L^2.5 * endgameMultiplier(L) * reductionMultiplier(L))`
- `endgameMultiplier`: 60~69 1.0→1.27, 70~89 1.3→1.5375, **90~99 1.55→1.955** (곱 스택)
- `reductionMultiplier`: 35~49 1.0→0.85 램프, 50+ 0.85 고정
- `MAX_LEVEL=100`, 초과 EXP → `overflowExp` → 파라곤. 신참 ×2 + 드랍 ×2 (L<30).

**백로딩**: 10레벨 밴드 비중 1-10 0.1%, 60-70 ~10%, 80-90 ~24%, **90-100 ~35%**.
막판 20레벨(80→100)이 전체 1→100(11.88M EXP)의 ~60%.

**전투 수 기준에서도 실재** (Codex 측정 — 유입이 곡선을 상쇄하지 못함):
몹 EXP는 Lv10→95에서 ~20배 오르는데 요구치는 ~120배 → 구간 전투 수 L60 ~1057,
L80 ~1347, L95 ~1784, **L99 ~2073** (전투 쿨 1.5~3s → 99→100이 최대 ~1.7시간).

## 핵심 설계 결정 — 곡선이 아니라 유입을 손댄다

**EXP는 골드·드랍과 완전 분리** (`data/monsters` `MonsterDrop` 에 exp 미사용 — Codex 확인).
→ EXP만 독립 상향 가능, 부작용 없음. 그래서:

- **저장 요구치(곡선)는 거의 안 건드린다** → 기존 세이브 **burst-level 위험 0, 마이그레이션 불필요**.
  (참고: 세이브는 로그인 시 자동 레벨업 안 됨 — 다음 `applyExpGain`(전투/퀘/위탁 수령) 때만.
  곡선을 크게 낮추면 누적 EXP 유저가 연쇄 레벨업 터뜨림 → 그래서 곡선은 최소만.)
- **유입(몹/퀘 EXP)을 레벨 밴드별로 올려** 구간 전투 수를 목표선으로.

## 확정 설계

### 유입 밴드 배율

| 구간 | 유입 배율 |
|------|------|
| L30-49 | ×1.10 |
| L50-69 | ×1.25 |
| L70-89 | ×1.45 |
| L90-100 | ×1.55 |

(L1-29 는 신참 ×2 가 이미 커버 — 미변경.)

### 곡선 미세 완화

- **Lv90-99 만.** Lv90 기준값 1.55 유지(경계 점프 없음 — 90이 이미 깨끗한 접합점),
  L99 까지 **-15% 선형 램프**. → 90-100 구간 요구치 ~-8%, **전체 1→100 요구치 -3.1%뿐**.
- 35-49 reduction / 60-90 endgame 경계는 안 건드림.

### 결과 (엔드캡 = 1170, 유저 확정)

- 99→100 전투 수 ~2073 → **~1170** (실효 ~1.76x 완화). L95-100 을 ×1.6 으로 더 올려
  ~1050 으로 낮추는 안은 **기각** — 1170(레벨당 ~0.5~1시간)도 건강한 소프트 엔드캡.
  1050 은 하드 목표 아닌 하한으로 본다(Codex 권고).
- 막판 벽 완화 + 중반 가속 → "대기=진행" 해소. 별빛 진입 전 준비도(파라곤/장비)는
  곡선 단축이 아니라 별빛 밸런스 별도 조정으로(아래 비목표).

## 기각된 곁가지 (Codex 2R)

- **단일 power 전역 곡선 교체** — 총 35-44% 삭감 → burst-level + 게임 과단축. 기각.
- **신참 보너스 범위 확대(L<30 → L<50)** — `applyNewbieBonus` 가 EXP ×2 뿐 아니라
  **드랍 ×2** 도 같이 줌 → 중반 1.1~1.3x 만 필요한데 2x 는 과다. 기각, 별도 밴드 배율로.

## 통합 지점 (파일:라인 → 할 일)

**단일 진실원 없음 주의** — `monster.exp`/퀘스트 EXP 소비가 3곳. 한 곳만 고치면
라이브·위탁·퀘스트 페이싱 불일치.

1. **신규 공유 헬퍼** (예: `lib/leveling.ts` 또는 인접) — `levelBandExpMultiplier(level)`
   순수 함수(위 밴드 테이블). 단일 진실원.
2. **`lib/server/battleClaim.ts:620`** (라이브 전투 EXP) — 헬퍼 배율 적용.
3. **`adventure/battle/offlineSim.ts:217`** (위탁/오토헌트 EXP) — 동일 적용.
4. **`lib/server/questReward.ts:204`** (퀘스트 EXP) — 동일 적용.
   (세 곳 모두 기존 길드 expMult/룬/파라곤/부여/신참 배율과 **곱산** — 그 스택 위에 밴드 배율
   추가. 곱해져 후반 수령 EXP 가 더 튈 수 있음 — 의도된 가속.)
5. **`lib/leveling.ts` `endgameMultiplier`** — 90-99 구간만 -15% 램프 추가(L90 1.55 유지).
6. 도감/어드민 EXP 표시(`shared.tsx:108` 등)는 자동 반영(파괴 아님, 숫자만 달라짐).

## 검증

- 단위: `levelBandExpMultiplier` 경계값(29/30, 49/50, 69/70, 89/90), `endgameMultiplier`
  90-99 램프 연속성(90=1.55, 점프 없음).
- 회귀: L1-29 EXP 산출 무변(신참 경로 불변), 곡선 변경이 전체 요구치 -3.1% 이내인지.
- **3-경로 일관성(중요)**: 라이브·위탁·퀘스트가 같은 밴드 배율을 먹는지 (한 곳 누락 시 페이싱
  불일치 — Codex 가 지적한 핵심 누수 통로).
- 수동(dev): 70-100 구간 전투/퀘 EXP 가 의도 배율로 들어오는지 라운드트립.
- 배포 후 튜닝: 레벨 도달 시간 분포 측정([[monitoring-queries]] 류) 후 밴드 배율 재조정.
