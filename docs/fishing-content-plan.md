# 낚시 컨텐츠 설계 (Fishing Content Plan)

작성 2026-06-01. 상태: 설계 확정 대기 → PR 스택 착수 전.

## 0. 한 줄 요약

스태미나를 다 쓴 유저가 "조금 더 노력해서 더 챙기고 싶을 때" 하는 **완전 수동·반응형 사이드 미니게임**. 잡은 물고기는 모험의서(도감)에 박제되고, **주간 종별 최대어 대회**의 순위에 따라 **낚시 코인**을 받아 (후속) 낚시 코인 샵에서 원하는 물품을 산다.

## 1. 설계 원칙 (확정)

- **완전 수동·반응형**: 캐스팅 → 입질 대기 → 입질 타이밍에 직접 눌러야 낚인다. 자동/방치/일괄 불가. (게임의 "완전 자동 단판 전투"와 정반대 결.)
- **스태미나 0 소모**: 메인 루프(전투/사냥)를 다 쓴 유저를 위한 컨텐츠. 별도 자원도 없음 — **시간과 집중만이 비용.**
- **순수 평등 미니게임**:
  - 사이즈·희귀도 = **순수 운**. 반응은 성공/실패만 가른다.
  - 캐릭터 레벨·스탯·장비 **영향 없음.** 신규·약캐도 월척 한 방으로 종별 1등 가능.
- **보상은 "잡으면 무조건"이 아니라 주간 대회 결과로**: 종별 사이즈 랭킹 1·2·3등 차등 + 4~10등 골고루. "참여하면 왠만하면 받음."
- **몰빵 방지**: 보상을 30어종 × 10순위로 쪼갠다 + **사이즈 heavy-tail**로 노가다 우위를 눌러 캐주얼 스나이핑 여지를 남긴다.
- **인플레 통제**: 보상 화폐는 골드가 아니라 전용 **낚시 코인**. 주간 총 코인 예산을 먼저 정하고 슬롯으로 나눈다.

## 2. 핵심 루프

1. 남단 자유 항구의 낚시터 진입 → "찌 던지기".
2. 서버가 입질까지의 지연(2~7초, 비공개 랜덤)을 정함. 클라는 "기다리는 중…".
3. 입질! 표시 → 유저가 **반응 윈도우(약 700ms) 안에 "낚아채기"** 를 눌러야 함.
   - 너무 빠름(<150ms, 프리파이어) 또는 윈도우 초과 → **놓침**(보상 없음).
   - 성공 → 서버가 어종·사이즈를 **서버에서 굴려** 결정.
4. 결과 연출: 어떤 종을 몇 cm 잡았는지. 개인 최고기록 갱신/도감 신규 등록 여부 표시.
5. 도감 갱신 + (해당 주) 종별 기록 upsert. 반복.

## 3. 어종 (30종)

종은 5개 희귀도 티어로 나눈다. 티어는 (a) 캐스팅 시 어떤 종이 걸릴 확률(encounter weight), (b) 사이즈 분포 파라미터, (c) 종별 기록 보상 코인 규모를 결정한다.

| 티어 | 종 수 | 어종 | 캐스팅 가중치(티어합) | 사이즈 단위(cm) min~max | heavy-tail 지수 k |
|---|---|---|---|---|---|
| 흔함 | 6 | 붕어, 피라미, 송사리, 미꾸라지, 망둑어, 줄새우 | 40% | 8 ~ 45 | 3.0 |
| 보통 | 7 | 잉어, 메기, 농어, 숭어, 도다리, 가자미, 전어 | 28% | 20 ~ 90 | 3.5 |
| 희귀 | 7 | 송어, 강꼬치고기, 참돔, 갈치, 광어, 우럭, 무지개송어 | 20% | 30 ~ 130 | 4.0 |
| 영웅 | 6 | 청새치, 참다랑어, 만새기, 철갑상어, 대왕문어, 심해아귀 | 9% | 80 ~ 300 | 5.0 |
| 전설 | 4 | 백금 잉어, 별빛 가오리, 심연의 리바이어던, 무지개 비늘 용어 | 3% | 150 ~ 1200 | 6.0 |

- 한 티어 안에서는 종이 균등 추첨. 예) 특정 전설종 한 마리가 걸릴 확률 ≈ 3% / 4 ≈ 0.75%.
- 종별 min~max는 위 티어 밴드를 기준으로 종마다 살짝 다르게(개성) 둔다 — PR-1에서 30행 확정. 단위는 **길이(cm)**.

### 사이즈 분포 (heavy-tail)

```
p   = random()            // 0~1 균등
size = minCm + (maxCm - minCm) * p^k     // k>1 → 작은 사이즈 흔함, 대물 희박
```

- k가 클수록 max 근처가 희박 → **던진 횟수가 늘어도 기록치가 천천히 포화**한다. 노가다 우위 억제 + 캐주얼 한 방 스나이핑 여지. (k는 밸런스 다이얼.)
- 사이즈는 **반응 속도·캐릭터와 완전 무관.** 서버에서만 굴린다.

## 4. 모험의서(도감) 등록

- 저장 키 신설: `fishing-codex.v1` (savesKv). `AdventureLog`(`adventure-log.v2`) 패턴을 따른다.
- 종별 엔트리:

```ts
type FishCodexEntry = {
  discovered: boolean;     // 한 번이라도 잡음
  bestSize: number;        // 개인 역대 최대어(cm) — 영구 박제
  totalCaught: number;
  firstCaughtAt: number;
  bestCaughtAt: number;
};
type FishCodex = { fish: Record<FishId, FishCodexEntry> };
```

- UI: 기존 모험의서/도감 화면에 **"어보(魚譜)" 섹션** 추가. 등재 N/30, 종별 개인 최대어 cm 표기. (수집 재미.)
- 최초 등재 시 소량 코인 마일스톤(선택, 작은 값)으로 수집 동기 부여 — 코어 보상과 별개.

## 5. 주간 대회 (종별 리더보드)

PvP 시즌 인프라(`pvpSeasons` + `pvpRatings` + 주간 경계 헬퍼 `weekStartUtcFor`/`seasonIdFor`)를 그대로 복제·재사용.

### 저장 스키마 (신규 DB 테이블)

```
fishing_seasons        (id "YYYY-Www" PK, startAt, endAt, status, closedAt, rewardsGrantedAt)
fishing_records        (userId, seasonId, fishId, bestSize, caughtAt)
  PK   (userId, seasonId, fishId)        -- 유저·종·주 당 개인 최고만 1행
  IDX  (seasonId, fishId, bestSize DESC) -- 종별 top-N 조회
```

- 캐스팅 성공 시: 해당 (user, season, fish) 행 upsert — 새 사이즈 > 저장된 bestSize면 갱신.
- 종별 리더보드 조회 = `WHERE seasonId=? AND fishId=? ORDER BY bestSize DESC LIMIT 10`.
- 시즌 경계·롤오버는 PvP와 동일(월요일 00:00 KST = 일 15:00 UTC). 충돌 피하려 정산 분만 오프셋.

### 보상 티어 (종별, 코인)

| 순위 | 흔함 | 보통 | 희귀 | 영웅 | 전설 |
|---|---|---|---|---|---|
| 1등 | 25 | 35 | 50 | 80 | 140 |
| 2등 | 15 | 22 | 32 | 50 | 90 |
| 3등 | 10 | 15 | 22 | 35 | 60 |
| 4~10등 | 6 | 8 | 12 | 18 | 30 |

- 전부 튜닝 다이얼. 한 명이 흔함 다수를 1등 석권해도 주당 수백 코인 선에서 묶이도록 의도.
- (선택 다이얼) **1인당 1등 수상 종 수 상한** — 켜면 초과분이 2등에게 넘어가 몰빵을 더 막음. 기본 off, heavy-tail로 1차 억제.

### 정산 크론

- `fishing-season-rewards` 크론(월요일 새벽 KST). PvP `pvp-season-rewards` 라우트·정산 로직 복제.
- 각 어종 top-10 조회 → 티어 코인 지급 → `rewardsGrantedAt` 마킹(중복 지급 방지, idempotent).
- `deploy/crontab.txt`에 1줄 추가. **배포 후 EC2 crontab 등록 필요.**

## 6. 낚시 코인 & 샵

- 지갑: `fishing-wallet.v1` (savesKv) — PvP `pvp-wallet.v1` 복제. `{ coins: number }`.
- 코인 획득 경로 = **주간 정산이 코어** (+선택 도감 마일스톤). 캐스팅 자체로는 코인 안 줌 → 인플레 통제.
- 낚시 코인 샵: PvP 투기장 상점(`/api/pvp/shop` + 카탈로그) 패턴 복제. **내용물은 별도 협의** (낚싯대 외형/칭호/소비템/장비 교환 등). 사용자 요청대로 **마지막 PR.**

## 7. 봇/자동화 방지 (서버 권위)

웹 클라라 완전 차단은 불가하지만, 이 설계는 자동화의 이득 자체가 거의 없게 만든다:

- **어종·사이즈 굴림은 100% 서버에서.** 클라는 결과를 못 만든다("999cm 잡았다" 위조 불가). 클라가 서버에 보내는 건 반응 타이밍뿐.
- **사이즈가 반응 속도와 무관**하므로(설계 §1), 반응을 봇으로 통과해도 **사이즈 이득 0.** 봇은 사람보다 안 유리.
- **반응 윈도우 검증**: <150ms(프리파이어) 거부, 윈도우 초과 거부.
- **벽시계 레이트 제한**: 매 캐스팅에 입질 대기(수 초)가 강제돼 시간당 시도 횟수가 자연 제한 + heavy-tail로 노가다 우위 미미.
- 세션 토큰(서버 발급, 서명)으로 캐스팅↔낚아채기 1쌍 검증.

## 9. PR 스택 (6단계)

각 PR은 독립 리뷰·머지 가능. PR-1~3까지 가면 "낚시로 도감 채우기"가 동작하고, PR-4~5에서 대회·보상이 켜진다.

| PR | 내용 | 끝나면 |
|---|---|---|
| **PR-1** | 30어종 데이터(티어/사이즈/코인 스케일) + `fishing-codex.v1` 저장 모델 + 모험의서 "어보" 섹션(빈 상태) | 토대 |
| **PR-2** | cast/reel 서버 액션(서버 권위 roll + 반응 검증) + `FishingView`/`useFishing` 반응 UI + 도감 등록 배선 + `/dev/fishing` | 낚시→도감 채우기 동작 |
| **PR-3** | 남단 항구에 낚시터 진입점 wiring (V2 게임 플로우) | 본 게임에서 접근 가능 |
| **PR-4** | `fishing_seasons`/`fishing_records` 테이블 + 마이그레이션 + 캐스팅 시 record upsert + 종별 리더보드 조회 API/UI | 이번 주 순위 확인 |
| **PR-5** | `fishing-wallet.v1` + `fishing-season-rewards` 크론 + 티어 정산 + crontab 등록 | 코인 실제 지급 |
| **PR-6** | 낚시 코인 샵(카탈로그 + 구매 라우트). 내용물 별도 협의 | 코인 소비처 |
