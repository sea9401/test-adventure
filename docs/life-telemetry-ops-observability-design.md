# 생활 텔레메트리·운영 관측 개선 설계

## 목표

- 관리자 생활 텔레메트리의 7일·30일 집계가 10만 건 제한 때문에 최근 일부만 반영되는 문제를 없앤다.
- 고빈도 경제 로그 배치의 처리량, 큐 적체, 실패를 운영자가 확인하고 장애 징후를 자동으로 알 수 있게 한다.
- 30일 보존 로그의 하루 유입량이 정리 처리량을 넘기기 전에 경고하고, 실제 적체는 첫날부터 알린다.
- DB 커넥션 풀 대기가 일시적 표본이 아니라 연속해서 발생할 때 운영 알림을 보낸다.

## 생활 텔레메트리

원본 행을 애플리케이션으로 최대 10만 건 가져와 집계하는 방식을 폐기한다. PostgreSQL에서 기간 조건 전체를 다음 차원으로 집계한다.

- 활동 합계와 고유 이용자
- 채집 대상별 시도·성공
- 재료별 주/추가 수급량
- KST 일자별 시도·성공·수급량
- 활동·이용자별 시도·성공·수급량과 전체 기간의 활동 간격 통계

상위 이용자는 SQL 윈도 함수로 활동별 10명만 반환한다. 따라서 결과 크기는 이벤트 수가 아니라 활동·대상·재료·일자 수에 비례한다. 이상 행동 원본 로그는 기존 2만 건 제한을 유지하고 별도 경고를 표시한다.

## 배치 관측과 경보

best-effort 배처가 현재 대기 수와 처리 중 수를 노출한다. 경제 로그 배처는 프로세스 시작 이후의 성공 배치 수, 처리 건수, 평균·최대 배치 크기, 실패 배치·건수, 마지막 성공·실패 시각을 누적한다. 관리자 런타임 프로파일러 응답과 운영 화면에서 이를 확인한다.

- 배치 INSERT 실패: 첫 실패부터 운영 알림, 10분 단위 중복 억제
- 큐 적체: 대기+처리 중 500건 이상이면 운영 알림, 10분 단위 중복 억제
- DB 풀 대기: 1분 구간에서 waiting이 3회 연속 1 이상이면 1회 알림, 정상 표본 후 다시 감시

관측과 알림 자체의 실패는 게임 요청을 실패시키지 않는다.

## 보존 처리량

경제 로그의 일일 삭제 가능량은 `deleteBatchSize * economyDeleteMaxBatches`로 계산한다. 정리 크론 시작 시 최근 24시간 유입 건수를 세어 사용률을 반환한다.

- 80% 이상: 경고 상태로 표시
- 100% 이상: 용량 초과 운영 알림
- 정리 후 `economy.more=true`: 유입량과 무관하게 즉시 적체 알림

기존 전체 로그 적체 3일/7일 알림은 장기 추세 확인용으로 유지한다.

## 비목표

- 로그 저장소를 ELK/OpenSearch로 이전하지 않는다.
- DB 인스턴스 증설이나 배포 설정을 바꾸지 않는다.
- 텔레메트리 원본 이벤트 계약이나 30일 보존 기간을 바꾸지 않는다.
