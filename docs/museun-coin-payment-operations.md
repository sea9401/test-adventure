# 무슨 코인 카드 결제 운영 절차

이 문서는 Toss 카드 결제 코드의 테스트·활성화·장애·환불 절차를 정리한다. 현재 저장소의
운영 기본값은 비활성 상태이며, 명시적인 출시 승인과 별도 배포 없이는 결제를 켜지 않는다.

## 환경과 출시 게이트

| 변수 | 용도 | 운영 준비 전 값 |
| --- | --- | --- |
| `NEXT_PUBLIC_MUSEUN_COIN_SHOP_OPEN` | 상점 화면·API 공개 | `false` |
| `MUSEUN_COIN_PAYMENTS_MODE` | `disabled`, `test`, `live` 선택 | `disabled` |
| `TOSS_PAYMENTS_CLIENT_KEY` | 브라우저 결제창 공개 키 | 비워 둠 |
| `TOSS_PAYMENTS_SECRET_KEY` | 서버 Core API 비밀 키 | 비워 둠 |

`test`는 테스트 키와 기존 상점 허용 계정만 사용한다. `live`에는 테스트 키를 넣을 수 없다.
비밀 키를 로그, DB, 클라이언트 응답, 문서에 남기지 않는다. 실제 키는 승인된 비밀 저장소에
등록하고 키 유출 점검을 마친 뒤 주입한다.

출시 전에는 다음을 모두 확인한다.

1. Toss 가맹점·카드사 심사와 정산 계정 준비
2. 등급분류의 유료 재화·확률형 꾸미기 상자 관련 내용정보 및 변경 절차 확인
3. 판매자 정보, 원화 가격, 환불 기준, 개정 약관·개인정보처리방침 시행일 공지
4. 테스트 키로 주문 생성, 성공·실패 콜백, 전액·부분 취소, 중복 승인, 웹훅 재전송 검증
5. Toss 웹훅 주소를 `https://<운영 도메인>/api/toss-payments/webhook`으로 등록
6. 운영자 `/admin/payments` 접근, 감사 로그, 고객 문의 대응 권한 확인

모든 준비가 끝난 뒤에도 상점 공개와 `live` 전환은 각각 명시적으로 승인받아 같은 변경
절차로 배포한다. 배포만으로 점검 모드를 자동 해제하지 않는다.

## 주문과 복구

- 브라우저가 보내는 가격이나 코인 수량은 사용하지 않고 서버 상품표를 기준으로 주문한다.
- 승인 콜백의 주문번호·결제 키·금액을 저장된 주문과 대조한 뒤 유료 코인을 한 번만 지급한다.
- 승인 요청이 불명확하면 Toss 결제 조회로 확인한다. 자동 확인에 실패한 주문은
  `review_required`로 두고 코인을 임의 지급하지 않는다.
- 웹훅은 알림 신호로만 사용하고, 내부 주문을 찾은 뒤 Toss 조회 결과를 권위 상태로 삼는다.
- 운영자는 `/admin/payments`에서 주문번호로 조회한 뒤 `상태 재확인`을 실행한다. Toss 승인과
  내부 원장 지급이 일치하지 않으면 DB를 직접 수정하지 말고 장애 기록을 남긴다.

## 환불

- 미사용 유료 코인은 환불 요청과 동시에 보류해 새 소비를 막고 Toss 전액 취소를 요청한다.
- 일부 사용한 로트는 자동 취소하지 않고 `review_required`로 보낸다. 운영자는 남은 수량을
  넘지 않는 범위에서만 승인할 수 있으며 원화 환산이 정수로 떨어지지 않으면 처리하지 않는다.
- 명확한 Toss 취소 실패에는 보류를 해제한다. 네트워크 단절처럼 결과가 불명확하면 보류를
  유지하고 Toss 결제 조회·상점관리자 내역으로 확인한다.
- 완료된 취소는 원장에 음수 유료 코인 이벤트로 추가한다. 기존 원장 행을 수정하거나
  삭제하지 않는다.

## 보존과 보안

- 계약·청약철회, 대금결제, 유료 코인 공급·취소 기록은 거래 종료 후 5년 보존한다.
- 결제 관련 소비자 불만·분쟁 기록은 처리 종료 후 3년 보존한다.
- 내부에는 카드번호, 유효기간, CVC를 저장하지 않는다. 고객 문의에도 해당 정보를 받지 않는다.
- 삭제·보존 정책을 변경할 때 결제 주문, 원장, 로트, 배분, 환불 테이블을 일반 게임 로그와
  같은 단기 정리 대상으로 넣지 않는다.

## 롤백과 비활성화

신규 결제를 즉시 막아야 하면 먼저 상점 공개 또는 결제 모드를 비활성화한다. 이미 승인된
주문과 웹훅·환불 복구 경로는 기록을 보존한 채 운영자가 조회할 수 있어야 한다. 스키마나
원장을 되돌리거나 결제 행을 삭제하지 않는다. 런타임 롤백 뒤에도 점검 모드는 사용자의 별도
해제 지시가 있을 때만 해제한다.
