# 서버 권한 저장 경계

출시 환경에서 브라우저는 게임 재화와 진행도의 진실 출처가 아니다. 클라이언트는 행동을
요청하고, 서버가 현재 DB 상태를 잠근 뒤 비용·보상·결과를 계산해 저장한다.

## 범용 저장 API

`GET /api/save`는 로그인 직후 호환용 동기화 키를 읽으며, 없는 `character.v2`와
`inventory.v2`는 서버에 정의된 초기값으로 한 번만 생성한다.

`PATCH/DELETE /api/save`에서 클라이언트가 직접 변경할 수 있는 키는 아래 하나뿐이다.

- `storyFlags.v2`: 튜토리얼 표시 상태. 경제·보상 판정에는 사용하지 않는다.

나머지 `SYNCED_KEYS`는 읽기 호환 목록일 뿐 클라이언트 쓰기 허용 목록이 아니다.

## 서버 권한 데이터

다음 값은 반드시 전용 API와 DB 트랜잭션을 통해서만 변경한다.

- 캐릭터: `gold`, `bankedGold`, `level`, `exp`, `hp`, `stamina`, `fame`
- 자원: `materials`, `cashItems`, `rareMaps`, 충전량과 소비 아이템
- 전투/진행: 전투 보상, 퀘스트 보상, 던전·거점·탑 진행도, 명예와 랭킹 입력값
- 소유권: 장비 개체, 장착 상태, 스킬 학습·로드아웃, 칭호, 도감
- 소셜/운영: 길드 자원과 역할, 마켓 등록·구매·정산, 제재와 관리자 보정

`character.v2`, `inventory.v2`처럼 여러 도메인이 공유하는 JSON 저장은 전용 라우트에서
`lockSaveForUpdate` 후 필요한 필드만 변경하고, 읽은 객체의 나머지 필드를 보존한다.

## 새 기능 체크리스트

1. 클라이언트는 보상 결과나 잔액을 보내지 않고 행동 ID와 선택값만 보낸다.
2. 서버는 사용자와 현재 상태를 다시 읽고 허용 여부·비용·보상을 계산한다.
3. 재화 또는 소유권 변경은 하나의 트랜잭션에서 행 잠금과 함께 처리한다.
4. 재시도 가능한 요청은 idempotency 키나 마지막 결과 replay를 제공한다.
5. 응답은 변경 후 서버 스냅샷을 반환하며 클라이언트는 그 값을 채택한다.
6. 정상, 잔액 부족, 중복 요청, 경쟁 요청, 위조 payload 테스트를 함께 추가한다.

범용 저장 키를 다시 클라이언트 쓰기 목록에 추가하려면 해당 값이 경제·보상·접근 제어에
사용되지 않는다는 보안 검토와 payload 크기·형태 검증이 선행되어야 한다.
