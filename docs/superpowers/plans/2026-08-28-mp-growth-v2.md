# MP Growth Version 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve every existing MP record while making newly created/rejobbed characters use moderated random MP growth plus direct MP from trained INT and SPI.

**Architecture:** The client/server-safe life-resource module owns versioned range calculation and the pure trained-stat MP bonus. Existing version-1 records always request version-1 ranges; new creation and completed combat rejob create version 2. Combat derive adds trained INT/SPI only for version 2, while the state API exposes separate current and next-rejob ranges for accurate UI copy.

**Tech Stack:** TypeScript 5, Next.js 16.2 Route Handlers, React 19, Vitest 4.

## Global Constraints

- HP ranges, stored HP, HP derive, equipment MP, `maxMpPct`, and skill MP costs do not change.
- Version 1 records retain their stored totals and old future level-up ranges.
- Legacy characters stay legacy until a completed Lv.100 combat rejob.
- New characters and completed combat rejobs create version 2; lifestyle switching never rerolls resources.
- Version 2 Lv.1 MP uses the existing formula; only level-up permanent-step influence changes from 100% to 40%.
- Version 2 trained MP is `max(0, baseAllocatedStats.int - 15) + max(0, baseAllocatedStats.spi - 15)` before `maxMpPct`.
- Job bonus, class anchor bonus, food stats, and `statPct` never enter trained MP.
- Ryu Harin calibration (`spiFloor=218`, `intCap=60`, trained INT/SPI `60/60`) is Lv.1 `85..115`, per-level `11..13`, and Lv.100 expected MP `1,378` before equipment.
- No database migration, production write, deployment, or maintenance mode.
- Keep Route Handlers on the existing uncached mutation and Web `Response.json` conventions documented in `node_modules/next/dist/docs/01-app/01-getting-started/15-route-handlers.md`.

- [ ] **Step 3: Implement versioned pure formulas and strict parsing**

Use the current HP and Lv.1 MP formulas for both versions. Branch only level-up MP:

```ts
export const LIFE_RESOURCE_GROWTH_VERSION = 2 as const;
export type V2LifeResourceGrowthVersion = 1 | typeof LIFE_RESOURCE_GROWTH_VERSION;
export const MP_LEVEL_STEP_SCALE = 0.4;

const spiLevelStep = version === 1
  ? spi
  : Math.floor(spi * MP_LEVEL_STEP_SCALE);
const intLevelStep = version === 1
  ? int
  : Math.floor(int * MP_LEVEL_STEP_SCALE);
const mpLevelMin = 3 + spiLevelStep;

export function trainedIntSpiMpBonus(stats: { int: number; spi: number }): number {
  return (
    Math.max(0, Math.floor(Number(stats.int) || 0) - 15) +
    Math.max(0, Math.floor(Number(stats.spi) || 0) - 15)
  );
}
```

`rollInitialLifeResourceGrowth` emits `version: LIFE_RESOURCE_GROWTH_VERSION`. `parseLifeResourceGrowth` accepts only integer versions 1 and 2 and returns the original valid version. `resetLifeResourceLevels` already spreads the record and must keep doing so.
