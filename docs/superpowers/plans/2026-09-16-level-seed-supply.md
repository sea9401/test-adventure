# 생활 레벨별 씨앗 수급 구현 계획

사용자 승인: 농사 1레벨 30% → 100레벨 55%, 벌목 1레벨 1.495% → 100레벨 5% 선형 성장.
현재 브랜치에서 관련 파일만 수정·커밋한다. 기존 전투 변경은 보존한다. 배포하지 않는다.

- [x] 농사 반환과 벌목 레벨 보너스의 경계·중간 레벨 회귀 테스트를 작성하고 실패를 확인한다.
- [x] lifeLevelBonuses.ts에 농사 반환 확률 함수를 추가한다. 벌목 seedChancePct는 (level-1)/99*3.505로 대체한다. 레벨은 1~100으로 제한한다.
- [x] farm.ts의 harvestPlot에서 수확 전 레벨로 밭당 독립 판정하여 해당 씨앗을 최대 1개 지급한다. 결과에 seedReturned를 추가한다. 수확량과 희귀 작물 판정은 유지한다.
- [x] 수확 알림·농장 안내·벌목 안내·생활 마일스톤과 매뉴얼을 갱신한다. 수동·자동 벌목의 공통 함수 연결을 확인한다.
- [x] 관련 Vitest, TypeScript, 변경 파일 lint와 diff 검사를 수행하고 요청 범위만 커밋한다.

검증 기준: 레벨 1과 100에서 정확한 확률 경계, 수확 전 레벨 사용, 반환 실패 시 씨앗 보존, 성공 시 해당 작물만 1개 추가, 재수확 거부, 기존 수확량 유지. 벌목은 기존 작물 가중치와 자동 효율을 유지한다.

검증 결과: 핵심·UI·API 관련 8개 파일 122개 테스트 통과 후 벌목 API의 100레벨 케이스 추가 검증(해당 파일 24개 통과). TypeScript는 기본 Node 힙 한도 초과 후 8GB 한도로 재실행하여 통과. 변경 파일 ESLint 통과. 안내서 테스트의 직업 수 고정 기대값(149) 실패 1건은 변경 전 HEAD를 /tmp에 추출하여 동일하게 재현했다.
직접 코드 검토: 기존 씨앗 가중치, 자동 벌목 재료 효율, 트랜잭션 저장 경로 유지 확인. 신규 표면 없이 기존 화면에 문구만 추가했다.
