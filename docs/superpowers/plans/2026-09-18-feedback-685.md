# 건의 #685 구현 계획

Goal: 정신의 MP 설명을 실제 계산과 맞추고 관심매물을 계정에 저장한다.
Architecture: 공통 MP 안내와 savesKv 기반 GET/PATCH API, 클라이언트 훅을 사용한다.
Tech Stack: Next.js App Router, React, Drizzle, Vitest.

- [x] 회귀 테스트: API 계정별 목록, add/remove/clear/import, 인증과 잘못된 입력, 200개 한도. 훅 서버 복원/재진입/저장 실패/가져오기 테스트를 먼저 작성하고 실패 확인.
- [x] API: watchlist/route.ts에 인증 및 rate limit, 생성 충돌 방지 후 행 잠금과 명령 반영. 기존 savesKv 도우미 재사용.
- [x] 훅: GET으로 복원, PATCH 성공 후 목록 갱신, 요청 중 조작 방지, 창 복귀 갱신, 오류 재시도. 기존 로컬 목록 명시적 가져오기.
- [x] 설명: 최신/이전 자원 성장 공식을 공통 안내로 정리하고 stats/combat-formulas 및 툴팁 갱신. 기존 안내서 테스트 정정.
- [x] 관련 Vitest, TypeScript, ESLint, diff 검토 후 현재 브랜치에 커밋.

AGENTS.md에 따라 별도 승인 반복과 서브에이전트 없이 이 세션에서 실행한다. 배포/푸시는 수행하지 않는다.

## 검증 결과

- 새 회귀 테스트가 기존 로컬 저장 구현에서 실패하는 것을 확인한 뒤 구현했다.
- 거래소, MP 계산, 안내서 관련 23개 파일에서 281개 테스트 통과.
- 안내서의 기존 직업 도감 개수 테스트 1개는 수정 전 HEAD 테스트에서도 동일하게 실패하여 별도 제외했다.
- 변경 파일 ESLint와 TypeScript 검사 통과. TypeScript는 기본 힙 한도 초과 후 8GB 한도로 재실행했다.
- 자체 검토: 인증한 계정으로만 읽기/쓰기, 첫 저장 시 동시 생성 처리, 목록 전체 덮어쓰기 방지, 실패 시 상태 보존, 로컬 가져오기 성공 후 원본 제거, 최신/구형 MP 공식 구분 확인.
- 실제 운영 DB나 배포 환경에는 접근하지 않았다.
