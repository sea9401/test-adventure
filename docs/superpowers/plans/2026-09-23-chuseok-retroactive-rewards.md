# 추석 복주머니 누락 단계 보상 지급

> 작업은 현재 브랜치에서 직접 수행한다. AGENTS.md에 따라 설계 재승인과 서브에이전트 없이 테스트, 구현, 검증, 커밋까지 진행한다.

**Goal:** 한 번이라도 공격에 참여하면 참여 전 처치된 단계도 단계당 회복약 15개를 우편으로 지급한다.

**Architecture:** 첫 유효 공격의 기존 트랜잭션 안에서 공유 이벤트 잠금으로 확정한 `progress.stage - 1`개 단계의 보상을 추가한다. 같은 공격에서 새로 처치한 단계는 기존 전체 참여자 지급 경로로 처리한다. 기존 참여자는 데이터 마이그레이션에서 첫 공격 직전 단계까지만 보충한다. 마이그레이션은 런타임이 중지된 상태에서 실행되며 Drizzle 저널로 한 번만 적용된다.

**Tech Stack:** TypeScript, Drizzle, PostgreSQL, Vitest, React.

## 제약과 설계

- 출석만 한 사용자는 대상이 아니다. 유효 공격 1회가 참여 기준이다.
- 실제 처치된 단계만 지급한다. 이벤트 진행도와 일일 공격 횟수는 변경하지 않는다.
- 공격 재시도와 다른 사용자의 동시 첫 공격에도 중복/누락이 없어야 한다.
- 기존 우편의 수령/삭제 여부를 지급 기준으로 사용하지 않는다.
- 공격 기록의 `MIN(stage - stagesCleared - 1)`로 기존 사용자의 참여 전 처치 수를 구한다. 트랜잭션 시작 시각은 잠금 획득 순서와 다를 수 있으므로 created_at 정렬에 의존하지 않는다.
- 배포는 별도 요청이 있을 때 수행한다.

## 검증 결과

- 변경 전 신규 회귀 조건 4개가 기대한 보상 누락으로 실패했다.
- 변경 후 PostgreSQL 통합 13개와 규칙/화면 8개, 총 21개 테스트 통과.
- 타입 검사, 변경 파일 ESLint, 마이그레이션 187개 저널 검사 통과.
- 전용 로컬 DB에 기존 늦은 참여 기록을 만든 뒤 실제 마이그레이션 러너를 두 번 실행했다. 두 실행 모두 미지급 2단계 보상 30개 우편 1건과 마이그레이션 기록 1건만 유지됐다.
- 운영 배포 및 운영 DB 변경은 수행하지 않았다.
