# 요리책 보유 수량 표시 설계

## 목표

개인 주방의 요리책에서 각 요리를 얼마나 보유하고 있는지 조리 전에 바로 확인할 수 있게 한다.

## 표시 방식

- 각 레시피 카드의 요리명 바로 옆에 `보유 N개`를 표시한다.
- 보유하지 않은 요리도 `보유 0개`로 표시해 수량 정보가 누락된 것으로 오해하지 않게 한다.
- 표시는 기존 불투명 레시피 카드 안에 배치하며 별도 반투명 표면을 추가하지 않는다.

## 수량 계산

완성 요리는 품질, 희귀 재료 사용 여부, 지속시간에 따라 서로 다른 인벤토리 ID로 저장된다. 사용자가 납품 준비에 필요한 전체 수량을 확인할 수 있도록, 같은 `recipeId`에 속하는 모든 변형의 개수를 합산한다.

기존 `/api/v2/cooking` 응답의 `cookingFoods`를 사용하므로 API와 저장 구조는 변경하지 않는다. 조리와 납품 성공 시 `CookingPanel`이 응답 전체를 `data` 상태에 다시 저장하므로 보유 수량도 추가 요청 없이 즉시 갱신된다.

## 변경 경계

- `CookingPanel`에 레시피 ID와 완성 요리 인벤토리를 받아 총량을 보여 주는 작은 표시 컴포넌트를 둔다.
- 기존 `deliverableCookingFoods`가 유효한 인벤토리 항목을 레시피별로 분류하므로 그 결과를 합산한다.
- 주문판, 도감, 인벤토리, 서버 라우트의 동작은 변경하지 않는다.

## 테스트

- 같은 레시피의 서로 다른 품질 변형이 하나의 보유 수량으로 합산되는지 검증한다.
- 해당 레시피를 보유하지 않은 경우 `보유 0개`가 렌더링되는지 검증한다.
- 기존 요리 패널 테스트와 타입 검사를 실행해 회귀가 없는지 확인한다.
