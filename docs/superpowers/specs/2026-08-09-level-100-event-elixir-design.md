# 100레벨 달성 이벤트 비약 설계

## 목표

관리자가 전체 유저 우편에 첨부할 수 있는 계정 귀속 이벤트 소모품 `100레벨 달성의 비약`을 추가한다. 유저가 아이템을 사용하면 현재 레벨이 100 미만일 때 즉시 100레벨에 도달하며, 실제 전체 우편 발송은 이 변경에 포함하지 않는다.

## 아이템 정의

- 식별자는 `level_100_elixir`로 한다.
- 표시 이름은 `100레벨 달성의 비약`으로 한다.
- `이벤트` 태그를 카탈로그 데이터에 명시하고 인벤토리 목록 및 상세 정보에 표시한다.
- 계정 귀속, 거래 불가, 상점 미판매 아이템으로 정의한다.
- 관리자 우편에서만 지급 가능한 아이템 목록에 포함한다.
- 기존 테스트 전용 `경험치의 비약 (테스트)` 레어맵은 호환성을 위해 변경하지 않는다.

## 사용 동작

사용 요청은 서버 권위 트랜잭션으로 처리한다. 트랜잭션은 캐릭터 저장값을 먼저 잠근 뒤 현재 보유량과 레벨을 검증하고, 필요한 경우 숙련도 저장값을 기존 공통 락 순서에 따라 잠근다.

현재 레벨이 100 미만이면 다음을 하나의 트랜잭션에서 수행한다.

1. 현재 레벨에서 100까지 필요한 레벨 수를 계산한다.
2. 기존 사냥 레벨업과 같은 성장 스탯 로직을 건너뛴 레벨마다 한 번씩 적용한다.
3. 캐릭터 레벨을 정확히 100으로, 현재 EXP를 0으로 설정한다.
4. 직업 숙련도와 누적 직업 레벨은 변경하지 않는다.
5. 비약 한 개를 차감한다.

현재 레벨이 이미 100이면 `already_max_level` 오류를 반환하고 아이템을 차감하지 않는다. 아이템을 보유하지 않았으면 기존 캐시 소모품 규약과 같은 `not_owned` 오류를 반환한다. 잘못된 아이템이나 요청 형식은 기존 사용 API의 검증 규칙을 따른다.

## 서버 구조

아이템은 기존 `MUSEUN_CASH_ITEMS` 기반 인벤토리 소모품 모델에 추가한다. 효과 종류에는 목표 레벨 100을 나타내는 전용 효과를 추가한다.

레벨 도약 계산과 성장 스탯 반영은 서버용 순수 함수로 분리한다. 이 함수는 캐릭터의 현재 직업, 레벨, 성장 상태를 입력받아 다음 레벨·EXP·숙련도 성장 상태와 획득 레벨 수를 반환한다. 기존 `applyExpTomeGrant`와 같은 원시 성장 함수 및 직업 판별 규약을 재사용하되, 고정 EXP 양에 의존하지 않고 목표 레벨을 직접 적용한다.

`POST /api/v2/me/use-cash-item`은 전용 효과를 만나면 캐릭터와 숙련도 저장값을 같은 트랜잭션에서 갱신한다. 성공 응답에는 갱신된 아이템 보유량, `level: 100`, `levelsGained`를 포함해 클라이언트가 즉시 상태와 알림을 갱신할 수 있게 한다.

## 관리자 전체 우편 준비

아이템을 관리자 지급 허용 목록에 추가한다. 그러면 기존 `공지·우편` 화면의 캐시 아이템 첨부 선택지와 `target: "all"` 우편 경로를 그대로 사용해 운영자가 전체 유저에게 원하는 수량을 보낼 수 있다.

이번 변경에서는 우편을 생성하거나 운영 데이터에 아이템을 직접 지급하지 않는다. 관리자 화면에서 운영자가 명시적으로 발송해야만 실제 지급이 발생한다.

## 클라이언트 표시

인벤토리 소모품 탭에서 아이템 이름 옆에 `이벤트` 태그를 표시한다. 상세 카드도 유형을 `이벤트 소모품`으로 표시하고 계정 귀속·거래 불가 정보를 유지한다. 사용 성공 시 `100레벨 달성`과 획득 레벨 수를 안내하고 전역 캐릭터 상태를 새로 가져온다. `already_max_level`은 아이템이 소모되지 않았음을 알 수 있는 한국어 안내로 변환한다.

새 표면을 추가하지 않고 기존 불투명 `SURFACE_CARD`와 상세 카드 구조를 그대로 사용한다. 따라서 장면 배경 위 가독성 규칙과 라이트·다크 모드 표면 규칙을 유지한다.

## 테스트

- 카탈로그 테스트: 식별자, 표시 이름, 이벤트 태그, 계정 귀속, 상점 제외, 관리자 지급 허용을 검증한다.
- 성장 함수 테스트: 1레벨과 중간 레벨에서 정확히 100레벨·EXP 0이 되고, 획득 레벨 수만큼 성장 롤이 적용되며 직업 숙련도는 증가하지 않는지 검증한다.
- 경계 테스트: 이미 100레벨일 때 변화가 없고 비약을 소모하지 않을 수 있는 결과를 검증한다.
- API 테스트: 미보유, 이미 만렙, 정상 사용의 상태 코드와 저장 결과를 검증한다.
- 관리자 우편 테스트: 아이템이 전체 우편 첨부 허용 목록과 검증 경로를 통과하는지 검증한다.
- UI 테스트: 인벤토리에 `이벤트` 태그와 사용 결과 안내가 표시되는지 검증한다.

## 배포 범위

구현과 자동 검증까지만 수행한다. 운영 배포, 점검 모드 전환, 실제 전체 유저 우편 발송은 이 작업의 범위에 포함하지 않는다.
