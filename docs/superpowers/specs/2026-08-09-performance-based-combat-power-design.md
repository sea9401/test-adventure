# 실전 성능 기반 전투력 재설계

## 배경

현재 `derivePowerScore`ub294 공격력·방어력·HP·MP·속도·마나 실드·회피도·적중도를 가중 합산한다. 회피도는 이미 전투력에 포함되지만, 최종 정수 반올림과 툴팁의 부정확한 설명 때문에 투자 효과가 보이지 않을 수 있다.

더 큰 문제는 각 능력치의 가중치가 실제 전투 결과를 직접 설명하지 못한다는 점이다. 치명타·다중 공격·속도 상한·방어 점감·회피 경감·회복·반사·지속 피해·장착 액티브 스킬의 재사용 주기와 조건부 시너지가 빠져 있다. 그 결과 실제 사냥 성능이 다른 빌드가 비슷한 전투력으로 표시될 수 있다.

## 목표

- 전투력을 단순 스탯 합계가 아니라 실제 PvE 자동 전투의 예상 공격 성능과 생존 성능을 근사하는 지표로 바꾼다.
- 장착한 액티브·패시브 스킬, 스킬 강화, 전투 패턴과 장비 시너지를 반영한다.
- 회피도·적중도·치명타·속도·회복·방어·마나 실드·반사·지속 피해를 실제 전투 공식에 맞게 평가한다.
- 런타임 계산은 랭킹·장비 미리보기에서도 사용할 수 있을 만큼 결정적이고 가볍게 유지한다.
- 전투력을 사용하는 권장 사냥터, 성장탑, 거점 게이트·공성 피해와 랭킹을 같은 단위로 재보정한다.

## 비목표

- PvP 전용 전투력은 이번 범위에서 만들지 않는다. 신규 지표는 PvE 기준이다.
- 현재 HP·MP, 일회성 포션, 핫타임, 일시적 이벤트 버프는 캐릭터의 기준 전투력에 반영하지 않는다.
- 특정 몬스터의 속성 상성·상태이상 면역에 맞춘 별도 점수를 만들지 않는다.
- 전투력이 올라보이게 하려고 실전 기여가 없는 능력치에 최소 보정치를 주지 않는다.
- 전투 엔진의 피해·회복·방어 공식은 변경하지 않는다.

## 선택한 접근

실시간 모의 전투 대신 **실제 전투 엔진으로 보정한 경량 성능 모델**을 사용한다.

1. 개발·검증 시 대표 빌드와 대표 적을 실제 `resolveBattle`에서 반복 전투시켜 승률, 승리 턴, 남은 HP와 패배 시 적의 남은 HP를 측정한다.
2. 런타임에서는 해당 결과에 맞춰 보정된 기대 DPS·EHP 근사식만 실행한다.
3. 전투 엔진의 상수·스킬 데이터를 공유하고, 계수를 가져오려고 전투 엔진을 복사한 두 번째 전투 공식을 만들지 않는다.

실시간 모의 전투는 정확하지만 랭킹에서 모든 유저를 반복 계산하고 장비 미리보기를 빠르게 응답해야 하는 현재 구조에 맞지 않다. 수동 가중 합산은 가볍지만 이번 재설계의 목적인 조건부 스킬과 시너지 평가를 다시 놓친다.

## 기준 전투 환경

성능 모델은 네 개의 중립 PvE 프로필을 같은 비중으로 평가한다.

| 프로필 | 주요 평가 목적 |
|---|---|
| 물리 균형형 | 물리 방어, HP, 회피 경감, 반사·반격 |
| 마법 균형형 | 마법 방어, HP, 마나 실드, 회복 |
| 고방어형 | 적 방어를 뚚는 공격, 지속 피해, 방어 감소, 스킬 순환 |
| 고회피·고적중형 | 적중도, 자신의 회피도, 조건부 명중·회피 시너지 |

모든 프로필은 무속성이고, 특수 면역·상태이상 저항·처형 기믹을 갖지 않는다. 평가 지평은 플레이어 행동 12회로 고정해 오프너, 재사용 대기시간, 지속 피해, 누적 버프와 회복을 반영하되 무한 회복·무한 반사로 평가가 폭주하지 않게 한다.

기준 적의 스탯은 사냥터 단일 구간에 고정하지 않고, 현재 `dungeonLadder`의 단조 증가 밴드를 사용한다. 성능 모델은 빌드가 목표 승률을 유지할 수 있는 가장 높은 밴드를 찾아 절대 전투력으로 환산한다. 이로써 초반 기준 적에 대한 과도한 오버킬과 후반 고정 적에 대한 방어 포화를 피한다.

## 성능 모델

### 공격 지수

공격 지수는 네 프로필에 대한 12행동 기대 DPS의 기하평균으로 계산한다.

- 현재 직업의 주 공격축과 보조 공격축을 실제 평타·스킬 선택 규칙에 맞게 사용한다.
- 속도는 ATB 행동 간격, 치명타는 발생 확률과 피해 배율, 다중 공격은 기대 타수로 환산한다.
- 적중도는 기준 적의 회피도를 누르는 실제 대결식으로 계산한다.
- 장착 액티브 스킬은 MP, 발동률, 재사용 대기시간, 장착 순서와 전투 패턴의 조건을 사용해 12행동 기대 사용 횟수를 구한다.
- 직접 피해, 다단 히트, 지속 피해, 스택 소모, 적 방어 감소, 취약, 속성 분기와 장착 시너지를 같은 스킬 효과 데이터에서 읽는다.

### 생존 지수

생존 지수는 각 프로필의 12행동 동안 견딜 수 있는 총 기대 원피해량의 기하평균으로 계산한다.

- 최대 HP, 물리·마법 방어, 회피 피해 경감, 받는 피해 감소와 마나 실드 내구도를 반영한다.
- 회복·흡혈·재생·자해·보호막·보장 회피는 12행동에서의 기대 생명력 증감으로 환산한다.
- 반사·반격은 적의 예상 공격 횟수를 기준으로 공격 지수에 반영하고, 피격으로 인한 추가 손실은 생존 지수에 중복 계산하지 않는다.
- 무적·무한 회복으로의 발산을 막기 위해 모든 지속 생존 기여는 12행동 지평 내에서만 계산한다.

### 최종 전투력

기본 결합식은 다음과 같다.

```text
전투력 = 스케일 계수 × √(공격 지수 × 생존 지수)
```

공격과 생존 중 하나만 극단적으로 높은 빌드가 권장 전투력을 쉽게 뚫지 못하도록 산술평균 대신 기하평균을 쓴다. 스케일 계수는 초반·중반·후반·최상위 성장 밴드의 대표 빌드 중앙값이 현재 권장 전투력 곡선과 같은 밴드에 남도록 단일 전역 계수로 보정한다. 개별 캐릭터의 구 전투력을 보존하는 보정은 하지 않는다.

## 스킬·패턴 반영

- 장착한 패시브는 현재처럼 `derivePlayerCombatV2FromSaves`에서 파생 스탯과 엔진 레버로 반영한다.
- 장착한 액티브, 스킬 강화, 장착 순서와 현재 전투 패턴을 성능 모델 입력으로 넘긴다.
- 전투 패턴이 없으면 실제 전투와 동일하게 `smartDefaultPatternFromEquipped`를 사용한다.
- 조건을 충족할 수 없는 스킬은 가치를 얻지 못한다. MP가 부족한 로드아웃, 상태이상 스택 생성기 없는 소모기, 사용 조건이 서로 맞지 않는 패턴은 실제 기대 사용 횟수만 반영한다.
- 장착 순서나 패턴이 변하면 전투력이 변할 수 있다. 이는 의도한 동작이다.

## 런타임 구조와 데이터 흐름

1. 저장 데이터에서 캐릭터·장비·숙련·스킬을 읽고 현재와 같은 전투 파생을 수행한다.
2. 순수 모듈이 파생 플레이어, 최대 HP·MP, 정규화한 `V2SkillsState`를 받아 공격 지수·생존 지수·최종 전투력과 표시용 분해를 반환한다.
3. `me/state`, 공개 프로필, 랭킹, 장비 미리보기, 성장탑, 거점 점령·공성이 같은 순수 모듈을 사용한다.
4. 출력은 정수 `total`, 정수 `offense`, 정수 `survival`, 관측용 세부 항목을 포함한다. 랭킹·게이트는 `total`만 쓰고 화면은 분해를 설명에 쓴다.

계산 코드는 DB와 UI를 import하지 않는 순수 모듈로 둔다. 랭킹은 현재처럼 조회한 저장 데이터에서 즉시 계산하며, 신규 DB 캐시나 보정용 저장 키를 추가하지 않는다.

## 표시

- 캐릭터 기본 정보의 전투력 툴팁을 실제 반영 항목에 맞게 고친다.
- 총 전투력 아래에 `공격 지수`와 `생존 지수`를 표시해 회피도·스킬 변경이 어느 축에 기여했는지 확인할 수 있게 한다.
- 장비 미리보기는 총 전투력 증감과 공격·생존 지수 증감을 같이 보여준다.
- 회피도를 바꾸었는데 총점이 정수 반올림으로 동일한 경우에도 생존 지수 변화를 별도로 표시한다.

## 재보정 범위

산식을 바꾸면 전투력을 사용하는 모든 기준을 같이 검증한다.

- 사냥터·던전 권장 전투력
- 성장탑 층별 필요 전투력과 보스 스케일
- 거점 수비 게이트와 공성 피해
- 전투력 랭킹
- 장비 전투력 미리보기
- 관리자 밸런스 텔레메트리와 운영 시뮬레이션

보정은 기존 임계값에 새 점수를 억지로 맞추지 않고, 각 콘텐츠의 기존 대표 빌드가 같은 목표 승률·소요 턴·성장 구간을 유지하도록 새 임계값을 다시 측정한다.

## 테스트와 합격 기준

### 순수 산식

- 같은 입력은 항상 같은 전투력과 분해를 반환한다.
- 유효한 공격·생존 투자를 높이면 관련 지수가 단조 증가한다. 단, 상한 이후 속도나 사용할 MP 소모가 없는 추가 MP처럼 실전 기여가 없는 투자는 예외다.
- 회피도를 높이면 물리·마법 기준 적 모두에서 생존 지수가 올라가고, 적중도가 높은 프로필에서는 증가폭이 더 작아진다.
- 공격 스킬을 추가하면 MP·재사용 주기·패턴에서 실제로 사용될 때만 공격 지수가 올라간다.
- 회복·보호막·받는 피해 감소 스킬은 생존 지수에, 반사·반격은 공격 지수에 반영된다.
- 비전투 스킬은 전투력을 바꾸지 않는다.

### 전투 엔진 교차 검증

- 초반·중반·후반·최상위 성장 밴드와 물리·마법·회피·지속 피해·회복·반사 대표 빌드를 결합한 표본을 사용한다.
- 각 표본을 네 기준 적 프로필과 고정 시드로 반복 전투해 승률·승리 턴·잔여 HP를 측정한다.
- 전체 표본에서 전투력 순위와 실전 성능 순위의 Spearman 상관계수는 0.90 이상이어야 한다.
- 물리·마법·회피·지속 피해·회복·반사 각 아키타입 내의 Spearman 상관계수는 0.80 이상이어야 한다.
- 같은 성장 밴드에서 아키타입별 `예측 전투력 − 실전 성능 환산치` 중앙 편향은 전체 중앙의 ±15% 이내여야 한다.
- 상관계수나 편향 기준을 만족하지 못하면 임계값만 조정하지 않고 성능 모델을 다시 보정한다.

### 콘텐츠 회귀

- 새 전투력 기준으로 재계산한 권장 사냥터에서 대표 빌드의 승률이 기존 목표 구간을 유지한다.
- 성장탑·거점 게이트·공성 피해가 새 스케일에서 기존 진행 템포를 유지한다.
- 랭킹, 내 정보, 공개 프로필, 장비 미리보기가 같은 입력에 대해 같은 총 전투력을 보여준다.
- 활성 음식 버프 여부가 랭킹 전투력을 바꾸지 않도록 캐릭터 표시 전투력도 동일한 기준 파생을 사용한다.

## 구현 순서

1. 전투력 입력·출력 계약과 구 산식 특성 테스트를 추가한다.
2. 대표 빌드·적 생성기와 실전 전투 측정 스크립트를 만든다.
3. 공격·생존 근사 모델을 TDD로 구현하고 시뮬레이션 결과에 맞게 계수를 보정한다.
4. 캐릭터·랭킹·미리보기·성장탑·거점 호출부를 하나씩 전환하고 일치 테스트를 추가한다.
5. 권장 전투력·성장탑·거점 임계값을 실전 승률과 기존 템포에 맞게 재측정한다.
6. 전투력 세부 표시와 설명을 연결한다.

## 마이그레이션과 배포

- DB 마이그레이션은 필요 없다. 전투력은 저장값이 아니라 현재 저장 상태에서 파생한다.
- 기존 전투력 랭킹은 새 공식으로 즉시 재정렬된다. 이는 의도한 변경이다.
- 하드 게이트와 공성 피해는 새 기준치와 같은 변경에 포함해 전환한다. 산식만 먼저 바꿔 사용자를 일시적으로 차단하지 않는다.
- 신규 산식은 기존 밸런스 조정과 엮어 롤백하기 어렵게 만들지 않고 독립 모듈·계수로 둔다.
- 사용자가 명시적으로 지시하기 전에는 어떤 환경에도 배포하지 않는다.
