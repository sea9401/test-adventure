# 스킬 강화 숙달 비용 인상 및 기존 강화 전액 환급 설계

## 목표

- 스킬 강화에서 직업 숙련도 조건을 없앤 대신, 제거된 단계별 요구치만큼 숙달 포인트 비용을 높인다.
- 변경 전에 강화한 사용자는 강화 상태를 초기화하고 실제 납부한 골드와 숙달 포인트를 100% 돌려받는다.
- 변경 후 강화의 일반 초기화는 기존과 같이 누적 비용의 50%만 환급한다.

## 비용

| 단계 | 기존 숙달 | 제거된 직업 숙련도 요구치 | 신규 숙달 |
| --- | ---: | ---: | ---: |
| +1 | 300 | 0 | 300 |
| +2 | 800 | 150 | 950 |
| +3 | 1,800 | 300 | 2,100 |
| +4 | 4,000 | 500 | 4,500 |
| +5 | 9,000 | 800 | 9,800 |

골드 비용과 강화 효과 수치는 바꾸지 않는다. 신규 최대 강화의 누적 숙달 비용은 17,650이다.

## 기존 강화 환급

Drizzle 데이터 마이그레이션이 `skills.v2.value.enhancements`의 각 스킬 단계에서 기존 누적 비용을 계산한다.

- 기존 단계별 누적 골드: 1,000,000 / 4,000,000 / 12,000,000 / 32,000,000 / 82,000,000
- 기존 단계별 누적 숙달: 300 / 1,100 / 2,900 / 6,900 / 15,900
- 사용자별 모든 강화 스킬의 금액을 합산해 `character.v2.gold`와 `proficiency.v2.points`에 전액 더한다.
- 환급 후 `skills.v2.enhancements`를 제거해 모든 기존 강화를 초기화한다.
- 관련 세이브의 `version`과 `updated_at`을 갱신한다.
- 강화 데이터가 없으면 대상이 아니며, 환급 후에는 데이터가 제거되므로 마이그레이션 SQL을 다시 실행해도 중복 지급되지 않는다.
- 기존 직업 숙련도는 애초에 차감되지 않았으므로 별도 변경하지 않는다.

마이그레이션과 신규 비용 코드는 점검 모드에서 함께 반영해야 한다. 마이그레이션 후 신규 코드 전환 전까지 옛 비용으로 강화 요청을 받는 구간을 만들지 않는다.

## 화면과 일반 초기화

강화 화면은 인상된 숙달 비용을 데이터에서 그대로 표시한다. 데이터 마이그레이션 이후 새로 강화한 기록은 인상된 비용표로만 만들어지므로, 기존 `skillRitualRefund`의 50% 계산은 신규 강화에 정확히 적용된다.

## 검증

- 순수 로직 테스트에서 신규 단계 비용과 신규 누적 50% 환급액을 검증한다.
- 라우트 테스트에서 인상된 +2 숙달 비용이 차감되는지 검증한다.
- PostgreSQL 마이그레이션 검증에서 여러 스킬·여러 단계 합산, 전액 환급, 강화 제거, 세이브 버전 증가, 재실행 멱등성을 확인한다.
- 타입 검사, 대상 린트, 마이그레이션 저널 검사와 전체 테스트를 실행한다.
