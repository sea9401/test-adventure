# 식당 개인 메뉴 선택 전환 설계

## 목적

길드 식당과 모험가 협회 식당의 주간 메뉴 선정·잠금 절차를 없앤다. 구성원이 함께 식재료를 기부해 공동 목표를 달성하면 각 구성원의 식권이 사용 가능해지고, 각자는 현재 식당 시설 레벨에서 해금된 메뉴 중 원하는 메뉴를 주문한다.

## 이용 흐름

1. 주간 참여 대상 구성원이 농장 식재료와 낚시 어획물을 공동 준비 점수에 기부한다.
2. 개인 기여 점수는 기존 규칙대로 추가 식권 수량을 계산한다. 기본 식권과 기여 식권은 목표 달성 전에는 `발급 예정`으로 표시한다.
3. 공동 준비 점수가 목표에 도달하면 모든 주간 참여 대상자의 계산된 식권이 사용 가능해진다.
4. 이용자는 시설 레벨에서 해금된 모든 메뉴 중 하나를 골라 식권 1장으로 주문한다.
5. 공동 준비 점수, 개인 기여, 식권 사용량과 음식 효과는 기존과 같이 매주 월요일 00:00 KST에 초기화한다.

## 메뉴 해금

메뉴의 유일한 시설 조건은 `GuildDiningMenu.minFacilityLevel`이다. 주간 운영 메뉴 수나 관리자의 선택은 더 이상 주문 가능 여부에 관여하지 않는다. 시설별 이용 가능 메뉴 수는 메뉴 등록부에서 레벨 조건을 만족하는 항목을 계산해 표시한다.

- Lv.1: 2종
- Lv.2: 3종
- Lv.3: 4종
- Lv.4: 5종
- Lv.5: 6종

## 서버와 저장 호환성

- 길드 식당의 `select_menus` 요청을 제거한다.
- 길드·협회 주문 판정에서 `selectedMenuIds` 검사를 제거하고 시설 레벨만 검사한다.
- 응답에서 관리자 권한, 메뉴 슬롯 수, 메뉴별 선택 상태를 제거한다.
- 기존 DB의 `selectedMenuIds` 필드는 마이그레이션 위험을 피하기 위해 남겨 둔다. 새 동작에서는 읽지 않으며, 과거에 저장된 선택 값도 주문 가능 메뉴를 제한하지 않는다.
- 식권은 별도 발급 레코드를 만들지 않고 기존 주간 개인 상태에서 계산한다. 공동 목표 달성 여부가 계산된 식권의 사용 가능 시점을 결정한다.
- 길드와 협회는 동일한 메뉴 해금·주문 규칙을 사용한다.

## 화면과 안내

- `이번 주 메뉴`, `동시 운영`, 관리자 체크박스와 `메뉴 확정` 버튼, 메뉴 잠금 안내를 제거한다.
- 메뉴 영역은 `시설 메뉴`로 바꾸고, 시설 레벨에 따라 해금된 메뉴를 개인이 선택한다는 설명을 표시한다.
- 목표 달성 전 식권 카드는 `목표 달성 시 식권`으로 표시하고, 달성 뒤에는 `내 식권`으로 표시한다.
- 목표 미달, 주간 참여 대상 아님, 다른 식당 이용처 선택, 식권 소진, 회복량 포화 안내는 유지한다.
- 사용 설명서와 시설 업그레이드 요약은 `동시 운영 메뉴` 대신 `이용 가능 메뉴` 수를 보여준다.

## 오류 처리

- 등록되지 않았거나 시설 레벨이 부족한 메뉴는 `menu_unavailable`로 거부한다.
- 목표 미달은 `pantry_not_ready`, 식권 소진은 `no_meal_ticket`로 기존과 같이 거부한다.
- 폐기된 `select_menus` 요청은 `invalid_body`로 거부한다.

## 검증

- 과거 주간 선택 목록에 없는 해금 메뉴도 주문되는 회귀 테스트를 길드와 협회 라우트에 둔다.
- 시설 레벨보다 높은 메뉴는 계속 거부되는지 확인한다.
- 공동 목표 미달·식권 소진 등의 기존 주문 제한이 유지되는지 확인한다.
- 시설 레벨별 메뉴 수, 시설 요약, 이용 불가 사유에서 주간 메뉴 선정 조건이 제거됐는지 순수 함수 테스트로 확인한다.
- 관련 테스트, 타입 검사와 린트를 실행한다.

## 범위 제외

- 식권 수량, 기여 점수 환산, 공동 목표 산식과 음식 효과 수치는 변경하지 않는다.
- 길드·협회 중 한 곳만 고르는 주간 이용처 규칙은 변경하지 않는다.
- 기존 저장 필드 삭제를 위한 DB 마이그레이션은 진행하지 않는다.
