# 장비 강화 초기화 설계

## 배경과 목표

강화된 장비는 캐릭터에 귀속되어 거래소와 길드 창고를 통한 이전이 제한된다. 이 정책은 유지한다. 다만 더 이상 사용하지 않는 강화 장비의 기본 개체까지 처분하지 못하는 불편을 줄이기 위해, 강화 투자분을 포기하고 장비를 미강화 상태로 되돌리는 기능을 제공한다.

## 확정 정책

- 강화 초기화 자체에는 골드나 재료 비용이 없다.
- 강화에 사용한 골드, 강화석과 재료 장비는 일절 환급하지 않는다.
- 장착 중이거나 잠금된 장비는 초기화할 수 없다. 장착 및 잠금 해제 후 다시 시도해야 한다.
- 강화 단계와 강화 위력 보너스만 완전히 제거한다.
- 장비 ID, 개체 ID, 옵션 굴림, 제작 품질, 제작자 정보와 폭풍 개량 상태는 유지한다.
- 초기화는 되돌릴 수 없다.
- 강화 장비 거래 제한은 유지한다. 초기화 후 다른 거래 조건도 충족한 장비만 거래할 수 있다.

## 사용자 흐름

대장간의 기존 `강화` 작업대에서 강화된 장비를 선택하면 기본 강화 버튼 아래에 `강화 초기화` 보조 버튼을 표시한다. 별도 작업 탭은 추가하지 않는다.

장착 또는 잠금 상태에서는 버튼을 비활성화하고 각각 `장착 해제 후 초기화 가능`, `잠금 해제 후 초기화 가능`으로 이유를 안내한다. 조건을 충족한 장비에서 버튼을 누르면 확인창을 연다.

확인창에는 다음 정보를 표시한다.

- 장비명과 현재 강화 단계
- 초기화 전후 위력
- 기존 강화 비용과 재료 장비는 환급되지 않는다는 경고
- 강화 단계와 강화 보너스가 삭제된다는 설명
- 초기화 후 거래 가능 조건을 다시 충족할 수 있다는 안내
- 작업을 되돌릴 수 없다는 경고

사용자가 `강화 초기화 확정`을 눌렀을 때만 서버 요청을 보낸다. 성공하면 장비 목록과 전역 게임 상태를 새로고침하고, 선택한 장비는 그대로 유지하되 화면상 강화 단계와 위력을 갱신한다.

## 서버 처리

전용 `POST /api/v2/me/enhance/reset` 엔드포인트를 추가하며 요청 본문은 `{ iid: string }`으로 제한한다.

서버는 사용자 인증과 요청 제한을 적용한 뒤 `equipment.v2` 저장을 트랜잭션 안에서 잠근다. 다음 조건을 순서대로 검증한다.

1. 요청한 장비 개체를 사용자가 실제로 보유하고 있는가
2. 장비에 유효한 강화 상태가 존재하는가
3. 어느 슬롯에도 장착되어 있지 않은가
4. 장비 잠금이 해제되어 있는가

검증을 통과하면 해당 개체에서 `enhance` 필드만 제거하고 저장한다. 강화 외 필드는 기존 객체를 그대로 복사해 보존한다. 재화 저장은 읽거나 변경하지 않는다.

오류 응답은 `not_owned`, `not_enhanced`, `equipped`, `locked`로 구분해 UI가 구체적인 안내를 표시할 수 있게 한다. 중복 요청은 첫 요청 이후 `not_enhanced`로 안전하게 종료된다.

## 테스트와 검증

- 순수 초기화 헬퍼가 `enhance`만 제거하고 다른 장비 메타데이터를 보존하는지 검증한다.
- 미강화, 장착, 잠금, 미보유 장비 요청이 각각 거부되는지 검증한다.
- 확인창이 장비명, 강화 단계, 위력 변화, 무환급 및 되돌릴 수 없음 경고를 표시하는지 검증한다.
- 장착 또는 잠금 장비에서 초기화 동작이 비활성화되는지 검증한다.
- 성공 후 강화 표시가 사라지고 장비 및 전역 상태 새로고침이 호출되는지 검증한다.
- 관련 테스트, TypeScript 검사, 린트와 운영 빌드를 실행한다.

## 비범위

- 강화 재료 환급이나 일부 환급
- 강화 단계 일부만 낮추는 기능
- 초기화 비용 또는 전용 초기화 재료
- 인벤토리나 거래소에서 직접 초기화하는 기능
- 강화된 장비의 거래 제한 완화
