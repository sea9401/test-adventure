# 건의 답변 알림 직접 이동 설계

## 배경

건의 답변 알림의 이동 경로가 진입점마다 다르다.

- 전체 알림 화면은 이미 `/feedback#feedback-<id>`로 이동한다.
- 상단 알림 종의 미리보기는 답변 알림을 눌러도 전체 알림 화면으로만 이동한다.
- 브라우저 푸시는 건의 번호 없이 `/feedback`으로 이동한다.
- 건의 내역은 최초 진입 시 해시를 읽지만, 같은 페이지에서 해시만 바뀌면 열린 항목을 동기화하지 않는다.
- 건의 API는 최근 50건만 반환하므로 오래된 건의에 늦게 답변이 달리면 정확한 항목을 열 수 없다.

## 목표

답변 알림을 누른 모든 경로에서 대상 건의의 상세 내용과 관리자 답변이 즉시 열린 상태로 보이게 한다.

## 범위

### 포함

- 상단 알림 종의 건의 답변 항목
- 전체 알림 화면과 기존 광장 우편 호환 화면의 건의 답변 항목
- 브라우저 푸시 알림
- 건의 페이지의 탭 선택, 대상 항목 펼침, 스크롤
- 최근 50건 밖의 오래된 대상 건의 조회
- 클릭한 상단 답변 알림 한 건의 읽음 처리

### 제외

- 건의 상세 전용 모달 신설
- 관리자 건의 화면 변경
- 건의 목록의 페이지네이션 개편
- 다른 알림 종류의 이동 정책 변경

## 사용자 흐름

1. 사용자가 건의 답변 알림을 누른다.
2. 모든 진입점은 공통 링크 `/feedback#feedback-<id>`를 사용한다.
3. 건의 페이지는 `내 건의 내역` 탭을 선택한다.
4. 건의 목록은 해시의 번호를 대상 조회값으로 API에 전달한다.
5. 대상 건의가 최근 50건에 없으면 API가 로그인 사용자의 해당 건의를 추가로 조회해 목록에 포함한다.
6. 목록 로드 후 대상 행을 펼치고 화면 중앙으로 스크롤한다.
7. 이미 건의 페이지가 열린 상태에서 다른 답변 알림을 눌러 해시만 변경되어도 새 대상에 맞춰 펼침 상태를 갱신한다.

대상이 존재하지 않거나 현재 사용자 소유가 아니면 다른 사용자의 내용을 노출하지 않고, 건의 내역 화면에 `해당 건의를 찾을 수 없습니다.` 안내를 표시한다.

## 구조

### 공통 링크 생성기

양의 정수 건의 번호를 받아 `/feedback#feedback-<id>`를 반환하는 작은 순수 함수를 둔다. 상단 알림, 전체 알림 페이지, 광장 우편 호환 페이지와 웹 푸시가 이 함수를 공유해 링크 불일치를 막는다.

### 상단 알림 종

`feedback_replied` 항목을 누르면 다음 순서로 처리한다.

1. 미리보기를 닫는다.
2. 해당 알림 한 건을 읽음 처리하고 미리보기·배지에서 제거한다.
3. 공통 링크로 이동한다.

읽음 처리 요청이 실패해도 상세 이동은 막지 않는다. 다음 폴링에서 서버 상태로 배지가 복구될 수 있다.

### 브라우저 푸시

푸시 메시지 생성 시 payload의 `feedbackId`를 공통 링크에 반영한다. 제목과 본문, 태그는 유지한다.

### 건의 조회 API

`GET /api/feedback?targetId=<id>`를 지원한다.

- 기본 최근 50건 조회는 유지한다.
- 유효한 양의 정수 `targetId`가 최근 50건에 없으면 `userId`와 `id`를 함께 조건으로 추가 조회한다.
- 찾은 대상은 중복 없이 기존 목록에 합치고 최신 번호순으로 반환한다.
- 잘못된 `targetId`는 일반 목록 조회로 처리한다.
- 다른 사용자 소유 건의는 반환하지 않는다.

### 건의 내역 화면

해시 파싱을 한 곳으로 모으고 최초 렌더와 `hashchange` 양쪽에서 사용한다. 대상 번호가 바뀌면 이전 상세를 닫고 새 대상을 펼친다. 데이터가 준비되면 대상 행으로 스크롤한다.

해시에 대상 번호가 있지만 응답 목록에 없으면 찾을 수 없다는 안내를 표시한다. 사용자가 목록 항목을 직접 열고 닫는 기존 동작과 해시 갱신 방식은 유지한다.

## 오류와 보안

- API 인증 실패 처리는 기존과 동일하게 유지한다.
- 대상 추가 조회는 반드시 현재 `userId` 조건을 포함한다.
- 읽음 처리 실패와 라우팅 실패를 결합하지 않는다.
- 비정상 해시와 쿼리 값은 예외를 내지 않고 대상 없는 일반 내역으로 처리한다.

## 검증

- 공통 링크 생성기가 올바른 해시 URL을 반환하는지 단위 테스트한다.
- 웹 푸시 답변 알림 URL이 대상 건의 링크인지 검증한다.
- 건의 API가 최근 50건 밖의 본인 건의를 포함하고 다른 사용자의 건의는 포함하지 않는지 검증한다.
- 상단 알림의 답변 항목 클릭이 한 건 읽음 처리와 대상 링크 이동을 수행하는지 검증한다.
- 최초 해시 진입과 같은 페이지의 해시 변경 모두 대상 항목을 펼치는지 검증한다.
- 관련 테스트, ESLint, TypeScript 검사를 통과시킨다.

## 완료 조건

- 건의 답변 알림의 모든 사용자 진입점이 동일한 대상 링크를 사용한다.
- 대상 건의가 자동으로 펼쳐지고 보이는 위치로 이동한다.
- 오래된 건의와 같은 페이지 내 연속 클릭도 동작한다.
- 다른 사용자의 건의는 어떤 경우에도 조회되지 않는다.
- 이번 변경은 로컬 커밋까지만 수행하며 별도 요청 없이는 배포하지 않는다.
