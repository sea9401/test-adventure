# 모험가 목장 1차 설계

## 목표

기존 모험가 농장에 닭과 소를 기르는 목장을 추가한다. 이용자는 생활 제작에서 공용 사료를 만들고, 축사에 최대 12시간치를 채운 뒤 달걀과 우유를 수확한다. 축산물은 기존 농장 일일 납품과 신규 요리에 사용한다.

목장은 별도 생활 레벨이나 화폐를 만들지 않는다. 기존 농사 레벨, 농장 증표, 농장 보관함과 요리 시스템을 이어 기존 생활 콘텐츠 사이의 순환을 강화한다.

## 범위

### 포함

- 농장 내부 `목장` 탭
- 닭과 소, 최대 네 개의 사육 칸
- 생활 제작에서 만드는 공용 배합 사료
- 최대 12시간의 시간 기반 연속 생산
- 달걀과 우유 수확 및 농사 경험치
- 기존 농장 일일 납품에 축산물 의뢰 추가
- 달걀과 우유를 사용하는 신규 요리 네 종
- 기존 농작물·음식과 같은 계열의 신규 이미지

### 제외

- 목장 전용 레벨, 경험치 또는 화폐
- 동물별 친밀도, 이름, 품종, 번식과 질병
- 희귀 달걀·우유와 생산물 품질
- 치즈·버터 등 축산물 가공
- 동물 거래와 거래소 등록
- 목장 푸시 알림
- 서버 주기 작업 또는 크론 기반 생산
- 배포

## 해금과 성장

목장은 농부 스킬 `씨앗 선별`을 익히면 열린다. 이 스킬은 옥수수 재배와 씨앗 구매도 해금하므로, 목장을 열었지만 사료 재료를 구할 수 없는 상태가 생기지 않는다.

처음 열 때 기본 닭장과 닭 한 마리를 무료로 지급한다. 기존 저장 데이터에도 목장 상태를 처음 읽는 시점의 서버 시각을 기준으로 같은 기본 닭장을 추가하되, 과거 경과 시간에 대한 생산물은 지급하지 않는다.

추가 사육 칸은 농사 레벨과 사용 가능한 농장 증표를 모두 검사한다.

| 해금 | 조건 | 비용 | 누적 보유 |
| --- | --- | ---: | --- |
| 기본 닭장과 닭 | `씨앗 선별` 습득 | 무료 | 닭 1 |
| 닭장 증축과 닭 | 농사 Lv.10 | 증표 30 | 닭 2 |
| 작은 외양간과 소 | 농사 Lv.20 | 증표 60 | 닭 2, 소 1 |
| 외양간 증축과 소 | 농사 Lv.35 | 증표 120 | 닭 2, 소 2 |

축사와 동물은 한 묶음으로 영구 해금한다. 동물을 따로 사고팔거나 빈 축사에 배치하는 기능은 만들지 않는다.

## 공용 사료 제작

생활 조합 작업장의 `생활 제작`에 `목장 용품` 분류를 추가한다.

- 이름: `배합 사료`
- 1회 제작 결과: 5개
- 재료: 밀 4개, 옥수수 3개, 허브 1개
- 해금: 목장과 동일하게 `씨앗 선별` 습득
- 재료 출처: 농장 보관함
- 결과 저장 위치: 농장 보관함

사료 제작은 기존 생활 제작의 제작 횟수, 발견한 제작법, 총 제작 기록과 일괄 제작 숙련 단계에 포함한다. 다만 숨겨진 도안이나 별도 대성공은 적용하지 않는다.

일반 생활 제작은 캐릭터 생활 재료를 사용하지만 배합 사료는 농장 작물을 사용한다. 이를 억지로 같은 저장 처리에 섞지 않고 사료 제작 전용 서버 작업으로 처리한다. 거래 안에서 `farm.v2`를 먼저 잠그고 `life-workshop.v1`을 잠근 뒤 작물 차감, 사료 지급과 제작 기록을 함께 저장한다. 이는 요리와 거름 사용이 사용하는 `농장 → 생활 제작` 상대 잠금 순서와 일치한다.

## 생산 규칙

| 동물 | 1회 시간 | 사료 소비 | 1회 생산 | 사료통 용량 | 완충 지속 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 닭 | 2시간 | 1개 | 달걀 2개 | 6개 | 12시간 |
| 소 | 6시간 | 1개 | 우유 3개 | 2개 | 12시간 |

각 축사는 독립적으로 사료량, 진행 시간과 수확 대기 생산물을 가진다. 사료 한 개는 생산 한 회가 완료될 때 소비한다. 진행 중 사료를 보충해도 현재 회차의 경과 시간은 초기화하지 않는다. 사료가 모두 소진된 뒤 흐른 시간은 다음에 사료를 넣었을 때 소급 적용하지 않는다.

서버는 생산 주기마다 작업을 실행하지 않는다. 축사별로 마지막 정산 시각과 현재 회차 누적 진행 시간을 저장하고 다음 상황에 경과 생산을 계산한다.

- 농장 또는 목장 상태 조회
- 사료 투입
- 생산물 수확
- 축사 구매

조회 응답은 계산된 최신 상태를 보여주되 생산물 지급은 하지 않는다. 사료 투입, 수확과 구매 요청은 트랜잭션에서 잠근 저장값을 다시 정산하고 결과를 저장한다. 모든 시간 계산은 서버 시각을 사용한다.

수확 대기 생산물에는 별도 공간 상한을 두지 않는다. 최대 사료량이 생산량을 12시간치로 제한하므로 보관 상한으로 인한 추가 예외가 필요하지 않다.

`모두 수확`은 모든 해금 축사의 대기 생산물을 농장 보관함으로 옮긴다. 수확 시 완료한 생산 회차만큼 다음 농사 경험치를 한 번에 지급한다.

- 닭 생산 1회당 농사 경험치 2
- 소 생산 1회당 농사 경험치 6

대기 생산물이 없으면 수확 요청을 거절하며 경험치도 주지 않는다.

## 저장 모델과 마이그레이션

목장 상태는 별도 저장 키를 만들지 않고 `farm.v2` 안의 `ranch` 하위 상태로 저장한다. 목장 계산과 정의는 농장 본체 파일이 더 커지지 않도록 독립된 목장 모듈에 둔다.

각 사육 칸은 다음 정보를 가진다.

- 고정된 축사 ID와 동물 종류
- 해금 여부
- 현재 사료 수량
- 마지막 정산 시각
- 현재 회차 누적 진행 시간
- 수확 대기 생산물 수량
- 아직 수확하지 않은 완료 회차 수

목장 전체 통계에는 누적 닭·소 생산 회차, 누적 달걀·우유 수확량을 저장한다. 일일 납품 횟수와 농장 증표는 기존 농장 상태를 그대로 사용한다.

기존 `farm.v2`를 읽을 때 `ranch`가 없거나 일부 값이 손상되었으면 다음 원칙으로 정규화한다.

- 기본 닭장만 해금하고 나머지는 잠근다.
- 사료, 대기 생산물, 완료 회차와 통계는 0으로 시작한다.
- 마지막 정산 시각은 현재 서버 시각으로 설정한다.
- 음수, 무한대와 허용량을 넘는 사료는 안전 범위로 보정한다.
- 미래 시각 또는 비정상적으로 큰 진행 시간은 생산물을 만들지 않도록 보정한다.

## 서버 작업과 원자성

농장 기본 조회 응답에 계산된 목장 상태, 동물 정의, 해금 조건과 사료 보유량을 포함한다. 변경 작업은 다음 책임으로 분리한다.

- 사료 제작: 작물 차감, 사료 지급과 생활 제작 기록 갱신
- 사료 투입: 경과 생산 정산 후 지정 축사에 허용량만큼 투입
- 모두 수확: 경과 생산 정산 후 생산물과 농사 경험치 지급
- 축사 구매: 경과 생산 정산 후 레벨·증표 검증과 영구 해금

각 변경은 하나의 데이터베이스 트랜잭션에서 최신 `farm.v2`를 잠근 뒤 처리한다. 사료 제작만 `farm.v2 → life-workshop.v1` 순서로 두 저장값을 잠근다. 클라이언트가 보낸 시각, 생산량, 비용과 해금 상태는 신뢰하지 않는다.

동일 수확 또는 구매 요청이 동시에 들어와도 첫 요청이 저장한 최신 상태를 두 번째 요청이 다시 읽으므로 중복 생산물, 경험치와 중복 구매가 발생하지 않는다. 실패한 사료 제작은 작물 차감, 사료 지급과 제작 기록 모두를 롤백한다.

## 농장 화면

농장 내부 탭은 다음 순서로 표시한다.

`농장 홈 / 재배 / 목장 / 납품 / 상점`

목장 화면의 각 동물 카드는 다음 정보를 표시한다.

- 동물 이미지, 이름과 생산물
- 다음 생산까지 남은 시간 또는 사료 부족 상태
- 사료 수량과 축사별 최대 수량
- 현재 수확 가능한 달걀 또는 우유
- 사료 수량 선택과 `사료 넣기`
- 전체 화면 상단의 `모두 수확`

잠긴 카드에는 필요한 농사 레벨, 농장 증표와 현재 충족 여부를 표시한다. 사료가 부족한 상태에는 `생활 제작으로 이동` 동선을 제공하고 작업장의 목장 용품 영역으로 연결한다.

농장 홈에는 수확 가능한 축산물 수와 남은 사료 시간을 요약한다. 목장 탭 배지는 생산물 총개수가 아니라 수확 가능한 축사 수를 표시해 숫자가 과도하게 커지지 않게 한다. 첫 버전에는 목장 푸시 알림을 추가하지 않는다.

장면 배경 위의 목장 콘텐츠 래퍼와 동물 카드는 기존 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`를 사용해 라이트·다크 모드 모두 불투명하게 유지한다. 잠긴 카드 전체에 투명도를 적용하지 않는다.

## 농장 보관함과 납품

농장 품목에 다음 세 가지를 추가한다.

- `compound_feed`: 배합 사료
- `egg`: 달걀
- `milk`: 우유

배합 사료는 축사 투입에만 사용한다. 달걀과 우유는 요리 및 납품에 사용한다.

목장 납품은 별도 횟수를 만들지 않고 기존 농장 일일 납품 목록에 추가한다. 기존 일일 2회 한도를 작물 납품과 공유한다.

| 의뢰 | 요구량 | 보상 |
| --- | ---: | ---: |
| 제빵소 달걀 상자 | 달걀 8개 | 농장 증표 3개 |
| 여관 우유병 묶음 | 우유 6개 | 농장 증표 4개 |

축산물 납품은 씨앗을 보상하지 않는다. 기존 일일 완료 ID와 제한 검사를 사용해 같은 의뢰의 중복 완료와 하루 세 번째 납품을 막는다.

## 신규 요리

신규 요리는 네 종으로 제한하고, 효과 총량과 경험치는 같은 요구 레벨의 기존 요리 범위를 따른다. 신규 축산물에는 희귀 재료 선택을 두지 않는다.

| ID | 이름 | 필요 요리 레벨 | 재료 |
| --- | --- | ---: | --- |
| `country_egg_bread` | 시골식 달걀빵 | 1 | 밀 8, 달걀 4 |
| `herb_omelet` | 허브 오믈렛 | 10 | 달걀 6, 토마토 5, 허브 3 |
| `milk_potato_soup` | 우유 감자 수프 | 20 | 우유 6, 감자 8, 양파 4 |
| `ranch_cream_gratin` | 목장 크림 그라탱 | 35 | 우유 8, 달걀 6, 감자 8 |

달걀과 우유는 기존 농장 재료 소비 경로를 그대로 사용한다. 요리 주문, 재료 절감, 일괄 조리, 완성 음식 저장과 요리 도감도 다른 요리와 동일하게 동작한다.

## 이미지 자산

신규 이미지는 임시 이모지나 기존 이미지 재사용으로 대체하지 않고 현재 농작물·음식 이미지와 같은 계열로 제작한다. 코드 식별자와 파일명을 일치시킨다.

농장 계열 이미지는 현재 `wheat.webp`, `corn.webp`처럼 256×256 정사각형, 따뜻한 아이보리 질감 배경, 중앙에 놓인 손그림풍 단일 피사체, 글자와 테두리 없는 구도를 따른다.

- `public/images/items/farm/chicken.webp`
- `public/images/items/farm/cow.webp`
- `public/images/items/farm/compound_feed.webp`
- `public/images/items/farm/egg.webp`
- `public/images/items/farm/milk.webp`

음식 이미지는 현재 `rustic_bread.webp`, `potato_stew.webp`처럼 투명 배경, 중앙의 완성 음식, 따뜻한 조명과 반입체적인 게임 아이콘 구도를 따른다.

- `public/images/items/cooking/country_egg_bread.webp`
- `public/images/items/cooking/herb_omelet.webp`
- `public/images/items/cooking/milk_potato_soup.webp`
- `public/images/items/cooking/ranch_cream_gratin.webp`

생성 원본은 PNG로 추가한 뒤 기존 이미지 최적화 훅으로 256px WebP 변환한다. 변환 후 원본 PNG가 삭제되고 참조 누락이나 고아 이미지가 없는지 `npm run check-images`로 검증한다. 동물 이미지는 목장 카드 전용이지만 기존 `items` 프로필을 재사용하므로 새 이미지 카테고리는 만들지 않는다.

## 오류 처리

서버는 다음 상황을 구분해 반환하고 화면은 각 원인을 한국어로 안내한다.

- 목장 또는 축사가 잠김
- 잘못된 축사·구매 단계·수량
- 사료 부족 또는 사료통이 가득 참
- 농사 레벨 부족
- 농장 증표 부족
- 사료 제작 재료 부족
- 수확할 생산물이 없음
- 이미 구매한 축사 재구매

사료 투입은 요청량 전체가 들어갈 수 없으면 자동으로 일부만 소비하지 않고 실패시킨다. 화면의 `가득 채우기`는 서버가 반환한 현재 용량을 기준으로 정확한 수량을 요청한다.

## 테스트와 완료 기준

### 순수 로직

- 생산 완료 직전, 정각과 여러 회 경과 계산
- 닭 6회·소 2회의 12시간 사료 상한
- 진행 중 사료 보충 시 현재 회차 진행 시간 보존
- 사료 소진 뒤의 유휴 시간을 소급하지 않음
- 조회와 변경 요청이 같은 생산 결과를 계산함
- 손상된 시각, 음수와 초과 사료 정규화
- 기존 저장 데이터에 기본 닭장을 추가하되 소급 생산하지 않음
- 농사 경험치와 누적 통계 계산

### 서버와 원자성

- 사료 제작 시 작물 차감, 사료 지급과 제작 기록 동시 반영
- 사료 제작 실패 시 전체 롤백
- 동시 수확 요청의 생산물·경험치 중복 지급 방지
- 축사 중복 구매와 조건 우회 차단
- 작물 납품과 축산물 납품이 일일 2회 한도를 공유함
- 신규 요리가 달걀과 우유를 정확히 차감함

### 화면과 자산

- 목장 탭, 잠금 조건, 다음 생산 시각과 완료 배지 렌더링
- 사료 투입과 모두 수확 뒤 최신 서버 상태 동기화
- 생활 제작의 목장 용품 분류와 농장 보유량 표시
- 신규 요리 네 종의 재료 및 보유량 표시
- 모바일 폭과 라이트·다크 모드에서 불투명 표면 유지
- 모든 신규 이미지 참조와 파일 존재 검증

집중 테스트 뒤 전체 테스트, 타입 검사, 린트, 이미지 검사와 프로덕션 빌드를 실행한다. 구현과 검증이 끝나도 별도 요청 없이는 배포하지 않는다.
