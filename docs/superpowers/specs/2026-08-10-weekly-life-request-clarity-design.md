# 주간 생활 의뢰 선택 구조 개선 설계

## 목표

일반 주간 대량 의뢰와 의뢰인 전용 주간 의뢰가 같은 주간 1회 선택권을 사용한다는 사실을 사용자가 선택 전후 모두 명확히 이해할 수 있게 한다. 전용 의뢰가 일반 의뢰와 같은 납품 조건으로 보이는 중복도 없앤다.

## 화면 구조

- `주간` 메뉴의 기존 `주간 대량 의뢰` 영역을 `이번 주 의뢰 선택` 영역으로 바꾼다.
- 일반 대량 의뢰와 해금된 의뢰인 전용 의뢰를 같은 선택 영역에 함께 노출한다.
- 카드에는 `일반 대량` 또는 `전용 · 의뢰인 이름`을 표시해 출처를 구분한다.
- 주간 의뢰를 하나 완료하면 선택한 의뢰명을 영역 상단에 표시한다.
- 완료하지 않은 나머지 카드에는 `다른 주간 의뢰 선택으로 마감`을 표시한다. 이를 `납품 완료`로 표현하지 않는다.
- 아직 신뢰 조건을 달성하지 못한 전용 의뢰는 같은 영역 아래의 접힌 `잠긴 전용 의뢰` 목록으로 분리한다.
- `의뢰인` 메뉴에는 신뢰도와 해금 이정표만 남기고, 전용 의뢰는 `주간` 메뉴에서 선택한다고 안내한다.

## 데이터와 규칙

주간 1회 한도와 서버의 `period_limit` 검증은 그대로 유지한다. 완료 ID도 기존 `weekly.completedIds`를 계속 사용하므로 저장 데이터 마이그레이션은 필요 없다.

일반 의뢰와 전용 의뢰의 납품 품목·수량 조합이 완전히 같지 않도록 전용 의뢰의 요구량을 조정한다. 현재 겹치는 로사의 요리 준비 세트와 테오의 미끼 상자가 대상이며, 보상과 해금 조건은 변경하지 않는다.

## 테스트

- 여러 주간 게시판을 생성해 일반 의뢰와 전용 의뢰 사이에 동일한 품목·수량 조합이 없는지 검증한다.
- 주간 선택 모델이 일반 의뢰와 해금된 전용 의뢰를 한 목록으로 묶고 잠긴 전용 의뢰를 분리하는지 검증한다.
- 이미 하나를 선택한 경우 선택한 의뢰명과 나머지 카드의 마감 사유가 렌더링되는지 검증한다.
- 기존 생활 의뢰 서버 한도 테스트를 함께 실행해 두 번째 보상이 계속 차단되는지 확인한다.

## 범위 제외

- 주간 완료 한도를 늘리거나 전용 의뢰에 별도 횟수를 제공하지 않는다.
- 랭킹 1위의 누적 명성 240 산식은 의도된 동작이므로 변경하지 않는다.
- 배포하지 않는다.
