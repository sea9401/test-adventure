# 전투 로그 전용 페이지 통일 설계

## 목표

전투 결과 화면의 작은 내부 스크롤 영역을 없애고, 아레나·협동 보스·사냥·숙련의 탑·폭풍 원정·대련·영지 전투 등 플레이어가 확인하는 전투 로그를 별도 페이지 경험으로 통일한다. 긴 로그에서도 이전 화면 복귀와 페이지 맨 위 이동을 쉽게 제공한다.

## 화면 정책

- 이미 고유 URL이 있는 아레나 일반전, 아레나 토너먼트, 협동 보스 공격 기록은 현재 URL을 전용 로그 페이지로 사용한다.
- 결과 화면 안에 리플레이가 포함되던 전투는 작은 요약 카드와 `전체 전투 로그 보기` 버튼만 표시하고 공용 `/battle/log/[handoffId]` 페이지로 이동한다.
- 전용 페이지의 전투 로그는 고정 높이와 중첩 스크롤을 쓰지 않고 문서 흐름에서 끝까지 펼친다.
- 전용 페이지 상단에는 뒤로가기 버튼을 두고, 충분히 아래로 스크롤하면 우측 하단에 `맨 위로` 버튼을 표시한다.
- 결과 뒤의 다음 전투·다음 층 같은 행동 버튼은 원래 결과 화면의 요약 카드에 유지한다. 로그 페이지에서 돌아온 뒤 계속 진행할 수 있다.

## 데이터 전달

서버에 저장된 리플레이는 기존 `replayId`와 조회 API를 그대로 사용한다. 아직 서버 저장 대상이 아닌 일회성 전투 결과는 DB에 새 행을 만들지 않고 현재 브라우저 탭의 `sessionStorage`에 짧은 수명의 handoff 레코드를 저장한다.

handoff 레코드는 임의 ID, 버전, 만료 시각과 직렬화 가능한 리플레이 표시 정보만 포함한다. 메모리 백업도 함께 두어 `sessionStorage`가 차단된 환경의 같은 SPA 이동을 지원한다. 만료되거나 손상된 ID는 전투 정보를 노출하지 않고 오류 안내와 뒤로가기를 제공한다.

격자 던전의 문자열 전투 로그도 같은 handoff 저장소를 사용하되 구조화 리플레이와 구분되는 `text` 종류로 저장한다.

## 공용 컴포넌트

- `BattleScene`은 기존 내부 스크롤형과 전용 페이지 자연 흐름형 로그 레이아웃을 지원한다.
- `ReplayBattleScene`은 기본적으로 전용 페이지 이동 카드를 렌더하고, 이미 전용 URL 안에서 사용할 때만 페이지 모드로 실제 리플레이를 렌더한다.
- 공용 전투 로그 페이지는 저장된 handoff 종류에 따라 구조화 리플레이 또는 문자열 로그를 렌더한다.
- `BattleLogScrollTopButton`이 스크롤 위치를 감시하고 부드러운 맨 위 이동을 담당한다.

## 오류와 호환성

- 기존 서버 저장 리플레이의 소유권·만료 검사는 현재 API를 그대로 따른다.
- handoff 저장 실패 시 이동하지 않고 현재 결과 화면에 안내한다.
- 직접 주소 입력, 새 탭 복원 또는 만료로 handoff를 찾을 수 없으면 빈 페이지 대신 복귀 가능한 오류 카드를 표시한다.
- 관리자·개발 하니스는 기존 임베디드 렌더링을 유지할 수 있도록 명시적 모드를 지원한다.

## 검증

- handoff 쓰기·읽기·만료·손상 데이터 제거를 단위 테스트한다.
- `BattleScene` 페이지 모드에서 고정 높이 및 내부 `overflow-y-auto`가 사라지는지 회귀 테스트한다.
- 저장형 리플레이와 일회성 리플레이가 공용 페이지에서 열리는지 관련 컴포넌트 타입 검사를 수행한다.
- 집중 테스트, 전체 테스트, TypeScript, ESLint, production build를 실행한다.
- 이번 변경은 로컬 커밋까지만 수행하며 배포와 점검 모드는 변경하지 않는다.
