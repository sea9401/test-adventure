# 거래 가능한 어종 표본 설계

## 배경

낚시 도감은 발견 어종 수 5·10·20·30·40·46·50종에서 SP를 1씩 지급해 최대
SP 7을 제공한다. 장비 도감이나 직업 해금은 일반 전투 진행 중에도 자연스럽게
쌓이지만, 낚시를 하지 않는 이용자는 낚시 도감 SP를 얻을 수 없다. 이 차이는 생활
콘텐츠 선택이 아니라 전투 성장 손실처럼 느껴질 수 있다.

등록된 어종의 `도감 등록 권리`를 거래 가능한 표본으로 추출할 수 있게 한다. 낚시
이용자는 희귀 어종 발견을 수익으로 전환하고, 비낚시 이용자는 골드로 도감 SP를
보완할 수 있다. 표본은 어획 기록이나 랭킹 점수를 이전하지 않으며 등록 권리만
이동한다.

## 목표

- 등록된 개별 어종을 거래 가능한 수량형 표본으로 추출할 수 있다.
- 표본 사용자는 비어 있는 해당 어종 칸의 등록 권리와 그에 따른 도감 SP만 얻는다.
- 판매자가 표본을 추출해도 개인 최대어·누적 어획·최초 어획·랭킹 기록은 보존된다.
- 도감 SP 감소로 현재 스킬 로드아웃이 한도를 넘는 추출은 서버에서 차단한다.
- 구매해 등록한 권리도 같은 규칙으로 다시 추출해 거래할 수 있다.
- 기존 소모품 인벤토리·거래소·우편 정산 흐름을 재사용한다.
- 기존 낚시 도감 데이터는 별도 일괄 마이그레이션 없이 안전하게 호환한다.

## 제외 범위

- 낚시 도감 SP 마일스톤과 최대 SP 7 변경
- 물고기 출현율, 낚시 난이도, 코인·경험치·어획물 보상 변경
- 개인 최대어와 누적 어획 기록 자체의 거래
- 표본 사용으로 낚시 숙련도·퀘스트·업적·랭킹 점수를 지급하는 기능
- 표본 전용 거래소 종류나 별도 경매장 추가
- 추출 재료, 추출 골드 비용, 재추출 대기시간 추가

## 핵심 규칙

1. 현재 등록 권리를 가진 어종만 표본으로 추출할 수 있다.
2. 추출하면 해당 등록 권리는 사라지고 같은 어종 표본 1개가 인벤토리에 생긴다.
3. 표본은 해당 어종의 등록 권리가 비어 있을 때만 사용할 수 있다.
4. 표본을 사용하면 1개를 소비하고 등록 권리를 얻는다.
5. 등록 권리의 출처는 구분하지 않는다. 구매한 표본으로 등록한 권리도 다시 추출할 수
   있다.
6. 직접 어획 기록은 추출·사용과 무관하게 영구 보존한다.
7. 등록 권리가 없는 어종을 직접 낚으면 자동으로 등록 권리를 다시 얻는다.
8. 등록 권리가 있는 동안 같은 어종을 반복해서 낚아도 표본이 추가 생성되지는 않는다.
   권리를 추출한 뒤 같은 어종을 다시 낚아 재등록한 경우에는 다시 1회 추출할 수 있다.
9. 모든 어종은 같은 규칙을 사용한다. 등급별 거래 제한은 두지 않는다.
10. 추출 자체는 무료이며 기존 거래소 등록·판매 수수료만 적용한다.

## 도감 데이터 모델

### 등록과 어획 기록 분리

현재 `FishCodexEntry.discovered`는 도감 등록, 직접 어획 여부, SP, 랭킹 계산을 함께
표현한다. 이를 다음 두 상태로 분리한다.

- `registered`: 현재 도감 등록 권리를 보유하는지 나타낸다. 도감 발견 수와 SP는 이 값만
  사용한다.
- `caughtEver`: 이용자가 해당 어종을 직접 한 번 이상 낚았는지 나타낸다. 개인 기록과
  낚시 랭킹은 이 값과 실제 어획 수치만 사용한다.

최대어, 누적 어획, 최초 어획 시각, 최대어 갱신 시각은 기존처럼 같은 어종 엔트리에
보존하되 `caughtEver`가 참일 때만 개인 기록으로 인정한다. 표본만 사용한 이용자는
`registered: true`, `caughtEver: false` 상태가 될 수 있으며 어획 수치가 증가하지 않는다.

### 기존 저장 호환

`fishing-codex.v1` 키를 유지한다. 파서는 옛 `discovered: true` 엔트리를
`registered: true`, `caughtEver: true`로 해석한다. 따라서 기존 이용자는 등록 권리나
어획 기록을 잃지 않는다. 새 형식으로 저장된 뒤에도 파서는 옛 필드를 방어적으로
수용한다.

직접 잡지 않은 등록 권리를 다시 추출해 `registered`와 `caughtEver`가 모두 거짓이 되면
빈 엔트리를 제거할 수 있다. 직접 어획 기록이 있는 엔트리는 `registered: false`가 되어도
계속 보존한다.

### 계산 기준

- 도감 등록 수, 다음 마일스톤, 도감 SP: `registered`인 어종 수
- 도감에서 공개되는 어종 정보: `registered` 또는 `caughtEver`
- 개인 최대어, 누적 어획, 낚시 점수와 랭킹: `caughtEver`와 실제 어획 수치
- 반복 퀘스트·일일 과제·숙련도·업적: 기존 직접 어획 이벤트만

구매한 표본은 낚시 랭킹이나 직접 어획 기반 진행도를 올리지 않는다.

## 표본 카탈로그와 인벤토리

어종별 표본 정의는 `FISH` 카탈로그에서 파생한다. 새 어종을 추가하면 표본 ID, 이름,
아이콘, 등급이 자동으로 생기며 별도 수동 목록을 관리하지 않는다. 거래소용 ID는 어종
ID와 충돌하지 않는 고정 접두사를 사용하고 서버 파서가 표본 ID를 다시 `FishId`로
복원한다.

표본 보유량은 전용 저장 키 `fishing-specimens.v1`에 어종별 비음수 정수 수량으로
저장한다. 알 수 없는 어종, 음수, 소수, 비정상적으로 큰 입력은 파서와 서버 증감 함수가
정규화하거나 거부한다.

인벤토리 `소모품` 탭에 `어종 표본` 섹션을 추가한다. 표본 카드는 다음을 표시한다.

- 어종명, 아이콘, 등급
- 보유 수량
- 현재 도감 등록 여부
- 등록 권리가 비어 있을 때 활성화되는 `도감 등록` 버튼
- 기존 소모품과 같은 거래소 등록 진입점

이미 등록된 어종의 표본도 보관하거나 거래할 수 있으므로 숨기지 않는다. 등록 버튼만
비활성화하고 이유를 표시한다.

## 도감 사용자 경험

### 표본 추출

등록 권리를 가진 어종 카드에 `표본 추출` 버튼을 표시한다. 직접 잡은 적이 없고 표본으로
등록한 어종도 같은 버튼을 사용한다.

추출 전 서버가 최신 등록 수, 도감 SP, 전체 SP 예산, 현재 로드아웃 사용 SP를 계산한다.

- 추출 후에도 도감 SP가 같으면 등록 해제와 표본 생성을 알리는 일반 확인창을 표시한다.
- SP 마일스톤을 이탈하면 `도감 SP +7 → +6`, `전체 SP 34 → 33`처럼 전후 값을 강조한
  경고창을 표시한다.
- 새 전체 SP 예산이 현재 로드아웃 사용 SP보다 작으면 추출을 실행하지 않는다. 이용자에게
  필요한 SP만큼 장착 스킬을 먼저 해제하도록 안내한다.

배운 스킬 목록은 변하지 않으며 스킬을 자동 해제하지 않는다. 이용자가 로드아웃을 직접
조정한 뒤 다시 추출한다.

경고창을 오래 열어 둔 사이 상태가 바뀔 수 있으므로 확인 요청에는 이용자가 확인한 SP
전후 값을 포함한다. 서버가 트랜잭션 안에서 다시 계산한 값과 다르면 추출하지 않고 최신
값으로 경고를 다시 표시한다.

### 표본 등록

인벤토리에서 `도감 등록`을 누르면 어종명과 표본 1개 소비를 확인한다. 서버는 최신 도감과
표본 수량을 다시 검사한다.

- 등록 권리가 비어 있으면 표본 1개를 소비하고 `registered`를 참으로 바꾼다.
- 이미 등록된 어종이면 표본을 소비하지 않고 거부한다.
- 직접 잡은 적이 없는 이용자에게는 어획 기록 없는 표본 등록임을 도감에 구분해 표시한다.
- 등록으로 SP 마일스톤을 달성하면 획득한 도감 SP와 전체 SP 증가를 성공 안내에 포함한다.

## 서버 경계와 트랜잭션

### 추출 경로

표본 추출 전용 서버 경로는 다음을 하나의 트랜잭션에서 처리한다.

1. 캐릭터, 스킬, 직업·숙련도, 낚시·장비 도감, 표본 인벤토리 등 SP 예산과 수량에 필요한
   데이터를 기존 표준 순서로 잠근다.
2. 어종 ID와 현재 등록 권리를 검증한다.
3. 공용 SP 예산 계산과 스킬 비용 계산을 사용해 추출 후 예산을 구한다.
4. 로드아웃 초과 여부와 SP 감소 확인값을 검증한다.
5. 등록 권리를 제거하고 표본 수량을 1 증가시킨다.
6. 경제 이벤트에 어종, 추출 전후 등록 수와 SP, 추출 수량을 기록한다.

미리보기나 클라이언트 계산은 안내용일 뿐이며 추출 가능 여부의 권위는 이 트랜잭션에
있다.

### 등록 경로

표본 등록 전용 서버 경로는 도감과 표본 인벤토리를 같은 트랜잭션에서 잠근 뒤 등록 여부와
수량을 검증한다. 성공할 때만 표본 1개 차감과 등록 권리 추가를 함께 커밋한다. 등록 직후
도감 수, 도감 SP, 전체 SP와 남은 표본 수량을 반환한다.

### 직접 어획

기존 낚시 성공 트랜잭션은 직접 어획 기록을 갱신한다. 등록 권리가 비어 있으면 같은
트랜잭션에서 `registered`를 다시 참으로 만든다. 이미 등록돼 있으면 기록만 갱신하며
표본이나 추가 등록 권리를 지급하지 않는다.

모든 경로는 동일한 순수 도감 전이 함수를 사용해 추출·등록·직접 어획의 상태 규칙이 서로
어긋나지 않게 한다.

## 거래소 연결

표본은 기존 거래소의 수량형 `consumable`로 취급한다. 별도 거래 종류나 테이블을 추가하지
않는다. 표본 카탈로그 판정과 표시명 해석을 기존 소모품 화이트리스트에 연결한다.

- 등록: 판매자의 `fishing-specimens.v1`에서 수량을 원자적으로 차감한다.
- 고정가·묶음·부분 구매·구매 주문: 기존 수량형 소모품 규칙과 가격 제한을 사용한다.
- 구매·낙찰: 기존 우편 수령 흐름으로 구매자의 표본 인벤토리에 지급한다.
- 취소·만료·유찰: 판매자의 표본 인벤토리로 정확한 잔여 수량을 돌려준다.
- 판매 수수료와 등록 제한: 기존 거래소 정책을 그대로 적용한다.

거래소는 표본 사용이나 도감 등록 여부를 검사하지 않는다. 구매자가 이미 등록한 어종도
투자·재판매 목적으로 살 수 있다. 등록 가능 여부는 표본 사용 시점에만 검사한다.

## 오류 처리

- 미등록 어종 추출: 상태를 새로고침하고 `이미 비어 있는 도감입니다`를 표시한다.
- 추출 후 로드아웃 초과: 필요한 SP와 현재 사용량을 보여 주고 추출하지 않는다.
- 확인한 SP와 서버 값 불일치: 최신 전후 값으로 경고창을 갱신하고 재확인을 요구한다.
- 표본 부족: 보유량을 새로고침하며 아무 상태도 변경하지 않는다.
- 이미 등록된 표본 사용: 표본을 소비하지 않고 등록돼 있음을 안내한다.
- 동시 추출·사용·거래 등록: 잠금 뒤 재검증해 한 요청만 성공하게 한다.
- 거래 취소·만료·우편 중복 수령: 기존 거래소 원장의 멱등성과 상태 검사를 유지한다.
- 네트워크 실패: 성공 여부를 추측하지 않고 도감과 표본 보유량을 다시 조회한다.

오류 응답은 안정적인 코드와 최신 등록 수·SP·표본 수량을 함께 반환해 UI가 전체 페이지
새로고침 없이 복구할 수 있게 한다.

## 접근성과 반응형

- 추출 경고창은 포커스 이동, ESC 닫기, 배경 스크롤 잠금 등 기존 공용 모달 규칙을 따른다.
- SP 감소와 차단 사유를 색상만이 아니라 텍스트와 전후 숫자로 전달한다.
- 위험 동작 버튼은 `표본 추출`처럼 결과가 분명한 문구를 쓰고 기본 포커스로 두지 않는다.
- 모바일에서는 표본 카드의 어종명·수량·등록 상태가 먼저 보이고 동작 버튼은 줄바꿈한다.
- 표본 목록이 길어지면 기존 인벤토리 페이지네이션과 등급·이름 정렬을 재사용한다.

## 검증

### 도감과 SP

- 옛 `discovered` 엔트리가 등록 권리와 직접 어획 기록을 모두 유지하는지 검증한다.
- 표본 추출 후 `registered`만 사라지고 최대어·누적 어획·시각이 보존되는지 검증한다.
- 등록 수가 마일스톤을 이탈할 때만 도감 SP가 1 감소하는지 검증한다.
- SP 감소 후 로드아웃이 예산을 넘으면 추출이 차단되고 어떤 상태도 바뀌지 않는지 검증한다.
- 배운 스킬 목록과 어획 기반 진행도가 추출로 변하지 않는지 검증한다.

### 표본 사용과 재어획

- 비어 있는 어종에 표본을 사용하면 수량 1 감소와 등록 권리 추가가 함께 일어나는지
  검증한다.
- 이미 등록된 어종에는 표본을 소비하지 않는지 검증한다.
- 구매 표본 등록이 직접 어획 수·최대어·랭킹 점수를 올리지 않는지 검증한다.
- 구매 등록 권리를 다시 추출할 수 있는지 검증한다.
- 추출 후 직접 같은 어종을 잡으면 기록을 이어서 갱신하고 등록 권리를 복원하는지 검증한다.
- 이미 등록된 상태의 반복 어획이 표본 수량을 늘리지 않는지 검증한다.

### 거래소와 동시성

- 표본 묶음 등록, 부분 구매, 구매 주문, 취소, 만료, 낙찰, 우편 수령에서 총수량이 보존되는지
  검증한다.
- 추출과 거래 등록, 사용과 거래 등록, 중복 사용을 동시에 요청해 표본 복제가 발생하지
  않는지 검증한다.
- 알 수 없는 표본 ID와 잘못된 수량이 등록·구매·우편 지급 경로에서 거부되는지 검증한다.

### UI

- 도감 등록 상태에 따라 추출 버튼과 기록 보존 상태가 올바르게 표시되는지 검증한다.
- SP 감소 경고와 로드아웃 초과 차단 안내가 정확한 전후 값을 표시하는지 검증한다.
- 소모품 탭에서 표본 수량, 등록 가능 여부, 거래소 진입점이 표시되는지 검증한다.
- 모바일·데스크톱과 키보드 조작에서 모달과 표본 카드가 접근 가능한지 확인한다.

## 완료 기준

- 낚시를 하지 않는 이용자가 거래소에서 개별 어종 표본을 구매해 최대 SP 7까지 도감
  마일스톤을 달성할 수 있다.
- 낚시 이용자는 등록 권리를 표본으로 판매한 뒤 같은 어종을 다시 낚아 재등록할 수 있다.
- 표본 이동 전후로 개인 어획 기록과 낚시 랭킹이 변하지 않는다.
- 어떤 추출도 현재 장착 스킬 예산을 무효 상태로 만들지 않는다.
- 표본의 추출·사용·거래·반환 전 경로에서 등록 권리와 표본 수량이 복제되거나 사라지지
  않는다.
