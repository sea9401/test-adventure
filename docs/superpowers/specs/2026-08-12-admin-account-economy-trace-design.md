# 관리자 계정 재화 흐름 분석 설계

## 목표

관리자가 닉네임 또는 유저 ID로 한 계정의 생산, 현재 보유, 개인 소비, 거래 상대, 길드 창고 이동을 반복 조회할 수 있게 한다. 운영 DB에 직접 접속해 수동 SQL을 실행하지 않아도 흑우 계정 조사와 같은 근거를 관리자 화면에서 얻는 것이 목적이다.

## 접근 방식

기존 `경제 로그` 탭 상단에 `계정 재화 흐름 분석` 패널을 추가한다. 별도 관리자 탭은 분석 기능이 기존 경제 로그와 겹치고 탐색 위치를 늘리므로 만들지 않는다. 유저 상세에는 대상 ID를 포함한 경제 로그 딥링크를 제공한다.

분석 API는 관리자 전용 읽기 `GET /api/admin/economy-trace`로 제공한다. `user`에는 정확한 닉네임 또는 유저 ID를 받고 `days`는 7·30·90만 허용한다. 기본 기간은 30일이다.

## 보고서 구성

- 계정 닉네임, ID, 현재 길드와 역할
- 기간 내 벌목·채광·농사·낚시 생산량과 품목별 수량
- 현재 골드·보관 골드와 생산 품목의 현재 개인 재고
- 거래소 상대별 구매·판매 품목, 수량, 골드 증감
- 대상 계정이 직접 수행한 길드 창고 입고·출고 품목과 수량
- 제작 수수료, 상점 판매, 거래소 등 생산 외 주요 경제 이벤트
- `재료 거래소 판매 있음`, `길드 창고 입고 있음` 같은 직접 이전 근거 요약

생산물은 스택 수량으로 저장되어 개별 일련번호가 없다. 따라서 보고서는 확인된 직접 이전과 현재 잔액을 보여 주되, 생산품 한 개의 완전한 계보나 로그에 품목별 차감이 없는 제작 소비량을 확정하지 않는다. 이 한계를 화면에 상시 표시한다.

## 데이터 처리

API는 `economy_events`를 기간 내 이벤트·품목·상대별로 DB에서 집계해 대량 생활 로그를 애플리케이션으로 모두 가져오지 않는다. 현재 잔액은 `character.v2`, 길드 정보는 `guild_members`와 `guilds`, 길드 창고 이동은 대상이 `actor_user_id`인 `guild_activity_log`만 읽는다. 다른 길드원의 이동은 대상 계정의 이전으로 표시하지 않는다.

보고서 변환은 부수효과 없는 `buildAccountEconomyTrace` 함수가 맡는다. API는 인증·조회만 담당하고 UI와 테스트는 동일한 응답 타입을 공유한다.

## UI

경제 로그 탭에서 닉네임/ID와 기간을 입력한 뒤 명시적으로 조회한다. 유저 상세 딥링크로 들어오면 전달된 ID를 즉시 조회한다. 결과는 기존 불투명 표면 상수로 만든 요약 카드와 표로 표시하고, 거래 상대가 없거나 길드 이동이 없으면 `없음`을 분명히 표시한다.

## 오류와 보안

- 관리자 인증 실패는 기존 `requireAdmin` 응답을 그대로 사용한다.
- 빈 식별자와 허용되지 않은 기간은 400, 계정이 없으면 404를 반환한다.
- 조회는 GET과 SELECT만 사용하며 지급·회수·제재 기능은 포함하지 않는다.
- 응답에는 이메일, IP, 인증 정보 같은 분석에 불필요한 개인정보를 포함하지 않는다.

## 검증

- 기간 파싱, 생산 집계, 재료 거래 상대, 길드 창고 본인 이동, 빈 결과와 추적 한계를 순수 함수 테스트로 검증한다.
- 보고서 컴포넌트가 상대 이름, 없음 상태, 추적 한계를 표시하는지 정적 렌더 테스트로 검증한다.
- TypeScript, ESLint, 전체 Vitest, 이미지 검사, Next.js 16 프로덕션 빌드를 실행한다.
