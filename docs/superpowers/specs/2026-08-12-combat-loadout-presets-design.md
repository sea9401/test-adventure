# 통합 전투 프리셋 설계

## 목표

장비가 많아진 상황에서 스킬, 전투패턴, 장비를 각각 다시 맞추는 수고를 줄인다. 일반 전투용 통합 프리셋 5칸을 제공하고, 저장과 적용 모두 세 구성을 한 번에 처리한다.

기존 스킬 전용 프리셋 10칸과 아레나 전용 전투 템플릿은 그대로 유지한다. 새 기능은 장비만 따로 저장하는 프리셋이 아니며, 아레나 세팅에도 영향을 주지 않는다.

## 검토한 접근

1. **별도 통합 전투 프리셋을 둔다 — 채택.** 일반 전투 구성이라는 독립된 의미와 저장소를 가지며 기존 기능과 데이터 호환성을 유지한다.
2. 기존 스킬 프리셋에 장비와 전투패턴을 추가한다. 화면 수는 적지만 기존 스킬 프리셋의 의미와 10칸 데이터 형식을 바꾸고, 스킬만 빠르게 바꾸려는 사용 흐름을 훼손한다.
3. 아레나 템플릿을 여러 칸으로 확장해 일반 전투에도 적용한다. 구현 일부를 공유할 수 있지만 일반 세팅과 공격·수비용 아레나 스냅샷이 결합되어 한쪽을 바꿀 때 다른 쪽이 예상 밖으로 달라진다.

## 사용자 경험

- 캐릭터 메뉴와 상단 캐릭터 하위 메뉴에 `전투 프리셋` 진입 항목을 추가한다.
- `/character/presets` 화면은 고정된 5개 슬롯을 항상 표시한다.
- 빈 슬롯에서는 현재 세팅을 저장한다. 이름이 비어 있으면 `프리셋 N`을 사용한다.
- 저장된 슬롯은 이름, 저장 시각, 장착 스킬 수, 전투패턴 행동 수, 장착 장비 수를 요약한다.
- 저장된 슬롯에서 `적용`, `현재 세팅으로 덮어쓰기`, `삭제`를 제공한다.
- 적용 성공 후 해당 슬롯을 현재 적용 중으로 표시하고 스킬·전투패턴·장비가 함께 변경되었음을 알린다.
- 저장 후 스킬을 잊었거나 장비를 판매·분해한 경우, 적용 가능한 항목만 복원하고 제외된 스킬 및 장비 수를 결과 안내에 명시한다. 사라진 장비의 슬롯은 빈 슬롯이 되어 다른 프리셋의 장비가 남지 않게 한다.
- 본문과 슬롯 카드는 `SURFACE_CARD`, 세부 요약은 `SURFACE_INSET`, 경고는 `SURFACE_ACCENT`를 사용해 라이트·다크 모드 모두 불투명 표면을 유지한다.

## 데이터 모델

새 save key `combat-loadout-presets.v1`에 길이 5의 nullable 배열을 저장한다. 배열 인덱스가 화면 슬롯 번호이므로 중간 슬롯을 삭제해도 다른 슬롯 번호가 바뀌지 않는다.

각 저장 항목은 다음 필드를 가진다.

- `name`: 최대 24자의 표시 이름
- `savedAt`: ISO 저장 시각
- `skills`: 장착 스킬 ID를 우선순위 순으로 저장한 스냅샷
- `pattern`: 검증된 활성 전투패턴 또는 `null`
- `equipment`: 장비 슬롯에서 장비 개체 iid로 이어지는 스냅샷

방어적 파서는 배열 외 입력을 빈 5칸으로 처리하고, 이름·날짜·스킬·장비 필드의 타입을 검증하며, 전투패턴은 기존 `parseCombatPattern`으로 다시 검증한다. 5칸을 넘는 데이터는 무시한다.

## API와 원자성

`/api/v2/me/combat-loadout-presets`에 다음 인터페이스를 둔다.

- `GET`: 5개 슬롯과 현재 세팅에 정확히 일치하는 활성 슬롯 번호를 반환한다.
- `POST { action: "save", slot, name? }`: 현재 `skills.v2.equipped`, `skills.v2.pattern`, `equipment.v2.equipped`를 지정 슬롯에 함께 저장한다.
- `POST { action: "apply", slot }`: 저장 항목을 현재 세팅에 함께 적용한다.
- `POST { action: "delete", slot }`: 지정 슬롯만 비운다.

모든 변경은 서버가 인증 사용자와 슬롯 범위를 검증한 뒤 하나의 DB 트랜잭션에서 수행한다. 같은 사용자의 동시 요청을 직렬화하도록 프리셋 save row를 먼저 잠근다. 현재 세팅 저장은 `equipment.v2 → skills.v2`를 잠가 일관된 스냅샷을 만들고, 적용은 프로젝트의 전역 순서에 맞춰 `character.v2 → equipment.v2 → skills.v2 → proficiency.v2`를 잠근다. 스킬은 현재 학습 상태와 SP 예산으로 `sanitizeLoadout`을 거치고 생활 스킬 규칙을 보존한다. 장비는 현재 보유 중이며 저장 슬롯과 실제 장비 슬롯이 일치하는 개체만 적용한다. 스킬 상태를 갱신할 때 기존 스킬 전용 프리셋과 전투패턴 프리셋 라이브러리 등 다른 필드는 보존한다.

적용 응답은 최종 장착 스킬, 장비, 활성 전투패턴과 제외된 스킬·장비 요약을 반환한다. 트랜잭션 중 오류가 발생하면 세 구성 모두 변경하지 않는다.

저장된 `pattern`이 `null`이면 적용 시 현재 사용자 전투패턴도 `null`로 바꿔 엔진 기본 패턴을 사용한다. 활성 슬롯은 스킬 순서, 검증된 전투패턴, 6개 장비 슬롯의 iid가 모두 정확히 같은 경우에만 표시한다.

## 구성 요소

- `combatLoadoutPresets` 도메인 모듈: 상수, 타입, 파서, 현재 일치 판정, 적용용 스킬·장비 정규화
- API route: 조회, 현재 스냅샷 저장, 원자적 적용, 삭제
- `V2CombatLoadoutPresetsView`: 5개 슬롯 UI와 요청 상태·성공·경고·오류 안내
- 캐릭터 메뉴, 상단 하위 메뉴, `/character/presets` 페이지 연결

아레나 코드는 새 일반 프리셋을 읽지 않는다. 새 도메인 모듈이 아레나 저장소를 재사용하지도 않는다.

## 오류 처리

- 인증 실패는 `401`, 잘못된 JSON·action·slot은 `400`, 빈 슬롯 적용은 `404`로 응답한다.
- 저장/적용 중에는 해당 화면의 작업 버튼을 비활성화해 중복 요청을 막는다.
- 조회 실패에는 재시도 가능한 오류 배너를 표시한다.
- 적용 시 제외 항목이 있으면 성공 메시지와 별도로 경고 요약을 표시한다. 이는 부분 실패가 아니라 현재 보유·학습 상태에 맞춘 정상 적용 결과다.

## 테스트와 검증

- 도메인 단위 테스트: 손상 데이터 방어, 정확히 5칸 유지, 이름/목록 정규화, 현재 프리셋 일치, 미학습 스킬·미보유 또는 슬롯 불일치 장비 제외
- API 테스트: 인증/입력 검증, 현재 세팅 저장, 지정 슬롯 덮어쓰기·삭제, 한 트랜잭션에서 세 구성 적용, 다른 스킬 상태 필드 보존, 제외 항목 응답
- UI 테스트: 5칸 렌더링, 빈/저장/활성 상태, 요약과 경고, 불투명 surface 사용, 메뉴·라우트 진입
- 관련 Vitest, ESLint, TypeScript 검사, 전체 Vitest 및 Next.js build를 완료 전 실행한다.

## 제외 범위

- 슬롯 구매·확장
- 프리셋 순서 이동·복제·공유
- 전투 중 프리셋 변경
- 스탯 배분, 직업, 칭호, 소비 아이템, 아레나 템플릿 저장
- 기존 스킬 전용 및 전투패턴 전용 프리셋의 통합·삭제
