# 원소 계열 전직 마법서 우편 설계

## 목표

원소군주 또는 태초술사로 처음 전직한 이용자에게 해당 직업의 조합형 주문식 정보를 우편으로 한 번 안내한다. 전직 화면의 짧은 설명을 보완하고, 이용자가 우편함에서 발현 조건과 실제 효과 수치를 다시 확인할 수 있게 한다.

## 대상과 발송 정책

- 원소군주 최초 전직에는 `오원소 폭주`의 기본형과 12가지 주문식을 안내한다.
- 태초술사 최초 전직에는 `태초회귀`의 기본형과 12가지 주문식을 안내한다.
- 각 직업의 마법서는 계정 내 해당 캐릭터가 그 직업으로 처음 전직할 때 한 번만 발송한다.
- 같은 직업 재전직, 과거 직업 재방문, 이미 전직 이력이나 누적 숙련도가 있는 직업에는 발송하지 않는다.
- 기능 도입 전에 이미 두 직업을 거친 이용자에게는 소급 발송하지 않는다.
- 현재 직업과 대상 직업이 같으면 직업 이력 이상 여부와 관계없이 발송하지 않는다.

최초 전직 여부는 전직 처리 전의 `proficiency.v2`를 기준으로 판정한다. 대상 직업이 현재 직업과 다르고, `jobHistory`에 없으며, 해당 직업의 누적 숙련도가 0일 때만 최초 전직으로 본다.

## 우편 형식

기존 사용자 쪽지를 재사용하지 않고 읽기 전용 시스템 우편 종류 `job_spellbook`을 추가한다. `marketplace_inbox`의 기존 `kind`와 JSON payload를 사용하므로 제목 컬럼 추가나 DB 마이그레이션은 하지 않는다.

- 우편 제목/종류 라벨: `마법서`
- 발송자: 시스템 우편으로 처리하며 사용자 발송자 정보는 두지 않는다.
- payload: 대상 `jobId`, 안내할 `skillId`, 발송 시 생성한 본문 `text`
- 목록·알림 미리보기: `원소군주 전직 마법서가 도착했습니다.` 또는 `태초술사 전직 마법서가 도착했습니다.`
- 상세 본문: payload의 `text`를 줄바꿈을 보존해 표시한다.
- 보상과 수령 버튼은 없으며, 상세를 열면 일반 정보성 우편처럼 읽음·완료 처리한다.
- 받은 우편에만 표시하고 보낸 우편 기록에는 포함하지 않는다.

새 우편 종류는 payload 파서, claim 상태 판정, 클라이언트 `InboxItem` 타입, 우편함과 통합 알림·우편 종의 종류 라벨 및 본문/미리보기 처리에 모두 추가한다. 알 수 없거나 손상된 payload는 기존 정책대로 유효하지 않은 우편으로 다룬다.

## 마법서 본문 생성

본문 생성은 서버와 UI에서 재사용 가능한 순수 함수로 분리하고, 원소군주와 태초술사의 직업 ID를 지원한다. 지원하지 않는 직업에는 마법서를 생성하지 않는다.

본문은 표가 아닌 일반 텍스트 목록으로 구성한다.

1. 전직 축하와 대상 스킬의 이름·설명
2. 아무 주문식도 일치하지 않을 때 사용하는 기본형의 효과와 MP·발동률
3. 선언 순서대로 나열한 12가지 주문식
4. 각 주문식의 이름, 필요한 보유 주문, 필요한 장착 주문, 피해를 포함한 모든 효과 수치
5. 가장 먼저 일치하는 주문식 하나만 발현한다는 우선순위 규칙
6. 원소군주의 `원소 공명`, 태초술사의 `근원공명`을 함께 장착했을 때 대상 스킬에 붙는 추가 효과

주문 이름, 조건, 효과는 `V2_SKILLS`의 `castVariants`, `requiredLearnedSkillIds`, `requiredEquippedSkillIds`, `effects`, `equippedSynergies`에서 읽는다. 효과 문구는 기존 스킬 상세 표시의 효과 설명기를 재사용할 수 있게 공개 순수 함수로 정리한다. 마법서 전용 수치나 12개 주문식 설명을 별도로 하드코딩하지 않는다.

본문은 발송 시점의 실제 스킬 데이터로 한 번 생성해 payload에 저장한다. 이후 밸런스가 바뀌어도 이미 받은 우편은 발송 당시 내용대로 남고, 변경 뒤 최초 전직한 이용자부터 새 수치를 받는다.

## 전직 트랜잭션

`advance-class`의 코어루프 전직 경로에서 대상 직업과 최초 전직 여부를 계산한다. 캐릭터, 스킬, 숙련도 저장이 성공한 뒤 같은 DB 트랜잭션 안에서 마법서 우편 행을 추가한다.

캐릭터 저장 행 잠금과 갱신된 `jobHistory`가 동시 요청을 직렬화하므로, 같은 전직 요청이 겹쳐도 첫 요청만 최초 전직 조건을 만족한다. 마법서 생성 또는 삽입이 실패하면 전직 전체를 롤백해 전직은 됐지만 최초 마법서는 유실되는 상태를 만들지 않는다.

응답 형식과 전직 완료 UI는 바꾸지 않는다. 새 우편은 기존 우편 미확인 수 폴링에 잡히므로 전직 직후 알림 종에서 확인할 수 있다.

## 오류 및 호환성

- 지원 대상 직업이 아니면 기존 전직 흐름만 수행한다.
- 대상 스킬이나 주문식 데이터가 없거나 예상한 12종이 아니면 마법서를 보내지 않고 전직도 실패시킨다. 데이터 불일치를 조용히 숨기지 않는다.
- 과거 우편 종류와 payload 파싱, 보상 수령 동작은 변경하지 않는다.
- 새 `job_spellbook`은 자원 지급이 없는 `none` claim 상태로 판정한다.
- 본문은 렌더링 가능한 HTML이 아니라 일반 문자열로 저장하고 출력해 사용자 입력이나 스크립트가 섞일 경로를 만들지 않는다.

## 테스트

- 원소군주 최초 전직 시 `마법서` 우편이 정확히 한 건 생성되고, 본문에 `오원소 폭주` 기본형과 12개 주문식이 모두 포함되는지 확인한다.
- 태초술사 최초 전직 시 `태초회귀` 기본형과 12개 주문식, 근원공명 안내가 포함되는지 확인한다.
- 같은 직업 재전직, 과거 직업 재방문, 기존 직업 이력 또는 숙련도가 있는 경우 우편이 추가되지 않는지 확인한다.
- 전직 실패 시 우편이 생성되지 않고, 우편 삽입 실패 시 전직 저장도 롤백되는지 확인한다.
- 본문 생성기가 스킬 정의의 주문식 이름·조건·효과 수치를 사용하며 정확히 12종을 출력하는지 순수 함수 테스트로 확인한다.
- `job_spellbook` payload가 정상 파싱되고 보상 없는 우편으로 판정되며, 손상된 payload는 거절되는지 확인한다.
- 우편함 상세에 제목 `마법서`와 줄바꿈이 보존된 본문이 표시되고, 읽은 뒤 완료 처리되는지 확인한다.
- 통합 알림 종과 우편 종에서 마법서 라벨과 짧은 미리보기가 표시되는지 확인한다.
- 기존 전직, 쪽지, 거래·보상 우편의 조회·읽음·수령 테스트를 함께 실행해 회귀를 확인한다.
