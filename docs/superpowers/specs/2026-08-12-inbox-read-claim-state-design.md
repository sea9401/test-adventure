# 우편함 읽음·수령 상태 분리 설계

## 목표

받은 우편과 지난 우편을 하나의 목록으로 합치고, 사용자가 아직 열어 보지 않은 우편을
목록에서 바로 구분할 수 있게 한다. 전체 수령은 실제 보상이 남아 있는 우편만 처리하며,
유저 쪽지처럼 보상이 없는 우편을 사용자가 읽기 전에 완료 처리하지 않는다.

## 현재 문제

- `marketplace_inbox.claimed_at`이 보상 수령과 읽음 확인을 함께 나타낸다.
- 받은 우편 탭은 `claimed_at IS NULL`, 지난 우편 탭은 `claimed_at IS NOT NULL`인 행을
  따로 조회한다.
- 전체 수령은 길드 초대를 제외한 모든 받은 우편 ID를 전달하므로 유저 쪽지도 함께
  `claimed_at` 처리된다.
- 그 결과 사용자가 읽지 않은 개인 쪽지가 지난 우편으로 이동하며, 별도 탭을 열지 않으면
  놓치기 쉽다.
- 보상이 있는 우편은 "내용을 읽었지만 보상은 아직 받지 않은 상태"를 표현할 수 없다.

## 결정

### 1. 읽음과 처리 완료를 분리한다

`marketplace_inbox`에 nullable `read_at`을 추가한다.

- `read_at IS NULL`: 미확인
- `read_at IS NOT NULL AND claimed_at IS NULL`: 확인했지만 보상 수령 또는 별도 행동이 남음
- `claimed_at IS NOT NULL`: 수령·확인·초대 응답 등 처리가 끝남

마이그레이션 시 기존 `claimed_at IS NOT NULL` 행은 같은 시각을 `read_at`에 복사한다.
기존 미수령 행은 `read_at`을 비워 두어 미확인으로 취급한다. 읽음 배지 조회를 위해
`user_id`, `created_at` 기반의 `read_at IS NULL` 부분 인덱스를 추가하고, 기존 미수령
인덱스는 보상 수령 조회를 위해 유지한다.

### 2. 상세를 여는 즉시 읽음 처리한다

받은 우편 상세 모달은 먼저 즉시 열고, 백그라운드에서 멱등적인 읽음 API를 호출한다.
API는 현재 사용자 소유의 단일 우편만 갱신하며 이미 읽은 우편에는 변화가 없다.

- 보상 우편: `read_at`만 기록하여 미수령 상태를 유지한다.
- 보상이 없는 안내·유저 쪽지: `read_at`과 `claimed_at`을 함께 기록한다. 별도 수령할
  내용이 없으므로 읽는 순간 처리가 끝난다.
- 길드 초대처럼 별도 선택이 필요한 우편: `read_at`만 기록하고 수락·거절 전까지
  `claimed_at`은 비워 둔다.
- 파싱할 수 없는 우편: `read_at`만 기록하고 자동 완료하지 않는다. 기존 보존 원칙대로
  수령 대상에서 제거하거나 숨기지 않는다.

읽음 요청이 실패해도 모달의 내용은 보여 준다. 다만 클라이언트에서 읽음으로 확정하지
않고 오류를 표시하여 다음 진입 때 다시 시도할 수 있게 한다. 성공하면 로컬 목록과 상단
우편 배지를 즉시 동기화한다.

### 3. 받은 우편 목록을 통합한다

`지난 우편` 탭을 제거하고 `받은 우편`, `보낸 우편` 두 탭만 유지한다. 받은 우편 API는
다음을 합쳐 `created_at DESC`로 반환한다.

- 아직 처리가 끝나지 않은 모든 행(`claimed_at IS NULL`)
- 처리가 끝난 최근 우편 최대 100개

처리되지 않은 보상·초대·오류 우편에는 상한을 적용하지 않아 오래된 보상이 목록에서
잘리는 일을 막는다. 완료 우편에만 기존 기록 상한을 유지한다. 보낸 우편은 기존 최근
100개 정책을 유지하며, 수신자의 `read_at`을 기준으로 읽음 여부를 표시한다.

### 4. 목록에서 상태를 명확히 표시한다

미확인 우편 카드는 `SURFACE_ACCENT` 계열의 불투명 표면, 강조 테두리와 굵은 본문으로
구분한다. 컨테이너 전체 투명도는 사용하지 않는다. 라이트·다크 모드 모두에서 배경
이미지가 카드 안으로 비치지 않게 한다.

보상이 있고 아직 `claimed_at`이 없는 우편에는 읽음 여부와 무관하게 `미수령` 배지와
`수령` 버튼을 표시한다. 미확인 보상 우편은 미확인 강조와 미수령 배지를 함께 표시한다.
처리가 끝난 우편은 일반 글씨로 보여 주되 목록에서 사라지지 않는다.

받은 우편 탭의 숫자와 상단 우편 아이콘 배지는 `read_at IS NULL`인 미확인 개수를
사용한다. 미수령 보상의 개수와 혼동하지 않는다.

### 5. 전체 수령은 실제 보상만 처리한다

서버가 우편 종류와 검증된 payload를 바탕으로 `hasReward`를 계산하여 목록 응답에
포함한다. 클라이언트의 전체 수령 대상은 다음 조건을 모두 만족하는 우편으로 제한한다.

- `hasReward === true`
- `claimed_at IS NULL`
- 길드 초대 등 별도 응답 우편이 아님
- payload 파싱에 성공함

따라서 유저 쪽지, 시세 안내, 보상 없는 운영자 안내, 길드 초대, 손상된 payload는 전체
수령에서 제외된다. 개별 또는 전체 수령에 성공하면 `claimed_at`과 `read_at`을 같은
시각으로 기록한다. 사용자가 열지 않고 전체 수령한 보상 우편도 처리 완료와 동시에 읽은
것으로 본다.

전체 수령 버튼의 개수는 전체 우편 수가 아니라 실제 수령 대상 수를 표시한다. 수령 대상이
없으면 버튼을 숨긴다.

## API와 데이터 계약

받은·보낸 우편 항목에 다음 필드를 추가한다.

- `readAt: string | null`
- `hasReward: boolean`
- `claimState: "none" | "claimable" | "action" | "invalid"`

`claimState`는 UI가 종류별 payload를 다시 해석하지 않고 버튼과 배지를 결정하도록 한다.
`none`은 읽는 것으로 완료되는 우편, `claimable`은 보상 수령 우편, `action`은 길드 초대
같은 별도 응답 우편, `invalid`는 파싱 실패로 자동 처리하면 안 되는 우편이다.

읽음 갱신은 별도 `POST /api/marketplace/inbox/read`에서 `{ id }`를 받는다. 응답은 갱신된
`readAt`, `claimedAt`과 `claimState`를 반환하여 클라이언트가 추가 전체 조회 없이 해당
행을 갱신할 수 있게 한다.

기존 수령 API는 보상 적용과 `claimed_at` 갱신을 계속 원자적으로 수행한다. 추가로 성공한
행의 `read_at`도 같은 트랜잭션에서 채운다. 파싱 실패 행은 기존처럼 보상을 적용하거나
`claimed_at` 처리하지 않는다.

## 테스트

### 서버

- 마이그레이션 후 기존 수령 완료 행은 읽음, 기존 미수령 행은 미확인으로 해석된다.
- 받은 우편 조회는 모든 미완료 우편과 최근 완료 우편을 합쳐 최신순으로 반환한다.
- 미확인 카운트는 `read_at IS NULL`만 센다.
- 유저 쪽지를 읽으면 `read_at`과 `claimed_at`이 함께 기록된다.
- 보상 우편을 읽으면 `read_at`만 기록되고 보상은 적용되지 않는다.
- 길드 초대를 읽어도 수락·거절 전에는 `claimed_at`이 기록되지 않는다.
- 읽음 API 재호출은 멱등적이며 다른 사용자의 우편을 갱신하지 못한다.
- 보상 수령은 `read_at`과 `claimed_at`을 함께 기록한다.
- 파싱 실패 우편은 전체 수령과 자동 완료에서 제외된다.

### 클라이언트

- 받은 우편과 완료 우편이 한 탭에 최신순으로 나타나고 지난 우편 탭은 없다.
- 미확인 카드는 불투명 강조 표면과 굵은 글씨를 사용한다.
- 확인했지만 보상을 받지 않은 우편에 `미수령` 배지와 `수령` 버튼이 남는다.
- 전체 수령 ID에는 실제 보상 우편만 포함된다.
- 상세 모달은 즉시 열리며 읽음 성공 후 카드와 상단 배지가 갱신된다.
- 읽음 요청 실패 시 내용은 유지되고 미확인 상태도 유지된다.
- 라이트·다크 모드에서 카드 본문 뒤로 장면 배경이 비치지 않는다.

## 범위 밖

- 우편 삭제·보관·즐겨찾기 기능
- 받은 우편 검색과 페이지네이션 UI
- 우편 보관 기간 및 운영 정리 정책 변경
- 전체 수령 API의 100개 제한 변경
- 우편 종류별 만료 정책 변경
- 운영 배포 및 점검 모드 변경
