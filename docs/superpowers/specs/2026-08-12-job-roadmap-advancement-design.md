# 직업 로드맵 전직 설계

## 목표

직업 찾기 목록으로 돌아가지 않아도 전직 로드맵에서 선택한 직업으로 전직 또는 재전직을 시작할 수 있게 한다. 특히 모바일에서 로드맵 탐색과 전직 행동 사이의 화면 이동을 줄인다.

## 범위

- 로드맵의 선택 직업 상세 패널에 전직 행동을 추가한다.
- 기존 직업 목록의 전직 버튼, 검색, 태그, 목표 설정은 유지한다.
- 기존 `/api/v2/me/advance-class` 호출과 Lv 1 초기화 확인 모달을 재사용한다.
- 서버 전직 규칙, 직업 해금 규칙, 응답 형식은 변경하지 않는다.

## UX와 상태

- 해금된 다른 직업은 현재 캐릭터가 전직 가능 상태일 때 `전직` 버튼을 활성화한다.
- 현재 직업은 같은 직업 재전직 조건까지 충족했을 때 `재전직` 버튼을 활성화한다.
- 조건 부족 직업은 `조건 부족`, 현재 레벨이 부족한 직업은 `Lv 100 필요`로 비활성 사유를 표시한다.
- 로드맵 상세의 버튼을 누르면 기존 Lv 1 초기화 확인 모달을 로드맵 위에 표시한다.
- 확인을 취소하면 선택한 로드맵과 상세 정보를 그대로 유지한다.
- 전직이 성공하면 기존 성공 메시지와 상태 갱신을 수행하고 로드맵을 닫는다.
- 전직이 실패하면 기존 서버 오류 메시지를 사용하며 로드맵은 유지한다.

## 구성과 데이터 흐름

`V2JobLadder`가 전직 가능 여부 계산, 확인 대상 상태, API 호출의 단일 소유자로 남는다. `JobRoadmapDialog`와 `JobRoadmapDetails`는 선택한 직업과 전직 가능 상태를 받아 사용자 행동을 부모의 기존 선택 핸들러로 전달한다. 로드맵 전용 API 호출이나 중복 오류 처리는 만들지 않는다.

확인 모달은 로드맵보다 높은 레이어에 표시한다. 성공 시에만 로드맵을 닫아 취소와 오류 후 문맥이 보존되도록 한다.

## 가독성과 접근성

- 상세 패널은 기존 `SURFACE_INSET` 불투명 표면을 유지한다.
- 전직 버튼은 충분한 터치 높이와 명시적인 `disabled` 상태를 사용한다.
- 현재 직업에는 `재전직`, 다른 직업에는 `전직`이라는 기존 용어를 유지한다.
- 비활성 상태는 컨테이너 투명도가 아니라 버튼의 색과 문구로 표현한다.

## 테스트

`JobRoadmapDetails` 정적 렌더 테스트로 다음 회귀를 막는다.

- 해금 및 레벨 조건을 충족한 다른 직업에 활성 `전직` 행동이 노출된다.
- 현재 직업에는 `재전직` 행동이 노출된다.
- 잠긴 직업은 `조건 부족`으로 비활성화된다.
- 레벨 미달 직업은 `Lv 100 필요`로 비활성화된다.

관련 컴포넌트 테스트, ESLint, TypeScript 검사를 실행한다. 전체 빌드는 작업 트리에 이미 존재하는 미해결 충돌의 영향을 받을 수 있으므로, 실패 시 이번 변경과 기존 충돌을 구분해 보고한다.
