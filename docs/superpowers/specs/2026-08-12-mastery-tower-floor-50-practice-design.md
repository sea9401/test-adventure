# 숙련의 탑 50층 연습 재도전 설계

## 목표

숙련의 탑 50층을 클리어한 이용자가 현재 장비와 스킬 세팅의 전투 결과를 반복해서 비교할 수 있도록, 같은 날 50층 수호자에게 보상 없는 연습 재도전을 제공한다.

## 확정 규칙

- 현재 일일 등반의 `runFloor`가 50이면 다음 도전 대상은 종료 상태가 아니라 다시 50층이다.
- 연습 재도전은 그날 최초 입장료를 이미 낸 상태에서만 도달하므로 추가 스태미나를 소모하지 않는다.
- 연습 승패는 `todayBestFloor`, `lifetimeBestFloor`, `weekBestFloor`, `firstClearRewardsClaimed`, 일일 보상 계산을 바꾸지 않는다.
- 연습 패배에는 기존 30초 재입장 대기시간을 적용하지만 `runFloor`를 0으로 초기화하지 않는다. 대기시간 뒤 50층 연습을 다시 할 수 있다.
- 50층 최초 클리어와 이후 연습 전투를 응답의 `practice` 플래그로 구분한다.
- 메인 화면과 전투 결과 화면은 50층 완료 이용자에게 `50층 연습 재도전`임을 명시한다.

## 검토한 접근

1. **50층만 즉시 반복(채택)**: 기존 전투와 상태를 재사용하면서 보상 상태는 그대로 둔다. 세팅 비교 목적에 가장 직접적이고 새 저장 필드가 필요 없다.
2. 전체 등반을 다시 시작: 체크포인트 선택과 저층 전투가 다시 필요해 측정까지 시간이 오래 걸리고 기존 주간 등반 규칙과 섞인다.
3. 별도 허수아비/훈련장 추가: 측정 기능은 가장 확장성이 높지만 새 전투 규칙과 UI가 필요해 이번 문의 범위를 크게 넘는다.

## 상태와 데이터 흐름

`resolveMasteryTowerAttemptFloor`는 완료 상태에서 51층 대신 50층을 반환한다. 도전 API는 전투 시작 전 상태로 연습 여부를 계산하고 기존 전투 엔진으로 50층 수호자 전투를 수행한다. 승리는 기존 층 클리어 갱신을 다시 적용해 멱등 상태를 유지하고, 패배는 완료된 `runFloor`를 보존한 채 쿨다운만 기록한다.

상태 조회 API는 완료 상태의 `nextFloor`, `nextRequiredPower`, `nextGuardian`도 50층 연습 대상으로 반환한다. 클라이언트는 이 값과 `runFloor === 50`을 사용해 연습 문구와 활성화된 입장 버튼을 표시한다.

## 오류와 경계 조건

- 쿨다운 중 연습 요청은 기존처럼 전투를 시작하지 않고 남은 시간을 반환한다.
- 완료 상태에서 임의의 `startFloor`를 보내면 기존과 동일하게 `invalid_start_floor`로 거부한다.
- 날짜 변경과 관리자 일일 초기화는 기존 규칙대로 완료 상태를 0층으로 돌리므로 새 날짜의 첫 입장료와 등반 규칙은 유지된다.
- 기존 `max_floor` 응답은 방어적 분기로 남길 수 있지만 정상 완료 상태에서는 도달하지 않는다.

## 검증

- 순수 상태 테스트로 완료 상태의 도전 대상, 임의 시작 층 거부, 연습 승리의 멱등성, 연습 패배의 완료 기록 보존과 쿨다운을 검증한다.
- 전투 결과 표시 테스트로 연습 승리·패배 문구를 검증한다.
- 관련 Vitest, TypeScript, ESLint, 이미지 참조 검사, Next.js 빌드를 실행한다.
