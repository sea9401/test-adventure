# 홍보 이벤트 탈퇴·재가입 중복 보상 방지 설계

## 목표

홍보 링크로 가입한 사용자가 탈퇴한 뒤 같은 로그인 주체로 재가입해도 가입 및 진행 보상을 다시 받지 못하게 한다. 탈퇴해도 추천인의 홍보 실적과 이미 지급된 보상 합계는 사라지지 않게 한다.

## 데이터 모델

- `referral_reward_identities`는 로그인 주체별 HMAC-SHA-256 식별 해시만 저장한다. OAuth는 `provider + providerAccountId`, 운영자 발급 계정은 정규화한 로그인 ID를 입력값으로 사용하며 원문은 저장하지 않는다.
- HMAC 키는 운영 전용 `REFERRAL_IDENTITY_SECRET`만 사용한다. 키가 없으면 보상을 지급하지 않는 실패 폐쇄 방식으로 동작해 설정 누락이 중복 보상으로 이어지지 않게 한다.
- 사용자의 모든 연결 로그인 식별자를 한 번에 선점한다. 하나라도 이미 원장에 있으면 새 추천 귀속과 보상을 거절하며, 같은 요청에서 먼저 선점한 나머지 식별자는 되돌린다.
- `referral_conversions`에는 독립 PK, 가입 당시 이름 스냅샷, 탈퇴 시각을 추가한다. `referred_user_id`는 nullable FK(`ON DELETE SET NULL`)로 바꾸어 탈퇴 후에도 실적과 지급 진척도를 보존한다.

## 처리 흐름

1. 신규 캐릭터가 홍보 코드로 귀속될 때 코드 유효성과 자기 추천 여부를 먼저 검사한다.
2. 연결된 모든 OAuth·운영자 계정 식별자를 HMAC 처리해 원장을 원자적으로 선점한다.
3. 선점에 성공한 경우에만 추천 전환과 양쪽 가입 보상 우편을 만든다.
4. 기존 추천 사용자가 탈퇴할 때는 삭제 트랜잭션 안에서 식별 원장을 보강하고, 전환 행의 이름을 `탈퇴한 사용자`로 익명화한 뒤 사용자 FK를 끊는다.
5. 추천인 요약 API는 사용자 테이블을 `LEFT JOIN`하고 스냅샷 이름을 사용한다. 탈퇴자는 현재 진행도 대신 탈퇴 상태와 마지막 보상 진척도를 표시한다.

## 기존 데이터와 동시성

- 배포 전에 생성된 추천 전환은 해당 사용자의 탈퇴 시점에 연결 계정 전체를 원장에 보강하므로 기존 참여자도 재가입 악용이 차단된다.
- 여러 요청이 겹치면 PK 충돌을 이용해 한 요청만 식별자를 선점한다. 일부만 선점한 요청은 자신이 방금 넣은 행만 삭제하고 보상을 지급하지 않는다.
- 탈퇴자의 이미 지급된 추천인 우편은 추천인 소유이므로 그대로 유지한다. 전환 행도 남아 누적 보상 표시와 실제 지급 이력이 일치한다.

## 개인정보와 보유 기간

원문 로그인 식별자는 원장에 저장하지 않는다. HMAC 식별 해시는 홍보 이벤트 중복 보상 방지 목적으로 이벤트 운영 기간과 종료 후 180일까지 보관한다고 개인정보처리방침과 계정 삭제 안내에 고지한다. 이벤트 종료 시점이 정해지면 기존 보존 크론에서 종료 후 180일이 지난 원장을 삭제한다.

## 테스트

- 같은 로그인 식별자는 사용자 ID가 달라져도 두 번째 추천 귀속을 거절한다.
- 여러 연결 계정 중 하나가 이미 사용된 경우 부분 선점을 롤백한다.
- 기존 추천 사용자의 탈퇴 시 식별 원장을 보강하고 전환 행을 익명화한다.
- 추천 요약은 탈퇴한 사용자를 계속 집계하며 `탈퇴한 사용자`로 반환한다.
- 기존 자기 추천, 동일 사용자 중복, 진행 단계 멱등 지급 테스트를 유지한다.
