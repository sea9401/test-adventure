# 경제 대규모 골드 이동 웹훅 상세화 설계

## 현재 문제

`economy.large_gold_movement`는 전역 10분 버킷에서 2천만 골드 이상 변동이
3건 쌓이면 알림을 보낸다. 그러나 웹훅에는 임계치에 도달한 마지막 이벤트의
종류·금액·두 계정만 전달한다. 따라서 `감지 횟수 3`과 `골드 변동 -70,000,000 G`가
서로 어떤 관계인지, 앞선 두 변동이 무엇인지 알 수 없다.

## 설계

- 전역 임계치와 10분 집계 시간은 유지한다.
- 공용 운영 신호 버킷에 선택적인 `sample`을 최대 5건까지 시간순으로 저장한다.
- 대규모 골드 신호는 이벤트 시각, 이벤트 종류, 유저·상대 유저, 골드 변동,
  아이템 이름·ID·수량, 주문·매물 ID, 총액·세율을 샘플로 전달한다.
- 알림 시 버킷 샘플의 양수 합계를 `유입 골드`, 음수 절댓값 합계를 `유출 골드`로
  표시한다.
- Discord에는 각 샘플을 `시각 · 이벤트 · 아이템 ×수량 · 보내는 계정 → 받는 계정 ·
  금액 (총액)` 형식의 전체 폭 목록으로 표시한다.
- 계정 UUID는 내부 알림 이력에만 남긴다. 외부 웹훅에서는 기존 계정 조회를 거쳐
  인게임 이름과 짧은 ID로 바꾸며, 멘션 문자는 무력화한다.
- 경제 로그가 상세의 `itemName`을 우선 사용하고, 없으면 장비·재료 카탈로그에서
  이름을 찾아 코드 ID 대신 실제 아이템 이름을 보여 준다.

## 예외와 제한

- 임계치 도달 뒤 같은 버킷에 추가된 거래는 이미 발송된 메시지에 소급 추가하지 않는다.
- 아이템 이름이 없는 기존·비거래소 이벤트는 안전한 아이템 ID를 대신 표시한다.
- 운영 DB 스키마 변경, 기존 경제 기록 수정, 웹훅 발송 테스트, 배포는 하지 않는다.

## 검증

- 세 신호의 샘플이 한 Discord 알림에 시간순으로 표시되는 회귀 테스트
- 유입·유출 합계와 계정 ID 비노출 테스트
- 대규모 경제 이벤트가 거래 메타데이터를 샘플로 만드는 순수 함수 테스트
- 관련 Vitest, TypeScript, ESLint 검증
