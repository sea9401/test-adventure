# 게임 코드 전면 정비 설계

## 목표

기능 동작과 전투·보상 결과를 유지하면서, 현재 확인된 구조적 결합과 불필요한 런타임 비용을 한 번의 정비 작업에서 줄인다.

## 현재 기준선

- 전체 Vitest: 635개 파일, 5,068개 테스트, 실패 0건
- 운영 런타임: CPU 약 9~12%, RSS 약 400MB, DB 풀 대기 0
- 구조 위험: `V2MarketplaceView.tsx` 약 3,900줄, PvE/PvP 엔진 각각 3,000줄 이상, `GameStateProvider.tsx` 약 1,280줄
- 확인된 쿼리 낭비: 사냥 위치가 카탈로그 거점과 자유 타일을 동시에 가리킬 때 점령 행을 최대 두 번 조회
- 정적 분석: 은퇴한 거점 UI 클러스터가 진입점 없이 남아 있고, `tsx`가 전이 의존성으로만 사용됨

## 설계

1. 거래소의 묶음 매물 UI와 확인 모달을 전용 모듈로 옮긴다. 코디네이터는 상태·네트워크 요청을, 하위 모듈은 표시와 사용자 입력만 담당한다.
2. 사냥 위치 ID를 순수 함수로 정규화하고, 정렬된 `IN (...) FOR SHARE` 단일 쿼리로 점령 행을 잠근다. 기존 잠금 순서(거점 → 길드 → 캐릭터)는 유지한다.
3. `refreshGameState`만 필요한 소비자는 전용 컨텍스트를 구독하게 한다. 자원·위치가 변할 때 이 소비자들까지 다시 렌더링되는 결합을 끊는다.
4. PvE/PvP가 각각 구현한 마법 방어 감소 계산을 공통 전투 헬퍼로 옮긴다. 전투 결과는 수치 단위 테스트와 전체 엔진 테스트로 고정한다.
5. 정적 진입점이 없는 은퇴한 거점 UI 클러스터를 제거하고 Knip 진입점·직접 의존성을 바로잡는다.
6. 대형 파일 예산 검사를 추가해 이번 분리 뒤 파일이 다시 비대해지는 것을 막는다. 기존 초과 파일에는 현재 크기를 기준선으로 두고, 새 초과만 실패시킨다.

## 안전장치

- 새 순수 로직과 새 컨텍스트는 테스트를 먼저 실패시킨 뒤 구현한다.
- 전투·사냥은 수치와 잠금 순서를 바꾸지 않는다.
- DB 스키마·마이그레이션·운영 배포는 건드리지 않는다.
- 삭제 대상은 Knip와 전체 저장소 참조 검색에서 진입점이 없고, 서로만 참조하는 은퇴 UI 묶음으로 제한한다.
- 완료 전 전체 Vitest, ESLint, TypeScript, Next.js production build, 이미지 참조 검사를 새로 실행한다.
