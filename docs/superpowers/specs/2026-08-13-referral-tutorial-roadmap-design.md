# 홍보 이벤트 튜토리얼 로드맵 설계

## 배경

현재 홍보 이벤트는 가입 완료 뒤 프론티어 깊이 6·12·18·24·36만 확인한다. 보상 단계는 여섯 개지만 실제 행동은 사냥 반복 하나뿐이라, 신규 모험가에게 게임의 주요 기능을 소개하는 역할이 약하다.

홍보 보상의 총량은 유지하면서 진행 조건을 전투·길드·생활로 분산한다. 과제는 튜토리얼 순서로 보여 주되 서로 독립적으로 달성할 수 있게 한다.

## 목표

- 홍보 링크로 합류한 모험가가 사냥, 길드, 생활 콘텐츠를 자연스럽게 경험한다.
- 신규 모험가와 홍보자에게 지급되는 총보상은 각각 회복약 12개로 유지한다.
- 이미 지급한 보상은 회수하거나 중복 지급하지 않는다.
- 기존 지급 횟수는 새 로드맵의 완료 단계로 자연스럽게 승계하고, 화면에는 별도 전환 문구를 노출하지 않는다.
- 길드 탈퇴나 이후 상태 변화가 이미 완료된 과제를 되돌리지 않게 한다.
- 모바일에서도 단계와 다음 행동을 쉽게 파악할 수 있게 한다.

## 범위 밖

- 홍보 코드 발급, 링크 귀속, 중복 계정 방지 정책은 바꾸지 않는다.
- 회복약 종류와 단계당 수량은 바꾸지 않는다.
- 길드 가입 신청만으로는 과제를 완료하지 않는다.
- 생활 직종별 과제를 따로 만들거나 모든 생활 직종을 강제하지 않는다.
- 운영 배포는 이 작업 범위에 포함하지 않는다.

## 최종 로드맵

| 위치 | 과제 ID | 표시 이름 | 완료 조건 | 양쪽 보상 | 바로가기 |
| --- | --- | --- | --- | --- | --- |
| 1 | `signup` | 모험 시작 | 홍보 링크 귀속과 가입 보상 지급 완료 | 회복약 2개씩 | 없음 |
| 2 | `hunt_depth_24` | 더 깊은 사냥터로 | 프론티어 깊이 24 이상 | 회복약 2개씩 | `/battle` |
| 3 | `join_guild` | 길드의 일원 | 길드 가입 승인, 초대 수락 또는 길드 창단 성공 | 회복약 2개씩 | `/guild` |
| 4 | `life_level_5` | 첫 생활 숙련 | 낚시·농사·벌목·채광·요리 중 최고 레벨 5 이상 | 회복약 2개씩 | `/character/life` |
| 5 | `hunt_depth_36` | 심부 돌파 | 프론티어 깊이 36 이상 | 회복약 2개씩 | `/battle` |
| 6 | `life_level_10` | 생활의 기반 | 같은 기준의 최고 생활 레벨 10 이상 | 회복약 2개씩 | `/character/life` |

가입을 포함해 총 여섯 단계이며, 신규 모험가와 홍보자는 단계마다 회복약 2개씩 받아 각각 최대 12개를 얻는다. 친구 한 명을 기준으로 양쪽 합계는 최대 24개다.

## 완료 규칙

다섯 진행 과제는 표시 순서와 무관하게 독립적으로 완료된다. 생활 레벨 10을 먼저 충족하면 `life_level_5`와 `life_level_10`을 한 번에 완료할 수 있다. 프론티어 깊이 36을 달성한 상태를 재검사하면 `hunt_depth_24`와 `hunt_depth_36`을 함께 완료한다.

생활 레벨은 서버에서 정규화한 낚시, 농사, 벌목, 채광, 요리 레벨의 최댓값이다. 한 직종만 5 또는 10에 도달해도 해당 과제를 완료한다.

길드 과제는 `guild_members`에 실제 멤버십이 만들어진 시점에 완료한다. 가입 신청 제출은 완료로 보지 않는다. 가입 승인, 초대 수락, 길드 창단은 모두 같은 과제를 완료한다. 완료 ID를 영구 저장하므로 이후 길드를 탈퇴해도 완료 상태와 지급 이력은 유지된다.

## 저장 구조

`referral_conversions`에 완료된 진행 과제 ID 배열을 추가한다.

- 데이터베이스 열: `completed_tutorial_task_ids text[] NOT NULL`
- 기본값: 빈 배열
- 허용값: `hunt_depth_24`, `join_guild`, `life_level_5`, `hunt_depth_36`, `life_level_10`
- 서버 파서가 알 수 없는 값과 중복을 제거하고 로드맵 순서로 정규화한다.
- 배열은 최대 다섯 개로 제한한다.

`signup` 완료 여부는 기존 `referrerSignupRewardedAt`을 그대로 사용한다. 기존 `rewardedStaminaDepth`는 과거 지급 감사 기록으로 보존하되, 새 과제 지급 진척도로는 더 이상 갱신하지 않는다.

완료 배열의 각 ID는 해당 진행 보상이 양쪽에 이미 지급됐다는 의미도 겸한다. 진행 과제가 정확히 다섯 개이고 모든 과제의 보상이 같으므로 별도 보상 카운터는 두지 않는다.

## 기존 참여자 승계

마이그레이션은 기존 `rewardedStaminaDepth`가 나타내는 지급 횟수만큼 새 로드맵의 가입 다음 위치부터 완료 ID를 채운다.

| 기존 지급 깊이 | 기존 진행 보상 횟수 | 완료 처리할 새 과제 |
| --- | ---: | --- |
| 0 | 0 | 없음 |
| 6 | 1 | `hunt_depth_24` |
| 12 | 2 | 위 항목 + `join_guild` |
| 18 | 3 | 위 항목 + `life_level_5` |
| 24 | 4 | 위 항목 + `hunt_depth_36` |
| 36 | 5 | 위 항목 + `life_level_10` |

이는 과거 행동을 새 조건과 의미상 일치시키려는 변환이 아니라, 이미 받은 보상 수를 같은 로드맵 위치에 보존하는 변환이다. 따라서 승계된 단계는 새 조건을 다시 수행하지 않아도 완료 상태다.

UI는 승계 여부나 `기존 지급분` 문구를 표시하지 않는다. 일반 완료 단계와 똑같이 체크된 상태로 보여 준다.

## 서버 판정과 지급

공통 서비스가 후보 과제 ID를 받아 다음 순서로 처리한다.

1. 대상 신규 모험가의 `referral_conversions` 행을 `FOR UPDATE`로 잠근다.
2. 홍보 귀속이 없거나 탈퇴로 `referredUserId`가 분리된 경우 아무 작업도 하지 않는다.
3. 저장된 완료 ID를 정규화하고 후보 중 아직 없는 ID만 고른다.
4. 새 ID를 로드맵 순서로 추가한다.
5. 새 ID 수 × 회복약 2개를 신규 모험가와 홍보자 우편함에 각각 한 통으로 합산 지급한다.
6. 완료 배열 갱신과 양쪽 우편 생성을 호출한 게임 행동과 같은 트랜잭션에서 확정한다.

같은 과제를 여러 경로에서 동시에 감지해도 행 잠금과 완료 ID 중복 제거 때문에 한 번만 지급한다. 허용된 과제 ID가 다섯 개뿐이므로 가입 이후 진행 보상은 한 사람당 최대 회복약 10개, 가입 보상을 합치면 최대 12개다.

## 판정 시점

공통 판정기를 다음 서버 권위 행동의 성공 경계에 연결한다.

- 사냥: 승리 후 저장할 프론티어 깊이가 24 또는 36에 도달했을 때
- 길드: 가입 신청 승인, 길드 초대 수락, 길드 창단으로 멤버십 생성에 성공했을 때
- 생활: 낚시·농사·벌목·채광·요리에서 XP 반영 후 정규화 레벨이 5 또는 10에 도달했을 때

업데이트 이전에 조건을 이미 달성했거나 과거 경로에서 신호를 놓친 참여자를 위해 별도의 멱등 동기화 POST API를 둔다. 홍보 이벤트 화면은 로드 시 이 API를 한 번 호출한 뒤 최신 요약을 가져온다. 상태를 바꾸는 동기화를 GET 요청에 넣지 않는다.

동기화 API는 현재 프론티어 깊이, 길드 멤버십, 다섯 생활 세이브를 서버에서 읽어 충족한 모든 과제를 한 번에 후보로 전달한다. 이미 완료한 과제는 지급하지 않는다.

## API 응답과 화면

홍보 요약 API는 다음 정보를 추가한다.

- 현재 사용자가 홍보 링크로 합류했는지와 자신의 완료 단계
- 친구별 완료 과제 ID와 `완료 단계/6`
- 로드맵 정의: ID, 이름, 설명, 보상 수량, 바로가기

홍보 이벤트 화면의 기존 사냥 깊이 카드 여섯 칸은 세로형 로드맵으로 교체한다. 각 행은 완료 체크, 과제 이름, 한 줄 조건, 양쪽 보상, 미완료 시 바로가기 버튼을 가진다. 표면은 기존 불투명 `Card`와 `SURFACE_INSET`을 사용한다.

- 홍보 링크로 합류한 이용자에게는 자신의 실제 완료 상태를 보여 준다.
- 홍보자에게는 친구별 전체 진행률과 펼쳐 볼 수 있는 과제 상태를 보여 준다.
- 홍보 귀속이 없는 이용자에게도 친구가 달성할 로드맵 미리보기를 보여 준다.
- 승계된 단계는 일반 완료 단계와 시각적으로 동일하다.
- 좁은 화면에서는 한 열로 표시하고, 단계 번호·상태·행동 버튼을 한 카드 안에 배치한다.

## 오류 처리와 일관성

- 과제 지급이 실패하면 해당 게임 행동의 트랜잭션도 커밋하지 않아 완료와 보상이 갈라지지 않게 한다.
- 동기화 요청 실패는 기존 게임 진행을 막지 않으며 화면에 재시도 가능한 로드 오류를 표시한다.
- 우편 메시지는 한 번에 완료한 과제 이름과 합산 회복약 수를 안내한다.
- 홍보자가 탈퇴해 귀속 행이 사라졌거나 신규 모험가가 탈퇴해 연결이 분리된 기록에는 새 보상을 지급하지 않는다.
- 마이그레이션은 기존 행을 멱등 변환하며 이미 저장된 감사 필드를 삭제하지 않는다.

## 테스트 전략

### 데이터와 마이그레이션

- 과거 깊이 0·6·12·18·24·36이 각각 새 완료 ID 0~5개로 변환되는지 검증한다.
- 완료 ID 정규화가 알 수 없는 값, 중복, 순서 오염을 제거하는지 검증한다.

### 서버 지급

- 각 과제를 처음 완료할 때 양쪽에 회복약 2개가 지급되는지 검증한다.
- 생활 레벨 10 또는 깊이 36을 한 번에 감지하면 하위 과제까지 합산 지급하는지 검증한다.
- 재호출과 동시 호출이 보상을 중복 생성하지 않는지 검증한다.
- 승계로 완료된 위치는 실제 새 조건을 달성해도 다시 지급되지 않는지 검증한다.
- 길드 탈퇴 뒤에도 완료 배열이 유지되는지 검증한다.
- 다섯 진행 과제와 가입을 합친 최대 지급량이 양쪽 각각 12개인지 검증한다.

### 연동 경로

- 사냥 깊이 갱신, 길드 가입 승인·초대 수락·창단, 다섯 생활 레벨 상승 경로가 공통 판정기를 호출하는지 검증한다.
- 동기화 API가 업데이트 이전 달성 상태를 찾아 완료하며 멱등인지 검증한다.

### UI

- 여섯 단계가 확정된 순서로 표시되는지 검증한다.
- 독립 완료 상태, 친구별 진행률, 미완료 바로가기, 모바일 한 열 배치를 검증한다.
- 승계 단계에 별도 과거 보상 문구가 나타나지 않는지 검증한다.

## 완료 기준

- 신규 참여자는 가입 이후 다섯 종류의 튜토리얼 과제를 독립적으로 완료한다.
- 사냥 깊이만 반복해서는 전체 진행 보상을 받을 수 없다.
- 한 생활 직종만 레벨 10에 도달해도 생활 과제 두 개를 완료한다.
- 기존 참여자는 받은 보상 횟수만큼 새 로드맵이 이미 체크되어 있고 중복 보상을 받지 않는다.
- 신규 모험가와 홍보자의 친구 1명당 최대 보상은 각각 회복약 12개다.
- 모든 지급은 서버 권위·멱등·트랜잭션 방식으로 처리된다.
