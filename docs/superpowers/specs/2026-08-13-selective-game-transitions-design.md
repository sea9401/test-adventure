# 선택적 게임 화면 전환 디자인

## 목표

게임의 반복 조작 속도를 해치지 않으면서 다음 두 전환만 시험 적용한다.

1. 장소별 배경 이미지가 바뀔 때 짧은 교차 페이드를 적용한다.
2. 사냥터 목록(`/battle/dungeon`)에서 층 전투(`/battle/dungeon/[floorId]`)로 진입할 때 본문에 짧은 전진 전환을 적용한다.

## 범위

- 상단바, 메인 탭, 전쟁 전광판, 스태미나 바, 채팅 버튼은 움직이지 않는다.
- 배경 전환은 게임 크롬이 선택한 배경 URL이 실제로 달라질 때만 실행한다.
- 사냥터 본문 전환은 목록에서 유효한 숫자 층 경로로 이동할 때만 실행한다.
- 직접 층 URL로 접속하거나 층 사이를 이동하거나 다른 페이지로 이동할 때는 본문 전환을 실행하지 않는다.
- 모달, 드롭다운, 내부 탭, 전투 행동에는 새 전환을 추가하지 않는다.

## 동작

### 배경 교차 페이드

- 현재 배경을 유지한 채 새 배경 이미지를 별도 레이어로 로드한다.
- 새 이미지의 `load`가 확인된 뒤 두 레이어를 180ms 동안 교차 페이드한다.
- 전환이 끝나면 이전 레이어를 제거한다.
- 이미지 로드 전에는 기존 배경이 사라지지 않아 빈 화면이나 번쩍임이 없어야 한다.
- 기존 `fallbackSrc` 오류 복구 동작을 두 레이어 모두에서 유지한다.

### 사냥터 진입

- 게임 크롬의 영속 본문 래퍼가 직전 경로와 현재 경로를 비교한다.
- `/battle/dungeon`에서 `/battle/dungeon/<숫자>`로 바뀐 경우에만 160ms 동안 `opacity 0 → 1`, `translateX(8px) → 0` 전환을 적용한다.
- 기존 화면을 붙잡아 두는 퇴장 애니메이션은 사용하지 않는다. 새 전투 화면이 즉시 마운트되고 짧게 들어오므로 반복 진입을 지연시키지 않는다.

## 기술 선택

이번 시험 적용은 React/Next의 실험적 View Transition 설정을 켜지 않고 로컬 CSS 애니메이션으로 구현한다. 영향 범위가 두 컴포넌트로 제한되고, 미지원 브라우저 분기 없이 현재 모바일 브라우저에서 동일하게 동작하며, 문제가 있으면 쉽게 제거할 수 있기 때문이다.

## 접근성 및 안정성

- `prefers-reduced-motion: reduce`에서는 두 전환의 애니메이션을 제거하고 즉시 최종 상태를 표시한다.
- 배경은 계속 `aria-hidden`이며 입력이나 포커스를 가로채지 않는다.
- 애니메이션은 `opacity`와 `transform`만 사용해 레이아웃 재계산을 피한다.
- 배경 레이어는 로드 완료 후 정리하여 장시간 중복 DOM을 남기지 않는다.

## 테스트

- 새 배경이 로드되기 전 이전 배경이 유지되는지 검증한다.
- 로드 후 교차 페이드 상태가 생기고 180ms 뒤 이전 레이어가 제거되는지 검증한다.
- 직접 층 진입에는 본문 애니메이션이 없고 목록에서 층으로 이동할 때만 적용되는지 검증한다.
- 관련 컴포넌트 테스트, 전체 타입 검사, 린트, 전체 테스트, 프로덕션 빌드를 실행한다.
