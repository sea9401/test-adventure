# 전투 패턴 보호막 수치 조건 설계

## 목표

전투 패턴의 `내 보호막` 조건에서 기존 `없을 때`·`있을 때`뿐 아니라 현재 보호막 포인트가 지정값 `이하` 또는 `이상`일 때도 스킬을 발동할 수 있게 한다.

## 범위와 의미

- 비교 대상은 최대 HP 대비 비율이 아니라 전투 상태의 현재 보호막 포인트다.
- `이하`와 `이상`은 모두 경계를 포함한다. 보호막이 100일 때 `100 이하`와 `100 이상`은 모두 참이다.
- 입력값은 0 이상의 정수로 정규화한다.
- PvE와 PvP 모두 실제 시전자 보호막을 사용한다.
- 보호막을 사용하지 않는 격자 던전 파티 전투는 현재 보호막을 0으로 취급한다.
- 배포와 운영 점검 모드 변경은 범위에 포함하지 않는다.

## 데이터 모델과 호환성

`V2CombatCondition`의 `self_shield`는 두 저장 형태를 지원한다.

```ts
| { kind: "self_shield"; active: boolean }
| { kind: "self_shield"; op: "atMost" | "atLeast"; value: number }
```

기존 `active` 형태는 그대로 파싱하고 평가해 저장된 패턴을 깨뜨리지 않는다. 새 수치 형태는 파싱 시 유한한 숫자인지 확인하고 음수를 0으로 올린 뒤 소수점을 버린다. 알 수 없는 연산자나 값이 없는 조건은 기존 정책대로 해당 블록을 버린다.

패턴 평가 컨텍스트에는 `selfShield` 현재값을 추가한다. 기존 `selfShieldActive`도 구버전 조건과 기존 호출 호환을 위해 유지한다. 실제 엔진 호출부는 두 값을 같은 전투 스택에서 채운다.

## 편집기

`내 보호막` 조건의 비교 방식은 `없을 때`, `있을 때`, `이하`, `이상` 네 가지다. 기존 조건을 열면 기존 상태가 그대로 선택된다. 수치 비교를 선택하면 0 이상의 정수 입력을 함께 표시하며 기본값은 0이다. 다시 있음/없음으로 바꾸면 수치 입력을 숨기고 해당 `active` 조건으로 변환한다.

기존 불투명 표면 컴포넌트와 입력 스타일을 그대로 사용하며 새로운 패널이나 배경 표면은 추가하지 않는다.

아레나에 저장된 전투 패턴을 요약할 때 수치 조건은 `내 보호막 N 이하` 또는 `내 보호막 N 이상`으로 표시한다. 기존 있음·없음 문구는 유지한다.

## 검증

- 순수 조건 평가 테스트로 이하·이상과 경계 포함을 검증한다.
- 저장 파서 테스트로 정상 수치, 음수, 소수, 잘못된 연산자를 검증한다.
- 전투 캐스트 통합 테스트로 실제 보호막 값이 패턴 선택에 전달되는 경로를 검증한다.
- 편집기 정적 렌더 테스트로 네 비교 선택지와 수치 입력 노출을 검증한다.
- 아레나 패턴 요약 테스트로 보호막 수치와 비교 문구를 검증한다.
- 관련 Vitest, TypeScript 검사, ESLint를 실행한다.
