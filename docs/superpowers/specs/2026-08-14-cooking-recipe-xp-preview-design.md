# 요리별 제작 경험치 안내 설계

## 목표

개인 주방의 요리책에서 각 요리를 1개 제작할 때 현재 캐릭터가 실제로 받을 수 있는 요리 경험치를 조리 전에 안내한다.

## 표시 기준

- 각 요리 카드의 재료와 음식 효과 사이에 `제작 XP · 1개당 +N` 형식으로 표시한다.
- 요리 레벨이 레시피 요구 레벨보다 10 또는 20 이상 높을 때 적용되는 기존 경험치 감쇠를 반영한다.
- 요리 직업 2차 이상 보너스와 현재 장착한 요리 경험치 스킬 보너스를 합산해 반영한다.
- 보너스의 소수 경험치는 서버가 확률적으로 반올림하므로 가능한 값이 둘이면 `+N~M`, 하나면 `+N`으로 표시한다.
- 표시는 항상 1개 제작 기준이다. 여러 개 조리 결과는 서버가 합계에 한 번 확률 반올림하므로 1개 값을 단순 곱한 수치로 안내하지 않는다.
- 주문 납품 경험치는 기존 주문 카드 안내를 유지하며 이번 범위에 포함하지 않는다.

## 계산 경계

`cooking.ts`에 경험치 미리보기용 순수 함수를 둔다. 함수는 기본 경험치와 보너스율을 안전한 정수·0 이상 값으로 정규화한 뒤 서버의 `cookingXpReward`가 낼 수 있는 최솟값과 최댓값을 반환한다. 현재 레벨 감쇠에는 기존 `adjustedCookingXp`를 그대로 사용한다.

제작 서버의 실제 지급 로직은 변경하지 않는다. 화면은 GET 응답에 이미 포함된 현재 요리 레벨, 직업 차수, 장착 스킬 보너스와 레시피 데이터를 사용하므로 API 응답 구조도 변경하지 않는다.

## UI와 가독성

경험치 안내는 기존 불투명 요리 카드 내부에 작은 보조 문구로 추가한다. 배경 표면이나 패널을 새로 만들지 않으며 라이트·다크 모드의 기존 색상 토큰을 따른다. 잠긴 레시피에도 수치를 표시해 해금 후 성장량을 미리 비교할 수 있게 한다.

## 검증

- 순수 계산 테스트로 보너스 없음, 정수 보너스, 확률 반올림 범위, 비정상 입력 정규화를 검증한다.
- 감쇠된 레시피 경험치와 직업·스킬 보너스를 조합한 카드 안내 테스트를 추가한다.
- 관련 Vitest, TypeScript, 대상 ESLint와 전체 테스트를 실행한다.
- 이미지 최적화 훅이 파일을 변환할 수 있으므로 `npm run build`는 실행하지 않는다.
