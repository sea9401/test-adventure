# 위험 해역 낚시 시각 개편 설계

## 목표

- 위험 해역을 글과 셀렉트 박스 중심 화면에서 해역과 어종이 보이는 낚시 화면으로 바꾼다.
- 새로운 화면도 기존 낚시의 밝고 정돈된 게임 일러스트와 카드 UI를 그대로 확장한 것처럼 보이게 한다.
- 위험 해역 플레이와 상점 기능을 분리해 출항 중 필요한 정보와 조작에 집중할 수 있게 한다.
- 위험 해역 전용 장비와 특수 미끼에 식별 가능한 이미지를 제공한다.

## 범위 밖

- 어종 출현율, 장력 판정, 위험도, 사고 확률, 보상과 가격은 변경하지 않는다.
- 새 화폐, 장비 단계, 어종, 거대어 또는 도감 기능을 추가하지 않는다.
- 기존 낚시 화면의 조작 방식과 이미지는 교체하지 않는다.
- 이번 개편을 이유로 배포하거나 점검 모드를 변경하지 않는다.

## 정보 구조

낚시터의 공용 상단 탭은 `낚시`, `위험 해역`, `의뢰`, `주간 순위`, `명예의 전당`, `상점`을 유지한다. 현재 일부 경로에서 전달하지 않는 이동 핸들러를 연결해 위험 해역과 상점에서도 같은 탭 구성을 볼 수 있게 한다.

위험 해역 안에는 두 개의 로컬 탭을 둔다.

- `출항`: 해역·수심 선택, 출항, 개인 어획 조우, 미끼 선택, 화물과 안전 귀환을 담당한다.
- `거대어`: 현재 거대어 현황, 개인 시도, 기여도와 보상 수령을 담당한다. 활성 이벤트가 있거나 보상을 받을 수 있으면 탭 배지를 표시한다.

탭 전환은 화면 표시만 바꾸며 서버의 출항·조우·화물·거대어 상태를 초기화하지 않는다. 진행 중인 개인 조우가 있으면 `출항` 탭에 진행 중 배지를 표시한다. 다른 탭을 둘러볼 수는 있지만 동시에 새 조우나 거대어 시도를 시작하는 서버 제한은 그대로 유지한다.

별도의 `도감` 탭은 이번 범위에 넣지 않는다. 현재 목표인 시각 개선과 기능 분리에 집중하고, 기존 위험 해역 도감이 실제 기능으로 추가될 때 독립 설계한다.

## 출항 화면

### 출항 준비

기존 해역 셀렉트 박스를 세 장의 해역 카드로 바꾼다. 각 카드는 해역 배경의 축소 이미지, 이름, 해금 레벨, 기본 위험도와 한 줄 설명을 표시한다. 잠긴 해역은 카드 전체 투명도를 낮추지 않고 잠금 아이콘과 비활성 텍스트로 표현한다.

수심은 `표층`, `중층`, `심층` 세 개의 분할 버튼으로 선택한다. 선택한 해역과 수심으로 계산한 최종 위험도, 사고 확률과 최대 손실률은 출항 버튼 바로 위의 불투명 요약 카드에 함께 표시한다.

현재 장착한 위험 해역 낚싯대·릴·낚싯줄은 아이콘과 이름으로 된 한 줄 요약만 보여준다. 장비를 구매하거나 바꾸는 기능은 제거하고 `낚시 상점에서 변경` 링크를 제공한다. 미끼는 투척마다 선택해야 하므로 출항 화면에 남기되, 보유 수량과 대상 행동을 이미지 카드로 표시하고 구매는 상점에서만 한다.

### 개인 조우

조우 상단에는 현재 해역 배경과 대상 어종 이미지를 결합한 무대 영역을 둔다. 어종 이미지는 배경과 분리된 컷아웃이며, 어종 이름과 현재 행동은 무대 아래의 불투명 정보 패널에 표시한다. 본문이나 조작 문구를 배경 이미지 위에 직접 올리지 않는다.

현재의 장력·어체력·거리 게이지와 `감아올리기`, `줄 풀기`, `버티기` 조작은 유지한다. 행동마다 작은 아이콘과 짧은 반응 효과를 추가하되 판정 시간과 서버 요청은 바꾸지 않는다. 색상뿐 아니라 행동 이름, 권장 조작과 수치를 계속 표시해 접근성을 유지한다.

모바일에서는 세 조작 버튼을 현재처럼 화면 하단에 고정한다. 무대 이미지는 낮은 높이의 가로 비율로 줄이고, 게이지와 버튼이 첫 화면 안에 최대한 들어오게 한다.

### 화물과 귀환

화물 행에는 어종 이미지, 이름, 수량과 가치가 함께 표시된다. 위험도 3 이상이면 예상 손실 범위를 귀환 버튼 가까이에 경고 배지로 반복 표시한다. 빈 화물 상태는 선택한 해역의 작은 이미지와 안내 문구를 함께 사용한다.

## 거대어 화면

거대어가 없을 때는 단순 문구 대신 잔잔한 바다 흔적 일러스트와 출현 조건을 표시한다. 활성 거대어가 있으면 해당 거대어 컷아웃, 이름, 남은 시간, 공용 어체력과 내 기여를 한 장의 이벤트 카드로 구성한다.

개인 시도를 시작하면 개인 조우와 같은 무대·게이지·조작 컴포넌트를 재사용한다. 거대어 전용으로 별도의 조작 규칙이나 시각 언어를 만들지 않는다.

## 낚시 상점 통합

기존 낚시 코인 상점 본문에 `일반 낚시`와 `위험 해역` 로컬 탭을 추가한다.

- `일반 낚시`: 현재 낚싯대, 미끼, 칭호와 소비품 구성을 그대로 유지한다.
- `위험 해역`: 전용 낚싯대, 릴, 낚싯줄과 특수 미끼를 표시한다.

위험 해역 상품 카드도 기존 상점의 48px 아이콘, 보유·장착 배지, 설명, 효과 태그와 낚시 코인 버튼 형식을 재사용한다. 스타터 장비는 무료 상품이 아니라 이미 보유한 기본 장비로 표시한다. 장비는 구매 후 장착할 수 있고, 특수 미끼는 묶음 수량과 현재 보유량을 표시한다.

서버 구매 규칙은 기존 경계를 유지한다. 일반 상품은 `/api/v2/fishing/shop`, 위험 해역 상품은 `/api/v2/dangerous-fishing/shop`을 사용하고, 구매 계산 함수도 재사용한다. 상점 전용 클라이언트 조합 계층이 두 상태를 병렬로 불러오고 성공한 구매 뒤 공용 낚시 코인 잔액과 해당 상품 상태를 함께 갱신한다. 위험 해역 전체 화면이나 거대어 폴링을 상점에 마운트하지 않는다.

## 이미지 방향

모든 신규 이미지는 기존 낚시 자산의 선명한 판타지 게임 일러스트 톤을 따른다. 위험 해역이라는 이유로 공포·고어·극단적인 암흑 화면으로 바꾸지 않는다. 기존보다 파도, 먹구름, 낙뢰, 심해 청록색을 조금 강조하되 형태와 색이 작은 화면에서도 분명해야 한다. 이미지 안에는 글자, 로고와 워터마크를 넣지 않는다.

### 해역 배경 3종

기존 `fishing-pond.webp`와 같은 가로형 환경 일러스트로 제작해 `public/images/ui/`에 저장한다.

- `dangerous-fishing-shattered-reef.webp`: 맑은 하늘과 부서진 암초, 비교적 잔잔한 초입 바다
- `dangerous-fishing-storm-trench.webp`: 짙은 구름, 먼 낙뢰와 거친 파도가 있는 폭풍 해구
- `dangerous-fishing-abyssal-rift.webp`: 청록빛 심해 균열과 희미한 생물 발광이 보이는 깊은 바다

UI용 원본은 넓은 화면과 모바일 중앙 크롭을 모두 고려해 주요 피사체를 중앙에 둔다. 프로젝트의 이미지 최적화 훅이 `ui` 프로필로 WebP를 생성한다.

### 어종과 거대어 11종

기존 `public/images/fish/` 자산처럼 옆모습 중심의 단일 피사체 컷아웃으로 제작한다. 파일명은 데이터 ID와 일치시킨다.

- 일반 어종: `razor_sardine`, `ironjaw_tuna`, `reef_maw_grouper`, `storm_mackerel`, `thunder_ray`, `tempest_swordfish`, `lantern_eel`, `voidfin_coelacanth`, `abyssal_crownfish`
- 거대어: `tidal_colossus`, `abyss_kraken`

최종 파일은 `public/images/fish/<id>.webp`에 저장한다. 카드와 조우 무대에서 같은 이미지를 재사용한다.

### 장비 9종과 미끼 5종

기존 낚시 상점 장비처럼 하나의 물체가 중앙에 놓인 투명 배경 아이템 아이콘으로 제작한다. 입문 장비는 목재·황동, 중급 장비는 청록·강철, 최상급 장비는 심해 청색·은빛 소재로 단계가 구분되게 한다.

- 낚싯대: `starter_rod`, `breaker_rod`, `leviathan_rod`
- 릴: `starter_reel`, `current_reel`, `maelstrom_reel`
- 낚싯줄: `starter_line`, `braided_line`, `abyss_chain_line`
- 미끼: `basic_bait`, `reef_bait`, `blood_bait`, `luminous_bait`, `abyss_bait`

최종 파일은 `public/images/items/fishing/dangerous/<id>.webp`에 저장한다. 낚싯줄은 가는 선만 그리지 않고 감긴 스풀과 줄 끝 일부를 함께 보여 작은 아이콘에서도 종류를 알아볼 수 있게 한다. 미끼는 색만 바꾸지 않고 재료와 실루엣도 구분한다.

이미지는 각 자산별 프롬프트로 생성하고 결과를 눈으로 검수한다. 투명 아이콘은 평면 크로마키 배경으로 만든 뒤 로컬 제거 도구로 알파를 생성하고, 투명 모서리·피사체 점유율·색 번짐을 확인한다. PNG 중간 산출물은 프로젝트에 남기지 않고 최종 WebP만 코드에서 참조한다.

## 컴포넌트와 데이터 경계

- `DangerousFishingView`: 공용 상단 탭, 위험 해역 로컬 탭과 상태별 화면 전환을 담당한다.
- 출항 준비 컴포넌트: 해역 카드, 수심 선택, 장착 요약, 미끼 선택과 위험 미리보기를 담당한다.
- `DangerousFishingEncounterPanel`: 배경·대상 이미지가 있는 무대와 기존 게이지·조작을 담당하며 개인 어종과 거대어가 함께 사용한다.
- `DangerousFishingCargoPanel`: 이미지가 포함된 화물과 귀환 위험 안내를 담당한다.
- `DangerousFishingBossPanel`: 빈 상태와 이벤트 요약을 담당하고 조우 중에는 공용 조우 패널을 사용한다.
- 낚시 상점의 위험 해역 섹션: 상품 렌더링과 구매·장착 요청을 담당한다.
- 위험 해역 카탈로그: 해역 배경, 어종, 장비와 미끼의 이미지 경로를 제공한다.

표시 컴포넌트는 카탈로그 데이터만 읽고 이미지 경로를 자체 추측하지 않는다. 서버의 판정과 저장 형식에는 이미지 필드를 넣지 않는다.

## 오류와 대체 표시

- 상태 요청 실패 시 기존 오류 문구를 유지하고 선택·구매 버튼을 비활성화한다.
- 두 상점 상태 중 한쪽만 실패하면 정상인 탭은 계속 이용할 수 있고 실패한 탭에만 재시도 안내를 표시한다.
- 구매 성공 후 잔액 갱신이 실패하면 성공 결과는 유지하고 최신 상태를 다시 불러오도록 안내한다.
- 이미지 참조 누락은 `check-images`에서 빌드 실패로 처리한다. 런타임 네트워크 이미지 오류에는 의미 있는 어종·장비 이름이 남아 기능을 막지 않는다.

## 표면과 접근성

- 배경 이미지 위 텍스트와 조작은 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`의 불투명 표면 안에 둔다.
- 잠긴 해역과 미보유 상품 카드 전체에 `opacity-*`를 적용하지 않는다.
- 모든 장식 이미지는 빈 대체 텍스트를, 정보를 전달하는 어종·장비 이미지는 데이터 이름을 대체 텍스트로 사용한다.
- 탭, 해역 카드, 수심 버튼과 조작 버튼은 키보드 포커스와 선택 상태를 텍스트 및 `aria-*`로 전달한다.
- 라이트·다크 모드와 360px 모바일 너비에서 배경이 본문 뒤로 새지 않는지 확인한다.

## 검증

- 위험 해역 렌더 테스트에서 `출항`·`거대어` 탭, 진행 중 배지와 탭 전환 시 상태 보존을 확인한다.
- 출항 준비 테스트에서 해역 카드 잠금, 수심 선택, 위험 미리보기와 장착 장비 요약을 확인한다.
- 조우 테스트에서 대상별 이미지, 행동 안내, 세 게이지와 기존 세 조작 요청이 유지되는지 확인한다.
- 화물과 거대어 테스트에서 이미지·가치·손실 경고·기여도와 보상 상태를 확인한다.
- 낚시 상점 테스트에서 `일반 낚시`·`위험 해역` 탭, 장비 구매·장착, 미끼 묶음 구매와 공용 코인 갱신을 확인한다.
- 기존 위험 해역 서비스와 일반 낚시 상점 테스트를 회귀 실행해 가격·판정·저장 동작이 바뀌지 않았음을 확인한다.
- `npm run check-images`, TypeScript 검사, 린트, 관련 테스트와 프로덕션 빌드를 통과시킨다.
- 생성된 28개 이미지를 실제 카드 크기와 조우 무대 크기에서 각각 육안 검수한다.
