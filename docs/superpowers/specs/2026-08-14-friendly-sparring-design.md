# 유저 친선전 설계

**작성일:** 2026-08-14
**상태:** 승인됨

## 1. 목적

현재 대련장(`/battle/sparring`)은 보상과 손실 없이 허수아비를 상대로 장비·스킬·전투 패턴을 시험하는 공간이다. 여기에 특정 유저의 저장된 현재 세팅과 즉시 싸울 수 있는 비동기 친선전을 추가한다.

친선전은 아레나와 분리된 연습 기능이다. 상대의 접속이나 수락을 기다리지 않으며, 양쪽의 점수·전적·자원·기록에 영향을 주지 않는다.

## 2. 확정 범위

- 대련장 상단을 `허수아비 연습`과 `유저 친선전` 두 모드로 나눈다.
- 유저 친선전에서는 정확한 닉네임으로 상대를 찾는다.
- 공개 프로필에 `친선전` 버튼을 추가해 선택된 상대와 함께 대련장으로 이동한다.
- 전투는 상대의 저장된 현재 장비·스킬·전투 패턴을 사용해 즉시 서버에서 계산한다.
- 도전자에게만 결과와 전체 전투 로그를 현재 화면에서 보여준다.
- 결과는 새로고침하면 사라지며 양쪽 전투 기록과 알림에 남지 않는다.
- 친선전에는 스태미나·보상·점수·승패 전적·퀘스트 진행이 없다.
- 친선전 전용 10초 쿨타임과 고비용 전투 호출 제한을 적용한다.

다음 항목은 이번 범위에서 제외한다.

- 실시간 접속 및 초대·수락 흐름
- 닉네임 부분 검색과 자동 완성
- 친선전 전적, 최근 상대, 다시보기 보관
- 상대방 알림 또는 방어 기록
- 관전, 공유 링크, 다전제

## 3. 화면과 이용 흐름

### 3.1 대련장 모드

`V2SparringView`의 헤더 아래에 두 모드를 전환하는 컨트롤을 둔다.

- `허수아비 연습`: 기존 프리셋, 능력치 입력, 결과 및 리플레이를 그대로 유지한다.
- `유저 친선전`: 닉네임 검색, 선택된 상대 카드, 친선전 시작 버튼을 표시한다.

모드별 입력과 마지막 결과는 서로 섞이지 않는다. 친선전을 진행해도 허수아비 설정을 변경하지 않는다.

### 3.2 닉네임 검색

사용자가 닉네임을 정확히 입력해 검색하면 서버가 대상을 확인한다. 성공 시 불투명한 상대 카드에 다음 공개 정보만 표시한다.

- 프로필 이미지
- 닉네임
- 레벨

검색 결과는 전투 대상의 미리보기일 뿐이다. 전투 시작 시 서버가 대상을 다시 확인하고 최신 저장 세팅을 읽는다.

### 3.3 공개 프로필 바로가기

다른 유저의 공개 프로필에 `친선전` 버튼을 표시한다. 버튼은 다음 경로로 이동한다.

```text
/battle/sparring?mode=friendly&target=<URL 인코딩된 닉네임>
```

대련장은 쿼리를 읽어 친선전 모드를 선택하고 대상 검색을 자동 수행한다. 전투는 사용자가 `친선전 시작`을 눌렀을 때만 시작한다.

### 3.4 전투 결과

성공 응답은 대련장 친선전 모드 아래에서 `ReplayBattleScene`으로 재생한다. 승리·패배·무승부, 행동 수, 상대 이름과 전체 전투 로그를 보여준다. 같은 상대와 다시 싸우거나 다른 닉네임을 검색할 수 있다.

결과는 클라이언트 상태에만 보관한다. 별도 기록 식별자나 다시보기 URL은 만들지 않는다.

## 4. 서버 구조

기존 허수아비 API(`/api/v2/training/spar`)는 변경하지 않는다. 친선전은 책임과 엔진이 다른 PvP 기능이므로 전용 라우트로 분리한다.

### 4.1 상대 조회

```text
GET /api/v2/training/friendly?name=<정확한 닉네임>
```

응답은 공개 가능한 대상 요약만 포함한다.

```ts
type FriendlyTargetResponse =
  | {
      ok: true;
      target: {
        name: string;
        level: number;
        avatar: Avatar;
        profileBorder: ProfileBorderId | null;
      };
    }
  | { ok: false; error: FriendlySparringError };
```

표시 닉네임 해석은 공개 프로필과 같은 규칙을 쓴다. `users.game_name`을 우선하고 비어 있으면 `character-profile.v2.name`을 사용하며, 대소문자를 구분하지 않는 정확 일치로 찾는다.

### 4.2 친선전 실행

```text
POST /api/v2/training/friendly
Content-Type: application/json

{ "targetName": "상대 닉네임" }
```

서버는 클라이언트가 보낸 전투 능력치를 신뢰하지 않는다. 닉네임을 다시 userId로 해석하고 양쪽의 최신 저장 데이터를 읽어 전투원을 만든다.

성공 응답은 다음 정보만 반환한다.

```ts
type FriendlySparringResult = {
  outcome: "win" | "loss" | "draw";
  turns: number;
  opponent: { name: string; level: number };
  replay: ReplayPayload;
  startPlayerHp: number;
  cooldownMs: number;
};
```

### 4.3 전투원 준비

공통 서버 도우미가 한 유저의 현재 전투 세팅을 읽고 PvP 전투원을 만든다.

- `character.v2`
- `equipment.v2`의 현재 장착 장비
- `skills.v2`의 현재 장착 스킬과 전투 패턴
- `proficiency.v2`
- 도감 SP 보너스와 직업 해금 문맥

코어 루프가 켜진 경우 기존 서버 규칙으로 스킬 로드아웃을 정규화한다. 아레나 전용 `arena-loadouts.v2`는 읽지 않는다. 양쪽 모두 음식 효과를 제외하고 최대 HP·MP 상태로 시작한다.

### 4.4 전투 계산

아레나와 같은 `resolveBattlePvP` 엔진 및 자동 대련 문맥을 사용한다. 피해와 회복 보정도 아레나 상수를 그대로 참조해 친선전이 실제 PvP 연습으로 기능하게 한다. 별도의 친선전 전용 수치 사본은 만들지 않는다.

전투 결과는 도전자 관점의 `ReplayPayload`로 변환한다. 데이터베이스 저장이나 배틀 리플레이 보관소 쓰기는 수행하지 않는다.

## 5. 비용, 쿨타임, 부작용

친선전은 순수 읽기 및 계산 요청이다.

- 스태미나를 소비하지 않는다.
- 골드·아이템·코인을 지급하지 않는다.
- 아레나 Elo와 주간 승패를 변경하지 않는다.
- `arena-state.v2`, `arena-history.v2`, 캐릭터 세이브를 변경하지 않는다.
- 퀘스트와 업적의 전투 또는 아레나 횟수로 세지 않는다.
- 상대방에게 기록이나 알림을 만들지 않는다.

친선전 실행에는 도전자 기준 10초 쿨타임을 서버에서 강제한다. 이 쿨타임은 허수아비와 아레나 쿨타임에 영향을 주지 않는 별도 액션 키를 사용한다. 응답의 `retryAfterSec` 또는 `cooldownMs`로 클라이언트 카운트다운을 맞춘다. 고비용 전투에 대한 분당 사용자·IP 제한도 별도로 유지한다.

## 6. 접근 제어와 오류 처리

GET과 POST 모두 로그인한 유저만 호출할 수 있다. 다음 대상은 선택할 수 없다.

- 자기 자신
- 존재하지 않거나 캐릭터가 없는 유저
- 운영 계정
- 어느 한쪽이 상대를 차단한 관계
- 전투 세팅을 정상적으로 만들 수 없는 유저

존재 여부나 차단 관계를 추측하지 못하도록 자기 자신을 제외한 대상 검증 실패는 사용자 화면에서 기본적으로 `상대를 찾을 수 없습니다`로 통일한다. 자신의 캐릭터가 없거나 도전자 세팅이 손상된 경우에는 `내 캐릭터 정보를 불러올 수 없습니다`로 구분한다.

쿨타임은 HTTP 429와 남은 시간을 반환한다. 잘못된 요청은 400, 인증 실패는 401로 처리한다. 모든 실패는 자원 및 저장 데이터 변화 없이 끝난다.

## 7. 클라이언트 구조

- `V2SparringView`: 모드 전환과 각 패널 배치
- 기존 허수아비 패널 및 `useSparring`: 현재 동작 유지
- 새 `FriendlySparringPanel`: 검색 폼, 상대 카드, 전투 버튼, 결과 장면
- 새 친선전 훅: GET/POST 요청, 동시 제출 방지, 오류, 전용 쿨타임 카운트다운
- `V2CharacterScreen`: 다른 유저 공개 보기일 때 친선전 바로가기 표시
- 대련장 페이지: `mode`와 `target` 검색 파라미터를 읽어 초기 친선전 선택에 전달

상대 검색을 새로 수행하면 이전 친선전 결과를 지운다. 검색된 대상의 이름이 바뀌거나 삭제된 경우 POST 재검증 결과를 표시하고 자동으로 다른 대상을 선택하지 않는다.

## 8. 테스트와 검증

가능한 경우 회귀 테스트를 먼저 작성한다.

### 8.1 서버 테스트

- 비로그인 GET/POST 거부
- 정확한 닉네임 및 대소문자 무시 조회
- 본인, 운영 계정, 상호 차단, 존재하지 않는 대상 거부
- 캐릭터가 없거나 전투원 파생이 실패한 대상 거부
- 현재 장비·스킬·패턴을 사용하고 아레나 전용 세팅을 사용하지 않음
- 음식 효과 제외와 아레나 PvP 보정 적용
- 정상 전투 응답에 도전자 관점 리플레이 포함
- 친선전 뒤 캐릭터·아레나·퀘스트·기록 저장이 호출되지 않음
- 10초 쿨타임 및 고비용 호출 제한

### 8.2 클라이언트 테스트

- 허수아비/유저 친선전 모드 전환
- 쿼리 대상 자동 조회, 전투 자동 시작 금지
- 검색 성공·실패와 상대 카드 표시
- 빠른 중복 제출 방지와 쿨타임 카운트다운
- 승리·패배·무승부 결과와 전체 로그 표시
- 공개 프로필 친선전 링크 생성

### 8.3 완료 전 검증

구현 전에 저장소에 포함된 현재 Next.js 가이드에서 라우트 핸들러와 검색 파라미터 관련 문서를 확인한다. 구현 후 관련 테스트, TypeScript 검사, ESLint와 이미지 참조 검사를 실행한다.

## 9. 성공 기준

- 사용자가 대련장에서 정확한 닉네임으로 다른 유저를 선택해 즉시 친선전을 할 수 있다.
- 공개 프로필에서 선택된 상대가 있는 대련장으로 이동할 수 있다.
- 친선전은 현재 세팅과 아레나 PvP 보정을 정확히 반영한다.
- 전투 결과와 전체 로그는 도전자에게만 일시적으로 보인다.
- 양쪽의 자원·점수·전적·기록·알림·퀘스트 진행은 전혀 바뀌지 않는다.
- 10초 쿨타임, 호출 제한, 차단 및 운영 계정 제외가 서버에서 강제된다.
