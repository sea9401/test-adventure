# 생활 현장정보 포커스 갱신 안정화 설계

## 문제

생활 지도, 낚시, 벌목, 채광은 `LifeFieldPanels`의 공통 상태 훅을 사용한다. 창이 다시 포커스를 받거나 생활 활동 완료 이벤트가 발생하면 훅이 `loading=true`로 바뀌고, 화면은 이미 받은 현장정보 카드 대신 높이가 다른 로딩 카드를 렌더링한다. PC에서 창 복귀와 클릭이 이어질 때 아래 콘텐츠가 이동해 클릭 대상이 바뀌고 화면이 깜빡일 수 있다.

## 목표

- 최초 요청에는 기존 로딩 화면을 유지한다.
- 이미 정상 데이터를 받은 뒤의 포커스·이벤트·예약 갱신은 기존 내용을 계속 표시한다.
- 백그라운드 갱신이 실패해도 기존 데이터가 있으면 그 데이터를 유지한다.
- 데이터가 전혀 없는 최초 실패에는 기존 오류 화면을 표시한다.
- API, 갱신 주기, 사람 확인 로직은 변경하지 않는다.

## 설계

데이터 존재 여부, 로딩 여부, 오류 여부를 입력받아 `loading | error | ready`를 반환하는 순수 표시 상태 함수를 별도 파일에 둔다. 데이터가 있으면 로딩·오류 플래그보다 `ready`를 우선한다. `LifeFieldEnvironmentCard`와 `LifeFieldCodexPanel`은 이 판단을 공통으로 사용한다.

이 방식은 요청 로직을 바꾸지 않고 DOM 교체만 막으므로 영향 범위가 작다. 기존 데이터를 렌더링하는 동안 새 응답이 오면 React가 내용만 갱신한다.

## 검증

순수 함수 테스트로 다음 네 경계를 고정한다.

- 데이터 없음 + 로딩: `loading`
- 데이터 없음 + 오류: `error`
- 데이터 있음 + 재갱신 중: `ready`
- 데이터 있음 + 재갱신 실패: `ready`

관련 생활 현장정보·사람 확인 테스트, TypeScript 검사와 ESLint를 함께 실행한다.
