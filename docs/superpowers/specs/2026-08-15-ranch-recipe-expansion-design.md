# 목장 재료 요리 확장 설계

## 목표

목장에서 생산하는 돼지고기·달걀·우유의 소비처를 넓힌다. 기존 33종 요리의 단계별 분포와 능력치 조합을 해치지 않으면서 새 요리 6종을 추가하고, 모든 요리에 기존 아이콘과 같은 화풍의 전용 이미지를 제공한다.

## 범위와 배치

한 재료에 3종씩 9종을 추가하면 콘텐츠와 이미지가 한 번에 과도하게 늘어나고, 3종만 추가하면 재료별 선택지가 거의 늘지 않는다. 따라서 재료군별 2종씩 총 6종을 추가한다. 돼지고기는 농사 Lv.50 목장에서 나오므로 Lv.50에 배치하고, 달걀과 우유는 Lv.20과 Lv.35에 나눠 중반 요리 선택지를 보강한다.

## 데이터와 검색

새 요리는 기존 `recipe()` 생성기를 통해 `COOKING_RECIPES`에 직접 등록한다. 이미지 경로는 `/images/items/cooking/${recipeId}.webp` 규칙을 그대로 따른다. 재료 이름 검색은 기존 `cookingRecipeMatchesQuery()`가 `FARM_ITEMS` 이름을 읽으므로, `돼지고기`, `달걀`, `우유` 검색으로 새 요리가 노출되어야 한다.

새 레시피는 별도의 저장 마이그레이션이 필요 없다. 요리 도감의 최종 목표는 `COOKING_RECIPES.length`를 사용하므로 자동으로 39종에 맞춰진다. 이미 발견한 레시피와 보유 음식 식별자는 그대로 유지된다.

## 이미지

기존 요리 아이콘을 스타일 참조로 사용해 각 요리를 별도로 생성한다. 모든 이미지는 중앙에 음식 한 접시만 배치한 정사각형 판타지 게임 아이콘이며, 텍스트·테두리·사람·식기류는 넣지 않는다. 평면 크로마키 배경으로 생성한 뒤 알파를 제거하고, `items` 프로필과 같은 256×256 WebP 품질 85로 저장한다.

- `public/images/items/cooking/egg_fried_rice.webp`
- `public/images/items/cooking/milk_rice_porridge.webp`
- `public/images/items/cooking/soy_braised_eggs.webp`
- `public/images/items/cooking/milk_custard_pudding.webp`
- `public/images/items/cooking/crispy_pork_cutlet.webp`
- `public/images/items/cooking/soy_pork_rice_bowl.webp`

## 검증

`cooking.test.ts`에서 단계별 개수, 여섯 레시피의 재료·경험치·효과·희귀 재료, 재료명 검색을 검증한다. 이후 관련 테스트, TypeScript, ESLint, 이미지 참조 검사와 전체 테스트를 실행한다. 병행 중인 다른 작업의 미완성 이미지가 전역 이미지 검사를 막는 경우, 새 여섯 자산의 참조·존재·고아 여부를 별도로 확인하고 전역 실패 원인을 분리해 보고한다.
