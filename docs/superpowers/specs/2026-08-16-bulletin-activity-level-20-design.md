# 게시판 활동 레벨 20 확장 설계

## 배경

현재 커뮤니티 성장 지표는 게시판 활동 레벨이다. 게시글, 각 글에 남긴 첫 댓글,
다른 이용자에게 받은 좋아요를 점수로 환산하며 Lv.10·460점에서 성장이 끝난다.
장기 활동자가 계속 진행도를 쌓고 전시 보상을 얻을 수 있도록 상한을 Lv.20으로
확장한다.

이번 변경의 커뮤니티 레벨은 게시판 활동 레벨만 뜻한다. 채팅, 길드, 프로필 업적과
별도의 통합 커뮤니티 경험치 시스템은 추가하지 않는다.

## 목표

- 게시판 활동 레벨 상한을 Lv.10에서 Lv.20으로 확장한다.
- 글·댓글 인정량을 채우고 하루 평균 좋아요 1개를 받는 이용자가 약 6개월에
  Lv.20에 도달하게 한다.
- 기존 누적 활동 점수를 그대로 인정한다.
- Lv.15와 Lv.20에 영구 장착 칭호를 하나씩 지급한다.
- 기존 Lv.1~10의 점수 기준, 등급명, 칭호 보상을 바꾸지 않는다.
- 점수 산식, 일일 인정 한도, API와 DB 구조는 바꾸지 않는다.

## 선택한 접근

기존 `BULLETIN_ACTIVITY_LEVELS` 정적 표에 Lv.11~20을 추가한다. 수식으로 신규
구간을 생성하거나 Lv.10 이후 별도 등급을 도입하지 않는다. 정적 표는 운영자가 각
경계를 바로 읽고 특정 구간만 조정하기 쉬우며 현재 구현과도 일치한다.

게시글은 하루 2개까지 각 3점, 댓글은 하루 5개까지 각 1점이므로 글·댓글로 하루
최대 11점을 얻는다. 다른 이용자에게 받은 좋아요 1개 4점을 더한 하루 15점 기준으로
Lv.20의 2,610점은 174일 분량이다. 좋아요 수와 실제 활동일에 따라 도달 기간은
달라질 수 있다.

## 레벨 표

Lv.1~10은 현재 값을 그대로 유지한다.

| 레벨 | 최소 누적 점수 | 등급명 |
|---:|---:|---|
| 1 | 0 | 새싹 |
| 2 | 10 | 첫걸음 |
| 3 | 25 | 이야기꾼 |
| 4 | 50 | 이웃 |
| 5 | 85 | 단골 |
| 6 | 130 | 소식통 |
| 7 | 190 | 조언자 |
| 8 | 265 | 명필 |
| 9 | 355 | 현자 |
| 10 | 460 | 광장지기 |
| 11 | 585 | 길잡이 |
| 12 | 730 | 기록가 |
| 13 | 895 | 경청자 |
| 14 | 1,080 | 중재자 |
| 15 | 1,285 | 원로 |
| 16 | 1,510 | 연대기 작가 |
| 17 | 1,755 | 명망가 |
| 18 | 2,020 | 광장의 등불 |
| 19 | 2,305 | 산증인 |
| 20 | 2,610 | 전설 |

Lv.10에서 Lv.11로 오르는 데 필요한 추가 점수는 125점이며, 이후 레벨마다 20점씩
늘어난다. Lv.19에서 Lv.20으로 오르는 마지막 증가량은 305점이다.

## 칭호 보상

기존 Lv.3, Lv.5, Lv.7, Lv.10 보상은 유지하고 다음 두 보상을 추가한다.

- Lv.15 `광장 원로`
  - ID: `bulletin_elder`
  - 설명: 오랜 시간 광장의 이야기를 듣고 사람들의 자리를 이어 준 원로.
  - 조건: 게시판 활동 Lv.15 달성
- Lv.20 `광장의 전설`
  - ID: `bulletin_legend`
  - 설명: 수많은 이야기와 인연으로 광장의 역사를 함께 써 내려간 전설.
  - 조건: 게시판 활동 Lv.20 달성

칭호는 전투 능력치가 없는 수집·전시 보상이다. 기존 칭호 동기화 로직을 사용해
획득 자격이 있는 모든 미보유 이정표 칭호를 영구 지급한다. 활동 원본이 삭제되어
점수가 내려가더라도 이미 받은 칭호는 회수하지 않는다.

## 소급과 데이터 흐름

활동 점수는 저장된 레벨 값이 아니라 현재 게시글·댓글·좋아요 집계에서 매번
파생된다. 따라서 DB 마이그레이션이나 일괄 갱신 작업 없이 새 레벨 표를 적용한다.

기존 Lv.10 이용자도 보유 점수가 신규 경계를 넘으면 게시판 조회 시 즉시 해당
레벨로 표시된다. Lv.15 또는 Lv.20에 도달한 이용자는 게시판을 열거나 게시글·댓글·
좋아요 관련 요청이 처리될 때 기존 최선 노력 방식으로 칭호를 받는다. 칭호 저장이
일시적으로 실패해도 이미 성공한 게시판 요청은 실패로 바꾸지 않으며 다음 동기화
기회에 다시 시도한다.

## UI

- 활동 카드의 점수, 다음 레벨 진행률, 다음 칭호 안내 구조를 유지한다.
- Lv.10은 더 이상 최고 레벨이 아니며 `460 / 585점`에서 다음 레벨 진행을 시작한다.
- Lv.11~14에서는 다음 칭호로 Lv.15 `광장 원로`를 안내한다.
- Lv.15~19에서는 다음 칭호로 Lv.20 `광장의 전설`을 안내한다.
- Lv.20에서는 진행률 100%, `최고 레벨`, `게시판 칭호 보상을 모두 해금했습니다.`를
  표시한다.
- Lv.1~10 배지 스타일은 그대로 유지한다.
- Lv.11~19는 기존 색상 계열을 더 진한 배경과 테두리 효과로 반복해 상위 구간임을
  구분한다.
- Lv.20은 금색 계열 전용 스타일로 최고 레벨을 강조한다.
- 활동 카드와 진행률 영역은 기존 불투명 `Card`와 `SURFACE_INSET` 표면을 유지한다.

## 오류와 호환성

- 숫자가 아니거나 음수인 활동 집계값은 기존처럼 0 이상의 정수로 정규화한다.
- 최고 경계를 넘는 모든 점수는 Lv.20, 진행률 100%로 표시한다.
- 배지 스타일 함수는 1 미만 입력을 Lv.1, 20 초과 입력을 Lv.20으로 제한한다.
- 점수 산식과 집계 SQL을 변경하지 않으므로 기존 게시판 API 응답 구조는 유지된다.
- 기존 클라이언트가 받는 활동 요약 필드도 바뀌지 않는다.

## 테스트

- 기존 Lv.1~10의 최소 점수와 등급명이 변하지 않았는지 검증한다.
- Lv.11~20 각 경계의 1점 전과 정확한 기준점에서 레벨이 올바른지 검증한다.
- 2,610점 이상이 Lv.20, 다음 레벨 없음, 진행률 100%로 제한되는지 검증한다.
- 기존 고점 활동 내역이 별도 이전 없이 신규 레벨로 소급 계산되는지 검증한다.
- Lv.14에는 신규 칭호가 없고 Lv.15에는 `bulletin_elder`, Lv.20에는
  `bulletin_elder`와 `bulletin_legend`가 포함되는지 검증한다.
- 신규 칭호 ID, 이름과 `titles.ts` 정의가 일치하는지 검증한다.
- 배지 Lv.1~20 스타일이 구분되고 범위 밖 입력이 양 끝으로 제한되는지 검증한다.
- 활동 카드가 Lv.10에서 다음 레벨과 Lv.15 칭호를, Lv.15에서 Lv.20 칭호를,
  Lv.20에서 최고 레벨 안내를 표시하는지 검증한다.
- 관련 게시판 활동·칭호 동기화 테스트, TypeScript 검사와 ESLint를 함께 실행한다.

## 제외 범위

- 채팅·길드·프로필 활동을 합산하는 통합 커뮤니티 레벨
- 점수 배율, 일일 게시글·댓글 인정 한도, 좋아요 점수 또는 어뷰징 방지 규칙 변경
- 전투 능력치, 재화, 아이템 보상
- 관리자 수동 레벨 조정 도구와 별도 레벨 저장 컬럼
- 배포
