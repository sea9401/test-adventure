# 요리 납품·목장 요리 개선 설계

## 목표

완성 요리의 꾸준한 소모처를 만들고 하루 3건뿐인 주문 납품을 확장한다. 동시에 16시간 비육과 배합 사료를 요구하는 돼지고기 요리를 최종급 음식으로 상향하고, 달걀·우유·돼지고기를 사용하는 신규 요리 6종을 추가한다.

## 납품 구조

### 오늘의 정규 주문

- 일일 주문 수를 3건에서 6건으로 늘린다.
- 주문 레시피는 서로 중복되지 않아야 한다.
- 배포 당일 이미 노출된 첫 3개 주문과 완료 슬롯은 가능한 한 유지하고, 뒤에 새 주문 3건을 보충한다.
- 기존 단계별 보상은 유지한다. Lv.1/10/20/35/50 주문은 각각 5만/10만/15만/20만/25만 골드와 단계에 맞는 농장 증표 및 추가 요리 XP를 지급한다.
- 정성작은 골드·추가 XP +20%와 증표 +1, 걸작은 골드·추가 XP +50%와 증표 +2를 유지한다.

### 상시 납품

- 오늘 주문 아래에 보유한 모든 완성 요리를 받는 상시 납품을 추가한다.
- 계정당 하루 최대 20개를 납품할 수 있으며, 같은 완성 요리 변형은 한 번에 여러 개 납품할 수 있다.
- 레시피 요구 레벨에 따라 개당 보상을 지급한다.

| 요구 레벨 | 개당 기본 골드 |
| --- | ---: |
| 1 | 10,000 |
| 10 | 20,000 |
| 20 | 30,000 |
| 35 | 40,000 |
| 50 | 50,000 |

- 정성작은 +20%, 걸작은 +50%를 적용한다.
- 농장 증표와 추가 요리 XP는 지급하지 않는다.
- 희귀 재료 사용과 장시간 효과에는 별도 보상 배율을 적용하지 않는다.
- 일일 상태에 상시 납품 수량을 추가한다. 필드가 없는 기존 저장과 날짜가 바뀐 저장은 0개로 정규화하고, 손상된 값은 0~20 범위로 제한한다.

## 돼지고기 요리 상향

돼지우리의 16시간 비육, 배합 사료 4개, 돼지고기 8개 출하량과 기존 레시피의 돼지고기 요구량·제작 XP는 유지한다. 생산량 대신 음식 효과를 높여 희소한 최종급 재료라는 정체성을 살린다.

| 요리 | 기본 효과 | 희귀 특선 효과 |
| --- | --- | --- |
| 허브 돼지고기 구이 | 힘 20% · 활력 10% | 없음 |
| 바삭한 돼지고기 커틀릿 | 힘 20% · 민첩 10% | 힘 25% · 민첩 12% |
| 간장 돼지고기 덮밥 | 활력 20% · 힘 10% | 활력 25% · 힘 12% |

기존 품질 배율을 그대로 적용한다. 기본 걸작은 24%·12%, 희귀 특선 걸작은 최대 30%·14.4%가 된다.

## 화면과 처리 흐름

`주문 납품` 화면은 위쪽의 오늘 주문 6건과 아래쪽의 `상시 납품 N/20` 영역으로 나눈다. 상시 납품에는 현재 보유한 완성 요리만 표시하고 다음 정보를 제공한다.

- 요리 이미지와 이름
- 일반·정성작·걸작 품질
- 희귀 특선·장시간 여부
- 보유 수량과 개당 보상
- 납품 수량 입력과 총 예상 보상

납품 수량 기본값은 1개다. 기존처럼 불투명한 `SURFACE_INSET`과 `SURFACE_CARD`를 사용해 장면 배경이 콘텐츠 뒤로 비치지 않게 한다.

기존 요리 API의 납품 처리를 확장해 선택한 동일 음식 변형을 트랜잭션 안에서 여러 개 차감하고 총 골드를 지급한 뒤 일일 상시 납품 수량을 갱신한다. 보유량 부족, 남은 횟수 초과, 잘못된 음식 ID는 모두 거부한다. 실패하면 음식·골드·일일 수량 중 어느 것도 바뀌지 않는다.

## 이미지 자산

기존 음식 아이콘을 스타일 참조로 사용해 다음 파일을 각각 생성한다.

- `public/images/items/cooking/egg_salad_sandwich.webp`
- `public/images/items/cooking/corn_milk_chowder.webp`
- `public/images/items/cooking/strawberry_milk_parfait.webp`
- `public/images/items/cooking/spicy_pork_stew.webp`
- `public/images/items/cooking/royal_pork_pie.webp`
- `public/images/items/cooking/ranch_grand_feast.webp`

각 이미지는 중앙에 음식 한 접시만 배치한 정사각형 판타지 게임 아이콘으로 만든다. 기존 아이콘과 같은 3/4 시점, 따뜻한 조명, 선명한 음식 실루엣을 사용하고 텍스트·테두리·사람·워터마크는 넣지 않는다. 평면 크로마키 배경으로 생성한 뒤 알파를 제거하고 `items` 프로필에 맞춰 256×256 WebP 품질 85로 저장한다. 생성 근거는 자산 권리 기록에 추가한다.

## 오류 처리와 호환성

- 기존 저장의 정규 주문 완료 기록은 최대 6개까지 읽되 기존 완료 ID를 그대로 유지한다.
- 배포 당일 새로 열린 뒤쪽 주문만 추가로 수행할 수 있게 한다.
- 상시 납품 요청 수량은 양의 정수여야 하며 보유량과 남은 일일 한도 이하여야 한다.
- 서버가 계산한 레시피 단계와 품질만 보상에 사용하며 클라이언트가 보낸 보상 값은 신뢰하지 않는다.
- 상시 납품 응답은 갱신된 완성 요리 재고, 캐릭터 골드와 요리 일일 상태를 반환해 추가 새로고침 없이 화면을 맞춘다.

## 검증

- 정규 주문 6건의 유일성, 결정성, 기존 첫 주문 호환과 일일 완료 기록 파싱을 단위 테스트한다.
- 상시 납품의 단계별·품질별 단가와 하루 20개 제한을 단위 테스트한다.
- API에서 여러 개 납품 성공, 재고 부족, 한도 초과와 잘못된 음식 ID의 원자적 실패를 검증한다.
- 기존 돼지고기 요리 3종과 신규 6종의 재료·XP·효과·희귀 특선을 고정값으로 검증한다.
- 신규 레시피의 달걀·우유·돼지고기 재료명 검색과 전체 45종 도감을 검증한다.
- UI에서 보유량, 품질·특선·장시간 태그, 개당·총 보상, 기본 수량 1과 남은 한도를 검증한다.
- 관련 테스트, TypeScript 검사, ESLint와 `npm run check-images`를 실행한다.
