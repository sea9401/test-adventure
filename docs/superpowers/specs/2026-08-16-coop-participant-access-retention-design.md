# 협동 보스 기존 참여자 접근권한 승계 설계

## 문제

공개 협동 보스에 피해를 기록한 뒤 소환자가 공개 범위를 `길드원만` 또는 `나만`으로
좁히면, 범위 밖 참여자는 활성 목록에서 세션을 잃고 이후 공격도 거절된다. 2026-08-16
05:41에 생성된 심연어룡 세션에서 주닝쓰 사용자가 4회·375,153 피해를 기록한 뒤
소환자가 05:53에 `길드원만`으로 변경하면서 이 현상이 실제 발생했다. 세션은 처치되지
않고 HP 489,904가 남았지만 사용자에게는 보스와 보상이 함께 사라진 것처럼 보였다.

## 동작 계약

- 공개 범위는 새 참여자의 조회·공격 권한을 계속 제한한다.
- 한 번이라도 양수 피해를 기록한 기존 참여자는 이후 공개 범위가 좁아져도 해당 활성
  세션을 목록에서 보고 계속 공격할 수 있다.
- 기존 참여자가 아닌 범위 밖 사용자는 현재와 같이 세션을 보거나 공격할 수 없다.
- 제한 범위 밖에서 권한을 승계한 세션은 목록의 `참여 중인 보스` 구역에 표시해 현재
  공개 범위와 참여 경위를 혼동하지 않게 한다.
- 처치 판정, 기여도, 보상 산정·수령 및 소환자의 공개 범위 변경 기능은 바꾸지 않는다.

## 구현

`canAccessCoopBoss`에 기존 참여 여부를 선택 인자로 추가한다. 기본값은 `false`여서 기존
호출의 의미를 보존하고, 협동 보스 목록과 공격 라우트만 기여 행 존재 여부를 전달한다.
목록 API는 가시성 필터 전에 현재 사용자의 활성 세션 기여를 읽어야 한다. 공격 API는
시뮬레이션 전 빠른 권한 검사와 세션 잠금 후 race 재검사 양쪽에서 참여 여부를 적용한다.

클라이언트 목록 분류에는 제한 범위 세션이면서 내 피해가 양수인 경우를 위한
`participated` 구역을 추가한다. 전체 공개 세션은 기존 `전체 공개` 구역에 그대로 둔다.

## 검증

- 순수 권한 테스트: 범위 밖 기존 참여자는 허용되고 비참여자는 거절된다.
- 목록 분류 테스트: `summoner_only`/`guild_only` 기존 참여자가 누락되지 않고 전용 구역에
  정확히 한 번 들어간다.
- 관련 집중 테스트, TypeScript, ESLint, 전체 테스트를 실행한다.
- 운영 배포나 운영 데이터 변경은 하지 않는다.
