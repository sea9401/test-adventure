# 수행 일괄 실행 오조작 방지 설계

## 문제

모바일에서 1회 수행을 반복할 때 같은 줄의 버튼 문구와 폭이 요청 상태에 따라 바뀌고,
좁은 너비에서는 `flex-wrap` 재배치가 발생할 수 있다. 반복 탭 좌표에 옆의
`가능한 만큼 수행` 버튼이 들어오면 사용자가 의도하지 않은 일괄 수행이 즉시 실행된다.

## 설계

- `수행`과 `가능한 만큼 수행` 버튼 문구를 처리 중에도 유지해 버튼 폭을 바꾸지 않는다.
- 모바일에서는 두 버튼을 고정된 1:2 그리드 칸에 두고, 수행 상태 요약과 액션을 서로
  다른 행에 배치한다. 넓은 화면에서도 버튼 칸은 고정 폭을 사용한다.
- `가능한 만큼 수행`의 첫 클릭은 서버 요청을 보내지 않고 확인 모달만 연다.
- 모달의 별도 `가능한 만큼 수행 확정` 버튼을 눌렀을 때만 기존 `mode=max` 요청을 보낸다.
- 모달은 기존 최대 제작 확인창과 동일하게 불투명 표면, `role="dialog"`,
  `aria-modal`, 제목/설명 연결, Escape 및 바깥 영역 닫기를 제공한다.
- 1회 수행과 서버 수행 계산, 비용, 초기화 흐름은 변경하지 않는다.

## 테스트

- 액션 영역이 모바일 고정 그리드이며 처리 중에도 두 버튼 문구가 유지되는지 정적 렌더링으로 확인한다.
- 일괄 수행 버튼이 대화상자를 연다는 접근성 속성을 갖는지 확인한다.
- 확인 모달이 독립된 확정 버튼과 접근성 대화상자 구조를 렌더링하는지 확인한다.
- 기존 요청 직렬화 및 결과 요약 테스트를 함께 실행한다.
