# 위험 해역 어획물·거대어 증표 사용처 설계

## 배경

위험 해역에서 안전 귀환한 어획물과 거대어 공동 제압 보상인 증표는 현재
`character.v2.materials`에 거래 가능한 재료로 들어간다. 두 재료군 모두 거래소에는
등록할 수 있지만, 제작·교환·NPC 판매 사용처가 없다. 포획 당시 지급되는 낚시 경험치,
낚시 코인, 도감 기록과 별개로 인벤토리에 남은 재료의 목적이 보이지 않아 이용자가
사용처를 문의하고 거래소 수요도 생기기 어렵다.

이 변경은 위험 해역 보상이 다시 위험 해역 플레이로 이어지는 순환을 만들고, 거대어
증표에는 한 번 획득해 오래 보여 줄 수 있는 수집 목표를 부여한다.

## 목표

- 모든 위험 해역 어획물에 반복 가능한 사용처를 만든다.
- 거대어 증표를 최상급 위험 해역 장비의 대체 구매 경로와 한정 수집 보상에 사용한다.
- 새 화폐를 만들지 않고 기존 재료, 낚시 코인, 장비·칭호·꾸미기 상태를 재사용한다.
- 전투 능력치나 SP에 영향을 주지 않고 위험 해역 내부 성장에만 보상을 연결한다.
- 기존 재료와 증표의 거래소 거래를 유지해 플레이하지 않는 이용자도 거래로 참여할 수
  있게 한다.
- 인벤토리, 귀환 결과, 거대어 보상, 상점, 매뉴얼에서 사용처를 바로 찾을 수 있게 한다.

## 비목표

- 위험 해역 재료의 NPC 골드 판매를 열지 않는다.
- 위험 해역 장비 강화 단계나 영구 능력치 성장 시스템을 새로 만들지 않는다.
- 요리, 길드 제작소, 일반 전투 성장 재료로 연결하지 않는다.
- 기존 최상급 장비 보유자에게 코인이나 증표를 소급 환불하지 않는다.
- 기존 코인 단독 장비 구매 경로와 가격을 변경하지 않는다.
- 배포나 점검 모드 변경은 이 작업 범위에 포함하지 않는다.

## 핵심 보상 순환

낚시 상점에 `위험 해역 교환` 구역을 추가한다. 낚시 Lv.15부터 노출하며 별도 상점과
별도 화폐는 만들지 않는다.

```text
위험 해역 포획 → 안전 귀환 → 거래 가능한 어획물
       ↓                           ↓
 낚시 경험치·코인·도감      특수 미끼로 교환 → 다음 출항

거대어 공동 제압 → 거래 가능한 증표
       ↓
최상급 장비 할인 교환 / 칭호·프로필 테두리 / 반복 미끼 교환
```

### 어획물 교환

같은 등급의 어획물은 서로 다른 어종을 섞어 납품할 수 있다. 등록 권리나 최대 크기 같은
도감 기록은 어획물 재료와 별도이므로 교환해도 영향을 받지 않는다.

| 교환 ID | 소모 | 지급 |
|---|---:|---:|
| `catch_common_to_reef_bait` | 일반 어획물 4개 | 암초 향 미끼 5개 |
| `catch_rare_to_blood_bait` | 희귀 어획물 4개 | 핏빛 미끼 5개 |
| `catch_epic_to_luminous_bait` | 영웅 어획물 3개 | 발광 미끼 5개 |
| `catch_legendary_to_abyss_bait` | 전설 어획물 2개 | 심연 응축 미끼 5개 |

교환 횟수에는 일일·주간 제한을 두지 않는다. 투입 재료가 포획 성공과 안전 귀환을 거쳐야
하고, 특수 미끼도 실제로 물고기가 걸렸을 때 소모되므로 별도 시간 제한은 필요하지 않다.

### 증표 장비 교환

기존 코인 단독 구매는 그대로 둔다. 아래 항목은 증표를 모은 이용자가 더 적은 코인으로
같은 장비를 얻는 대체 경로다. 장비 보유 목록은 기존 `dangerous-fishing.v1`을 사용하고,
어느 경로로 구매했든 한 번만 보유한다.

| 교환 ID | 지급 장비 | 소모 |
|---|---|---|
| `token_maelstrom_reel` | 대소용돌이 릴 | 해일의 거신 증표 8개 + 낚시 코인 20,000 |
| `token_abyss_chain_line` | 심연 사슬줄 | 심연 크라켄 증표 8개 + 낚시 코인 35,000 |
| `token_leviathan_rod` | 레비아탄 낚싯대 | 해일의 거신 증표 8개 + 심연 크라켄 증표 4개 + 낚시 코인 40,000 |

이미 장비를 보유한 이용자에게는 해당 교환을 노출하되 `보유 중`으로 비활성화한다. 소급
환불은 하지 않으며, 보유자는 증표를 수집 보상과 반복 미끼 교환에 사용할 수 있다.

### 증표 수집·반복 교환

| 교환 ID | 소모 | 지급 |
|---|---|---|
| `token_tidal_title` | 해일의 거신 증표 10개 | 칭호 `파도를 거둔 자` |
| `token_abyss_title` | 심연 크라켄 증표 10개 | 칭호 `심연을 낚은 자` |
| `token_abyssal_border` | 두 증표 각각 15개 | 영구 프로필 테두리 `심해의 지배자` |
| `token_tidal_to_luminous_bait` | 해일의 거신 증표 1개 | 발광 미끼 5개 |
| `token_abyss_to_abyss_bait` | 심연 크라켄 증표 1개 | 심연 응축 미끼 5개 |

칭호 ID는 각각 `dangerous_tidal_conqueror`, `dangerous_abyss_conqueror`로 정의하고 낚시
카테고리에 넣는다. 프로필 테두리는 `dangerous_abyssal_profile_border` 아이템과
`abyssal_master` 스타일을 사용한다. 무슨 코인 상점이나 꾸미기 상자에서는 나오지 않는
위험 해역 전용 보상이다.

프로필 테두리는 기존 기간제 꾸미기와 달리 영구 사용한다. 기존 `character.v2`의
`museunCosmetics`에 `permanentOwned` 배열을 추가하고, 누락된 옛 저장값은 빈 배열로
해석한다. 장착 및 외형 해석 시 `permanentOwned`에 있는 항목은 `accessUntil`과 관계없이
활성으로 판단한다. 기존 기간제 꾸미기의 획득·연장·만료 동작은 바꾸지 않는다.
전용 테두리는 기존 꾸미기 타입과 렌더러가 인식하는 카탈로그에는 등록하되, 무슨 코인 상점
판매 목록과 무작위 꾸미기 상자 풀에는 등록하지 않는다.

## 화면과 발견 가능성

### 낚시 상점

기존 전용 장비·미끼 다음에 `위험 해역 교환` 구역을 둔다. 최상위 래퍼와 모든 교환 카드는
`SURFACE_CARD` 또는 `SURFACE_INSET`을 사용해 지역 배경이 비치지 않게 한다.

- 어획물 카드는 등급별 보유 합계, 1회 필요량, 교환 가능 횟수를 표시한다.
- `1회 교환`과 `최대 교환`을 제공한다.
- 혼합 납품 확인창에 어종별 소모 수량과 교환 후 잔량을 표시한다.
- 자동 선택은 같은 등급에서 보유 수량이 많은 어종을 먼저 고르고, 동률이면
  `cargoValue`가 낮은 어종, 다시 동률이면 카탈로그 순서를 따른다.
- 클라이언트가 자동 선택한 어종별 수량을 요청에 명시해 확인창과 실제 차감 내역이 달라지지
  않게 한다.
- 장비 카드에는 기존 `코인 구매`와 `증표 할인 교환`을 함께 표시한다.
- 칭호와 프로필 테두리는 이미 보유하면 `보유 중`으로 표시하고 다시 교환하지 못하게 한다.
- 반복 미끼 교환에는 현재 증표 잔액과 지급 미끼 수량을 표시한다.

`최대 교환`은 기존 일반 작물 떨이 교환과 같은 확인창 패턴을 재사용한다. 확인 없이 여러
회차를 한꺼번에 소모하지 않는다.

### 사용처 안내

- 위험 해역 어획물 설명을 `안전 귀환 후 위험 해역 교환이나 거래소에서 사용하는 어획물`로
  바꾼다.
- 거대어 증표 설명에 `최상급 전용 장비와 한정 꾸미기 교환`을 명시한다.
- 안전 귀환 결과의 확정 재료 아래에 `낚시 상점에서 교환 가능` 링크를 표시한다.
- 거대어 보상 수령 결과에 해당 증표의 대표 사용처를 표시한다.
- 생활 콘텐츠 매뉴얼의 위험 해역 절에 전체 교환표, 혼합 납품, 거래 가능 여부, NPC 판매
  불가를 기록한다.

## 코드 경계

### 교환 카탈로그와 도메인 로직

`src/adventure/v2/dangerousFishingExchange.ts`에 선언형 교환 카탈로그와 순수 함수를 둔다.

- 교환 항목 ID, 종류, 비용, 지급 결과
- 어획물 재료 ID에서 어종과 등급을 찾는 검증
- 등급별 보유 합계와 최대 교환 횟수 계산
- 자동 납품 수량 선택과 명시적 선택 검증
- 장비·칭호·꾸미기 보유 여부 판정에 필요한 공통 타입

카탈로그는 UI 표시와 서버 검증이 함께 사용한다. API 라우트나 컴포넌트에 비용 숫자를
중복해서 적지 않는다.

### API

`/api/v2/dangerous-fishing/exchange`를 별도 제공한다.

`GET`은 다음을 반환한다.

- 낚시 레벨과 해금 여부
- 어획물·증표 보유량
- 낚시 코인 잔액
- 항목별 교환 가능 횟수와 영구 보상 보유 여부
- 화면에 필요한 교환 카탈로그

`POST` 요청은 다음 형태를 사용한다.

```ts
type DangerousFishingExchangeRequest = {
  operationId: string;
  entryId: string;
  batches: number;
  selectedMaterials?: Record<string, number>;
};
```

`selectedMaterials`는 혼합 어획물 교환에만 필수다. 서버는 선택한 모든 ID가 해당 등급의
위험 해역 어획물인지, 합계가 `회당 필요량 × batches`와 일치하는지 다시 검사한다. 증표,
코인, 보상 ID와 수량은 클라이언트 값을 받지 않고 카탈로그에서만 계산한다.

### 트랜잭션과 중복 방지

서버는 필요한 저장값을 일정한 순서로 잠그고 하나의 트랜잭션에서 처리한다.

- `character.v2`: 어획물·증표 재료와 프로필 꾸미기
- `fishing-wallet.v1`: 낚시 코인
- `dangerous-fishing.v1`: 장비와 미끼
- `adventure-log.v2`: 칭호
- `dangerous-fishing-exchange.v1`: 최근 처리한 요청 ID

`operationId`는 클라이언트가 교환 확인 시 새로 만드는 UUID이며, 서버는 형식과 길이를
검증한다. `dangerous-fishing-exchange.v1`에는 최근 24시간 동안 성공한 요청 ID를 최대
128개 보관한다. 같은 ID가 멱등성 창 안에 다시 오면 재차 차감하거나 지급하지 않고
`alreadyProcessed: true`와 최신 잔액을 반환한다. 클라이언트도 요청 중 버튼을
비활성화하지만, 서버 중복 방지가 최종 기준이다. 24시간이 지난 항목은 다음 교환 처리 때
제거한다.

검증 순서는 다음과 같다.

1. 인증, 요청 형식, 속도 제한
2. 낚시 Lv.15 해금
3. 유효한 교환 항목과 배치 수량
4. 명시적 어획물 선택의 등급·합계
5. 재료와 코인 잔액
6. 장비·칭호·꾸미기 중복 보유
7. 원자적 차감과 지급
8. 성공한 요청 ID 기록

어느 단계든 실패하면 저장값을 갱신하지 않는다. 예상 오류 코드는
`fishing_level_locked`, `invalid_entry`, `invalid_quantity`, `invalid_material_selection`,
`insufficient_materials`, `insufficient_coins`, `already_owned`다.

## 호환성과 데이터 처리

- 기존 어획물·증표 ID와 수량은 그대로 사용한다.
- 기존 거래소 목록, 구매 주문, 에스크로, 취소·만료 반환 동작을 유지한다.
- 교환 완료 후 남은 재료도 계속 거래할 수 있다.
- `museunCosmetics.permanentOwned`만 선택적으로 추가하며 옛 저장값은 자동 보완한다.
- 별도 관계형 DB 테이블이나 Drizzle 마이그레이션은 필요하지 않다.
- 프로필 테두리는 획득 직후 자동 장착하지 않는다. 이용자가 꾸미기 설정에서 선택한다.

## 오류 및 경계 상황

- 확인창을 연 뒤 재료가 거래소에 등록되어 잔액이 줄면 서버는 `insufficient_materials`로
  거절하고 최신 잔액을 반환한다.
- 클라이언트가 다른 등급이나 일반 낚시 표본을 제출하면
  `invalid_material_selection`으로 거절한다.
- 장비를 코인으로 구매한 직후 오래된 화면에서 증표 교환을 요청해도 `already_owned`로
  거절하고 아무것도 차감하지 않는다.
- 기간제 동일 스타일이 존재할 수 없도록 전용 테두리 ID를 사용한다. 영구 보유 항목은 기간제
  연장 대상에서 제외한다.
- `batches`에는 서버 상한을 두어 한 요청이 지나치게 큰 JSON 저장 갱신을 만들지 않게 한다.
  상한은 100회이며, 더 많은 수량은 여러 요청으로 나눈다.

## 검증 계획

### 도메인 테스트

- 모든 교환 항목의 ID, 비용, 출력이 유일하고 유효한 카탈로그 ID를 참조한다.
- 등급별 혼합 수량과 최대 교환 횟수를 정확히 계산한다.
- 자동 선택 정렬이 보유 수량, `cargoValue`, 카탈로그 순서를 따른다.
- 다른 등급, 알 수 없는 재료, 잘못된 합계와 100회를 넘는 요청을 거절한다.

### API 및 동시성 테스트

- 재료 교환이 정확한 재료를 차감하고 미끼를 지급한다.
- 장비 교환이 증표와 코인을 함께 차감하고 기존 장비 보유 상태를 갱신한다.
- 칭호와 영구 프로필 테두리를 기존 저장 구조에 지급한다.
- 재료·코인 부족과 중복 보유 시 모든 저장값이 불변이다.
- 같은 `operationId`를 24시간 멱등성 창 안에 재전송하거나 동시에 요청해도 한 번만
  지급한다.
- 서로 다른 정상 요청은 직렬화된 최신 잔액을 기준으로 처리한다.

### 회귀 테스트

- 위험 해역 장비의 기존 코인 구매와 장착이 그대로 동작한다.
- 기존 기간제 꾸미기의 획득, 30일 연장, 만료, 장착 제한이 바뀌지 않는다.
- 어획물과 증표를 거래소에 등록하고 구매·취소·만료 반환할 수 있다.
- 안전 귀환, 사고 손실, 거대어 보상 수령 로직은 교환 기능 추가 전과 같다.

### UI 및 문서 테스트

- 낚시 Lv.15 잠금, 재료·코인 부족, 보유 중 상태와 교환 가능 상태를 표시한다.
- 1회 및 최대 교환 확인창에 정확한 어종별 차감 내역을 표시한다.
- 처리 중 중복 클릭을 막고 서버 오류에 대응하는 안내를 보여 준다.
- 라이트·다크 모드에서 최상위 래퍼와 중첩 카드가 불투명 표면을 사용한다.
- 인벤토리 설명, 귀환 결과, 거대어 보상, 매뉴얼에 교환 사용처가 나타난다.

## 완료 기준

- 위험 해역의 모든 일반·희귀·영웅·전설 어획물을 해당 등급 미끼로 반복 교환할 수 있다.
- 두 거대어 증표가 장비, 칭호, 영구 프로필 테두리, 반복 미끼 중 하나 이상의 실제 교환에
  사용된다.
- 거래소와 기존 코인 상점 경로가 유지된다.
- 실패·중복·동시 요청에서 자원 손실이나 중복 지급이 없다.
- 이용자가 아이템 설명과 낚시 상점만 보고 사용처를 찾을 수 있다.
