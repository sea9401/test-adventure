# PvP 속도 가중 선공 설계

## 목표

PvP에서 화면 왼쪽 또는 `p1`이라는 이유로 선공이 고정되는 편향을 없애면서, 속도 스탯은 선공 확률에 약하게 기여하고 기존 ATB 행동 빈도 가치는 유지한다.

## 적용 범위

- PvP 공용 전투 엔진에만 적용한다.
- PvE 선공 규칙은 변경하지 않는다.
- 투기장, 토너먼트, 친선전, 전초기지처럼 `resolveBattlePvP`를 사용하는 표면에 동일하게 적용한다.

## 선공 확률

- 양쪽은 각각 기본 티켓 100장을 가진다.
- 속도 티켓은 기존 ATB의 압축 행동 속도 `actionRate(spd)`를 사용한다.
- 원시 확률은 `(100 + 내 actionRate) / (200 + 양쪽 actionRate 합)`이다.
- 최종 확률은 35% 이상 65% 이하로 제한한다.
- 속도가 같으면 정확히 50:50이다.
- 추첨 결과는 전투 시작 로그에 남긴다.

## ATB 시작과 동시 행동

- 양쪽의 첫 행동 예정 시각을 동일하게 0으로 시작한다.
- 선공 추첨은 첫 행동의 순서만 정하며, 선공자에게 추가 행동 간격을 주지 않는다.
- 첫 행동 후에는 각자의 기존 `actionInterval`로 다음 행동을 예약한다.
- 이후 행동 시각이 다시 같아지면 직전 동시 행동과 반대쪽에 우선권을 주어 좌우 고정 편향을 없앤다.

## 결정성과 테스트

- 선공 확률 계산과 추첨을 순수 함수로 분리한다.
- `PvPResolveContext`에서 0 이상 1 미만의 추첨값을 선택적으로 주입할 수 있게 한다.
- 실제 전투는 주입값이 없을 때 서버의 `Math.random()`을 한 번 사용한다.
- 단위 테스트는 추첨값을 명시하여 비결정적·통계적 테스트를 만들지 않는다.

## 성공 조건

- 동속도에서 `p1`과 `p2`가 각각 선공할 수 있다.
- 매우 큰 속도 차이에도 선공 확률은 65:35를 넘지 않는다.
- 더 빠른 쪽이 추첨에서 져도 첫 행동 이후에는 기존 ATB 행동 빈도 우위를 유지한다.
- 기존 PvP 전투 기능과 다시보기 관점 변환은 유지된다.
