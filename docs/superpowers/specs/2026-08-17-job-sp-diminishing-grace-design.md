# 직업 해금 SP 체감 보상 및 24시간 유예 설계

## 목표

직업이 계속 추가되어도 해금 직업 수가 SP 예산을 선형으로 팽창시키지 않도록 직업 해금 SP를 체감식으로 바꾼다. 기존 이용자의 현재 전투 구성을 즉시 깨뜨리지 않기 위해 전역 24시간 유예를 제공한다.

## SP 산식

해금한 `tier > 0` 직업 수를 `n`이라고 할 때 직업 해금 SP는 다음과 같다.

```text
min(n, 50) + floor(max(n - 50, 0) / 2)
```

- 첫 50개: 직업 하나당 SP +1
- 51개째부터: 직업 두 개당 SP +1
- 홀수로 남은 두 번째 구간 직업은 다음 직업 해금 때 SP가 오른다.
- 현재 122개를 모두 해금하면 직업 해금 SP는 122가 아니라 86이다.
- 기본 SP, SP 열매, 어보·장비 도감 보너스는 변경하지 않는다.

서버와 UI가 같은 값을 사용하도록 해금 직업 수와 신규·기존 직업 SP를 하나의 순수 계산 모듈에서 파생한다.

## 전역 24시간 유예

배포 시 실행되는 데이터 마이그레이션이 `ops_settings`에 정책 시작 시각을 한 번 기록한다. 유예 종료 시각은 이 시각에서 정확히 24시간 뒤다. 이미 키가 있으면 덮어쓰지 않아 재실행으로 유예가 연장되지 않는다.

유예 중에는 다음 규칙을 적용한다.

- 저장되어 있던 현재 로드아웃은 기존 직업당 +1 예산으로 정리하고 전투에서도 그대로 사용한다.
- 스킬 장착·우선순위 변경·프리셋 적용 등 로드아웃을 수정하는 요청은 신규 예산으로 검증한다.
- 다만 신규 한도를 초과한 기존 구성에서 스킬을 해제할 때는, 요청 결과가 기존 장착 스킬의 순수 부분집합이고 사용 SP가 실제로 감소하면 신규 한도를 여전히 초과해도 저장할 수 있다. 스킬 추가·교체·동일 비용 재정렬은 이 예외에 포함하지 않는다.
- 따라서 현재 구성을 건드리지 않으면 유예 종료까지 유지할 수 있고, 필요하면 스킬을 한 개씩 해제해 신규 한도에 맞출 수 있다. 그 밖의 수정 결과를 신규 한도보다 높게 저장할 수는 없다.
- 무효 스킬, 미학습 스킬, 배타 장착 충돌은 유예와 무관하게 기존 규칙대로 정리한다.

유예가 끝난 뒤 첫 상태 조회에서 현재 우선순위 순으로 신규 예산에 맞춘다. 앞에서부터 담되 들어가지 않는 스킬은 건너뛰는 기존 `sanitizeLoadout` 정책을 그대로 사용한다. 저장된 프리셋은 삭제하지 않으며, 적용 시 신규 예산으로 정리한다.

## 화면 안내

로드아웃 응답에 다음 마이그레이션 상태를 제공한다.

- 유예 활성 여부와 종료 시각
- 현재 사용 SP와 신규 한도, 초과량
- 이번 상태 조회에서 신규 한도 때문에 제외된 스킬 ID

유예 중 초과 상태라면 로드아웃 상단에 현재 사용량, 새 한도, 남은 시간을 표시한다. 유예가 끝나 자동 조정된 첫 조회에는 제외된 스킬 이름을 안내한다. 프리셋은 현재 진단 화면의 초과 예산 경고를 유지한다.

## 경계와 장애 대응

- 설정 행이 아직 없는 개발·테스트 환경은 유예가 끝난 상태로 취급해 신규 산식을 즉시 적용한다.
- 손상된 시작 시각도 유예 없음으로 처리한다.
- 유예 판정에는 서버 시각을 사용하고, 클라이언트는 서버가 내려준 종료 시각을 표시만 한다.
- 전투 진입과 상태 조회가 서로 다른 예산을 쓰지 않도록 공용 정책 함수로 신규·기존 예산과 적용 예산을 계산한다.

## 비범위

- SP 열매, 도감 SP, 기본 SP 수치 변경
- 저장 프리셋 삭제 또는 영구 수정
- 직업 해금 조건 변경
- 배포 및 점검 모드 조작
