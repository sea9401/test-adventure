# 모바일 장착 스킬 접기 설계

## 배경

모바일에서 전투 스킬 장착 칩의 터치 영역을 44px로 유지하면서 칩이 두 열로 줄바꿈되어, 장착 스킬이 많은 사용자는 스킬 목록에 도달하기 전에 긴 세로 스크롤을 거쳐야 한다.

## 결정

- 모바일에서는 전투 스킬 장착 영역을 기본으로 접는다.
- 접힌 상태에는 제목, 장착 개수, `펼쳐보기` 버튼, `전부 해제` 버튼을 표시한다.
- 사용자가 펼치면 기존 장착 칩, 순서 번호, 드래그 재정렬, 개별 해제 동작을 그대로 제공한다.
- 펼친 상태에서는 버튼 문구를 `접기`로 바꾼다.
- `sm` 이상 화면에서는 기존처럼 장착 칩을 항상 표시하고 모바일 접기 버튼은 숨긴다.
- 생활 패시브 영역과 아래의 전투·생활 스킬 목록은 변경하지 않는다.

## 대안 검토

1. 한 줄 가로 스크롤: 세로 길이는 줄지만 21개 스킬의 위치 파악과 드래그 재정렬이 불편하다.
2. 모바일 기본 접기: 터치 영역과 기존 편집 기능을 유지하면서 초기 세로 길이를 가장 많이 줄인다. 이 방식을 채택한다.
3. 칩 축소: 화면은 조밀해지지만 최근 확보한 44px 터치 목표를 훼손한다.

## 상태와 접근성

- 접힘 상태는 컴포넌트의 로컬 boolean 상태로 관리하며 화면 진입 시마다 접힌 상태로 시작한다.
- 토글 버튼은 `aria-expanded`와 장착 영역을 가리키는 `aria-controls`를 제공한다.
- 장착 영역은 모바일에서만 조건부로 숨기고, `sm` 이상에서는 CSS로 항상 노출한다.
- 전부 해제 후에도 토글 상태는 유지한다. 빈 상태를 펼치면 기존의 빈 안내 문구를 표시한다.

## 검증

- 서버 렌더링 결과에서 모바일 토글의 기본 `aria-expanded=false`와 장착 개수 문구를 확인한다.
- 브라우저 상호작용 테스트에서 펼치기와 접기, 버튼 문구 및 장착 영역 노출을 확인한다.
- 반응형 클래스가 `sm` 이상에서 기존 장착 영역을 강제로 노출하는지 회귀 테스트로 고정한다.
- 관련 단위 테스트와 타입 검사를 실행한다.
