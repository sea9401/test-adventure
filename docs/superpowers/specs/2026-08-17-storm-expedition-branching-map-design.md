# 폭풍 원정 분기형 진행 맵 설계

## 목표

폭풍 원정의 세로형 순차 체크포인트 목록을 고정형 분기 맵으로 바꾼다. 플레이어는 연결된 원형 노드를 선택해 이동하고, 공용 보급과 공용 제단에서 세 항로가 합류한 뒤 다음 항로를 다시 선택할 수 있다.

이번 변경은 원정의 탐색과 경로 선택을 강화하는 UI·진행 구조 개편이다. 기존 원정당 체크포인트 9개, 전투 7회, 전투 난도, 보상 수치, 임시 전리품, 위험 이벤트, 연습 모드, 완주 및 SP 열매 규칙은 유지한다.

## 현재 구조

- 원정 시작 시 `gale`, `thunder`, `wreckage` 중 하나의 `routeId`를 선택한다.
- 진행 중에는 공용 `STORM_EXPEDITION_NODES` 배열과 0-based `nodeIndex`를 사용한다.
- 선택한 항로는 원정이 끝날 때까지 고정된다.
- 화면은 9개 체크포인트를 세로 목록으로 보여주며 현재 노드의 전투 또는 선택을 완료하면 다음 인덱스로 자동 진행한다.
- `early_battle`과 `late_battle`은 각각 2연전이며 전체 전투 수는 7회다.

## 범위

### 포함

- 세 항로와 공용 합류 노드로 구성된 고정 방향성 비순환 그래프
- 연결된 다음 노드의 2단계 선택 및 확정 이동
- 보급과 제단에서의 항로 재선택
- HTML 버튼과 SVG 연결선을 조합한 반응형 원정 지도
- 서버 권위 이동 검증
- 진행 중인 version 2 원정의 version 3 자동 변환
- 기존 위험 이벤트, 임시 전리품, 연습 모드 및 보상 흐름 보존

### 제외

- 원정마다 달라지는 무작위 맵
- 뒤로 이동, 이미 방문한 노드 재진입, 노드 건너뛰기
- 전투 난도와 보상 확률·수량 변경
- 새로운 전투 종류, 보급 효과, 제단 축복 또는 위험 이벤트 추가
- 길드 원정 등 폭풍 원정 이외 콘텐츠 변경

## 고정 그래프

입구는 체크포인트 수에 포함하지 않는 시작 선택 지점이다. 실제 한 원정에서 방문하는 노드는 기존과 동일하게 9개다.

```text
입구
 ├─ 칼바람 외곽
 ├─ 뇌운 외곽       → 공용 보급
 └─ 부유 잔해지

공용 보급
 ├─ 칼바람 중층 → 칼바람 야영지 → 칼바람 정예
 ├─ 뇌운 중층   → 뇌운 야영지   → 뇌운 정예     → 공용 제단
 └─ 잔해 중층   → 잔해 야영지   → 잔해 정예

공용 제단
 ├─ 칼바람 수호자
 ├─ 뇌운 수호자       → 공용 최종 정비 → 폭풍의 심장
 └─ 잔해 수호자
```

### 노드 계층과 연결

| 계층 | 노드 | 다음 노드 |
| --- | --- | --- |
| 시작 | 입구 | 세 항로의 외곽 중 하나 |
| 1 | 항로별 외곽 전투 2연전 | 공용 보급 |
| 2 | 공용 보급 | 세 항로의 중층 중 하나 |
| 3 | 항로별 중층 전투 2연전 | 같은 항로의 야영지 |
| 4 | 항로별 야영지 | 같은 항로의 정예 |
| 5 | 항로별 정예 | 공용 제단 |
| 6 | 공용 제단 | 세 항로의 수호자 중 하나 |
| 7 | 항로별 수호자 | 공용 최종 정비 |
| 8 | 공용 최종 정비 | 폭풍의 심장 |
| 9 | 폭풍의 심장 | 원정 완료 |

보급에서 선택한 중층 항로는 중층·야영지·정예까지 고정된다. 제단에 도달하면 수호자 항로를 다시 선택할 수 있다. 공용 최종 정비 이후에는 모든 경로가 기존 공통 최종 보스로 이어진다.

## 플레이 흐름

### 원정 시작

1. 전체 지도를 미리 표시한다.
2. 실전 또는 연습 모드를 선택한다.
3. 세 외곽 노드 중 하나를 누르면 적 위협, 항로 재료, 장비 종류를 미리 보여준다.
4. `이 항로로 원정 시작`을 누르면 서버가 첫 노드를 검증하고 원정을 생성한다.
5. 실전 입장 횟수는 서버가 시작 요청을 성공시킨 시점에만 차감한다.

### 진행 중 노드 완료와 이동

- 전투 노드는 마지막 연전을 승리했을 때 완료된다.
- 보급·야영지·제단·최종 정비는 효과 선택이 적용됐을 때 완료된다.
- 현재 노드를 완료하기 전에는 다음 노드를 미리 볼 수 있지만 이동 확정 버튼은 비활성화된다.
- 현재 노드를 완료하면 연결된 다음 노드만 활성화된다.
- 활성 노드를 한 번 누르면 상세 미리보기를 표시하고, `이 노드로 이동`을 눌러야 실제 이동한다.
- 이동이 성공하면 선택 상태를 초기화하고 새 현재 노드를 지도 중앙에 맞춘다.
- 뒤로 이동, 노드 건너뛰기, 완료한 노드 재진입은 허용하지 않는다.

### 항로 변경 효과

- 항로별 전투 노드가 자신의 `routeId`를 가진다.
- 이동이 확정되면 현재 항로가 해당 노드의 항로로 갱신된다.
- 이후 적, 항로 재료, 일반 6티어 장비, 항로 유니크는 새 항로를 기준으로 계산한다.
- 이미 획득한 임시 골드·재료·장비, HP·MP, 제단 축복, 위험 이벤트의 이익과 저주는 유지한다.
- 최종 보스, 완주 횟수, SP 열매 확률·천장·획득 제한은 기존 공통 규칙을 유지한다.

## 상태 모델

진행 상태를 `version: 3`으로 올린다.

```ts
type StormExpeditionActiveV3 = {
  version: 3;
  mode: "normal" | "practice";
  currentNodeId: StormExpeditionMapNodeId;
  visitedNodeIds: StormExpeditionMapNodeId[];
  completedNodeIds: StormExpeditionMapNodeId[];
  routeId: StormExpeditionRouteId;
  encounterIndex: number;
  // 기존 HP·MP·전리품·축복·위험 이벤트 필드는 그대로 유지
};
```

- `visitedNodeIds`는 실제 이동 순서를 보존하고 마지막 항목은 `currentNodeId`와 일치해야 한다.
- `completedNodeIds`에 현재 노드가 포함되면 다음 연결 노드로 이동할 수 있다.
- `routeId`는 마지막으로 진입한 항로별 노드의 항로를 나타낸다. 공용 노드에서는 직전 항로를 유지한다.
- 이동 가능 노드는 고정 그래프와 현재 완료 상태에서 서버가 계산한다. 저장된 클라이언트 값을 신뢰하지 않는다.
- 노드별 선택 결과는 기존 `chosenChoices`를 유지하되, 지도 노드 ID를 함께 사용해 완료 여부를 판정한다.
- 위험 이벤트 위치는 숫자 `nodeIndex` 대신 `supply`, `camp`, `altar` 중 하나인 안정적인 `triggerCheckpoint`로 저장한다. 항로별 야영지는 모두 `camp` 체크포인트로 판정한다.

## 기존 진행 상태 이전

저장소 전체 일괄 마이그레이션은 하지 않는다. `parseStormExpeditionState`가 version 2 활성 원정을 읽을 때 다음 대응표로 version 3 상태를 메모리에서 복원하고 다음 저장 시 version 3으로 기록한다.

| 기존 `nodeIndex` | 변환 대상 |
| --- | --- |
| 0 | 기존 `routeId`의 외곽 |
| 1 | 공용 보급 |
| 2 | 기존 `routeId`의 중층 |
| 3 | 기존 `routeId`의 야영지 |
| 4 | 기존 `routeId`의 정예 |
| 5 | 공용 제단 |
| 6 | 기존 `routeId`의 수호자 |
| 7 | 공용 최종 정비 |
| 8 | 폭풍의 심장 |

이전 노드까지의 단일 항로 경로를 `visitedNodeIds`와 `completedNodeIds`로 채운다. 현재 노드는 완료되지 않은 상태로 복원한다. `encounterIndex`, HP·MP, 처치 수, 임시 전리품, 장비 옵션, 축복, 다음 전투 효과, 회복기 사용 기록, 제단 제시 목록과 선택 결과는 그대로 보존한다. 기존 위험 이벤트의 `nodeIndex` 1·3·5는 각각 `supply`·`camp`·`altar`의 `triggerCheckpoint`로 변환한다.

변환할 수 없는 손상 데이터는 임시 전리품을 삭제하는 초기화로 처리하지 않는다. 오류를 기록하고 기존 파서가 복원 가능한 가장 가까운 대응 노드로 제한한 뒤 상태 조회 응답에 새로고침 가능한 복구 안내를 포함한다.

## 서버 API

### 시작

`start` 요청은 `mode`와 `targetNodeId`를 받는다. 서버는 대상이 입구에서 연결된 항로별 외곽인지 확인한다. 기존 `routeId` 형식은 호환 입력으로 받아 대응 외곽 노드로 변환할 수 있다.

### 이동

새 `move` 작업은 다음을 받는다.

```ts
{
  action: "move";
  targetNodeId: StormExpeditionMapNodeId;
  expectedCurrentNodeId: StormExpeditionMapNodeId;
  expectedEncounterIndex: number;
}
```

서버는 현재 노드 완료 여부, 그래프 연결, 방문 여부, 최신 위치를 한 트랜잭션 안에서 검증한다. 성공하면 `currentNodeId`, `visitedNodeIds`, 필요 시 `routeId`를 갱신한다.

### 전투·선택

- `fight`, `choose`, `risk_event`, `withdraw`는 `expectedCurrentNodeId`를 사용한다.
- 2연전의 첫 승리는 `encounterIndex`만 올린다.
- 마지막 전투 승리 또는 선택 적용은 현재 노드를 `completedNodeIds`에 추가하되 다음 노드로 자동 이동하지 않는다.
- 최종 보스 승리는 기존과 같이 즉시 전리품을 확정하고 원정을 종료한다.
- 황금 나침반 수락은 현재 항로 야영지를 완료 처리하며 같은 항로의 정예만 다음 이동 대상으로 연다.

### 오류 코드

- `invalid_node`: 존재하지 않는 노드
- `node_not_reachable`: 현재 위치에서 연결되지 않은 노드
- `node_not_completed`: 현재 전투 또는 선택이 끝나지 않음
- `node_already_visited`: 이미 방문한 노드
- `stale_state`: 화면의 예상 위치와 서버 위치가 다름

오류 응답은 최신 원정 상태와 서버가 계산한 이동 가능 노드 목록을 포함한다. 클라이언트는 이를 즉시 반영하고 선택 중이던 노드를 해제한다.

## 화면 설계

### 지도 구성

- `ExpeditionRouteMap`은 지도 표시와 노드 선택만 담당한다.
- 원형 노드는 실제 HTML `button`으로 만들고, 연결선은 클릭을 받지 않는 SVG 레이어로 그린다.
- 노드 좌표와 연결선은 고정 그래프 데이터에서 제공한다.
- 지도 카드에는 불투명 표면 토큰을 사용하고 배경 이미지가 텍스트와 조작부 뒤로 비치지 않게 한다.

### 상태 표현

- 완료: 초록색, 체크 아이콘, `완료` 접근성 문구
- 현재: 굵은 강조 테두리, 현재 위치 아이콘과 `현재` 문구
- 이동 가능: 항로별 색상 테두리와 절제된 강조 애니메이션
- 선택됨: 별도의 링과 상세 패널 연결
- 잠김: 불투명 배경을 유지하고 회색 텍스트·아이콘으로 표시

색상만으로 상태를 구분하지 않는다. 각 노드는 전투, 보급, 야영지, 제단, 수호자, 정비, 보스 아이콘과 이름을 함께 제공한다.

### 레이아웃

- 최대 폭 900px의 현재 원정 화면에서 지도 카드를 전체 너비로 먼저 배치한다.
- 지도 아래에는 선택 노드 미리보기와 현재 HP·MP·축복·전리품 영역을 배치한다.
- 데스크톱에서는 전체 그래프를 가능한 한 한 화면에 표시한다.
- 모바일에서는 지도 내부에 최소 너비를 두고 가로 스크롤을 허용한다.
- 현재 노드 변경 시 `scrollIntoView`의 부드러운 가로 정렬로 현재 위치를 중앙에 둔다. 사용자의 수동 스크롤을 지속적으로 되돌리지는 않는다.
- 키보드 사용자는 Tab으로 활성 노드를 이동하고 Enter/Space로 미리보기를 선택한 뒤 별도 확정 버튼을 사용한다.

## 오류 및 동시성 처리

- 이동·전투·선택 요청 중에는 모든 원정 조작을 잠근다.
- 서버 위치가 바뀐 중복 요청은 `stale_state`로 처리하고 최신 상태를 표시한다.
- 지도 미리보기는 로컬 UI 상태일 뿐이며 서버 진행 상태를 바꾸지 않는다.
- 이동 확정 성공 전에는 현재 노드와 항로 색상을 바꾸지 않는다.
- 네트워크 실패 시 선택한 미리보기는 유지하되 재시도 문구를 표시한다.
- 기존 진행 상태 변환 실패나 알 수 없는 노드는 서버 로그에 구조화해 기록한다.

## 테스트 계획

### 그래프 데이터

- 모든 시작 항로에서 폭풍의 심장까지 도달 가능하다.
- 순환, 고립 노드, 잘못된 연결이 없다.
- 모든 유효 경로는 체크포인트 9개와 전투 7회를 지난다.
- 항로 재선택은 보급 다음과 제단 다음에서만 가능하다.
- 중층에서 정예까지는 선택한 같은 항로를 유지한다.

### 상태와 이전

- version 2의 각 `nodeIndex`를 올바른 version 3 노드로 변환한다.
- 변환 전후 HP·MP·전리품·축복·회복기 사용 기록과 위험 이벤트가 보존된다.
- 날짜 변경은 입장 횟수만 초기화하고 진행 중 그래프 경로를 보존한다.

### API

- 완료한 현재 노드에서 연결된 미방문 노드로만 이동할 수 있다.
- 미완료·비연결·기방문·오래된 위치 요청을 거절한다.
- 보급과 제단에서 변경한 항로의 적·재료·장비 규칙을 사용한다.
- 황금 나침반은 같은 항로의 야영지를 건너뛰고 정예만 연다.
- 연습 모드의 이동과 전투는 보상·입장 횟수·완주 기록을 바꾸지 않는다.

### UI

- 완료·현재·이동 가능·선택·잠김 상태를 문구와 스타일로 구분한다.
- 첫 클릭은 미리보기만 열고 확정 버튼 전에는 이동 요청을 보내지 않는다.
- 미완료 노드에서는 이동 확정 버튼이 잠긴다.
- 서버 오류 뒤 최신 이동 가능 목록으로 지도를 갱신한다.
- 모바일 가로 스크롤과 현재 노드 자동 정렬이 동작한다.
- 키보드와 스크린리더로 노드 이름·종류·상태를 확인할 수 있다.

## 완료 기준

- 플레이어가 지도에서 연결된 원형 노드를 2단계 방식으로 선택해 이동할 수 있다.
- 보급과 제단에서 항로를 바꾸면 이후 전투와 전리품이 새 항로 기준으로 적용된다.
- 기존 진행 중 원정이 손실 없이 새 그래프로 이어진다.
- 기존 전투 수, 보상 수치, 위험 이벤트, 연습 모드, 임시 전리품과 완주 보상에 회귀가 없다.
- 데스크톱과 모바일에서 현재 위치와 다음 선택지가 명확하게 보인다.
