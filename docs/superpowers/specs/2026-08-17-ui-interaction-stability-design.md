# UI 상호작용 안정화 설계

## 목표

게임 전반에서 클릭할 때 컨트롤과 본문이 물리적으로 튀거나, 비동기 상태 문구 때문에 주변 레이아웃이 밀리거나, 페이지가 한 박자 뒤에 갑자기 교체되는 감각을 줄인다. 게임 규칙과 데이터 흐름은 바꾸지 않으며 라이트·다크 모드의 불투명 표면 규칙을 유지한다.

## 변경 범위와 순서

1. 데스크톱 채팅 열기 버튼을 열린 패널보다 높은 입력 레이어에 두어 같은 버튼으로 닫을 수 있게 한다.
2. 공통 버튼과 클릭 가능한 카드의 hover/active `translate`를 제거한다. 색·테두리·그림자 피드백은 유지한다.
3. 공통 드롭다운은 opacity만 짧게 전환하고, 컨테이너 scale/translate와 자식별 지연 등장은 제거한다.
4. 공통 `Button`에 폭을 유지하는 `loading` 상태를 추가한다. 로딩 중에는 기존 라벨이 공간을 차지한 채 시각적으로 숨고 고정 크기 스피너만 겹쳐지며, 버튼은 비활성화되고 `aria-busy`와 로딩 라벨을 제공한다.
5. 실제 폭 변화가 확인된 스킬 학습·퀘스트 수령 버튼부터 새 로딩 상태를 적용한다. 나머지 화면은 별도 동작 변경 없이 새 API를 점진적으로 사용할 수 있다.
6. 스킬 허브는 항상 같은 1080px 외곽 프레임을 유지하고 좁은 탭 내용만 내부 720px 래퍼로 제한한다. 탭 내용은 위치 이동 없이 opacity로만 나타난다.
7. 퀘스트 일일/주간 내용은 탭별 키를 가진 고정 시작점 아래에서 교체해 기존 행 DOM의 텍스트·높이 변형으로 인한 레이아웃 이동을 피하고, opacity 전환만 사용한다.
8. 모든 게임 라우트에 공통 불투명 로딩 셸을 제공하고, 실제 라우트 본문도 경로 변경 시 짧은 opacity 전환을 적용한다. 기존 사냥터 층 진입 전환은 유지하되 일반 라우트에는 기하 이동을 추가하지 않는다.

## 접근성 및 모션

- 로딩 버튼은 `aria-busy=true`, `disabled`, 동작별 로딩 `aria-label`을 함께 제공한다.
- `prefers-reduced-motion: reduce`에서는 새 전환과 기존 공통 등장 애니메이션을 모두 비활성화한다.
- 스피너와 로딩 셸은 상태 전달용이며 레이아웃 크기를 바꾸지 않는다.

## 테스트

- 채팅 레이어는 데스크톱 열린 토글이 패널보다 높은지를 회귀 테스트로 검증한다.
- 공통 버튼은 로딩 전후 정적 렌더 폭 구조, 비활성화, 접근성 속성을 검증한다.
- 브라우저 스타일 테스트는 hover/active 시 버튼과 카드의 bounding box 위치가 변하지 않는지 검증한다.
- 스킬·퀘스트 탭은 고정 프레임과 탭별 전환 경계를 검증한다.
- `GameContentTransition`은 첫 렌더에는 애니메이션이 없고 일반 경로 변경에는 opacity 전환, 사냥터 목록→층에는 기존 전환을 선택하는 순수 정책을 검증한다.
- 게임 라우트 로딩 셸은 불투명 surface 토큰을 사용해 정적 렌더링한다.
- 관련 Vitest, 타입 검사, 린트, 프로덕션 빌드를 실행한다.

## 완료 기준

- 데스크톱에서 열린 채팅을 같은 플로팅 버튼으로 닫을 수 있다.
- 공통 버튼·카드는 hover와 press 동안 화면상의 x/y 위치가 변하지 않는다.
- 적용된 비동기 버튼은 로딩 전후 주변 레이아웃 폭을 바꾸지 않는다.
- 스킬·퀘스트 탭과 일반 게임 라우트가 기하 이동 없이 즉시 시각 피드백을 준다.
- 게임 로직·API·저장 데이터와 동시 진행 중인 모바일 UX 작업은 변경하지 않는다.
- 배포하지 않는다.
