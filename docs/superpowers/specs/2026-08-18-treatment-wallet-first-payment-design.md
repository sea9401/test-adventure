# 치료소 충전약 지갑 우선 결제 설계

## 배경

치료소의 HP·MP 충전약은 현재 다른 골드 소비처와 같은 공통 결제 함수를 사용한다. 코어 루프가 켜진 환경에서는 이 함수가 은행 골드를 먼저 차감하므로, 사냥 실패 때 손실될 수 있는 지갑 골드가 남고 안전한 은행 골드가 먼저 줄어든다.

## 목표

치료소에서 HP·MP 충전약을 구매할 때 지갑 골드를 먼저 쓰고, 지갑이 부족한 경우에만 부족분을 은행 골드로 결제한다. 지갑 골드만으로 제한하지 않으며 지갑과 은행의 합계가 구매액 이상이면 구매를 허용한다.

## 결정

- 치료소 충전약 전용 결제 래퍼를 추가한다.
- 코어 루프가 켜져 있으면 지갑에서 가능한 만큼 먼저 차감하고 남은 비용만 은행에서 차감한다.
- 코어 루프가 꺼져 있으면 기존 호환 동작대로 지갑 골드만 사용한다.
- 지갑과 은행의 합계가 부족하면 두 잔액과 충전약 수량을 모두 변경하지 않는다.
- 장비 상점, 강화, 거래소 등 다른 골드 소비처의 은행 우선 결제는 변경하지 않는다.
- 치료소 UI의 결제 가능 금액은 계속 지갑과 은행의 합계를 사용한다.

## 구현 경계

정규화와 잔액 배분은 `src/adventure/data/v2/coreLoopConfig.ts`의 순수 함수로 캡슐화한다. `POST /api/v2/shop/charge`만 새 래퍼를 사용하며, 기존 트랜잭션·저장 잠금·응답 계약은 유지한다.

## 검증

- 지갑이 충분하면 지갑만 차감하고 은행은 보존한다.
- 지갑이 부족하면 지갑을 모두 쓰고 부족분만 은행에서 차감한다.
- 총 잔액이 부족하면 실패하며 잔액은 보존한다.
- 충전 API가 계산 결과를 `character.v2`와 응답에 동일하게 반영한다.
- 집중 테스트, 전체 TypeScript 검사, 대상 ESLint를 실행한다.
- 배포하지 않는다.
