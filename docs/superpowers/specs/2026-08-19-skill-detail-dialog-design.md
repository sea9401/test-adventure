# 스킬 상세 설명 공용 창 설계

## 배경

현재 스킬 학습·장착 화면은 `V2SkillDefinition.description`의 짧은 소개와
`describeV2Skill`이 효과 데이터에서 만든 요약 칩을 보여 준다. 목록을 빠르게 훑기에는
적합하지만, 신규 직업과 6차 이후 스킬에 늘어난 발동 순서, 중첩 획득·소비, 장착 시너지,
주문식 변형, 적용 예외와 PvP 차이를 충분히 설명하지 못한다.

일부 규칙은 구조화된 스킬 데이터로 표현되어 있지만 일부는 전투 처리 코드와 주석에만 있다.
따라서 기존 툴팁을 그대로 크게 띄우는 방식으로는 문의 원인을 해결할 수 없다. 짧은 소개는
유지하면서 실제 데이터에서 계산한 수치와 사람이 작성한 규칙 설명을 한곳에서 제공해야 한다.

## 목표

- 스킬 학습 화면, 장착 목록, 직업 로드맵에서 같은 스킬 상세 정보를 열 수 있다.
- 목록용 설명은 짧게 유지하고 상세 창에서 정확한 수치와 복잡한 규칙을 확인할 수 있다.
- 효과 데이터에 있는 값은 자동으로 표시해 밸런스 변경 뒤 설명 숫자가 어긋나지 않게 한다.
- 데이터만으로 설명할 수 없는 처리 순서, 연계, 예외와 PvP 차이는 별도 원문으로 관리한다.
- 현재 6차 전투 스킬과 앞으로 추가되는 신규·7차 전투 스킬의 상세 설명 누락을 테스트로 막는다.
- 수동 상세 설명을 아직 작성하지 않은 기존 단순 스킬도 자동 정보로 상세 창을 사용할 수 있다.

## 제외 범위

- 스킬 효과나 밸런스 자체의 변경
- 운영자용 설명 편집 화면 또는 데이터베이스 기반 콘텐츠 관리 기능
- 전투 중 현재 캐릭터 능력치를 대입한 예상 피해량 계산기
- 몬스터 전용 스킬 상세 보기
- 이번 작업에서 모든 기존 저차 스킬의 수동 설명을 일괄 작성하는 작업

## 선택한 방식

모든 주요 스킬 화면이 재사용하는 공용 상세 다이얼로그를 만든다. 기존 `description`은
목록용 한 줄 소개로 유지하고, 구조화된 효과에서 만든 자동 정보와 새 `detail` 원문을 상세
표시 모델에서 합친다.

카드 자체를 길게 펼치는 방식은 많은 스킬이 있는 모바일 목록의 세로 길이를 다시 키운다.
별도 페이지는 스킬 하나를 확인할 때마다 현재 화면을 벗어나야 한다. 공용 다이얼로그는 현재
맥락과 기존 버튼을 유지하면서 여러 화면의 설명을 하나로 통일할 수 있어 채택한다.

## 데이터 모델

`V2SkillDefinition`에 선택형 상세 설명을 추가한다. 정확한 필드명은 구현 중 기존 명명 규칙에
맞추되 의미는 다음과 같이 고정한다.

```ts
type V2SkillDetail = {
  mechanics: readonly [string, ...string[]];
  synergies?: readonly string[];
  limitations?: readonly string[];
  pvp?: readonly string[];
};

type V2SkillDefinition = {
  // 기존 필드
  description: string;
  detail?: V2SkillDetail;
};
```

- `description`: 목록과 간단 툴팁에 쓰는 짧은 소개다.
- `mechanics`: 발동 시점과 처리 순서 등 데이터만 보고 이해하기 어려운 핵심 작동 방식이다.
- `synergies`: 다른 스킬의 보유·장착 조건, 중첩 생성·소비와 연계 결과다.
- `limitations`: 적용되지 않는 대상과 상황, 횟수 제한 등 오해하기 쉬운 제약이다.
- `pvp`: PvE와 다른 PvP 수치 또는 동작만 적는다.

수치가 이미 `effects`, `passive`, `procChance`, `cooldown`, `castVariants`,
`elementEffects`, `equippedSynergies` 같은 구조화된 필드에 있다면 `detail` 문자열에 반복해서
적지 않는다. 자동 표시로 표현할 수 없는 의미만 수동 원문에 둔다.

## 상세 표시 모델

UI 컴포넌트가 원시 스킬 정의를 직접 해석하지 않도록 순수 변환 함수를 둔다. 이 함수는 스킬
정의를 받아 다음 표시 모델을 만든다.

- 스킬명과 목록용 소개
- 카테고리, 스킬 단계, 주 능력치와 속성 메타데이터
- 피해·회복·버프·디버프·패시브 수치
- MP, 재사용 대기시간, 발동률, 전투당 제한과 SP
- 속성별 효과, 주문식 변형과 장착 시너지의 조건 및 효과
- 수동 `mechanics`, `synergies`, `limitations`, `pvp` 구역

기존 `describeV2Skill`과 효과 설명 함수를 재사용하거나 작은 공용 함수로 분리해 목록 칩과 상세
수치가 같은 계산 경로를 사용하게 한다. 주문식과 속성 분기처럼 현재 요약 칩이 개수만 보여 주는
구조는 상세 모델에서 각 조건과 효과를 펼쳐 보여 준다. 선행 스킬 ID는 사용자에게 노출하지 않고
해당 스킬 이름으로 변환한다.

수동 `detail`이 없는 기존 스킬은 소개와 자동 생성 정보만 표시한다. 값이 없는 구역은 모델에서
제외해 빈 제목이나 `없음` 문구가 연속해서 나타나지 않게 한다. 알 수 없는 스킬 ID가 전달되면
다이얼로그를 열지 않고 개발 환경에서만 원인을 찾을 수 있는 경고를 남긴다.

## UI와 상호작용

공용 `SkillDetailDialog`는 선택한 스킬 ID와 닫기 콜백을 받는다.

- 모바일에서는 화면 대부분을 사용하는 세로 스크롤형 상세 창으로 표시한다.
- 데스크톱에서는 최대 너비와 최대 높이를 둔 중앙 다이얼로그로 표시한다.
- 표면은 `src/components/ui/surfaces.ts`의 불투명 표면 상수를 사용해 지역 배경이 본문 뒤로
  비치지 않게 한다.
- 상단에는 스킬명, 메타데이터, 닫기 버튼을 둔다.
- 본문은 짧은 소개, 핵심 효과, 작동 방식, 연계, 제약, PvP 차이 순으로 표시한다.
- 긴 상세 내용은 다이얼로그 내부만 스크롤하며 배경 화면의 스크롤은 잠근다.
- `Esc`, 닫기 버튼과 바깥 영역 클릭으로 닫을 수 있고 포커스 이동·복귀와 포커스 트랩을
  기존 모달 접근성 유틸로 처리한다.

스킬 학습 카드, 장착 스킬 목록과 직업 로드맵에서 스킬명 또는 설명 영역을 누르면 같은 상세
창을 연다. 터치·키보드 사용자가 동작을 발견할 수 있도록 `상세 보기`라는 접근 가능한 이름을
제공한다. 카드 안의 `학습`, `장착`, `해제`, `강화` 버튼은 이벤트가 상세 열기로 전파되지 않고
기존 기능만 수행해야 한다.

## 상세 설명 적용 정책

이번 도입에서는 다음 순서로 원문을 채운다.

1. 현재 6차 전투 직업의 모든 시그니처 스킬
2. 최근 추가된 복잡한 신규 직업 스킬 중 주문식, 속성 분기, 중첩 소비, 전용 전투 상태 또는
   PvP 분기를 사용하는 스킬
3. 문의와 오해가 잦은 기존 스킬
4. 나머지 기존 단순 스킬은 자동 상세를 유지하며 점진적으로 보완

현재 수동 원문이 없는 기존 전투 스킬 ID는 명시적인 레거시 예외 목록에 고정한다. 새 전투
스킬은 이 목록에 자동으로 들어가지 않으므로 `detail` 없이 추가하면 검증이 실패한다. 예외 목록은
새 스킬을 편하게 우회하는 용도로 늘리지 않고, 기존 스킬의 원문을 보완할 때마다 줄인다.

직업 카탈로그와 `V2_SKILLS_BY_JOB`을 함께 조회해 직업 차수를 판별한다. 생활 효과 스킬은
직업명 목록이 아니라 실제 패시브 효과를 검사하는 기존 `isLifestyleSkill`로 제외하고, 몬스터 전용
스킬도 제외한다. 6차 이상 전투 직업의 스킬은 레거시 예외를 허용하지 않는다. 현재 카탈로그의
직업 차수 타입은 6까지이므로 향후 7차를 추가할 때 타입 범위를 넓히면 같은 `tier >= 6` 검증이
그대로 적용된다.

## 코드 경계

- `src/adventure/data/v2/v2Skills.ts`
  - 상세 설명 타입과 `V2SkillDefinition.detail`을 추가한다.
  - 자동 수치 설명이 상세 표시 모델에서도 재사용될 수 있도록 효과 설명 경계를 정리한다.
- `src/adventure/data/v2/v2SkillsCommonCatalog.ts` 및 관련 분리 카탈로그
  - 6차와 우선 대상 복잡 스킬의 수동 상세 원문을 추가한다.
- 새 상세 표시 모델 모듈
  - 원시 정의를 화면 독립적인 섹션 모델로 변환한다.
  - 변형 조건의 스킬 ID를 이름으로 해석하고 빈 구역을 제거한다.
- 새 `SkillDetailDialog` 컴포넌트
  - 반응형 배치, 섹션 렌더링과 모달 접근성을 담당한다.
- `V2SkillLearnView.tsx`
  - 학습 카드와 보유 스킬에서 상세 열기를 연결하고 학습·강화 동작을 분리한다.
- `V2LoadoutPanel.tsx`
  - 장착·미장착 스킬에서 상세 열기를 연결하고 장착·해제 동작을 분리한다.
- `JobRoadmapDialog.tsx`
  - 시그니처 스킬 목록에서 상세 열기를 연결한다.

부모 화면마다 다이얼로그 구현을 복제하지 않는다. 한 화면에 다이얼로그 인스턴스 하나를 두고
현재 선택한 스킬 ID만 상태로 관리한다.

## 테스트

- 상세 표시 모델이 실제 효과에서 피해·회복·상태 효과, MP, 쿨다운, 발동률과 SP를 정확히
  만든다.
- 속성별 효과, 주문식 변형과 장착 시너지의 조건 및 효과가 사용자용 스킬명으로 표시된다.
- 수동 상세 구역이 정해진 순서로 자동 정보와 합쳐지고 빈 구역은 제거된다.
- 수동 상세가 없는 레거시 스킬도 소개와 자동 정보로 상세 모델을 만든다.
- 신규 전투 스킬은 `detail` 또는 사전에 고정된 레거시 예외가 없으면 카탈로그 검증이 실패한다.
- 생활 숙련 및 몬스터 전용 스킬은 전투 스킬 상세 원문 검증 대상에서 제외된다.
- 6차 이상 전투 직업의 모든 시그니처 스킬은 수동 상세 원문을 가진다.
- 학습 화면, 장착 목록과 직업 로드맵에서 상세 창을 열고 닫을 수 있다.
- 학습·장착·해제·강화 버튼이 상세 창을 열지 않고 기존 콜백을 한 번만 실행한다.
- 다이얼로그 제목 연결, 초기 포커스, 포커스 복귀, `Esc` 닫기와 배경 스크롤 잠금을 검증한다.
- 모바일과 데스크톱의 반응형 클래스 및 불투명 표면 상수 사용을 회귀 테스트로 고정한다.

## 완료 기준

- 세 주요 스킬 화면에서 같은 상세 창을 열 수 있다.
- 현재 6차 전투 스킬은 수치뿐 아니라 발동 순서, 연계와 예외를 확인할 수 있다.
- 기존 단순 스킬은 별도 원문이 없어도 정확한 자동 정보를 보여 준다.
- 새 전투 스킬과 향후 7차 스킬은 상세 원문 누락 상태로 검증을 통과할 수 없다.
- 목록 카드의 높이와 현재 학습·장착·강화 동작은 바뀌지 않는다.
- 라이트·다크 모드 모두에서 배경 이미지가 상세 본문 뒤로 비치지 않는다.
