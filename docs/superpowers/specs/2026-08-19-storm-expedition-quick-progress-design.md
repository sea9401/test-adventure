# 폭풍 원정 간편 진행 설계

## 배경

현재 폭풍 원정의 전투 구간은 `전투 시작 → 전투 리플레이 결과 확인 → 원정 지도 확인 → 다음 노드 선택 → 이동 확정 → 다음 전투 시작`을 반복한다. 경로와 정비 효과를 고르는 판단은 원정의 핵심이지만, 전투 결과를 닫고 이미 선택한 전투 노드에서 다시 시작을 누르는 단계는 같은 의사를 반복 확인하게 한다.

기존 화면에는 `전투 결과 바로 보기` 옵션이 있으나 화면을 다시 열면 초기화되며, 리플레이만 생략할 뿐 다음 노드 이동과 전투 시작은 각각 따로 눌러야 한다.

## 목표

- 유저가 직접 결정해야 하는 경로·야영·제단·위험 이벤트 선택은 유지한다.
- 간편 진행에서는 전투 리플레이를 자동으로 생략하고 결과를 원정 화면 안에 간략히 표시한다.
- 다음 전투 노드를 한 번 선택하면 이동과 전투 시작을 연속 처리한다.
- 한 체크포인트에 전투가 여러 번 있으면 다음 전투를 자동으로 이어간다.
- 기존 상세 리플레이와 단계별 진행 방식을 원하는 유저를 위해 일반 진행을 보존한다.
- 중복 요청, 네트워크 실패 또는 오래된 화면 상태에서도 원정 저장이 손상되지 않게 한다.

## 비목표

- 경로를 시스템이 대신 선택하는 완전 자동 원정은 만들지 않는다.
- 야영지·보급·제단·최종 정비의 선택을 자동화하지 않는다.
- 위험 이벤트의 수락 또는 거절을 자동화하지 않는다.
- 전투 계산, 드롭 확률, 입장 횟수, 귀환 및 패배 규칙은 변경하지 않는다.
- 서버에 새로운 원정 진행 상태나 데이터베이스 마이그레이션을 추가하지 않는다.

## 사용자 경험

### 간편 진행

기존 `전투 결과 바로 보기` 체크박스를 `간편 진행` 설정으로 확장한다.

- 기본값은 켜짐이다.
- 브라우저 로컬 저장소에 선택을 보존한다.
- 켜짐:
  - 전투 리플레이 화면을 띄우지 않는다.
  - 승패와 전리품은 현재 원정 화면의 배너·결과 카드로 표시한다.
  - 전투 노드를 선택하면 이동 직후 전투를 자동 시작한다.
  - 동일 체크포인트에 남은 연속 전투가 있으면 자동으로 다음 전투를 시작한다.
- 꺼짐:
  - 기존과 같이 전투 시작 버튼을 누른다.
  - 전투 뒤 상세 리플레이를 표시한다.
  - 지도에서 노드를 고른 뒤 이동을 확정하고, 이동 후 전투 시작 버튼을 누른다.

설정은 원정 화면 안에서 언제든 바꿀 수 있다. 자동 진행 중에는 설정과 행동 버튼을 비활성화해 중복 입력을 막는다.

### 다음 경로 선택

현재 체크포인트가 완료되면 지도 아래에 이동 가능한 다음 노드를 각각 한 번에 누를 수 있는 진행 카드로 표시한다. 카드에는 노드 이름, 종류, 설명과 항로 정보를 함께 보여주어 별도 미리보기 확인 없이도 선택할 수 있게 한다.

간편 진행에서 카드를 누르면 다음과 같이 동작한다.

1. 기존 `move` 요청으로 해당 노드로 이동한다.
2. 이동 응답의 현재 노드가 전투 노드라면 기존 `fight` 요청을 즉시 보낸다.
3. 선택 노드라면 자동 처리를 멈추고 기존 선택 UI를 표시한다.
4. 전투가 여러 번인 노드는 승리 응답의 `encounterIndex`를 확인해 완료될 때까지 `fight`를 반복한다.
5. 패배, 원정 완주, 오류가 발생하면 즉시 자동 진행을 멈춘다.

지도 자체의 노드 클릭은 기존 미리보기 역할을 유지한다. 즉시 진행은 명확하게 표시된 다음 경로 카드에서만 시작해 지도 탐색 중 오선택을 방지한다.

첫 항로 선택은 입장 횟수와 모드를 확정하는 중요한 단계이므로 현재의 항로 미리보기와 `이 항로로 원정 시작` 확인을 유지한다. 다만 간편 진행이 켜져 있으면 원정 생성 직후 첫 전투를 자동 시작한다.

## 클라이언트 처리 구조

`V2StormExpeditionView`에서 서버 요청과 화면 상태 갱신의 공통 부분을 작은 요청 함수로 분리한다. 이 함수는 응답을 파싱하고 최신 `status`를 저장하되, `result` 표시와 연속 행동 여부는 호출한 흐름에서 결정한다.

간편 진행 전용 조정 함수는 다음 책임만 가진다.

- 시작 또는 이동 요청을 한 번 보낸다.
- 응답의 활성 원정과 현재 노드를 확인한다.
- 전투 노드이면 현재 노드 ID와 전투 인덱스를 기대값으로 담아 전투 요청을 보낸다.
- 승리 후 같은 노드가 미완료이면 갱신된 기대값으로 다음 전투를 반복한다.
- 각 응답마다 화면 상태를 갱신해 중간 실패 후에도 서버의 실제 위치를 보여준다.
- 마지막 전투 응답을 간략 결과로 남긴다.

기존 `start`, `move`, `fight` API를 그대로 사용한다. 이동 성공 후 전투 요청이 네트워크 오류로 실패하더라도 유저는 이동한 노드에 정상적으로 머물며, 화면의 전투 시작 버튼으로 재시도할 수 있다. 별도의 복합 서버 액션을 추가하지 않아 기존 클라이언트와 API 호환성을 유지한다.

연속 요청 전체에서 하나의 `busy` 상태를 사용한다. 자동 진행이 끝나기 전에 다른 경로나 귀환 버튼을 누를 수 없도록 한다.

## 결과 및 전리품 표시

간편 진행에서도 서버가 반환하는 리플레이 데이터는 변경하지 않는다. 클라이언트가 `result`에 저장할 때만 리플레이를 제외하므로 API와 기존 리플레이 호환성은 유지된다.

- 승리: 기존 성공 배너와 이번 전투 전리품 카드를 표시한다.
- 연속 전투: 마지막 전투 결과를 카드로 표시하고, 누적 결과는 기존 임시 전리품 가방에서 확인한다.
- 패배: 기존 실패 배너를 표시하고 자동 진행을 종료한다.
- 최종 보스: 기존 완주·확정 획득·SP 열매 결과를 표시한다.
- 상세 확인: 일반 진행으로 전환하면 이후 전투부터 기존 리플레이를 볼 수 있다. 이미 생략한 전투를 다시 여는 별도 보관 기능은 이번 범위에 포함하지 않는다.

## 오류 처리

- 모든 요청은 기존 `expectedCurrentNodeId`, `expectedEncounterIndex` 검증을 사용한다.
- `stale_state`를 포함한 서버 오류가 오면 연속 진행을 멈추고 서버 응답 상태와 오류 배너를 표시한다.
- 응답 본문을 읽지 못하거나 네트워크 오류가 나면 `network` 오류를 표시하고 현재까지 성공한 상태는 유지한다.
- 이동까지만 성공한 경우 해당 노드의 기존 전투 시작 UI를 남겨 수동 재시도가 가능하게 한다.
- 중복 클릭은 전체 연속 흐름 동안 `busy`로 차단한다.
- 컴포넌트가 사라진 뒤 늦게 도착한 요청이 상태를 덮지 않도록 기존 React 생명주기 범위 안에서만 상태를 갱신한다.

## 접근성과 화면 규칙

- 다음 경로 카드는 `button`으로 제공하고 노드 이름과 실행 결과를 접근 가능한 이름에 포함한다.
- 자동 전투 중 버튼 문구를 `다음 전투 진행 중...`으로 바꿔 현재 상태를 알린다.
- 라이트·다크 모드 모두 기존 `Card`, `SURFACE_INSET` 불투명 표면을 사용한다.
- 지도와 현재 행동 카드의 기존 배치 순서는 유지한다.

## 테스트

- 간편 진행 기본값과 로컬 저장소 복원·변경 저장을 검증한다.
- 다음 전투 노드 선택이 `move → fight` 순서로 요청되는지 검증한다.
- 선택 노드로 이동하면 자동 전투 요청을 보내지 않는지 검증한다.
- 다중 전투 노드가 완료될 때까지 갱신된 전투 인덱스로 이어지는지 검증한다.
- 패배·완주·서버 오류·네트워크 오류에서 연속 진행이 중단되는지 검증한다.
- 간편 진행이 꺼져 있으면 기존 노드 미리보기, 이동 확인, 전투 시작과 리플레이 흐름이 유지되는지 검증한다.
- 기존 원정 API 테스트 전체를 실행해 보상·상태 저장 규칙이 변하지 않았음을 확인한다.
- TypeScript, ESLint와 프로덕션 빌드를 완료 전 검증으로 실행한다.
