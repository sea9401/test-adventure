# 전투 로그 현재 시간대 표시 설계

## 목표

전용 전투 로그 화면에서 사용자가 현재 읽고 있는 로그 구간의 전투 틱을 빠르게 파악할 수 있게 한다. 표시는 `1,500 / 3,000틱` 형식을 사용하며, 앞 숫자는 화면 최상단에 보이는 로그 묶음의 첫 틱이다.

## 범위

- ATB 틱(`BattleLogEntry.t`)이 기록된 PvE·PvP 전투 로그에 적용한다.
- 전용 전투 로그 페이지와 전체 화면 오버레이에 적용한다.
- 틱 정보가 없는 구형·레거시 로그에서는 표시를 숨긴다.
- 전투 엔진 결과와 저장된 리플레이 형식은 변경하지 않는다.

## 표시 방식

- 데스크톱에서는 로그 카드 오른쪽의 빈 공간에 작은 불투명 카드를 배치한다.
- 표시 카드는 스크롤 중에도 보이도록 고정된 세로 위치를 유지한다.
- 오른쪽 공간이 부족한 좁은 화면에서는 로그 카드 내부 우측 상단에 작은 고정 배지로 표시한다.
- 문구는 `현재 시간대`와 `{현재 틱} / 3,000틱` 두 줄로 구성한다.
- 기존 표면 상수를 사용해 라이트·다크 모드 모두에서 배경 이미지가 비치지 않게 한다.

## 틱 결정

1. `BattleLogList`가 이미 만드는 로그 묶음별로, 묶음 안에서 가장 먼저 나타나는 `t` 값을 노출한다.
2. 전용 로그 스크롤 컨테이너를 기준으로 현재 보이는 묶음을 관찰한다.
3. 보이는 묶음 중 화면 상단에 가장 가까운 묶음의 첫 틱을 현재 시간대로 선택한다.
4. 사용자가 위아래로 스크롤하면 표시값을 즉시 갱신한다.
5. 틱이 기록된 묶음이 하나도 없으면 시간대 표시 자체를 렌더링하지 않는다.

최대값 `3,000틱`은 PvE와 PvP 엔진이 함께 사용하는 타임라인 상한을 공용 상수로 두어 UI와 엔진의 값이 어긋나지 않게 한다.

## 컴포넌트 경계와 데이터 흐름

- `BattleLogList`는 각 묶음의 DOM 요소에 첫 틱 메타데이터만 제공한다.
- `BattleScene`은 로그 뷰포트와 묶음을 관찰하고 현재 틱 상태를 관리한다.
- 시간대 표시 컴포넌트는 현재 틱과 최대 틱만 입력받아 데스크톱 카드와 모바일 배지를 렌더링한다.
- 엔진이나 리플레이 데이터에 UI 전용 현재 위치 상태를 추가하지 않는다.

## 예외 처리

- 구형 로그처럼 `t`가 없으면 기존 전투 로그만 그대로 표시한다.
- 브라우저가 관찰 API를 지원하지 않는 경우 스크롤 위치 계산 방식으로 동일한 값을 구한다.
- 로그가 비었거나 아직 로드 중이면 표시하지 않는다.
- 현재 틱은 `0` 이상 `3,000` 이하로 제한해 손상된 데이터가 UI를 깨뜨리지 않게 한다.

## 검증

- 묶음의 첫 틱을 올바르게 추출하는 단위 테스트를 추가한다.
- 가장 위에 보이는 묶음이 바뀔 때 표시값이 갱신되는 회귀 테스트를 추가한다.
- 틱 없는 레거시 로그에서 표시가 숨겨지는지 테스트한다.
- 전용 페이지의 데스크톱 카드와 모바일 배지 마크업을 확인한다.
- 관련 테스트와 타입 검사를 실행한다.
