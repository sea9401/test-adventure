# 도감 숙련 B3 장비·요리·현장 기록 연결 설계

상태: 기존 도감 숙련 엔드게임 설계의 승인된 구현 5단계
작성일: 2026-08-20
기반: `docs/superpowers/specs/2026-08-20-codex-mastery-endgame-design.md`

## 1. 목표와 범위

B3는 장비, 요리, 현장 기록의 서버 권위 진행을 기존 도감 숙련 중앙 기록 서비스에 연결한다.
기존 보상과 응답은 바꾸지 않고 성공한 게임 행동의 같은 데이터베이스 트랜잭션에서만 기록한다.

- 장비는 직접 사냥 드롭, 폭풍 원정 회수, 협동 보스 시그니처 보상과 장비 상자, 길드 공방 제작만 센다.
- 요리는 `cook` 액션이 실제 생산한 수량만 센다.
- 현장 지역은 성공 횟수, 환경은 KST 기준 서로 다른 관찰일, 발견은 완료 관찰 횟수를 센다.
- 실패, 중복 요청, 주문 납품, 상점 구매, 퀘스트 보상, 거래·우편·창고 이동, 관리자·개발자 지급은 세지 않는다.
- 특별 인장, 트로피, UI, 랭킹, 숙소 전시와 월간 연구전은 B3 범위 밖이다.
- `recordingEnabled`와 `sealsEnabled` 기본값은 계속 `false`로 유지한다.

## 2. 접근안과 선택

### 선택안: 권위 성공 경로의 명시적 이벤트 + 생활 공용 훅

기존 `recordCodexMasteryGameplayBatch` 이벤트에 장비·요리·현장 기록을 추가한다. 장비는 실제 발생
출처를 아는 라우트에서만 호출한다. 요리는 조리 성공 분기에서 직업 이벤트와 함께 한 번에 기록한다.
생활은 낚시·채광·벌목이 모두 통과하는 `recordLifeFieldSuccessInTx`에서 저장 전후 상태의 의미적
델타를 계산해 기록한다.

이 방식은 거래나 반납을 획득으로 오인하지 않고, 같은 게임 트랜잭션이므로 보상과 숙련이 갈라지지
않는다. 생활 기록의 복잡한 일 단위 의미도 여러 라우트에서 중복 구현하지 않는다.

### 제외안: 범용 장비 저장·추가 헬퍼에서 자동 기록

`appendEquipInstances`와 `equipment.v2` 저장은 보스 보상뿐 아니라 마켓 구매, 판매 취소, 만료 반납,
관리자·개발자 지급에도 쓰인다. 이 지점에서는 아이템의 원래 출처를 알 수 없어 이전과 신규 획득을
구분할 수 없다.

### 제외안: 세이브 스냅샷 비교 또는 비동기 재계산

장비 보유 수 비교는 판매·이동·재획득의 출처를 잃고, 조리 재고 비교는 납품과 소비에 영향을 받는다.
현장 환경의 서로 다른 KST 관찰일은 현재 누적값만으로 재구성할 수 없다. 비동기 방식은 별도 멱등 키와
복구 소비자를 요구하고 게임 보상과 기록 사이에 불일치 구간을 만든다.

## 3. 중앙 게임플레이 이벤트 확장

기존 이벤트에 다음 세 종류를 추가한다.

```ts
type CodexMasteryGameplayEvent =
  | {
      category: "equipment";
      entryId: V2EquipmentId;
      amount: number;
      source: "equipment.drop" | "equipment.craft";
    }
  | {
      category: "cooking";
      entryId: string;
      amount: number;
      source: "cooking.complete";
    }
  | {
      category: "life";
      entryId: string;
      amount: number;
      source: "life.complete";
    };
```

기존 어보·몬스터·직업 이벤트와 동일하게 `category + entryId + source`로 합산하고 안정적으로 정렬한다.
모든 이벤트는 `discovered: true`로 기록하며, 어보 외에는 `bestValue`를 제출하지 않는다. 0은 제거하고
음수·비정수·오버플로 합계는 트랜잭션을 실패시킨다. 기능 스위치가 꺼져 있으면 진행 행은 쓰지 않는다.

## 4. 장비 연결

장비 이벤트는 실제 장비 인스턴스가 해당 사용자 소유 목록에 추가된 뒤 같은 트랜잭션에서 제출한다.

| 권위 경로 | 항목과 수량 | 출처 |
|---|---|---|
| 일반·일괄·오프라인 사냥 드롭 | `droppedEquipment`, `droppedUnique` 각각 1 | `equipment.drop` |
| 폭풍 원정 귀환·최종 회수 | `active.pendingEquipment`의 각 인스턴스 ID 1 | `equipment.drop` |
| 협동 보스 보상 수령 | 새로 굴린 `uniqueId` 1 | `equipment.drop` |
| 협동 장비 상자 사용 | 상자에서 확정된 `equipmentId` 1 | `equipment.drop` |
| 길드 공방 제작 | `recipe.equipmentId` 1 | `equipment.craft` |

사냥은 기존 몬스터·직업 이벤트 수집기에 장비 이벤트를 넣어 단판은 즉시, 일괄과 오프라인은 한 번에
flush한다. 폭풍 원정은 같은 pending 장비를 실소유로 옮기는 `claimPendingRewards`에서 기록하므로 중간
노드의 임시 보상이나 연습 모드는 세지 않는다. 협동 보상 재요청은 기존 `claimedAt` 멱등 가드에서
조기 반환되어 다시 기록되지 않는다. 상자 없음과 빈 풀 실패도 기록되지 않는다.

상점, 퀘스트, 마켓 체결·취소·만료, 우편, 길드 창고, 시작 장비, 관리자와 개발자 지급은 의도적으로
연결하지 않는다. 이미 보유한 장비 백필은 발견만 복원하며 과거 반복 획득 수는 추측하지 않는다.

## 5. 요리 연결

`POST /api/v2/cooking`의 `action === "cook"` 성공만 다음 이벤트를 만든다.

```ts
{
  category: "cooking",
  entryId: recipe.id,
  amount: quantity,
  source: "cooking.complete",
}
```

`quantity`는 재료 소비와 완성 음식 추가에 사용한 동일한 서버 권위 생산량이다. 품질, 희귀 재료 사용,
완성 음식 변형에 관계없이 기본 조리법 항목에 합산한다. `order`와 `standing_delivery`는 기존 완성품을
소비하므로 조리 횟수를 늘리지 않는다. 실제 직업 숙련도도 오른 경우 기존 `job.activity` 이벤트를 같은
배치에 넣어 운영 설정 조회와 중앙 호출을 한 번으로 묶는다.

## 6. 현장 기록 연결

`recordLifeFieldSuccessInTx`가 적용 전 상태와 `applyLifeFieldSuccess` 결과를 비교해 이벤트를 만든다.

- 지역: `region:<activity>:<sourceId>` 항목에 실제 지역 기록 증가량을 더한다. 자동 정산의
  `successes > 1`도 그대로 반영한다.
- 환경: `environment:<environmentId>` 항목은 해당 환경의 이전 `lastAt`이 현재 KST 일자와 다를
  때만 1을 더한다. 같은 날 여러 행동과 자동 정산은 한 번만 센다.
- 발견: 완료 관찰이 있으면 `discovery:<discoveryId>` 항목에 실제 완료 기록 증가량을 더한다.

실제 항목 ID는 프로덕션 카탈로그가 사용하는 기존 ID 생성 규칙과 일치시킨다. 환경·발견 기능이 꺼져
있어 상태가 변하지 않으면 이벤트도 생기지 않는다. `duplicate` 결과는 세이브와 숙련 모두 쓰지 않는다.
생활 상태를 먼저 저장한 뒤 숙련을 기록하고 어느 한쪽이라도 실패하면 전체 게임 행동을 롤백한다.

환경은 행동 횟수가 아니라 서로 다른 KST 날짜 수이므로 `successes`를 이벤트 수량으로 사용하지 않는다.
과거 백필도 저장된 `count`가 실제 날짜 수임을 증명하지 못하므로 발견 상태만 복원하고 반복 수는 0으로
둔다는 기존 정책을 유지한다.

## 7. 잠금과 실패 처리

모든 기록 호출은 이미 게임 세이브 잠금을 얻은 트랜잭션 후반부에 위치한다. 순서는 게임 세이브,
`codex_mastery_summary`, `codex_mastery_progress`다. 동일 사용자의 장비·요리·생활 행동과 백필이 반대
순서로 잠그지 않는다.

중앙 기록 실패를 삼키지 않는다. 따라서 보상만 지급되고 숙련이 빠지는 부분 성공은 없다. 카탈로그에
없는 장비·조리법·현장 ID나 잘못된 출처는 중앙 서비스가 거부해 배선 누락을 조기에 드러낸다.

## 8. 특별 인장 제외

B3는 특별 인장을 부분적으로 구현하지 않는다. 장비 품질, 요리 품질·희귀 재료, 생활 희귀 발견 같은
인장은 어보·몬스터·직업과 함께 별도 인장 묶음에서 공통 규칙과 중복 방지를 설계한다. B3 이벤트는
`sealIds`를 제출하지 않으며 `sealsEnabled = false`를 유지한다.

## 9. 검증 기준

- 어댑터가 장비·요리·현장 이벤트를 정확한 출처로 합산하고 기존 이벤트 의미를 보존한다.
- 장비는 다섯 권위 획득 경로만 기록하며 실패·재요청·이동·구매·지급은 기록하지 않는다.
- 사냥 단판·일괄·오프라인에서 실제 드롭 인스턴스마다 정확히 한 번 기록한다.
- 조리 배치는 실제 생산량을 기록하고 주문·상시 납품은 조리 횟수를 올리지 않는다.
- 지역은 성공 수, 환경은 KST 일자당 1, 발견은 완료 증가량만 기록하며 중복 세션은 기록하지 않는다.
- 기존 응답, SP, 전투 수치, 골드, 재료와 장비 결과는 바뀌지 않는다.
- 집중 회귀 테스트, TypeScript, ESLint, 예산 검사와 프로덕션 빌드가 통과한다.
- 기능 스위치는 꺼져 있고 Phase A/B 작업은 현재 배포 대상 브랜치에 포함되지 않으며 배포하지 않는다.
