# 도감 숙련 트로피 숙소 전시 B7 설계

## 목표

도감 숙련 트로피를 기존 개인 숙소와 공개 방문 숙소에 연결한다. 모험 기록 서가는 모든 이용자에게
지급되는 기본 가구이므로, 획득한 분야·종합 트로피 중 하나를 프로필 대표 슬롯과 독립적으로 무료
전시할 수 있다. 관련 전시 가구에는 기존 장비·물고기·토벌 기록을 유지하면서 도감 트로피를 동반
전시할 수 있게 한다.

트로피 전시는 수집 성과를 보여 주는 장식 기능이며 SP, 전투력, 골드, 아이템, 업적 점수를 지급하지
않는다. B7은 배포, 기능 플래그 활성화, 실데이터 재구축을 수행하지 않는다.

## 접근안

### 1. 기존 `display` 한 칸을 트로피까지 포함하는 공용 선택으로 확장

저장 형식 변경은 작지만 장비 마네킹이나 수조에서 기존 전시품과 트로피 중 하나만 골라야 한다.
원 설계의 “관련 숙련 기록이나 트로피를 선택적으로 함께 표시”를 충족하지 못하므로 채택하지 않는다.

### 2. 트로피 전용 신규 가구 추가

기존 모델을 거의 건드리지 않지만 기본 서가와 관련 전시 가구를 활용한다는 목표에서 벗어난다. 신규
이미지와 가구 지급·제작 밸런스까지 범위가 커지므로 B7에서는 채택하지 않는다.

### 3. 배치마다 별도 도감 트로피 동반 전시 필드 추가

기존 `display`는 그대로 두고 `masteryTrophy`를 별도 선택으로 저장한다. 기존 숙소 세이브와 호환되고,
장비·물고기·토벌 기록과 트로피를 동시에 보여 줄 수 있다. 트로피는 안정적인 가족 ID만 저장하고
이름·등급은 현재 권위 데이터에서 매번 해석한다. 이 방식을 채택한다.

## 저장 모델과 호환성

`HousingPlacement`에 다음 선택 필드를 추가한다.

```ts
type HousingMasteryTrophyRef = {
  trophyId: string;
};

type HousingPlacement = {
  // 기존 필드
  masteryTrophy?: HousingMasteryTrophyRef;
};
```

기존 `housing.v1` 키와 `version: 1`은 유지한다. 선택 필드 추가이므로 마이그레이션이 필요하지 않다.
파서는 알려진 `mastery:<category>` 가족 ID만 받아들이고, 손상되거나 알 수 없는 참조는 읽기에서
제거한다. 쓰기에서는 다음을 모두 검증한다.

- 실제 획득한 도감 숙련 트로피인지
- 해당 가구가 트로피 동반 전시를 지원하는지
- 트로피 분야가 가구에 허용된 분야인지

검증 실패는 `invalid_mastery_trophy` 또는 `mastery_trophy_not_owned`로 구분한다.

## 가구별 연결 규칙

| 가구 | 선택 가능한 도감 트로피 |
|---|---|
| 모험 기록 서가 | 장비, 어보, 몬스터·사냥터, 요리, 현장 기록, 직업, 종합 중 1개 |
| 대물 전시 수조 | 어보 |
| 토벌 트로피 | 몬스터·사냥터 |
| 장비 마네킹 | 장비 |
| 무기 진열대 | 장비 |
| 조리도구 전시대 | 요리 |

모험 기록 서가는 기본 보유 수량 1개와 기본 배치를 그대로 사용하므로 별도 구매 없이 대표 도감
트로피 하나를 전시할 수 있다. 다른 가구는 기존 보유·제작 규칙을 바꾸지 않는다.

## 서버 데이터 흐름

### 내 숙소 조회

`GET /api/v2/me/housing`은 기존 숙소 원본과 장비·어보·토벌 데이터를 읽은 뒤 도감 숙련 기능 설정을
읽는다. `trophiesEnabled=true`이면 `codex_trophy_history`에서 획득 연혁을 읽어 숙소용 트로피 옵션을
만든다. 옵션은 안정 ID, 이름, 분야, 현재 최고 등급과 “도감 숙련 · 백금” 같은 상세 문구만 포함한다.
잠긴 트로피와 다음 단계 진행도는 전시 선택에 필요하지 않으므로 반환하지 않는다.

### 내 숙소 저장

`POST /api/v2/me/housing`은 클라이언트 값을 믿지 않고 현재 획득 연혁을 다시 읽어 검증한다. 트로피
기능이 꺼졌을 때는 새 선택이나 변경을 받지 않는다. 다만 기능이 켜져 있을 때 저장했던 선택이 운영상
일시 비공개된 뒤 사용자가 가구 위치만 바꾸는 경우를 위해, 같은 배치 UID에 있던 기존 트로피 선택은
서버에서 복원하여 보존한다. 가구를 보관함으로 돌려 배치가 사라지면 그 전시 선택도 함께 제거된다.

### 공개 숙소 조회

`GET /api/v2/player/[name]/housing`은 공개 숙소에서 실제 선택된 옵션만 반환한다. 현재 획득 연혁에 없는
트로피 참조는 응답에서 제거하고, 기능이 꺼져 있으면 모든 도감 트로피 참조와 옵션을 숨긴다. 이
정리는 공개 응답에만 적용하며 저장 원본을 자동 삭제하지 않는다.

## 기능 플래그와 실패 처리

- 기존 생활/숙소 게이트가 꺼져 있으면 지금처럼 인증·DB 접근 전에 404를 반환한다.
- `trophiesEnabled=false`이면 트로피 연혁을 읽지 않고 기존 숙소 동작만 제공한다.
- 트로피 연혁 조회가 실패하면 숙소 전체를 부분 데이터로 저장하지 않고 요청을 실패시킨다.
- 저장은 기존 `housing.v1` 행 잠금과 트랜잭션을 유지한다.
- 프로필 대표 트로피와 숙소 대표 트로피는 서로 다른 저장소를 사용하며 한쪽 선택이 다른 쪽을
  변경하지 않는다.

## UI

편집 화면의 가구 선택 패널은 기존 전시품 선택 아래에 `도감 숙련 트로피` 선택기를 추가한다. 해당
가구에 허용된 분야의 획득 트로피만 보이며, 선택지는 이름과 현재 등급을 함께 표시한다. 가능한
트로피가 없으면 획득 후 표시된다는 안내를 제공한다.

방 캔버스에서는 선택한 트로피를 작은 등급 메달과 이름으로 표시한다. 가구 이미지를 가리지 않도록
상단 모서리의 불투명 배지로 배치하고, 백금·다이아·전설 색상은 B6 전시대와 같은 의미를 사용한다.
방문자 화면의 `대표 전시 기록`에는 기존 장비·물고기·토벌 기록과 도감 트로피가 함께 나타난다.

새 본문·선택 패널·방문자 카드는 기존 `Card`, `SURFACE_INSET`, 불투명 입력 배경을 유지한다. 잠긴
가구나 트로피를 컨테이너 전체 투명도로 표현하지 않는다.

## 테스트

- 순수 모델: 참조 파싱, 가구별 분야 허용, 미획득·위조·잘못된 분야 거부, 손상 세이브 복구
- 서버 조합: 연혁을 숙소 옵션으로 변환하고 공개 선택만 필터링
- 내 숙소 API: 플래그가 켜졌을 때 옵션 반환·저장, 꺼졌을 때 연혁 미조회, 기존 선택 보존, 위조 거부
- 공개 숙소 API: 선택된 획득 트로피만 반환, stale 참조 제거, 플래그 off 응답 숨김
- UI: 서가 무료 전시 선택, 관련 분야 필터, 기존 전시품과 동시 표시, 불투명 표면 유지
- 회귀: 기존 장비·어보·토벌 전시와 손상 세이브 복구가 그대로 동작
- 완료 전 TypeScript, ESLint, 전체 Vitest, 이미지 검사와 프로덕션 빌드

## B7 범위 밖

- 월간 연구전 트로피와 명예의 전당
- 신규 가구, 신규 숙소 이미지, 가구 지급·제작 밸런스 변경
- 트로피 획득 알림과 전광판 게시
- SP, 전투력, 골드, 아이템, 업적 점수 보상
- 운영 배포, 기능 플래그 활성화, 실데이터 재구축
