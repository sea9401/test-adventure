# 도감 숙련 월간 연구 진행 기반(B8a) 설계

## 목표

운영자가 검토해 예약한 월간 연구 시즌만 KST 월 경계에서 활성화하고, 서버가 확정한 게임 행동으로
18개 목표·다양성·기록 점수를 개인별로 누적한다. 이번 묶음은 시즌 정의, 개인 진행 저장과 조회,
모험의 서 표시까지 구현한다.

월간 공개 랭킹, 최종 정산, 월간 트로피 발급, 전광판은 다음 묶음으로 남긴다. 모든 도감 숙련 기능
기본값은 계속 `false`이며 실제 시즌 예약, 기능 활성화, 백필, 배포는 하지 않는다.

## 고정 원칙

- 시즌은 `Asia/Seoul` 기준 매월 1일 00:00부터 다음 달 1일 00:00까지다. 종료 시각은 배타적이다.
- 시즌 ID는 시작 월의 `YYYY-MM`이며, 같은 달에는 정의 하나만 존재한다.
- 정의가 없는 달은 자동 생성하지 않는다. 검증을 통과해 `scheduled`로 저장된 정의만 시각이 되면
  기록 대상으로 취급한다.
- 목표 18개는 첫날부터 모두 보이며 일일 과제, 연속 출석, 시간 제한 하위 목표가 없다.
- 목표 그룹은 기초 조사 6, 분야 연구 6, 전문 연구 4, 도전 기록 2개로 고정한다.
- 기본 목표 점수는 정확히 12,000점, 다양성 상한은 5,000점, 기록 상한은 3,000점이다.
- 월간 최대 점수는 20,000점이고 영구 숙련, SP, 전투력, 골드, 아이템에 합산하거나 보상하지 않는다.
- 정의 스냅샷은 시즌 시작 뒤 수정하지 않는다.

## 검토한 접근

### 1. 영구 숙련 진행에서 월간 값을 역산

별도 쓰기가 적지만 시즌 시작 기준값, 기능 차단 중 행동, 영구 기록 비활성 상태를 정확히 구분할 수
없다. 개인 최고 기록도 달 안에서 새로 세운 값인지 판별하기 어렵다. 채택하지 않는다.

### 2. 기존 세이브 JSON에 시즌 상태 저장

초기 구현은 단순하지만 18개 목표와 다양성 집합이 사용자 세이브 전체의 잠금 범위와 크기를 키운다.
랭킹 및 정산 시 전체 JSON을 읽어야 하며, 시즌별 불변 기록도 보존하기 어렵다. 채택하지 않는다.

### 3. 전용 시즌·진행 테이블과 순수 평가기

월 경계, 사용자별 행 잠금, 점수 인덱스, 향후 멱등 정산을 자연스럽게 지원한다. 정의와 평가를 순수
도메인 코드로 두고 저장만 서버 저장소에서 처리한다. 이 방식을 채택한다.

## 정의 계약

`CodexResearchDefinitionSnapshot`은 다음을 포함한다.

- 버전, 시즌 ID, 테마 ID와 표시명
- 주 분야 2개와 보조 분야 1개
- 정확히 18개의 목표
- 다양성 점수 트랙
- 기록 점수 트랙

목표는 안정적인 ID, 그룹, 표시명과 설명, 고정 점수, 평가 규칙을 가진다. 평가 규칙은 현재 중앙
게임플레이 이벤트가 권위 있게 제공할 수 있는 세 종류만 허용한다.

- `count`: 필터에 맞는 성공 수량 누적
- `distinct_entries`: 필터에 맞는 서로 다른 항목 수
- `best_value`: 필터에 맞는 개인 최고 수치

모든 규칙은 분야와 선택적인 출처·항목 ID 필터를 가진다. 클라이언트는 진행량이나 점수를 제출하지
않는다. 목표 점수는 목표를 처음 완료할 때 한 번만 붙는다.

다양성 트랙은 서로 다른 `category:entryId`를 저장하고 항목당 점수를 상한까지 준다. 기록 트랙은
`bestValue`의 최고치를 저장하며 고정된 단계별 점수를 적용한다. 반복 수량은 목표별 목표치에서,
다양성과 기록은 트랙별 최대점에서 각각 제한되므로 무제한 점수원이 없다.

검증기는 다음을 거부한다.

- KST 월 경계나 시즌 ID가 맞지 않는 정의
- 중복 ID, 알 수 없는 분야·출처, 비어 있는 필터, 잘못된 목표 그룹 수
- 목표 점수 합계가 12,000점이 아닌 정의
- 다양성 최대 합계가 5,000점이 아니거나 기록 최대 합계가 3,000점이 아닌 정의
- 감소하거나 중복된 기록 단계, 안전한 정수 범위를 벗어나는 수치

## 저장 모델

### `codex_research_seasons`

- `season_id` 기본 키
- `theme_id`
- `definition_snapshot` JSONB
- `start_at`, `end_at`
- `status`: `scheduled`, `active`, `settling`, `closed`
- `settled_at`, `created_at`, `updated_at`

### `codex_research_progress`

- `user_id + season_id` 복합 기본 키
- `score`
- `objective_progress` JSONB: 목표별 값·완료 시각, 다양성 항목 집합, 기록 최고값
- `objective_completed_count`
- `diversity_score`, `record_score`
- `score_reached_at`
- 다음 묶음용 nullable `final_rank`, `final_tier`
- `representative_record`, `updated_at`

점수와 완료 수에는 비음수 검사와 20,000/18 상한 검사를 둔다. 시즌별 점수와 동점 판정 필드를
포함한 인덱스를 미리 두어 다음 묶음의 랭킹이 같은 권위 행을 사용하게 한다.

## 기록 흐름

중앙 `recordCodexMasteryGameplayBatch`가 설정을 한 번 읽고 이벤트를 기존 규칙대로 검증·합산한다.

1. 영구 기록과 월간 기록이 모두 꺼져 있으면 즉시 반환한다.
2. 영구 기록이 켜져 있으면 기존 영구 숙련 기록기를 호출한다.
3. 월간 진행이 켜져 있으면 같은 집계 이벤트를 월간 기록기에 전달한다.
4. 월간 기록기는 `start_at <= now < end_at`인 예약/활성 시즌을 하나 찾고 정의를 검증한다.
5. 사용자·시즌 진행 행을 생성 후 잠그고 순수 평가기로 다음 상태를 계산한다.
6. 변화가 있을 때만 행을 저장한다. 예약 시즌은 첫 유효 기록 시 `active`로 단조 전환한다.
7. 어느 기록기든 실패하면 바깥 게임 행동 트랜잭션도 실패해 보상과 연구 기록이 갈라지지 않는다.

기존 게임 행동의 재시도 방지와 트랜잭션 경계를 그대로 상속한다. 한 배치 안의 같은 분야·항목·출처는
먼저 합산되므로 같은 목표가 중복 증가하지 않는다. 종료 시각 이후 이벤트는 지난 시즌에 기록하지
않으며, 월간 정의나 활성 시즌이 없으면 정상적으로 아무 것도 쓰지 않는다. 월간은 소급 백필하지 않는다.

영구 기록과 월간 기록은 독립 게이트다. 따라서 비공개 시험에서는 영구 기록을 건드리지 않고 월간만
기록할 수 있고, 반대로 월간 장애 시 영구 숙련만 유지할 수도 있다.

## 시즌 예약 경계

저장소에 `scheduleCodexResearchSeason`을 제공한다. 기본 동작은 정의를 검증하고 기존 시즌과의 충돌을
확인하는 것까지이며, 명시적인 적용 경로에서만 `scheduled` 행을 만든다. 시작된 시즌은 같은 ID로
덮어쓰지 않는다. 이번 묶음에는 실제 운영 월 정의를 넣지 않아 기능을 실수로 켜도 자동 시즌이 생기지
않는다. 운영용 정의 작성과 예약 UI/명령은 비공개 시험 준비 묶음에서 연결할 수 있다.

## 개인 조회와 화면

기존 인증된 `/api/v2/me/codex-mastery` 응답에 `monthlyResearch`를 추가한다.

- `monthlyProgressEnabled=false`: 월간 DB를 읽지 않고 `null`
- 기능은 켜졌지만 활성 시즌 없음: 준비 중 상태
- 활성 시즌 있음: 테마, KST 기간, 총점과 세 점수 구성, 완료 수, 18개 목표의 진행·완료 상태

모험의 서 숙련 화면 상단에 불투명 월간 연구 카드를 둔다. 현재 점수와 남은 기간, 점수 구성을 먼저
보이고 18개 목표를 그룹별로 모두 펼쳐서 늦게 시작한 이용자도 전체 목표를 확인할 수 있게 한다.
랭킹, 예상 트로피, 최종 등급은 아직 권위 서비스가 없으므로 표시하지 않는다. 모든 패널은 기존
`SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`만 사용한다.

## 오류와 운영 안전

- 예약 시 검증되지 않은 정의는 저장하지 않는다.
- 저장된 활성 정의가 손상되면 조용히 점수를 누락하지 않고 트랜잭션 오류로 드러낸다.
- 기능이 꺼진 동안의 월간 행동은 소급하지 않는다.
- 시즌 상태와 진행 점수는 이번 묶음에서 정산하거나 트로피로 변환하지 않는다.
- 기본 플래그, 실제 데이터, 배포 체크아웃은 변경하지 않는다.

## 검증 범위

- KST 월 경계, 연말, 윤년과 종료 시각 배타성
- 18개 그룹 수와 12,000/5,000/3,000 예산 검증
- 수량·다양성·최고 기록 평가, 상한, 단조 증가, 한 번만 완료
- 사용자 행 잠금과 저장, 시즌 지연 활성화, 정의 없는 달 무기록
- 영구/월간 독립 게이트와 같은 트랜잭션 오류 전파
- 인증·기능 차단 시 조기 반환과 개인 응답
- 라이트/다크 불투명 화면, 18개 목표 표시, 가짜 랭킹·트로피 미표시
- PostgreSQL 마이그레이션과 실제 동시 갱신
