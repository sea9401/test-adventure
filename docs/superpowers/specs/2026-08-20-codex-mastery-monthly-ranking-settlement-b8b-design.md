# 도감 숙련 월간 랭킹·정산·시즌 트로피(B8b) 설계

## 위치와 종착점

전체 도감 숙련 로드맵은 B10에서 끝난다.

- 완료: Phase A, B1~B7, B8a
- 이번 묶음 B8b: 월간 공개 랭킹, 최종 순위 정산, 시즌 트로피 발급 기반과 기존 전시 표면 연결
- B9: 시즌 정의 작성·예약·정산 운영 도구, 비공개 시험, 관측과 복구 절차
- B10: 종료 시즌 명예의 전당, 전광판·알림, 공개 준비와 출시 점검

B10까지의 로컬 구현이 끝나도 실제 시즌 예약, 기능 활성화, 백필, 트로피 발급, 배포는 별도 운영
승인 없이는 실행하지 않는다.

## 목표

B8a의 `codex_research_seasons`와 `codex_research_progress`를 권위 데이터로 사용해 현재 시즌의 공식
동점 규칙을 적용한 공개 랭킹을 제공한다. 종료된 시즌은 한 번만 확정 정산하고, 확정 결과에서 월간
시즌 트로피를 별도로 멱등 발급할 수 있게 한다. 발급된 트로피는 기존 트로피 전시대, 공개 프로필과
숙소의 도감 트로피 선택 모델을 재사용한다.

월간 보상은 트로피와 기록 메타데이터뿐이다. SP, 전투 능력치, 골드, 아이템, 업적 점수와 영구 도감
숙련 점수에는 영향을 주지 않는다.

## 검토한 접근

### 1. 조회할 때마다 순위를 계산하고 종료 시즌도 고정하지 않기

구현량은 작지만 정지 상태나 닉네임 변경에 따라 과거 순위가 바뀌고 트로피 발급의 권위 기준이 없다.
채택하지 않는다.

### 2. 시즌 종료와 동시에 순위 확정 및 트로피 발급을 하나의 작업으로 처리

원자적이지만 비공개 시험에서 순위만 검증할 수 없고, 트로피 기능 차단 중 정산을 미루거나 누락해야
한다. 정산 오류와 전시 오류의 복구 범위도 불필요하게 결합된다. 채택하지 않는다.

### 3. 현재 랭킹, 확정 정산, 트로피 발급을 세 단계로 분리

현재 랭킹은 읽기 전용, 정산은 순위·등급 고정, 트로피 발급은 닫힌 시즌 결과의 전시 연혁 반영만
담당한다. B9 비공개 시험에서 정산까지만 실행하고 B10 공개 승인 뒤 같은 결과로 트로피를 발급할 수
있다. 각 단계가 독립 플래그와 멱등 키를 가지므로 이 방식을 채택한다.

## 등급과 동점 규칙

월간 등급은 다음 순서로 계산한다.

1. 18,000점 이상이면서 1~3위면 `legendary`
2. 16,000점 이상이면서 1~10위면 `diamond`
3. 16,000점 이상이면 `platinum`
4. 12,000점 이상이면 `gold`
5. 8,000점 이상이면 `silver`
6. 4,000점 이상이면 `bronze`
7. 그 미만은 등급 없음

따라서 1~3위가 18,000점 미만이어도 16,000점 이상이면 다이아를 받고, 11위 이하라도 16,000점
이상이면 백금을 보장받는다. 순위가 없는 이용자에게는 점수 기반 동·은·금·백금 예상만 제공할 수
있지만 다이아·전설은 부여하지 않는다.

공식 정렬은 다음 값의 내림차순/오름차순 조합으로 고정한다.

1. 총점 내림차순
2. 완료 목표 수 내림차순
3. 다양성 점수 내림차순
4. 기록 점수 내림차순
5. 현재 최종 점수 도달 시각 오름차순
6. 사용자 ID 오름차순

활성 시즌의 등급과 순위에는 `잠정` 표기를 붙인다. 닉네임을 가진 정상 이용자 중 점수가 1점 이상인
행만 공식 순위에 포함한다. 운영 관리자 이메일과 정산 시점에 제재 중인 계정은 제외한다. 사용자별
차단 관계는 화면에서 상대 행을 숨기는 데만 사용하고 공식 순위 숫자를 다시 매기지 않는다.

## 도메인 경계

`src/adventure/data/v2/codexResearchRanking.ts`에 DB와 무관한 월간 공개 계약을 둔다.

- `codexResearchTierFor(score, rank)`: 등급 경계와 순위 조건을 검증하고 결정한다.
- `CodexResearchRankingRow`: 순위, 이름, 아바타, 총점, 세 점수 구성, 완료 목표 수, 잠정 등급,
  본인 여부와 프로필 장식을 포함한다.
- `CodexResearchRankingResponse`: 기능 차단, 시즌 없음, 활성 랭킹의 닫힌 응답 합집합이다.
- `CodexResearchSeasonTrophyMetadata`: 시즌·테마·최종 순위·점수 구성·대표 기록·정산 시각을 보존한다.

점수, 순위, 날짜와 메타데이터가 범위를 벗어나면 조용히 보정하지 않고 오류로 처리한다.

## 현재 시즌 랭킹

`src/lib/server/codexResearchRanking.ts`는 현재 열린 시즌 한 개를 찾고 한 SQL 질의에서 다음을 수행한다.

1. 점수가 있는 진행 행을 사용자와 공개 프로필에 결합한다.
2. 제재 계정, 운영 관리자 이메일, 공개 이름이 없는 이용자를 제외한다.
3. 전체 적격 이용자에 공식 `ROW_NUMBER()`를 부여한다.
4. 순위를 매긴 뒤 현재 사용자가 차단한 다른 이용자만 응답에서 숨긴다.
5. 상위 50명, 본인 앞뒤 2명, 본인 행을 반환한다.

차단 필터를 순위 계산 뒤에 적용하므로 이용자마다 공식 순위가 달라지지 않는다. 활성 시즌에서는
점수와 순위로 잠정 등급을 계산한다. B8b 공개 API는 현재 열린 시즌만 다루며 종료 시즌 탐색과 명예의
전당은 B10에 남긴다.

`GET /api/rankings/codex-research`는 인증 후 `monthlyRankingVisible`을 읽는다. 기능이 꺼져 있으면
시즌·진행 테이블을 읽지 않고 `{ ok: true, enabled: false }`를 반환한다. 기능은 켜졌지만 열린 시즌이
없으면 명시적인 `no_season` 상태를 반환한다. GET Route Handler는 요청별 권위 상태이므로 정적 캐시를
사용하지 않는다.

## 확정 정산

`settleCodexResearchSeason`은 반드시 호출자가 연 DB 트랜잭션 안에서 실행한다.

1. 시즌 행을 `FOR UPDATE`로 잠근다.
2. 현재 시각이 `end_at`보다 이르면 거부한다.
3. 이미 `closed`이면 변경 없이 `already_closed` 결과를 반환한다.
4. `scheduled` 또는 `active` 시즌을 `settling`으로 전환한다.
5. 현재 랭킹과 같은 적격 조건·동점 규칙으로 모든 순위를 계산한다.
6. 시즌의 모든 진행 행에서 기존 최종 값을 비운 뒤 적격 행에 `final_rank`, `final_tier`를 기록한다.
7. 시즌을 `closed`로 전환하고 `settled_at`을 기록한다.

상태 전환과 최종 결과 저장은 한 트랜잭션이므로 중간 실패 시 모두 롤백된다. 동시 정산은 시즌 행
잠금으로 직렬화되며 두 번째 호출은 닫힌 결과를 확인한다. `(season_id, final_rank)`의 NULL 제외 고유
인덱스로 공식 순위 중복도 방어한다. 점수가 4,000점 미만인 적격 참가자도 최종 순위는 보존하되
`final_tier`는 NULL이다.

B8b는 정산 함수와 테스트 가능한 런타임만 제공한다. 자동 크론, 관리자 버튼, 실제 실행 명령은 B9의
운영 경계다. `settlementEnabled`가 꺼진 상태에서는 이후 운영 진입점이 이 함수를 호출하지 않는다.

## 시즌 트로피 발급

정산과 트로피 발급은 의도적으로 분리한다. `awardCodexResearchSeasonTrophies`는 `closed` 시즌의
`final_tier`가 있는 행만 읽어 `codex_trophy_history`에 다음 값을 UPSERT한다.

- 안정 ID: `research:{seasonId}`
- 종류: `research_season`
- 현재 등급: 확정 `final_tier`
- 등급 달성 시각: 정산 시각
- 카탈로그 버전: 시즌 정의 버전
- 시즌 메타데이터: 시즌 ID, 테마 ID·이름, 최종 순위, 총점, 목표·다양성·기록 점수, 대표 기록,
  정산 시각, 1위 각인 여부

사용자·트로피 ID 기본 키로 반복 실행을 멱등 처리한다. 같은 키에 다른 확정 결과가 있으면 덮어쓰지
않고 불일치 오류를 낸다. 트로피 발급은 게임 보상과 별도이며 `trophiesEnabled`가 꺼진 동안 실행하지
않는다. 비공개 시험에서 닫은 시즌도 이후 공개 승인 시 동일한 확정 행으로 안전하게 발급할 수 있다.

`codex_trophy_history_kind_valid`는 `research_season`을 허용하도록 확장한다. 영구 숙련 트로피 조회는
영구 종류만 명시적으로 필터해 월간 행 때문에 기존 평가기가 실패하지 않게 한다.

## 전시 연결

월간 트로피는 기존 `masteryTrophy` 선택 저장 형식을 바꾸지 않고 안정 ID만 재사용한다. 기존 저장값과
숙소 배치를 마이그레이션하지 않는다.

- 트로피 전시대: `월간 연구` 종류 필터, 시즌·테마·등급·순위·점수·대표 기록 표시
- 공개 프로필 대표 슬롯: 획득한 월간 트로피 선택 및 공개 표시
- 개인·방문 숙소: 기존 도감 트로피 선택기와 전시 배지에 월간 트로피 포함

영구 트로피 정의와 월간 트로피 메타데이터를 각각 검증한 뒤 표시용 공통 옵션으로 합친다. 손상된
메타데이터는 전시에서 조용히 꾸미지 않고 서버 오류로 드러낸다. 이미 선택된 월간 트로피를 기능
차단 때문에 삭제하지 않으며, 기능이 다시 켜지면 같은 ID로 복구한다.

## 화면 연결

기존 도감 랭킹 하위 탭은 다음 네 개가 된다.

```text
완성도 | 종합 숙련 | 분야별 | 이달의 연구
```

월간 랭킹 화면은 불투명 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`만 사용해 다음을 표시한다.

- 시즌 테마와 KST 기간, 잠정 상태
- 상위 50명과 본인 주변 순위
- 총점, 완료 목표, 목표·다양성·기록 점수
- 잠정 트로피 등급과 동점 판정 안내

모험의 서 월간 연구 카드에도 랭킹 공개가 켜졌을 때 내 잠정 순위와 예상 등급을 표시한다. 랭킹이
꺼져 있으면 기존 B8a 화면을 유지하며 순위나 등급을 추정해 표시하지 않는다. 잠긴 카드 전체에
`opacity-*`를 적용하지 않는다.

## 기능 차단과 비목표

- `monthlyProgressEnabled`: 게임 행동의 월간 점수 기록과 개인 진행 화면
- `monthlyRankingVisible`: 현재 시즌 랭킹 API와 랭킹 화면, 개인 잠정 순위
- `settlementEnabled`: B9 운영 진입점의 정산 실행 허용
- `trophiesEnabled`: 월간 트로피 발급 및 전시 포함

모든 기본값은 계속 `false`다. B8b에는 실제 시즌 정의, 자동 정산 스케줄, 관리자 UI, 명예의 전당,
전광판·피드 알림, 칭호·표지 실물, 수치 조정, 기능 활성화와 배포가 포함되지 않는다.

## 검증

- 3,999/4,000, 7,999/8,000, 11,999/12,000, 15,999/16,000, 17,999/18,000점 경계
- 1~3위 전설 최소점, 1~10위 다이아 최소점, 11위 백금 보장
- 여섯 단계 동점 규칙과 사용자 ID 최종 정렬
- 관리자·제재·무명 계정 제외, 차단 후에도 공식 순위 숫자 유지
- 기능 차단 시 랭킹 DB 조기 반환
- 종료 전 정산 거부, 동시 정산 직렬화, 재실행 멱등, 중간 실패 전체 롤백
- 최종 순위·등급 고정과 낮은 점수 참가자의 순위 보존
- 닫히지 않은 시즌 트로피 발급 거부, 반복 발급 무변경, 불일치 결과 거부
- 월간 트로피 전시대·프로필·숙소 연결과 기존 영구 트로피 회귀
- 라이트·다크 불투명 표면과 잠정/확정 문구
- 실제 PostgreSQL 마이그레이션, 고유 순위, 동시 정산
- 전체 테스트, 타입 검사, 린트, 이미지 검사, 마이그레이션 검사와 운영 빌드
