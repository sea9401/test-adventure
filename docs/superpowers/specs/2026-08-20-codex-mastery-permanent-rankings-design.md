# 도감 숙련도 B5 영구 랭킹 설계

## 목표와 범위

B5는 이미 누적되는 `codex_mastery_summary`를 이용해 다음 영구 랭킹을 제공한다.

- 종합 숙련도
- 장비·어류·생태·미식·현장·직업 분야별 숙련도
- 각 랭킹의 상위 50명
- 로그인한 사용자의 순위와 앞뒤 2명

월간 연구, 명예의 전당, 트로피 대표 전시는 후속 묶음이다. B5는 기존 `rankingVisible` 운영
스위치가 `true`일 때만 API와 UI를 연다. 기본값은 계속 `false`이며 배포나 운영 설정 변경은
하지 않는다.

## 접근안 비교

### 1. 기존 `/api/rankings`에 숙련 지표 추가

기존 화면과 훅을 가장 적게 바꿀 수 있지만, 세이브 JSON을 전부 읽어 정렬하는 범용 랭킹 코드가
더 커진다. 종합/6개 분야/내 주변 목록처럼 응답 구조도 기존 한 줄 지표와 다르므로 제외한다.

### 2. 전 사용자 목록을 읽은 뒤 애플리케이션에서 정렬

구현은 단순하지만 사용자 수에 비례해 메모리와 전송량이 늘고, 정지·관리자·차단 사용자를 뺀 뒤
순위를 다시 계산하기도 어렵다. 큰 규모를 전제로 한 요구와 맞지 않아 제외한다.

### 3. 전용 API와 DB 순위 질의

`/api/rankings/codex-mastery?scope=...`를 두고, 닫힌 scope 목록으로만 점수 열과 도달 시각 열을
선택한다. DB의 `row_number()`가 공개 가능 사용자만 대상으로 동률 규칙을 적용한다. 상위 50명과
내 순위 ±2만 반환하므로 응답 크기는 일정하다. 기존 요약 테이블과 랭킹 인덱스를 그대로 활용할
수 있고 후속 월간 랭킹과도 경계가 분명해 이 방식을 채택한다.

## 서버 설계

공유 타입 모듈은 scope, 응답 행, 기능 비활성 응답을 정의한다. 서버 조회 모듈은 scope별 점수
열과 도달 시각 열을 정적 매핑하고 다음 조건을 SQL 안에서 처리한다.

- 선택한 점수가 0보다 큰 사용자만 포함
- 닉네임이 있는 사용자만 포함
- 현재 정지 중인 사용자와 관리자 이메일 제외
- 조회자가 차단한 사용자는 제외하되 조회자 본인은 유지

순서는 `점수 → 금 이상 항목 수 → 인장 수 → 점수 획득 분야 수 → 해당 점수 도달 시각 → user_id`
이다. 단계 카운트는 단계 승급 때 누적되므로 `gold_count`가 금 이상 달성 항목 수다. 마지막
`user_id`는 응답에서 노출하지 않고 내부의 본인 여부와 프로필 이동용 식별도 닉네임만 사용한다.

하나의 ranked CTE에서 상위 50명과 본인 ±2 범위를 골라 반환한다. API 계층은 인증과
`rankingVisible`을 먼저 확인해 기능이 닫혀 있으면 랭킹 테이블을 조회하지 않는다. 응답은 다음
형태다.

```text
{ ok: true, enabled: false }
{ ok: true, enabled: true, scope, list, nearby, me }
```

각 행은 순위, 닉네임, 아바타, 선택 점수, 종합/분야 점수, 금 이상 수, 단계별 수, 인장 수,
점수 획득 분야 수, 본인 여부와 현재 제공 가능한 프로필 꾸미기를 포함한다. 점수는 기존과 같은
밀리 단위 반올림 함수를 거쳐 표시 정수로 변환한다.

## UI 설계

기존 `도감` 탭 안에 `완성도 | 종합 숙련 | 분야별` 전환을 둔다. 완성도는 기존 API와 화면을
그대로 사용한다. 종합 숙련과 분야별을 골랐을 때만 전용 API를 지연 호출한다. 분야별은 여섯 분야
선택기를 한 단계 더 제공한다.

숙련 랭킹 화면은 다음을 보여 준다.

- 상위 50명 목록(10명씩 페이지)
- 내 순위가 있으면 항상 보이는 `내 주변 순위` 5행
- 선택 점수와 동률 판정에 쓰이는 금 이상·인장·분야 수
- 행 선택 시 기존 공개 프로필로 이동

로딩, 오류, 기능 비활성, 아직 점수가 없는 상태를 각각 구분한다. 모든 최상위 패널과 중첩 행은
`Card`, `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`의 불투명 표면을 사용하며 컨테이너
전체 opacity로 비활성 상태를 표현하지 않는다.

## 오류와 안전성

- 알 수 없는 scope는 400을 반환한다.
- 비로그인은 401을 반환한다.
- 기능 비활성은 정상 200 응답으로 다루며 조회를 생략한다.
- bigint, 날짜, 잘못된 프로필 아바타는 서버 경계에서 안전한 표시값으로 정규화한다.
- 같은 사람이 상위 목록과 주변 목록에 함께 있어도 두 영역의 목적이 달라 그대로 둔다.
- 개인 차단 때문에 사용자별로 보이는 순위가 달라질 수 있으며, 이는 기존 랭킹 가시성 정책과
  일치한다.

## 검증

순수 정렬/정규화 테스트와 서버 조회 테스트로 일곱 scope, 동률 순서, 제외 조건, 상위/주변 경계를
고정한다. 라우트 테스트는 인증·스위치·잘못된 scope·정상 응답을 확인한다. UI 테스트는 지연 호출,
분야 전환, 비활성/오류/빈 상태, 주변 순위와 프로필 이동을 확인한다. PostgreSQL 통합 테스트로 실제
윈도 함수와 제외 조건을 검증하고, 이후 타입 검사·집중 ESLint·빌드·전체 회귀를 실행한다.
