# 도감 숙련 시즌 운영(B9) 설계

## 위치와 범위

B9는 B8a의 월간 진행과 B8b의 랭킹·결산·트로피 엔진을 운영자가 안전하게 사용할 수 있게 한다.
실제 시즌 정의 등록, 결산, 트로피 발급은 이 코드가 배포된 뒤에도 운영자가 별도로 실행해야 한다.
이번 로컬 작업에서는 실제 시즌을 만들거나 기능 플래그를 켜거나 배포하지 않는다.

B9 다음에는 B10 하나만 남는다. B10은 종료 시즌 명예의 전당, 공개 아카이브, 알림과 출시 점검을
담는다.

## 목표

- 운영자가 월간 연구 정의 JSON을 서버의 권위 검증기로 미리 검사한다.
- 검증된 미래 월 정의를 정확한 확인 문구와 함께 한 번만 예약한다.
- 현재·예정·종료 시즌과 참가자, 최종 순위, 트로피 발급 수를 한 화면에서 관찰한다.
- 종료 시점 전에는 결산할 수 없고, `settlementEnabled`가 꺼져 있으면 결산·재결산을 실행하지 않는다.
- 결산과 트로피 발급을 분리해 비공개 시험 결과를 먼저 확인한다.
- 재결산은 트로피가 한 건도 발급되지 않은 종료 시즌에만 허용한다.
- 모든 변경은 super 관리자 권한, 입력 검증, 정확한 확인 문자열, 감사 로그를 거친다.

## 검토한 접근

### 범용 `/api/admin/season-ops`에 버튼만 추가

코드는 짧지만 큰 정의 입력, 검증 미리보기, 시즌별 관측, 재결산 금지 조건을 표현하기 어렵다. 기존
아레나·낚시 작업과 도감 월간 연구의 상태 기계가 다르므로 채택하지 않는다.

### 도감 전용 운영 서비스와 API를 만들고 기존 시즌 운영 탭에 섹션 추가

도메인 검증, DB 트랜잭션, HTTP 권한, UI를 분리할 수 있다. 쓰기 API는 작고 명시적인 작업 합집합을
사용하고, 읽기 API는 같은 서비스의 권위 요약을 보여준다. 이 방식을 채택한다.

### 자동 cron과 자동 정의 생성을 함께 추가

운영 편의는 높지만 공개 전 시험에서 자동 상태 변경이 발생하고, 잘못된 정의가 다음 달에 자동
활성화될 위험이 있다. B9에는 넣지 않는다.

## 운영 흐름

### 1. 정의 검증

운영자는 JSON 편집기에 `CodexResearchDefinitionSnapshot`을 입력한다. `validate` 작업은 DB를 쓰지
않고 다음을 반환한다.

- 시즌 ID와 KST 월 경계
- 테마 이름과 세 카테고리
- 목표 18개와 그룹별 6/6/4/2 개수
- 목표 12,000점, 다양성 5,000점, 기록 3,000점 예산
- 정의 버전

검증 실패는 서버 검증기의 구체적인 오류를 반환한다. 클라이언트 검증만으로 예약하지 않는다.

### 2. 예약

`schedule`은 super 권한과 `SCHEDULE {seasonId}` 확인 문자열을 요구한다. 시작 시각이 이미 지난 월은
예약할 수 없다. 동일 시즌 ID와 겹치는 월 창이 없어야 하며, 정의는 저장 직전에 다시 검증한다.
성공 시 `scheduled` 상태의 불변 스냅샷을 저장한다. 예약은 기능 플래그를 자동 변경하지 않는다.

### 3. 관측과 결산 미리보기

관리자 GET은 최근 24개 시즌을 반환한다. 각 시즌은 다음 수치를 가진다.

- 상태, KST 시작·종료, 정산 시각, 정의 버전
- 전체 진행 행 수와 점수가 있는 행 수
- 현재 저장된 최종 순위 행 수와 등급별 수
- 발급된 시즌 트로피 수
- `ready`, `too_early`, `closed`, `inconsistent` 중 운영 상태

`preview-settlement`은 현재 공식 적격 조건과 동점 규칙으로 후보를 읽되 아무것도 쓰지 않는다. 참가자
수, 등급별 예상 수, 상위 10명의 사용자 ID·점수·예상 등급을 반환한다. 공개 이름과 관리자·제재 제외는
B8b 결산과 같은 SQL을 재사용한다.

### 4. 확정 결산과 트로피 발급

`settle`은 `settlementEnabled`가 켜져 있고 `SETTLE {seasonId}` 확인 문자열이 일치할 때만 호출한다.
DB 트랜잭션 안에서 B8b `settleCodexResearchSeason`을 실행한다. 닫힌 시즌은 멱등 `already_closed`로
응답한다.

`award-trophies`는 `settlementEnabled`와 `trophiesEnabled`가 모두 켜져 있고
`AWARD {seasonId}`가 일치할 때만 실행한다. 닫힌 시즌의 확정 결과만 B8b 발급기로 전달한다. 반복
실행은 기존 행과 결과가 같을 때 `existing`으로 집계하며 다른 결과는 오류다.

### 5. 제한된 재결산

재결산은 운영 복구 수단이지 일반 버튼이 아니다. 다음 조건을 모두 만족해야 한다.

- 시즌이 `closed`다.
- 시즌 종료 시각이 지났다.
- 해당 시즌 트로피 이력이 0건이다.
- `settlementEnabled`가 켜져 있다.
- 확인 문자열이 `RESETTLE {seasonId}`와 정확히 일치한다.

서비스는 시즌 행을 잠그고 트로피 수를 다시 확인한 뒤 현재 적격 사용자와 동점 규칙으로 최종 결과를
전부 다시 쓴다. 같은 트랜잭션에서 새 `settledAt`으로 닫는다. 트로피가 발급된 뒤에는 과거 전시 기록을
자동 수정하지 않고 명시적으로 거부한다.

## API와 권한

`GET /api/admin/codex-research-seasons`는 `requireAdmin()`을 통과한 읽기 전용 요약이다.

`POST /api/admin/codex-research-seasons`는 모든 작업에서 `requireAdminRole("super")`를 요구한다.

- `{ op: "validate", definition }`
- `{ op: "schedule", definition, confirm }`
- `{ op: "preview-settlement", seasonId }`
- `{ op: "settle", seasonId, confirm }`
- `{ op: "resettle", seasonId, confirm }`
- `{ op: "award-trophies", seasonId, confirm }`

상속 속성, 알 수 없는 작업, 잘못된 시즌 ID, 확인 문자열 불일치는 DB 접근 전에 거부한다. 성공한
쓰기와 실패한 쓰기는 작업, 시즌 ID, 결과 요약을 관리자 감사 로그에 남긴다. 정의 전체나 사용자별
순위는 감사 로그에 넣지 않는다.

## 관리자 화면

기존 `SeasonOpsTab` 하단에 `CodexResearchSeasonOps`를 별도 컴포넌트로 둔다.

- 상태 새로고침과 최근 시즌 표
- JSON 정의 편집기, 서버 검증 버튼, 검증 요약
- 검증 성공 뒤에만 보이는 예약 확인 입력
- 시즌별 결산 미리보기
- `DangerAction`을 사용하는 결산·재결산·트로피 발급
- 보기 전용 모드에서는 모든 쓰기 버튼 비활성

카드와 표는 불투명 `bg-white`/`dark:bg-zinc-900` 또는 기존 관리자 표면을 사용한다. 상태 변경 중에는
같은 작업을 중복 시작하지 않는다.

## 관측과 오류 처리

- API 오류는 `invalid_json`, `unknown_op`, `invalid_definition`, `confirm_mismatch`,
  `feature_disabled`, `season_not_found`, `season_not_ready`, `trophies_already_published`처럼 안정된 코드를
  반환하고 운영자용 `message`를 함께 제공할 수 있다.
- 서버는 작업 실패를 콘솔에 시즌 ID와 작업명만 기록한다. 정의 전체와 사용자 ID 목록은 출력하지 않는다.
- 감사 로그 실패는 기존 정책대로 본 작업을 롤백하지 않는다.
- 상태 요약이 `closed`인데 최종 순위가 없거나 트로피 수가 최종 등급 수보다 많으면 `inconsistent`로
  표시한다.

## 비목표

- 자동 cron, 실제 시즌 예약, 플래그 활성화, 배포
- 트로피가 발급된 시즌의 순위 수정
- JSON 이외의 시각적 목표 빌더
- 경제 보상, SP, 전투 능력치, 아이템, 업적 점수
- 공개 명예의 전당과 사용자 알림(B10)

## 검증

- 정의 미리보기는 DB 쓰기 없이 정확한 예산과 월 경계를 반환한다.
- 과거 월, 중복·겹침 시즌, 잘못된 확인 문구를 거부한다.
- 관리자 읽기와 super 쓰기 권한을 분리한다.
- 기능 플래그가 꺼진 결산·발급은 엔진을 호출하지 않는다.
- 결산·발급 재실행이 멱등이다.
- 트로피 발급 전 재결산은 가능하고 발급 후에는 거부된다.
- 동시 재결산·발급은 시즌 행 잠금으로 직렬화된다.
- 감사 로그에는 작업과 요약만 기록된다.
- 관리자 UI는 보기 전용 모드와 정확한 확인 문구를 유지한다.
- PostgreSQL 통합, 전체 테스트, 타입, 린트, 마이그레이션, 이미지와 빌드를 통과한다.
