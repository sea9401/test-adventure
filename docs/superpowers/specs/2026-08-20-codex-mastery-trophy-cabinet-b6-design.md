# 도감 숙련 트로피 전시대 B6 설계

## 목표

도감 숙련의 여섯 분야와 종합 진행을 기존 트로피 전시대 및 공개 프로필 대표 슬롯에 연결한다.
기존 동·은·금·전설 트로피 표현은 동·은·금·백금·다이아·전설의 여섯 등급을 지원하도록
확장한다. 트로피는 수집·전시 목표일 뿐이며 SP, 전투력, 골드, 아이템을 지급하지 않는다.

이번 묶음은 전체 도감 숙련 로드맵의 8단계다. 숙소 전시는 다음 9단계에 남겨 두며, 월간
연구전 트로피도 이후 단계에서 같은 저장소와 전시 모델을 재사용한다.

## 현재 구조와 제약

- 기존 업적 트로피는 `V2_QUESTS`와 가이드 퀘스트의 `claimed`에서 즉시 산출한다.
- 대표 3칸은 `profile-showcase.v1`에 장비·칭호·업적 선택을 저장한다.
- 도감 상세 진행과 랭킹 요약은 전용 PostgreSQL 테이블을 사용한다.
- `trophiesEnabled` 운영 스위치는 이미 존재하며 기본값은 `false`다.
- 도감 카탈로그가 늘어나도 이미 획득한 분야·종합 트로피는 회수하면 안 된다.
- Phase A 및 B1~B6는 현재 기능 브랜치에만 남기고 배포·기능 활성화·실데이터 반영은 하지 않는다.

## 검토한 접근

### 1. 요청 때마다 현재 진행에서 전부 재계산

구현은 가장 작지만 신규 도감 항목이 추가되면 과거 트로피가 다시 잠길 수 있다. 정확한 승급일과
연혁도 보존할 수 없어 채택하지 않는다.

### 2. 기존 세이브 JSON에 도감 트로피 저장

대표 슬롯과 형태는 비슷하지만 상세 숙련 기록과 트로피 갱신이 서로 다른 저장 단위가 되어 원자성이
깨진다. 사용자당 큰 JSON을 계속 잠그게 되고 월간 트로피 확장에도 불리해 채택하지 않는다.

### 3. 전용 트로피 연혁 + 현재 진행으로 다음 목표 계산

`codex_trophy_history`에 획득한 최고 등급과 등급별 획득 시각을 영구 저장한다. 현재 진행은 잠긴
다음 등급의 조건과 진척률을 계산하는 데만 쓴다. 신규 항목이 생겨도 저장된 획득 기록은 내려가지
않으며, 기존 중앙 기록 트랜잭션 안에서 진행·요약·트로피를 함께 갱신할 수 있다. 이 방식을 채택한다.

## 트로피 정의

안정적인 가족 ID는 다음과 같다.

| ID | 종류 | 이름 |
|---|---|---|
| `mastery:equipment` | 분야 | 무구의 기록자 |
| `mastery:fish` | 분야 | 만경의 어탁 |
| `mastery:monster` | 분야 | 대륙 생태 표본 |
| `mastery:cooking` | 분야 | 왕실의 조리도구 |
| `mastery:life` | 분야 | 대지의 관찰일지 |
| `mastery:job` | 분야 | 천직의 문장 |
| `mastery:overall` | 종합 | 모험왕의 대서 |

등급 순서는 `bronze`, `silver`, `gold`, `platinum`, `diamond`, `legendary`다.

분야별 조건은 현재 카탈로그의 해당 분야 항목 수를 분모로 삼는다.

- 동: `ceil(전체 × 25%)`개가 동 이상
- 은: `ceil(전체 × 50%)`개가 은 이상
- 금: 전체 항목이 금 이상
- 백금: 금 트로피 보유 및 `ceil(전체 × 25%)`개가 백금 이상
- 다이아: 금 트로피 보유 및 `ceil(전체 × 50%)`개가 다이아 이상
- 전설: 전체 항목이 전설

종합 트로피는 여섯 분야가 모두 해당 등급 이상일 때 승급한다. 한 번 획득한 단계는 조건이 나중에
달라져도 회수하지 않는다. 한 번의 기록이나 백필로 여러 단계를 넘으면 중간 단계도 모두 같은 처리
안에서 기록한다.

## 획득 시각

온라인 승급은 게임 행동의 `now`를 사용한다. 기존 진행을 재구성할 때는 항목별 `tierAchievedAt`을
사용해 조건을 처음 만족한 시각을 결정한다.

- 비율 조건: 필요한 개수만큼의 단계 도달 시각을 오름차순 정렬한 뒤 마지막 시각
- 전체 조건: 모든 항목의 해당 단계 도달 시각 중 가장 늦은 시각
- 백금·다이아: 금 획득 시각과 비율 조건 시각 중 더 늦은 시각
- 종합: 여섯 분야의 해당 등급 획득 시각 중 가장 늦은 시각

불완전한 레거시 데이터로 시각을 결정할 수 없지만 현재 조건은 만족한다면 재구성 실행 시각을
사용한다. 저장된 과거 시각은 이후 재계산으로 덮어쓰지 않는다.

## 데이터 모델

`codex_trophy_history`는 사용자와 트로피 가족 ID를 복합 기본키로 사용한다.

```text
user_id
trophy_id
trophy_kind        // mastery_category | mastery_overall, 이후 monthly 확장
current_tier
tier_achieved_at   // 등급별 ISO 시각 JSON
catalog_version
season_metadata    // 이후 월간 트로피용 nullable JSON
updated_at
```

쓰기 규칙은 단조 증가다. 현재 등급은 낮아질 수 없고, 이미 저장된 등급별 시각은 유지한다.
카탈로그 버전은 마지막 평가 기준을 기록해 운영자가 재구성 범위를 판단할 수 있게 한다.

## 평가와 트랜잭션

순수 평가기는 카탈로그, 전체 사용자 진행 행, 기존 트로피 연혁을 받아 다음 상태와 신규 승급 목록을
만든다. PostgreSQL 저장소는 사용자 트로피 행을 잠근 뒤 평가 결과를 upsert한다.

중앙 기록 서비스는 진행과 요약 저장 뒤 같은 트랜잭션에서 트로피를 재평가한다. 단,
`trophiesEnabled=false`이면 트로피 조회·평가·쓰기를 모두 건너뛴다. 기록 자체와 랭킹은 기존 운영
스위치에 따라 그대로 동작한다. 트로피 쓰기에 실패하면 같은 게임 행동 트랜잭션도 실패하여 진행과
트로피가 갈라지지 않는다.

과거 사용자용 재구성 작업은 별도 건식 실행/반영 CLI를 제공한다. 상세 진행을 권위 데이터로 삼고,
기존 트로피보다 낮은 결과를 절대 쓰지 않으며 재실행해도 중복 기록하지 않는다. 운영 기능 스위치를
자동으로 켜지 않는다.

## API와 대표 전시

프로필 선택 모델에 다음 안정 식별자를 추가한다.

```ts
{ kind: "masteryTrophy"; trophyId: string }
```

`GET /api/v2/me/profile-showcase`는 트로피 기능이 켜졌을 때 업적과 도감 숙련 트로피를 한 옵션 목록으로
반환한다. 도감 트로피는 가족당 카드 하나를 반환하고, 획득했으면 최고 등급, 잠겼으면 다음 등급과
현재/필요 수치를 제공한다. 이미 대표로 고른 도감 트로피는 기능 정의를 일시적으로 읽지 못해도
선택값 자체를 삭제하지 않는다.

`POST`는 대표 배지 전시대 보유 여부, 알려진 안정 ID, 실제 획득 연혁을 모두 확인한다. 같은 트로피를
여러 슬롯에 중복 지정할 수 없다. `trophiesEnabled=false`에서는 새 도감 트로피 선택을 받지 않지만
기존 저장값을 삭제하지 않는다.

## 전시대 UI

기존 업적과 도감 숙련 트로피를 한 그리드에 표시하고 다음 기능을 제공한다.

- 종류: 전체·업적·도감 숙련
- 분야: 여섯 분야·종합
- 등급: 동·은·금·백금·다이아·전설
- 획득: 전체·획득·미획득
- 텍스트 검색
- 잠긴 카드의 다음 조건과 진행도
- 획득한 트로피의 등급별 승급 연혁

백금은 청백색, 다이아는 청록색 결정 계열, 전설은 보라색 계열로 표현한다. 전설 광채는
`motion-safe`에서만 사용하고 움직임 줄이기에서는 정적 테두리만 남긴다. 카드와 상세 패널은
`SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`를 사용하며 잠긴 카드 전체에 opacity를 적용하지
않는다. 모바일에서는 필터가 줄바꿈되고 카드가 2열부터 시작한다.

## 호환성과 실패 처리

- 기존 `achievement` 선택과 레거시 단일 `selection` 파싱을 유지한다.
- 기존 업적 데이터의 등급은 바꾸지 않고 타입과 표현만 여섯 등급을 허용한다.
- 트로피 옵션 조회 실패는 기존 업적 전시까지 망가뜨리지 않도록 API 경계에서 명시적인 오류로
  처리하되, DB 오류를 획득 없음으로 위장하지 않는다.
- 보유 검증에 실패하면 저장하지 않고 `not_owned`를 반환한다.
- 트로피 기능이 꺼진 상태에서는 기존 전시대 동작이 B5 이전과 같아야 한다.

## 검증

- 순수 평가: 모든 단계 경계, 다단 승급, 승급일, 신규 카탈로그 추가 후 강등 없음
- 저장소: 행 잠금, upsert, 과거 시각 보존, 재실행 안전성
- 중앙 기록: 기능 스위치 off 시 무접근, on 시 동일 트랜잭션 승급, 실패 전파
- 재구성 CLI: dry-run 무쓰기, apply, 재실행, 진행만 있는 사용자 열거
- API: 기능 차단, 옵션 병합, 보유 검증, 중복 선택, 레거시 선택 보존
- UI: 백금·다이아·전설, 검색·필터·잠금 진행·연혁, 불투명 표면, reduced motion
- PostgreSQL 통합: 실제 마이그레이션 위에서 진행 갱신과 트로피 승급 원자성
- 전체 테스트, TypeScript, 집중 ESLint, 이미지 검사, 프로덕션 빌드

## 비범위

- 월간 연구전 트로피 생성과 정산

- 운영 기능 활성화, 실데이터 재구성, 배포
