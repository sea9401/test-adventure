# 도감 숙련 B4 모험의 서 UI 설계

상태: 기존 도감 숙련 엔드게임 설계의 승인된 구현 6단계
작성일: 2026-08-20
기반: `docs/superpowers/specs/2026-08-20-codex-mastery-endgame-design.md`

## 1. 목표와 범위

B4는 모험의 서에 `숙련` 탭을 추가하고, 서버 권위의 영구 숙련 진행을 큰 카탈로그에서도 빠르게
탐색할 수 있는 개요·분야별 목록·항목 상세 화면으로 연결한다.

- 종합 점수, 여섯 분야 점수, 발견 수와 금·백금·다이아·전설 보유 수를 표시한다.
- 최근 승급, 다음 승급에 가까운 목표, 사용자가 고정한 목표 최대 5개를 표시한다.
- 분야, 검색어, 진행 상태와 고정 목표로 필터링하고 30개씩 페이지를 나눈다.
- 항목 상세에서 단계별 기준과 달성일, 다음 목표 진행도, 누적 횟수와 개인 최고 기록을 표시한다.
- 특별 인장은 해당 운영 스위치가 켜진 경우에만 표시한다.
- 랭킹, 트로피, 월간 연구전은 다음 구현 단계의 실제 데이터가 준비될 때까지 값을 꾸며 내지 않는다.
- 기존 SP, 완성도, 보상, 게임플레이 기록 의미는 바꾸지 않는다.
- 구현 완료만으로 배포하거나 기능 스위치를 켜지 않는다.

## 2. 접근안 비교와 선택

### 선택안: 탭 진입 시 전체 읽기 스냅샷 + 클라이언트 페이지네이션

숙련 탭을 처음 열 때 `/api/v2/me/codex-mastery`에서 679개 카탈로그 정의와 해당 사용자의 진행을 한 번
읽는다. 서버는 저장된 진행을 정적 카탈로그에 결합해 표시 전용 DTO를 만들고, 클라이언트는 검색·필터와
30개 단위 페이지네이션을 처리한다.

현재 항목 수는 장비 351, 어보 50, 몬스터 70, 요리 45, 현장 기록 36, 직업 127개다. 이 규모에서는
한 번의 지연 로드가 충분히 작고, 필터를 바꿀 때마다 서버를 왕복하지 않아 조작 반응이 빠르다. 화면에
만드는 DOM은 현재 페이지만으로 제한한다. 향후 카탈로그가 수천 개를 넘으면 DTO를 유지한 채 서버
페이지네이션으로 교체할 수 있다.

### 제외안: 기존 `/api/v2/me/state` 응답에 포함

모험의 서를 열 때마다 사용 여부와 관계없이 큰 카탈로그를 내려 보내고 기존 핵심 상태 응답을 비대하게
만든다. 숙련 탭의 독립 공개와 실패 격리도 어렵다.

### 제외안: 필터 변경마다 서버 페이지 조회

초기 응답은 작지만 분야·필터·검색 조작마다 데이터베이스와 네트워크 왕복이 생긴다. 저장된 진행 행은
사용자당 최대 679개라서 지금은 복잡성과 체감 지연에 비해 이득이 작다.

## 3. 공개 차단과 API

기존 운영 설정에 `overviewVisible`을 추가하며 기본값은 `false`다. 이 스위치는 기록 중단과 화면 공개를
분리한다. 기록을 잠시 멈춰도 이미 쌓인 진행은 계속 볼 수 있고, 백필과 점검이 끝나기 전에는 기록이
켜져 있어도 화면을 숨길 수 있다.

`GET /api/v2/me/codex-mastery`는 다음 순서로 동작한다.

1. 로그인 사용자를 확인한다.
2. 운영 설정을 읽는다.
3. `overviewVisible = false`이면 진행 테이블이나 고정 목표를 읽지 않고 `{ ok: true, enabled: false }`를
   반환한다.
4. 공개 상태이면 요약, 사용자 진행 행, 고정 목표를 읽어 하나의 스냅샷을 반환한다.

응답에는 공개된 기능 능력도 함께 넣는다. `rankingVisible`, `trophiesEnabled`,
`monthlyProgressEnabled`, `sealsEnabled`가 꺼져 있으면 해당 섹션은 숨기거나 준비 상태로만 표시한다.
랭킹·트로피·월간 수치에는 임시 순위나 추정치를 넣지 않는다.

GET은 사용자별 권위 데이터이므로 캐시하지 않는다. 읽기 과정은 행을 만들거나 복구하지 않는다. 요약
불일치는 기존 복구 도구의 책임으로 유지해 화면 조회가 예기치 않은 쓰기를 만들지 않게 한다.

## 4. 표시 스냅샷

서버는 `codex_mastery_summary`의 점수와 단계 수를 권위 값으로 사용하고, 진행 행을 카탈로그에 결합한다.
저장 행이 없는 항목도 `none`, 횟수 0의 항목으로 포함한다. 카탈로그에서 제거된 레거시 행은 점수를
회수하지 않지만 현재 탐색 목록에는 섞지 않는다.

각 항목 DTO는 다음 정보를 가진다.

- 분야, 안정적인 항목 ID, 표시 이름
- 누적 횟수, 개인 최고 기록, 현재 단계, 항목 점수
- 동부터 전설까지의 기준과 단계별 달성 시각
- 다음 단계와 기준, 현재 진행률
- 획득한 특별 인장 ID
- 고정 목표 여부

분야 요약은 분야 점수, 전체 항목 수, 발견 항목 수와 금 이상 수를 제공한다. 최근 승급은 모든 단계
달성 시각을 펼쳐 최신 5건을 고른다. 근접 목표는 전설 미만이며 이미 시작한 항목 중 다음 기준 진행률이
높은 순서로 최대 5건을 고른다. 발견만 소급되어 횟수가 0인 항목은 목록에는 보이지만 근접 목표를
가득 채우지 않는다.

표시 점수는 기존 `displayCodexMasteryScore`를 사용한다. 내부 milli 점수와 원본 타임스탬프는 클라이언트가
점수를 재계산하지 않도록 서버에서 표시 DTO로 변환한다.

## 5. 고정 연구 목표

고정 목표는 대용량 진행 데이터가 아니라 작은 사용자 선호이므로 `savesKv`의
`codex-mastery-pins.v1` 키에 `{ entries: [{ category, entryId }] }`로 저장한다.

`POST /api/v2/me/codex-mastery`는 전체 고정 목록을 받는다.

- 배열이 아니거나 5개를 넘으면 거부한다.
- 분야와 항목 ID가 현재 카탈로그에 존재해야 한다.
- 중복 항목은 거부한다.
- 트랜잭션 안에서 저장 행을 잠근 뒤 한 번에 갱신한다.
- 화면 공개 스위치가 꺼져 있으면 쓰지 않는다.

읽을 때는 과거의 잘못된 값이나 제거된 항목을 안전하게 제외하고 최대 5개까지만 사용한다. 클라이언트는
낙관적으로 바꾸지 않고 POST 성공 응답의 정규화된 목록을 적용해 서버 상태와 어긋나지 않게 한다.

## 6. 화면 구성

현재 탭 순서는 다음처럼 확장한다.

```text
SP 수집 | 숙련 | 직업 | 장비 | 사냥터 | 어보 | 요리 | 현장 기록 | 칭호
```

숙련 탭은 다음 순서로 구성한다.

1. 종합 점수와 발견 항목 수, 금·백금·다이아·전설 수
2. 여섯 분야 점수·발견 진행 카드
3. 고정 목표, 최근 승급, 다음 승급 근접 목표
4. 분야·검색·상태 필터
5. 30개 단위 항목 목록과 페이지 이동
6. 선택 항목의 단계 연혁과 개인 기록 상세

진행 필터는 `전체`, `미발견`, `승급 임박`, `금 미만`, `백금 이상`, `고정 목표`를 제공한다.
`특별 인장 미획득`은 인장 기능이 공개된 경우에만 추가한다. 검색은 항목 이름과 안정 ID에 적용한다.
필터나 분야가 바뀌면 첫 페이지로 돌아간다.

랭킹·트로피·월간 연구전 스위치가 꺼진 상태에서는 종합 개요 아래에 “후속 연구 기능 준비 중”이라는
짧은 안내만 제공한다. 실제 기능이 켜졌지만 B4 응답에 데이터가 없는 상태도 숫자 0으로 오해시키지
않는다.

## 7. 상태와 오류 처리

- 최초 진입: 불투명 카드에 로딩 상태를 표시한다.
- 공개 전: 준비 중 안내를 표시하고 재요청 버튼을 만들지 않는다.
- 네트워크·서버 오류: 오류 안내와 다시 불러오기 버튼을 표시한다.
- 빈 필터 결과: 현재 조건을 완화하라는 안내를 표시한다.
- 고정 목표 저장 실패: 기존 서버 목록을 유지하고 화면 안에 실패 안내를 표시한다.
- 컴포넌트가 언마운트되면 늦게 도착한 응답으로 상태를 갱신하지 않는다.

## 8. 표면과 접근성

최상위 영역은 `SURFACE_INSET`, 주요 요약은 `SURFACE_ACCENT`, 카드와 목록 행은 `SURFACE_CARD` 또는
`SURFACE_INSET`을 사용한다. 직접 만든 반투명 콘텐츠 배경이나 카드 전체 `opacity-*`는 사용하지 않는다.
라이트·다크 모드에서 모든 본문 뒤에 불투명 표면이 남는다.

탭·필터·페이지·고정·상세 버튼은 실제 `button` 요소와 선택 상태를 사용한다. 검색 입력에는 레이블을,
진행 막대에는 텍스트 수치와 접근성 레이블을 함께 제공한다. 색만으로 단계를 구분하지 않고 단계 이름을
항상 표시한다.

## 9. 검증 기준

- 공개 스위치가 꺼지면 API가 진행을 읽지 않고 UI가 준비 상태를 표시한다.
- 요약과 679개 카탈로그가 누락·레거시 진행을 안전하게 처리하며 점수를 클라이언트에서 재계산하지 않는다.
- 최근 승급과 근접 목표의 정렬이 결정적이며 달성일과 다음 기준이 정확하다.
- 고정 목표는 서버에서 최대 5개·중복 없음·현재 카탈로그 항목만 허용한다.
- `숙련` 탭은 URL로 직접 열리고 최초 진입 때만 스냅샷을 읽는다.
- 검색·분야·진행·고정 필터와 페이지네이션이 긴 목록의 DOM을 제한한다.
- 상세 화면이 단계별 목표·달성일·다음 진행·개인 기록을 표시한다.
- 랭킹·트로피·월간 연구전은 실제 데이터가 없을 때 가짜 값을 표시하지 않는다.
- 모든 콘텐츠 표면이 공용 불투명 토큰을 사용한다.
- 집중 테스트, TypeScript, ESLint, 예산 검사와 프로덕션 빌드가 통과한다.
- 기능 스위치는 모두 꺼져 있고 현재 배포 브랜치는 바뀌지 않으며 배포하지 않는다.
