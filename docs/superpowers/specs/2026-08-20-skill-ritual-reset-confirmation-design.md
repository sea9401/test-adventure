# 스킬 강화 초기화 확인창 설계

## 목표

강화 의식 상세 화면의 `초기화` 버튼을 한 번 잘못 눌렀을 때 즉시 초기화되는 문제를 막는다. 실제 초기화 요청 전에 대상 스킬, 현재 강화 상태와 환급량을 다시 확인할 수 있는 전용 확인창을 제공한다.

## 화면과 동작

- 기존 `초기화` 버튼을 누르면 API를 호출하지 않고 확인창만 연다.
- 확인창에는 대상 스킬명, 현재 의식 종류와 단계, 환급 골드와 숙달 포인트를 표시한다.
- 누적 비용의 50%만 환급되고 현재 강화 효과가 사라지며 되돌릴 수 없다는 경고를 표시한다.
- `취소`, 바깥 영역 클릭, Esc는 확인창만 닫고 초기화를 실행하지 않는다.
- `강화 초기화 확정`을 눌렀을 때만 기존 초기화 함수를 호출한다.
- 초기화 요청 중에는 닫기와 중복 확정을 비활성화하고 버튼 문구를 `초기화 중…`으로 바꾼다.

## 구성

- `SkillRitualResetAction`이 확인창의 열림 상태를 소유하고 기존 초기화 버튼과 확인창을 연결한다.
- `SkillRitualResetConfirmDialog`가 경고와 환급 정보를 표시하고 취소·확정 입력을 전달한다.
- `V2SkillLearnView`의 기존 `resetRitual` API 호출과 성공·오류 처리, 환급 계산은 변경하지 않는다.

## 접근성과 표면

- 확인창은 제목과 설명이 연결된 `role="dialog"`, `aria-modal="true"`를 제공한다.
- 기존 `useModalA11y`와 `useEscapeKey`로 포커스 고정, 스크롤 잠금, Esc 닫기를 처리한다.
- 확인창과 정보 영역은 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`를 사용해 라이트·다크 모드에서 불투명하게 유지한다.
- 모바일에서는 하단 시트, 넓은 화면에서는 중앙 대화상자로 표시하고 하단 안전 영역을 반영한다.

## 검증

- 첫 `초기화` 클릭은 확인창만 열고 초기화 콜백을 호출하지 않는지 검증한다.
- 취소 뒤에도 초기화 콜백이 호출되지 않는지 검증한다.
- `강화 초기화 확정`을 누른 경우에만 초기화 콜백이 정확히 한 번 호출되는지 검증한다.
- 확인창에 대상, 현재 단계, 환급량과 손실 경고가 모두 표시되는지 검증한다.
