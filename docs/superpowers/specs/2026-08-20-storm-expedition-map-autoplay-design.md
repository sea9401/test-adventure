# 폭풍 원정 지도 통합과 일괄 진행 설계

## 배경

현재 진행 중인 폭풍 원정 화면은 현재 체크포인트 행동, 항로 지도, 선택 노드 미리보기와 이동 확인, 임시 전리품 가방을 서로 다른 카드에 배치한다. 모바일에서는 행동 카드에서 지도로 내려가 노드를 고른 뒤 지도 아래의 이동 버튼까지 다시 내려가야 한다. PC에서도 지도와 이동 확인은 왼쪽, 전투와 체크포인트 선택은 오른쪽에 있어 매 단계마다 시선과 포인터가 왕복한다.

원정은 매일 반복하는 콘텐츠다. 설명을 모두 읽는다는 전제보다 지금 해야 할 행동을 지도에서 바로 찾고 실행할 수 있어야 한다. 반복 플레이에서는 체크포인트마다 같은 확인과 선택을 되풀이하지 않고, 출발 전에 정한 경로와 운영 방침으로 완주 또는 패배까지 이어갈 수 있어야 한다.

## 목표

- 항로 지도를 원정 진행의 유일한 주 조작 표면으로 만든다.
- 전투, 정비, 축복과 이동 확인을 해당 지도 노드의 모달에서 처리한다.
- 모바일에서 현재 행동부터 다음 이동까지 한 화면 범위 안에서 찾을 수 있게 한다.
- PC에서도 지도와 행동 버튼 사이의 좌우 왕복을 없앤다.
- 출발 전에 세 구간의 경로를 정하고 완주 또는 패배까지 일괄 진행할 수 있게 한다.
- 자동 진행 중에도 기존 API로 각 단계 결과를 서버에 저장해 중단과 오류에 안전하게 한다.
- 원정의 보상, 패배, 귀환과 입장 횟수 규칙은 유지한다.

## 비목표

- 전투 계산, 몬스터 수치, 드롭률과 보상 목록을 변경하지 않는다.
- 원정 전용 물약이나 새 소비 아이템을 추가하지 않는다.
- 자동 진행에 패배 방지, 자동 귀환 또는 전리품 보호를 제공하지 않는다.
- 위험 이벤트를 자동 수락하는 고위험 설정을 추가하지 않는다.
- 원정 전체를 한 서버 요청이나 긴 데이터베이스 트랜잭션으로 처리하지 않는다.
- 데이터베이스 마이그레이션이나 새 서버 저장 필드를 추가하지 않는다.
- 기존 연습 모드를 제거하거나 보상 없는 연습 규칙을 바꾸지 않는다.

## 화면 구조

### 진행 중 원정

진행 중 원정의 주 영역은 항로 지도 카드 하나다.

- 지도 상단에 현재 HP, MP, 완료 체크포인트 수와 자동 진행 상태를 한 줄로 표시한다.
- 현재 노드는 다른 노드보다 강하게 강조하고 `전투 필요`, `선택 필요`, `완료`, `자동 진행 중` 상태를 색상과 문구로 함께 표시한다.
- 현재 노드를 누르면 현재 노드 모달을 연다.
- 이동 가능한 다음 노드를 누르면 이동 확인 모달을 연다.
- 완료한 노드를 누르면 선택 결과와 전투 결과 요약만 보여준다.
- 잠긴 노드는 비활성화하지 않고 정보 모달은 열 수 있게 하되 진행 버튼은 제공하지 않는다.
- 현재 체크포인트 카드, 선택 노드 미리보기 카드와 지도 밖의 이동 확인 버튼은 제거한다.

축복 목록, 적용 중인 위험 효과, 임시 전리품 가방과 귀환 버튼은 지도 아래 보조 영역에 둔다. 이 정보는 게임 진행 버튼과 섞지 않는다. 모바일에서는 접을 수 있으며 기본 상태에서는 전리품 총량과 위험 여부만 요약한다.

### 반응형 지도

PC는 현재의 넓은 항로 관계를 보존하되 모든 진행 행동을 노드 모달로 옮긴다. 별도 오른쪽 행동 열은 없앤다.

모바일은 전체 PC 지도를 축소하지 않는다.

- 출발 전에는 외곽, 중층, 수호자 세 구간의 항로 선택을 같은 지도 카드 안에 세 행으로 표시한다.
- 각 행은 칼바람, 뇌운, 잔해 중 하나를 선택하는 분기 노드다.
- 보급, 야영지, 정예, 제단, 최종 정비와 폭풍의 심장 같은 공통 체크포인트는 선택 행 사이의 고정 노드로 축약해 표시한다.
- 진행 중에는 완료 구간을 짧은 경로 요약으로 접고, 현재 노드와 바로 다음 후보를 가장 크게 표시한다.
- 사전에 예약한 이후 항로는 지도 안의 작은 경로 요약으로 계속 노출한다.

모바일과 PC는 배치만 다르고 같은 노드 상태, 모달과 행동 규칙을 사용한다.

## 노드 모달

### 열리는 시점

- 수동 진행에서 노드를 누르면 해당 모달을 연다.
- 원정 시작 또는 이동 성공 직후에는 도착한 현재 노드 모달을 자동으로 연다.
- 페이지 새로고침이나 재진입만으로 모달을 강제로 열지는 않는다. 현재 노드를 누르면 다시 진행할 수 있다.
- 자동 진행 중에는 체크포인트 모달을 열지 않고 지도 상태만 갱신한다.

### 종류별 내용

- 전투 노드: 적 종류, 남은 연전 수, 예상 보상과 `전투 시작` 버튼
- 보급·야영·최종 정비: 현재 HP·MP와 선택지, 선택 확정 버튼
- 제단: 이번에 제시된 축복만 표시하고 하나를 선택
- 위험 이벤트: 이익과 대가, 수락과 지나치기 버튼
- 다음 경로: 노드 이름, 위협과 설명, `이 경로로 이동` 버튼
- 완료 노드: 전투 또는 선택 결과 요약, 진행 버튼 없음
- 잠긴 노드: 설명과 잠금 사유, 진행 버튼 없음

모든 모달은 닫을 수 있다. 서버 요청 중에는 닫기와 중복 행동을 잠근다.

## 진행 방식

### 직접 진행

직접 진행은 지도에서 노드를 하나씩 선택하고 각 모달에서 전투와 체크포인트 선택을 확정한다. 기존 상세 전투 리플레이 선택은 직접 진행에 보존한다.

### 일괄 진행 설정

출발 전 지도 카드에 `직접 진행`과 `일괄 진행`을 함께 제공한다. 일괄 진행 설정 모달에서 다음 항목을 정한다.

1. 모드: 실전 또는 연습
2. 외곽 항로: 칼바람, 뇌운, 잔해
3. 중층 항로: 칼바람, 뇌운, 잔해
4. 수호자 항로: 칼바람, 뇌운, 잔해
5. 축복 전략: 공격 우선, 생존 우선, 자원 우선

세 항로는 서로 달라도 된다. 기존에 보급과 제단에서 다른 항로로 갈아탈 수 있는 자유도를 보존한다. 시작 버튼 위에는 `패배하면 임시 전리품을 모두 잃으며 자동 귀환하지 않습니다`를 명시한다.

### 축복 우선순위

제시된 축복 중 전략 순서에서 가장 앞선 축복을 선택한다. 이미 보유했거나 제시되지 않은 축복은 건너뛴다.

- 공격 우선: 폭풍의 완력 → 질풍의 운명 → 폭풍의 가호 → 승리의 숨결 → 깊은 마나
- 생존 우선: 승리의 숨결 → 폭풍의 가호 → 질풍의 운명 → 폭풍의 완력 → 깊은 마나
- 자원 우선: 깊은 마나 → 승리의 숨결 → 폭풍의 가호 → 폭풍의 완력 → 질풍의 운명

### 정비 자동 선택

HP와 MP 비율은 선택 직전의 최신 서버 상태를 사용한다.

보급품:

- HP가 85% 이하이고 MP가 80% 이하라면 현재 비율이 더 낮은 자원을 회복한다.
- HP만 85% 이하면 응급 식량을 선택한다.
- MP만 80% 이하면 마력 앰풀을 선택한다.
- 둘 다 임계보다 높으면 폭풍 연마유를 선택한다.
- 자동 진행은 떠밀려온 금고를 선택하지 않는다. 생존과 완주를 골드보다 우선한다.

야영지:

- 깊은 휴식, 마력 명상과 균형 정비 각각의 실제 유효 회복량을 계산한다.
- 유효 회복량은 `min(현재 결손 비율, 선택지 회복 비율)`의 HP와 MP 합이다.
- 합이 가장 큰 선택을 사용한다.
- 동률이면 현재 비율이 더 낮은 자원을 더 많이 회복하는 선택을 우선하고, 다시 동률이면 균형 정비를 선택한다.

최종 정비:

- HP가 75% 이하이고 MP가 65% 이하라면 현재 비율이 더 낮은 자원을 회복한다.
- HP만 75% 이하면 갑주 수리를 선택한다.
- MP만 65% 이하면 마력 집중을 선택한다.
- 둘 다 임계보다 높으면 심장 파쇄 준비를 선택한다.

### 위험 이벤트

일괄 진행은 모든 위험 이벤트를 자동으로 지나친다. 별도의 항상 수락 또는 이벤트별 수락 설정은 이번 범위에 포함하지 않는다.

## 자동 진행 상태 전이

자동 진행은 기존 `start`, `move`, `fight`, `choose`, `risk_event` 요청을 한 번씩 순서대로 호출하는 클라이언트 조정기로 구현한다.

1. 선택한 외곽 노드로 원정을 시작한다.
2. 현재 노드가 전투라면 완료될 때까지 `fight`를 반복한다.
3. 현재 노드가 정비라면 최신 HP·MP로 선택 정책을 계산하고 `choose`를 보낸다.
4. 위험 이벤트가 제시됐다면 `risk_event: decline`을 먼저 보낸다.
5. 체크포인트가 완료되면 계획에 맞는 다음 노드로 `move`한다.
6. 완주, 패배, 사용자 중단 또는 오류까지 반복한다.

각 요청은 기존 `expectedCurrentNodeId`와 `expectedEncounterIndex`를 사용한다. 응답을 받을 때마다 화면 상태를 갱신하고 서버가 저장한 최신 상태를 다음 요청 기준으로 사용한다.

자동 진행 중 지도에는 현재 처리 중인 노드, 완료 단계와 `자동 진행 중단` 버튼을 표시한다. 중단은 이미 서버에 도착한 요청을 취소하지 않는다. 현재 요청이 끝난 뒤 다음 요청을 보내지 않고 직접 진행 상태로 전환한다.

완주 또는 패배하면 체크포인트 모달 대신 결과 요약 모달을 연다. 완주 시 확정 보상, 패배 시 잃은 임시 전리품과 도달 지점을 표시한다.

## 자동 계획 보존과 재개

자동 경로와 축복 전략은 버전이 붙은 브라우저 로컬 저장소에 보존한다. 서버 원정 상태나 데이터베이스 형식은 변경하지 않는다.

- 자동 진행 중 화면을 닫거나 새로고침하면 서버에는 마지막 성공 단계가 남는다.
- 재진입 시 활성 원정과 남은 계획이 양립하면 `일괄 진행 재개`와 `직접 진행`을 표시한다.
- 자동으로 재시작하지 않으며 사용자가 재개를 눌러야 다음 요청을 보낸다.
- 저장된 계획의 노드가 현재 활성 원정의 방문 이력과 충돌하면 재개를 제공하지 않고 계획을 폐기한다.
- 완주, 패배 또는 귀환 시 현재 실행 계획을 제거한다.
- 축복 전략과 마지막으로 선택한 세 항로는 실행 계획과 분리해 다음 원정의 기본값으로 보존한다.

로컬 설정은 계정 권한이나 보상을 바꾸지 않는다. 다른 계정 또는 기기에서는 서버의 현재 노드에서 직접 진행할 수 있으며 자동 계획은 새로 선택해야 한다.

## 오류 처리

- 자동 진행 전체에 하나의 `busy` 잠금을 적용해 중복 입력을 막는다.
- 네트워크 오류가 나면 다음 요청을 보내지 않고 마지막으로 받은 서버 상태를 표시한다.
- 이동은 성공하고 전투 요청만 실패했다면 이동한 전투 노드에서 직접 진행하거나 재개할 수 있다.
- `stale_state`가 오면 자동 진행을 중단하고 상태를 새로고침한다.
- 서버가 계획과 다른 현재 노드를 반환하면 자동 진행을 중단하고 계획 충돌 안내를 표시한다.
- 선택 가능한 축복이 하나도 없거나 선택 카탈로그가 예상과 다르면 임의 선택하지 않고 자동 진행을 중단한다.
- 패배와 완주는 정상 종료로 처리하며 추가 요청을 보내지 않는다.
- 귀환은 자동화하지 않는다. 사용자가 직접 진행으로 전환한 뒤 지도 아래 전리품 가방에서 실행한다.

## 컴포넌트와 로직 경계

- 지도 컴포넌트: 반응형 배치, 노드 상태와 노드 선택 이벤트만 담당한다.
- 노드 모달: 노드 종류에 맞는 표시와 단일 사용자 의도를 전달한다.
- 일괄 진행 설정 모달: 경로 계획과 축복 전략을 만들고 유효성을 검사한다.
- 자동 선택 정책: HP·MP·제시된 축복을 입력받아 선택 ID만 반환하는 순수 함수다.
- 자동 진행 조정기: 기존 요청을 순차 실행하고 종료 조건을 판단한다.
- 원정 화면: 최신 상태, 모달, 결과와 자동 진행 여부를 조합한다.

현재 큰 `V2StormExpeditionView`에서 지도 조작, 모달과 자동 정책을 별도 모듈로 분리한다. 전투와 보상 계산은 기존 서버 코드에 남긴다.

## 접근성과 가독성

- 모든 노드는 `button`으로 제공하고 이름, 상태와 가능한 행동을 접근 가능한 이름에 포함한다.
- 노드 상태는 색상만으로 구분하지 않고 문구와 아이콘을 함께 쓴다.
- 모달은 제목, 설명과 명확한 취소·확정 버튼을 가지며 키보드 포커스를 가둔다.
- 자동 진행 상태는 `aria-live` 영역으로 현재 노드와 중단 결과를 알린다.
- 모바일 주요 터치 영역은 최소 44px을 지킨다.
- 지도, 모달과 보조 카드는 `Card`, `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`의 불투명 표면을 사용한다.
- 배경 이미지가 지도 글자나 모달 뒤로 비치지 않게 한다.

## 테스트

### 순수 로직

- 세 구간 경로 계획의 생성과 방문 이력 충돌 검증
- 세 축복 전략의 우선순위와 미제시·기보유 축복 건너뛰기
- 보급품의 HP·MP 임계와 동시 결손 처리
- 야영지의 유효 회복량, 동률과 균형 정비 우선 규칙
- 최종 정비의 회복 임계와 심장 파쇄 준비 선택
- 모든 위험 이벤트가 거절되는지 검증

### 자동 진행 조정기

- `start → fight 반복 → choose → move` 요청 순서
- 계획한 외곽·중층·수호자 노드 선택
- 다중 전투의 최신 전투 인덱스 전달
- 각 응답 직후 화면 상태 갱신
- 사용자 중단, 네트워크 오류, `stale_state`, 계획 충돌에서 다음 요청 중단
- 패배와 완주에서 계획 정리와 결과 요약
- 새로고침 뒤 명시적 재개와 직접 진행 전환

### UI

- 모바일에서 현재 노드와 다음 후보, 진행 행동이 같은 지도 영역에 존재
- PC에서 별도 오른쪽 현재 행동 열과 지도 밖 이동 버튼이 제거됨
- 이동 성공 뒤 수동 진행 노드 모달 자동 열림
- 자동 진행 중 체크포인트 모달이 열리지 않음
- 전리품 가방과 귀환이 지도 아래 보조 영역에 존재
- 모달 포커스, 키보드 조작, 44px 터치 영역과 라이트·다크 불투명 표면

### 회귀 검증

- 기존 원정 API, 전투, 보상, 입장 횟수, 패배와 귀환 테스트
- 전체 Vitest, TypeScript, ESLint와 프로덕션 빌드
- Playwright 모바일 뷰포트에서 직접 진행과 일괄 진행 핵심 흐름

## 완료 기준

- 모바일과 PC에서 진행을 위해 지도와 다른 행동 카드 사이를 왕복하지 않는다.
- 수동 진행의 모든 전투, 선택과 이동이 노드 모달 안에서 끝난다.
- 일괄 진행은 세 경로와 축복 전략을 한 번 정한 뒤 추가 모달 없이 완주 또는 패배까지 진행한다.
- 중단이나 오류 뒤에도 서버의 마지막 성공 체크포인트에서 정상적으로 이어갈 수 있다.
- 자동 진행이 기존 보상과 패배 위험을 완화하거나 변경하지 않는다.
