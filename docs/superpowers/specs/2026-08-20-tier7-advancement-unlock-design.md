# 7차 직업 최초 전직과 영구 해금 설계

## 목적과 범위

7차는 두 선행 6차 계보를 모두 충분히 숙련한 플레이어가 폭풍 원정에서 모은
공통 재료를 사용해 처음 해금하는 장기 성장 종착점이다. 최초 전직에는 높은
숙련도와 재료를 요구하되, 한 번 해금한 뒤에는 같은 비용과 계보 이동을 반복해서
요구하지 않는다.

이번 범위는 다음 네 7차의 공통 전직 정책, 서버 검증·소비 규칙과 전직 UI 지원을
정의한다.

- 무영검신(`shadowblade`)
- 멸검제(`ruinblade`)
- 비천무신(`skyascendant`)
- 태초현자(`primordialsage`)

네 직업의 전투 스킬 패키지는 내부에 준비되어 있지만 수행 성향과 전직 중 스탯
보너스는 아직 승인되지 않았다. 따라서 이번 작업에서는 네 직업을 선택 가능
카탈로그에 연결하지 않는다. 다음 직업 능력치 설계에서 두 값을 확정한 뒤 카탈로그에
연결하면 이 문서의 전직 정책과 UI가 활성화된다. 빈 보너스나 임시 능력치를 넣지
않고, 별도 공개 기능 플래그도 만들지 않는다.

다음 내용은 이번 범위에 포함하지 않는다.

- 네 7차의 수행 성향과 전직 중 스탯 보너스
- 아직 전투 구조가 확정되지 않은 다른 7차 직업
- 7차 스킬 수치와 SP 비용 변경
- 폭풍 원정의 파편 공급량과 드롭 확률 변경
- 별도 전직 의식 화면, 퀘스트 또는 연출
- 운영 배포와 기존 플레이어 데이터 일괄 변경

## 선택한 구조

공통 전직 시스템에 선언형 7차 최초 해금 정책을 추가한다. 기존
`extraConditions`는 숙련도·생활 레벨처럼 소비하지 않는 해금 조건을 평가하는 순수
규칙이므로, 현재 직업 검사와 재료 소비 및 영구 해금을 그 안에 섞지 않는다. 별도
7차 전직 API도 만들지 않는다.

내부 7차 정책 데이터는 직업별로 다음 항목을 가진다.

- 선행 6차 직업 ID 두 개
- 각 선행 직업의 최소 숙련도
- 최초 전직에 소비할 재료 ID와 수량

직업 차수 타입은 `0 | 1 | 2 | 3 | 4 | 5 | 6 | 7`로 확장한다. 선택 가능
카탈로그에 나중에 추가되는 7차 정의는 승인된 내부 정책을 참조한다. 이를 통해 이후
7차도 같은 검증·표시·소비 흐름을 재사용할 수 있다.

## 대상 직업과 확정 조건

| 7차 직업 | 선행 6차 A | 선행 6차 B |
| --- | --- | --- |
| 무영검신 | 검성(`swordsaint`) | 흑월(`blackmoon`) |
| 멸검제 | 검성(`swordsaint`) | 패황(`hegemon`) |
| 비천무신 | 천궁(`heavenlybow`) | 천룡권성(`celestialdragon`) |
| 태초현자 | 대마도사(`archmage`) | 태초술사(`primordialmage`) |

네 직업에 적용할 최초 전직 조건은 모두 같다.

- 두 선행 6차의 직업별 숙련도 `jobCumLevel`이 각각 `100,000` 이상이다.
- 현재 직업이 두 선행 6차 중 하나다.
- 현재 레벨이 `100`이다.
- 캐릭터가 `폭풍 기원의 파편`(`v2_storm_origin_fragment`)을 30개 이상
  보유한다.
- 최초 전직이 성공하면 파편 30개를 정확히 한 번 소비한다.

두 숙련도는 합산하지 않는다. 한쪽이 150,000이고 다른 쪽이 50,000이면 해금되지
않는다. 현재 직업 조건도 단순한 전직 이력으로 대신하지 않는다. 최초 전직 버튼을
누르는 시점에 실제로 두 선행 6차 중 하나여야 한다.

## 영구 해금 판정

별도 `unlockedTier7Jobs` 저장값을 추가하지 않는다. 기존 `proficiency.v2`의
`jobHistory`에 대상 7차 ID가 있으면 과거에 그 직업으로 성공적으로 전직한 것으로
보고 영구 해금 상태로 판정한다. 전직 성공 트랜잭션이 이미 대상 직업을
`jobHistory`에 기록하므로, 동일 사실을 두 필드에 중복 저장해 불일치가 생기는 것을
피한다.

- 이력에 대상 7차가 없으면 최초 전직 조건을 모두 검사한다.
- 이력에 대상 7차가 있으면 선행 숙련도, 현재 선행 직업과 파편 조건을 다시 검사하지
  않는다.
- 영구 해금 후에도 현재 직업에서 다른 전투직으로 이동하기 위한 기존 레벨 조건과
  전직 후 Lv.1 초기화 규칙은 그대로 적용한다.
- 현재 7차를 같은 7차로 재전직하는 경우도 이미 이력에 있으므로 파편을 소비하지
  않는다.

7차 출시 전에는 해당 ID가 정상 플레이로 `jobHistory`에 들어갈 수 없다. 운영 도구가
의도적으로 이력을 부여했다면 영구 해금을 부여한 것으로 취급한다.

## 서버 권위 전직 흐름

기존 `/api/v2/me/advance-class` 트랜잭션이 전직의 유일한 쓰기 경로로 남는다. 서버는
클라이언트가 보낸 조건 충족 여부나 예상 보유량을 신뢰하지 않는다.

처리 순서는 다음과 같다.

1. 캐릭터, 스킬, 필요한 생활 저장값과 숙련도 저장값을 기존 잠금 순서대로 잠근다.
2. 대상 직업이 선택 가능한 카탈로그에 있고 전직 가능한 직업인지 확인한다. 따라서
   수행 성향과 직업 보너스가 확정되어 카탈로그에 연결되기 전에는 내부 7차 정책만
   있어도 실제 전직할 수 없다.
3. 현재 직업에 적용되는 기존 재전직 레벨 조건을 확인한다.
4. 대상에 7차 정책이 있고 `jobHistory`에 대상 ID가 없다면 최초 전직 상태를
   계산한다.
5. 현재 직업, 두 숙련도와 파편 보유량을 모두 확인한다.
6. 캐릭터 저장값의 재료에서 파편 30개를 차감한 다음, 같은 캐릭터 갱신에 새
   class/spec, Lv.1과 경험치 초기화를 함께 반영한다.
7. 성장 스탯을 초기화하고 대상 7차를 `jobHistory`에 기록한다.
8. 보유 스킬은 유지하되 새 SP 예산을 초과하는 장착분을 기존 규칙으로 정리한다.
9. 모든 저장이 성공하면 커밋하고, 하나라도 실패하면 파편 차감을 포함한 전체 변경을
   롤백한다.

동시 최초 전직 요청은 기존 캐릭터와 숙련도 행 잠금으로 직렬화한다. 첫 요청이
성공한 뒤 두 번째 요청은 현재 직업과 레벨 및 갱신된 이력을 다시 읽는다. 따라서
파편을 두 번 소비하거나 같은 최초 해금을 두 번 기록하지 않는다.

## 조건 판정 모델과 오류

서버와 UI가 같은 의미를 사용하도록 순수한 7차 전직 상태 계산기를 둔다. 입력은 대상
정책, 현재 직업과 레벨, `jobCumLevel`, `jobHistory`와 재료 보유량이다. 출력은 영구
해금 여부, 전직 가능 여부와 조건별 현재값·요구값이다.

최초 전직 실패 사유는 다음처럼 구분한다.

- `tier7_prerequisite_proficiency`: 선행 6차 숙련도 부족
- `tier7_current_job`: 현재 직업이 선행 6차가 아님
- 기존 `level_too_low`: 현재 레벨 부족
- `tier7_material_shortage`: 폭풍 기원의 파편 부족
- 기존 저장·트랜잭션 오류

클라이언트는 오류 코드에 맞는 한국어 안내를 보여준다. 최종 권위는 서버에 있으므로
화면을 연 뒤 숙련도나 재료 상태가 달라졌다면 서버 응답으로 거부하고 최신 상태를
다시 불러온다. 저장 실패에는 성공 응답이나 낙관적 재료 차감을 표시하지 않는다.

## 전직 로드맵과 확인 모달

7차가 카탈로그에 연결된 뒤 로드맵에서는 두 선행 6차에서 합쳐지는 하나의 종착
노드로 표시한다. 최초 전직 상세에는 조건별 현재 진행도를 표시한다.

- 선행 6차 A 숙련도 `현재 / 100,000`
- 선행 6차 B 숙련도 `현재 / 100,000`
- 현재 직업 `선행 6차 A 또는 선행 6차 B`
- 현재 레벨 `현재 / 100`
- 폭풍 기원의 파편 `현재 / 30`

부족한 항목은 개별적으로 강조하고 전직 버튼을 비활성화한다. 모든 조건을 충족해
최초 전직 확인 모달을 열면 다음을 명시한다.

- 폭풍 기원의 파편 30개가 소비된다.
- 재료 비용은 최초 전직에만 발생한다.
- 전직 후 Lv.1과 경험치 0으로 초기화된다.
- 배운 스킬과 누적 숙련도는 유지된다.

이미 해금한 7차에는 `영구 해금` 배지를 표시한다. 파편과 선행 조건 진행도는 숨기고
기존 재전직 레벨 조건 및 초기화 안내만 표시한다. 별도 전직 의식 페이지를 만들지
않고 기존 직업 상세·확인 모달을 확장한다. 모바일에서도 조건 목록 다음에 주 행동이
이어지고, 모든 카드와 모달은 공용 불투명 표면 토큰을 사용한다.

전직 성공 후에는 서버 응답을 기준으로 캐릭터, 재료, 숙련도와 로드맵 상태를 다시
불러온다. 실패하면 모달을 유지해 부족 사유를 확인할 수 있게 한다.

## 공개 경계

이번 조건 작업은 네 정책 데이터와 재사용 가능한 판정·서버·UI 지원을 내부에
준비한다. 다음 직업 능력치 설계 전까지는 다음 불변식을 유지한다.

- 네 7차는 `V2_JOB_CATALOG`와 선택 가능한 직업 목록에 없다.
- 내부 스킬 패키지는 선택 가능한 직업 스킬 풀에 노출되지 않는다.
- 일반 이용자가 네 7차 ID를 API에 직접 보내도 `bad_target`으로 거부된다.
- 직업 도감의 총 직업 수와 해금 SP 보너스에는 네 7차가 포함되지 않는다.
- 임시 기능 플래그나 빈 직업 보너스로 공개 상태를 흉내 내지 않는다.

다음 설계가 수행 성향과 전직 중 스탯 보너스를 확정하면 네 직업을 카탈로그에
연결한다. 연결 시 각 직업은 이 문서의 기존 정책을 참조하며 별도의 조건 수치를 다시
선택하지 않는다.

## 검증 기준

순수 정책 테스트는 다음 경계를 검증한다.

- 네 직업의 선행 6차 매핑과 공통 파편 비용이 정확하다.
- 어느 한 선행 숙련도라도 99,999면 실패하고 둘 다 100,000이면 통과한다.
- 숙련도 합계가 200,000 이상이어도 한쪽이 100,000 미만이면 실패한다.
- 파편 29개는 실패하고 30개는 재료 조건을 통과한다.
- 선행 6차가 아닌 현재 직업은 나머지 조건을 모두 만족해도 실패한다.
- 이력에 대상 7차가 있으면 선행 숙련도, 현재 직업과 파편 조건을 생략한다.

전직 트랜잭션 테스트는 다음을 검증한다.

- 최초 전직 성공 시 파편을 정확히 30개 차감하고 Lv.1 초기화와 전직 이력을 함께
  저장한다.
- 전직 저장 또는 이후 저장 단계가 실패하면 파편, 직업과 이력이 모두 원복된다.
- 동시에 들어온 두 최초 전직 요청에서 한 요청만 최초 비용을 소비한다.
- 영구 해금된 7차 재방문과 같은 직업 재전직은 파편을 소비하지 않는다.
- 기존 1~6차 전직에는 새 재료 검사나 소비가 발생하지 않는다.

UI 테스트는 최초 전직의 다섯 진행 항목, 부족 항목과 비활성 버튼, 파편 소비 확인
문구 및 영구 해금 상태를 검증한다. 모바일 뷰포트에서 모달의 조건 목록과 주 행동을
스크롤로 도달할 수 있고 배경 이미지가 카드 뒤로 비치지 않는지도 확인한다.

공개 경계 테스트는 직업 능력치 설계가 승인되기 전까지 네 7차가 카탈로그, 도감,
해금 SP 계산과 선택 가능한 스킬 풀에 들어가지 않고 API 직접 요청도 거부되는지
보장한다.
