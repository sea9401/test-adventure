# 도감 연구 공개 종착점(B10) 설계

## 위치와 원칙

B10은 도감 숙련 로드맵의 마지막 로컬 구현 묶음이다. B8b가 최종 순위와 트로피를 만들고 B9가 이를
운영자가 검증·실행하게 했다면, B10은 비공개 결산 결과를 명시적으로 공개하고 종료 시즌을 오래 볼 수
있게 한다.

이번 작업에서도 실제 시즌 예약, 결산, 트로피 발급, 공개 실행, 기능 플래그 변경, 백필, 배포는 하지
않는다. 모든 기능 기본값은 계속 `false`다. SP, 전투 능력치, 골드, 아이템, 업적 점수와 영구 도감
숙련 점수는 바뀌지 않는다.

## 목표

- B9에서 닫은 비공개 시험 시즌은 공개 작업 전까지 어떤 공개 아카이브에도 나타나지 않는다.
- 운영자가 트로피 결과를 확인한 뒤 `PUBLISH {seasonId}`로 시즌을 한 번 공개한다.
- 공개 시 트로피 대상자에게 개인 알림을 남기고, 다이아·전설 결과만 전광판·전체 소식에 올린다.
- 채널별 발행 원장으로 재실행과 부분 기능 차단을 안전하게 처리한다.
- 공개된 종료 시즌은 명예의 전당에서 확정 순위와 점수 구성을 계속 볼 수 있다.
- 공개 뒤에는 트로피가 0건인 시즌도 재결산할 수 없다.
- 정적 출시 점검과 운영 순서를 문서·명령으로 남기되 실제 상태 변경은 하지 않는다.

## 검토한 접근

### 닫힌 시즌을 즉시 아카이브에 노출

구현은 짧지만 B9의 비공개 점수 시험이 바로 공개되고, 재결산 중인 결과가 보일 수 있다. 채택하지
않는다.

### 트로피 발급과 알림·전광판을 한 작업에 결합

최초 발급 때 `feedEnabled`가 꺼져 있거나 부수 효과가 실패하면, 멱등 트로피 행 때문에 재실행 시
누락된 채널을 복구하기 어렵다. 채택하지 않는다.

### 시즌 공개 시각과 채널별 발행 원장을 별도로 저장

트로피 발급 뒤 별도 공개 작업을 실행한다. 개인 알림과 전광판은 각각 사용자·시즌·채널 고유 키로
멱등 처리하고, 모든 쓰기는 한 트랜잭션에서 수행한다. `feedEnabled`가 꺼진 실행에서는 개인 알림과
아카이브만 공개하고, 나중에 다시 실행하면 빠진 전광판 채널만 채운다. 이 방식을 채택한다.

## 데이터 모델

`codex_research_seasons`에 nullable `published_at`을 추가한다.

- `NULL`: 닫혀 있어도 비공개. B9 미리보기·재결산 가능 범위다.
- 시각 있음: 명예의 전당 공개 완료. 이후 최종 결과는 불변이다.

`codex_research_publications`를 추가한다.

```text
season_id
user_id
channel          notification | feed
published_at
PRIMARY KEY (season_id, user_id, channel)
```

개인 알림은 트로피 등급이 있는 모든 확정 사용자, 전광판은 `diamond`와 `legendary` 사용자만 대상이다.
고유 키를 먼저 만들고 같은 트랜잭션에서 실제 채널 행을 저장한다. 채널 쓰기가 실패하면 원장도 같이
롤백되어 재실행할 수 있다.

## 공개 작업

관리자 API에 `{ op: "publish-honors", seasonId, confirm }`를 추가한다. 확인 문자열은 정확히
`PUBLISH {seasonId}`다. `super` 권한, `settlementEnabled`, `trophiesEnabled`가 필요하다.
`feedEnabled`는 전광판 채널만 제어한다.

한 DB 트랜잭션에서 다음 순서로 실행한다.

1. 시즌 행을 `FOR UPDATE`로 잠근다.
2. `closed`, 유효한 `settledAt`, 종료 시각 경과를 확인한다.
3. 최종 등급 대상자와 `research:{seasonId}` 트로피 이력이 정확히 일치하는지 확인한다.
4. 없는 `notification` 원장을 만들고 영속 개인 알림을 저장한다.
5. `feedEnabled`라면 다이아·전설의 없는 `feed` 원장을 만들고 닉네임 스냅샷과 소식 행을 저장한다.
6. `publishedAt`이 없으면 현재 시각으로 기록한다.
7. 생성·기존 개인 알림 수와 전광판 수를 반환한다.

등급 대상자가 0명인 시즌도 공개할 수 있다. 이 경우 채널 행은 없지만 시즌 `publishedAt`이 공개의
권위 표식이 된다. 반복 실행은 공개 시각을 바꾸지 않는다. 공개된 시즌은 재결산 진입점과 저장소
상태 전이 양쪽에서 거부한다.

## 개인 알림과 전광판

개인 알림 종류는 `codex_research_trophy`다.

```text
seasonId, themeName, tier, finalRank, score
```

알림 종과 알림 센터에는 “2026-08 강과 호수의 달 최종 2위 · 다이아 트로피”처럼 확정 결과를
표시한다. 클릭은 기존 알림 센터로 이동하며, 경제 보상 수령 동작은 없다.

전체 소식 종류는 `codex_research_result`다. 같은 메타데이터를 사용하되 다이아·전설만 저장한다.
전체 소식과 상단 전광판에는 시즌, 순위, 등급을 짧게 표시한다. 공개 작업 자체가 채널 원장으로
멱등하므로 일반 5초 디바운스에 의존하지 않는다.

## 종료 시즌 명예의 전당

`GET /api/rankings/codex-research/archive`는 인증 후 `monthlyRankingVisible`과 `trophiesEnabled`를
확인한다. 하나라도 꺼져 있으면 시즌·진행 테이블을 읽지 않고 `enabled: false`를 반환한다.

공개된 닫힌 시즌만 최근 24개를 반환한다. `seasonId`가 없으면 최신 공개 시즌, 있으면 해당 공개
시즌을 선택한다. 응답에는 다음을 포함한다.

- 시즌 ID, 테마, 기간, 결산·공개 시각, 참가자 수
- 상위 50명의 고정 최종 순위, 현재 공개 이름·아바타·장식, 총점과 세 점수 구성, 확정 등급
- 현재 사용자의 행과 앞뒤 2명
- 1위 각인 표시

최종 순위는 다시 계산하지 않는다. 현재 차단 관계는 행을 숨기되 순위 숫자를 다시 매기지 않는다.
정지·관리자 제외는 결산 때 이미 고정된 결과를 권위로 삼는다. 이름이 없는 계정은 공개 행에서 숨기고
순위는 그대로 둔다.

기존 도감 랭킹 탭은 다음 다섯 개가 된다.

```text
완성도 | 종합 숙련 | 분야별 | 월간 연구 | 명예의 전당
```

명예의 전당은 시즌 선택, 우승자 강조, 상위 목록, 내 확정 결과와 점수 구성을 불투명
`SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`로 표시한다. 공개 시즌이 없거나 플래그가 꺼진
상태에서 점수나 순위를 추정하지 않는다.

## 출시 점검

`npm run check:codex-mastery-release`는 상태를 바꾸지 않는 정적 검사다.

- 모든 도감 기능 기본값이 `false`인지 확인
- B10 마이그레이션과 공개 API·운영 API·명예의 전당 파일 존재 확인
- 도감 전용 cron이나 실제 생산 시즌 정의 파일이 추가되지 않았는지 확인
- 필수 확인 문자열과 공개 플래그 게이트가 소스에 남아 있는지 확인

운영 런북은 배포 전 플래그 전부 꺼짐, 백필·복구 검증, 미래 시즌 예약, 진행 비공개 시험, 결산
미리보기, 결산, 트로피 발급, 공개 발행, 랭킹 공개 순서를 체크리스트로 제공한다. 명령은 자동 실행하지
않으며 점검 모드 해제도 다루지 않는다.

## 오류와 관측

- 안정 오류: `season_not_found`, `season_not_ready`, `trophies_not_published`,
  `season_already_published`, `feature_disabled`, `confirm_mismatch`.
- 공개 성공·실패 감사 로그에는 시즌 ID, 결과 상태, 생성·기존 개수만 넣는다.
- 알림 대상 사용자 ID 목록, 정의 JSON, 상위 순위 목록은 감사 로그·콘솔에 넣지 않는다.
- 공개 원장 수와 실제 알림·피드 수 불일치는 PostgreSQL 통합 테스트와 관리자 시즌 집계에서
  확인한다.

## 비목표

- 실제 시즌·플래그·백필·결산·트로피·공개 실행과 배포
- 자동 cron 또는 다음 달 정의 자동 생성
- 브라우저 푸시의 전달 보장
- 시즌 칭호·표지 신규 실물, 경제·전투 보상
- 공개된 과거 순위 수정

## 완료 기준

- 비공개 닫힌 시즌과 공개 시즌이 명확히 분리된다.
- 공개 작업이 채널별로 재실행 안전하고 부분 플래그 복구가 가능하다.
- 트로피 없는 공개 시즌도 다시 결산할 수 없다.
- 명예의 전당은 고정 순위를 재계산하지 않고 공개 시즌만 보여 준다.
- 알림 센터, 전체 소식, 전광판이 새 타입을 안전하게 해석한다.
- 출시 점검은 읽기 전용이며 기본 비활성·무자동화 원칙을 확인한다.
- PostgreSQL 통합, 전체 테스트, 타입, 린트, 마이그레이션, 이미지와 빌드가 통과한다.
