# 농장 후반 증표 교환소 설계

## 목적

밭과 목장을 모두 확장한 플레이어에게 농장 증표의 반복 사용처와 장기 수집 목표를 제공한다. 성장 중인 플레이어의 밭·축사 확장 비용은 그대로 유지하고, 모든 시설을 완성한 뒤에만 후반 교환소를 연다.

현재 농장 증표의 영구 소모처는 밭 확장 350개와 유료 축사 확장 390개로 끝난다. 이후에는 씨앗 상자만 반복 구매할 수 있지만 납품과 요리 주문은 증표를 계속 공급한다. 새 교환소는 이 후반 잉여를 기존 농장 소모품으로 흡수하고, 칭호로 장기 목표를 제공한다.

## 범위

- 기존 농장 증표 상점 아래에 `농장주의 교환소`를 추가한다.
- 통합 교환소의 농장 화면에도 같은 교환소를 노출한다.
- 반복 구매 상품으로 배합 사료와 유기질 거름을 판매한다.
- 농장 전용 영구 칭호 2종을 판매한다.
- 신규 능력치 효과, 신규 이미지, 프로필 꾸미기 상자는 추가하지 않는다.
- 기존 씨앗 상자, 밭 확장, 축사 확장의 가격과 동작은 바꾸지 않는다.

## 해금 조건

다음 조건을 모두 충족하면 교환소를 이용할 수 있다.

- 밭 6칸 개방
- 비용이 있는 축사 4칸을 모두 개방: 두 번째 닭장, 첫 번째·두 번째 외양간, 돼지우리

해금 여부는 정규화된 `farm.v2` 상태에서 계산한다. 별도의 해금 플래그는 저장하지 않는다. 시설 확장은 되돌릴 수 없으므로 계산 결과가 곧 영구 해금 상태가 된다.

해금 전에도 교환소 영역을 표시하며 `밭 N/6 · 축사 N/4` 진행도를 제공한다. 클라이언트 표시와 별개로 모든 구매 요청에서 서버가 해금 조건을 다시 검사한다.

## 상품 구성

### 반복 상품

| 상품 | 지급 | 가격 | 구매 제한 |
| --- | ---: | ---: | --- |
| 목장 사료 꾸러미 | 배합 사료 5개 | 농장 증표 20개 | 없음 |
| 영농 거름 꾸러미 | 유기질 거름 3개 | 농장 증표 24개 | 없음 |

상품 ID는 각각 `ranch-feed-bundle`, `fertilizer-bundle`로 둔다.

거름은 밭 6칸에 모두 사용하려면 두 꾸러미가 필요하므로 한 재배 주기마다 증표 48개를 선택적으로 소비할 수 있다. 두 상품은 직접 제작을 대체하는 필수 경로가 아니라, 남는 증표로 제작 재료와 시간을 아끼는 보조 경로다. 운영 데이터에서 증표 잔액과 직접 제작 비율을 확인한 뒤 가격만 별도 조정할 수 있도록 카탈로그 상수로 둔다.

### 영구 수집 보상

| 칭호 | 가격 | 용도 |
| --- | ---: | --- |
| 풍요의 손 | 농장 증표 1,000개 | 첫 장기 수집 목표 |
| 황금 들판의 주인 | 농장 증표 5,000개 | 최종 수집 목표 |

칭호 ID는 각각 `farm_bountiful_hand`, `farm_golden_fields_owner`로 두고 상품 ID는 `title-bountiful-hand`, `title-golden-fields-owner`로 구분한다. 칭호는 `collection` 분류로 도감에 등록한다. 구매 조건 설명에는 농장주의 교환소와 가격을 명시한다. 이미 가진 칭호는 다시 살 수 없으며 증표도 차감하지 않는다.

프로필 꾸미기 상자는 유료 상점과 출석 보상의 가치를 건드리므로 이번 범위에서 제외한다.

## 데이터와 모듈 경계

후반 교환소의 카탈로그와 순수 판정 로직은 별도 `farmEndgameShop` 모듈에 둔다.

- 상품 ID, 이름, 설명, 가격, 지급 종류와 수량
- 밭·축사 해금 진행도 계산
- 상품 ID 조회와 서버 검증에 필요한 타입

기존 씨앗 상점의 `FarmShopItem`과 `buyFarmShopItem`은 씨앗 보상만 다루는 현재 책임을 유지한다. 후반 상품은 농장 보관함, 생활 제작 완성품, 모험의 서 칭호처럼 서로 다른 저장소를 사용하므로 기존 순수 함수에 억지로 합치지 않는다.

농장 조회 응답에는 다음 후반 교환소 뷰를 추가한다.

- 해금 여부
- 현재/필요 밭 수와 축사 수
- 상품 카탈로그
- 보유한 교환소 칭호 ID

## 구매 흐름

전용 `POST /api/v2/farm/endgame-shop` API는 `{ itemId }` 하나를 받는다. 서버 카탈로그가 가격과 보상을 결정하며 클라이언트가 보낸 가격이나 수량은 사용하지 않는다.

트랜잭션은 다음 순서로 처리한다.

1. `farm.v2`를 잠그고 정규화한다.
2. 교환소 해금 여부와 사용 가능한 증표를 검사한다.
3. 상품 종류에 따라 보상 저장소를 처리한다.
   - 배합 사료: `farm.v2.inventory.compound_feed`에 5개 추가
   - 유기질 거름: `life-workshop.v1.crafting.balances.organic_fertilizer`에 3개 추가
   - 칭호: `adventure-log.v2`에 해당 칭호를 멱등 등록
4. `farm.v2.stats.reputationSpent`에 상품 가격을 더한다.
5. 변경된 저장 상태와 구매 결과를 함께 반환한다.

성공 응답에는 갱신된 농장 상태, 거름 잔액, 보유 교환소 칭호 ID와 구매 결과를 포함한다. 클라이언트는 이 응답만으로 증표·사료·거름·칭호 표시를 동시에 갱신하며 성공 직후 별도 재조회에 의존하지 않는다.

잠금 순서는 기존 농장 제작 흐름과 같은 `farm.v2 → life-workshop.v1 또는 adventure-log.v2`로 고정한다. 같은 사용자의 동시 구매는 `farm.v2` 행 잠금에서 직렬화되어 동일한 증표를 중복 사용할 수 없다. 어느 단계에서든 실패하면 트랜잭션 전체가 롤백되어 증표와 보상이 함께 보존된다.

## 화면 동작

기존 농장 증표 상점 아래에 별도 제목과 설명을 가진 교환소 영역을 둔다.

해금 전에는 상품 대신 다음 정보를 표시한다.

- 모든 농장 시설을 완성하면 열린다는 안내
- `밭 N/6 · 축사 N/4` 진행도

해금 후에는 반복 상품과 영구 칭호를 구분해 카드로 표시한다.

- 반복 상품은 제한 없이 바로 구매한다.
- 칭호 구매는 이름과 가격을 포함한 확인창을 거친다.
- 이미 보유한 칭호는 `보유 중`으로 표시하고 버튼을 비활성화한다.
- 증표가 부족하면 `증표 부족`을 표시한다.
- 구매 성공 후 증표 잔액과 해당 보유 수량을 즉시 갱신한다.
- 구매 성공과 실패는 기존 농장 토스트 흐름으로 알린다.

새 패널과 카드는 `SURFACE_CARD`와 `SURFACE_INSET`을 사용한다. 라이트·다크 모드 모두에서 지역 배경이 카드 본문 뒤로 비치지 않도록 불투명 표면을 유지한다. 사료와 거름은 기존 이미지 자산을 재사용한다. 칭호에는 신규 이미지가 필요하지 않다.

## 오류 처리

서버는 다음 오류 코드를 반환한다.

- `endgame_shop_locked`: 밭 또는 축사 조건 미달
- `not_enough_reputation`: 사용 가능한 농장 증표 부족
- `already_owned`: 이미 보유한 칭호 재구매
- `shop_item_not_found`: 카탈로그에 없는 상품 ID

인증 실패와 잘못된 요청 본문은 기존 농장 API 규칙을 따른다. 모든 실패는 상태를 변경하지 않는다.

## 검증

구현 시 동작 회귀 테스트를 먼저 작성한다.

### 순수 로직

- 밭과 유료 축사가 모두 열렸을 때만 해금된다.
- 잠긴 밭·축사 수가 진행도에 정확히 반영된다.
- 카탈로그의 상품 가격과 지급 수량이 승인된 값과 일치한다.

### 서버 경로

- 잠긴 교환소에서 구매가 거부되고 상태가 유지된다.
- 증표가 부족하면 보상 지급과 증표 차감이 모두 일어나지 않는다.
- 사료 구매는 농장 보관함에 5개를 더하고 증표 20개를 사용한다.
- 거름 구매는 생활 제작 잔액에 3개를 더하고 증표 24개를 사용한다.
- 칭호 구매는 모험의 서에 칭호를 등록하고 정확한 증표를 사용한다.
- 보유 칭호 재구매는 차감 없이 거부된다.
- 알 수 없는 상품은 거부된다.

### UI와 회귀

- 해금 전 밭·축사 진행도를 표시한다.
- 해금 후 반복 상품과 칭호 카드를 표시한다.
- 보유 칭호와 증표 부족 상태에서 버튼을 비활성화한다.
- 칭호 구매 확인창에 이름과 가격을 표시한다.
- 농장 화면과 통합 교환소가 같은 후반 교환소 상태를 사용한다.
- 기존 씨앗 구매, 밭 확장, 축사 확장 테스트가 계속 통과한다.
- 새 카드가 표면 상수를 사용하며 라이트·다크 모드용 불투명 배경을 유지한다.

변경 후 관련 단위·라우트·컴포넌트 테스트와 이미지 참조 검사를 실행한다. 신규 이미지가 없으므로 이미지 최적화 대상은 추가되지 않는다.

## 제외 사항

- 증표 획득량 하향
- 기존 시설 가격 변경
- 주간 구매 제한 또는 가격 상승식
- 신규 농장 능력치·희귀 수확 보조 효과
- 프로필 꾸미기 상자와 유료 상품 지급
- 배포와 운영 점검 모드 변경
