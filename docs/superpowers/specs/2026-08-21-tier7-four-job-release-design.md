# 7차 네 직업 선공개 설계

## 목적과 범위

내부 구현이 끝난 네 7차 전투 직업을 실제 직업 카탈로그에 연결해 전직 로드맵,
직업 도감, 스킬 학습과 기존 전직 API에서 사용할 수 있게 한다.

- 무영검신(`shadowblade`)
- 멸검제(`ruinblade`)
- 비천무신(`skyascendant`)
- 태초현자(`primordialsage`)

오행법왕, 혈천마신과 부동성주는 전투 구조가 확정되지 않았으므로 이번 공개에서
제외한다. 네 직업의 기존 스킬 수치, 폭풍 원정 파편 공급량, 전직 연출, 별도 퀘스트와
운영 배포도 이번 범위에서 바꾸지 않는다.

## 공개 방식

네 직업을 `V2_JOB_CATALOG`와 기존 legacy class/spec 호환 매핑에 등록한다. 별도 기능
플래그나 전용 API를 만들지 않는다. 카탈로그 등록을 공개의 단일 경계로 유지해 기존
직업 목록, 전직 로드맵, 직업 도감, 스킬 학습과 서버 전직 검증이 같은 대상을 보게
한다.

다만 기존 `isJobUnlocked`는 선행 숙련도 충족 여부를 뜻하므로 7차의 영구 해금
판정으로 그대로 사용하지 않는다. 로드맵의 최초 전직 후보 표시는 기존
`tier7AdvancementStatus`를 사용하고, 도감 해금·직업 SP·숙련도 탑·숙련 증서처럼
해금된 직업에 영구 권한을 주는 표면은 `jobHistory`의 첫 전직 성공 기록을 요구한다.
선행 숙련도만 충족했거나 파편을 보유한 상태는 7차 영구 해금으로 간주하지 않는다.

로드맵에서는 기존 하이브리드 노드 규칙을 사용한다. 각 7차는 두 선행 6차를 모두
선행 조건으로 보존하되 첫 번째 선행 직업 아래에 한 번만 배치하고, 상세 정보에는 두
계보를 모두 표시한다.

## 대상 직업과 능력치

7차 수행 성장량은 합계 7, 현재 직업으로 있을 때 적용되는 플랫 보너스는 합계 48로
통일한다. 6차보다 한 단계 높은 성장을 제공하되, 이미 46 SP와 16~18점 기준으로
설계된 7차 스킬 패키지의 성능을 고려해 내장 보너스의 상승 폭은 제한한다.

| 직업 | 수행 성향 | 전직 중 보너스 | legacy class/spec |
| --- | --- | --- | --- |
| 무영검신 | LUK 4, DEX 2, STR 1 | LUK 32, DEX 10, STR 6 | `warrior/shadowblade` |
| 멸검제 | STR 4, VIT 2, LUK 1 | STR 34, VIT 10, LUK 4 | `warrior/ruinblade` |
| 비천무신 | DEX 4, STR 2, LUK 1 | DEX 32, STR 10, LUK 6 | `rogue/skyascendant` |
| 태초현자 | INT 4, SPI 3 | INT 32, SPI 16 | `mage/primordialsage` |

`effectiveCultivateProfile`은 7차에서도 카탈로그의 직업 전용 수행 성향을 사용한다.
직업 ID, 이름과 두 선행 계보는 `tier7Jobs.ts`의 공유 메타데이터를 진실 출처로 삼아
카탈로그와 전직 정책의 중복 드리프트를 막는다.

## 전직과 영구 해금

기존 `tier7Advancement.ts`와 `/api/v2/me/advance-class` 흐름을 그대로 사용한다.

- 두 선행 6차의 `jobCumLevel`이 각각 100,000 이상이어야 한다.
- 현재 직업은 두 선행 6차 중 하나여야 한다.
- 현재 레벨은 100이어야 한다.
- 최초 전직에는 폭풍 기원의 파편 30개를 소비한다.
- 성공한 전직은 대상 ID를 기존 `proficiency.v2.jobHistory`에 기록한다.
- 이력에 대상 7차가 있으면 영구 해금으로 보고 이후 재전직에 파편과 선행 조건을
  다시 요구하지 않는다. 기존 재전직 레벨 조건과 Lv.1 초기화는 유지한다.

서버는 카탈로그 존재 여부, 숙련도, 현재 직업, 레벨, 재료와 이력을 트랜잭션 안에서
다시 확인한다. 최초 전직의 파편 차감, 직업 변경, 레벨·경험치 초기화와 이력 기록은
모두 성공하거나 모두 롤백되어야 한다. 클라이언트가 보낸 진행도나 재료 수량은
신뢰하지 않는다.

이미 조건을 충족한 이용자는 공개 뒤 추가 백필 없이 바로 전직할 수 있다. 별도 DB
마이그레이션과 기존 플레이어 데이터 일괄 변경은 필요하지 않다.

## SP와 수집 영향

첫 전직에 성공해 `jobHistory`에 기록된 7차는 다른 `tier > 0` 직업처럼 해금 직업
수에 포함한다. 선행 숙련도만 충족한 최초 전직 후보는 아직 포함하지 않는다. SP
환산은 기존 체감식 `min(n, 50) + floor(max(0, n - 50) / 2)`를 변경하지 않으며,
현재 구간에서 네 직업을 모두 처음 해금하면 직업 해금 SP가 정확히 2 증가한다.

직업 도감의 전체 수와 해금 진행도에는 공개된 네 직업을 포함한다. 카탈로그에 없는
나머지 세 7차는 도감, SP 계산, 스킬 학습과 로드맵에 계속 포함하지 않는다.
도감의 전체 수에는 네 직업이 즉시 들어가지만, 개별 `해금` 표시는 첫 전직 성공 뒤에
바뀐다.

## UI와 오류 처리

기존 직업 로드맵 상세와 전직 확인 모달을 재사용한다. 최초 전직 상세에는 다음 다섯
진행 항목을 표시한다.

- 선행 6차 A 숙련도 현재값 / 100,000
- 선행 6차 B 숙련도 현재값 / 100,000
- 현재 직업이 선행 6차 중 하나인지 여부
- 현재 레벨 / 100
- 폭풍 기원의 파편 현재값 / 30

부족한 조건이 있으면 해당 행을 구분하고 전직 버튼을 비활성화한다. 조건을 충족한
최초 전직 확인에는 파편 30개 소비, 최초 1회 비용, Lv.1·경험치 0 초기화와 스킬·누적
숙련도 유지 안내를 표시한다. 영구 해금된 직업은 `영구 해금` 상태와 기존 재전직
안내만 보여 준다.

서버가 `tier7_prerequisite_proficiency`, `tier7_current_job`, `level_too_low`,
`tier7_material_shortage`를 반환하면 기존 한국어 오류 문구를 사용하고 최신 상태를
다시 불러온다. 저장 실패에는 성공 상태나 낙관적 파편 차감을 표시하지 않는다.

신규 화면을 만들지 않으므로 기존 불투명 카드·모달 표면과 모바일 스크롤 구조를
유지한다.

## 검증 기준

### 카탈로그와 수행

- 네 직업만 tier 7로 등록되고 이름·선행 계보·legacy 매핑이 정확하다.
- 수행 성향 합계는 각 7, 직업 보너스 합계는 각 48이다.
- 7차의 실제 수행은 카탈로그의 직업 전용 성향을 사용한다.
- 나머지 세 7차는 카탈로그와 공개 표면에 없다.

### 전직과 SP

- 선행 숙련도 99,999/100,000, 파편 29/30과 레벨 99/100 경계를 검증한다.
- 최초 전직은 파편을 정확히 30개 한 번만 차감한다.
- 저장 실패와 동시 요청에서 부분 저장이나 중복 소비가 없다.
- 영구 해금 재전직은 파편을 소비하지 않는다.
- 선행 숙련도만 충족한 7차는 도감 해금, 직업 SP, 숙련도 탑과 숙련 증서 대상이
  아니며 첫 전직 성공 뒤에만 네 표면이 함께 열린다.
- 네 직업을 모두 처음 해금하면 기존 체감식에 따라 직업 SP가 정확히 2 증가한다.

### UI와 전투

- 로드맵에서 두 부모 계보와 조건별 진행도, 최초 비용과 영구 해금을 표시한다.
- 네 직업의 기존 7차 스킬 패키지만 학습 가능 목록에 노출된다.
- 7차 스킬은 해당 직업으로 전직한 뒤 기존 현재 직업 학습 규칙으로만 배울 수 있다.
- 각 패키지의 SP 합계 46, 성능 점수 16~18과 PvE/PvP 분리 계수를 유지한다.
- 검영, 검의·멸검 충전, 교차 계열과 완전식 상태의 발동·초기화 회귀 테스트를
  유지한다.

## 출시 경계

이번 구현은 로컬 변경과 커밋까지다. 운영 배포는 사용자가 별도로 명시적으로 요청한
뒤에만 수행한다. 배포 전에는 집중 테스트, TypeScript 검사, ESLint와 프로덕션 빌드를
통과해야 한다. DB 마이그레이션이나 백필이 없으므로 배포 후 별도 데이터 작업은 하지
않는다.
