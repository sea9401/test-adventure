# 요리 연구 전면 개편 설계

## 목표

현재 공개 레시피 목록에서 버튼을 눌러 제작하는 요리를, 재료와 조리법을 직접 조합해 숨은 정답을 발견하고 영구 전문 분야를 육성하는 콘텐츠로 교체한다. 기존 음식은 전량 회수하여 기존 기본 소모 재료의 50%를 반환하고, 개편 전 조합을 통해 새 숨은 레시피를 추측할 수 없게 한다.

## 핵심 규칙

- 전체 레시피는 기본 공개 레시피 6종, 전문 분야별 숨은 레시피 16종씩 80종, 교차 분야·만찬·전설 레시피 14종으로 총 100종이다.
- 전문 분야는 화덕, 냄비, 제과, 해산물, 약선의 5종이다.
- 연구자는 해금된 조리법 하나와 재료 2~5종을 직접 고른다. 재료 선택 순서와 수량은 정답에 영향을 주지 않으며 연구 시 선택한 재료를 각각 1개 소비한다.
- 정답 조합에는 완성 음식 1개, 큰 요리 경험치, 미식 연구 점수, 개인 도감 등록, 해당 분야 숙련 경험치를 준다.
- 오답에는 작은 요리 경험치와 실패 음식 부산물을 준다. 동일한 정규화 조합은 소비 전에 차단하며 힌트나 근접도는 제공하지 않는다.
- 다른 사람이 발견한 레시피도 개인이 다시 발견해야 제작할 수 있다. 거래로 산 미발견 음식은 먹을 수 있다.
- 조합 정답과 실제 제작 소모량은 서버 전용 모듈에만 둔다. 클라이언트 번들 및 미발견 API 응답에는 포함하지 않는다.

## 성장과 전문 분야

- Lv.1: 재료 2칸, 굽기·끓이기
- Lv.10: 재료 3칸, 볶기·튀기기
- Lv.20: 재료 4칸, 찌기·오븐
- Lv.35: 재료 5칸, 우리기·발효
- Lv.50 이상: 교차 분야·만찬·전설 레시피
- 요리 Lv.20과 숨은 레시피 개인 발견 10종을 만족하면 주 전문 분야를 고른다.
- 전문 분야는 이중 확인 후 영구 고정하며 변경·초기화할 수 없다.
- 분야 숙련은 5단계이며 발견은 큰 경험치, 제작은 작은 경험치, 조건 납품은 중간 경험치를 준다.
- 선택 분야 음식은 숙련 단계에 따라 기본 성능의 +1~+5%를 받는다. 모든 음식은 분야와 관계없이 발견·제작할 수 있다.
- 기존 요리 직업은 재료 절약, 품질 확률, 희귀 재료 보존 등 제작 효율을 담당하고 전문 분야는 완성 음식 성능을 담당한다.

## 서버 최초 발견

- 레시피별 서버 최초 발견은 DB 고유 제약과 트랜잭션으로 원자적으로 결정한다.
- 최초 발견자의 이름과 발견 시각을 전 서버 도감과 서버 피드에 공개하되 조합은 공개하지 않는다.
- 최초 발견자는 해당 레시피의 영구 원조 권리를 얻는다.
- 원조가 직접 만든 음식은 거래 가능한 `원조` 표식을 가지며 기본 성능의 +10%를 받는다.
- 원조 보너스와 전문 분야 보너스는 음식 생성 시 식별자에 스냅샷하여 거래 후에도 유지한다.

## 음식 효과와 품질

- 음식은 하나만 활성화할 수 있고 모든 지속시간은 12시간이다.
- 같은 음식을 다시 먹어도 누적하지 않고 12시간으로 초기화한다. 다른 음식은 기존 효과를 교체한다.
- PvP, 아레나, 랭킹 전투에서는 기존과 같이 음식 효과를 제외한다.
- 효과군은 1차 능력치 고정값, 공격·마법공격·방어·마법방어·최대 HP/MP·적중 고정값, 낮은 한 자리 능력치 %, 사냥 경험치·골드, 요리/생활 활동 보조로 구성한다.
- 티어별 효과 예산을 두고 복합 효과는 같은 예산을 나눠 쓴다. 전 능력치 10% 같은 효과는 만들지 않는다.
- 능력치 %는 효과별 5% 이하, 사냥 보상은 15% 이하로 제한하고 고정 전투 수치에도 효과별 하드캡을 둔다.
- 일반은 성능 100%·납품 점수 100%, 정성작은 110%·125%, 걸작은 120%·160%다.
- 품질 +20%, 전문 분야 +5%, 원조 +10%는 기본 성능을 기준으로 가산하여 최대 135%다.
- 정수 효과는 최종 반올림하고 소수 효과는 한 자리까지 반올림한다.

## 주방 재료 가공

- 소금, 후추, 기름, 식초, 향신료, 효모는 주방 상점에서 골드로 산다.
- 밀가루, 버터, 치즈, 육수, 소스, 크림은 간단한 주방 가공 메뉴에서 농장·목장 재료로 만든다.
- 새 대형 시설을 추가하지 않고 요리 화면의 `재료 가공` 탭에서 구매·가공한다.

## 납품

- 특정 음식 이름을 요구하는 기존 일일 주문을 없애고 일일 조건 요청 3건과 주간 만찬 1건으로 교체한다.
- 조건은 전문 분야, 조리법, 주재료군, 효과군, 최소 품질을 조합한다.
- 조건을 만족하는 여러 종류의 음식으로 목표 점수를 채울 수 있다.
- 레시피 티어, 품질, 전문 분야 표식, 원조 표식이 점수에 반영되며 납품 전에 적합 여부와 점수를 보여준다.
- 보상은 골드, 농장 평판, 요리 경험치, 전문 분야 경험치다.
- 실패 음식은 납품할 수 없다.
- 상시 납품은 모든 음식의 저가 매입으로 유지하되 일일 수량 제한을 둔다. 일일·주간 요청의 기대 보상이 더 높고 전체 일일 경제량은 기존과 크게 달라지지 않게 한다.

## 상태와 DB

- 개인 상태는 `cooking.v2`에 요리 XP/레벨, 개인 발견 ID, 즐겨찾기, 누적 미식 연구 점수, 영구 전문 분야와 숙련 XP, 주방 재료, 일일·주간 납품 상태, 전승 보상 지급 표식을 저장한다.
- 실패 조합은 무제한 JSON 배열 대신 `(user_id, combo_hash)` 고유 키를 가진 별도 테이블에 저장한다.
- 최초 발견은 `recipe_id`를 기본 키로 하는 별도 테이블에 저장한다.
- 조합 해시는 조리법과 정렬된 재료 ID로 생성한다.
- 기본 6종은 자동 습득하고 숨은 레시피 개인 발견 및 서버 최초 발견 기록은 모두 새로 시작한다.
- 기존 요리 XP와 레벨은 보존한다. 기존 도감 발견 수만 전승 요리 증표 수량으로 스냅샷하고 10/25/45종 구간 한정 칭호·주방 장식을 표시한다. 전승 보상은 새 레시피나 전문 분야 XP를 주지 않는다.

## 기존 음식 전량 회수

- 인벤토리, 활성 거래소 매물, 미수령 거래소 우편에 남은 기존 음식 수량을 소유자별로 모두 합산한다.
- 음식 ID에서 기존 레시피와 희귀 재료 사용 여부를 복원한다. 품질과 지속시간 변형은 반환량에 영향을 주지 않는다.
- 계정별·재료별 기존 기본 소모량을 모두 합산한 뒤 `floor(총량 × 0.5)`를 반환한다. 음식 한 개씩 내림하지 않는다.
- 농장·목장 재료는 `farm.v2`, 어획물은 `fishing.stock.v1`에 반환한다.
- 활성 매물은 취소 처리하고 구매 주문이 있다면 남은 골드 에스크로를 반환한다. 기존 음식 우편은 회수 완료 처리해 나중에 중복 수령할 수 없게 한다.
- 이미 먹었거나 납품해 현재 소유하지 않은 음식은 반환하지 않는다. 적용 중인 기존 음식 효과는 제거한다.
- 마이그레이션은 완료 표식과 SQL/DB 고유 제약으로 멱등성을 보장한다.

## UI와 자산

- 요리 화면을 연구, 도감, 전문 분야, 납품, 재료 가공의 다섯 탭으로 분리한다.
- 모든 최상위·중첩 카드에는 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`를 사용해 배경 이미지가 비치지 않게 한다.
- 45개 기존 요리 이미지는 대응되는 개편 레시피에 재사용하고, 새 ID 55종은 같은 아이템 일러스트 톤의 신규 WebP 자산을 만든다.
- 파일명은 레시피 ID와 일치하는 `public/images/items/cooking/<recipe-id>.webp`로 둔다.

## 검증

- 100개 조합의 정규화 키 중복, 슬롯·레벨·조리법 해금, 이미지 참조를 검사한다.
- 연구 성공·오답·중복 오답 차단, 전문 분야 영구 선택, 원조 경쟁, 효과 예산·하드캡·보너스 합산을 단위 테스트한다.
- 기존 음식 회수는 인벤토리·거래소·우편 혼합 사례와 재실행 멱등성을 DB 통합 테스트로 검증한다.
- API 응답과 클라이언트 모듈 그래프에 미발견 조합이 노출되지 않는 회귀 테스트를 둔다.
- 요리 관련 단위·라우트·컴포넌트 테스트, 타입 검사, ESLint, 이미지 검사, 프로덕션 빌드를 완료한다.
