# 위험 해역 실시간 장력 낚시와 보상 성장 개편 설계

## 배경

현재 위험 해역 낚시는 물고기 정지 이미지 아래에서 `감아올리기`, `줄 풀기`, `버티기`
버튼을 차례로 누르는 방식이다. 화면이 현재 행동과 추천 조작을 직접 알려 주기 때문에
물고기의 움직임을 읽거나 힘을 조절하는 판단이 거의 없다. 각 입력은 서버 응답을 기다린 뒤
반영되어 조작과 화면 반응도 끊긴다.

보상은 어획 즉시 낚시 경험치와 코인을 지급하고 안전 귀환한 화물을 재료로 확정하지만,
일반 어획물의 사용처는 대부분 특수 미끼 교환과 거래소뿐이다. 해역·수심 조합마다 출현
어종이 사실상 한 종이어서 기존 미끼의 출현 가중치도 체감 효과가 없다. `cargoValue`는 사고
손실 계산과 교환 자동 선택에만 쓰여 화면에 보이는 가치가 실제 보상으로 이어지지 않는다.

위험 해역을 일반 낚시와 구별되는 선택형 상위 콘텐츠로 만들기 위해 조우를 실시간 장력
미니게임으로 교체하고, 영구 장비 성장과 안전 귀환 보상을 연결한다.

## 목표

- 누르고 있는 동안 감아올리고 손을 떼면 줄을 풀어 장력을 조절하는 실시간 조작을 제공한다.
- 정답 문구 대신 물고기의 이동과 애니메이션을 읽어 판단하게 한다.
- 입력마다 서버 응답을 기다리지 않는 즉각적인 클라이언트 렌더링을 제공한다.
- 서버가 동일한 결정론적 시뮬레이션으로 결과와 보상을 검증한다.
- 위험도는 체력만 늘리는 대신 안전 구간, 행동 속도와 연계 횟수를 바꾼다.
- 낚시 레벨, 전용 장비와 미끼가 조우 시간과 안정성을 체감 가능하게 개선한다.
- 안전 귀환 어획물에 영구 장비 강화, NPC 판매와 귀환 보너스 사용처를 추가한다.
- 해역별 조우 전용 수중 배경 세 장과 가벼운 물고기 애니메이션을 제공한다.
- 기존 어획물, 장비, 도감, 화물과 거대어 기여 데이터를 보존한다.

## 비목표

- 일반 낚시의 캐스팅, 챔질, 의뢰, 일일 과제와 자동 진행 규칙은 바꾸지 않는다.
- 위험 해역을 일일·주간 숙제로 만들거나 진행도와 재료를 주기적으로 초기화하지 않는다.
- 프레임마다 서버와 통신하거나 WebSocket 기반 실시간 서버 물리를 도입하지 않는다.
- 장비 강화 실패, 파괴, 하락 또는 확률형 성공을 추가하지 않는다.
- 신규 화폐를 추가하지 않는다.
- 이번 설계 문서 작성 자체에는 배포와 점검 모드 변경을 포함하지 않는다.

## 콘텐츠 흐름

1. 출항 화면에서 해역, 수심과 미끼를 선택한다.
2. 서버가 어종, 위험도, 장비·레벨·미끼 보정치, 행동 시드와 제한 시간을 확정한다.
3. 클라이언트가 실시간 조우를 시작한다. 누르면 감고, 떼면 줄을 풀며 물고기의 움직임과
   장력 변화를 즉시 렌더링한다.
4. 어체력과 거리가 모두 0이 되면 서버가 입력 기록을 재현해 어획을 확정한다.
5. 어획 성공 시 기존 낚시 경험치·코인·위험 해역 도감을 즉시 갱신하고 어획물을 화물에
   싣는다.
6. 플레이어는 다시 투척하거나 안전 귀환한다. 안전 귀환 시 화물을 영구 재료로 확정하고
   위험도 기반 귀환 보너스를 받는다.
7. 확정 어획물은 미끼 교환, 장비 강화, 거래소 또는 NPC 일괄 판매에 사용한다.

실패해도 이미 실은 화물과 과거 거대어 기여는 보존한다. 실패 화면에서 다시 투척과 안전
귀환을 모두 선택할 수 있다.

## 실시간 조작과 시뮬레이션

### 입력

- 터치와 마우스: 조작 영역을 누르는 동안 감아올리고, 떼면 줄을 푼다.
- 키보드: `Space`를 누르는 동안 감아올리고, 떼면 줄을 푼다.
- 포인터가 조작 영역 밖으로 나가거나 취소되면 안전하게 `줄 풀기` 상태로 전환한다.
- 브라우저 탭이 숨겨지면 마지막 입력을 `줄 풀기`로 닫는다. 복귀 시 누락된 고정 틱을
  경과 시간만큼 계산해 화면과 서버 체크포인트를 맞춘다.

`버티기` 독립 버튼과 행동별 추천 표시는 제거한다. 장비·미끼가 제공하는 보조 효과는
자동 적용하되 HUD에서 현재 활성 효과를 짧게 표시한다.

### 판정

판정은 렌더 프레임과 분리한 50ms 고정 틱으로 실행한다. 모든 핵심 값은 정수 단위로
계산하며 서버와 클라이언트가 같은 순수 시뮬레이션 함수를 사용한다. 화면은
`requestAnimationFrame`으로 최대 60fps까지 보간한다.

- 감아올리기: 거리를 줄이고 어체력을 소모시키지만 장력이 상승한다.
- 줄 풀기: 장력을 낮추지만 거리가 일부 늘어난다.
- 장력이 상한을 넘으면 줄이 끊어진다.
- 장력이 하한 아래에서 허용 시간 이상 유지되면 바늘이 빠진다.
- 어체력과 거리가 모두 0이 되면 포획에 성공한다.
- 물고기가 쉬거나 방향을 바꾸는 구간은 강하게 감을 기회가 된다.

물고기 행동은 기존 `charge`, `thrash`, `turn`, `dive` 데이터를 유지하되 버튼 정답표가
아니라 이동 곡선과 장력 충격을 결정하는 패턴으로 사용한다. 고위험 행동에도 읽을 수 있는
전조를 두며 입력을 속이는 가짜 동작은 사용하지 않는다.

### 목표 시간

- 일반 어종: 8~15초
- 희귀·영웅 어종: 12~20초
- 전설 어종: 18~25초
- 거대어 개인 시도: 25~40초

목표 시간은 해당 위험도에서 기본 장비와 기본 미끼를 사용하고 행동 전조에 정상적으로
반응했을 때의 범위다. 낚시 레벨, 장비 강화와 미끼를 합친 시간 단축은 기준 시간의 최대
35%로 제한한다. 이 제한은 조우 시작 시 확정한 보정치에 적용하며 진행 중 장비를 바꿔
우회할 수 없다.

## 위험도

위험도는 기존처럼 `해역 기본 위험도 + 수심 위험도`를 0~5로 제한해 계산한다. 위험도별
기본 판정값은 다음과 같다.

| 위험도 | 장력 안전 구간 폭 | 행동 간 최소 간격 | 최대 행동 연계 | 장력 충격 배율 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 52% | 1.60초 | 1 | 0.80 |
| 1 | 50% | 1.50초 | 1 | 0.90 |
| 2 | 46% | 1.40초 | 2 | 1.00 |
| 3 | 42% | 1.25초 | 2 | 1.12 |
| 4 | 38% | 1.10초 | 3 | 1.25 |
| 5 | 34% | 0.95초 | 3 | 1.40 |

위험도가 높아져도 어체력만 크게 늘려 시간을 끌지 않는다. 어종별 어체력과 거리는 목표
시간 범위 안에서 맞추고, 난이도 차이는 짧아지는 판단 시간과 강한 연계 행동에서 만든다.

## 낚시 레벨, 장비와 미끼

### 낚시 레벨

현재 15~50레벨 구간의 `levelAssistPct` 0~10% 성장은 그대로 유지하고 50레벨 이후에는
10%로 고정한다. 확장된 50~100레벨 구간에는 별도의 영구 보정을 선형으로 추가한다.

- 감아올리기 효율: 50레벨 0%에서 100레벨 12%까지 증가
- 장력 제어: 50레벨 0%에서 100레벨 8%까지 증가

기존 낚시 직업 계보와 장착 스킬이 제공하는 전조, 화물 보호와 거대어 발견 보정은 유지한다.
따라서 50레벨 이하 캐릭터의 기존 보정은 낮아지지 않고, 50레벨 이후 성장만 새 조우의
속도와 장력 제어에 추가된다.

### 전용 장비

기존 낚싯대·릴·낚싯줄 ID와 보유·장착 상태를 유지한다. 각 보유 장비에는 `0~3` 강화 단계를
추가한다. 강화는 항상 성공하며 한 번 적용한 단계는 영구 보존한다.

- 낚싯대: 단계당 어체력 피해 6% 증가
- 릴: 단계당 거리 회수량 5% 증가
- 낚싯줄: 단계당 안전 구간 폭 3%p, 화물 보호 2%p 증가

모든 장비의 단계별 공통 비용은 다음과 같다. 같은 희귀도의 위험 해역 어획물은 어종을
섞어 납품할 수 있다.

| 강화 | 어획물 | 낚시 코인 |
| --- | --- | ---: |
| +1 | 일반 6개 + 희귀 4개 | 1,000 |
| +2 | 희귀 8개 + 영웅 5개 | 3,000 |
| +3 | 영웅 8개 + 전설 3개 | 8,000 |

최상급 장비의 최초 획득에 필요한 기존 거대어 증표와 낚시 코인 비용은 유지한다. 획득한
최상급 장비도 같은 확정 강화 규칙을 사용한다.

### 미끼

해역·수심별 출현 어종이 하나인 현재 구조에서 의미가 없는 희귀도 가중치 대신 조우 효과를
부여한다.

- 해역용 기본 미끼: 추가 효과 없음, 무제한
- 암초 향 미끼: `turn` 행동의 거리 회복과 장력 충격 20% 감소
- 핏빛 미끼: `charge`와 `thrash` 중 가하는 어체력 피해 20% 증가
- 발광 미끼: 다음 행동 하나를 HUD에 미리 표시하고 `dive` 속도 15% 감소
- 심연 응축 미끼: 시작 어체력 10% 감소, 모든 행동의 장력 충격 12% 감소

기존 미끼 수량, 묶음 크기와 교환 비용은 유지한다. 미끼 효과는 한 조우에 하나만 적용한다.

## 보상과 사용처

### 즉시 보상

어획 성공 시 기존 어종별 낚시 경험치와 낚시 코인을 그대로 지급한다. 낚시 직업 숙련도,
활동 기록과 위험 해역 도감 갱신도 기존 동작을 유지한다.

### 안전 귀환 보너스

안전 귀환 또는 사고 귀환으로 확정한 화물의 보존 `cargoValue` 합계를 기준으로 낚시 코인을
추가 지급한다.

`귀환 보너스 = floor(보존 화물 가치 × 위험도 × 0.02)`

위험도 0에서는 추가 보너스가 없고 위험도 5에서는 보존 화물 가치의 10%를 받는다. 사고로
잃은 화물은 계산에서 제외한다. 보너스는 귀환 트랜잭션 안에서 어획물 확정과 함께 한 번만
지급한다.

### 어획물 NPC 판매

낚시 상점의 위험 해역 교환에 `어획물 판매`를 추가한다. 판매가는 어종의
`cargoValue × 10` 골드이며 수량을 지정해 일괄 판매할 수 있다. 거래소 판매와 장비 강화가
주 사용처이고 NPC 판매는 남는 재료를 정리하는 하한가 역할만 한다. 판매 전 어종, 수량과
총 골드를 확인한다. 계정 제한 판정은 기존 NPC 판매 정책을 그대로 따르며 위험 어획물
판매가 거래 제한을 우회하는 별도 자산 이전 경로가 되지 않게 한다.

### 기존 교환과 거대어

- 일반·희귀·영웅·전설 어획물의 특수 미끼 교환을 유지한다.
- 거대어 증표의 최상급 장비, 칭호, 영구 프로필 테두리와 잔여 증표 미끼 교환을 유지한다.
- 거대어 보상은 한 번 이상 검증된 개인 시도를 성공하고 공용 거대어가 제압된 뒤 직접
  수령하는 기존 구조를 유지한다.
- 재료, 강화 단계와 보상 진행은 일일·주간·월간으로 초기화하지 않는다.

## 화면과 시각 자산

### 배경

지역 선택에 사용하는 기존 풍경 원화는 유지한다. 실제 조우가 시작되면 다음 전용 수중
배경으로 교체한다.

- `public/images/ui/dangerous-fishing-shattered-reef-encounter.webp`
- `public/images/ui/dangerous-fishing-storm-trench-encounter.webp`
- `public/images/ui/dangerous-fishing-abyssal-rift-encounter.webp`

세 배경은 16:9 측면 수중 구도, 중앙 60%의 낮은 시각 밀도, 우측 상단 낚싯줄 진입 공간을
공통 규칙으로 사용한다. 물고기, 낚싯대, 낚싯줄, UI와 글자는 이미지에 포함하지 않는다.
`ui/` 이미지 최적화 프로필을 재사용하고 코드에서 세 파일을 명시적으로 참조해 이미지 검사에
포함한다.

수심과 위험도는 새 이미지를 더 만들지 않고 클라이언트 효과로 구분한다.

- 수심: 광량, 색온도, 빛줄기와 부유물 밀도
- 위험도: 파도 속도, 기포, 낚싯줄 진동과 제한적인 화면 흔들림

### 물고기 애니메이션

일반 어종은 기존 투명 원화를 세로 조각으로 나눠 꼬리 쪽 변형량이 커지는 파형을 적용한다.
전체 이미지의 위치, 기울기와 크기를 함께 바꿔 유영, 방향 전환, 몸부림, 잠수와 피로 상태를
표현한다. 프레임별 새 원화를 만들지 않는다.

거대어 두 종은 기존 원화 변형에 더해 돌진·몸부림 전용 4프레임 가로 스프라이트 한 장씩을
추가한다. 각 프레임은 동일한 크기와 중심점을 사용하며 투명 배경으로 제작한다.

- `public/images/fish/tidal_colossus-struggle.webp`
- `public/images/fish/abyss_kraken-struggle.webp`

### HUD와 접근성

- 현재 행동명, 정답 설명과 추천 버튼을 제거한다.
- 캔버스 위에는 장력 안전 구간, 어체력, 거리, 제한 시간과 활성 미끼 효과만 DOM으로
  표시한다.
- 장력 상한은 줄 색상, 진동과 경고 문구로, 하한은 느슨한 줄 곡선과 경고 문구로 알린다.
- 캔버스에는 대체 설명을 제공하고 모든 수치 상태를 DOM 텍스트로도 읽을 수 있게 한다.
- `prefers-reduced-motion`에서는 화면 흔들림, 큰 회전과 파티클 수를 줄이되 판정과 시간은
  바꾸지 않는다.
- 지원 환경에서는 고장력 진입과 줄 끊김에만 짧은 진동을 사용한다.
- 배경 위 콘텐츠 패널은 기존 불투명 표면 상수를 사용하며 라이트·다크 모드에서 배경이
  글자 뒤로 비치지 않게 한다.

## 클라이언트와 서버 데이터 흐름

### 공유 시뮬레이션

클라이언트와 서버가 의존성 없는 순수 시뮬레이션 모듈을 공유한다. 입력은 조우 설정,
50ms 틱 번호와 `reel` 또는 `release` 전환 기록이며 출력은 장력, 어체력, 거리, 행동,
상태와 다음 시드 상태다. 난수는 서버가 발급한 시드만 사용한다.

### API

기존 위험 해역 조우 라우트의 요청 종류를 다음 세 단계로 확장한다.

1. `start`: 조우 ID, 시뮬레이션 버전, 시드, 확정 보정치, 서버 시작 시각과 만료 시각 반환
2. `checkpoint`: 마지막 승인 틱 이후 입력 묶음을 검증하고 승인 틱·상태·revision 반환
3. `finish`: 남은 입력을 검증하고 성공·실패 및 보상을 원자적으로 확정

클라이언트는 입력 전환을 메모리와 `sessionStorage`에 기록하고 2초마다 비동기 체크포인트를
보낸다. 체크포인트 응답을 기다리지 않고 로컬 시뮬레이션을 계속한다. 서버 상태와 차이가
발생하면 승인된 틱부터 입력을 다시 재생해 화면을 보정한다.

완료 요청은 `encounterId`, `revision`과 요청 ID로 멱등 처리한다. 같은 완료 요청을 다시
받으면 저장된 최초 결과를 반환하고 경험치, 코인, 화물과 거대어 기여를 중복 지급하지 않는다.
일반 어획과 거대어 개인 시도는 같은 시뮬레이션을 사용하되 거대어 공용 체력 차감은 검증된
개인 성공을 확정한 뒤에만 수행한다.

### 통신 장애와 복구

- 체크포인트 실패는 렌더링과 입력을 막지 않고 지수 백오프로 재시도한다.
- 새로고침하면 `sessionStorage`의 입력과 서버의 마지막 승인 틱을 합쳐 복구한다.
- 완료 후 통신이 끊기면 동일 요청 ID로 재전송한다.
- 클라이언트 기준 완료가 서버 만료 전이고 30초 안에 결과를 제출하면 지연 제출을 허용한다.
- 서버는 제출된 마지막 틱이 서버 시작 후 실제 경과 시간과 30초 유예 범위를 넘지 않는지
  함께 검사해 미래 시점 입력을 거부한다.
- 유효하지 않은 틱, 시간 역행, 불가능한 입력 전환 또는 만료된 조우는 보상 없이 거부한다.
  이때 기존 화물과 과거 기여는 변경하지 않는다.

## 저장 호환성과 전환

- 위험 해역 저장 버전을 올리고 새 조우에 `simulationVersion: 2`를 기록한다.
- 버전 필드가 없는 기존 진행 중 조우는 `simulationVersion: 1`로 해석한다.
- 기존 조우는 배포 뒤에도 기존 세 버튼 화면과 판정 경로로 한 번 끝낼 수 있게 호환 코드를
  유지한다. 종료 또는 만료 뒤 다음 투척부터 새 조우를 사용한다.
- 기존 화물, 어획 도감, 미끼 수량, 장비 보유·장착, 거대어 도감·기여·보상 수령 기록은
  변환 없이 보존한다.
- 장비 강화 상태가 없는 저장값은 모든 보유 장비를 `+0`으로 해석한다.
- 기존 `cargoValue`는 사고 손실 가중치에 계속 사용하며 귀환 보너스와 NPC 판매가 계산에도
  같은 값을 사용한다.

## 오류 처리

- 시작 중 자동 생활 활동이 발견되면 기존과 같이 출항 또는 투척을 거부한다.
- 이미 끝난 조우의 체크포인트는 현재 확정 결과를 반환한다.
- 오래된 revision은 마지막 승인 틱과 상태를 반환해 클라이언트가 재조정하게 한다.
- 렌더링 초기화나 이미지 로딩에 실패하면 파티클과 배경 애니메이션을 끄고 단색 수중 배경,
  정지 어종 이미지와 동일한 누르기·떼기 판정으로 계속 진행한다.
- Canvas API를 사용할 수 없는 환경에는 DOM 기반 정적 대체 화면을 제공한다.

## 테스트

### 도메인

- 같은 시드와 입력 기록이 클라이언트·서버 환경에서 완전히 같은 결과를 만드는지 검증한다.
- 감기·풀기, 장력 상·하한, 포획, 만료와 네 행동 패턴을 고정 틱 테스트로 검증한다.
- 위험도 0~5의 안전 구간, 행동 간격, 연계와 충격 배율을 검증한다.
- 낚시 레벨 15·50·100, 장비 +0·+3, 미끼별 보정과 전체 시간 단축 35% 상한을 검증한다.
- 강화 비용, 확정 강화, 최대 단계와 재료 혼합 선택을 검증한다.
- 귀환 보너스와 NPC 판매가, 사고 손실 뒤 보존 화물만 반영하는 계산을 검증한다.

### 서버

- 시작·체크포인트·완료의 정상 흐름, 오래된 revision과 잘못된 입력을 검증한다.
- 완료 재시도, 동시 완료와 요청 ID 재사용에서 보상이 한 번만 지급되는지 검증한다.
- 거대어 개인 성공만 공용 체력과 기여를 변경하는지 검증한다.
- 안전 귀환 트랜잭션이 재료와 보너스를 함께 확정하는지 검증한다.
- NPC 판매와 장비 강화가 재료·코인·골드를 원자적으로 갱신하는지 검증한다.
- 거래 제한 계정의 NPC 판매와 거래소 판정이 기존 정책을 따르는지 검증한다.
- 버전 없는 기존 조우와 저장값을 읽고 화물·미끼·장비·기여를 보존하는지 검증한다.

### 클라이언트

- 포인터와 Space 누르기·떼기가 동일한 입력 기록을 만드는지 검증한다.
- 2초 체크포인트, 새로고침 복구, 완료 재전송과 서버 상태 재조정을 검증한다.
- 행동 정답과 추천 표시가 제거되고 장력·어체력·거리·시간이 접근 가능한 DOM으로
  표시되는지 검증한다.
- 모션 감소 설정과 Canvas 실패 대체 화면을 검증한다.
- 세 전용 배경과 두 거대어 스프라이트의 참조·크기·프레임 규칙을 이미지 검사에 포함한다.
- 관련 위험 해역 도메인·라우트·렌더 테스트, ESLint, TypeScript, 이미지 검사를 실행한다.

## 구현 순서

범위가 큰 변경이므로 다음 세 묶음으로 나누되 최종 전환 전까지 기존 조우를 기본 경로로
유지한다.

1. **판정 기반:** 결정론적 시뮬레이션, 위험도·레벨·장비·미끼 보정, v2 시작·체크포인트·완료
   API, 저장 버전과 v1 호환 테스트를 구현한다.
2. **플레이 화면:** 해역별 배경 세 장과 거대어 보조 스프라이트 두 장을 제작하고 Canvas
   렌더러, 누르기·떼기 입력, HUD, 복구와 접근성 대체 화면을 연결한다.
3. **보상 성장:** 장비 확정 강화, 안전 귀환 보너스, 어획물 NPC 판매와 상점 UI를 추가하고
   매뉴얼·업데이트 안내를 동기화한다.

각 묶음은 자체 테스트를 통과한 커밋으로 남긴다. 세 묶음과 전체 회귀 검증이 모두 끝난 뒤에만
새 조우를 기본값으로 전환한다. 배포는 이 구현 순서에 포함하지 않는다.

## 문서와 운영

- 게임 매뉴얼의 위험 해역 조작, 위험도, 장비 강화, 미끼 효과, 귀환 보너스와 판매 설명을
  새 규칙으로 교체한다.
- 업데이트 안내에는 일반 낚시가 아니라 위험 해역만 바뀐다는 점과 기존 재료·진행 보존을
  명시한다.
- 실제 배포와 점검 모드 전환은 별도 사용자 지시를 받은 뒤 수행한다.
