# 길드 전투보급 운용비 설계

## 배경

길드원은 개인 골드를 길드 금고에 기부해 개인 명예와 길드 명성을 얻는다. 길드
금고는 길드·시설 승급, 영토 개척과 영지 건설에 쓰이지만 대부분 일회성 사용처다.
길드와 시설이 성장한 뒤에도 기부·탐사·교역·영지 수익은 계속 유입되므로 길드
자금이 누적된다.

## 목표

- 최고 단계 길드도 매주 자발적으로 선택할 수 있는 반복형 길드 자금 사용처를 만든다.
- 명성으로 올리는 영구 전투보급 연구와 골드로 유지하는 주간 운용을 한 화면에 묶는다.
- 기존 사냥 보상 계산과 길드 권한·활동 기록 규칙을 재사용한다.

## 제외 범위

- 자동 유지비나 접속하지 않아도 차감되는 비용은 만들지 않는다.
- 개인에게 아이템이나 골드를 나눠 주는 길드 보급 상자는 만들지 않는다.
- 시설 재료를 골드로 구매하거나 길드 토벌전 규칙을 변경하지 않는다.
- 전투보급이 적용되지 않는 제작·생활·PvP 보상에는 효과를 추가하지 않는다.

## 사용자 경험

길드 연구의 전투보급 화면 상단에 `주간 전투보급 운용` 카드를 추가한다. 카드는
현재 주차, 운용 단계, 길드 자금, 현재 추가 효과, 다음 단계 비용을 보여 준다.

마스터와 관리자는 확인창을 거쳐 한 단계씩 운용비를 결제한다. 일반 길드원은 상태와
효과만 볼 수 있다. 단계별 결제액과 누적 효과는 다음과 같다.

| 운용 단계 | 해당 단계 결제액 | 주간 누적 결제액 | 추가 효과 |
| --- | ---: | ---: | --- |
| 1 | 10,000,000 G | 10,000,000 G | 사냥 골드·EXP +1%p, 추가 숙달 확률 +5%p |
| 2 | 20,000,000 G | 30,000,000 G | 사냥 골드·EXP +2%p, 추가 숙달 확률 +10%p |
| 3 | 40,000,000 G | 70,000,000 G | 사냥 골드·EXP +3%p, 추가 숙달 확률 +15%p |

운용비는 결제 즉시 길드 금고에서 차감되고 같은 주의 현재·이후 길드원 사냥에
적용된다. 연구가 Lv.10이어도 운용 효과는 별도로 더해져 최대 골드·EXP +13%, 추가
숙달 확률 65%가 된다. 운용 단계는 매주 월요일 00:00 KST에 0으로 돌아간다. 별도
초기화 작업은 두지 않고 저장된 활성화 시각의 KST 주차와 현재 주차가 다르면 0으로
해석한다.

## 데이터와 계산

신규 테이블이나 마이그레이션은 만들지 않는다. `guilds.buffs`의 기존 슬롯 배열에
다음 항목을 저장한다.

```ts
{
  buffId: "combat_operations",
  tier: 1 | 2 | 3,
  installedAt: string, // 해당 주의 마지막 단계 결제 시각 ISO 문자열
}
```

순수 데이터 모듈은 운용 단계 비용, 단계 정규화, 현재 주차 판정, 슬롯 갱신과 최종
보너스 합산을 담당한다. 영구 연구 슬롯을 갱신할 때도 `combat_operations` 슬롯을
삭제하지 않는다. 반대로 운용 슬롯 갱신은 기존 연구와 다른 길드 버프를 보존한다.

사냥 서버는 길드의 영구 연구 단계와 현재 주 운용 단계를 한 번에 읽고 다음처럼
최종 보너스를 계산한다.

```ts
goldPct = permanentGoldLevel + operationsTier
expPct = permanentExpLevel + operationsTier
proficiencyChancePct = permanentProficiencyLevel * 5 + operationsTier * 5
```

무소속, 잘못된 슬롯, 지난 주 슬롯은 운용 0단계로 처리한다.

## API와 원자성

기존 `/api/v2/guild/combat-supply`를 확장한다.

- `GET`은 기존 연구 정보와 함께 `guildGold`와 주간 운용 상태를 반환한다.
- 기존 `POST { supplyId }`는 그대로 유지한다.
- `POST { action: "fund_operations" }`는 현재 주 운용을 정확히 한 단계 올린다.

운용 결제는 사용자·IP 속도 제한과 마스터/관리자 권한을 확인한다. 트랜잭션 안에서
길드 자금 행을 먼저 잠근 뒤 길드 행을 잠가 현재 주 단계를 다시 계산한다. 최고 단계,
자금 부족, 해산 길드 상태는 차감 없이 거절한다. 길드 자금 차감, 운용 슬롯 갱신,
활동 기록은 한 트랜잭션에서 처리한다. 동시 요청은 잠금 뒤 최신 단계 비용을 사용하므로
같은 단계를 중복 결제하지 않는다.

오류 코드는 기존 `not_allowed`, `no_guild`, `guild_not_found`에 더해
`operations_maxed`, `insufficient_gold`, `invalid_action`을 사용한다.

## 활동 기록

결제 성공 시 `combat_supply_funding` 활동을 남긴다. 메타데이터에는 새 운용 단계와
실제 차감한 길드 골드를 기록한다. 활동 문구는 다음 형식이다.

`OO 님이 주간 전투보급 운용을 Lv N로 강화했어요 · 길드 자금 -X G`

이 활동은 관리자 지출 기록이며 개인 기여 점수를 만들지 않는다.

## UI와 표면

운용 카드는 `src/components/ui/surfaces.ts`의 불투명 `SURFACE_CARD`와
`SURFACE_INSET`을 사용한다. 컨테이너 전체 투명도는 사용하지 않고 버튼의 비활성
투명도만 허용한다. 라이트·다크 모드에서 배경 이미지가 본문과 중첩 카드 뒤로 비치지
않게 한다.

결제 전 확인창에는 새 단계, 이번 결제액, 적용 효과, 월요일 초기화를 명시한다.
결제 뒤에는 응답으로 받은 최신 길드 자금과 운용 단계를 즉시 표시한다.

## 테스트와 검증

- 순수 함수 테스트: 비용 곡선, KST 주차 경계, 지난 주 만료, 슬롯 보존, 최대 연구
  단계 위의 운용 효과 합산.
- API 회귀 테스트: 관리자 성공 결제, 일반 길드원 거절, 자금 부족 무차감, 주간 최대
  단계 거절, 지난 주 슬롯의 1단계 재시작, 동시 처리에 필요한 잠금 순서와 활동 기록.
- UI 테스트: 확인 취소 시 요청하지 않음, 확인 문구에 비용·효과·초기화 포함.
- 통합 검증: 관련 Vitest, TypeScript 검사, ESLint, 이미지 참조 검사.

## 운영

스키마 변경과 데이터 이관은 없다. 지난 주 슬롯은 남아 있어도 효과 계산에서 자동으로
무시되며 다음 결제 때 같은 슬롯을 덮어쓴다. 배포와 점검 모드 변경은 이 작업 범위에
포함하지 않는다.
