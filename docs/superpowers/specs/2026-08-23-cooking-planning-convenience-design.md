# 요리 계획 편의성 개선 설계

## 목표

요리 도감에서 레시피별 기본 조리 경험치를 확인할 수 있게 하고, 재료 가공 화면에서 조미료 구매와 중간 재료 가공 수량을 직접 지정할 수 있게 한다.

## 범위

- 발견한 레시피 카드에 `기본 조리 XP +N`을 표시한다.
- 주방 상점의 각 품목에 1~100 범위의 구매 수량 입력을 제공한다.
- 주방 가공의 각 레시피에 현재 보유 재료로 만들 수 있는 수량 범위의 입력을 제공한다.
- 선택 수량에 맞춰 구매 총액과 가공 필요 재료 수량을 즉시 갱신한다.
- 기존 `/api/v2/cooking`의 `quantity` 계약과 서버 검증은 변경하지 않는다.

## 설계

### 도감 경험치

도감 응답의 `knownRecipes`에는 서버가 조리에 사용하는 `craftXp`가 이미 포함되어 있다. 발견한 레시피의 효과 설명 아래에 `기본 조리 XP +{craftXp}`를 표시한다. 장비, 직업, 음식 버프에 따른 최종 획득량은 상황에 따라 달라지므로 기본값임을 명시한다. 미발견 레시피에는 경험치를 노출하지 않는다.

### 구매 수량

각 상점 행이 독립적인 수량 상태를 가진다. `DraftNumberInput`으로 빈 입력 중 상태를 허용하고 포커스를 벗어나거나 값이 변할 때 1~100 정수로 보정한다. 구매 버튼은 `{수량}개 · {총액}골드 구매`로 표시하고 선택 수량을 기존 `buy_pantry` mutation에 전달한다.

### 가공 수량

각 가공 행은 필요한 농장 재료와 현재 보유량으로 최대 가공 가능 수량을 계산하고 서버 한도 100을 적용한다. 수량 입력은 1부터 계산된 최대치까지 보정한다. 선택 수량에 맞춰 필요 재료 수량을 표시하고 기존 `process` mutation에 전달한다. 하나도 만들 수 없으면 입력과 버튼을 비활성화하고 `재료 부족`을 표시한다.

## UI와 접근성

- 기존 불투명 `SURFACE_CARD`, `SURFACE_INSET` 표면을 유지한다.
- 각 입력에 품목명을 포함한 `aria-label`을 제공한다.
- 모바일 폭에서도 줄바꿈될 수 있도록 행을 세로/가로 혼합 레이아웃으로 구성한다.
- 비활성 상태는 카드 전체 투명도가 아니라 입력·버튼 상태와 텍스트 색으로 표현한다.

## 오류 처리

클라이언트는 입력을 유효 범위로 보정하지만 최종 권한은 기존 서버 검증에 둔다. 요청 도중 데이터가 달라져 재료나 골드가 부족해지면 기존 오류 메시지를 그대로 사용한다.

## 테스트

- 발견한 도감 카드가 레시피의 기본 조리 경험치를 표시하는지 검증한다.
- 구매 수량 변경 시 총액과 mutation의 `quantity`가 함께 바뀌는지 검증한다.
- 가공 수량 변경 시 필요 재료 표시와 mutation의 `quantity`가 함께 바뀌는지 검증한다.
- 가공 가능 최대치를 넘는 입력이 보유 재료 기준으로 제한되는지 검증한다.

## 제외 범위

- 요리 자체의 다중 조리 UI 변경
- 경험치 공식 변경
- 구매·가공 서버 한도 변경
- 배포
