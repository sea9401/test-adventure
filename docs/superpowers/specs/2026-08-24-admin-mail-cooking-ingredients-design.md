# 관리자 대량 우편 요리 재료 첨부 설계

## 목표

관리자 공지·우편 화면에서 요리 전용 재료를 선택해 한 명 또는 전체 사용자에게 보내고, 수신자가 우편을 받으면 `cooking.v2.kitchenItems`에 안전하게 적립한다.

## 대상 품목

- 상점 재료 6종: 소금, 후추, 조리용 기름, 숙성 식초, 향신료, 효모
- 가공 재료 6종: 밀가루, 버터, 치즈, 진한 육수, 만능 소스, 생크림
- 농장 작물과 어획물은 각자의 별도 인벤토리에 속하므로 이번 `요리 재료` 범위에 포함하지 않는다.

## 데이터 흐름

1. 관리자 화면은 위 12종을 `요리 재료 첨부` 선택기에 표시한다.
2. 클라이언트는 `cookingIngredients: { ingredientId, count }[]`를 `/api/admin/mail`로 보낸다.
3. 관리자 API는 실제 요리 재료 카탈로그 ID와 양의 정수 수량만 허용하고, 기존 첨부와 함께 `admin_gift` 우편 페이로드에 저장한다.
4. 우편 파서는 이 필드를 정규화한다. 필드가 없는 기존 우편은 빈 배열로 처리한다.
5. 수령 API는 유효한 항목을 합산해 `cooking.v2.kitchenItems`에 적립하고 응답에 지급 내역을 포함한다.

## 안전성과 호환성

- 기존 `materials` 필드에 섞지 않아 `character.v2.materials`로 잘못 들어가는 것을 방지한다.
- 관리자 API의 기존 항목 수 상한과 개별 수량 상한을 동일하게 적용한다.
- 요리 재료만 첨부한 우편도 유효한 보상으로 취급한다.
- 손상되거나 알 수 없는 요리 재료 ID는 수령 저장소에 넣지 않는다.
- 배포는 수행하지 않는다.

## 검증

- 관리자 화면에 12종 선택기가 노출되는지 검증한다.
- 관리자 API가 유효한 요리 재료만 우편에 보존하는지 검증한다.
- 우편 페이로드의 신규 필드와 레거시 기본값을 검증한다.
- 수령 시 기존 수량에 누적되고 다른 저장소로 새지 않는지 검증한다.
