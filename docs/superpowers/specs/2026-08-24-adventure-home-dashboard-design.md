# 개인화 모험 홈 및 활동 알림 설계

## 배경

게임에 전투, 생활, 길드, 일일·주간 보상이 늘면서 사용자가 각 화면에 직접 들어가야 무엇을 했고 무엇이 남았는지 알 수 있게 되었다. 콘텐츠 양 자체보다 상태 정보가 여러 화면에 흩어진 점이 문제다. 현재 모험 홈은 캐릭터 정보, 퀘스트 안내, 공지와 랭킹을 보여주지만 아레나, 원정, 숙련의 탑, 농장, 낚시, 길드 시설 등의 현재 상태를 모아 보지 못한다.

이번 개편은 기존 무슨무슨게임의 마을 배경, 캐릭터 카드, 상단 메뉴와 카드 디자인을 유지하면서 모험 홈에 개인화 가능한 상태 대시보드를 더한다. 목업 검토 결과, 일반적인 스케줄러 화면으로 홈을 교체하지 않고 기존 홈을 위젯화하는 방향과 캐릭터 정보를 요약 상태로 접는 안을 채택한다.

## 목표

- 사용자가 오늘과 이번 주에 완료한 일, 남은 일, 지금 처리 가능한 작업을 모험 홈에서 파악한다.
- 메인 탭의 작은 알림으로 어느 영역에 처리 가능한 일이 있는지 알 수 있다.
- 하지 않는 콘텐츠는 체크 목록과 알림에서 제외할 수 있다.
- 기존 홈의 캐릭터 중심 분위기와 게임 디자인 시스템을 유지한다.
- PC와 모바일에서 같은 정보 순서를 사용하되 화면 폭에 맞게 안정적으로 배치한다.
- 위젯의 순서와 표시 여부를 사용자가 정할 수 있다.

## 비목표

- 전투, 마을, 캐릭터, 길드의 개별 화면을 새 디자인으로 전면 교체하지 않는다.
- 콘텐츠 보상, 입장 횟수, 초기화 주기와 게임 밸런스를 변경하지 않는다.
- PC 전용 2차원 격자나 임의 크기 조절 기능을 만들지 않는다.
- 모든 미완료 콘텐츠를 경고로 취급하거나 빨간 알림을 계속 표시하지 않는다.
- 홈에서 여러 콘텐츠의 보상을 일괄 수령하거나 작업을 원격 실행하지 않는다.

## 정보 구조

### 기본 위젯

모험 홈의 콘텐츠를 다음 위젯으로 분리한다.

1. `character_summary` — 캐릭터 요약
2. `activity_checklist` — 오늘의 모험 체크
3. `quest_rewards` — 받을 수 있는 퀘스트 보상과 가이드
4. `hot_time` — 진행 중인 핫타임
5. `announcements` — 최근 공지
6. `bulletin_preview` — 최근 게시글
7. `ranking_preview` — 모험가 명예 기록

기본 배치는 캐릭터 요약, 오늘의 모험 체크, 퀘스트 보상, 핫타임, 공지, 최근 게시글, 랭킹 순서다. 값이 없는 핫타임이나 받을 보상이 없는 퀘스트 위젯은 빈 카드 대신 렌더링하지 않지만 저장된 순서에서는 자리를 유지한다.

위젯 순서는 하나의 선형 배열로 저장한다. 모바일은 이 순서를 그대로 한 열로 표시한다. PC는 캐릭터 요약과 오늘의 모험 체크를 전체 너비로, 공지·게시글·랭킹처럼 짧은 위젯을 반 너비로 배치한다. 반 너비 위젯은 저장 순서를 바꾸지 않고 인접한 항목끼리만 한 행에 묶는다.

### 캐릭터 요약

캐릭터 위젯은 기본적으로 접힌 상태로 시작한다. 접힌 상태에서도 다음 정보는 남긴다.

- 프로필 이미지
- 이름, 레벨, 현재 직업과 길드
- HP와 MP
- 펼치기 버튼

펼치면 현재 캐릭터 카드가 제공하는 경험치, 장비 슬롯, 음식 효과, 모험 지원권, 프리셋과 전시 정보를 모두 확인할 수 있다. 접기·펼치기 상태는 계정에 저장한다. 위젯 자체도 이동하거나 숨길 수 있으며, 숨긴 위젯은 홈 편집의 위젯 추가 목록에서 복구한다.

### 오늘의 모험 체크

활동을 세 종류로 나눈다.

- `daily` — 일일 횟수, 일일 보상과 일일 납품
- `weekly` — 주간 횟수, 주간 보상과 주간 기록
- `ready` — 수확, 채집, 제작처럼 시간이 지나 현재 처리 가능해진 작업

일일·주간 항목만 `완료 N/M` 계산에 포함한다. `ready` 항목은 하루에도 다시 준비될 수 있으므로 완료율에 넣지 않고 `지금 가능한 행동 N개`로 별도 표시한다. 이 구분으로 수확 후 다시 작물을 심었을 때 오늘의 완료율이 역행하지 않게 한다.

각 활동 상태는 다음 중 하나다.

- `completed` — 현재 초기화 주기의 목표나 보상 처리를 마침
- `actionable` — 지금 입장, 수령, 납품, 수확 또는 완료 확인이 가능함
- `in_progress` — 진행 중이지만 아직 처리할 수 없음
- `unavailable` — 미해금, 조건 미충족 또는 조회 실패

목록 우선순위는 보상 수령 가능, 완료된 시간 작업, 초기화가 가까운 미완료 활동, 일반 진행 중, 완료 순이다. 사용자는 일일, 주간, 생활·길드 그룹을 접거나 펼칠 수 있다. 각 행의 버튼은 보상을 대신 처리하지 않고 실제 콘텐츠의 정확한 화면과 탭으로 이동한다.

### 초기 활동 카탈로그

초기 버전은 현재 게임에 이미 존재하는 다음 상태를 등록한다.

- 일일·주간 반복 퀘스트와 수령 가능한 묶음 보상
- 출석 확인
- 아레나의 일일 참여 상태
- 원정의 일일 참여 상태
- 숙련의 탑 주간 진행과 수령 가능한 보상
- 낚시 일일 과제, 오늘의 의뢰와 주간 과제·보상
- 농장 일일·주간 납품과 수확 가능한 밭
- 벌목·채광 완료 작업
- 길드 토벌 참여·보상
- 길드 훈련, 대장간과 기타 시설의 완료·수령 가능한 작업

장기 업적, 도감 수집률, 단순 성장 권장 사항은 기본 체크 항목에 포함하지 않는다. 필요하면 후속 활동 카탈로그에서 기본 비활성 항목으로 추가한다.

## 개인 설정

### 체크 항목 관리

해금된 기본 활동은 처음 해금할 때 자동으로 활성화하고 한 번만 안내한다. 사용자는 `체크 항목 관리`에서 활동별 표시 여부를 바꿀 수 있다. 비활성화한 활동은 다음 모두에서 제외한다.

- 일일·주간 완료율의 분자와 분모
- 지금 가능한 행동 수
- 모험 홈 활동 목록
- 메인 탭과 하위 메뉴의 알림
- 초기화 임박 안내

위젯 숨김과 체크 항목 비활성화는 서로 다른 설정이다. 예를 들어 활동 체크 위젯을 홈에서 숨겨도 활성화된 활동의 메인 탭 알림은 유지한다. 알림까지 끄려면 체크 항목 관리에서 해당 활동을 비활성화해야 한다.

### 홈 편집

평상시에는 드래그를 비활성화해 스크롤 중 오조작을 막는다. `홈 편집` 버튼을 누른 동안에만 다음 기능을 제공한다.

- 드래그 핸들로 위젯 순서 변경
- 키보드와 모바일용 위·아래 이동 버튼
- 위젯 숨기기
- 숨긴 위젯 다시 추가
- 기본 배치로 초기화

스킬 페이지의 포인터 기반 순서 변경 UX를 참고하되 홈 전용 순수 순서 변경 로직과 접근 가능한 조작을 별도 컴포넌트로 만든다. 드래그 도중에는 링크와 위젯 내부 버튼이 실행되지 않는다. 변경은 낙관적으로 화면에 반영한 뒤 서버 저장이 실패하면 직전 순서로 되돌리고 안내한다.

## 메인 탭 알림

알림은 빨간 경고가 아니라 작은 주황색 점을 사용한다. 메인 탭은 활성화된 하위 활동 중 `actionable` 상태가 하나 이상일 때만 점을 표시한다. 드롭다운을 열면 실제 원인이 된 하위 메뉴에도 같은 점을 표시한다.

단순히 미완료라는 이유만으로 알림을 표시하지 않는다. 시간 작업이 진행 중이거나 현재 조건상 행동할 수 없는 항목은 점을 만들지 않는다. 여러 건이 있어도 메인 탭에는 숫자를 넣지 않고 하나의 점만 사용하며, 상세 개수는 오늘의 모험 체크에서 확인한다. 색상만으로 상태를 전달하지 않도록 접근성 이름에는 `처리 가능한 항목 있음`을 포함한다.

활동과 메인 탭의 기본 연결은 다음과 같다.

- 전투 콘텐츠 → `battle`
- 농장, 낚시, 벌목, 채광, 생활 작업장과 주방 → `life`
- 반복 퀘스트 → `character`
- 출석처럼 메인 6탭 밖에 실제 진입점이 있는 콘텐츠 → 메인 탭 점 없음
- 길드 콘텐츠 → `guild`

모험 탭 자체에는 다른 탭의 합산 점을 다시 표시하지 않는다. 상단 탭 전체가 항상 켜지는 것을 막고, 홈에 들어오면 활동 위젯의 `지금 가능한 행동` 요약으로 전체 상태를 보여준다.

## 저장 모델

새 `saves_kv` 키 `adventure-home.v1`을 사용한다.

```ts
type AdventureHomeWidgetId =
  | "character_summary"
  | "activity_checklist"
  | "quest_rewards"
  | "hot_time"
  | "announcements"
  | "bulletin_preview"
  | "ranking_preview";

type AdventureHomePreferences = {
  version: 1;
  widgetOrder: AdventureHomeWidgetId[];
  hiddenWidgetIds: AdventureHomeWidgetId[];
  characterExpanded: boolean;
  activityEnabled: Record<string, boolean>;
  seenUnlockedActivityIds: string[];
};
```

파서는 알 수 없는 위젯과 활동 ID를 버리고 중복을 제거한다. 새 기본 위젯은 기존 사용자의 저장 배열 뒤에 자동으로 보충한다. `widgetOrder`와 `hiddenWidgetIds`에 같은 ID가 있으면 숨김을 우선하되 순서 배열에는 ID를 유지해 복구 위치를 보존한다. 설정 저장에 DB 스키마 마이그레이션은 필요하지 않다.

## 활동 상태 계약

서버가 클라이언트에 원시 세이브를 보내지 않도록 공통 활동 뷰를 사용한다.

```ts
type AdventureActivityView = {
  id: string;
  group: "daily" | "weekly" | "ready";
  tab: "battle" | "town" | "life" | "character" | "guild" | null;
  title: string;
  detail: string;
  href: string;
  state: "completed" | "actionable" | "in_progress" | "unavailable";
  current?: number;
  target?: number;
  resetAt?: number;
  readyAt?: number;
  enabled: boolean;
  defaultEnabled: boolean;
};
```

`detail`과 `href`는 서버가 활동별 정의에서 생성한다. 클라이언트는 임의 URL을 조립하지 않는다. 시간은 서버 기준 절대 시각으로 전달하고 남은 시간 표시는 응답의 `serverNow`를 기준으로 계산한다.

## API와 데이터 흐름

### 조회

`GET /api/v2/adventure-dashboard`가 다음을 반환한다.

- `serverNow`
- 파싱된 홈 설정
- 활성·비활성 상태를 포함한 해금 활동 목록
- 일일·주간 완료 요약과 지금 가능한 행동 수
- 메인 탭과 하위 경로별 알림 여부

필요한 `saves_kv` 키는 키 목록을 조건으로 한 번에 조회하고, 관계형 테이블 상태는 독립된 작은 조회로 병렬 처리한다. 활동별 resolver는 선언된 입력만 받아 공통 `AdventureActivityView`로 변환한다. 하나의 resolver 실패가 전체 응답을 실패시키지 않으며 해당 활동만 `unavailable`로 처리한다.

게임의 영속 크롬에 `AdventureDashboardProvider`를 두어 대시보드 스냅샷을 한 번 로드한다. `MainTabNav`와 `V2AdventureHome`은 같은 스냅샷을 사용해 중복 요청과 서로 다른 알림 상태를 피한다. 다음 시점에 갱신한다.

- 게임 레이아웃 최초 진입
- 경로 이동 후
- 창이 다시 활성화됐을 때
- 활동 완료 mutation이 전역 게임 상태 갱신을 요청했을 때
- 일일·주간 초기화 시각을 클라이언트가 통과했을 때

진행 중 타이머의 남은 시간은 클라이언트에서 표시하되 상태를 임의로 `actionable`로 바꾸지 않는다. `readyAt`을 통과하면 대시보드 스냅샷을 다시 요청해 서버 상태를 확정한다.

### 설정 변경

`PATCH /api/v2/adventure-dashboard/preferences`는 전체 정규화 설정을 받아 서버에서 허용된 위젯과 활동만 저장한다. 홈 편집 완료, 캐릭터 접기·펼치기, 체크 항목 변경은 이 계약을 공유한다. 빠른 연속 변경은 마지막 상태만 저장하도록 클라이언트에서 합치되 서버는 매 요청을 독립적으로 검증한다.

## 컴포넌트 경계

- `AdventureDashboardProvider` — 스냅샷 조회, 새로고침과 설정 mutation
- `AdventureHomeWidgetGrid` — 저장 순서에 따른 반응형 위젯 배치
- `AdventureHomeEditor` — 편집 모드, 순서 변경, 숨김과 복구
- `CompactCharacterSummary` — 접힌 캐릭터 상태와 기존 카드 펼침
- `AdventureActivityChecklist` — 활동 그룹, 우선순위와 바로가기
- `AdventureActivitySettings` — 개인별 체크 항목 관리
- `MainTabActivityDot` — 탭과 하위 메뉴의 접근 가능한 주황색 점
- 활동별 server resolver — 도메인 상태를 공통 활동 뷰로 변환

각 기존 공지, 퀘스트와 랭킹 컴포넌트는 위젯 래퍼 안에서 재사용한다. 개별 콘텐츠 화면은 홈 때문에 레이아웃을 바꾸지 않고 필요한 깊은 링크 쿼리만 지원한다.

## 반응형 UI와 디자인 시스템

- 최상위 폭은 현재 게임의 720px·확장 864px 규칙을 유지한다.
- 마을 배경 위 모든 본문 카드에는 `SURFACE_CARD`, 중첩 행에는 `SURFACE_INSET`, 수령 가능 강조에는 `SURFACE_ACCENT`를 사용한다.
- 모바일은 모든 위젯을 한 열로 표시하며 가로 스크롤이 생기지 않는다.
- PC의 반 너비 위젯도 사용자가 저장한 선형 순서를 바꾸지 않는다.
- 카드 전체에 투명도나 반투명 배경을 사용하지 않는다.
- 알림 점, 체크 아이콘, 상태 문구를 함께 사용해 색각에 의존하지 않는다.
- 편집 모드의 드래그 핸들은 최소 44px 터치 영역을 제공한다.
- 사용자가 모션 감소를 요청하면 순서 이동과 펼침 전환 애니메이션을 제거한다.

## 오류와 경계 상황

- 대시보드 전체 조회가 실패하면 기존 캐릭터 홈, 퀘스트, 공지와 랭킹은 계속 표시하고 활동 위젯에만 재시도 안내를 표시한다.
- 일부 활동 조회가 실패하면 해당 항목을 완료율과 알림에서 제외하고 `상태 확인 불가`로 표시한다.
- 설정 저장 실패 시 낙관적 변경을 되돌리고 시스템 메시지를 표시한다.
- 카탈로그에 남아 있지만 현재 잠긴 활동은 저장된 활성 설정을 보존하되 UI와 완료율에서 제외한다. 다시 해금되면 이전 선택을 복원한다. 카탈로그에서 완전히 삭제된 알 수 없는 ID는 파서가 제거한다.
- 새 활동이 추가되면 해금 시 기본 활성화하고 한 번 안내한다. 사용자가 끈 활동은 다음 해금이나 초기화 때 자동으로 다시 켜지지 않는다.
- 홈의 바로가기 대상이 일시적으로 접근 불가능해지면 대상 화면이 기존 권한·조건 오류를 처리하며 대시보드는 보상을 선차감하지 않는다.

## 테스트

### 순수 로직

- 위젯 순서·숨김·새 기본 위젯 보충 파싱
- 활동 상태별 우선순위 정렬
- 활성 활동만 사용하는 완료율과 알림 집계
- 반복 가능한 `ready` 활동이 완료율에 포함되지 않는 규칙
- 하위 활동에서 메인 탭 점을 도출하는 규칙
- 신규 해금, 사용자 비활성화와 재해금 처리

### API

- 여러 저장 상태를 올바른 활동 뷰로 변환
- 하나의 resolver 실패 시 나머지 활동과 응답 유지
- 잘못된 위젯·활동 ID를 저장하지 않는 설정 검증
- 다른 사용자의 설정이나 상태를 읽고 쓸 수 없음
- 초기화 경계 전후의 일일·주간 상태

### UI

- 캐릭터 요약의 기본 접힘과 저장된 펼침 복원
- 홈 편집 중에만 순서 변경 가능
- 포인터 드래그, 키보드와 위·아래 버튼 순서 변경
- 위젯 숨김·복구와 기본 배치 초기화
- 체크 항목 비활성화 시 목록, 완료율과 탭 점이 함께 사라짐
- 탭과 드롭다운 하위 메뉴의 접근 가능한 알림
- 모바일 320·360·390px에서 첫 화면에 캐릭터 요약과 활동 요약이 함께 보임
- 라이트·다크 모드에서 배경이 카드 본문으로 비치지 않음

### 회귀 검증

- 기존 모험 홈의 캐릭터 정보, 퀘스트 보상, 공지와 랭킹 기능 유지
- 다른 게임 경로의 메인 탭 이동과 드롭다운 동작 유지
- 전체 타입 검사, 린트, 테스트와 프로덕션 빌드

## 단계별 구현

1. 활동 계약, 설정 파서와 저장 API를 만든다.
2. 활동 resolver와 대시보드 조회 API를 추가한다.
3. 영속 provider와 메인 탭 알림을 연결한다.
4. 기존 모험 홈을 위젯 그리드로 옮기고 캐릭터 요약·활동 체크를 추가한다.
5. 홈 편집과 체크 항목 관리 UI를 연결한다.
6. 모바일·다크 모드·접근성과 전체 회귀를 검증한다.

## 배포

이 설계와 구현은 로컬 변경만 다룬다. 운영 배포와 점검 모드 변경은 사용자가 별도로 요청할 때만 진행한다.
