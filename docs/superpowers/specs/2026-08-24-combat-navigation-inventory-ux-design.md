# 전투 결과·생활 내비게이션·인벤토리 밀도 개선 설계

## 배경

개별 화면에 필요한 기능은 갖춰져 있지만 모바일에서 정보의 중요도와 화면 점유율이 맞지 않는 구간이 있다.

- 일반 사냥은 던전명, 난이도 안내, 전체 캐릭터 상태와 사냥 조작부 뒤에 결과가 나타나 스크롤해야 확인할 수 있다.
- 마을 드롭다운에는 마을 시설과 농장·주방·생활 작업장이 섞여 있으며 각 생활 콘텐츠의 현재 상태는 해당 화면에 들어가야 알 수 있다.
- 인벤토리의 장착 장비 6칸은 모바일에서 2열 3줄, 칸당 최소 100px 이상을 사용한다. 장비명과 해제 버튼을 보여주기 위해 첫 화면 대부분을 차지한다.

이번 개선은 기존 상단 메뉴, 카드, 아이콘 색과 게임 배경을 유지하면서 결과와 상태 정보를 더 빨리 파악하도록 정보 밀도와 순서를 조정한다. 시각 검토에서 전투 결과는 B안인 하단 시트, 장착 장비는 A안인 모바일 3열 2줄을 채택했다.

## 목표

- 사냥이 끝난 직후 스크롤 없이 승패와 핵심 보상을 확인한다.
- 마을 시설과 생활 콘텐츠의 탐색 경로를 분리한다.
- 생활 메뉴를 열면 농장, 낚시, 채집 등의 진행 상태를 함께 확인한다.
- 모바일 인벤토리 첫 화면에서 장착 장비 6개와 보유 장비 목록 일부를 함께 본다.
- PC와 모바일에서 같은 정보와 기능을 제공하되 각 폭에 맞는 배치를 사용한다.
- 기존 디자인 시스템과 불투명 표면 규칙을 유지한다.

## 비목표

- 전투 계산, 보상, 사냥 횟수와 회복 규칙을 변경하지 않는다.
- 생활 콘텐츠의 초기화 주기나 완료 조건을 변경하지 않는다.
- 인벤토리의 장착, 해제, 비교, 잠금, 판매와 도감 등록 규칙을 변경하지 않는다.
- 상단 헤더에 모든 콘텐츠의 숫자와 타이머를 상시 노출하지 않는다.
- 모바일에서 메인 메뉴 여섯 개를 화면 폭에 맞추기 위해 글자 크기나 터치 영역을 과도하게 줄이지 않는다.
- 이 설계만으로 전체 게임 화면을 새 디자인 시스템으로 교체하지 않는다.

## 1. 전투 결과 하단 시트

### 던전 화면의 기본 정보 압축

결과 표시 방식과 별개로 던전 화면의 중복된 상단 정보를 한 카드로 합친다.

- 첫 줄: 뒤로, 던전명, 도전·특수 상태
- 둘째 줄: 거점명, 내 전투력, 난이도 지표, 사냥 안정도
- 캐릭터 상태: 이름, 레벨, HP, MP와 경험치만 보이는 요약형
- 공격력, 방어력, 회복 수치 등 상세 상태는 펼침 영역에서 확인

난이도 지표는 입장 가능 여부처럼 오해되지 않도록 기존 설명을 유지하고, 안정도 문구와 시각적으로 구분한다. 배경 위의 카드에는 `SURFACE_CARD`, 중첩 상태 행에는 `SURFACE_INSET`을 사용한다.

### 결과 시트 동작

단일 사냥 또는 묶음 사냥이 완료되면 결과를 페이지 아래에 추가하는 대신 하단 결과 시트를 연다.

시트는 다음 순서로 표시한다.

1. 승리·패배와 대상 이름
2. 경험치, 골드, 숙련도 등 핵심 변화
3. 획득 아이템과 수량
4. 회복약 사용, 레벨 상승, 특별 보상 같은 부가 변화
5. `다시 사냥` 기본 버튼
6. `닫기`와 `전투 기록 보기` 보조 동작

묶음 사냥은 각 전투마다 시트를 열지 않고 전체 묶음이 끝났을 때 한 번만 요약을 표시한다. 자동으로 이어지는 전투가 있다면 반복 중에는 열지 않고 정지 또는 정산 시점에만 연다.

모바일에서는 화면 아래에서 올라오는 `dialog` 형태로 표시하고 최대 높이를 `75dvh`로 제한한다. 내용이 길면 페이지가 아니라 시트 본문만 스크롤한다. PC에서도 게임 콘텐츠 폭 안의 하단 시트를 사용해 정보 순서와 버튼 위치를 동일하게 유지한다.

### 닫기와 재확인

- 명시적인 닫기 버튼, `Escape`, 모바일 뒤로 동작을 지원한다.
- 배경을 눌러 닫는 동작은 허용하되 결과 데이터는 버리지 않는다.
- 닫은 뒤에는 사냥 조작부 가까이에 `최근 결과` 버튼을 남겨 다음 사냥 전까지 다시 열 수 있게 한다.
- `다시 사냥`은 기존 사냥 조건과 확인 로직을 그대로 실행한다.
- 전투 기록을 누르면 시트를 닫고 현재 리플레이·로그 화면으로 이동한다.
- 결과 시트가 열려 있는 동안 떠 있는 채팅 버튼은 숨기거나 시트 위로 재배치해 주요 버튼을 가리지 않게 한다.
- 하단 여백에는 `env(safe-area-inset-bottom)`을 반영한다.

### 결과 상태

- 승리: 보상 중심의 에메랄드 강조
- 패배: 보상 없음과 회복·성장 안내를 분명히 표시
- 일부 보상 처리 실패: 성공한 결과와 실패 항목을 함께 표시하고 재조회 안내
- 결과 데이터 조회 실패: 사냥 성공 여부를 임의로 추정하지 않고 최근 기록 재조회 버튼 표시
- 보상 없음: 빈 목록 대신 `획득한 아이템 없음`을 명시

시트의 배경은 불투명하게 유지하고, 승패는 색상뿐 아니라 아이콘과 문구로도 구분한다. 열릴 때 제목으로 초점을 이동하고 닫을 때 사냥 버튼으로 되돌린다.

## 2. 마을·생활 내비게이션 분리

### 메인 탭

기존 다섯 탭을 다음 여섯 탭으로 확장한다.

1. 모험
2. 전투
3. 마을
4. 생활
5. 캐릭터
6. 길드

모바일에서는 탭을 한 화면에 강제로 축소하지 않고 현재처럼 가로 스크롤 가능한 한 줄을 사용한다. 활성 탭으로 진입하면 해당 탭이 보이도록 자동 정렬하되 사용자의 수평 스크롤을 가로채지 않는다. 각 탭은 최소 44px 터치 높이를 유지한다.

### 메뉴 분류

`마을`에는 NPC와 시설 방문 성격의 항목을 둔다.

- 모험가 협회
- 치료소
- 은행
- 통합 교환소
- 대장간

`생활`에는 생산, 수집과 연구 성격의 항목을 둔다.

- 생활 지도
- 생활 의뢰·조합 작업장
- 모험가 농장
- 낚시
- 자동 벌목
- 자동 채광
- 주방

기존 URL은 유지한다. `/town/*` 아래에 있는 경로도 사용자에게 보이는 정보 구조에서만 `생활`로 분류하고, 대규모 라우트 이동이나 호환 리디렉션을 만들지 않는다.

### 생활 진행도

헤더에는 콘텐츠별 숫자를 직접 나열하지 않는다. 활성화된 생활 항목 중 지금 처리 가능한 작업이 하나 이상일 때 `생활` 탭에 작은 주황색 점 하나만 표시한다. 메뉴를 열면 각 항목의 오른쪽에 짧은 상태를 표시한다.

예시:

- 농장 `5 / 5` 또는 `수확 가능`
- 낚시 `3 / 7`
- 벌목 `18분`
- 채광 `완료`
- 주방 `새 기록 4`

상태 문구는 다음 우선순위를 사용한다.

1. 지금 수령·수확·완료 확인 가능
2. 목표 진행도
3. 남은 시간
4. 표시할 상태 없음

한 항목에 여러 상태가 있어도 메뉴에는 가장 중요한 한 줄만 표시하고 자세한 내용은 모험 홈 활동 위젯이나 해당 화면에서 확인한다. 진행도와 알림은 개인화 모험 홈의 `AdventureDashboardProvider` 스냅샷을 재사용해 헤더용 별도 API 호출을 만들지 않는다.

### 알림 의미

- 주황색 점은 `미완료`가 아니라 `지금 행동 가능`을 뜻한다.
- 사용자가 체크 항목 관리에서 끈 생활 활동은 탭 점과 메뉴 진행도에서도 제외한다.
- 단순 진행 중인 타이머는 점을 만들지 않는다.
- 색상만으로 전달하지 않도록 접근성 이름에 `처리 가능한 생활 항목 있음`을 포함한다.

## 3. 인벤토리 밀도 개선

### 장착 장비 요약

모바일은 장착 슬롯을 `3열 × 2줄`, 작은 PC 폭 이상은 `6열 × 1줄`로 표시한다. 각 슬롯은 약 54~64px 높이를 목표로 하고 다음만 상시 표시한다.

- 슬롯 아이콘
- 슬롯명
- 장비명 한 줄 말줄임
- 강화 단계
- 상세 메뉴 표시

빈 슬롯은 같은 크기를 유지하면서 `비어 있음`을 표시한다. 카드 전체가 최소 44px 이상의 하나의 버튼이며, 누르면 기존 장비 상세 카드를 연다.

현재 각 슬롯에 따로 있는 `해제` 버튼은 제거한다. 장착 해제는 상세 카드의 기존 해제 동작을 사용한다. 이로써 실수로 해제할 가능성을 줄이고, 장비명과 기능을 중복해 차지하던 높이를 없앤다.

장착부 아래에는 현재 값이 이미 클라이언트에 준비된 경우에만 전투력과 활성 세트 효과 개수의 한 줄 요약을 표시한다. 이 요약을 위해 별도 네트워크 요청을 만들지 않으며 값이 없으면 행 전체를 숨긴다.

### 보유 장비 목록

보유 장비는 모바일 2열, PC 2열 이상이라는 현재 정보 구조를 유지하되 불필요한 최소 높이와 여백을 줄인다.

- 장비명, 품질, 핵심 스탯과 중요한 배지는 유지
- 동일 의미의 티어·상태 표시는 한 번만 표시
- 상세 설명은 카드 클릭 후 기존 상세에서 확인
- 카드 전체 터치 영역은 최소 44px 유지
- 긴 이름과 여러 배지는 카드 높이를 무한히 늘리지 않도록 말줄임과 우선순위 적용

목표는 일반적인 360~390px 모바일 첫 화면에서 장착 장비 6개와 보유 장비 최소 2~4개를 함께 확인하는 것이다. 글자를 지나치게 줄여 달성하지 않고, 장착부의 중복 버튼과 큰 최소 높이를 줄여 확보한다.

### 장비 조작 유지

- 장착 슬롯 클릭은 기존 `V2ItemCard`를 재사용한다.
- 장착, 해제, 비교, 잠금, 도감 등록의 서버 계약은 바꾸지 않는다.
- 일괄 판매와 선택 판매 중 장착·잠금 장비를 막는 규칙을 유지한다.
- 희귀도 색, 슬롯 아이콘과 강화 색을 유지한다.
- 잠김·비활성 상태에 카드 전체 `opacity`를 적용하지 않는다.

## 데이터와 컴포넌트 경계

### 전투

- `DungeonContextSummary` — 던전명, 전투력, 난이도와 안정도 요약
- `CompactBattlePlayerStatus` — 접힌 캐릭터 상태
- `HuntResultSheet` — 단일·묶음 결과를 공통 시트 모델로 표시
- `RecentHuntResultTrigger` — 닫은 결과 다시 열기

기존 `HuntResultCard`와 `BatchSummaryCard`의 표시 모델을 공통 결과 뷰로 정규화하되 보상 계산과 저장 로직은 건드리지 않는다. 리플레이는 기존 컴포넌트를 재사용한다.

### 내비게이션

- `TOWN_MENU_ITEMS`에서 생활 항목 분리
- 새 `LIFE_MENU_ITEMS`와 `lifeMenuItemsForViewer`
- `MainTabNav`의 탭 정의에 `life` 추가
- 각 생활 메뉴 항목에 대시보드 활동 요약을 연결하는 표시 어댑터

### 인벤토리

- `EquippedItemSummaryGrid` — 장착 슬롯 요약과 상세 열기
- 기존 `EquipmentCardGrid` — 간격과 정보 우선순위만 조정
- 기존 `V2ItemCard` — 장착 해제와 상세 동작 유지

장착 그리드를 `V2InventoryView` 내부의 큰 JSX 블록에서 분리해 반응형 레이아웃과 상호작용을 독립 테스트한다.

## 반응형·디자인 규칙

- 장면 배경 위의 모든 본문과 시트는 `SURFACE_CARD`, 중첩 행은 `SURFACE_INSET`, 강조 상태는 `SURFACE_ACCENT`를 사용한다.
- 모바일 320px에서도 장착 슬롯 3열이 가로 넘침 없이 표시돼야 한다.
- 긴 한국어 장비명은 한 줄 말줄임을 사용하고 전체 이름은 상세 카드에서 제공한다.
- 생활 메뉴는 모바일 2열, 충분한 폭에서는 3열을 사용하되 진행도 문구가 잘리지 않도록 항목 내부는 아이콘·이름·상태의 세 영역으로 나눈다.
- 하단 시트는 안전 영역과 채팅 버튼을 고려하고 배경 스크롤을 잠근다.
- 라이트·다크 모드 모두 배경 이미지가 카드와 결과 시트의 글자 뒤로 비치지 않는다.
- 모션 감소 설정에서는 시트 이동 애니메이션을 제거한다.

## 오류와 경계 상황

- 대시보드 상태 조회 실패 시 생활 메뉴 링크는 계속 제공하고 진행도와 점만 숨긴다.
- 생활 상태가 오래됐으면 헤더에서 완료로 추정하지 않고 다음 대시보드 갱신을 기다린다.
- 전투 결과 시트가 열린 상태에서 경로가 바뀌면 시트를 닫고 포커스 복귀를 생략한다.
- 사냥을 연속으로 빠르게 실행해도 가장 최신 완료 결과 하나만 시트의 현재 결과가 된다.
- 결과를 닫은 뒤 새 사냥을 시작하면 이전 `최근 결과`는 새 결과가 확정될 때까지 유지하고 진행 중 상태와 구분한다.
- 장착 장비 이름이 길거나 배지가 많아도 슬롯 높이는 고정하고 상세 카드로 넘긴다.
- 장비 상세에서 해제 실패 시 슬롯 요약은 낙관적으로 비우지 않고 서버 확정 상태를 유지한다.

## 테스트

### 전투

- 단일 사냥 완료 시 결과 시트가 한 번 열림
- 묶음 사냥은 개별 전투가 아니라 묶음 완료 시 한 번 열림
- 승리, 패배, 보상 없음과 긴 획득 목록 표시
- 닫기, `Escape`, 최근 결과 다시 열기와 포커스 복귀
- 다시 사냥과 전투 기록 버튼이 기존 동작 호출
- 모바일 최대 높이, 내부 스크롤과 안전 영역

### 내비게이션

- 마을과 생활 메뉴 항목이 설계한 분류와 기존 URL을 유지
- `/town/farm`, `/town/fishing`, `/town/logging`, `/town/mining`, `/town/kitchen`에서 `생활` 탭 활성
- 행동 가능한 생활 항목만 주황색 점 생성
- 개인 설정에서 끈 항목은 진행도와 점에서 제외
- 상태 조회 실패 시 링크 유지
- 320·360·390px에서 여섯 탭 가로 스크롤과 활성 탭 노출

### 인벤토리

- 모바일 3열 2줄, PC 6열 1줄에 슬롯 6개 표시
- 빈 슬롯, 긴 이름, 강화 없음과 최대 강화 표시
- 슬롯 클릭으로 상세 열기, 상세에서 해제 성공·실패 처리
- 별도 해제 버튼이 장착 요약에 노출되지 않음
- 장착·잠금 장비 판매 차단 회귀
- 모바일 첫 화면에서 장착 장비와 보유 목록 일부 동시 노출
- 라이트·다크 모드 불투명 표면과 가독성

### 전체 회귀

- 타입 검사, 린트와 관련 테스트
- 프로덕션 빌드
- 전투 결과 저장·보상 중복 지급이 없음
- 기존 마을·생활 URL 직접 접근과 북마크 유지
- 인벤토리 장착, 비교, 판매와 도감 등록 동작 유지

## 단계별 구현

1. 생활 메뉴 분류와 활동 대시보드 계약의 `life` 탭 연결
2. 장착 장비 요약 그리드 분리와 인벤토리 밀도 개선
3. 던전 정보와 캐릭터 상태 요약
4. 단일·묶음 전투 결과 공통 모델과 하단 시트
5. 최근 결과, 채팅 버튼·안전 영역과 접근성 처리
6. 모바일·다크 모드·전체 회귀 검증
