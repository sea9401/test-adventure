# 선택형 목장 부지 10칸 확장 설계

## 목표

고정된 닭장 2개·외양간 2개·돼지우리 1개로 끝나는 현재 목장을 최대 10개 부지로 확장한다. 이용자는 각 부지에 필요한 축사 종류를 직접 선택하고, 비어 있는 축사는 증표를 지불해 다른 종류로 재건축할 수 있다. 기존 이용자의 해금 상태와 생산 진행은 손실 없이 새 구조로 이전한다.

## 부지 확장

목장에는 순서가 고정된 부지 10개가 있다. 앞 부지를 열지 않으면 다음 부지를 열 수 없다.

| 부지 | 필요 농사 레벨 | 해금 비용 |
| ---: | ---: | ---: |
| 1 | 1 | 무료, 닭장 기본 제공 |
| 2 | 10 | 30증표 |
| 3 | 20 | 60증표 |
| 4 | 35 | 120증표 |
| 5 | 50 | 180증표 |
| 6 | 60 | 1,000증표 |
| 7 | 70 | 2,000증표 |
| 8 | 80 | 4,000증표 |
| 9 | 90 | 8,000증표 |
| 10 | 100 | 16,000증표 |

부지 6~10의 추가 비용은 총 31,000증표다. 부지를 해금할 때 축사 종류를 함께 선택하며 최초 건설비는 부지 가격에 포함한다. 부지 해금과 축사 선택은 서버에서 하나의 원자적 작업으로 처리해, 비용만 빠지거나 종류가 없는 열린 부지가 남지 않게 한다.

## 축사 종류와 생산 규칙

축사 종류별 생산 수치는 현재 값을 유지한다.

| 축사 | 선택 가능 레벨 | 생산 | 사료 |
| --- | ---: | --- | --- |
| 닭장 | 1 | 달걀 2개 / 2시간 | 회당 1개, 최대 6개 적재 |
| 외양간 | 20 | 우유 3개 / 6시간 | 회당 1개, 최대 2개 적재 |
| 돼지우리 | 50 | 돼지고기 8개 / 16시간 | 돼지 한 마리당 4개 |

부지 레벨을 충족해도 선택한 축사의 종류 레벨을 충족하지 못하면 건설할 수 없다. 돼지우리를 건설하거나 재건축하면 현재 해금 동작과 같이 첫 돼지가 포함되어 즉시 비육을 시작한다. 이 동작은 사료 4개를 인벤토리에서 차감하지 않는다.

## 저장 구조

목장 저장 버전을 2로 올리고 고정 축사 ID 대신 `slot-1`부터 `slot-10`까지의 부지 상태를 저장한다. 각 상태는 다음 정보를 가진다.

- 해금 여부
- 선택한 `animalId`; 미해금 부지는 `null`
- 투입된 사료
- 마지막 정산 시각과 부분 진행 시간
- 수확·출하 대기 수량과 완료 주기 수

생산 시간·생산량·사료 용량 같은 규칙은 부지에 중복 저장하지 않고 축사 종류 정의에서 읽는다. 기존 누적 생산·수확 통계는 현재 구조를 유지한다.

## 기존 저장 마이그레이션

버전 1의 고정 축사는 다음 부지로 이전한다.

| 기존 축사 | 신규 부지 | 축사 종류 |
| --- | --- | --- |
| `coop-1` | `slot-1` | 닭장 |
| `coop-2` | `slot-2` | 닭장 |
| `cowshed-1` | `slot-3` | 외양간 |
| `cowshed-2` | `slot-4` | 외양간 |
| `pigsty-1` | `slot-5` | 돼지우리 |

각 축사의 해금 여부, 사료, 마지막 정산 시각, 부분 진행, 대기 물품과 완료 주기를 그대로 이전한다. 잠긴 기존 축사는 같은 번호의 미해금 부지로 이전하며 축사 종류는 저장하지 않는다. 부지 6~10은 미해금 상태로 추가한다. 마이그레이션 후 정규 파서가 축사 종류에 맞는 사료 용량과 진행 범위를 검증한다.

버전 2 저장은 다시 마이그레이션하지 않는다. 잘못된 부지 ID, 축사 종류, 음수 수량과 미래 시각은 현재 방어 규칙과 같은 방식으로 정규화하며, 손상된 값으로 생산물이 새로 생기지 않게 한다.

## 재건축

열린 부지는 다음 조건을 모두 만족할 때 다른 축사로 재건축할 수 있다.

- 사료가 0개다.
- 부분 생산 진행이 0이다.
- 수확·출하 대기 물품과 완료 주기가 0이다.
- 현재와 다른 축사 종류를 선택했다.
- 대상 축사의 종류 레벨을 충족한다.
- 필요한 증표를 보유한다.

대상 축사별 재건축 비용은 닭장 500증표, 외양간 1,000증표, 돼지우리 2,000증표다. 조건을 만족하지 못하면 상태와 증표를 모두 변경하지 않는다. 성공하면 대상 축사의 빈 초기 상태로 교체하고, 돼지우리만 첫 돼지가 포함된 비육 상태로 시작한다. 재건축 비용과 상태 교체도 서버에서 하나의 원자적 작업으로 처리한다.

## 서버 동작과 API

- 생산 정산, 사료 투입, 전체 수확·출하는 부지에 저장된 `animalId`를 통해 축사 정의를 조회한다.
- 부지 해금 요청은 `slotId`와 `animalId`를 함께 받으며 순서, 농사 레벨, 축사 종류 레벨, 증표를 서버에서 다시 검증한다.
- 재건축은 별도 서버 작업으로 두고 부지의 최신 상태를 먼저 정산한 뒤 비어 있는지 검사한다.
- 중복 요청은 첫 성공 이후 이미 열린 부지 또는 동일 축사 오류가 되어 추가 비용을 차감하지 않는다.
- 없는 부지, 미해금 부지, 지원하지 않는 축사 종류와 잘못된 수량은 명시적인 오류로 거부한다.
- 클라이언트는 서버 응답으로 받은 최신 농장 상태만 반영한다.

## 화면 구성

- 목장 화면에는 부지 1~10을 한 화면에 표시하고 기존 2열 카드 배치를 유지한다.
- 열린 부지는 현재의 생산 카드와 사료·진행·대기 수량을 표시한다.
- 재건축 가능한 빈 축사에는 재건축 동작을 표시하고, 선택 확인창에 대상 축사와 비용을 명시한다.
- 아직 열지 않은 다음 부지는 닭장·외양간·돼지우리 선택지를 함께 보여 준다. 레벨이 부족한 종류는 이유와 필요 레벨을 표시한 채 비활성화한다.
- 순서상 아직 열 수 없는 뒤 부지는 잠금 조건만 간결하게 표시한다.
- 전체 수확·출하는 열린 10개 부지 전체를 대상으로 유지한다.
- 목장 상단에는 보유 부지 수와 최대 10칸, 다음 부지의 레벨·증표 조건을 표시한다.

모든 카드와 선택 영역은 기존 불투명 표면 상수를 사용하고, 잠긴 카드 전체에 불투명도를 적용하지 않는다.

## 후반 교환소 호환성

후반 교환소의 기존 조건인 무료 닭장 외 유료 축사 4개 해금을 보존한다. 새 구조에서는 부지 1~5가 모두 열렸는지를 기준으로 계산하고 진행 수치는 `유료 축사 4/4`를 유지한다. 축사 종류와 재건축 여부, 부지 6~10 해금은 교환소 상태에 영향을 주지 않는다.

## 검증

- 버전 1의 다섯 고정 축사가 버전 2의 부지 1~5로 정확히 이전되는지 확인한다.
- 마이그레이션 전후의 해금, 사료, 진행, 대기 물품과 누적 통계가 동일한지 확인한다.
- 부지 1~10의 순차 해금, 레벨과 30·60·120·180·1,000·2,000·4,000·8,000·16,000증표 비용을 검증한다.
- 부지와 축사 종류 레벨을 각각 검증하고 실패 시 저장과 증표가 변하지 않는지 확인한다.
- 닭장·외양간·돼지우리를 임의 조합한 10개 부지의 오프라인 생산, 사료 소모와 전체 수확을 검증한다.
- 재건축 가능 조건, 대상별 500·1,000·2,000증표 비용, 같은 종류 및 생산 중 요청 차단을 검증한다.
- 돼지우리 건설·재건축 시 첫 돼지가 포함되고 기존 돼지우리 저장은 진행을 보존하는지 확인한다.
- 부지 5까지 연 이용자의 후반 교환소가 계속 열리는지 검증한다.
- 목장 화면이 축사 선택, 잠금 사유, 재건축 비용과 10개 부지를 올바르게 표시하는지 렌더링 테스트로 검증한다.
- 관련 API 테스트, 농장·목장 집중 테스트, 타입 검사, 린트와 전체 테스트를 실행한다.

## 범위 제외

- 축사별 생산 시간, 생산량, 사료 용량과 농사 경험치는 변경하지 않는다.
- 배합 사료와 실패 음식 재활용 사료의 제작법은 변경하지 않는다.
- 새로운 동물이나 목장 생산 재료는 추가하지 않는다.
- 축사의 동시 일괄 재건축이나 자동 사료 분배는 추가하지 않는다.
- 배포, 푸시, PR 생성은 수행하지 않는다.
