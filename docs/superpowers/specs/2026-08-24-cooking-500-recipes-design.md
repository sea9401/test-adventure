# 요리 레시피 500종 확장 설계

## 목표

현재 120종인 요리 레시피를 총 500종으로 확장한다. 신규 380종은 조리법과 재료를 직접 선택하는 연구에서 정답을 만날 가능성을 높이고, 현실적인 일상 요리와 세계관에 어울리는 판타지 요리를 함께 제공한다. 이름만 다르고 효과가 완전히 같은 요리가 반복되지 않도록 신규 380종의 효과 조합은 모두 고유하게 만든다.

## 중단 가능한 배치 전략

- 신규 레시피는 10종씩 38개 배치로 추가한다.
- 각 배치는 공개 레시피, 서버 정답, 고유 효과, 이미지 10장, 회귀 테스트를 모두 포함하는 완결 단위다.
- 배치 하나의 집중 테스트와 이미지 검사가 통과한 뒤 그 배치만 커밋하고 다음 배치로 이동한다.
- 작업이 사용량 제한이나 세션 종료로 중단되면 `COOKING_EXPANSION_BATCHES`의 마지막 배치 번호와 Git 커밋 기록을 기준으로 다음 배치부터 재개한다.
- 미완성 이미지나 참조만 있는 레시피는 커밋하지 않는다. 따라서 모든 배치 커밋은 빌드 가능한 상태를 유지한다.
- 배포, 푸시, PR 생성은 하지 않는다.

## 콘텐츠 구성

신규 380종의 목표 티어 분포는 다음과 같다.

| 티어 | 신규 수량 | 재료 슬롯 | 성격 |
| --- | ---: | ---: | --- |
| T1 | 160 | 2 | 간단한 일상식과 직관적인 조합 |
| T2 | 120 | 3 | 가정식, 간식, 기본 응용 요리 |
| T3 | 60 | 4 | 지역 특선과 전문 요리 |
| T4 | 30 | 5 | 희귀 재료를 사용한 판타지 요리 |
| T5 | 10 | 5 | 세계관 최상급 연회와 전설 요리 |

각 10종 배치는 가능한 한 다섯 요리 분야와 여러 조리법을 섞는다. 전체적으로는 일상 요리가 다수를 차지하고, 티어가 오를수록 판타지 이름과 희귀 재료 비중을 높인다. 같은 `조리법 + 정렬된 재료 집합`은 기존 120종과 신규 380종 전체에서 한 번만 사용한다.

## 공개 카탈로그와 서버 비밀 분리

- 클라이언트 공개 모듈에는 ID, 이름, 분야, 조리법, 아이콘, 티어, 효과, 설명, 이미지 경로만 둔다.
- 서버 전용 모듈에는 각 ID의 정답 재료만 둔다. 공개 번들에서 정답 조합을 직접 가져올 수 없게 현재 경계를 유지한다.
- 신규 배치는 번호가 붙은 작은 모듈로 분리해 한 파일에 380행을 몰아넣지 않는다.
- 기존 120종의 ID, 순서, 정답, 효과, 최초 발견 기록은 변경하지 않는다.
- 공개 카탈로그는 완료된 배치만 합치므로, 중간 상태에서도 이미지 누락이나 공개/비밀 수량 불일치가 없다.

## 효과 다양성

- 기존 120종의 효과는 호환성을 위해 그대로 둔다.
- 신규 효과는 티어별 기존 전투력 예산을 넘지 않는 범위에서 주효과, 보조효과, 특색효과 세 축으로 나눈다.
- 분야별 주효과 정체성은 화덕=물리 공격, 냄비=생존, 제과=마법과 보상, 해산물=명중과 민첩, 약선=정신과 생활로 유지한다.
- 신규 레시피는 서로 다른 세 효과 성분의 조합과 배분을 사용한다. 정규화한 효과 객체가 기존 레시피 또는 다른 신규 레시피와 정확히 같으면 카탈로그 검증을 실패시킨다.
- 효과 태그는 실제 효과 성분에서 파생하거나 함께 검증해, 표시용 태그와 실제 버프가 어긋나지 않게 한다.
- 같은 티어 안에서 총 효율은 비슷하게 유지하되 한 수치에 몰린 기존 요리와 다르게 여러 능력에 나뉜 선택지를 제공한다.

## 도감과 보상

- 도감 분모와 페이지 수는 이미 실제 카탈로그 길이를 사용하므로 배치가 추가될 때 자동 증가한다.
- 기존 10·25·50·75·100 이정표는 유지한다.
- 최종적으로 150·200·300·400·500 이정표를 추가한다. 중간 배치에서도 달성 가능한 목표만 UI에 자연스럽게 표시된다.
- 저장 스키마와 API 응답 구조는 변경하지 않는다.

## 이미지 품질

- 신규 380종 각각에 기존 요리 자산과 같은 품질의 개별 이미지를 만든다.
- 이미지 생성은 배치마다 10회 별도로 수행하며, 한 장에 여러 음식을 넣어 잘라 쓰거나 기존 이미지를 복제하지 않는다.
- 단일 음식 중심의 세밀한 판타지 게임 아이템 일러스트, 정사각형 구도, 투명 배경, 텍스트·테두리·워터마크 없음 규칙을 유지한다.
- 파일명은 레시피 ID와 일치시키고 `public/images/items/cooking/<id>.webp`로 최적화한다.
- 각 배치 커밋 전에 파일 존재, 참조, 크기, 투명 배경을 검사한다.

## 검증

- 각 배치 추가 전 총 레시피 수와 배치 ID를 리터럴로 기대하는 실패 테스트를 먼저 작성한다.
- 모든 공개 ID, 서버 ID, 정답 조합이 고유한지 검증한다.
- 기존 120종 정답 해시는 유지한다.
- 신규 레시피 효과의 정규화 결과가 기존 및 신규 전체에서 중복되지 않는지 검증한다.
- 모든 레시피가 티어 슬롯 수에 맞는 정답 재료 수와 해금된 조리법을 사용하는지 검증한다.
- 완료된 배치의 이미지가 모두 존재하는지 레시피 인식 테스트로 검증한다.
- 배치마다 요리 집중 테스트와 이미지 검사를 실행하고, 최종 500종에서 전체 테스트·타입 검사·린트·이미지 검사·프로덕션 빌드를 수행한다.
