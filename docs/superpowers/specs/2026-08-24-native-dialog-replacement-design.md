# 브라우저 기본 다이얼로그 일괄 교체 설계

## 목표

프로젝트의 `window.confirm`, 전역 `confirm`, `window.alert`, 전역 `alert` 사용을 제거하고 모든 확인·안내를 앱 디자인과 접근성 규칙을 따르는 공용 다이얼로그로 표시한다.

## 범위

- 일반 사용자 화면의 확인 동작 29개
- 관리자 화면의 확인 동작 11개와 안내 동작 1개
- 개발 화면의 확인 동작 1개와 안내 동작 1개
- 기존 요리 전문 분야 전용 모달은 이미 공용 스타일을 사용하므로 유지한다.

## 구조

`src/components/ui/gameDialog.ts`는 화면 코드가 호출하는 `confirmGameAction()`과 `showGameAlert()`를 제공한다. 요청은 모듈 내부 FIFO 큐에 들어가며, 앱 루트에 한 번 마운트된 `GameDialogHost`가 한 건씩 표시하고 결과를 Promise로 돌려준다. 확인창은 승인·취소 버튼을, 안내창은 확인 버튼 하나를 사용한다.

`GameDialogHost`는 불투명 `SURFACE_CARD`와 `SURFACE_INSET`, 공용 `Button`, 포커스 트랩, 스크롤 잠금, Escape 처리 규칙을 사용한다. 메시지의 기존 줄바꿈은 유지한다. 확인창의 Escape·배경 클릭은 취소이며 안내창에서는 닫기로 처리한다.

## 호출부 전환

직접 호출은 `if (!(await confirmGameAction(message))) return` 형태로 바꾼다. 인라인 이벤트 핸들러는 `async`로 변경하되 기존 busy 검사와 서버 요청 순서는 유지한다. 확인 함수를 주입받는 순수 헬퍼는 비동기 확인 함수 `ConfirmGameAction`을 받아 `Promise<boolean>`을 반환하도록 변경한다.

## 오류와 연속 요청

호스트가 마운트되기 전에 들어온 요청도 큐에 보관한다. 여러 요청은 동시에 겹치지 않고 FIFO로 표시한다. 호스트가 교체되더라도 아직 표시하지 않은 요청은 유지한다.

## 검증

- 공용 호스트에서 승인, 취소, 안내, FIFO 순서를 실제 DOM 상호작용으로 검사한다.
- 기존 비용·영구 변경 확인 헬퍼 테스트를 비동기 계약으로 갱신한다.
- 관련 화면 테스트, ESLint, TypeScript, 프로덕션 빌드를 실행한다.
- 마지막 전수 검색으로 테스트 외 런타임 코드에 브라우저 기본 `alert/confirm` 호출이 0개인지 확인한다.
