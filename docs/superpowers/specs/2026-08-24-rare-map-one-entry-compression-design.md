# 희귀 탐사 1회 입장 압축 설계

## 목표

일반 사냥에서 발견한 희귀 탐사를 사냥 화면에서 즉시 확인하고, 기존 30판 또는 10판을 반복하는 대신 지도 한 장당 한 번의 전투로 완료한다. 조작 횟수만 줄이고 기존 지도 한 장이 제공하던 총 보상 기대값은 100% 보존한다.

## 현재 문제

- 50회 일괄 사냥은 기본 설정에서 희귀 탐사를 발견해도 계속 진행한다.
- 일괄 결과는 새 지도마다 발견 알림과 `바로가기`를 따로 표시하므로, 여러 장을 얻었을 때 총수량과 다음 행동이 한눈에 들어오지 않는다.
- 희귀 탐사는 발견 후 30분에 만료되고 최대 5장만 보유할 수 있어, 발견한 지도를 확인한 뒤 사냥터 목록과 희귀 탐사 화면을 반복해서 오가게 된다.
- 희귀 탐사 한 장은 현재 30판, 빛바랜 유적 탐사는 10판으로 구성되어 있다. 일괄 사냥으로 처리하더라도 지도 입장과 반복 사냥이라는 별도 단계가 남는다.

## 사용자 경험

### 일반 사냥 화면

기존 `N회 사냥` 주 버튼 바로 아래에 열린 희귀 탐사 영역을 표시한다. 보유한 사냥형 희귀 지도가 없으면 영역 자체를 렌더링하지 않는다.

- 기본 버튼: `희귀 탐사 · {지도 이름}`
- 보조 정보: 발견 깊이, 지도 수, 가장 먼저 만료되는 지도의 남은 시간
- 지도 한 장이면 버튼을 누를 때 그 지도로 이동한다.
- 지도 여러 장이면 가장 먼저 만료되는 지도를 기본 선택하고, 같은 영역의 `다른 지도` 컨트롤에서 나머지를 선택할 수 있다.
- 비밀 상점·개명 신전 같은 `location` 지도는 기존 열린 레어맵 목록과 전용 장소 흐름을 유지한다. 이번 압축 대상은 `hunt` 지도뿐이다.
- 일반 사냥의 일괄 결과에는 새로 발견한 지도를 `희귀 탐사 N개 발견` 한 묶음으로 표시한다. 개별 발견 배너를 여러 개 쌓지 않고, 주 행동은 `희귀 탐사 입장`, 보조 행동은 `다른 지도`로 통일한다.

### 희귀 탐사 화면

희귀 탐사는 지도 한 장당 전투 1회만 제공한다.

- 입장 화면의 주 버튼은 `희귀 탐사 시작`으로 표시한다.
- 승리하면 해당 지도에 남아 있던 보상량을 한 번에 정산하고 지도를 소모한다.
- 패배하면 보상을 지급하지 않고 지도도 소모하지 않는다. 30판분 전체가 한 번의 패배로 사라지는 불균형을 막기 위한 규칙이다.
- 완료 후 다른 사냥형 희귀 지도가 남아 있으면 결과 하단에 `다음 희귀 탐사 입장`을 표시한다. 다음 대상은 가장 먼저 만료되는 지도다.
- `다른 지도`를 선택하면 열린 희귀 지도 목록을 열어 원하는 지도로 바꿀 수 있다.

## 보상 기대값

일반 사냥 1회의 각 보상 기대값을 `×1`로 놓는다. 신규 지도 한 장의 압축 보상은 현재 전체 판수와 지도 배율을 곱한 값을 그대로 사용한다.

| 희귀 탐사 | 기존 판수 | 경험치 | 골드 | 일반 재료·장비 | 강화석 | 유니크 |
|---|---:|---:|---:|---:|---:|---:|
| 낡은 탐사로 | 30 | ×90 | ×90 | ×90 | ×30 | ×30 |
| 금빛 탐사로 | 30 | ×30 | ×210 | ×30 | ×30 | ×30 |
| 현자의 탐사로 | 30 | ×210 | ×30 | ×30 | ×30 | ×30 |
| 사냥꾼의 탐사로 | 30 | ×30 | ×30 | ×210 | ×120 | ×30 |
| 빛바랜 유적 탐사 | 10 | ×10 | ×10 | ×30 | ×10 | ×50 |

소환서, 재련석, 정착지 재료, 활력의 파편처럼 지도 전용 배율이 없는 독립 드랍도 기존 판수만큼 추첨한다. 따라서 30판 지도는 30회, 빛바랜 유적 탐사는 10회의 현재 드랍 분포를 보존한다.

확률형 보상은 확률 수치 자체를 `×210`처럼 키우지 않는다. 기존 보상 추첨을 남은 보상 횟수만큼 독립적으로 실행하고 결과를 합산한다. 그래야 한 지도에서 장비가 여러 개 나올 가능성과 무득 확률을 포함한 기존 분포를 유지할 수 있다.

## 서버 처리

### 보상 횟수

기존 `RareMapInstance.runsLeft`는 저장 호환성을 위해 유지하되, 화면에 남은 전투 판수로 노출하지 않고 `남은 보상 추첨 횟수`로 해석한다.

- 새 30판 지도: `runsLeft = 30`
- 새 빛바랜 유적 탐사: `runsLeft = 10`
- 이미 일부 사용한 지도: 저장된 `runsLeft`만큼만 압축 정산

따라서 별도 데이터 마이그레이션 없이 기존 미사용·부분 사용 지도의 남은 가치를 그대로 보존한다.

### 한 번의 전투와 압축 정산

희귀 탐사 전투는 기존 전투 엔진으로 한 번 해결한다. 승리 시 `runsLeft`를 `rewardRolls`로 고정해 다음을 처리한다.

- 경험치·골드·직업 숙련도·숙달 포인트: 현재 희귀 탐사 1판 보상에 `rewardRolls`를 적용해 한 번에 성장 처리
- 일반 재료·장비·강화석·유니크와 독립 드랍: 현재 희귀 탐사 드랍 함수를 `rewardRolls`회 독립 실행해 합산
- 장비 개체: 각 성공 추첨마다 기존과 동일하게 별도 iid와 옵션 굴림 생성
- 지도 소모: 모든 정산과 저장이 성공했을 때만 해당 지도 제거

전투 횟수, 몬스터 처치 퀘스트, 길드 탐사 진행, 몬스터 도감 처치량은 화면에 실제로 해결한 전투 1회만 반영한다. 압축 보상 횟수를 전투 활동량으로 중복 기록하지 않는다. 압축 과정에서는 또 다른 희귀 지도를 발견할 수 없다.

정산은 기존 사냥 저장과 같은 트랜잭션 안에서 원자적으로 처리한다. 중간 저장 실패 시 지도 소모와 일부 보상 지급이 따로 남지 않게 전체를 실패시킨다.

## 클라이언트 데이터 흐름

1. 일반 사냥 화면이 기존 희귀 지도 API에서 유효한 `hunt` 지도를 읽는다.
2. 만료 시각 오름차순으로 정렬해 기본 지도와 총수량을 결정한다.
3. 사용자가 희귀 탐사 버튼을 누르면 기존 `rareMapEntryHref`로 해당 지도 화면에 들어간다.
4. 희귀 탐사 시작 요청은 지도 iid와 발견 깊이를 보내고, 서버가 소유권·만료·깊이·남은 보상 횟수를 다시 검증한다.
5. 승리 응답은 압축된 합계 보상과 획득 장비 목록을 반환한다.
6. 결과 화면은 합산 보상을 보여 주고, 남은 지도 목록을 새로 읽어 `다음 희귀 탐사 입장`을 결정한다.

클라이언트가 알고 있던 지도 수나 남은 시간이 오래되었더라도 서버 검증을 최종 권위로 둔다.

## 오류와 경계 조건

- 입장 전에 지도가 만료되면 기존 만료 안내 후 일반 사냥 또는 열린 지도 목록으로 돌아간다.
- 전투 중 만료되더라도 서버가 입장 시 유효성을 검증해 시작한 요청은 정상 정산한다.
- 패배 시 지도와 `runsLeft`를 보존하며, 회복 후 다시 시도할 수 있다.
- 지도 소유권이 없거나 깊이가 맞지 않으면 보상 없이 기존 `rare_map_invalid` 오류를 반환한다.
- 보유 장비 저장이나 보상 저장이 실패하면 지도도 소모하지 않는다.
- 결과 화면에서 다음 지도가 이미 만료되었으면 자동으로 제외하고 그다음 유효한 지도를 선택한다.
- `utility` 및 `location` 지도는 기존 사용·완료 규칙을 변경하지 않는다.

## 테스트

- 각 지도 종류의 `기존 판수 × 보상 배율` 기대값 표를 순수 함수 테스트로 고정한다.
- 부분 사용 지도가 저장된 `runsLeft`만큼만 정산되는지 검증한다.
- 압축 드랍이 기존 함수를 `rewardRolls`회 실행하고 여러 장비 개체와 합산 재료를 보존하는지 검증한다.
- 승리 시 보상 지급과 지도 제거가 함께 일어나고, 패배·오류 시 둘 다 일어나지 않는지 검증한다.
- 압축 탐사에서 전투 횟수·퀘스트·길드 탐사·몬스터 도감이 1회만 증가하는지 검증한다.
- 일반 사냥 화면에서 열린 희귀 탐사 버튼이 `N회 사냥` 바로 아래 나타나고, 지도 없을 때 사라지는지 렌더링 테스트로 검증한다.
- 여러 지도는 가장 빠른 만료 순으로 기본 선택되고 `다른 지도`에서 전환 가능한지 검증한다.
- 일괄 결과가 여러 발견 배너 대신 `희귀 탐사 N개 발견`으로 압축되는지 검증한다.
- 완료 결과의 `다음 희귀 탐사 입장`이 만료된 지도를 건너뛰는지 검증한다.

## 비범위

- 희귀 지도 발견 확률, 최대 보유 수 5장, 30분 만료 시간 변경
- 희귀 장소와 테스트용 utility 지도 재설계
- 희귀 탐사 자체의 보상 기대값 하향 또는 상향
- 일반 사냥의 1·5·10·50회 설정 변경
