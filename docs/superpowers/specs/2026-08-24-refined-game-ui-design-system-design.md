# 정돈된 게임 UI 디자인 시스템 설계

## 배경

현재 게임은 기능과 콘텐츠가 늘어나는 동안 화면마다 카드 반경, 여백, 버튼 색, 그림자와 정보 밀도가 조금씩 달라졌다. 개별 기능은 동작하지만 사용자는 같은 종류의 정보와 행동을 화면마다 다시 해석해야 하고, 모바일에서는 큰 카드와 반복 설명 때문에 핵심 상태를 보기 전에 스크롤하는 경우가 많다.

앞서 확정한 모험 홈은 일반적인 업무용 스케줄러가 아니라 기존 게임 분위기를 유지한 위젯형 대시보드다. 캐릭터 요약, 개인화 체크 항목, 위젯 순서 변경, 생활 알림과 진행도를 제공하며 전투와 인벤토리도 같은 원칙으로 밀도를 높였다. 이번 작업은 이 구조를 다시 설계하지 않는다. 선택한 `A — 정돈된 현재형`을 공용 디자인 시스템으로 정의해 기존 위젯형 홈과 다른 게임 화면이 같은 시각 언어를 사용하도록 한다.

## 확정된 방향

- 기존 무슨무슨게임의 배경 이미지, 콘텐츠별 아이콘, 희귀도 색과 기능별 고유색을 유지한다.
- 흰색·zinc 계열의 불투명 카드와 현재의 밝은 UI를 기반으로 한다.
- 일반적인 생산성 대시보드처럼 보이도록 게임 요소를 제거하지 않는다.
- 큰 장식이나 새로운 재질을 추가하기보다 반경, 선, 그림자, 간격과 버튼 깊이를 정돈한다.
- 이전에 확정한 위젯형 메인 화면을 그대로 사용한다.
- PC와 모바일의 기능과 정보 순서는 같게 유지하고, 모바일에서는 중복 설명과 빈 공간을 먼저 줄인다.

## 목표

- 같은 역할의 카드, 버튼, 탭, 상태 표시는 모든 화면에서 같은 높이와 조작감으로 보이게 한다.
- 모험 홈 첫 화면에서 캐릭터 요약과 오늘의 활동 상태를 함께 파악할 수 있게 한다.
- 모바일 320~390px에서도 글자 크기나 터치 영역을 과도하게 줄이지 않고 화면 밀도를 높인다.
- 라이트·다크 모드와 지역 배경 위에서 본문 가독성을 보장한다.
- 기존 화면이 공용 컴포넌트로 점진적으로 이동할 수 있도록 토큰과 변형 API를 안정적으로 만든다.

## 비목표

- 모험 홈의 위젯 구성, 개인 설정 모델이나 활동 상태 API를 다시 설계하지 않는다.
- 게임 전체를 한 번에 기계적으로 치환하지 않는다.
- 콘텐츠 보상, 전투 계산, 인벤토리 조작과 같은 게임 로직을 변경하지 않는다.
- 모든 콘텐츠의 고유 강조색을 하나의 보라색으로 통일하지 않는다.
- 배경 이미지를 제거하거나 본문 카드에 반투명 유리를 광범위하게 사용하지 않는다.
- 모바일과 PC에 서로 다른 기능을 제공하지 않는다.

## 시각 원칙

### 1. 세 단계 표면

화면 깊이는 다음 세 단계로 제한한다.

1. 페이지·장면 배경
2. 페이지 위에 뜨는 `card`
3. 카드 안으로 들어간 `inset`

기본 카드는 흰색, 다크 모드는 zinc-900의 불투명 배경을 사용한다. 인셋은 라이트 모드 zinc-50, 다크 모드에서는 카드와 구분되는 zinc-950 또는 명시된 내부 표면을 사용한다. 지역 배경이 본문이나 입력 컨트롤 뒤로 비치지 않게 한다. 프로스티드 표면은 기존처럼 의도적인 헤더에만 허용한다.

### 2. 반경과 테두리

- 페이지급 카드와 다이얼로그: 기본 12px
- 카드 내부 행, 버튼과 입력: 기본 8px
- 상태 배지: 내용에 맞춘 pill
- 전체 화면을 지나치게 둥글게 만드는 16~24px 반경은 특별한 영웅 카드나 하단 시트 외에는 사용하지 않는다.
- 기본 테두리는 zinc-200, 다크 모드는 zinc-700 한 단계로 통일한다.
- 선택과 오류는 카드 전체를 다시 칠하지 않고 테두리, 링과 보조 배경으로 표현한다.

### 3. 그림자와 입체감

- 카드는 얕은 1단 그림자로 페이지와 분리한다.
- 버튼은 현재 `ui-game-button`의 얕은 눌림감을 유지하되 그림자 크기와 이동량을 통일한다.
- 내부 행과 슬롯에는 외부 그림자를 사용하지 않는다.
- 모달, 드롭다운과 결과 시트만 일반 카드보다 높은 그림자를 사용한다.
- 장식적인 빛 번짐은 보상 획득과 등급 상승처럼 짧은 피드백에만 사용한다.

### 4. 색의 역할

- 기본 주요 행동: violet 계열
- 현재 처리 가능한 활동과 작은 알림: orange 계열
- 성공·완료: emerald 계열
- 위험·삭제·패배: rose 계열
- 정보·도움말: sky 계열
- 콘텐츠별 정체성 색: 기존 농장, 낚시, 장비 희귀도와 직업 색을 유지

주요 행동색과 알림색을 분리해 주황색 점이 버튼 또는 선택 상태처럼 보이지 않게 한다. 상태는 색상만으로 전달하지 않고 문구나 아이콘을 함께 사용한다.

### 5. 밀도와 타이포그래피

- 본문 기본 크기와 최소 44px 터치 영역은 유지한다.
- 모바일 밀도는 글자를 줄이는 대신 반복 제목, 개별 해제 버튼, 큰 최소 높이와 과한 패딩을 제거해 확보한다.
- 카드 제목, 보조 설명, 수치, 상태 문구의 네 단계만 사용한다.
- 한글 이름은 강제 단어 분리를 피하고, 장비명처럼 상세 화면이 있는 이름만 한 줄 말줄임을 허용한다.
- 수치 표에는 tabular number를 사용해 진행도가 흔들리지 않게 한다.

## 공용 컴포넌트 체계

### 표면 토큰

`src/components/ui/surfaces.ts`를 표면의 단일 출처로 유지한다. 기존 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`, `SURFACE_FROSTED`의 역할을 바꾸지 않되 새 반경과 깊이 규칙을 반영한다. 특별한 화면에서 직접 `bg-white`, `dark:bg-zinc-900`, 임의 그림자를 조합하는 대신 이 토큰을 사용한다.

강조 카드는 기본 행동색을 의미하지 않는다. `SURFACE_ACCENT`는 퀘스트 보상이나 특별 안내처럼 콘텐츠가 강조 표면을 요구할 때만 사용하고, 버튼 변형은 별도 컴포넌트가 담당한다.

### Button

기존 `src/components/ui/Button.tsx`를 공용 행동 계층의 기준으로 사용한다.

- `primary`: 화면의 대표 실행, violet
- `secondary`: 일반 보조 동작, white/zinc
- `soft`: 편집, 필터와 설정, 연한 violet
- `danger`: 삭제·취소처럼 되돌리기 어렵거나 부정적인 동작, rose
- `ghost`: 헤더 아이콘과 낮은 우선순위 동작

크기는 `sm`, `md`, `lg`, 아이콘 전용으로 제한한다. 기능 화면의 고유색이 반드시 필요한 경우 `tone`을 통해 emerald, amber, sky 등을 사용하되 크기와 눌림감은 같은 Button에서 가져온다. 비활성 버튼의 opacity는 허용하지만 비활성 카드 전체에는 opacity를 적용하지 않는다.

### Card와 내부 행

기존 `Card`는 `SURFACE_CARD`를 계속 사용한다. 제목부, 본문, 행동부의 표준 간격을 제공하는 얇은 보조 API를 추가하되 복잡한 만능 카드 컴포넌트는 만들지 않는다. 반복 리스트 행과 슬롯은 `SURFACE_INSET` 또는 전용 `InsetRow` 수준의 작은 래퍼를 사용한다.

### TabBar와 공통 내비게이션

탭의 정보 구조와 현재 여섯 개 메인 탭은 유지한다.

- 활성 탭: violet 텍스트와 2px 밑줄
- 비활성 탭: zinc 보조 텍스트
- 처리 가능한 활동: 작은 orange 점과 접근성 문구
- 최소 44px 터치 높이
- 모바일: 한 줄 가로 스크롤, 활성 탭만 자동 노출
- 하위 탭도 동일한 활성선과 간격을 사용하되 메인 탭보다 한 단계 작게 표시

### 상태 배너와 알림

`StatusBanner`, 오류 배너, 완료 배지와 헤더 알림에 동일한 의미색을 사용한다. 단순 미완료에는 경고색을 쓰지 않는다. 처리 가능한 상태와 실제 오류를 구분하며, 빨간색은 실패나 위험에만 사용한다.

### 입력과 다이얼로그

입력은 8px 반경, zinc 테두리, violet focus ring과 최소 44px 높이를 사용한다. 다이얼로그는 불투명 카드, 명시적 제목과 닫기, 내부 스크롤, safe-area 여백을 공통으로 보장한다. 브라우저 기본 confirm을 새로 추가하지 않고 공용 게임 다이얼로그를 사용한다.

## 화면 적용

### 모험 홈

기존 위젯 구조와 저장 모델을 유지한다.

- 캐릭터 요약은 기본 접힘 상태에서 프로필, 이름, 직업, 레벨, HP·MP와 펼치기만 표시한다.
- 오늘의 모험은 일일, 주간, 지금 가능 상태를 3개의 인셋 수치로 보여준다.
- 활동 행은 아이콘, 제목·설명, 행동 또는 완료 상태의 세 영역으로 통일한다.
- 위젯 편집은 soft 버튼을 사용하고 편집 중에만 드래그와 이동 컨트롤을 보인다.
- 공지, 퀘스트와 랭킹은 같은 카드 깊이를 사용하되 각각의 콘텐츠 아이콘과 상태색은 유지한다.

### 공통 헤더와 메뉴

- 프로필과 현재 상태, 공지·알림·메뉴는 기존 위치를 유지한다.
- 아이콘 버튼은 ghost 계층과 동일한 터치 크기를 사용한다.
- 메인 탭과 드롭다운은 같은 테두리와 표면 깊이를 사용한다.
- 생활 메뉴의 진행도와 알림은 기존 대시보드 스냅샷을 사용하며 시각 변경을 위해 새 요청을 만들지 않는다.

### 전투

- 압축된 던전 정보 카드와 캐릭터 상태는 공용 카드·인셋 규칙으로 통일한다.
- 결과 하단 시트는 높은 표면을 사용하지만 보상 카드 내부는 동일한 카드 체계를 따른다.
- 승패, 획득 보상과 다시 사냥의 우선순위를 색과 버튼 계층으로 명확히 한다.

### 인벤토리

- 장착 슬롯은 기존 모바일 3×2, 작은 PC 이상 6×1 구조를 유지한다.
- 슬롯은 그림자 없는 인셋으로 보이고 장비 상세 행동은 카드 전체 클릭으로 통일한다.
- 보유 장비 카드의 희귀도, 강화와 잠금 표시는 유지하되 공용 여백과 반경을 사용한다.

### 후속 화면

농장, 낚시, 길드, 주방, 교환소와 도감은 공용 토큰과 컴포넌트를 이용해 점진적으로 전환한다. 기능별 대형 화면을 한 번에 기계 치환하지 않고 다음 우선순위로 진행한다.

1. 공통 헤더·메인 탭·모험 홈
2. 전투·인벤토리처럼 이미 밀도 개선이 적용된 핵심 화면
3. 생활 화면의 공통 패널과 작업 행
4. 마을·길드·교환소·도감의 반복 카드와 다이얼로그

한 단계에서 공용 API를 안정화한 뒤 다음 화면으로 확장한다. 새 화면은 처음부터 이 디자인 시스템을 사용한다.

## 반응형 규칙

- 320px에서도 페이지 자체의 가로 스크롤을 만들지 않는다.
- 모바일은 한 열, 충분한 폭에서는 정보 성격이 같은 짧은 카드만 두 열로 배치한다.
- 버튼이 세 개 이상 나열되면 모바일에서는 우선순위에 따라 줄바꿈하거나 대표 행동만 전체 너비로 둔다.
- 표와 수치 중심 화면은 중요한 열을 먼저 표시하고 상세 열은 접기 또는 행 상세로 이동한다.
- 하단 고정 요소는 safe-area를 반영하고 채팅 버튼과 겹치지 않는다.
- PC에서 콘텐츠 폭을 억지로 늘리지 않고 기존 720px·864px 계열의 읽기 폭을 유지한다.

## 다크 모드와 접근성

- 카드와 인셋의 밝기 차이를 다크 모드에서도 명확히 유지한다.
- 배경 이미지 위 콘텐츠는 불투명 표면을 사용한다.
- 모든 클릭 대상은 키보드 포커스가 보이며 최소 44px 터치 영역을 가진다.
- 선택, 성공, 오류와 알림은 색상 외에 아이콘, 텍스트 또는 형태를 함께 사용한다.
- `prefers-reduced-motion`에서는 카드 이동, 시트 진입과 보상 강조 애니메이션을 줄인다.
- 다이얼로그는 포커스 트랩, Escape 닫기와 닫은 뒤 포커스 복귀를 제공한다.

## 구현 구조

- `surfaces.ts`: 표면·깊이 토큰의 단일 출처
- `Button.tsx`: 행동 계층, 크기와 기능별 tone
- `Card.tsx`: 기본 카드와 표준 내부 간격
- `TabBar.tsx`: 공통 활성 상태와 모바일 스크롤
- `StatusBanner.tsx`: 의미색과 메시지 상태
- `globals.css`: 공용 버튼 눌림, 카드 그림자와 짧은 피드백 애니메이션
- 화면 컴포넌트: 공용 원시 컴포넌트를 조합하고 콘텐츠 고유색과 데이터만 소유

공용 컴포넌트는 데이터 조회나 게임 상태를 알지 않는다. 모험 홈의 위젯, 전투 결과와 인벤토리 슬롯은 데이터와 상호작용을 소유하며 디자인 시스템에는 표시 목적의 props만 전달한다.

## 마이그레이션과 호환성

- 기존 `className` 확장을 유지해 기능별 색과 레이아웃을 점진적으로 이관한다.
- 공용 컴포넌트의 기존 variant 이름과 동작은 가능한 한 호환한다.
- 새 변형을 추가한 뒤 대표 화면부터 전환하고, 사용되지 않는 직접 스타일은 해당 화면을 이관할 때 제거한다.
- 전체 앱에 강한 전역 CSS 선택자를 적용해 기존 화면을 암묵적으로 바꾸지 않는다.
- 시각 변경은 서버 계약과 세이브 데이터에 영향을 주지 않는다.

## 테스트와 검증

### 공용 컴포넌트

- Button variant, size, disabled와 키보드 포커스
- Card와 inset의 라이트·다크 표면
- TabBar 활성 상태, 알림 점과 모바일 활성 탭 노출
- StatusBanner의 의미색과 접근성 문구

### 화면 회귀

- 모험 홈의 위젯 순서, 숨김, 캐릭터 펼침과 활동 설정 유지
- 헤더 드롭다운과 여섯 개 메인 탭 이동 유지
- 전투 결과 시트의 닫기·다시 사냥·포커스 처리 유지
- 인벤토리 장착 상세, 해제, 잠금과 판매 차단 유지

### 시각·반응형

- 320, 360, 390px와 PC 읽기 폭에서 가로 넘침 확인
- 라이트·다크 모드에서 페이지, 카드와 인셋 깊이 확인
- 지역 배경이 본문 카드 뒤로 비치지 않는지 확인
- 긴 한글 이름, 빈 상태, 오류 상태와 많은 배지 확인
- Storybook이 없으므로 공용 컴포넌트 미리보기 또는 개발 전용 갤러리에서 대표 상태를 한 화면에 검증

### 완료 전 검증

- 관련 컴포넌트 테스트
- ESLint
- TypeScript 검사
- 프로덕션 빌드
- 이미지 참조 검사
- 모바일과 PC 브라우저에서 핵심 화면 수동 확인

## 완료 기준

- 공통 헤더와 위젯형 모험 홈이 A안의 동일한 표면, 반경, 간격과 버튼 계층을 사용한다.
- 전투와 인벤토리의 밀도 개선이 같은 디자인 시스템으로 표현된다.
- 기존 기능과 저장 상태가 그대로 동작한다.
- 모바일 320px에서 가로 넘침이 없고 주요 컨트롤이 44px 터치 영역을 유지한다.
- 라이트·다크 모드 모두 배경 이미지가 카드 본문 뒤로 비치지 않는다.
- 이후 화면이 직접 색과 그림자를 새로 만들지 않고 공용 토큰으로 확장할 수 있다.
