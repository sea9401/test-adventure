# 직관적인 간단 요리 20종 추가 설계

## 목표

현재 100종 레시피에 이름만 보고도 조합을 추측할 수 있는 발견형 레시피 20종을 추가한다. 고급 재료를 무작위로 섞는 방식이 아니라 `달걀 + 소금 + 튀기기 = 계란후라이`처럼 현실적인 조리 상식을 정답으로 삼아, 초반 요리 연구가 막막하지 않고 작은 성공을 자주 주도록 한다.

## 구성 원칙

- 새 레시피는 모두 직접 연구해 찾는 `hidden` 등급이다. 기본 6종처럼 자동 습득하지 않는다.
- 12종은 T1·재료 2개, 8종은 T2·재료 3개로 구성한다.
- 요구 레벨은 기존 규칙대로 티어 기준과 조리법 해금 레벨 중 높은 값을 사용한다. 따라서 끓이기·굽기 T1은 Lv.1, 볶기·튀기기 T1은 Lv.10, 오븐·찌기는 Lv.20, 우리기·발효는 Lv.35에 열린다.
- 연구에는 선택 재료를 각각 1개 사용하고, 발견 후 실제 조리 비용은 기존 규칙대로 T1 농장 재료 2개·T2 농장 재료 3개를 사용한다. 조미료·가공품·낚시 재료 비용 규칙은 유지한다.
- 기존 100개 정답 및 새 20개 상호 간에 `조리법 + 정렬된 재료 집합`이 겹치지 않아야 한다.
- 기존 레시피의 이름, 정답 조합, 효과, 최초 발견 기록은 변경하지 않는다.

## 카탈로그와 정답 구조

공개 카탈로그에는 티어를 함께 가진 `SIMPLE_ROWS`를 추가하고, 기본 6종 다음에 배치한다. 새 레시피가 도감 앞쪽에 모여 초반 이용자가 발견 결과를 쉽게 확인할 수 있게 한다. 효과 계산에는 각 묶음 안의 기존 인덱스를 사용하고, 서버 자동 조합 생성에는 새 레시피 삽입 전 100종의 고정 인덱스 맵을 사용한다. 새 명시 조합은 현재 정답과 충돌하지 않는 조합만 채택해 기존 분야별 80종과 시그니처 14종의 효과와 정답이 변하지 않게 한다.

서버 정답은 기존 기본 조합 맵을 `EXPLICIT_COMBINATIONS`로 확장해 기본 6종과 새 20종을 모두 명시한다. 명시 조합이 없는 기존 레시피만 현재의 분야별 조합 생성기를 사용한다. 카탈로그 검증은 `100`을 내부에 반복하지 않고 공개 카탈로그 길이를 기준으로 비밀 레시피 수, ID 수, 정답 수가 모두 같은지 확인한다. 테스트에서는 제품 요구사항인 총 120종, 기본 6종, 발견형·시그니처 114종을 리터럴로 검증한다.

## 도감과 진행도

- 요리 도감의 `개인 발견 N/100` 표시는 `data.recipes.length`를 사용해 `N/120`으로 바뀐다.
- 기본 자동 습득 수는 계속 6종이다.
- 기존 도감 마일스톤 10·25·50·75·100은 유지한다. 새 120 완주 보상은 이번 범위에 추가하지 않는다.
- 페이지당 12개와 기존 페이지네이션을 유지하므로 총 10페이지가 된다.

## 이미지 자산

각 레시피 ID와 같은 이름의 PNG 20개를 `public/images/items/cooking/`에 추가한다. 기존 자산과 같은 단일 음식 중심의 세밀한 판타지 게임 아이템 일러스트, 정사각형 구도, 투명 배경, 텍스트·테두리·워터마크 없음으로 제작한다. 생성 원본은 프로젝트의 `prebuild` 이미지 최적화 규칙에 따라 최대 256px WebP로 변환하고 PNG 원본은 제거한다.

각 이미지는 접시·그릇·잔 등 최소한의 받침만 사용하고, 레시피의 핵심 재료가 한눈에 구분돼야 한다. 기존 음식 이미지를 덮어쓰거나 다른 레시피에서 재사용하지 않는다.

## 호환성과 오류 처리

- 기존 저장에는 새 ID가 없으므로 그대로 미발견 상태로 보인다.
- 기존 최초 발견 테이블과 실패 조합 테이블의 스키마는 바꾸지 않는다.
- 과거에 새 정답과 같은 조합을 실패로 기록한 사용자는 서버의 중복 실패 보호 때문에 재시도할 수 없는 문제가 생길 수 있다. 연구 판정은 현재 유효한 발견형 정답을 과거 실패 기록보다 먼저 처리하고, GET 오답 노트에서도 현재 정답이 된 조합을 제외한다. 이미 발견한 레시피는 기존처럼 `recipe_already_known`을 반환한다.
- API 응답 형태, 제작·품질·버프·납품·최초 발견 흐름은 유지한다.

## 테스트와 검증

- 카탈로그가 총 120종이며 ID와 정답이 모두 고유한지 검증한다.
- 20개 레시피 각각의 조리법, 티어, 정확한 재료 집합을 테이블 테스트로 검증한다.
- 기존 100종의 `ID=조리법+재료 집합` 목록 SHA-256이 변경 전 값 `45a79d708249d9c2f82ae664a4bd72396ebff5dffc813f03c570a62003066962`와 같은지 검증한다.
- 대표 조합인 달걀+소금+튀기기가 `fried_egg`를 찾고 재료 순서와 무관한지 검증한다.
- 과거 실패 기록이 있어도 새 유효 정답은 발견할 수 있고 오답 노트에서 사라지며, 정답이 아닌 과거 실패 조합은 계속 차단되는지 검증한다.
- GET 공개 카탈로그가 120종을 반환하고 기본 습득은 6종으로 유지되는지 검증한다.
- 도감이 실제 카탈로그 길이 120을 표시하고 12개씩 10페이지로 이동하는지 검증한다.
- 새 이미지 20개가 모두 참조되고 고아·누락 이미지가 없는지 검사한다.
- 관련 요리 테스트, 전체 테스트, 타입 검사, 린트, 이미지 검사와 프로덕션 빌드를 수행한다.
