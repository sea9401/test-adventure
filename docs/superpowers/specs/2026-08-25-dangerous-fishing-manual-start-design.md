# 위험 해역 낚시 수동 시작 설계

## 목표

위험 해역 일반 조우와 거대어 개인 시도가 사용자의 명시적인 시작 입력 없이 진행되지
않게 한다. 모바일 사용자는 시작 전에 화면 위치와 조작 방법을 확인할 수 있어야 하며,
느린 네트워크에서도 준비 시간 때문에 실제 제한 시간을 잃지 않아야 한다.

## 시작 흐름

일반 조우는 기존 `낚싯줄 던지기` 한 단계 흐름을 다음 두 단계로 바꾼다.

1. 사용자가 미끼를 선택하고 `낚시 준비`를 누른다.
2. 선택한 미끼와 “아직 제한 시간이 시작되지 않았다”는 안내를 담은 준비 카드를 보여 준다.
3. 사용자가 `낚시 시작`을 누를 때만 기존 `start_realtime` 요청을 보낸다.
4. 서버 응답으로 조우가 렌더되면 조우 상단을 뷰포트 시작 지점으로 이동한다.

거대어는 기존 `개인 시도 시작`을 `개인 시도 준비`로 바꾸고, 같은 패널 안에서
`거대어 낚시 시작`과 `준비 취소`를 제공한다. 실제 시작 요청은 두 번째 버튼에서만 보낸다.

준비 단계에서 미끼, 시도 횟수, 거대어 기여도는 소비하거나 변경하지 않는다. 실제 요청이
성공한 뒤에는 기존 서버 권위 상태, 1초 안전 준비 구간, 실시간 시뮬레이션과 복구 흐름을
그대로 사용한다.

## 상태와 컴포넌트

- `DangerousFishingView`는 일반 조우의 로컬 `encounterPrepared` 상태를 소유한다.
- 일반 조우 준비 상태는 미끼 변경, 항해 종료, 조우 생성 시 해제한다.
- `DangerousFishingPreparationPanel`은 일반 조우 준비 여부와 준비/시작/취소 콜백을 받아
  선택 화면과 시작 확인 카드를 전환한다.
- `DangerousFishingBossPanel`은 거대어 준비 상태를 로컬로 소유한다. 이벤트가 바뀌거나
  활성 상태가 끝나면 준비 상태를 해제한다.
- `DangerousFishingView`는 새 실시간 조우 ID가 나타날 때 조우 래퍼의 `scrollIntoView`를
  한 번 호출한다. 복원된 조우의 최초 렌더나 10초 상태 갱신에서는 자동 이동하지 않는다.

별도 API와 저장 형식은 추가하지 않는다. 첫 번째 준비 입력은 로컬 UI 전환일 뿐이며,
두 번째 시작 입력에서 기존 API를 호출하므로 서버 시간이 미리 흐르지 않는다.

## UI와 접근성

- 준비 카드는 `SURFACE_CARD`와 `SURFACE_INSET`만 사용해 라이트·다크 모드에서 배경이
  비치지 않게 한다.
- 시작 버튼은 모바일에서 충분한 높이와 전체 너비를 유지한다.
- 준비 안내는 “시작 버튼을 누르기 전에는 제한 시간이 흐르지 않습니다”라고 명시한다.
- 준비 카드는 `aria-label`로 일반 조우와 거대어 시작 준비를 구분한다.
- 조우 래퍼에는 고정 헤더를 고려한 `scroll-mt`를 적용한다.
- 기존 실시간 조작 버튼의 하단 고정, HUD meter, 키보드·포인터 입력은 변경하지 않는다.

## 오류와 복구

- 시작 요청이 실패하면 준비 카드를 유지해 사용자가 같은 선택으로 다시 시도할 수 있게 한다.
- 시작 요청 중에는 중복 클릭을 막고 기존 오류 메시지를 사용한다.
- 준비 취소는 서버 요청 없이 선택 화면으로 돌아간다.
- 이미 진행 중인 일반·거대어 조우를 복원하면 준비 단계를 거치지 않고 기존 복구 흐름으로
  바로 진입한다.
- 항해 중 거대어 시도를 막는 기존 규칙과 사람 확인 게이트를 유지한다.

## 검증

- 일반 조우에서 첫 클릭은 API 콜백을 실행하지 않고 준비 카드를 표시하는지 검증한다.
- 일반 조우에서 두 번째 클릭만 실제 시작 콜백을 실행하고 실패 시 준비 상태를 유지하는지
  검증한다.
- 거대어에서도 준비와 실제 시작이 분리되고 취소가 가능한지 검증한다.
- 새 조우가 시작된 경우에만 조우 상단으로 이동하고 복원된 조우에서는 이동하지 않는지
  검증한다.
- 기존 위험 해역·거대어·실시간 조우 테스트, TypeScript, ESLint, 이미지 참조 검사와
  Next.js 프로덕션 빌드를 실행한다.

## 범위 제외

- 일반 낚시, 위험 해역 서버 API·저장 형식·밸런스는 변경하지 않는다.
- 실시간 HUD의 수치 배치와 조작 규칙은 변경하지 않는다.
- 배포, 푸시와 점검 모드 변경은 수행하지 않는다.
