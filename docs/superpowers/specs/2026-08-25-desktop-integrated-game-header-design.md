# PC 통합형 게임 헤더 디자인

## 목표

모바일의 현재 5탭 내비게이션은 그대로 유지하면서, PC에서는 넓은 화면에 맞는 한 줄짜리 통합 헤더를 제공한다. PC 헤더에서 불필요한 골드 표기를 제거하고, 스태미나를 남은 생활 시간 옆으로 옮겨 정보와 내비게이션의 위계를 단순화한다.

## 확정 요구사항

- 모바일(`md` 미만)은 현재 상단 상태 바와 5탭 내비게이션의 모양·순서·드롭다운 카드 레이아웃을 변경하지 않는다.
- PC(`md` 이상)는 헤더 높이를 키우고, 상단 상태 영역과 메인 내비게이션을 한 줄에 배치한다.
- PC 왼쪽은 홈 아이콘, 남은 생활 시간, 스태미나 순서로 표시한다.
- PC에서는 골드를 표시하지 않는다. 모바일의 기존 골드 표시 동작은 유지한다.
- PC 오른쪽은 `전투`, `마을`, `생활`, `캐릭터`, `길드`, 알림, 설정 순서로 배치한다.
- PC 메인 메뉴 드롭다운은 각 탭 버튼 아래에 떠 있는 고정 폭 패널로 열리며, 모바일의 전체 폭 카드 그리드와 분리한다.
- 알림 점, 활동 상세 문구, 키보드 Escape 닫기, 바깥 클릭 닫기, 길드 시설 동적 조회는 기존 동작을 유지한다.

## 접근 방식

### 선택: 같은 데이터와 상태를 공유하는 반응형 렌더링

`MainTabNav`의 탭 데이터·열림 상태·알림 계산은 공유하되, 모바일 탭 바와 PC 헤더 메뉴를 반응형 컨테이너로 각각 렌더링한다. `V2TopBar`는 PC에서 `MainTabNav`를 오른쪽 슬롯으로 받아 통합 헤더를 만들고, 모바일에서는 기존처럼 `GameChrome`이 탭 바를 별도 행에 둔다.

이 방식은 메뉴 데이터나 길드 조회 로직의 중복 없이 화면 구조만 분리할 수 있고, 모바일 디자인을 가장 안전하게 고정한다.

### 검토했지만 선택하지 않은 방식

- CSS만으로 기존 5열 탭 바를 한 줄 헤더처럼 변형: 변경량은 작지만 드롭다운의 기준점과 PC 우측 정렬이 불안정하고 모바일 스타일 회귀 위험이 크다.
- PC 전용 내비게이션 컴포넌트를 완전히 별도 구현: 화면 분리는 명확하지만 탭·알림·길드 시설 로직이 중복되어 유지보수 비용이 커진다.

## 컴포넌트 구조

- `GameChrome`: `MainTabNav`를 한 번 마운트하고 PC용 내비게이션을 `V2TopBar`에 전달한다. 모바일 탭 바는 기존 위치에 유지한다.
- `V2TopBar`: PC에서 더 큰 높이와 여백을 적용하고, 생활 상태 옆에 스태미나 버튼을 배치한다. 골드는 모바일에서만 표시한다. 우측에는 전달받은 PC 내비게이션과 알림·설정을 둔다.
- `MainTabNav`: 공통 메뉴 계산을 유지하면서 모바일 전체 폭 탭 바와 PC 인라인 탭 메뉴에 서로 다른 스타일을 적용한다. PC 드롭다운은 해당 탭의 우측 헤더 버튼을 기준으로 아래에 열린다.

## 동작과 접근성

- 탭 버튼의 `aria-haspopup`, `aria-expanded`, 알림 상태가 포함된 `aria-label`을 유지한다.
- 드롭다운 메뉴는 기존 `role="menu"`와 `role="menuitem"`을 유지한다.
- PC와 모바일 표현은 CSS 브레이크포인트로 전환하므로 화면 크기 변경 시 동일한 열림 상태를 공유한다.
- 스태미나 버튼은 기존 포션 모달을 그대로 열며 실시간 회복 계산도 유지한다.

## 테스트

- 모바일 내비게이션이 5열·전체 폭·기존 카드 그리드를 유지하는지 검사한다.
- PC 내비게이션이 인라인 메뉴와 탭 기준 드롭다운 클래스를 갖는지 검사한다.
- PC 골드가 숨겨지고 모바일 골드 동작이 유지되는지 검사한다.
- 생활 상태 다음에 스태미나가 배치되고 버튼 클릭 시 포션 모달이 열리는지 검사한다.
- 기존 알림, 메뉴 항목 높이, Escape/바깥 클릭, 길드 시설 테스트를 회귀 실행한다.
