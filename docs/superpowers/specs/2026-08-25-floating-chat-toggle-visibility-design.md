# 플로팅 채팅 토글 표시 조건 설계

## 문제

데스크톱에서 플로팅 채팅 패널을 열면 패널 우상단의 닫기 버튼과 별도로 우측 하단 플로팅 토글이 계속 표시된다. 이 토글이 채팅 작성 영역의 전송 버튼과 겹쳐 입력 UI를 가린다.

## 결정

`ChatButton`의 `floating` 변형은 채팅이 닫혀 있을 때만 토글 버튼을 렌더링한다. 채팅이 열리면 토글 버튼을 DOM에서 제거하고, 패널 우상단의 기존 `채팅 닫기` 버튼을 유일한 닫기 경로로 사용한다.

상단바에서 사용하는 `inline` 변형은 기존처럼 열린 상태에도 남겨 둔다. 이번 변경은 제보된 우측 하단 플로팅 버튼에만 적용한다.

## 검토한 대안

- 반응형 CSS로 숨김: 현재 모바일에만 적용된 방식이다. 데스크톱에서도 적용할 수 있지만, 보이지 않는 중복 컨트롤을 DOM에 유지할 이유가 없다.
- 플로팅 버튼 위치 이동: 전송 버튼과의 직접 겹침은 줄일 수 있으나 패널 안에 닫기 버튼이 두 개 존재하는 중복은 남는다.
- 조건부 렌더링: 열림 상태에서 플로팅 버튼 자체를 제거해 중복과 겹침을 동시에 해소한다. 가장 작은 동작 변경이므로 이 방식을 채택한다.

## 상태 흐름

1. 닫힘 상태에서는 플로팅 `채팅 열기` 버튼을 표시한다.
2. 사용자가 버튼을 누르면 기존처럼 패널을 활성화하고 연다.
3. 열린 상태에서는 플로팅 버튼을 렌더링하지 않는다.
4. 패널 우상단 닫기 버튼이 `onClose`를 호출하면 닫힘 상태로 돌아가 플로팅 버튼이 다시 표시된다.

## 검증

- 실제 `ChatButton`을 렌더링하는 회귀 테스트에서 플로팅 버튼을 클릭한 뒤 해당 버튼이 사라지는지 확인한다.
- 같은 테스트에서 채팅 패널의 닫기 동작 뒤 플로팅 버튼이 다시 나타나는지 확인한다.
- 인라인 변형은 열린 상태에도 토글 버튼을 유지하는지 확인한다.
- 관련 단위 테스트, 린트, 타입/프로덕션 빌드를 실행한다.
