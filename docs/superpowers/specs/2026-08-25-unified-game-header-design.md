# 결합형 게임 헤더 디자인

## 목표

전역 상단바와 메인 탭 바를 서로 떨어진 두 줄처럼 보이지 않게 하나의 게임 헤더로 묶는다. 사용자가 제시한 목업처럼 게임명·자원·알림·메뉴가 있는 상단 행, 주요 화면으로 이동하는 탭 행, 전역 알림 티커가 같은 폭과 정렬 축을 공유해야 한다.

## 검토한 접근

1. **`GameChrome`에 하나의 의미론적 헤더 셸을 두는 방식(채택)**
   - 기존 `V2TopBar`, `MainTabNav`, `WarTicker`의 데이터와 상호작용 책임은 유지한다.
   - `GameChrome`이 세 컴포넌트를 공통 `header` 안에서 조합하고, sticky·전체 폭 표면과 내부 콘텐츠 폭을 소유한다.
   - 변경 범위가 작고 드롭다운, 폴링, 라우팅 동작을 그대로 보존한다.
2. `V2TopBar`가 메인 탭과 티커까지 직접 렌더하는 방식
   - 파일 하나에서 형태를 파악하기 쉽지만 상단 행 컴포넌트가 라우팅·길드·티커 상태까지 책임져 결합도가 높아진다.
3. CSS만으로 기존 형제 요소를 붙여 보이게 하는 방식
   - 코드 변경은 가장 작지만 하나의 헤더라는 의미 구조가 생기지 않고, 공통 폭·sticky·그림자를 여러 컴포넌트가 중복 관리하게 된다.

## 구조

- `GameChrome`에 `data-game-header`가 있는 단일 `<header>`를 둔다.
- 헤더 표면은 화면 상단과 좌우 끝까지 빈틈없이 채운다. 상단 안전 영역만 확보하며 별도의 위쪽·좌우 여백이나 둥근 외곽 모서리를 두지 않는다.
- 상단 행·메인 탭·티커의 실제 콘텐츠도 별도 최대 폭 제한 없이 헤더 전체 폭을 사용한다.
- 헤더 아래 일반 게임 본문은 모바일에서 기존 화면 폭과 좌우 패딩을 유지하고, `md` 이상에서 최대 `960px`까지 넓힌다.
- `V2TopBar`의 루트는 중첩 `<header>`가 되지 않도록 상단 행 `<div>`로 바꾸고, sticky·바깥 그림자 책임을 헤더 셸로 옮긴다.
- `MainTabNav`는 상단 행 바로 아래에 배치한다. 현재 6열 탭, 활성 밑줄, 알림 점, 드롭다운 동작을 유지한다.
- `WarTicker`는 메인 탭 바로 아래에서 같은 폭을 공유한다. 티커가 항목이 없어 렌더되지 않아도 상단 행과 탭은 완전한 헤더 카드로 남는다.
- 동의 프롬프트, 채팅 버튼, 오프라인 정산, 스태미나 상세 바와 페이지 콘텐츠는 헤더 밖에 유지한다.

## 시각 규칙

- 상단 행과 탭 행은 화면 폭 전체를 채우는 하나의 불투명 헤더 표면으로 읽혀야 하며 그 사이에 외부 배경이 비치지 않는다.
- 외곽 모서리는 둥글게 만들지 않고 화면 상단과 좌우에 밀착한다. 상단 행과 탭 행 사이에는 얇은 구분선만 둔다.
- 전체 헤더에 한 번만 그림자를 적용하여 두 개의 독립 카드처럼 보이지 않게 한다.
- 기존 라이트·다크 모드 표면 토큰을 재사용하고, 새로운 반투명 콘텐츠 표면은 만들지 않는다.
- 티커의 색상과 애니메이션은 이번 범위에서 바꾸지 않는다. 구조 결합만 수행해 정보 위계와 동작 변경을 분리한다.

## 동작과 접근성

- 전체 영역의 랜드마크는 하나의 `<header>`이며 그 안에 브랜드 링크와 `aria-label="메인 메뉴"` 내비게이션이 들어간다.
- 빠른 메뉴 내비게이션과 메인 내비게이션의 기존 접근 가능한 이름을 유지한다.
- 드롭다운의 바깥 클릭 닫기, 활성 탭 자동 스크롤, 길드 시설 조회, 알림 점, 티커 이동은 변경하지 않는다.
- 상단 safe-area 패딩을 유지해 모바일 노치 영역과 겹치지 않게 한다.
- 장비 팝오버처럼 sticky 상단 경계를 피하는 오버레이는 상단 행만이 아니라 결합형 게임 헤더 전체 높이를 기준으로 배치한다.

## 테스트와 검증

- `GameChrome` 레이아웃 테스트에서 단일 게임 헤더가 상단 행·메인 메뉴·티커를 모두 포함하는지 확인한다.
- `V2TopBar` 테스트에서 자체 sticky 헤더가 아니라 결합 셸 안의 상단 행으로 렌더되는지 확인한다.
- 장비 팝오버가 결합형 헤더 전체 아래에 배치되는지 DOM 경계 테스트로 확인한다.
- 기존 `MainTabNav`, `V2TopBar`, `WarTicker` 테스트를 함께 실행해 상호작용 회귀를 확인한다.
- 타입 검사, 린트, 프로덕션 빌드로 Next.js 클라이언트 경계와 Tailwind 클래스 생성을 검증한다.

## 범위 밖

- 메뉴 항목, 라우트, 자원 표시 종류 변경
- 전광판 데이터나 애니메이션 변경
- 캐릭터 요약 카드 및 본문 레이아웃 변경
- 배포와 점검 모드 조작
