# 채팅방 참여자 명단 설계

## 목표

사용자 채팅방에 들어온 사람이 현재 방에 참여 중인 캐릭터를 확인할 수 있게 한다. 이 명단은 접속 상태가 아니라 채팅방 멤버십을 뜻하므로 UI에서는 일관되게 `참여자`라고 표현한다.

## 범위

- 사용자 생성 채팅방에만 참여자 명단을 제공한다.
- 길드 기본 채널, 전체 채팅, 거래 채팅, 알림 채널은 변경하지 않는다.
- 방 참여자만 명단을 조회할 수 있다.
- 방장과 일반 참여자를 구분하고 캐릭터 이름에서 기존 프로필 화면으로 이동할 수 있게 한다.
- 초대, 강퇴, 접속 상태 표시 같은 방 관리 기능은 추가하지 않는다.

## 사용자 경험

사용자 채팅방 헤더에 현재 `memberCount`를 포함한 참여자 버튼을 표시한다. 버튼을 누르면 헤더 아래에 불투명한 작은 패널이 열리고, 서버에서 최신 참여자 명단을 한 번 조회한다. 패널에는 참여자 수, 캐릭터 이름, 방장 배지를 표시한다. 이름을 누르면 해당 캐릭터 프로필로 이동한다.

조회 중에는 로딩 문구를, 실패하면 재시도 버튼과 오류 문구를 표시한다. 패널을 닫았다 다시 열 때는 이미 받은 명단을 재사용하고, 재시도할 때만 다시 조회한다. 다른 방에 들어가면 컴포넌트를 다시 마운트해 이전 방 명단이 보이지 않게 한다.

## 데이터 흐름과 권한

`GET /api/chat/rooms/[roomId]`는 인증 사용자와 유효한 양의 방 번호를 확인한 뒤 요청자가 해당 방의 참여자인지 검사한다. 참여자가 아니면 `403 not in room`을 반환한다. 참여자라면 방장을 먼저, 나머지는 참여 시각 순으로 정렬해 다음 형태로 반환한다.

```ts
{
  members: Array<{
    userId: string;
    name: string;
    role: "owner" | "member";
    joinedAt: number;
  }>;
}
```

캐릭터 이름이 없는 예외 데이터는 기존 채팅방 API와 동일하게 `모험가`로 표시한다. 실시간 접속 여부는 반환하지 않는다.

## UI 표면

참여자 패널은 `src/components/ui/surfaces.ts`의 불투명 공용 표면을 사용한다. 작은 화면에서도 채팅 패널 너비 안에 머물며, 컨테이너 전체 투명도나 반투명 배경은 사용하지 않는다.

## 테스트

- API 테스트는 비참여자 접근 거절과 참여자 명단의 직렬화·역할 표시를 검증한다.
- 컴포넌트 테스트는 버튼을 눌렀을 때 명단을 조회·표시하고 이름 클릭이 프로필 이동 콜백으로 이어지는지 검증한다.
- 관련 단위 테스트, ESLint, TypeScript 검사, 프로덕션 빌드를 실행한다.
