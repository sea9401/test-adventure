# 생애별 HP·MP 무작위 성장 설계

## 목표

장착 스킬의 INT·SPI 퍼센트가 바뀔 때 최대 MP까지 함께 출렁이는 결합을 없앤다. 대신 영구 스탯 저점과 수행 한계치가 재전직 후 한 생애의 Lv.1 자원과 레벨업 자원 성장 범위를 결정하게 한다.

기본 캐릭터의 기대 HP·MP는 현행과 비슷하게 유지한다. 재전직과 수행을 반복해 영구 저점·한계치가 높아지면 다음 생애의 최소·최대·평균 자원 성장이 단조롭게 증가해야 한다.

## 확정된 역할

| 스탯 | 생애 자원 역할 | 기존 직접 효과 |
|---|---|---|
| STR | Lv.1 HP와 레벨업 HP의 최솟값을 높인다 | 최대 HP 직접 증가를 유지한다 |
| VIT | Lv.1 HP와 레벨업 HP의 성장폭을 넓힌다 | 최대 HP 직접 증가를 유지한다 |
| SPI | Lv.1 MP와 레벨업 MP의 최솟값을 높인다 | 최대 MP에는 직접 더하지 않는다 |
| INT | Lv.1 MP와 레벨업 MP의 성장폭을 넓힌다 | 최대 MP 직접 환산을 제거한다 |

`statPct`, 직업 앵커 보정, 직업 플랫 보너스, 장비 교체처럼 현재 `totalStats`를 바꾸는 효과는 이미 확정된 생애 자원 굴림을 다시 계산하지 않는다. 명시적인 장비 HP·MP와 `maxHpPct`·`maxMpPct`는 이름 그대로 최종 최대 자원에 계속 적용한다.

## 영구 입력과 단계

굴림 범위는 현재 전투 스탯이 아니라 영구 진행값만 사용한다.

- 저점 입력: `computeStatFloors(proficiency)`의 해당 스탯
- 한계치 입력: `effectiveStatCap(capGain(proficiency, stat))`
- 기본 저점: 15
- 기본 한계치: 60
- 영구값이 기준보다 10 오를 때마다 한 단계 증가한다.

단계는 다음처럼 음수가 되지 않게 계산한다.

```ts
floorStep = Math.floor(Math.max(0, statFloor - 15) / 10);
capStep = Math.floor(Math.max(0, statCap - 60) / 10);
```

SPI·STR 저점 단계는 분포 전체를 위로 옮겨 저점을 보장한다. INT·VIT 한계치 단계는 최솟값 위의 성장폭만 넓힌다. 따라서 어떤 영구 진행 조합에서도 최댓값이 최솟값보다 작아지지 않는다.

## 굴림 공식

모든 범위는 양 끝을 포함하는 정수 균등분포다.

### Lv.1 생애 자원

```ts
mpBaseMin = 65 + spiFloorStep;
mpBaseMax = mpBaseMin + 30 + intCapStep;

hpBaseMin = 150 + 2 * strFloorStep;
hpBaseMax = hpBaseMin + 30 + 2 * vitCapStep;
```

기본 영구값에서 Lv.1 MP는 `65..95`로 평균 80이다. Lv.1 HP 생애 성장분은 `150..180`으로 평균 165이며, 여기에 기존 STR·VIT 직접 HP가 더해진다. 기본 STR 15와 VIT 15에서는 장비 전 기대 최대 HP가 225다.

### 레벨업 자원 증가

각 레벨은 같은 범위 안에서도 서로 독립적으로 한 번씩 굴린다.

```ts
mpGainMin = 3 + spiFloorStep;
mpGainMax = mpGainMin + 2 + intCapStep;

hpGainMin = 8 + strFloorStep;
hpGainMax = hpGainMin + 4 + vitCapStep;
```

기본 영구값에서 레벨당 HP는 `8..12`로 평균 10, MP는 `3..5`로 평균 4다. 기본 Lv.100의 MP 기대값은 `80 + 99 * 4 = 476`으로 현행 대표값 467과 약 2% 차이다. HP 생애 성장분 기대값은 `135 + 99 * 10 = 1,125`이며, STR·VIT 직접 HP를 포함하면 현행 기대 규모를 유지한다.

생애 도중 수행이나 숙련 진행으로 저점·한계치가 오르면 다음 레벨업부터 갱신된 범위를 사용한다. 과거에 저장한 굴림 결과는 소급 변경하지 않는다. 한 요청에서 여러 레벨이 오르면 동일한 최신 영구 범위로 레벨 수만큼 독립 굴림한다.

## 저장 모델

`proficiency.v2`에 현재 전투 생애의 자원 기록을 선택 필드로 저장한다.

```ts
type V2LifeResourceGrowth = {
  version: 1;
  rolledLevel: number;
  baseHp: number;
  baseMp: number;
  gainedHp: number;
  gainedMp: number;
};
```

- `baseHp`, `baseMp`: 해당 생애 Lv.1 굴림
- `gainedHp`, `gainedMp`: Lv.2부터 `rolledLevel`까지 실제 굴림의 누계
- `rolledLevel`: 기록이 반영한 캐릭터 레벨. 새 생애는 1에서 시작한다.
- 결과값만 저장한다. 과거 RNG나 레벨별 개별 굴림 배열은 저장하지 않는다.

레벨업에서는 스탯 성장과 자원 성장을 같은 트랜잭션에서 갱신한다. 일반 사냥, 일괄 사냥, 경험치 아이템, 레벨 지정 지급 등 모든 레벨 상승 경로는 하나의 순수 자원 굴림 함수를 공유한다. 호출자는 테스트 가능한 RNG를 주입한다.

정상 신형 기록에서 `rolledLevel`과 캐릭터 레벨이 다르면 요청을 조용히 재추첨하지 않는다. 쓰기 경로는 불일치를 오류로 처리해 중복 굴림과 자원 복제를 막고, 읽기 경로는 저장된 누계를 표시하되 비정상 수치를 0 이상의 안전한 정수로 정규화한다.

## 최대 자원 파생식

신형 생애의 HP 캐릭터 본체값은 고정 베이스·레벨당 고정 HP 대신 저장된 생애 HP를 사용한다.

```ts
lifeHp = resource.baseHp + resource.gainedHp;
characterHp = lifeHp + totalStats.str * HP_PER_STR + totalStats.vit * HP_PER_VIT;
```

이후 기존과 같은 코어루프 HP 배수와 `maxHpPct`를 적용하고, 장비 HP를 기존 순서대로 마지막에 더한다. 따라서 STR·VIT와 해당 퍼센트 패시브의 직접 HP 효과는 유지된다.

신형 생애의 MP에서는 INT 직접 환산과 레벨당 고정 MP를 제거한다.

```ts
lifeMp = resource.baseMp + resource.gainedMp;
maxMp = Math.floor((lifeMp + equipmentMp) * (1 + maxMpPct / 100));
```

장비 MP와 명시적 `maxMpPct`는 계속 최대 MP를 바꾼다. INT·SPI 또는 그 퍼센트만 바뀌면 최대 MP는 변하지 않는다. 최대 자원이 늘어도 현재 HP·MP를 증가분만큼 자동 회복하지 않으며, 현재값이 최대치를 넘을 때만 기존처럼 클램프한다.

## 생애 시작과 재전직

- 업데이트 이후 생성되는 신규 캐릭터는 생성 트랜잭션에서 Lv.1 HP·MP를 굴려 신형 기록을 만든다.
- Lv.100 전투 생애를 마치고 재전직하면 기존 기록을 버리고 최신 영구 저점·한계치로 Lv.1 값을 다시 굴린다.
- 재전직 후 `rolledLevel`은 1이고 `gainedHp`, `gainedMp`는 0이다.
- Lv.1에서 반복 가능한 생활직 전환은 자원 재굴림을 하지 않는다. 전투 생애를 끝내지 않은 직업 변경으로 좋은 Lv.1 값만 반복 추첨하는 악용을 막는다.
- 현재 HP·MP의 재전직 처리 방식은 현행을 유지한다. 새 최대치를 넘는 값은 파생 단계에서 클램프된다.

## 기존 캐릭터 호환

기존 캐릭터에는 소급 굴림이나 중간값 환산을 하지 않는다.

- 생애 자원 기록이 없으면 그 현재 생애 전체에서 현행 HP·MP 공식을 그대로 사용한다.
- 기록 없는 캐릭터의 남은 레벨업도 현행 `v2LevelGrowthHpMp` 표시와 파생 규칙을 유지한다.
- INT 퍼센트에 따른 기존 MP 변화도 현재 생애가 끝날 때까지 유지한다.
- 다음 Lv.100 전투 재전직에서 처음으로 신형 Lv.1 기록을 만들고 이후 신형 규칙을 사용한다.
- 생활직 전환만으로는 레거시 캐릭터를 신형으로 바꾸지 않는다.

이 선택 필드가 레거시와 신형의 유일한 판별 기준이다. 별도 일괄 데이터 마이그레이션은 만들지 않는다.

## 사용자 표시

- 신형 캐릭터의 레벨업 결과에는 해당 레벨에서 실제로 굴린 `HP +N`, `MP +N`을 표시한다.
- 다중 레벨 상승 결과에는 각 레벨의 합계를 표시한다.
- 재전직 완료 결과에는 새 Lv.1 최대 HP·MP와 현재 영구값 기준 레벨업 HP·MP 범위를 표시한다.
- 캐릭터 상세 화면에는 신형 캐릭터의 현재 레벨업 HP·MP 범위를 표시한다.
- 레거시 캐릭터에는 현재 생애에 적용되지 않는 범위를 현재값처럼 표시하지 않는다. 대신 다음 전투 재전직부터 무작위 자원 성장이 적용된다는 안내와 현재 영구값 기준 미리보기를 표시할 수 있다.
- 스탯 설명은 STR=HP 저점, VIT=HP 고점, SPI=MP 저점, INT=MP 고점 역할을 명시한다.
- 장비 자원과 명시적 최대 HP·MP 퍼센트는 생애 성장과 구분해 최종 보정으로 표시한다.

## 오류와 무결성

- 굴림 헬퍼는 RNG 입력을 `[0, 1)` 범위로 정규화하고 양 끝을 포함하는 정수 결과를 낸다.
- 파서는 버전, 레벨, 누계가 유한한 0 이상의 정수인지 검증한다. `baseHp`, `baseMp`는 1 이상이어야 한다.
- 신형 쓰기 경로의 레벨 불일치는 자동 재굴림하지 않고 실패시킨다.
- 재전직과 레벨업은 캐릭터·숙련도 잠금 안에서 자원 기록을 한 번만 갱신한다.
- 실패한 트랜잭션의 굴림은 저장되지 않는다. 성공 응답은 실제 저장된 결과만 사용한다.

## 검증

### 순수 함수

- 기본 단계와 10포인트 경계에서 저점·한계치 단계를 검증한다.
- Lv.1 및 레벨업 HP·MP 범위와 RNG 양 끝값을 검증한다.
- 저점·한계치가 증가할 때 최소·최대·평균이 감소하지 않는지 검증한다.
- 다중 레벨 상승이 레벨마다 독립적으로 굴리고 정확한 누계를 저장하는지 검증한다.

### 파생과 호환

- 신형 캐릭터에서 INT·SPI와 그 퍼센트가 바뀌어도 최대 MP가 불변인지 검증한다.
- 장비 MP와 `maxMpPct`는 신형 최대 MP에 계속 적용되는지 검증한다.
- STR·VIT 직접 HP와 `maxHpPct`가 유지되는지 검증한다.
- 기록 없는 기존 캐릭터는 현행 파생식과 레벨업 결과를 그대로 유지하는 골든 테스트를 둔다.
- 현재 HP·MP 최대치 클램프를 검증한다.

### 생애 전환과 모든 레벨 경로

- 신규 캐릭터 생성이 Lv.1 기록을 만든다.
- Lv.100 전투 재전직이 기록을 초기화하고 새 Lv.1 값을 굴린다.
- 생활직 전환과 미완료 전투 생애의 직업 변경은 재굴림하지 않는다.
- 일반·일괄 사냥, 경험치 아이템, 레벨 지정 지급이 같은 굴림 규칙과 저장 형식을 사용한다.
- 레거시 캐릭터가 다음 전투 재전직에서만 신형으로 전환되는지 검증한다.

### 밸런스 시뮬레이션

- 기본 영구값의 Lv.1·Lv.100 HP·MP 기대값을 현행과 비교한다.
- 여러 재전직·수행 구간에서 평균뿐 아니라 하위·상위 분위수를 측정한다.
- 영구 성장 단계가 올라갈수록 다음 생애의 기대 성장과 고점이 체감되게 증가하는지 확인한다.
- 기본 Lv.100 기대 MP는 현행 대표값과 5% 이내, 기본 기대 HP는 현행과 5% 이내를 1차 수용 기준으로 삼는다.
- 극단적인 저점 연속 굴림도 같은 진행 구간의 사냥 가능성을 훼손하지 않는지 기존 진행 시뮬레이션으로 확인한다.

## 비범위

- 기존 캐릭터의 현재 생애 자원 소급 변환
- 장비 HP·MP 또는 명시적 최대 HP·MP 퍼센트 옵션 제거
- 현재 HP·MP 자동 회복 정책 변경
- 스탯 성장 RNG와 자원 성장 RNG를 하나의 통합 능력치 굴림으로 합치는 작업
- 배포 및 기존 저장값 일괄 마이그레이션
