# 미개척지 상위 유저 전투 시뮬레이션 설계

## 목적

현재 운영 캐릭터의 실제 직업, 장비, 숙련도와 스킬 세팅을 사용해 미개척지 난이도 90·95·100의 체감을 비교한다. 목표는 일부 최상위 캐릭터의 승률 하나에 수치를 맞추는 것이 아니라, 여러 직업과 세팅에서 현재는 안정적으로 사냥하기 어렵고 추가 성장 뒤 진입할 여지가 있는 난이도 구간을 찾는 것이다.

이 작업은 읽기 전용 밸런스 조사다. 운영 저장 데이터는 변경하지 않고, 미개척지의 최종 능력치나 능력 수치를 게임 데이터에 반영하지 않는다.

## 대상 캐릭터

- 공개 랭킹의 `level` 탭과 같은 기준인 모든 직군의 `cumLevel` 합계로 정렬한다.
- 동률이면 현재 캐릭터 레벨 내림차순, 캐릭터 저장 갱신 시각 오름차순으로 정렬한다.
- 관리자 계정, 활성 정지 계정, 전투 데이터를 정상적으로 산출할 수 없는 계정은 제외한다.
- 상위 30명의 실제 장비, 숙련도, 해금 상태와 정제된 현재 전투 스킬 장착을 그대로 사용한다.
- 결과에는 닉네임, 이메일, 사용자 ID를 출력하지 않는다. `01위`, 직업명과 익명화된 빌드 분류만 표시한다.

## 난이도 기준선

난이도 숫자는 기존 사냥터 깊이 곡선의 연장선으로 해석한다. 별의 무덤을 구성하는 5개 원본 몬스터를 기존 일반 사냥 스케일러로 각각 90·95·100까지 확장한다.

- 기본 풀 대용군은 확장된 별의 무덤 5종의 전투 실루엣과 기존 능력을 사용한다.
- 특화 몬스터의 공통 기준은 같은 난이도에서 이 5종의 HP, 공격, 물리 방어, 마법 방어, 속도와 적중도의 중앙값이다.
- 36종 특화 몬스터는 공통 기준에 승인된 상대 배율을 적용한다.
- 전용 사냥터의 보상, 드롭, 흔적과 스태미나는 승패 시뮬레이션에서 제외한다.
- 이 기준선은 후보 수치다. 결과가 의도와 크게 다르면 기존 사냥터 곡선을 바꾸지 않고 미개척지 전용 공통 배율 후보를 별도로 제안한다.

## 두 단계 전투 비교

각 난이도와 캐릭터 조합을 같은 고정 시드로 두 번 측정한다.

### 1. 능력치 전용

36종의 HP, 공격, 물리·마법 방어와 속도 배율만 적용한다. 이 결과는 물리·마법 공격, 방어형, 회피형과 지속 피해형 세팅이 순수 능력치 형태에 얼마나 영향을 받는지 보여준다.

### 2. 전투 특성 적용

현재 전투 엔진이 이미 지원하는 몬스터 필드와 스킬만 조합한다.

- 방어, 관통, 주기적 강타, 저체력 격노
- 물리·마법 공격 구분, 비전 공격과 제한된 마력
- 적중, 회피, 치명타와 추가 공격
- 중독, 출혈, 둔화와 상태 피해 저항
- 기존 10% 체력 회복 스킬과 제한된 마력으로 표현하는 재생

능력의 수치 상수는 현재 별의 무덤과 특수 몬스터가 사용하는 범위를 넘기지 않는 보수적인 값으로 둔다. 이는 최종 라이브 수치가 아니라 능력 활성화 전후의 민감도를 확인하기 위한 시뮬레이션 어댑터다. 결과에는 능력치 전용 대비 승률 변화도 함께 표시한다.

## 표본과 재현성

- 캐릭터 30명, 난이도 3개, 기본 대용군 5종과 특화 몬스터 36종을 측정한다.
- 한 캐릭터와 한 몬스터의 조합마다 30회를 실행한다.
- 기존 자동 전투 행동 선택과 실제 장착 스킬을 사용하며 물약은 사용하지 않는다.
- 모든 난수는 고정 시드로 재현 가능하게 만든다.
- 결과를 다시 실행해도 같은 데이터 스냅샷과 코드에서는 동일한 집계가 나와야 한다.

## 세팅 분류

직업명만으로 결과를 합치지 않는다. 각 캐릭터를 실제 파생 능력치와 장착 스킬로 다음 축에 태깅한다.

- 주 공격: 물리 우세 / 마법 우세 / 혼합
- 생존: 물리 방어 / 마법 방어 / 회피 / 균형
- 상태 활용: 중독 / 출혈 / 둔화 / 비상태

표본이 한 명뿐인 조합은 평균처럼 해석하지 않고 개별 사례로 표시한다. 직업별 집계도 인원수를 함께 출력해 표본 차이를 숨기지 않는다.

## 결과 지표

### 전체 요약

- 난이도별 기본 대용군, 특화 전체와 능력 적용 전후 승률
- 개인 승률 최소, 25분위, 중앙, 75분위, 최대
- 승률 20% 이상, 40% 이상, 70% 이상인 캐릭터 수
- 승리한 직업 수와 빌드 분류 수

### 캐릭터별

- 익명 순위, 총 숙련도, 직업, 빌드 태그와 핵심 전투 능력치
- 난이도별 전체 승률, 기본 풀 승률, 가장 쉬운 풀과 가장 어려운 풀
- 능력치 전용과 특성 적용 결과의 차이

### 몬스터 풀별

- 풀별 전체 승률과 캐릭터 승률 분포
- 직업 및 빌드 분류별 승률
- 능력치 전용 대비 특성 적용 시 승률 변화
- 특정 빌드만 거의 이기지 못하는 하드 카운터 여부

## 판정 원칙

20~40%는 일부 랭커에게 강제로 맞출 목표가 아니라 난이도 90의 대략적인 체감 방향이다.

- 난이도 90은 서로 다른 여러 직업·세팅에서 간헐적인 승리가 나올 수 있어야 한다.
- 현재 캐릭터가 혼합된 특화 풀을 70% 이상 안정적으로 이기면 즉시 파밍 가능한 구간으로 보고 의도보다 쉽다고 판정한다.
- 전체 승리가 한 직업이나 한 빌드 축에 몰리면 평균 승률이 적절해도 불균형으로 판정한다.
- 어떤 풀에서 특정 세팅이 거의 0%여도 다른 여러 세팅이 대응할 수 있으면 상성으로 기록한다. 대부분의 세팅이 막히면 과도한 벽으로 본다.
- 난이도 95는 극소수의 유리한 상성에서만 승리가 남는 성장 목표 구간을 기대한다.
- 난이도 100은 현재 캐릭터의 안정적인 승리가 거의 없는 장기 성장 여유 구간을 기대한다.

최종 권장 난이도는 이 원칙과 함께 직업·세팅별 분산, 풀별 하드 카운터와 전투 특성 적용 전후 차이를 종합해 판단한다.

## 구현 경계와 실패 처리

- 별도 CLI 스크립트와 순수 계산 모듈로 작성해 실제 사냥 API와 저장 형식에 연결하지 않는다.
- 데이터베이스 접근은 `SELECT`만 허용하고 연결은 하나만 사용한다.
- `DATABASE_URL`이 없거나 상위 30명을 구성할 수 없으면 명확한 오류로 중단한다.
- 일부 캐릭터 저장이 손상된 경우 해당 캐릭터를 제외하고 제외 인원 수를 알린다.
- 전투 중 예외가 발생하면 익명 순위, 난이도와 몬스터 ID만 포함해 중단하며 개인정보와 원본 저장 데이터는 출력하지 않는다.
- 시뮬레이터의 순수 변환, 순위 정렬, 집계와 익명화는 회귀 테스트를 먼저 작성한다.
