# 강화 장비 거래와 장비 귀속 분리 설계

## 목표

- 강화된 장비를 거래소 직접 판매, 장비 구매 주문 판매, 길드 창고 이전에 사용할 수 있게 한다.
- 강화 거래를 위해 장비의 강화 단계, 굴림, 제작 품질, 제작자, 폭풍 개량 정보를 전송 과정에서 보존한다.
- 강화 거래 제한을 해제하면서도 향후 다른 콘텐츠가 사용할 수 있는 명시적 장비 귀속 메커니즘을 남긴다.
- 거래 제한을 풀기 위해 만들어진 강화 초기화 기능을 UI, API, 도메인, 문서에서 제거한다.

## 현재 문제

`V2EquipInstance.enhance`의 존재 여부가 거래 불가 판정에 직접 사용된다. 별도 귀속 상태는 없으며, 거래소 둘러보기와 구매 라우트도 강화 payload를 숨기거나 거부한다. 직접 등록과 장비 구매 주문의 payload 생성기는 강화 상태를 직렬화하지 않으므로 제한만 제거하면 거래 후 강화가 소실될 수 있다. 강화 초기화는 이 거래 제한을 해제하기 위한 우회 기능으로 추가되어 있다.

## 설계

### 명시적 귀속

`V2EquipInstance`에 `bound?: true`를 추가한다. 저장 파서는 `true`만 보존하고 누락, `false`, 잘못된 값은 비귀속으로 정규화한다. 기존 세이브에는 이 필드가 없으므로 데이터 마이그레이션이나 소급 귀속은 없다.

계정 간 장비 이전의 서버 권위 판정은 `bound: true`를 `bound` 오류로 거부한다. 이 판정은 거래소 등록, 장비 구매 주문 판매, 길드 창고 입고가 공유한다. 잠금과 장착 제한은 기존대로 유지한다. NPC 판매나 강화 자체는 귀속 여부를 변경하지 않는다.

### 강화 장비 거래

`enhance`는 거래 가능 여부와 무관한 장비 성장 메타데이터가 된다. 직접 거래소 등록과 장비 구매 주문 체결 payload에 강화 상태를 포함한다. 구매, 취소, 만료, 우편 수령에서 기존 권위 파서를 통해 강화 상태를 복원한다.

정책 변경 전에 생성된 강화 매물도 둘러보기에서 보이고 구매할 수 있게 한다. 반대로 payload에 `bound: true`가 있는 방어적·미래 호환 매물은 공개 목록과 구매에서 거부하고, 취소나 만료로 원소유자에게 돌아갈 때는 귀속 상태를 보존한다.

### 강화 초기화 제거

대장간의 초기화 버튼, 확인 모달, 클라이언트 요청 헬퍼와 상태를 제거한다. `/api/v2/me/enhance/reset` 라우트와 도메인 초기화 함수도 삭제한다. 게임 설명서의 초기화 절을 제거하고, 강화 장비가 거래 가능하다는 설명으로 강화 거래 규칙을 갱신한다.

## 오류와 호환성

- `enhanced` 거래 오류는 제거하고 `bound` 오류를 추가한다.
- 기존 강화 장비는 즉시 거래 가능하다.
- 기존 강화 매물은 강화 상태를 유지한 채 거래 가능하다.
- 기존 비강화 장비와 귀속 필드가 없는 장비의 동작은 바뀌지 않는다.
- 명시적 귀속 장비는 거래소와 길드 창고를 통한 계정 간 이전이 모두 차단된다.

## 검증

- 저장 파서가 `bound: true`만 보존하는 테스트
- 강화 장비는 거래 가능하고 귀속 장비는 거부되는 정책 테스트
- 강화 상태가 직접 등록과 구매 주문 payload에 포함되고 수령 시 복원되는 테스트
- 강화 장비 길드 창고 입고 성공과 귀속 장비 입고 거부 테스트
- 초기화 관련 참조가 제품 코드와 설명서에서 사라졌는지 검색 검증
- 관련 Vitest, ESLint, TypeScript, 이미지 검사, Next.js 빌드
