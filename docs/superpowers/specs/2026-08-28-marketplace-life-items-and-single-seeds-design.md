# 생활 재료 거래와 씨앗 단품 구매 설계

## 목표

농장·요리에 필요한 원재료를 이용자 거래로 수급할 수 있게 하고, 거래소에 원하는
씨앗이 없더라도 농장 상점에서 필요한 씨앗 한 개만 살 수 있게 한다. 거래와 단품
구매는 기존 작물 해금 조건을 우회하지 않는다.

## 거래 대상

- 씨앗 11종: 밀, 허브, 옥수수, 토마토, 딸기, 감자, 양파, 쌀, 콩, 사탕수수,
  카카오에 대응하는 씨앗·씨감자·묘목
- 농장·축산 요리 재료 25종: 일반·희귀 농작물 22종과 달걀·우유·돼지고기
- 일반 낚시 요리 재료 5종: 일반·신선한·고급·특급·전설의 어획물
- 주방 재료 12종: 상점 조미료 6종과 가공 재료 6종

배합 사료는 요리 연구 재료가 아닌 농장 전용 소모품이므로 제외한다. 완성 음식,
위험 해역 재료, 물고기 표본 등 기존 거래 품목의 정책은 바꾸지 않는다.

## 거래소 모델

DB의 `equip | material | consumable` 구분은 유지하고 신규 생활 스택을 모두
`material`로 취급한다. 별도 마이그레이션 대신 거래소 전용 ID를 사용해 서로 다른
저장소의 동일한 원본 ID가 충돌하지 않게 한다.

- `farm_seed:<cropId>`
- `farm_item:<itemId>`
- `fishing_catch:<catchId>`
- `cooking_kitchen:<kitchenItemId>`

공개 카탈로그 모듈이 ID, 표시명, 원본 저장소와 원본 ID를 단일 소스로 제공한다.
기존 `V2_MATERIALS`와 생활 재료 카탈로그를 합친 판정 함수를 거래소 등록, 둘러보기,
즉시구매, 부분 구매, 구매 주문, 가격 알림에서 공통으로 사용한다.

## 저장과 정산

생활 스택의 등록·구매·취소·만료·자동 체결은 서버 전용 저장 헬퍼를 거친다.

- 씨앗과 농장 재료: `farm.v2.seeds`, `farm.v2.inventory`
- 일반 어획물: `fishing-stock.v1.items`
- 조미료·가공 재료: `cooking.v2.kitchenItems`

거래 등록 시 해당 저장소에서 수량을 원자적으로 차감하고 매물에 에스크로한다.
구매·구매 주문 체결 시 구매자 저장소에 적립하며 취소·만료 시 판매자 저장소에
반환한다. 기존 거래소 잠금 순서인 `character.v2` 이후 생활 저장소 잠금을 유지한다.
수량은 기존 스택 거래 한도인 1~9,999개를 사용하고, 즉시구매 매물은 기존 부분
구매 경로로 1개부터 살 수 있다.

## 거래소 UI

거래소 인벤토리 응답에 생활 거래 품목 보유량을 거래소 ID 기준으로 함께 제공한다.
판매 탭의 재료 카드와 구매 주문 카탈로그는 기존 재료와 생활 재료를 같은 방식으로
표시한다. 표시명은 공개 카탈로그에서 가져오며 보유 수량, 개당 가격, 판매 수량 입력,
시세·구매 주문·가격 알림 기능을 그대로 재사용한다.

## 씨앗 단품 구매

기존 씨앗 상자는 유지한다. 농장 상점 카탈로그에 작물별 단품 항목 11개를 추가하고,
각 구매는 해당 씨앗 정확히 1개를 지급한다. 단품 가격은 기존 묶음의 씨앗당 평균
비용을 정수로 올림해, 묶음의 소폭 할인은 유지하면서 필요한 한 개만 살 수 있게 한다.

| 씨앗 | 단품 증표 가격 |
| --- | ---: |
| 밀 | 3 |
| 허브 | 3 |
| 옥수수 | 6 |
| 토마토 | 3 |
| 딸기 | 3 |
| 감자 | 3 |
| 양파 | 3 |
| 쌀 | 4 |
| 콩 | 4 |
| 사탕수수 | 6 |
| 카카오 | 6 |

단품도 해당 작물의 기존 필요 스킬을 그대로 요구한다. 농장 상점 API는 현재처럼
한 요청당 카탈로그 항목 하나를 구매하므로 수량 API를 새로 만들지 않고, 단품 항목
구매 한 번이 씨앗 한 개 구매가 된다.

## 오류와 호환성

- 알 수 없거나 범위에서 제외된 ID는 `not_tradable`로 거부한다.
- 보유량이 부족하면 등록을 롤백하고 `insufficient_material`을 반환한다.
- 기존 일반 재료 매물과 완성 음식 매물의 저장·정산 경로는 그대로 유지한다.
- 기존 묶음 씨앗 상자와 저장 데이터는 변경하지 않는다.
- 작물 심기 단계의 스킬 검증은 유지되므로 거래로 잠긴 씨앗을 보유해도 심을 수 없다.

## 테스트

- 공개 카탈로그가 승인된 53개 품목만 노출하고 ID·표시명을 안정적으로 해석한다.
- 서버 저장 헬퍼가 네 저장소에서 차감·적립하며 수량 부족 시 원본을 보존한다.
- 거래소 판정, 표시명, 구매자 배송과 판매자 에스크로 반환이 생활 스택을 처리한다.
- 거래소 인벤토리 응답과 판매 UI가 생활 재료를 1개부터 등록할 수 있게 한다.
- 씨앗 단품 11종의 가격, 보상, 해금 조건과 실제 1개 지급을 검증한다.
- 관련 단위·라우트 테스트, TypeScript, ESLint, 이미지 검사와 프로덕션 빌드를 실행한다.
