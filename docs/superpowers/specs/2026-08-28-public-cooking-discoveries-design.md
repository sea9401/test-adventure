# 공개 요리 발견 목록 설계

## 목표

주방에 서버 전체의 최초 발견 요리를 모아 보는 `공개 발견` 탭을 추가한다. 전체 소식에서 이미 공개된 정보만 지속적으로 찾아볼 수 있게 하되, 레시피 정답이나 조리에 도움이 되는 상세 정보는 공개하지 않는다.

## 확정 범위

- 서버 최초 발견 기록이 있는 요리만 표시한다.
- 미발견 요리는 카드, 실루엣, 개수 등 어떤 형태로도 노출하지 않는다.
- 카드에는 요리 이미지, 요리 이름, 최초 발견자 이름만 표시한다.
- 재료, 조리법, 효과, 등급, 필요 레벨, 발견 시각은 표시하지 않는다.
- 정렬은 최근 발견순, 오래된 발견순, 요리 이름순, 발견자 이름순을 제공한다.
- 기본 정렬은 최근 발견순이다.
- 한 페이지에 20개를 표시하고 모바일은 1열, 넓은 화면은 2열로 배치한다.

## 제외 범위

- 별도 공개 API 또는 DB 테이블을 추가하지 않는다.
- 개인 요리 도감의 공개 범위나 제작 기능을 변경하지 않는다.
- 발견자 프로필 링크, 검색, 필터, 발견 시각 표시는 추가하지 않는다.
- 전체 소식 발행 규칙과 최초 발견 판정 규칙은 변경하지 않는다.

## 현재 구조

`/api/v2/cooking`은 다음 공개 정보를 이미 함께 반환한다.

- `recipes`: 공개 레시피 ID, 이름, 이미지 등. 정답 재료는 포함하지 않는다.
- `firstDiscoveries`: 레시피 ID, 권위 이름으로 보정된 최초 발견자, 발견 시각, 본인 여부.

비밀 재료 조합은 사용자가 직접 발견한 레시피에 한해 `knownRecipes`로 반환된다. 새 공개 목록은 `knownRecipes`를 읽거나 전달받지 않는다.

## 화면 구조

`CookingPanel`의 `CookingSection`에 `public`을 추가하고 기존 주방 탭 줄에 `공개 발견`을 배치한다. 선택 시 전용 `CookingPublicDiscoveryPanel`을 렌더링한다.

패널 상단에는 제목, 공개된 요리 수, 정렬 선택 상자를 둔다. 본문 카드는 불투명한 기존 표면 상수를 사용하며 다음 세 요소만 가진다.

- 요리 이미지
- 요리 이름
- `최초 발견자: {이름}`

공개된 요리가 없으면 `아직 공개된 요리가 없습니다.`를 표시한다. 카드 목록 아래에는 기존 `Pagination`을 사용한다.

## 데이터 경계

클라이언트 전용 변환 함수가 `recipes`와 `firstDiscoveries`를 받아 공개 카드 모델을 만든다.

```ts
type PublicCookingDiscovery = {
  recipeId: string;
  recipeName: string;
  imageSrc: string;
  actorName: string;
  discoveredAt: number;
};
```

변환 함수는 최초 발견 기록을 기준으로 공개 레시피 카탈로그와 결합한다. 카탈로그에 없는 레시피 ID는 제외한다. 결과 모델에 재료, 조리법, 효과, 등급, 필요 레벨, 본인 여부는 포함하지 않는다. `discoveredAt`은 정렬에만 사용하고 화면에는 출력하지 않는다.

API와 DB는 변경하지 않는다. 최초 발견자 이름은 현재 요리 API의 권위 이름 보정과 `이름 없는 모험가` 대체 규칙을 그대로 따른다.

## 정렬

정렬 값은 다음 네 가지다.

- `recent`: 발견 시각 내림차순
- `oldest`: 발견 시각 오름차순
- `recipe_name`: 요리 이름 한국어 오름차순
- `actor_name`: 발견자 이름 한국어 오름차순

같은 1차 정렬 값에서는 요리 이름, 레시피 ID 순으로 비교해 결과가 흔들리지 않게 한다. 알 수 없는 정렬 값은 `recent`로 정규화한다. 정렬이 바뀌면 페이지를 1쪽으로 되돌린다.

## 오류 및 빈 데이터 처리

- 최초 발견 기록이 없으면 정상적인 빈 상태를 표시한다.
- 레시피 카탈로그와 결합할 수 없는 과거 기록은 해당 항목만 제외한다.
- 발견자 이름 보정은 서버의 기존 정책을 사용하며 UI가 별도 이름 추론을 하지 않는다.
- 이미지 로딩은 기존 Next.js `Image`와 요리 이미지 경로를 사용한다.
- 일부 잘못된 기록 때문에 전체 주방 화면을 실패시키지 않는다.

## 보안 및 정보 공개

새 탭은 전체 소식에서 이미 공개되는 요리 이름과 최초 발견자에 기존 공개 이미지 하나만 더해 보여준다. 비밀 정답이 있는 `knownRecipes`는 새 컴포넌트의 입력이 아니며, 카드 모델에도 상세 레시피 필드를 두지 않는다. 따라서 개인이 아직 발견하지 않은 요리의 재료 조합이나 제작 상세는 노출되지 않는다.

## 테스트

- 변환 함수가 최초 발견 기록이 있는 요리만 만들고 카탈로그 불일치 기록을 제외하는지 검증한다.
- 네 가지 정렬과 동률 보조 정렬, 잘못된 정렬 값의 기본값 처리를 검증한다.
- 공개 패널이 이미지, 요리 이름, 최초 발견자만 표시하는지 검증한다.
- 미발견 요리와 재료명, 조리법, 효과, 등급, 필요 레벨이 출력되지 않는지 검증한다.
- 빈 상태, 20개 페이지 크기, 정렬 변경 시 첫 페이지 복귀를 검증한다.
- `CookingPanel`에 `공개 발견` 탭이 추가되고 선택 시 전용 패널이 렌더링되는지 검증한다.
- 기존 개인 도감, 연구, 전문 분야, 납품, 재료 가공 테스트를 함께 실행한다.

## 완료 기준

- 이용자는 주방의 `공개 발견` 탭에서 서버 최초 발견 요리만 볼 수 있다.
- 각 카드에는 이미지, 이름, 최초 발견자만 보인다.
- 미발견 요리와 상세 레시피 정보는 보이지 않는다.
- 이용자는 네 가지 정렬을 직접 선택할 수 있다.
- 기존 요리 API, 개인 도감, 조리 및 전체 소식 동작은 바뀌지 않는다.
