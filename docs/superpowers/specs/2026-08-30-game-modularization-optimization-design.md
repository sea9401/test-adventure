# 게임 모듈화·최적화 설계

## 목표

현재 게임 동작과 밸런스를 유지하면서 커진 클라이언트 상태·거래소·상태 API·사냥·전투 모듈의 책임을 단계적으로 분리한다. 줄 수만 줄이는 작업이 아니라 재렌더 범위, 화면 진입 요청 수, 읽기 API의 부수효과, 고위험 전투 코드의 변경 면적을 실제로 줄인다.

## 작업 순서

1. 현재 실패 중인 모듈 예산과 정적 품질 게이트를 복구한다.
2. `GameStateProvider`를 신원, 자원, 활동, 세계 상태의 좁은 컨텍스트로 나눈다.
3. 거래소의 기본 탐색과 고급 주문 도구를 분리하고 불필요한 선행 요청을 지연한다.
4. `/api/v2/me/state`의 조회 조립과 쓰기성 보정 작업을 분리한다.
5. 사냥 라우트와 전투 엔진은 결정적 회귀 테스트를 유지한 채 책임 단위로만 분리한다.

각 단계는 테스트, 타입 검사, 모듈 예산 검사 후 로컬 커밋한다. 배포·푸시·병합은 범위에 포함하지 않는다.

## 구조

### 품질 게이트

`scripts/module-budgets.mjs`의 상한은 올리지 않는다. 예산을 넘긴 여섯 모듈에서 이미 독립된 순수 계산, 응답 조립, 대화상자 또는 상태 계약을 별도 파일로 이동한다. 기존 공개 API와 응답 형태는 유지한다.

### 전역 게임 상태

기존 `useGameState()`는 호환 어댑터로 잠시 유지하되, 자주 변하는 자원과 거의 변하지 않는 신원·세계 상태를 별도 컨텍스트로 제공한다. 소비처는 작은 필드만 사용하는 곳부터 좁은 훅으로 옮긴다. 장비·낚시 도감 컨텍스트는 현재 구조를 유지한다.

### 거래소

기본 둘러보기에는 목록과 화면에 즉시 필요한 정보만 요청한다. 구매 주문·가격 알림·판매용 인벤토리는 해당 탭이나 도구가 실제로 열릴 때 가져온다. 주문 관리 대화상자는 동적으로 로드하며, 거래 후 서버 권위 잔액 갱신은 유지한다.

### 내 상태 API

저장값 일괄 조회와 core/full 응답 조립은 유지한다. 캐릭터 생성 보장, 장착 스킬 보정, 조건부 칭호 지급 같은 쓰기성 책임은 명시적인 초기화·조건 달성 경계로 옮길 수 있도록 서비스로 분리한다. 첫 단계에서는 응답 호환성을 보존하고, 테스트로 부수효과 호출 조건을 고정한 뒤 이동한다.

### 사냥·전투

사냥의 저장값 선행 로드와 일괄 flush 최적화는 유지한다. 요청 해석, 단판 실행, 일괄 집계, 응답 조립을 분리한다. 전투 엔진은 PvE 규칙을 바꾸지 않고 순수 상태 전이 또는 결과 조립 단위만 이동하며, 고정 시드 회귀 테스트를 통과해야 한다.

## 오류·호환성

- API 상태 코드, `error` 코드, JSON 필드, 클라이언트 안내 문구를 변경하지 않는다.
- 거래소 요청 실패 시 현재 데이터를 유지하는 기존 동작을 보존한다.
- 컨텍스트 분리 중 기존 `useGameState()` 소비처가 즉시 깨지지 않도록 호환 훅을 유지한다.
- 전투·사냥의 RNG 호출 순서와 저장 잠금 순서를 변경하지 않는다.

## 검증 기준

- 모듈 예산 검사 0건 실패
- 변경 범위의 회귀 테스트 통과
- TypeScript 검사 통과
- ESLint 검사 통과
- 전체 테스트 통과
- 거래소 기본 탭에서 구매 주문·가격 알림 API가 도구 사용 전 호출되지 않음
- 좁은 상태 컨텍스트 소비자가 무관한 자원 변경에 재렌더되지 않음
- 사냥·전투 고정 시드 결과가 분리 전과 동일함

## 제외 범위

- 밸런스 계수 변경
- 데이터 삭제 추가 진행
- DB 스키마 변경과 신규 인덱스
- UI 디자인 변경
- 배포, 푸시, 병합
