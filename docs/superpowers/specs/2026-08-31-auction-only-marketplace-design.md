# 경매장 전 품목 입찰제 전환 설계

## 목표

경매장의 즉시 구매와 구매 주문을 제거하고 모든 판매 등록을 6시간짜리 입찰 경매로 통일한다. 재료·소모품처럼 수량을 묶어 등록하는 품목도 등록 묶음 전체를 한 번에 입찰·낙찰하게 하며, 판매자가 나눠 팔고 싶으면 원하는 수량별로 여러 건을 직접 등록한다. 종료 직전 입찰에는 10분 연장을 적용해 마지막 순간 가로채기를 줄인다.

## 확정 정책

- 모든 신규 판매 등록은 등록 시점부터 정확히 6시간 동안 입찰을 받는다.
- 판매자가 입력하는 가격은 즉시 구매가나 개당 가격이 아니라 `등록 묶음 전체의 시작 입찰가`다.
- 장비 한 개는 기존처럼 한 등록 단위다.
- 재료·소모품은 판매자가 고른 수량 전체가 한 등록 단위다. 예를 들어 재료 10개를 등록하면 입찰자와 낙찰자는 10개 전체를 거래한다.
- 재료 10개를 2개·3개·5개로 나눠 팔려면 판매자가 각각 별도 등록한다. 구매자가 등록 묶음 일부만 선택하거나 여러 등록을 합쳐 수량 구매하는 기능은 제공하지 않는다.
- 첫 입찰은 시작 입찰가 이상이어야 한다.
- 입찰이 하나 이상 있으면 다음 최소 입찰가는 기존 규칙인 `max(현재가 + 1, ceil(현재가 × 1.05))`를 유지한다.
- 유효한 입찰이 들어온 순간 남은 시간이 10분 미만이면 기존 종료 시각에 10분을 더한다. 정확히 10분이 남았을 때는 연장하지 않는다.
- 종료 직전 입찰이 반복되면 매번 같은 규칙으로 누적 연장하며 횟수 상한은 두지 않는다.
- 경매 종료 시 최고 입찰자가 있으면 묶음 전체를 낙찰하고, 없으면 판매자에게 묶음 전체를 반환한다.
- 기존 판매 수수료, 골드·물품 에스크로, 거래 정지, 익명 표시, 거래 이력과 신고 규칙은 유지한다.
- 판매자는 입찰이 생기기 전까지만 등록을 취소할 수 있다. 시작가 수정 기능은 제거하며, 바꾸려면 취소 후 다시 등록한다.

## 선택한 접근

기존 `marketplace_listings_v2`, 입찰, 받은 편지함, 에스크로 및 정산 구조를 재사용하고 경매 전용 정책으로 좁힌다. 별도 경매 테이블을 새로 만드는 방식은 정산과 에스크로를 중복 구현해 오류 위험이 크고, 구형·신형 방식을 병행하는 방식은 즉시 구매 우회 경로와 운영 복잡성을 남기므로 채택하지 않는다.

기존 행과 신규 경매 행을 구분하는 `auction_mode_version` 정수 필드를 판매 등록에 추가한다. 마이그레이션 기본값은 `0`으로 두어 배포 시점 이전 행을 레거시로 유지하고, 신규 등록 API만 현재 버전 `1`을 명시적으로 기록한다. 조회는 버전 `1` 등록만 노출하고, 만료 처리 작업이 버전 `0`의 활성 판매 등록과 구매 주문을 멱등적으로 회수한다.

## 시간과 입찰 모델

서버의 단일 정책 모듈이 다음 값을 권위 있게 제공한다.

- 기본 경매 시간: 6시간
- 종료 임박 판정 구간: 10분
- 유효 입찰 시 연장 시간: 10분
- 최소 인상률: 5%

신규 등록의 `bidEndsAt`은 `createdAt + 6시간`이며, `expiresAt`은 현재 스키마 제약을 만족하도록 `bidEndsAt`보다 뒤에 두되 고정가 판매 단계에는 사용하지 않는다. 연장 시에는 동일한 간격을 유지하도록 `bidEndsAt`과 `expiresAt`을 함께 10분 이동한다.

입찰 API는 판매 등록 행을 잠근 트랜잭션 안에서 다음 순서로 처리한다.

1. 경매 전용 등록인지, 아직 종료되지 않았는지, 본인 등록이 아닌지 검증한다.
2. 입찰이 없으면 묶음 시작가, 있으면 현재 최고 입찰가의 5% 인상값을 최소 입찰가로 계산한다.
3. 입찰자의 골드를 에스크로로 이동하고 이전 최고 입찰자의 골드를 받은 편지함으로 반환한다.
4. 최고 입찰과 입찰 횟수를 저장한다.
5. 입찰 직전 남은 시간이 10분 미만이면 기존 종료 시각에 10분을 더해 저장한다.
6. 응답에 변경된 종료 시각과 다음 최소 입찰가를 포함해 클라이언트 타이머를 즉시 갱신한다.

행 잠금 안에서 종료 시각을 다시 읽고 갱신하므로 동시 입찰도 직렬화되며 연장을 잃지 않는다. 종료 시각 이후 도착한 요청은 정산 작업 실행 전이라도 거절한다.

## 경매 정산

주기 정산 작업은 종료된 경매 전용 등록을 다음과 같이 처리한다.

- 최고 입찰자가 있음: 등록 묶음 전체를 낙찰자 받은 편지함에 넣고, 기존 세율을 차감한 판매 대금을 판매자에게 넣는다.
- 최고 입찰자가 없음: 등록 묶음 전체를 판매자에게 반환한다.
- 정산이 이미 끝난 등록: 다시 지급하지 않는다.

현재처럼 종료 후 고정가 판매 단계로 전환하지 않는다. 정산 작업이 수 분 늦더라도 종료 시각이 지난 경매에는 새 입찰을 받지 않으며 화면에는 `정산 중`으로 표시할 수 있다.

## 기존 데이터 반환

전환 시 기존 활성 판매 등록은 새로운 6시간 경매로 바꾸지 않고 전부 반환한다.

- 등록된 장비·재료·소모품은 판매자에게 반환한다.
- 기존 판매 등록에 잡힌 최고 입찰금은 해당 입찰자에게 전액 반환한다.
- 활성 구매 주문은 모두 취소하고 주문에 예치된 골드를 주문자에게 전액 반환한다.
- 이미 완료·취소·만료된 과거 기록은 변경하지 않는다.
- 반환은 기존 에스크로 취소 함수를 재사용하고, 처리 완료 상태를 조건부 갱신해 반복 실행해도 중복 지급하지 않는다.

전환 직후 레거시 등록과 구매 주문은 사용자 조회에서 숨긴다. 정산 작업은 제한된 묶음으로 회수 작업을 반복해 한 번의 긴 트랜잭션이나 서버 정지를 피한다. 따라서 이 기능 자체는 본 서버 점검 모드를 요구하지 않는다. 실제 배포와 점검 모드 운용은 저장소의 별도 배포 규칙을 따른다.

## API 변경

### 유지·변경

- 판매 등록 API: `graceHours`를 받지 않고 서버가 6시간을 고정한다. 스택 품목의 `price`는 전체 묶음 시작가다.
- 입찰 API: 시작가 검증과 종료 임박 연장을 적용하고 새 종료 시각을 반환한다.
- 조회 API: 경매 전용 등록만 반환하고 6시간·10분 정책값을 제공한다.
- 취소 API: 입찰 전 본인 등록만 취소할 수 있는 규칙을 유지한다.
- 입찰 내역·거래 이력·시세·신고 API: 최종 낙찰 거래를 기준으로 유지한다.
- 가격 알림 API: 기존 개당 목표 가격을 유지하되, 신규 스택 경매의 `묶음 시작가 ÷ 수량`이 목표 이하일 때 알린다. 알림 문구는 즉시 구매 가능 가격이 아니라 시작 입찰가 기준임을 밝힌다.

### 종료

다음 구형 쓰기 API는 UI에서 제거하는 것만으로 끝내지 않고 서버에서도 `410 Gone`과 일관된 `marketplace_feature_retired` 오류를 반환한다. 구형 클라이언트가 직접 호출해 정책을 우회하지 못하게 하기 위해서다.

- 장비 즉시 구매
- 스택 수량 즉시 구매
- 구매 주문 생성·수정·취소
- 구매 주문에 장비 판매·일괄 판매
- 판매 등록 시작가 수정

## 사용자 화면

- 경매장 구매 탭은 `경매` 의미가 드러나도록 문구를 정리한다.
- 등록 화면에서 기간 선택을 제거하고 `등록 후 6시간`을 고정 안내한다.
- 가격 입력 라벨은 장비와 스택 모두 `시작 입찰가`로 표시한다. 스택 품목은 `묶음 전체 가격`임을 바로 옆에 안내한다.
- 카드에는 시작가, 현재 최고 입찰가, 다음 최소 입찰가, 묶음 수량, 남은 시간을 표시한다.
- 구매·수량 선택·구매 주문·일괄 판매 버튼을 제거하고 입찰 버튼만 제공한다. 가격 알림은 `시작 입찰가 알림`으로 이름과 설명을 바꿔 유지한다.
- 스택 품목도 각 판매 등록을 개별 카드로 표시한다. 같은 품목 등록을 하나의 수량 구매 묶음으로 합치지 않는다.
- 입찰 성공 응답의 종료 시각으로 해당 카드 타이머를 갱신해 10분 연장을 즉시 보여 준다.
- 입찰이 없는 본인 등록에는 취소를 제공하고, 입찰이 생기면 취소할 수 없음을 표시한다.
- 종료 시각이 지났지만 서버 정산 전이면 즉시 구매나 입찰을 열지 않고 `정산 중`으로 표시한다.

기존 화면의 불투명 표면 토큰 사용 규칙을 유지하며 이번 변경에서 별도의 시각 체계를 만들지 않는다.

## 오류와 경계 조건

- 시작가보다 낮은 첫 입찰은 거절한다.
- 최고 입찰가가 시작가와 같아도 유효한 낙찰로 처리한다.
- 남은 시간이 정확히 10분이면 연장하지 않고, 10분보다 조금이라도 적으면 10분 연장한다.
- 연장은 입찰 시각부터 10분으로 재설정하는 것이 아니라 기존 종료 시각에 10분을 더한다.
- 연장 도중 들어온 동시 입찰은 행 잠금 이후의 최신 종료 시각을 기준으로 각각 판단한다.
- 종료 시각과 같은 시각 또는 그 이후의 입찰은 거절한다.
- 판매 등록 취소와 입찰이 경합하면 먼저 행 잠금을 얻어 성공한 요청만 상태를 변경한다.
- 스택 낙찰은 항상 저장된 등록 수량 전체를 한 번만 이동한다.
- 레거시 반환 중 보관함 한도나 장비 인벤토리 한도는 기존 받은 편지함 에스크로 복원 경로로 처리한다.
- 거래 정지된 계정의 판매 등록·입찰·정산은 기존 정책을 유지한다.

## 테스트

- 정책 순수 함수 테스트로 6시간 종료 시각, 첫 입찰 시작가, 5% 최소 인상, 정확히 10분 경계, 10분 미만 연장과 반복 누적 연장을 고정한다.
- 판매 등록 API가 모든 품목에 6시간과 경매 전용 버전을 저장하고 클라이언트의 기간 입력을 무시하거나 거절하는지 검증한다.
- 스택 등록 가격이 개당 가격이 아니라 묶음 전체 시작가로 사용되는지 검증한다.
- 입찰 API가 시작가 미달을 거절하고, 이전 최고 입찰금을 반환하며, 행 잠금 안에서 새 종료 시각을 저장·반환하는지 검증한다.
- 정산 작업이 최고 입찰자에게 묶음 전체를 지급하고 기존 세금을 적용하는지, 무입찰 경매는 판매자에게 반환하는지 검증한다.
- 레거시 판매 등록의 물품·최고 입찰금과 활성 구매 주문 예치금이 멱등적으로 반환되는지 검증한다.
- 종료된 API가 모두 `410 Gone`을 반환해 구형 클라이언트 우회를 차단하는지 검증한다.
- 가격 알림이 묶음 시작가를 수량으로 나눈 개당 가격에만 반응하고 즉시 구매를 암시하지 않는지 검증한다.
- 화면 테스트로 기간 선택, 즉시 구매, 수량 구매, 구매 주문과 일괄 판매 컨트롤이 사라지는지 검증한다.
- 스택 등록이 개별 묶음 카드로 표시되고 입찰 성공 후 연장된 종료 시각이 반영되는지 검증한다.
- 거래 정지, 세금, 에스크로, 희귀 지도 장비 복원, 거래 이력과 신고의 기존 회귀 테스트를 유지한다.

## 비범위

- 최소 인상률 5%, 판매 수수료율, 경매장 익명 정책 변경
- 판매자 대신 서버가 한 묶음을 자동 분할하는 기능
- 구매자가 한 등록의 일부 수량만 낙찰하거나 여러 등록을 한 번에 공동 입찰하는 기능
- 경매 종료 알림, 자동 입찰 상한, 예약 입찰, 입찰 횟수 제한
- 기존 완료 거래 이력 삭제 또는 과거 시세 데이터 재작성
- 운영 배포와 점검 모드 활성화·해제
