# 요리 납품 조건 표시 설계

## 문제

요리 조건 납품 카드는 요청 제목과 목표 점수만 보여 준다. 효과군 요청만 제목에 효과 조건을 덧붙이는 예외가 있지만, 모든 요청에 공통으로 적용되는 최소 품질은 표시하지 않는다. 이 때문에 같은 분야가 일일 요청과 주간 만찬에 동시에 배정되면 `일반 이상`인 일일 요청에는 납품할 수 있지만 `정성작 이상`인 주간 만찬에는 납품할 수 없는 이유를 화면에서 알 수 없다.

## 결정

일일 3건과 주간 만찬 1건의 모든 카드에 `조건:` 행을 추가한다. 행에는 요청에 존재하는 분야, 조리법, 효과군을 순서대로 표시하고 마지막에 최소 품질을 항상 `이상` 조건으로 표시한다.

예시는 다음과 같다.

- `조건: 화덕 분야 · 일반 이상`
- `조건: 굽기 조리 · 일반 이상`
- `조건: 공격 효과 · 정성작 이상`
- `조건: 화덕 분야 · 정성작 이상`

요청 제목은 원래 제목을 그대로 사용한다. 기존 효과군 요청의 제목에만 효과를 덧붙이던 예외 표시는 제거해 조건 행과 중복되지 않게 한다.

## 구현 경계

- `CookingDeliveryCondition`을 사람이 읽는 문장으로 바꾸는 순수 함수를 납품 도메인 모듈에 둔다.
- 기존 `COOKING_FIELD_NAMES`, `COOKING_METHOD_NAMES`, `COOKING_EFFECT_TAG_NAMES`, `cookingQualityName`을 재사용한다.
- `CookingDeliveryPanel`은 순수 함수 결과를 모든 `RequestCard`에 렌더링한다.
- 요청 생성, 점수 판정, 납품 가능 음식 필터, API 응답 형식과 보상은 변경하지 않는다.
- 새 표면을 만들지 않으며 기존 불투명 `SURFACE_INSET` 카드 안에 텍스트만 추가한다.

## 검증

- 순수 함수가 분야·조리법·효과군의 조합과 최소 품질을 빠짐없이 올바른 순서로 표시하는지 단위 테스트한다.
- 실제 납품 화면을 렌더링해 일일 일반 품질 조건과 주간 정성작 품질 조건이 동시에 보이는지 회귀 테스트한다.
- 요리 관련 집중 테스트, ESLint, TypeScript 검사를 실행한다.
