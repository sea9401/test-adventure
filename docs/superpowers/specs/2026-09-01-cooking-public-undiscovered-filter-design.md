# 공개 발견 요리 도감 미등록 필터 설계

## 문제

주방의 `공개 발견` 탭은 최근 발견순, 오래된 발견순, 요리 이름순, 발견자 이름순만 제공한다. 플레이어가 공개 발견된 요리 중 자신의 도감에 아직 등록하지 않은 요리를 찾으려면 공개 목록과 개인 도감을 외부에서 직접 대조해야 한다.

## 결정

기존 `공개 발견 정렬` 선택지에 `도감 미등록`을 추가한다. 이 선택지는 현재 사용자의 요리 도감에 등록되지 않은 공개 발견 카드만 남기며, 결과 순서는 기존 기본값과 같은 최근 발견순을 사용한다. 선택을 바꾸면 페이지네이션은 첫 페이지로 돌아간다.

필터 결과가 없으면 `공개 발견 요리는 모두 도감에 등록했습니다.`를 표시한다. 다른 정렬에서 공개 발견 자체가 없을 때는 기존 `아직 공개된 요리가 없습니다.` 문구를 유지한다.

## 데이터 경계

- 서버는 공개 발견 항목마다 현재 사용자 기준의 `codexRegistered: boolean`만 계산해 응답한다.
- 서버 전용 레시피 ID, 재료, 조리법, 효과와 같은 비밀 정보는 추가로 공개하지 않는다.
- 클라이언트는 이 불리언만 사용해 필터링하므로 요리 이름의 유일성이나 표시 문구에 의존하지 않는다.
- 공개 발견 데이터의 기존 정렬 네 가지와 기본 폴백은 그대로 유지한다.

## UI와 접근성

- 새 컨트롤을 만들지 않고 기존 `공개 발견 정렬` 셀렉트에 옵션 하나만 추가한다.
- 기존 불투명 `SURFACE_CARD`, `SURFACE_INSET` 표면을 유지한다.
- 표시되는 개수는 필터 적용 후 결과 수를 사용한다.

## 검증

- API 테스트에서 도감 등록 여부가 현재 사용자의 저장 상태를 반영하면서 비밀 레시피 ID는 노출하지 않는지 확인한다.
- 순수 목록 테스트에서 `도감 미등록`이 등록 항목을 제외하고 최근 발견순을 유지하는지 확인한다.
- 컴포넌트 테스트에서 옵션 선택, 필터 결과, 첫 페이지 복귀, 전용 빈 상태를 확인한다.
- 관련 요리 테스트, ESLint, TypeScript 검사를 실행한다.
