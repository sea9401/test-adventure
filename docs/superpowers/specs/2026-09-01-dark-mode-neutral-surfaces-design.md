# 다크모드 중립 표면 정비 설계

## 배경

현재 게임 UI는 라이트모드에서 강조 카드가 밝은 색면으로 자연스럽게 구분되지만, 다크모드에서는 `amber-950`, `emerald-950`, `violet-950` 같은 매우 어두운 유채색이 카드와 패널 전체를 채우는 경우가 많다. 여러 강조 영역이 한 화면에 모이면 갈색·녹색·보라색 덩어리가 겹쳐 보이고, 표면의 높낮이보다 색면이 먼저 보여 화면이 무겁고 칙칙해진다.

최신 `staging` 기준으로 실제 게임 코드에서 `SURFACE_ACCENT`를 사용하는 파일은 39개이며, `src/adventure`와 게임에서 공유하는 `src/components`에는 `dark:bg-<색상>-900/950` 계열을 직접 지정한 파일이 141개다. 이 직접 지정에는 카드뿐 아니라 배지, 게이지, 버튼도 섞여 있으므로 기계적 일괄 치환은 정보 의미를 훼손한다.

## 목표

- 다크모드의 큰 카드, 패널, 선택 행과 안내 영역을 중립 회색 표면으로 통일한다.
- 의미색은 테두리, 아이콘, 핵심 숫자, 선택 링과 실행 버튼에 집중한다.
- 카드와 인셋의 높낮이, 상태와 선택 여부가 색면 없이도 분명하게 읽히게 한다.
- 라이트모드의 현재 색감과 동작은 유지한다.
- 이후 게임 화면에 큰 진한 유채색 표면이 다시 무분별하게 추가되지 않도록 검사 기준을 남긴다.

## 제외 범위

- 관리자, 개발 도구, 매뉴얼, 로그인과 캐릭터 생성 화면
- 게임 로직, API, 데이터 구조와 밸런스
- 아이템 희귀도, 상태 이상, 직업/속성 구분처럼 색 자체가 정보인 작은 요소의 재설계
- 새로운 반투명 또는 글래스 표면 도입

## 선택한 방향

사용자가 시각 비교에서 **중립 표면 + 포인트 강조(A안)**을 선택했다.

다크모드에서 넓은 영역은 `zinc` 계열의 불투명 표면을 사용한다. 강조 의미는 기존 색상의 테두리와 텍스트, 아이콘에 남긴다. 현재 불투명 표면 원칙과 배경 이미지 가독성 규칙을 유지하며, 색을 줄이기 위해 투명도를 사용하지 않는다.

### 검토한 대안

1. **토큰 우선 + 선별 감사 — 채택**
   공통 표면을 먼저 바꾸고, 공통 토큰을 우회한 큰 유채색 표면만 문맥에 따라 중립화한다. 일관성과 정보 보존을 함께 달성할 수 있다.
2. **전체 색상 클래스 일괄 치환 — 기각**
   빠르지만 희귀도 배지, 전투 상태, 게이지와 실행 버튼까지 중립화해 중요한 시각 정보를 잃는다.
3. **화면별 전면 재설계 — 기각**
   화면별 완성도는 높일 수 있으나 범위가 지나치게 커지고 같은 역할의 표면이 다시 서로 다른 방식으로 구현될 위험이 있다.

## 표면 체계

### 공통 표면

- `SURFACE_CARD`: 최상위 카드. 현재의 흰색/`zinc-900` 조합을 유지한다.
- `SURFACE_INSET`: 카드 내부의 파인 영역. 현재의 `zinc-50`/`zinc-950` 조합을 유지한다.
- `SURFACE_ACCENT`: 라이트모드는 기존 amber 표면을 유지한다. 다크모드는 중립 강조 표면으로 바꾸고 amber 테두리와 그림자로 강조 의미를 남긴다.
- `StatusBanner`: 라이트모드는 기존 상태색 배경을 유지한다. 다크모드는 중립 배경을 공유하고 상태별 테두리와 텍스트 색만 다르게 한다.

다크모드에서 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`는 배경 밝기와 테두리로 서로 구분되어야 한다. `SURFACE_ACCENT`는 큰 색면이 아니라 선택·보상·주의가 필요한 영역의 외곽 강조를 의미한다.

### 직접 지정 표면 감사

`src/adventure`와 실제 게임에서 사용되는 `src/components`를 전수 검색하고 아래 기준으로 분류한다.

중립화 대상:

- `section`, `article`, 큰 `div`, 목록 행, 선택 카드와 전체 너비 버튼의 유채색 다크 배경
- 여러 줄의 제목·설명·조작을 포함하는 안내, 경고, 성공 및 보상 패널
- 읽지 않음, 선택됨, 수령 가능 상태를 카드 전체 색면으로 표현한 영역
- 공통 표면 안에서 다시 큰 `*-900/950` 색면을 만드는 중첩 카드

유지 대상:

- 배지, 칩, pill, 아이콘 타일과 작은 카운터
- HP/MP/진행도/내구도 게이지와 그래프
- 아이템 희귀도, 등급, 속성, 전투 상태와 로그 유형 표시
- 기본·위험·확정 행동 버튼, 선택된 탭과 토글
- 짧게 나타나는 결과 토스트와 연출 전용 요소

경계가 애매한 요소는 면적과 정보 밀도를 기준으로 판단한다. 두 줄 이상의 본문이나 여러 조작을 품는 요소는 큰 표면으로 보고 중립화하며, 한 가지 상태를 짧게 표시하는 요소는 의미색을 유지한다.

## 구현 구조

1. 공통 표면 토큰과 `StatusBanner`를 먼저 변경한다.
2. UI 시스템 미리보기에 중립 강조 표면과 모든 상태 배너를 함께 표시해 기준 화면으로 사용한다.
3. 직접 유채색 배경 사용처를 기능군별로 감사한다.
   - 공통 게임 셸과 채팅
   - 캐릭터·장비·강화·마법부여
   - 전투·던전·협동·랭킹
   - 생활·낚시·농장·요리
   - 길드·시장·상점·도감·주거
4. 큰 표면만 중립 배경으로 바꾸고 기존 의미색 테두리·텍스트·아이콘을 유지한다.
5. 소스 검사를 추가해 공통 토큰이 다시 진한 유채색 다크 배경으로 회귀하지 않게 하고, 감사한 직접 지정 목록의 증가를 감지한다.

## 검증

- 공통 표면과 상태 배너의 라이트/다크 클래스 회귀 테스트
- 마법부여, 수령 가능 카드, 경고·성공 배너 등 대표 컴포넌트 렌더링 테스트
- 직접 `dark:bg-<색상>-900/950` 사용처 감사 결과와 허용된 소형 요소 기준 확인
- TypeScript, ESLint, 단위 테스트와 프로덕션 빌드
- `/dev/ui-system`과 대표 게임 화면의 라이트·다크 시각 확인
  - 마법부여
  - 홈/출석 또는 수령 가능 카드가 많은 화면
  - 전투/던전
  - 생활/낚시
  - 길드/시장
- 320px, 390px와 데스크톱 폭에서 배경 이미지가 카드 사이로 비치지 않고 선택·상태 구분이 유지되는지 확인

## 완료 조건

- 마법부여 화면의 대상 장비와 현재 옵션 영역이 다크모드에서 중립 표면으로 표시된다.
- `SURFACE_ACCENT`와 `StatusBanner`를 사용하는 모든 게임 화면이 큰 진한 유채색 채움 없이 표시된다.
- 직접 지정된 큰 유채색 다크 표면이 전수 감사되어 중립화되거나 소형 의미 요소로 명시적으로 유지된다.
- 라이트모드의 기존 색상과 상호작용이 바뀌지 않는다.
- 불투명 표면 규칙, 텍스트 대비와 선택 상태가 유지된다.
- 관련 테스트, 정적 검사와 빌드가 통과한다.
