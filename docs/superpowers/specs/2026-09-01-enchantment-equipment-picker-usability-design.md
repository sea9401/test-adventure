# 마법부여 장비 선택 사용성 개선 설계

## 목표

장비 마법부여 작업대에서 대상 변경 동선을 눈에 띄게 만들고, 많은 장비와 같은 이름의 장비도 부위·옵션·정렬 기준으로 빠르게 구분해 선택할 수 있게 한다. 재마법부여의 소멸 안내는 작업대 본문에서 제거하고 도움말로 모아 화면의 정보 밀도를 낮춘다.

## 범위

- 작업대의 장비 선택 진입 버튼 강조
- 선택 모달의 부위별 탭, 검색, 정렬 추가
- 인벤토리와 같은 시각 언어를 쓰는 장비 카드 목록 도입
- 현재 마법부여 옵션을 포함한 개체별 구분 정보 표시
- 재마법부여 소멸·줄 수 유지·즉시 실행 안내를 도움말로 이동
- 기존 최초 마법부여 확인과 재마법부여 즉시 실행 동작 유지

서버 API, 마법부여 확률, 비용, 옵션 생성 규칙은 변경하지 않는다. 이번 작업 자체로 어떤 환경에도 배포하지 않는다.

## 화면 구조

### 작업대 진입 버튼

현재 제목 옆의 작은 `장비 선택` 버튼을 작업대 상단의 독립된 큰 액션으로 바꾼다. 버튼에는 `대상 장비 변경`과 선택 가능한 장비 수를 함께 표시하고, violet 계열 테두리·아이콘·hover/focus 강조를 사용한다. 도움말 아이콘은 기존 위치를 유지하되 선택 버튼과 시각적으로 경쟁하지 않게 한다.

### 장비 선택 모달

모달은 다음 순서로 구성한다.

1. 제목과 닫기 버튼
2. 검색 입력과 정렬 select
3. `전체·무기·갑옷·장갑·신발·반지·목걸이` 탭
4. 장비 카드 그리드
5. 검색 또는 탭 결과가 없을 때의 빈 상태

모달을 열면 `전체` 탭과 `기본` 정렬로 시작한다. 검색어·탭·정렬은 함께 적용한다. 탭에는 해당 부위의 후보 개수를 표시한다.

### 장비 카드

선택창 전용 카드를 만들고 인벤토리 카드의 슬롯 아이콘, 티어·강화·품질 배지, 위력색 이름, 불투명 배경과 선택 강조 규칙을 따른다. 인벤토리의 판매·도감·상세 팝오버 동작은 가져오지 않는다.

각 카드는 다음 정보를 직접 표시한다.

- 장비 이름과 부위 아이콘
- 장착 중·잠금 상태
- 표시 티어, 강화 수치, 품질
- 굴림과 강화가 반영된 위력 및 핵심 기본 옵션
- 현재 마법부여 단계와 줄 수
- 마법부여된 경우 각 옵션의 이름·수치·레벨
- 마법부여되지 않은 경우 `미마법부여` 상태

모바일은 1열, `sm` 이상은 2열로 표시한다. 카드 전체를 누르면 장비를 선택하고 모달을 닫는다. 현재 선택 장비는 violet 테두리·ring·체크로 구분한다. 같은 이름의 장비는 품질, 위력, 강화 수치와 마법부여 옵션이 동시에 보여 개체를 구분할 수 있게 한다.

## 탭·검색·정렬 규칙

검색은 장비 이름을 한글 locale 기준 대소문자 구분 없이 포함 검색한다. 필터 적용 순서는 `검색 → 부위 → 정렬`이다.

정렬은 다음 여섯 가지를 제공한다.

- `기본`: 장착 장비 우선, 부위 순서, 이름순
- `최근 획득`: 보유 배열에서 나중에 들어온 장비부터
- `티어`: 표시 티어 높은 순
- `품질`: 굴림 품질 높은 순, 품질이 없는 장비는 뒤
- `위력`: 굴림·강화·제작 품질을 반영한 실효 위력 높은 순
- `마법부여 단계`: 3단계, 2단계, 1단계, 미마법부여 순

동률은 기본 정렬을 보조 기준으로 사용해 결과가 흔들리지 않게 한다. 인벤토리의 `sortEquipInstances`와 장비 표시 계산 함수를 재사용하되, 마법부여 단계 정렬과 장착 우선 기본 정렬은 선택창 전용 view model에서 조합한다.

## 도움말과 실행 동작

작업대 본문에 상시 노출된 rose 경고 박스를 제거한다. 도움말에 `재마법부여 안내` 섹션을 추가하고 다음 내용을 표시한다.

- 재마법부여하면 현재 옵션 전체가 즉시 소멸한다.
- 옵션 줄 수는 유지된다.
- 재마법부여 버튼을 누르면 별도 확인 없이 바로 진행된다.

최초 마법부여는 기존처럼 귀속과 옵션 줄 수 고정을 확인하는 모달을 한 번 표시한다. 이미 마법부여된 장비는 기존처럼 확인창 없이 즉시 API 요청을 보낸다.

## 코드 구조

- `EquipmentEnchantmentPickerDialog.tsx`: 검색·탭·정렬 상태와 선택 카드 렌더링을 전담한다.
- `EquipmentEnchantmentDialogs.tsx`: 도움말과 최초 마법부여 확인창을 유지하며 재마법부여 안내를 도움말에 추가한다.
- `EquipmentLiberationPanel.tsx`: 강조된 선택 진입 버튼, 모달 열기와 선택 결과 연결, 본문 경고 제거를 담당한다.
- `equipmentLiberationViewModel.ts`: 후보의 표시 정보, 탭 개수, 검색·부위 필터와 여섯 정렬 규칙을 순수 함수로 제공한다.

선택 모달을 별도 파일로 분리해 도움말·확인창과 목록 상태가 한 파일에 뒤섞이지 않게 한다. 기존 `LiberationCandidateRow`에는 획득 순서, 품질, 실효 위력, 기본 옵션 요약처럼 카드와 정렬에 필요한 파생값을 추가한다.

## 접근성과 표면 규칙

- 모달의 dialog semantics, focus trap, Escape 닫기와 바깥 영역 닫기를 유지한다.
- 탭은 `tablist`·`tab`과 `aria-selected`를 사용한다.
- 카드 목록은 `listbox`, 카드는 `option`과 `aria-selected`를 사용한다.
- 검색, 정렬, 탭 변경 후에도 현재 선택 상태를 보존한다.
- 카드와 컨트롤은 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT`를 사용해 라이트·다크 모드 모두 불투명한 표면을 유지한다.
- 잠금이나 미선택 상태에 카드 전체 opacity를 적용하지 않는다.

## 테스트 전략

TDD로 다음 동작을 먼저 실패하게 만든 뒤 구현한다.

1. view model이 전체·부위별 개수를 계산하고 검색과 부위 필터를 함께 적용한다.
2. 최근 획득·티어·품질·위력·마법부여 단계 정렬이 안정적으로 동작한다.
3. 선택 모달이 일곱 탭과 여섯 정렬 옵션을 표시하고 탭·검색 결과를 카드로 갱신한다.
4. 같은 이름의 두 장비 카드에 서로 다른 품질·위력·마법부여 옵션이 표시된다.
5. 강조된 대상 변경 버튼이 모달을 열고 카드를 누르면 선택 후 닫힌다.
6. 재마법부여 안내가 작업대 본문에는 없고 도움말에만 표시된다.
7. 재마법부여가 확인창 없이 즉시 요청되는 기존 회귀 테스트는 유지한다.

관련 테스트 통과 후 TypeScript, 변경 파일 ESLint, 프로덕션 빌드를 실행한다.
