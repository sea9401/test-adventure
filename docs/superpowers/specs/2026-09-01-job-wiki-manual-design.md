# 직업 위키형 매뉴얼 설계

## 배경

현재 게임 안내서의 `직업·숙련도·전직` 섹션은 직업 계보와 성장 규칙을 설명하지만,
개별 직업의 선행·후행 관계와 전체 스킬 효과를 한곳에서 읽을 수 없다. 전직 로드맵과
스킬 툴팁은 플레이 중 빠르게 확인하기에는 적합하지만, 복합 주문식·장착 시너지·PvE와
PvP 차이처럼 긴 설명을 담기에는 공간이 부족하다.

직업 카탈로그에는 141개 직업의 전직 조건, 직업 보너스, 수행 성장 프로필이 있고,
직업별 스킬 카탈로그에는 각 직업의 전체 스킬이 연결돼 있다. 이 데이터를 권위 원본으로
사용해 위키처럼 탐색 가능한 직업 상세 문서를 자동 생성한다.

## 목표

- 전투·생활 직업을 포함한 141개 직업을 로그인이나 해금 상태와 무관하게 공개한다.
- 직업명이나 스킬명으로 원하는 직업을 찾고, 전투/생활·직군·차수로 좁힐 수 있게 한다.
- 개별 직업 페이지에서 선행 필수 직업, 후행 가능 직업, 직업 보너스, 수행 성장과 전체
  스킬 정보를 확인할 수 있게 한다.
- 스킬의 기본 효과뿐 아니라 주문식 변형, 필요 보유·장착 스킬, 장착 시너지, PvE·PvP
  차이까지 구조화해 보여준다.
- 밸런스 수치와 관계를 별도 문서에 복사하지 않고 실제 게임 카탈로그에서 파생한다.
- 직업별 URL을 제공해 링크 공유와 검색 엔진 색인을 지원한다.

## 비목표

- 게임에 없는 설정 문구, 추정 공식, 숨은 효과를 새로 만들지 않는다.
- 플레이어의 현재 해금·숙련·스킬 보유 상태를 매뉴얼에 결합하지 않는다.
- 전직 로드맵이나 모험의 서 직업 도감의 게임플레이 UI를 교체하지 않는다.
- 이번 작업에서 기존 스킬 밸런스나 전투 동작을 변경하지 않는다.
- 141개 직업의 창작형 플레이버 텍스트를 별도로 집필하지 않는다. 소개문은 카탈로그에서
  확인할 수 있는 계열, 차수, 성장 스탯, 스킬 구성만 사용한다.

## URL과 정적 생성

### 목록

기존 `/manual/jobs`는 전직·숙련도·수행 안내를 그대로 유지하고 본문 하단에 `전체 직업
도감`을 추가한다. 별도 최상위 매뉴얼 섹션을 만들지 않아 기존 설명과 상세 도감의 진입점이
갈라지지 않게 한다.

### 상세

개별 직업은 `/manual/jobs/[jobId]`에서 제공한다. `V2_JOB_LIST`의 141개 직업 ID를
`generateStaticParams`로 모두 반환하고 `dynamicParams = false`를 사용한다. Next.js 16의
Promise 형태 `params`를 `await`해 읽는다. 등록되지 않은 ID는 정적 경로에 포함하지 않으며
404로 처리한다.

상세 페이지의 제목, 설명, canonical URL과 Open Graph 메타데이터는 직업 모델에서 생성한다.
페이지는 계정이나 요청 시점 데이터에 의존하지 않는 정적 서버 컴포넌트로 유지한다.

## 권위 데이터와 파생 모델

표시 컴포넌트가 원시 카탈로그 구조를 직접 조립하지 않도록 순수한 직업 매뉴얼 모델 빌더를
둔다. 이 빌더는 다음 원본만 읽는다.

- `V2_JOB_CATALOG` 및 `V2_JOB_LIST`: 이름, 차수, 전직 조건, 직업 보너스, 수행 성장
- `V2_SKILLS_BY_JOB` 및 `skillsForJob`: 직업별 전체 스킬 ID
- `V2_SKILLS`: 스킬 이름, 설명, 비용, 발동 조건과 구조화 효과
- 기존 직업 분류 헬퍼: 전투/생활, 직군과 계보 분류
- 기존 포매터: `jobUnlockConditionText`, `spCostOf`, `describeV2Skill`, 스탯·속성 라벨

### 직업 관계

선행 직업은 `unlock.prereqs`와 `jobUnlocked` 추가 조건에서 구한다. 후행 가능 직업은 전체
카탈로그를 역탐색해 현재 직업을 선행으로 참조하는 항목을 구한다. 관계는 이름과 요구
숙련도를 포함하며 상세 페이지 링크로 표시한다. 생활 레벨 같은 비직업 추가 조건도 기존
해금 조건 포매터를 통해 빠뜨리지 않는다.

### 분류와 소개

목록용 모델에는 직업 ID, 이름, 차수, 전투/생활 구분, 직군, 주요 수행 스탯, 소속 스킬
이름만 담는다. 검색용 클라이언트 데이터에 전체 효과식을 넣지 않아 번들 크기를 제한한다.

상세 소개는 `N차 {직군/생활} 직업`, 주요 수행 스탯, 액티브·패시브 스킬 수처럼 실제
데이터에서 검증되는 문장만 생성한다. 직군을 하나로 단정할 수 없는 복합 직업은 `복합`으로
표시하고 모든 선행 계보를 함께 보여준다.

### 스킬 정보

각 스킬은 다음 정보를 가진 상세 모델로 변환한다.

- 이름, ID, 액티브/패시브 구분, 스킬 차수와 기준 스탯
- SP 비용, 습득 숙달 포인트, 발동률, 실효 MP 비용, 쿨다운, 전투당 제한
- 카탈로그의 기본 설명
- `describeV2Skill`이 생성한 전체 효과 설명
- 주문식 변형별 이름, 필요 보유 스킬, 필요 장착 스킬과 변형 효과
- 장착 시너지별 필요 스킬과 추가 효과

주문식 변형과 장착 시너지는 ID 대신 사용자에게 보이는 스킬 이름을 사용하되, 원본 ID도
검색과 테스트를 위해 모델에 보존한다. 변형 효과는 기본 효과와 섞지 않고 별도 하위 표로
표시해 어느 조건에서 무엇이 바뀌는지 드러낸다. 카탈로그에 구조화된 PvP 수치와 제한은
기존 설명 포매터를 재사용한다.

동일 수치를 설명문에 다시 하드코딩하지 않는다. 기존 포매터가 구조화 필드를 설명하지
못하는 것이 발견되면 그 포매터를 확장하고 해당 필드의 회귀 테스트를 추가해 게임 내
툴팁과 매뉴얼이 함께 개선되게 한다.

## 목록 화면

`/manual/jobs` 하단의 도감은 작은 클라이언트 컴포넌트가 검색과 필터 상태만 관리한다.
서버에서 만든 가벼운 목록 모델을 props로 받으며 별도 API 요청은 하지 않는다.

### 검색

검색 대상은 직업명, 직업 ID, 소속 스킬명이다. 앞뒤 공백과 한글 대소문자 차이를 정규화한다.
검색 결과 수와 전체 수를 함께 표시한다. 결과가 없으면 필터 초기화 방법을 안내한다.

### 필터

- 전부 / 전투 / 생활
- 직군: 전사, 무도가, 마법사, 도적, 생존자, 변이자, 복합
- 차수: 0~7차 중 실제 목록에 존재하는 값

필터는 교집합으로 적용하고 개별 해제와 전체 초기화를 제공한다. 기본 상태에서는 카탈로그
정의 순서와 기존 계보 정렬 규칙을 따라 전부 표시한다.

### 카드

각 카드는 직업명, 차수·분류 배지, 주요 수행 스탯, 전용 스킬 이름을 보여주고 전체 카드가
상세 페이지 링크로 동작한다. 효과식은 목록에 싣지 않아 밀도와 전송량을 관리한다.

## 상세 화면

상세 페이지는 기존 `ManualLayout`을 재사용하고 `직업·숙련도·전직` 메뉴를 활성 상태로
유지한다. 본문은 다음 순서다.

1. 목록으로 돌아가는 링크와 직업명, 차수·직군·전투/생활 배지
2. 데이터 기반 한 줄 소개
3. 선행 필수 직업과 비직업 추가 조건
4. 후행 가능 직업
5. 직업 고정 보너스와 수행 성장 프로필
6. 소속 스킬 전체 목록
7. 선행·후행 직업과 목록으로 이동하는 하단 탐색

직업 고정 보너스는 실제 플랫 보너스로 표시하고, 수행 성장은 `STR ×4`처럼 1회 성장의
상대 가중치를 보여준다. 존재하지 않는 최소 스탯이나 최대 숙련도 필드는 만들어내지 않는다.

스킬 카드는 기본적으로 핵심 메타데이터와 설명을 펼친 상태로 보여준다. 주문식 변형이나
시너지처럼 길고 반복되는 하위 정보만 `<details>`로 접을 수 있게 한다. 상세 페이지에 진입한
사용자가 다시 클릭해야 기본 효과를 볼 수 있는 구조는 피한다.

## 반응형·접근성·표면

- 모바일은 한 열, 넓은 화면은 요약 영역과 직업 카드 목록을 여러 열로 배치한다.
- 긴 효과와 조건은 자동 줄바꿈하고, 열 구조가 필요한 표만 자체 가로 스크롤을 허용한다.
- 검색 입력에는 명시적 레이블을, 필터 버튼에는 눌림 상태를 제공한다.
- 결과 수 변화는 과도한 실시간 알림 없이 화면에 텍스트로 표시한다.
- 링크와 `<details>`는 키보드로 조작할 수 있고 제목 계층은 `h1`부터 순서대로 유지한다.
- 최상위 본문과 모든 중첩 카드에는 `SURFACE_CARD`, `SURFACE_INSET`, `SURFACE_ACCENT` 중
  의도에 맞는 불투명 표면을 사용한다.
- 잠긴 카드 개념이 없으므로 컨테이너 전체 투명도는 사용하지 않는다.
- 라이트·다크 모드에서 배경 이미지가 본문이나 카드 뒤로 비치지 않는지 렌더 테스트와 수동
  확인을 수행한다.

## 누락과 오류 처리

- 알 수 없는 `jobId`: `notFound()`로 404 처리
- 카탈로그 직업이 존재하지 않는 스킬 ID를 참조: 모델 무결성 테스트 실패
- 스킬 ID는 유효하지만 정의를 읽을 수 없음: 프로덕션 UI에서 조용히 숨기지 않고 테스트로
  차단
- 실제 전용 스킬이 없는 직업: `전용 스킬 없음`을 정상 상태로 표시
- 선행 또는 후행 직업 없음: 각각 `선행 직업 없음`, `현재 공개된 후행 직업 없음` 표시
- 검색 결과 없음: 빈 화면 대신 검색어·필터 초기화 안내 표시

## 테스트 전략

### 모델 단위 테스트

- `V2_JOB_LIST`의 모든 직업이 목록 모델과 정적 경로에 정확히 한 번씩 포함된다. 현재
  카탈로그 기준 개수는 141개이며, 이후 직업이 추가되면 원본 목록을 따라 자동 증가한다.
- 모든 직업별 스킬 ID가 `V2_SKILLS`에 존재한다.
- 단일 계보, 복합 계보, 생활 레벨 조건, 7차 복수 선행의 관계가 올바르게 변환된다.
- 후행 관계가 선행 관계의 정확한 역관계다.
- 스탯 보너스와 수행 가중치가 원본 카탈로그 값에서 생성된다.
- 주문식 변형과 장착 시너지가 필요 스킬 이름 및 효과를 빠짐없이 보존한다.
- 실제 스킬이 없는 직업과 손상된 참조를 구분한다.

### 목록 컴포넌트 테스트

- 직업명과 스킬명 검색
- 전투/생활, 직군, 차수 필터의 교집합과 초기화
- 결과 수, 빈 결과 안내와 상세 링크
- 전체 스킬 효과를 목록 DOM에 펼치지 않고 가벼운 직업 카드 정보만 렌더한다.

### 상세 렌더 테스트

일반 단일 계보, 복합 직업, 주문식 변형이 있는 마법 직업, 7차 직업, 생활 직업, 전용 스킬이
없는 직업을 대표 사례로 렌더한다. 각 사례에서 관계, 성장, 스킬 메타데이터, 기본 효과,
변형과 시너지를 검증한다.

### 라우트와 품질 검증

- `generateStaticParams`가 전체 직업 ID를 반환하고 잘못된 ID가 404 처리된다.
- 직업별 메타데이터와 canonical URL을 검증한다.
- 목록과 상세 페이지의 모바일 구조, 제목 계층, 키보드 접근성과 불투명 표면을 검증한다.
- 대상 테스트, ESLint, 타입 검사와 전체 Vitest를 실행한다.
- Next.js 16 정적 경로 동작은 프로젝트 내 `node_modules/next/dist/docs/`의 현재 문서를 기준으로
  구현하고 빌드로 검증한다.

## 완료 기준

- `/manual/jobs`에서 모든 직업을 검색·필터하고 상세 페이지로 이동할 수 있다.
- 141개 직업 상세 페이지가 모두 정적으로 생성된다.
- 각 상세 페이지가 선행·후행 관계, 직업 성장과 소속 스킬 전체를 실제 데이터 기준으로
  보여준다.
- 복합 주문식과 장착 시너지의 조건·효과가 기본 효과와 구분되어 노출된다.
- 어떠한 직업이나 스킬도 플레이어 해금 상태 때문에 숨겨지지 않는다.
- 데이터 참조 누락은 테스트에서 실패하며 UI가 조용히 숨기지 않는다.
- 라이트·다크 및 모바일·데스크톱에서 본문과 카드의 가독성이 유지된다.
