# 마법부여 현재 대상 장비 표시 설계

## 목표

마법부여 대상 선택 창을 닫은 뒤에도 사용자가 어떤 장비를 선택했는지 이름뿐 아니라 개체를 구분할 수 있는 핵심 정보로 확인하게 한다. 같은 이름의 장비를 잘못 고른 경우 마법부여 실행 전에 알아차릴 수 있어야 한다.

## 범위

- 작업대 본문에 `현재 선택 장비` 요약 카드 추가
- 장비 이름, 부위, 표시 티어, 강화, 장착 여부, 잠금 여부, 위력, 품질 표시
- 장비 선택을 바꾸면 요약 카드도 즉시 갱신
- 기존 마법부여 옵션, 비용, 확률, API 요청 동작 유지
- 서버 API와 저장 데이터 변경 없음
- 배포하지 않음

## 화면 구조

작업대 상단은 일반 제목과 도움말 버튼만 표시한다. 기존 `대상 장비 변경` 버튼 바로 아래에 불투명한 `SURFACE_INSET` 요약 카드를 배치한다. 카드에는 작은 라벨 `현재 선택 장비`, 선택된 장비 이름과 부위 칩, 티어·강화·장착·잠금 배지, 위력과 품질을 표시한다.

마법부여 옵션은 별도의 기존 영역에 그대로 둔다. 따라서 장비 자체 정보와 마법부여 결과가 시각적으로 구분되며, 옵션이 없는 최초 마법부여 장비도 현재 대상을 명확히 확인할 수 있다.

## 구현 경계

`EquipmentLiberationPanel`은 이미 계산된 `LiberationCandidateRow`의 `displayTier`, `effectivePower`, `qualityPct`, `isEquipped`를 사용한다. 이름·부위·강화·잠금은 후보의 장비 인스턴스와 카탈로그에서 읽는다. 선택 창과 같은 `EquipmentTierBadge`, `EnhanceLevelBadge`, `QualityPctText`, `ItemTypeChip`을 재사용해 표시 기준을 일치시킨다.

새 상태나 API 호출은 추가하지 않는다. 기존 `selectEquipment`가 `selectedIid`를 바꾸면 현재 후보에서 파생된 요약 카드가 다시 렌더링된다.

## 접근성과 표면

- 요약 영역은 `aria-labelledby`로 `현재 선택 장비` 라벨과 연결한다.
- 선택된 장비 이름은 heading으로 유지해 선택 변경을 보조기술에서도 확인할 수 있게 한다.
- 카드와 배지는 불투명 표면을 사용하고 컨테이너 전체 opacity를 사용하지 않는다.
- 라이트·다크 모드 색상은 기존 공용 표면과 배지 컴포넌트를 따른다.

## 테스트

컴포넌트 테스트에서 서로 다른 부위·품질·위력을 가진 두 장비를 렌더링한다. 최초 대상 요약에 이름, 위력, 품질, 장착 상태가 보이는지 확인하고, 선택 창에서 다른 장비를 고른 뒤 요약의 이름·위력·품질이 새 장비 값으로 교체되는지 검증한다. 이 테스트는 요약 카드가 사라지거나 선택 상태와 동기화되지 않는 회귀를 잡는다.
