# 개척 노드 경로 일괄 선택 설계

## 목표

탐사망에서 먼 노드를 선택했을 때 화면에 보이는 최단 경로를 한 번의 요청으로 모두 활성화한다. 이미 활성화한 경로를 되돌릴 때도 선택한 노드와 그 노드 제거로 시작점에서 끊기는 외곽 노드를 한 번에 반환한다.

## 선택 방식

- 미개척 노드를 누르면 `탐사 시작`에서 대상까지의 기존 결정적 최단 경로를 사용한다.
- 경로에서 이미 활성화된 노드는 유지하고, 아직 활성화되지 않은 노드만 활성화 대기로 표시한다.
- 대기 노드를 경로 순서대로 가상 적용하여 포인트 부족, 보상 전환 충돌, 난이도 120 상한을 검사한다. 하나라도 위반하면 전체 경로를 적용하지 않는다.
- 활성 노드를 누르면 그 노드를 제거한 뒤 `탐사 시작`에서 도달할 수 없게 되는 활성 노드를 모두 반환 대기로 표시한다. 이는 선택한 노드를 반환하기 위해 필요한 최소 제거 집합이며, 다른 연결로 시작점에 남아 있는 가지는 보존한다.
- `탐사 시작` 노드는 반환할 수 없다.

## 화면

- 활성화 대기 노드는 보라색, 반환 대기 노드는 붉은색으로 표시하고 연결선도 같은 의도로 구분한다.
- 상세 패널에는 대상 노드 설명과 함께 적용 노드 수, 사용 포인트 또는 총 반환 골드를 표시한다.
- 활성화 버튼은 `탐사 포인트 N 사용 · N개 활성화`, 반환 버튼은 `합계G로 N개 반환`으로 표시한다.
- 경로 전체가 유효하지 않으면 기존 오류 문구를 사용하고 적용 버튼을 비활성화한다.
- 요청 중에는 중복 요청을 막고, 성공 응답의 서버 스냅샷으로 화면을 교체한다.

## 서버 계약

- 기존 단일 `activate`, `refund`, `reset` 요청은 호환성을 위해 유지한다.
- 새 요청은 `{ action: "activate_path", nodeId }`와 `{ action: "refund_path", nodeId }`를 사용한다.
- 서버는 클라이언트가 계산한 노드 배열을 신뢰하지 않고 현재 저장값과 대상 노드로 경로를 다시 계산한다.
- 한 트랜잭션 안에서 전체 검증, 골드 결제, 저장을 수행한다. 실패하면 선택 노드와 골드가 모두 이전 상태로 남는다.
- 반환 비용은 실제 반환 노드 수에 `50,000G`를 곱한다. 소지 골드와 은행 골드는 기존 `spendGold` 순서를 그대로 사용한다.
- 경로 활성화로 달성하는 특화 풀 업적은 최종 선택 상태를 기준으로 한 번 지급한다.

## 테스트

- 순수 경로 계산: 최단 경로의 미활성 노드만 순서대로 반환, 포인트/충돌/난이도 오류, 반환 최소 집합과 우회 연결 보존.
- 서비스: 여러 노드 원자적 활성화, 전체 반환 비용, 골드 부족 시 무변경, 기존 단일 요청 호환.
- API: 새 액션 파싱, 성공 시 저장 1회, 실패 시 저장 0회.
- UI: 먼 노드의 다중 미리보기와 일괄 활성화 요청, 활성 경로의 다중 반환 미리보기와 총비용 요청.

## 범위 제외

- 사용자가 임의의 서로 떨어진 노드를 체크박스처럼 조합하는 편집 모드.
- 최단 경로 알고리즘이나 탐사망 노드·효과·비용 자체의 밸런스 변경.
- 운영 또는 테스트 서버 배포.
