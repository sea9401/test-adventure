# 개척 노드 간선 우회 표시 설계

## 문제

개척 노드 탐사망은 모든 간선을 직선으로 그린다. 실제로 연결되지 않은 노드의 원을
직선이 통과하면, 선이 노드 아래에 가려지면서 해당 노드와 연결된 것처럼 보인다.
현재 160개 노드 전체 그래프에는 이런 교차가 27건 있으며, 대표적으로
`deep-tracking`과 `deep-boss` 사이 선이 `sector-medium-4`(장비 탐색)를 관통한다.
서버의 인접 판정은 올바른 실제 간선만 사용하므로 화면과 동작이 모순되어 보인다.

## 목표와 비목표

- 모든 표시 간선이 실제 비연결 노드의 원과 안전 여백을 침범하지 않게 한다.
- 그래프의 실제 간선, 최단 경로, 활성화 및 반환 규칙은 변경하지 않는다.
- 충돌하지 않는 기존 직선은 그대로 유지한다.
- 간선끼리 교차하는 문제나 노드 자체 배치는 이번 범위에서 바꾸지 않는다.

## 설계

`unexploredTreeGeometry.ts`가 노드 종류별 표시 반경과 간선 표시 경로를 담당한다.
직선 구간이 비연결 노드의 반경과 안전 여백을 침범하지 않으면 SVG 직선 경로를
반환한다. 침범하면 탐사망 중심에서 바깥쪽으로 제어점을 옮긴 2차 베지어 곡선을
시도하고, 모든 비연결 노드에서 충분히 떨어지는 첫 경로를 선택한다. 검사는 곡선을
짧은 선분들로 나눠 실제 표시 경로의 최소 거리를 확인한다.

탐사망 모델은 각 간선에 상태와 함께 완성된 SVG `path` 문자열을 제공한다. 화면은
노드 반경도 같은 기하 모듈에서 읽고, 기존 `<line>` 대신 `<path>`를 그린다. 따라서
모델과 화면이 서로 다른 반경을 사용해 회귀하는 일을 막는다.

## 검증

- 기존 직선 충돌 27건이 검출되는 테스트를 먼저 실패시킨다.
- 대표 문제 간선이 곡선으로 바뀌고 장비 탐색과 안전 거리를 확보하는지 확인한다.
- 충돌하지 않는 간선은 직선 경로를 유지하는지 확인한다.
- 전체 간선의 완성된 표시 경로가 모든 비연결 노드에서 안전 여백을 확보하는지
  전수 검사한다.
- 화면 정적 마크업이 `<path>` 간선을 렌더링하는지 확인한다.
