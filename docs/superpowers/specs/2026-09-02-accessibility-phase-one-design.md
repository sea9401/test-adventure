# 웹 접근성 1차 개선 설계

## 목표

로그인부터 핵심 게임 이용 흐름까지 WCAG 2.2 AA 수준의 자동 접근성 회귀 검사를
도입하고, 키보드 사용자와 스크린리더 사용자가 핵심 기능에 접근하지 못하게 만드는
문제를 우선 해결한다. 법률 준수 여부를 단정하는 문서가 아니라 제품 개발 기준과 검증
범위를 정의한다.

## 현재 상태

- 공개 화면 6종은 `@axe-core/playwright`로 WCAG 2.0/2.1/2.2 AA 규칙을 검사한다.
- 공용 버튼, 일부 탭과 모달에는 접근 가능한 이름, ARIA 상태, 포커스 트랩이 있다.
- 전역 스타일에는 여러 `prefers-reduced-motion` 대응이 있다.
- 로그인 후 게임 화면에는 동일한 axe 회귀 검사가 없다.
- 핵심 콘텐츠로 바로 이동하는 링크와 공통 본문 대상이 없다.
- 실제 키보드 이동 순서, 모달 종료 후 포커스 복귀, 상태 변화 안내는 흐름 단위로
  검증되지 않는다.

## 접근 방식

### 검토한 선택지

1. axe 검사만 전체 화면에 추가한다. 빠르지만 키보드 이동과 포커스 문맥 문제를
   놓치므로 단독 방식으로는 부족하다.
2. 공용 UI 컴포넌트부터 일괄 수정한다. 파급 범위는 넓지만 실제 사용을 막는 문제가
   무엇인지 확인하기 어렵다.
3. 핵심 흐름을 세로로 검사하고, 발견된 문제는 공용 계층부터 수정한다. 자동검사와
   사용자 흐름 검증을 함께 확보할 수 있다.

3번을 채택한다. 검사를 먼저 추가해 실패를 재현하고, 같은 원인의 문제는 개별 화면에
중복 수정하지 않고 공용 컴포넌트 또는 게임 셸에서 해결한다.

## 1차 범위

### 대상 흐름

- 로그인과 신규 캐릭터 생성
- 로그인 후 메인 화면과 전역 내비게이션
- 던전 목록 및 전투 진입 화면
- 거래소
- 알림 센터의 우편 화면

공개 정책·안내 화면은 기존 axe 검사를 유지한다. 길드, 생활, 제작, 관리자 화면 전체와
스크린리더별 실기 인증은 후속 단계로 둔다.

### 검증 항목

- axe의 `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` 위반 0건
- 페이지마다 하나의 식별 가능한 핵심 본문 랜드마크와 논리적인 제목 구조
- 첫 키보드 탐색에서 보이는 "본문으로 바로가기" 링크
- 상단 메뉴와 핵심 조작을 키보드만으로 실행 가능
- 모달을 열면 내부로 포커스가 이동하고, 닫으면 실행 요소로 복귀
- 로딩, 성공, 실패처럼 시각적으로만 전달되던 주요 상태의 적절한 라이브 안내
- 포커스 표시가 라이트·다크 모드에서 식별 가능
- 동작 줄이기 설정에서 필수 정보 손실 없이 비필수 애니메이션 억제

## 구조

### 공용 접근성 계약

게임 셸이 본문 바로가기 링크와 안정적인 본문 대상 ID를 제공한다. 각 페이지가 이미
`<main>`을 소유하므로 중첩된 `<main>`을 새로 만들지 않고, 전환 영역에서 렌더링된 현재
페이지의 `<main>`을 대상으로 연결한다. 모든 핵심 페이지는 고유한 `<h1>` 또는 고유한
문서 제목을 제공해 Next.js 라우트 알림이 의미 있는 이름을 읽도록 한다.

모달은 기존 `useModalA11y`를 우선 사용하거나 같은 계약을 따른다. 대화상자의 이름,
초기 포커스, Tab 순환, Escape 종료, 실행 요소로의 포커스 복귀를 하나의 계약으로
검증한다.

### 자동검사 구조

공개 화면과 인증 화면이 같은 WCAG 태그 및 위반 요약 도우미를 사용하도록 접근성 검사
헬퍼를 분리한다. 인증 검사는 기존 격리 PostgreSQL 계정 재설정과 로그인/캐릭터 생성
흐름을 재사용하며 직렬 실행한다. 각 검사는 화면이 안정된 뒤 axe를 실행해 네트워크
로딩 중간 상태로 인한 오탐을 피한다.

데스크톱 Chromium과 모바일 WebKit 모두에서 자동 규칙을 실행한다. 키보드 전용 세부
검사는 실제 키보드 모델이 안정적인 Chromium에서 수행하고, 모바일은 접근 가능한
이름·랜드마크·터치 대상의 자동 탐지 범위를 담당한다.

### 수정 우선순위

1. 게임 셸, 버튼, 입력, 탭, 모달 같은 공용 계층
2. 여러 핵심 흐름이 공유하는 화면 컴포넌트
3. 특정 페이지에만 존재하는 마크업과 색 대비

이 순서로 고쳐 동일 결함의 재발과 중복 수정을 줄인다. 자동 도구가 판단하지 못하는
한국어 레이블의 명확성, 시각적 읽기 순서, 게임 상태 이해 가능성은 수동 점검표에
기록한다.

## 오류 및 예외 처리

- axe 위반은 규칙 ID, 영향도, 대상 선택자를 포함해 테스트 실패 메시지로 출력한다.
- 인증·데이터 준비 실패는 접근성 위반으로 오인하지 않도록 별도 오류로 실패시킨다.
- 실시간 데이터 때문에 화면이 달라져도 비어 있는 상태와 데이터가 있는 상태 모두
  의미 있는 제목과 상태 안내를 유지한다.
- 접근성 개선 과정에서 게임 API, 보상, 전투 결과 같은 도메인 동작은 변경하지 않는다.

## 테스트와 완료 조건

- 새 접근성 테스트가 수정 전 결함을 재현하고 수정 후 통과한다.
- 기존 공개 화면 axe 검사와 인증 E2E 테스트가 계속 통과한다.
- 관련 단위/렌더링 테스트, ESLint, TypeScript 검사와 프로덕션 빌드가 통과한다.
- 핵심 흐름별 수동 체크리스트를 저장해 자동검사로 보장하지 못하는 항목을 명시한다.
- 배포는 이 설계 범위에 포함하지 않는다. 사용자가 별도로 요청한 경우에만 기존 운영
  배포 절차를 따른다.

## 후속 단계

1차 완료 후 길드, 생활, 제작, 설정, 채팅, 관리자 화면 순으로 같은 검사 계약을 확장한다.
실제 NVDA/VoiceOver 검수와 외부 전문가 점검 결과가 생기면 수동 체크리스트와 회귀
테스트로 환류한다.
