# 웹 접근성 3차 개선 설계

## 목표

1·2차의 공개 화면, 초기 사용자 화면, 채팅 접근성 검사를 권한과 데이터가 필요한 상태로
확장한다. 데이터가 채워진 인벤토리·생활 작업장·거래소, 길드 가입 후 관리 화면, 운영자
도구의 대표 탭에서 WCAG 2.2 AA 자동 탐지 위반과 구조 회귀를 막는다.

이 단계는 제품의 자동 회귀 범위를 넓히는 작업이다. 실제 NVDA·VoiceOver 실기 검수와
법률 준수 인증을 대신하지 않는다.

## 접근 방식

### 검토한 선택지

1. 관리자와 길드의 모든 하위 상태를 전수 검사한다. 표면적 범위는 넓지만 권한·시즌·길드
   시설·데이터 조합이 폭발해 테스트가 느리고 불안정해진다.
2. 각 컴포넌트의 정적 렌더링만 검사한다. 빠르지만 동적 import, 포털, API 로딩과 실제
   라우트 조합에서 발생하는 문제를 놓친다.
3. 격리 계정을 결정적으로 시드하고 카테고리별 대표 흐름을 브라우저에서 검사한다. 실제
   조합을 다루면서 데이터와 실행 시간을 통제할 수 있다.

3번을 채택한다. 테스트 서버에만 최고 관리자 이메일과 스테이징 플래그를 주입하고, 이미
격리 DB로 제한된 인증 계정에 공식 개발용 지급 API를 호출한다. 운영 환경 설정과 운영
데이터에는 어떤 변경도 가하지 않는다.

## 3차 범위

### 데이터가 채워진 사용자 화면

- 신규 캐릭터 생성 후 레벨, 골드, 소나무 원목과 철광석을 지급한다.
- 인벤토리에서 실제 보유 재료와 수량이 보이는 상태를 검사한다.
- 생활 조합 작업장에서 실제 가공 가능 수량과 활성 조작이 보이는 상태를 검사한다.
- 거래소의 판매 탭에서 판매 가능한 재료가 보이는 상태를 검사한다.

상태 주입은 Node 테스트 헬퍼가 고정 E2E 계정의 `character.v2`를 직접 갱신한다. 기존
loopback `adventure_e2e` 검증과 저장 행 존재 확인을 통과해야 하며, 운영에서 숨겨야 하는
개발 지급 API는 Playwright 서버에도 노출하지 않는다.

### 가입 후 길드 화면

- 같은 시드 계정을 레벨 30과 창단 비용 이상으로 준비하고 UI를 통해 길드를 창단한다.
- 길드 정보, 길드원, 토벌전, 시설, 관리 탭의 초기 가입 후 상태를 검사한다.
- 각 하위 화면의 로딩이 끝난 뒤 이름 있는 본문과 자동 접근성 규칙을 확인한다.

길드 시설 업그레이드나 토벌 공격처럼 게임 상태를 실제 소비하는 동작은 실행하지 않는다.
권한 있는 버튼과 잠긴·빈 상태가 이해 가능한지만 검사한다.

### 관리자 대표 화면

운영 업무 카테고리별로 다음 탭을 검사한다.

- 운영 홈: 요약 지표와 위험 신호
- 유저 관리: 검색과 대상 작업 진입점
- 공지·우편: 콘텐츠 작성과 발송 입력
- 신고 관리: 신고 목록과 처리 상태
- 전체 통계: 분석 카드와 표
- 관리자 기록: 필터와 감사 목록

관리자 검사는 읽기와 빈 상태 렌더링까지만 수행한다. 지급, 제재, 우편 발송, 설정 저장 등
외부 효과가 있는 관리자 동작은 실행하지 않는다.

## 구조와 데이터 흐름

### 인증 테스트 지원

`playwright.config.ts`의 테스트 서버 환경에만 격리 계정 이메일을 `ADMIN_EMAILS` 기본값으로
주입한다. 명시적으로 제공된 환경 변수는 덮어쓰지 않는다.
프로덕션 빌드 결과물은 동일하지만, 실행 중 권한은 Playwright가 시작한 로컬 서버에만
적용된다.

인증 접근성 스위트는 캐릭터 생성 헬퍼를 재사용한다. 별도 시드 헬퍼는 격리 DB 주소를
검증한 뒤 저장 행의 레벨·골드·재료만 갱신하고, 대상 행이 없으면 접근성 실패로 오인하지
않도록 준비 오류로 즉시 실패한다.

### 자동 검사

모든 화면은 기존 `a11yViolationSummary(page)`와 동일한 WCAG 태그를 사용한다. 화면 제목,
주요 탭 또는 시드된 아이템처럼 데이터 준비를 증명하는 요소를 기다린 뒤 network idle을
확인한다. 여러 하위 화면은 `{ path 또는 tab, violations }`로 위반을 모아 한 번의 실행에서
전체 진단 정보를 남긴다.

관리자 셸은 하나의 `<h1>`과 하나의 `<main>`을 유지하고, 현재 탭 제목은 `<h2>`로 식별한다.
게임 화면은 기존 페이지별 `<h1>`·`<main>` 계약을 유지한다.

## 수정 원칙

1. 관리자 셸, 탭, 입력, 카드, 표, 상태 배지 같은 공용 소유자
2. 길드·거래소·생활 화면이 공유하는 기능 컴포넌트
3. 한 상태에만 나타나는 마크업과 색상

실패는 규칙 ID, 대상 HTML과 실패 요약으로 원인을 확인한 후 위 순서로 최소 수정한다.
axe 규칙을 끄거나 요소를 검사에서 제외하지 않는다. 작은 텍스트는 데스크톱 게임 화면의
90% 축소 이후 실제 크기와 대비를 기준으로 판단하며, 버튼 터치 영역도 축소 후 24px을
충족하도록 한다.

## 오류와 예외 처리

- 시드 API가 2xx와 `{ ok: true }`를 반환하지 않으면 응답 본문을 포함해 준비 오류로
  실패시킨다.
- 동적 관리자 탭은 탭 제목과 핵심 로딩 문구의 종료를 기다려 중간 상태 오탐을 막는다.
- 관리자 API 일부가 빈 데이터를 반환해도 제목, 설명, 필터와 빈 상태를 읽을 수 있어야 한다.
- 로컬 WebKit 의존 라이브러리가 없으면 브라우저 시작 실패를 환경 제한으로 기록하고,
  공식 Playwright 컨테이너가 있는 CI 검증 대상을 유지한다.

## 테스트와 완료 조건

- 데이터가 채워진 인벤토리·생활 작업장·거래소 판매 상태에서 axe 위반이 0건이다.
- 가입 후 길드의 정보·길드원·토벌전·시설·관리 탭에서 axe 위반이 0건이다.
- 관리자 대표 6개 탭에서 하나의 셸 제목, 하나의 본문과 axe 위반 0건을 확인한다.
- 시드와 관리자 권한은 격리된 Playwright 서버·DB 밖에서 활성화되지 않는다.
- 1·2차 접근성 흐름, 전체 단위 테스트, ESLint, TypeScript와 프로덕션 빌드가 통과한다.
- 3차 화면의 키보드 읽기 순서, 200% 확대, NVDA·VoiceOver 항목을 수동 점검표에 추가한다.
- 배포, 푸시, PR 생성은 이 설계 범위에 포함하지 않는다.

## 제외와 후속 작업

모든 길드 시설 레벨, 실제 토벌 공격, 관리자 변경 작업, 모든 시장 주문 조합은 전수 검사하지
않는다. 실제 보조기술 검수나 운영자 사용자 테스트에서 발견된 상태는 재현 가능한 최소
fixture와 회귀 테스트로 후속 반영한다.
