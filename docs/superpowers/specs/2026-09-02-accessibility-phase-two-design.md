# 웹 접근성 2차 개선 설계

## 목표

1차에서 마련한 공용 axe 검사와 키보드 접근 계약을 캐릭터 성장, 생활, 커뮤니티,
환경 설정 영역으로 확장한다. 대표 화면 조합에서 WCAG 2.2 AA 자동 탐지 위반을 막고,
상시 노출되는 채팅을 키보드로 열고 닫은 뒤 원래 문맥으로 돌아갈 수 있게 보장한다.

이 단계 역시 법률 준수 인증이 아니라 개발 중 회귀를 막기 위한 제품 검증 범위다.

## 현재 기반

- 공개 화면과 1차 인증 화면은 같은 `@axe-core/playwright` 도우미와 WCAG 태그를
  사용한다.
- 게임 셸은 첫 Tab으로 노출되는 본문 바로가기 링크와 안정적인 본문 포커스 대상을
  제공한다.
- 공용 모달 포커스 트랩은 초기 포커스, Tab 순환, 종료 후 포커스 복귀 단위 테스트가
  있다.
- 캐릭터·생활·길드·환경 설정 화면과 실제 채팅 대화상자는 인증 axe 흐름에 포함되지
  않았다.

## 접근 방식

### 검토한 선택지

1. 모든 인증 라우트를 한 번에 검사한다. 표면적 범위는 넓지만 테스트 데이터와 화면
   상태가 지나치게 다양해 실패 원인을 분리하기 어렵다.
2. 공용 UI 컴포넌트를 먼저 일괄 수정한다. 수정 파급은 크지만 실제 화면 조합에서만
   생기는 제목, 대비, 상태 전달 문제를 놓칠 수 있다.
3. 대표 사용자 흐름을 세로로 검사하고, 반복 원인은 공용 컴포넌트에서 고친다. 실제
   사용 문맥과 수정 범위를 함께 통제할 수 있다.

3번을 채택한다. 새 검사가 현재 결함을 먼저 드러내게 하고, axe 규칙을 끄거나 특정
요소를 제외하지 않은 채 가장 좁은 공용 소유자에서 해결한다.

## 2차 범위

### 대상 화면

- 인벤토리와 스킬
- 마을 홈, 모험가 농장, 생활 조합 작업장
- 길드 미가입 상태의 창단·가입 탐색 화면
- 환경 설정
- 메인 화면의 플로팅 채팅 패널

각 화면은 신규 캐릭터의 빈 상태 또는 초기 상태를 기준으로 검사한다. 데이터가 필요한
조작을 억지로 만들어 내기보다 사용자가 처음 마주치는 실제 상태를 회귀 기준으로 삼는다.

관리자 화면, 길드 가입 후 관리 화면, 모든 제작 결과 조합, 실제 NVDA·VoiceOver 실기
인증은 이번 자동화 범위에서 제외한다. 보조기술 실기 검수 항목은 수동 점검표에 추가한다.

## 접근성 계약

### 화면 구조와 자동 검사

각 대상 라우트는 하나의 페이지 소유 `<main>`과 화면 이름을 나타내는 하나의 `<h1>`을
제공한다. 화면의 로딩이 끝나고 초기 데이터가 안정된 뒤 1차와 동일한 `wcag2a`,
`wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` 태그로 axe를 실행한다.

여러 라우트의 위반을 한 번에 모아 경로, 규칙 ID, 영향도, 도움말, 실패 요소 HTML과
실패 요약을 출력한다. 한 화면의 실패 때문에 나머지 화면의 진단 정보가 사라지지 않게
한다.

### 채팅 키보드 흐름

플로팅 채팅 버튼은 상태에 맞는 접근 가능한 이름과 `aria-expanded`를 유지한다. 버튼을
키보드로 실행하면 이름 있는 채팅 대화상자가 노출되고, 대화상자 내부의 닫기 버튼으로
포커스를 옮겨 조작할 수 있어야 한다. 닫은 뒤에는 채팅을 열었던 플로팅 버튼으로 포커스가
복귀한다.

모바일 채팅은 배경 입력을 막는 모달이고 데스크톱 채팅은 게임과 함께 사용할 수 있는
비모달 도킹 패널이라는 기존 동작을 유지한다. 따라서 데스크톱에 불필요한 포커스 트랩을
강제하지 않고, 열린 패널 전체의 axe 검사와 명시적인 포커스 복귀를 검증한다.

### 수정 원칙

1. `SubViewHeader`, 카드, 탭, 입력, 대화상자 같은 공용 계층
2. 여러 대상 화면이 공유하는 기능 컴포넌트
3. 한 화면에만 존재하는 마크업과 색상

수정은 이 순서로 적용한다. 아이콘 장식 여부, 접근 가능한 이름, 제목 수준, ARIA 상태,
텍스트 대비를 실제 실패 규칙에 맞춰 고친다. 배경 이미지 위 카드와 패널은 기존 불투명
표면 계약을 유지한다.

## 오류와 상태 처리

- 인증·데이터 초기화 실패는 접근성 위반 목록과 분리해 실패시킨다.
- 로딩 상태가 남아 있는 동안 axe를 실행하지 않도록 페이지 제목과 핵심 콘텐츠를 먼저
  기다린다.
- 빈 인벤토리, 미가입 길드, 초기 농장처럼 정상적인 빈 상태도 이름과 설명만으로 현재
  상황을 이해할 수 있어야 한다.
- 접근성 수정 중 캐릭터 능력치, 아이템, 제작 결과, 길드 권한, 채팅 전송 API의 동작은
  바꾸지 않는다.

## 테스트와 완료 조건

- 2차 대상 라우트 모두에서 자동 탐지 접근성 위반이 0건이다.
- 각 라우트에 정확히 하나의 이름 있는 1단계 제목과 페이지 본문이 있다.
- 채팅을 키보드로 열고 닫을 수 있고, 닫은 뒤 실행 버튼으로 포커스가 돌아온다.
- 1차 공개·인증 접근성 테스트와 기존 단위 테스트가 계속 통과한다.
- ESLint, TypeScript 검사와 프로덕션 빌드가 통과한다.
- 실제 NVDA·VoiceOver, 확대와 리플로우, 읽기 순서 검수는 수동 점검표에 기록한다.
- 배포, 푸시, PR 생성은 이 설계 범위에 포함하지 않는다.

## 후속 단계

3차에서는 관리자 화면, 길드 가입 후 관리 기능, 데이터가 채워진 제작·거래 상태처럼
권한과 데이터 조합이 필요한 표면을 다룬다. 실제 보조기술 검수에서 발견된 문제는 가장
작은 재현 흐름을 자동 회귀 테스트로 환류한다.
