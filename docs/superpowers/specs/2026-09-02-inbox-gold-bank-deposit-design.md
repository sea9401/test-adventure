# 우편 골드 은행 자동 입금 설계

## 문제

우편 수령 라우트는 판매 대금만 은행 골드에 적립하고, 입찰·구매주문 환불과 길드 의뢰·운영자 우편의 골드는 보유 골드에 적립한다. 큰 보상을 수령한 직후 사냥하면 사용자가 의도하지 않은 거액의 보유 골드를 들고 전투에 진입할 수 있다.

## 결정

우편으로 수령하는 모든 골드는 종류와 관계없이 `character.v2.bankedGold`에 직접 적립한다. 수령과 입금은 기존 우편 수령 데이터베이스 트랜잭션 안에서 한 번에 처리하므로 중간 실패 상태가 생기지 않는다.

## 구현 경계

- `sale_proceeds`, `bid_refund`, `buy_order_refund`, `guild_quest_reward`, `admin_gift`의 양수 골드를 모두 은행 골드 합계로 모은다.
- 기존 보유 골드는 변경하지 않는다.
- 응답은 적립액을 `bankedGoldAdded`, 최종 은행 잔액을 `newBankedGold`로 반환한다. 기존 클라이언트는 이 필드를 이미 반영하고 은행 골드로 안내한다.
- 아이템, 코인, 회복약 등 골드 외 우편 보상과 우편 수령의 원자성·중복 방지 동작은 변경하지 않는다.
- 배포하지 않는다.

## 검증

- 다섯 종류의 골드 우편을 함께 수령했을 때 보유 골드는 그대로이고 전액이 은행 잔액에 합산되는 통합 테스트를 먼저 실패시킨다.
- 집중 테스트, TypeScript 검사, ESLint, 프로덕션 빌드를 실행한다.
