# 거래소 내 입찰 조회 설계

## 배경과 목표

현재 공개 입찰은 입찰 즉시 골드를 에스크로에서 차감하지만, 거래소에는 사용자가 참여한 입찰을 모아 보는 화면이 없다. 공개 목록 응답은 현재 최고 입찰자 여부를 알고 있어도 UI에서 표시하지 않으며, 경매·즉시구매 모드와 품목 필터 때문에 사용자가 입찰하거나 등록한 매물을 다시 찾기 어렵다. 그 결과 매물과 골드가 함께 사라진 것으로 오해할 수 있다.

이번 변경의 목표는 다음과 같다.

- `내 거래`에서 진행 중인 입찰과 최근 종료 결과를 한곳에서 확인한다.
- 일반 거래소 목록에서 내 매물과 내가 참여한 입찰을 즉시 구분한다.
- 에스크로, 상위 입찰, 정산, 낙찰, 반환 확인 위치를 상태별로 설명한다.
- 다른 사용자의 신원이나 입찰자 ID는 추가로 노출하지 않는다.

## 사용자 화면

### 내 거래의 내 입찰 탭

`내 거래`의 하위 탭을 `판매 중`, `내 입찰`, `구매 주문`, `거래 내역` 네 개로 구성한다. `내 입찰`은 사용자가 한 번 이상 입찰한 매물을 최근 50개까지 보여준다.

각 행에는 다음 정보를 표시한다.

- 품목명과 수량
- 내 최고 입찰가
- 현재 최고 입찰가와 즉시구매가
- 마지막 입찰 시각
- 현재 상태와 자산 안내

상태 문구는 서버 원본을 추측해서 확정하지 않고 다음처럼 보수적으로 표현한다.

| 조건 | 표시 | 안내 |
| --- | --- | --- |
| 입찰 진행 중이며 내가 최고 입찰자 | `최고 입찰 중` | `입찰금 예치 중` |
| 입찰 진행 중이며 다른 사용자가 최고 입찰자 | `상위 입찰 발생` | `우편함에서 입찰금 반환 확인` |
| 입찰 시간이 끝났으나 매물이 아직 활성 | `정산 대기` | `최대 5분 내 정산` |
| 판매 완료이며 내가 구매자 | `낙찰 완료` | `인벤토리에서 물품 확인` |
| 판매 완료이며 다른 사용자가 구매자 | `입찰 종료` | `우편함에서 입찰금 반환 확인` |
| 취소 또는 만료 | `취소·만료` | `우편함에서 반환 내역 확인` |

진행 중인 행은 종료된 최근 내역보다 위에 두고, 각 그룹 안에서는 마지막 입찰 시각이 최신인 순서로 정렬한다. 입찰 가능한 활성 매물에서는 기존 공개 입찰 대화상자를 열 수 있다. 종료된 행은 읽기 전용으로 유지한다.

### 일반 거래소 목록

기존 가격·품질 정렬은 바꾸지 않는다. 매물 카드에 다음 배지를 표시한다.

- 판매자가 본인이면 `내 매물`
- 본인이 현재 최고 입찰자이면 `최고 입찰 중`
- 과거에 입찰했지만 현재 최고 입찰자가 아니면 `내 입찰`

`내 항목만 보기` 필터는 `내 매물`, `최고 입찰 중`, `내 입찰` 중 하나에 해당하는 행만 남긴다. 필터는 현재 선택한 즉시구매/경매 모드와 품목 분류 안에서 동작하며, 숨겨진 다른 모드나 품목이 있다는 점을 필터 문구로 오해시키지 않는다.

## 서버 API와 데이터 흐름

### 내 입찰 API

`GET /api/v2/marketplace/my-bids`를 추가한다.

1. 인증된 사용자 ID로 `marketplace_bids_v2`를 집계한다.
2. 매물별 `MAX(amount)`를 내 최고 입찰가로, `MAX(created_at)`을 마지막 입찰 시각으로 구한다.
3. `marketplace_listings_v2`와 조인해 최근 50개를 반환한다.
4. 현재 사용자와의 비교 결과만 `isHighestBidder`, `isBuyer`로 반환한다.
5. 판매자 ID, 구매자 ID, 최고 입찰자 ID와 다른 입찰자의 정보는 응답에서 제거한다.

응답 행은 품목 표시용 매물 필드와 함께 다음 필드를 가진다.

- `myHighestBid`
- `lastBidAt`
- `status`
- `isHighestBidder`
- `isBuyer`

별도 테이블이나 마이그레이션은 추가하지 않는다. 원본 매물·입찰 기록의 기존 보존 기간 안에서 최근 내역을 제공한다.

### 공개 목록의 참여 표시

기존 `GET /api/v2/marketplace/browse`는 반환 대상 매물 ID에 대해 인증 사용자의 입찰 존재 여부를 한 번의 집합 조회로 확인한다. 각 공개 행에 `hasMyBid` 불리언을 추가한다. 다른 사용자의 입찰 여부나 신원은 반환하지 않는다.

입찰 성공 뒤에는 공개 목록과, 이미 로드된 경우 내 입찰 목록을 함께 새로고침한다. `내 거래` 진입 시 판매 중 매물·거래 내역·내 입찰을 병렬로 불러온다. 개별 요청 실패는 기존 오류 영역에 표시하며 다른 성공한 목록을 삭제하지 않는다.

## 경계 조건

- 같은 매물에 여러 번 입찰해도 내 입찰 목록에는 한 행만 표시한다.
- 내 최고 입찰가는 해당 사용자의 입찰 중 가장 큰 금액으로 계산한다.
- 입찰 직후에는 에스크로 차감 결과와 새 목록 상태를 함께 갱신한다.
- 정산 크론이 최대 5분 주기이므로 입찰 종료 직후 활성 행은 `정산 대기`로 표시한다.
- 반환 우편의 수령 여부를 입찰 테이블만으로 단정하지 않는다. 종료·상위 입찰 상태에서는 `반환 완료`가 아니라 `우편함에서 확인`이라고 안내한다.
- 일반 목록에서 본인 매물은 기존처럼 구매·입찰할 수 없으며 관리 동선만 제공한다.
- 원본 기록이 보존 기간 이후 정리된 내역은 목록에 나타나지 않는다.

## 테스트

### 서버

- 동일 사용자의 복수 입찰이 매물별 한 행으로 집계되는지 검증한다.
- 내 최고 입찰가와 마지막 입찰 시각이 정확한지 검증한다.
- 진행 중·판매·취소·만료 매물이 모두 반환되는지 검증한다.
- 응답에 판매자·구매자·최고 입찰자 ID가 없는지 검증한다.
- 공개 목록의 `hasMyBid`가 현재 사용자 입찰에만 반응하는지 검증한다.

### UI

- `내 거래`에 `내 입찰` 탭과 건수 배지가 표시되는지 검증한다.
- 여섯 가지 상태가 올바른 문구와 자산 안내로 표시되는지 검증한다.
- 진행 중 항목이 최근 종료 항목보다 앞서는지 검증한다.
- 일반 목록의 `내 매물`, `최고 입찰 중`, `내 입찰` 배지 우선순위를 검증한다.
- `내 항목만 보기`가 기존 모드·품목·정렬을 유지하면서 대상 행만 거르는지 검증한다.
- 입찰 성공 뒤 공개 목록과 내 입찰 목록 갱신을 검증한다.

## 범위 제외

- 경매 규칙, 입찰 최소 증가율, 정산 주기 변경
- 에스크로·반환·낙찰 지급 방식 변경
- 우편 자동 수령
- 과거 보존 기간 연장 또는 신규 감사 테이블
- 거래소 전면 재설계
