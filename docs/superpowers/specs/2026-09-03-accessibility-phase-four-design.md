# 웹 접근성 4차 개선 설계

## 목표

1~3차에서 확보한 공개·인증·상태·권한 화면의 axe 검사를 실제 사용 조건과 상호작용으로
확장한다. 대표적인 복잡 화면을 다크 모드, CSS 320px 리플로우, 200% 확대에서 검증하고,
입력 오류·처리 결과·확인 대화상자가 키보드와 보조기술에 전달되는 계약을 자동화한다.

이 단계 역시 자동 회귀 방지 작업이다. NVDA·VoiceOver 실기 검수나 법률 준수 인증을
대신하지 않는다.

## 접근 방식

### 검토한 선택지

1. 3차의 모든 화면을 모든 브라우저·색상·크기 조합으로 전수 검사한다. 조합 수와 실행
   시간이 급증하고 동일한 레이아웃 결함을 반복 검출한다.
2. 대표 복잡 상태를 깊게 검사한다. 데이터가 채워진 거래소 판매, 생활 가공, 길드 시설을
   리플로우와 상호작용 경계로 삼으면 작은 화면의 밀집 입력, 동적 결과, 포털 대화상자를
   한정된 실행 시간 안에 함께 검증할 수 있다.
3. 수동 점검표만 확장한다. 실제 스크린리더 품질에는 유용하지만 반복 가능한 회귀 게이트가
   생기지 않는다.

2번을 채택한다. 기존 인증 E2E의 격리 계정과 3차 시드를 재사용하고, 변경이 필요한 경우
공용 컴포넌트에서 최소한으로 고친다.

## 4차 범위

### 리플로우·색상 모드

- 거래소 재료 판매 폼과 길드 시설 기부 폼을 320 CSS px 다크 모드에서 연다.
- 문서의 `scrollWidth`가 `clientWidth`를 넘지 않는지 확인하고 같은 상태에서 axe를 실행한다.
- 데스크톱 Chromium에서 문서에 200% CSS 확대를 적용해 동일한 유효 폭을 만들고, 핵심
  입력과 버튼이 사라지거나 문서 전체 가로 넘침을 만들지 않는지 확인한다.
- 가로로 스크롤하도록 설계된 탭·표 내부는 허용하되 문서 전체의 가로 넘침은 허용하지
  않는다.

CSS 확대는 브라우저 배율을 완전히 대체하지 않지만 레이아웃 계산에 확대를 반영해 자동
회귀를 검출한다. 실제 브라우저 200% 확대는 수동 점검표에 계속 남긴다.

### 동적 상태 안내

- 거래소 판매 폼에서 가격 없이 등록을 시도해 서버 쓰기 전에 발생하는 검증 오류를 만든다.
- 오류 컨테이너는 `role="alert"`로 즉시 안내하고, 오류가 어떤 품목의 어느 입력을 고쳐야
  하는지 이해할 수 있어야 한다.
- 생활 작업장에서 1회 가공을 실제 실행한다. 격리 DB의 시드 재료만 소비하며, 결과 영역은
  polite live region으로 완성 품목과 수량을 안내한다.
- 성공·오류 안내가 단순 색상이나 순간적인 토스트에만 의존하지 않는지 역할과 화면 문구를
  함께 검증한다.

### 확인 대화상자와 포커스

- 생활 작업장의 최대 가공 버튼으로 확인 대화상자를 열고 제목·설명·취소·확인 버튼을
  검사한다.
- 대화상자를 취소하면 실행 버튼으로 포커스가 돌아와야 한다.
- 길드 시설에서는 재료 기부 폼을 열어 재료별 범위 입력 이름, 증가·감소 버튼, 닫기 동작과
  문서 리플로우를 검사한다. 실제 기부나 업그레이드는 실행하지 않는다.
- 관리자 변경·발송·제재는 3차와 동일하게 실행하지 않는다. 공용 `GameDialogHost`의 단위
  회귀 검사를 통해 위험 작업 확인창의 포커스 계약을 보강한다.

## 구조와 데이터 흐름

`e2e/support/accessibility.ts`에 문서 리플로우 치수를 반환하고 넘침이 없음을 단언하는
작은 헬퍼를 둔다. 인증 접근성 스위트는 기존 캐릭터 생성과 3차 시드를 사용한 뒤 필요한
상태까지 UI로 이동한다. 색상 모드와 뷰포트는 테스트별로 설정하며 테스트 종료 후 새
페이지/컨텍스트와 계정 초기화로 격리한다.

제품 수정은 검사 결과가 가리키는 소유자에만 적용한다.

- 거래소 공용 가격 입력은 호출자가 품목을 포함한 접근 가능한 이름을 줄 수 있게 한다.
- 거래소 오류와 성공 안내는 각각 alert/status 의미를 갖는다.
- 생활 작업장 결과 영역은 기존 고정 높이와 불투명 표면을 유지하면서 상태 역할을 명시한다.
- 대화상자 포커스 복귀가 공용 훅에서 제공되지 않으면 호출 버튼 참조를 보존하는 가장 좁은
  소유자에서 복구한다.
- 길드 기부 카드의 밀집 행은 320px에서 세로 배치 또는 줄바꿈으로 바꾸되 불투명 표면과
  기존 게임 동작을 유지한다.

## 테스트 전략

1. 컴포넌트 단위에서 오류 역할, 품목별 가격 입력 이름, 상태 역할, 확인창 포커스 복귀를
   먼저 실패하는 테스트로 작성한다.
2. 인증 Chromium E2E에서 생활 가공 결과와 최대 수량 확인창을 실행한다.
3. 인증 Chromium의 320px 다크 모드와 200% CSS 확대에서 대표 거래·길드 상태의 axe 및
   문서 가로 넘침을 검사한다.
4. WebKit 프로젝트는 기존 CI의 공식 Playwright 이미지에서 동일 인증 스위트를 계속
   실행한다. 로컬 호스트 라이브러리 부족은 제품 실패로 위장하지 않고 문서에 명시한다.
5. 전체 Vitest, ESLint, TypeScript, 프로덕션 빌드와 기존 공개·인증 접근성 스위트를
   재검증한다.

## 완료 조건

- 거래소 판매 오류가 `role="alert"`로 안내되고 가격 입력 이름이 품목을 구분한다.
- 생활 가공 결과가 live status로 전달되며 최대 수량 확인창 취소 후 포커스가 복귀한다.
- 길드 시설 기부 폼의 모든 조작 이름이 구분되고 닫은 뒤 실행 버튼으로 포커스가 복귀한다.
- 대표 거래·길드 화면이 320px 다크 모드와 200% CSS 확대에서 문서 가로 넘침과 axe 위반
  없이 동작한다.
- CI는 Chromium과 WebKit 인증 접근성 프로젝트를 공식 Playwright 이미지에서 실행한다.
- 실제 NVDA·VoiceOver 및 브라우저 200% 확대 항목이 4차 수동 점검표에 기록된다.
- 배포, 푸시, PR 생성은 이 설계 범위에 포함하지 않는다.

## 제외와 후속 작업

모든 관리자 쓰기, 실제 길드 기부·시설 업그레이드, 거래소 매물 등록·입찰·구매는 자동으로
실행하지 않는다. 모든 화면과 모든 보조기술 조합의 전수 검사는 하지 않으며, 실기 검수에서
발견된 문제는 재현 가능한 최소 상태를 추가해 후속 단계에서 다룬다.
