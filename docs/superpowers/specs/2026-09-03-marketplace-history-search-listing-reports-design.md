# 거래소 최근 거래 검색·판매 중 매물 신고 설계

## 목표

- 최근 거래 탭에서 품목명으로 현재 제공되는 최근 100건을 검색한다.
- 다른 사용자의 판매 중 매물을 거래소 전용 사유로 신고한다.
- 완료 거래 신고와 판매 중 매물 신고를 운영 화면과 저장 데이터에서 구분한다.

## 설계

최근 거래 검색은 이미 클라이언트에 내려온 목록에 대해 공백을 제거한 검색어를 품목명과 대소문자 구분 없이 비교한다. 검색 결과에 기존 페이지네이션을 적용하며 검색어가 비면 원래 목록을 그대로 사용한다. 서버 조회 범위와 공개 정보는 바꾸지 않는다.

판매 중 매물 신고는 기존 `/api/safety/reports` 파이프라인을 재사용하되 `marketplace_listing` 소스 유형을 추가한다. 클라이언트는 매물 ID만 보내며, 서버가 DB에서 매물을 다시 조회해 다음을 검증한다.

- 매물이 실제로 `active` 상태인지 확인한다.
- 판매자 본인의 신고는 거부한다.
- 신고 대상은 판매자로 고정한다.
- 품목, 수량, 총 가격, 개당 가격, 등록·입찰 마감 시각, 입찰 상태를 접수 시점 스냅샷으로 보존한다.

완료 거래와 판매 중 매물은 동일한 거래소 전용 신고 사유를 쓴다. 운영 화면은 각각 `거래소 체결`, `거래소 매물`로 표시하고 관련 계정을 노출하며, 원본 콘텐츠 삭제 동작은 제공하지 않는다.

## 오류 처리와 보안

- 종료되거나 없는 매물은 `404 not found`로 처리한다.
- 자기 매물 신고는 기존 자기 신고 차단 규칙으로 `400` 처리한다.
- 중복 신고, 시간당 제한, 상세 설명 길이 제한은 기존 정책을 그대로 적용한다.
- 판매자 식별 정보와 스냅샷은 신고 API 서버와 운영 화면에서만 취급한다.

## 검증

- 검색 필터 단위 테스트
- 판매 중 매물 스냅샷·상태·자기 신고 단위 테스트
- 신고 입력 계약과 API 라우트 테스트
- 거래소 신고 버튼·최근 거래 화면 렌더링 테스트
- 운영 신고 화면 렌더링 테스트
- 마이그레이션 검사, 타입 검사, 관련 테스트, 린트
