# 거래소 서버 시각 보정 설계

## 문제

경매의 `bidEndsAt`은 서버 시각으로 생성되고 입찰 종료도 서버에서 판정하지만, 거래소 화면은 이용자 기기의 `Date.now()`로 남은 시간과 종료 상태를 판정한다. 기기 시계가 서버보다 빠르면 실제 마감 전부터 `정산 중`으로 표시되고 입찰 버튼이 사라진다.

## 설계

`GET /api/v2/marketplace/browse` 응답에 응답 생성 시점의 `serverNow`(Unix 밀리초)를 추가한다. 클라이언트는 응답을 받은 로컬 시각과 `serverNow`의 차이를 보관하고, 거래소의 모든 경매 카운트다운·종료 판정에 `Date.now() + offset`을 사용한다. 이후 입찰로 연장된 `bidEndsAt`도 같은 보정 시계와 비교하므로 별도 변환이 필요 없다.

서버 시각이 없거나 유효하지 않은 개발용 미리보기 응답은 현재처럼 로컬 시각을 사용한다. 6시간 경매, 종료 임박 10분 연장, 종료 후 최대 5분 정산 정책은 바꾸지 않는다.

## 검증

- 조회 API가 유효한 `serverNow`를 반환하는지 확인한다.
- 기기 시계가 서버보다 2분 빠르더라도 서버 기준 마감 전에는 남은 시간이 표시되고 입찰 버튼이 유지되는 컴포넌트 회귀 테스트를 추가한다.
- 관련 거래소 테스트와 TypeScript 검사를 실행한다.
