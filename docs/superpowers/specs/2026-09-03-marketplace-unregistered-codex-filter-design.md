# 거래소 도감 미등록 장비 필터 설계

## 배경과 목표

거래소에서 아직 장비 도감에 등록하지 않은 아이템의 매물만 골라볼 수 있게 한다. 사용자는 별도 목록을 대조하지 않고도 도감 수집에 필요한 장비를 찾을 수 있어야 한다.

## 적용 범위

- 거래소의 매물 탐색 화면에만 적용한다.
- 무기, 방어구, 장갑, 신발, 반지, 목걸이의 여섯 장비 탭에서만 제공한다.
- 재료와 소모품 탭에는 필터를 표시하거나 적용하지 않는다.
- 최근 거래, 판매 등록, 내 거래 등 다른 거래소 화면은 변경하지 않는다.
- 도감 등록 처리 자체, 서버 조회 API, 데이터베이스 스키마와 정렬 방식은 변경하지 않는다.

## 사용자 경험

장비 탭의 기존 상세 필터 패널에 `도감 상태` 항목을 추가하고 `도감 미등록만 보기` 토글 버튼을 둔다. 활성화하면 버튼 문구를 `✓ 도감 미등록만 보는 중`으로 바꾸고 `aria-pressed`로 상태를 함께 전달한다.

도감 데이터가 아직 준비되지 않았을 때는 버튼을 비활성화하고 `도감 불러오는 중`이라고 표시한다. 로딩 중인 상태를 미등록으로 간주해 매물을 잘못 숨기거나 노출하지 않는다.

필터가 활성화되면 다음 기존 요소에도 반영한다.

- 필터 버튼의 활성 필터 개수에 1을 더한다.
- 결과 요약에 `도감 미등록` 칩을 표시한다.
- `필터 초기화`가 이 필터도 함께 해제한다.
- 페이지네이션 키에 상태를 포함해 필터 변경 시 첫 페이지로 돌아간다.
- 필터 적용 결과가 비었으면 `도감 미등록 매물이 없어요.`를 표시한다.

재료나 소모품 탭으로 이동하면 도감 필터 UI, 칩, 활성 필터 개수 및 실제 필터링에서는 제외한다. 다만 기존 장비 전용 필터와 같은 방식으로 선택 상태 자체는 보존해, 장비 탭으로 돌아왔을 때 다시 적용한다.

## 데이터 흐름과 필터 규칙

`V2MarketplaceView`는 기존 `useEquipmentCodexContext()`에서 다음 값을 사용한다.

- `registeredIds`: 등록된 `V2EquipmentId` 집합
- `loaded`: 장비 도감 데이터 준비 여부

컨텍스트가 없는 렌더링 환경도 `loaded=false`와 같은 상태로 취급한다. 이 경우 토글은 비활성화하고 매물 목록에는 필터를 적용하지 않는다.

화면에는 `unregisteredCodexOnly` 불리언 상태를 둔다. 장비 매물 필터 파이프라인에서 다음 규칙을 기존 탭, 판매 방식, 즐겨찾기, 티어·제작 조건 및 검색 조건과 AND로 결합한다.

1. 장비 탭이 아니면 항상 통과시킨다.
2. 토글이 꺼져 있으면 항상 통과시킨다.
3. 도감 데이터가 준비되지 않았으면 항상 통과시킨다.
4. 토글이 켜져 있고 데이터가 준비됐으면 `registeredIds`에 `itemId`가 없는 매물만 통과시킨다.

판정 로직은 `marketplaceBrowseFilters.ts`의 순수 함수로 분리한다. 장비 카탈로그에 없는 식별자는 도감 대상 장비로 취급하지 않아 통과시키지 않는다. 정상 장비 탭 매물은 기존 탭 판정에서 이미 카탈로그와 슬롯이 확인되지만, 순수 함수에서도 이 경계를 명시해 잘못된 데이터가 미등록 장비로 노출되지 않게 한다.

클라이언트가 이미 받아온 매물과 도감 컨텍스트만 사용하므로 `/api/v2/marketplace/browse`의 요청·응답 형식과 서버 조회 상한은 바꾸지 않는다.

## 화면 구성과 접근성

- 기존 상세 필터 그리드 안에서 제작 여부 및 즐겨찾기 토글과 같은 버튼 문법을 사용한다.
- 토글은 명시적인 레이블, `type="button"`, `aria-pressed`, 로딩 중 `disabled` 상태를 갖는다.
- 필터 패널 표면은 기존 `SURFACE_INSET`을 그대로 사용하며 새 반투명 배경을 추가하지 않는다.
- 라이트·다크 모드의 기존 토글 색 체계를 재사용하고, 상태는 색상뿐 아니라 문구로도 구분한다.

## 테스트 전략

기능 구현은 회귀 테스트를 먼저 추가한다.

1. 순수 판정 함수가 토글 해제, 도감 로딩 전, 등록 장비, 미등록 장비, 카탈로그에 없는 식별자를 각각 올바르게 처리하는지 검증한다.
2. 장비 탭에서만 도감 필터가 적용되고 재료·소모품 탭에는 영향을 주지 않는지 검증한다.
3. 검색어, 장비 티어 및 기존 제작 필터와 동시에 적용했을 때 교집합 결과만 남는지 검증한다.
4. 활성 필터 개수, 상태 칩, 필터 초기화 및 페이지네이션 키가 도감 필터 상태를 반영하는지 검증한다.
5. 도감 데이터 로딩 전 버튼이 비활성화되고 매물은 숨기지 않는지 검증한다.
6. 결과가 없을 때 전용 빈 상태 문구가 표시되는지 검증한다.

전체 기준 테스트에서는 `levelDesignSim.test.ts`의 장시간 시뮬레이션 1건이 5초 제한으로 시간 초과했으나, 해당 파일만 단독 실행했을 때 13개 테스트가 모두 통과했다. 신규 기능 검증 때에도 이 기존 부하성 시간 초과와 신규 회귀를 구분한다.

## 완료 조건

- 여섯 장비 탭에서 도감 미등록 매물만 볼 수 있다.
- 도감 로딩 전에는 잘못된 미등록 판정을 하지 않는다.
- 기존 검색, 즐겨찾기, 티어, 제작 필터 및 정렬과 함께 정상 동작한다.
- 재료·소모품 및 거래소의 다른 화면에는 동작 변화가 없다.
- 초기화, 활성 상태 표시, 페이지 초기화와 빈 상태 안내가 일관되게 동작한다.
- 관련 신규 테스트와 기존 거래소 필터 테스트가 통과한다.

## 배포

이 설계와 구현은 자동으로 배포하지 않는다. 사용자가 별도로 배포를 요청한 경우에만 지정한 환경에 배포한다.
