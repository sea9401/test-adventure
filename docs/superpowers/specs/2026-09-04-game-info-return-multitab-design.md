# 게임 등급정보 복귀 중복 탭 수정 설계

## 문제

게임 내부의 설정 메뉴와 환경설정 화면은 진행 중인 게임 상태를 보존하기 위해
`/game-info`를 새 탭으로 연다. 그러나 등급정보 페이지의 `무슨무슨게임으로 돌아가기`
링크는 같은 보조 탭에서 `/`를 열어 원래 게임 탭과 두 번째 게임 탭을 동시에 만든다.
멀티탭 가드는 이를 정상적으로 감지해 중복 탭 경고를 표시한다.

## 선택한 해결 방식

게임에서 연 등급정보 URL에 `from=game`을 붙인다. 등급정보 페이지는 Next.js 16의
Promise형 `searchParams`를 읽어 이 경우 전용 클라이언트 복귀 컨트롤을 렌더링한다.
컨트롤은 새 게임 화면으로 이동하지 않고 `window.close()`로 현재 보조 탭을 닫는다.
브라우저가 닫기를 거부하면 기존 게임 탭을 직접 선택하라는 안내를 표시한다.

등급정보 URL을 직접 방문했거나 로그인 대문에서 이동한 경우에는 기존 `/` 링크를
유지한다. 멀티탭 가드와 저장 동기화 로직은 변경하지 않는다.

## 대안

- 등급정보를 같은 탭에서 열면 중복 탭은 생기지 않지만 진행 중인 게임 컴포넌트가
  언마운트되므로 기존의 상태 보존 목적을 훼손한다.
- 멀티탭 가드가 이 경우를 무시하게 하면 실제 두 게임 탭의 동시 수정을 허용할 위험이 있다.
- `window.opener`로 원래 탭을 제어하면 `noopener` 보호를 제거해야 하므로 사용하지 않는다.

## 검증

- 게임 내부 두 링크가 `/game-info?from=game`을 새 탭으로 연다.
- 게임에서 연 페이지는 홈 링크 대신 탭 닫기 버튼을 표시하고 클릭 시 `window.close()`를
  호출한다.
- 직접 방문 페이지는 `/`로 돌아가는 링크를 유지한다.
- 닫기 실패 시 `/`로 이동하지 않고 기존 게임 탭 선택 안내를 표시한다.

## 범위 밖

- 멀티탭 가드 프로토콜 변경
- 저장·세션 로직 변경
- 운영 배포 또는 피드백 상태의 외부 변경
