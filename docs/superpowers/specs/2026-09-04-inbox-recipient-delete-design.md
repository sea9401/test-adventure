# 받은 우편 삭제 기능 설계

## 목적

받은 우편함에서 확인과 처리가 끝난 우편을 이용자가 직접 정리할 수 있게 한다. 삭제는
수신자의 목록에만 적용하며, 발신자의 보낸 우편 기록과 운영상 원본은 보존한다. 미수령
보상, 미처리 길드 초대와 손상된 우편은 실수로 버릴 수 없게 삭제를 차단한다.

## 데이터 모델

`marketplace_inbox`에 수신자 전용 삭제 시각 `recipient_deleted_at`을 추가한다. 이 값은
해당 우편이 수신자의 받은 우편 목록에서 숨겨졌음을 나타내며 행 자체를 제거하지 않는다.
발신자의 보낸 우편 조회는 이 값을 사용하지 않으므로 기존 기록을 계속 표시한다.

받은 우편 일반 조회와 미확인 개수 조회에는 `recipient_deleted_at IS NULL` 조건을
추가한다. 삭제된 우편은 우편함, 통합 알림과 미확인 배지에서 모두 제외된다.

## 삭제 규칙과 API

수신자 전용 `POST /api/marketplace/inbox/delete` 엔드포인트를 추가한다. 요청 본문은 양의
정수 우편 ID 하나만 받는다. 서버는 로그인한 사용자가 해당 우편의 수신자인지 확인하고
행을 잠근 뒤 다음 규칙을 적용한다.

- `claimed_at`이 있는 완료 우편만 삭제할 수 있다.
- 미수령 보상, 미처리 길드 초대와 손상된 미완료 우편은 `not_completed`로 거부한다.
- 다른 사용자의 우편과 존재하지 않는 우편은 동일하게 `not found`로 처리한다.
- 이미 삭제된 우편을 다시 삭제해도 성공하는 멱등 동작으로 처리한다.
- 성공 시 `recipient_deleted_at`을 현재 시각으로 기록한다.

삭제 API는 행을 물리적으로 지우지 않으며 보상·인벤토리·골드·길드 상태를 변경하지
않는다.

## 화면 흐름

받은 우편 중 `claimedAt`이 있는 완료 우편의 카드와 상세 모달에만 `삭제` 버튼을
표시한다. 보낸 우편에는 삭제 버튼을 표시하지 않는다.

삭제 버튼을 누르면 우편 종류와 내용을 확인할 수 있는 확인창을 표시한다. 확인 후 API가
성공하면 상세 모달을 닫고 해당 우편을 로컬 목록에서 즉시 제거하며 통합 알림 갱신
이벤트를 보낸다. 성공 메시지는 `우편을 삭제했어요.`로 표시한다. 실패하면 목록과 상세
모달을 유지하고 다음과 같이 안내한다.

- `not_completed`: `수령하거나 처리를 마친 우편만 삭제할 수 있어요.`
- 그 밖의 서버 실패: `우편 삭제 실패 (상태 코드)`

삭제와 수령·초대 처리는 기존 `busy` 상태를 공유해 동시에 요청되지 않게 한다.

## 접근성과 표면

- 삭제 버튼은 텍스트와 구체적인 접근성 이름을 함께 제공한다.
- 확인창은 기존 프로젝트의 확인 대화상자 패턴을 사용한다.
- 카드와 상세 모달은 기존 불투명 공용 표면을 그대로 유지한다.
- 삭제 성공 후 키보드 포커스가 사라진 모달에 남지 않도록 상세 모달을 닫는다.

## 검증

- API 테스트에서 인증, ID 검증, 소유권, 완료 조건, 멱등 삭제와 삭제 시각 갱신을 확인한다.
- 받은 우편 조회와 개수 조회가 수신자 삭제 우편을 제외하고, 보낸 우편 조회는 계속
  포함하는지 확인한다.
- 클라이언트 API가 올바른 요청을 보내고 오류를 사용자 문구로 변환하는지 확인한다.
- 화면 테스트에서 완료 받은 우편에만 삭제 버튼이 나타나고 미완료·보낸 우편에는 나타나지
  않는지 확인한다.
- 삭제 성공 시 목록 제거, 모달 닫기, 성공 메시지와 알림 갱신 이벤트를 확인한다.
- 관련 테스트, 타입 검사, 린트, 마이그레이션 검사를 실행한다.

## 범위 밖

- 보낸 우편 삭제
- 전체 우편 일괄 삭제
- 미수령 보상이나 미처리 길드 초대 폐기
- 삭제 취소 또는 휴지통 화면
- 운영 배포와 점검 모드 변경
