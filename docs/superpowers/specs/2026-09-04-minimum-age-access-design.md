# 만 14세 이상 서비스 접근 설계

## 목표

공식 게임 등급인 `12세이용가` 표시는 그대로 유지하면서, 서비스 운영 기준을
`만 14세 이상`으로 제한한다. 생년월일은 새로 수집하지 않고 로그인 전에 이용자가
연령 요건을 확인하도록 하며, 화면과 서버 양쪽에서 확인되지 않은 접근을 차단한다.

## 채택 방식

로그인 화면에 `본인은 만 14세 이상입니다` 확인 절차를 둔다. 서버는 확인 시각과 버전을
담은 값을 `AUTH_SECRET`으로 서명해 HttpOnly 쿠키로 발급하고 최대 1년 동안 인정한다.
브라우저에서 임의의 쿠키 값을 만들거나 만료 시각을 바꿔도 서명 검증을 통과할 수 없다.

이 방식은 생년월일이나 신분증을 받지 않는 최소수집형 자기확인 절차다. 실제 생년월일을
외부 기관으로 확인하는 본인인증형 연령검증은 아니므로, 운영 문서에서 이를 과장하지
않고 추후 본인인증이 필요해질 경우의 별도 과제로 남긴다.

## 접근 경계

- `/sign-in`은 연령 확인 전에는 카카오 및 운영자 발급 계정 로그인 버튼을 노출하지 않는다.
- Auth.js 로그인 콜백도 유효한 확인 쿠키가 없으면 로그인을 거부한다.
- Proxy는 공개 문서·등급정보·연령 확인 API를 제외한 페이지와 API에 유효한 쿠키를 요구한다.
- 게임 레이아웃과 공통 게임 API 인증 함수에서도 다시 검증해 Proxy만을 보안 경계로 믿지 않는다.
- 이미 로그인한 이용자도 확인 쿠키가 없으면 `/sign-in?age=required`로 이동한다.
- 로컬 자동 로그인도 처음에는 같은 확인을 거치며, 확인 후 새로 고친 요청에서 자동 로그인을 계속한다.

## 쿠키와 API

- 이름: `msmsge_age_14_confirmed`
- 값: 버전, 확인 시각, HMAC-SHA-256 서명
- 속성: `HttpOnly`, `SameSite=Lax`, 운영에서 `Secure`, `Path=/`, 최대 1년
- `POST /api/age-eligibility`는 동일 출처 JSON 요청과 명시적인 `confirmed: true`만 받는다.
- `AUTH_SECRET`이 없거나 요청·서명이 잘못되면 실패 폐쇄한다.

## 화면과 정책

공식 `12세이용가`와 서비스의 `만 14세 이상` 기준이 서로 다른 개념임을 로그인 화면과
이용약관에 함께 설명한다. 개인정보처리방침에는 생년월일을 수집하지 않는다는 점,
확인 여부·시각 쿠키의 목적과 최대 보유 기간을 공개한다.
