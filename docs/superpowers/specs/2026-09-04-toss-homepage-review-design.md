# 토스페이먼츠 홈페이지 심사 준비 설계

## 목표

토스페이먼츠 홈페이지 심사자가 로그인하지 않아도 무슨 코인 상품, 가격, 공급 시점,
환불 기준과 사업자 정보를 확인할 수 있게 한다. 실제 결제는 기존 심사 계정만 접근할 수
있고 운영 공개 플래그는 계속 닫아 둔다.

## 공개 표면

- `/products/museun-coin`은 무슨 코인 1,000·2,000·3,000·5,000개 상품과 각각의
  10,000·20,000·30,000·50,000원 가격을 공개한다.
- 각 상품에는 서로 다른 상품 이미지, `결제 승인 후 즉시 지급`, 계정 귀속, 외부 현금
  환전 금지와 환불정책 링크를 표시한다.
- 대문 푸터에서 상품 안내와 정책 페이지로 이동할 수 있게 한다.
- 구매 버튼은 비로그인 사용자를 로그인 화면으로 안내한다. 계정에 귀속되는 디지털
  재화이므로 실제 구매와 지급은 로그인 뒤에만 수행한다.

## 사업자 정보

- 상호 `무슨게임`과 사업자등록번호 `781-52-01091`은 공개 상수로 관리한다.
- 대표자명, 사업장 주소, 구매자 공개 연락처, 통신판매업 신고번호는 배포 환경의
  `PUBLIC_MERCHANT_*` 변수에서 읽는다. 통신판매업 신고번호만 선택 값이다.
- 값이 완전할 때 대문과 공개 상품 페이지에 동일한 사업자 정보 블록을 렌더링한다.
- `PG_HOMEPAGE_REVIEW_MODE=true`인데 대표자명·주소·연락처가 빠졌다면 준비 상태
  검사에서 실패한다. 결제 비활성 기본값에서는 기존 빌드가 영향을 받지 않는다.

## 결제 심사 접근

- 운영 기본값 `NEXT_PUBLIC_MUSEUN_COIN_SHOP_OPEN=false`와
  `MUSEUN_COIN_PAYMENTS_MODE=disabled`는 바꾸지 않는다.
- 심사 환경에서는 지정된 비밀번호 로그인 계정만 코인 상점과 결제 API에 접근한다.
- 테스트 키는 서버의 미추적 환경 파일 또는 비밀 저장소에만 넣는다.
- 결제창형 SDK v2 흐름은 `setAmount()` → `renderPaymentWindow()` →
  `paymentRequest` 이벤트 → `requestPayment()` 순서를 따른다. 취소 이벤트에서는 UI
  잠금을 해제한다.

## 검증

- 사업자 정보 파싱과 심사 모드 누락 검사를 단위 테스트한다.
- 공개 상품 페이지가 네 상품, 서로 다른 이미지, 가격, 즉시 지급과 환불 링크를
  제공하는지 정적 렌더 테스트한다.
- 대문 푸터가 상품 링크와 완전한 사업자 정보를 표시하는지 테스트한다.
- 결제 컴포넌트가 결제창 렌더 후 이벤트에서 한 번만 결제를 요청하는지 테스트한다.
- 린트, 타입 검사, 전체 Vitest, 운영 빌드와 공개 페이지 E2E를 실행한다.

## 배포 제한

이 작업은 로컬 코드와 문서만 변경한다. 푸시, 운영 배포, 점검 모드 변경, 테스트·라이브
키 등록은 수행하지 않는다.
