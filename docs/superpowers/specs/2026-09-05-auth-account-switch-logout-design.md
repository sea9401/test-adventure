# 인증 계정 전환 로그아웃 보강 설계

## 배경

운영에서 비밀번호 심의 계정으로 로그인한 브라우저가 우측 상단 메뉴로 로그아웃한 뒤
카카오 로그인을 시도하면, 카카오 인증 실패 후 이전 심의 계정 화면으로 되돌아오는 현상이
확인됐다.

운영 요청 흐름은 다음과 같았다.

1. `POST /api/auth/logout`은 성공했고 직후 `/api/auth/session`은 빈 세션을 반환했다.
2. 이어진 카카오 콜백은 `OAuthAccountNotLinked`로 실패했다.
3. 오류가 붙은 `/sign-in` 요청이 `/`로 리다이렉트됐다.
4. 동일 브라우저의 디바이스 세션에는 심의 계정만 남아 있었고, 심의 계정에는 카카오
   OAuth 연결이 없었다.

이는 카카오 계정이 심의 계정에 연결되거나 게임 데이터가 병합된 문제가 아니다. 로그아웃
보호 쿠키가 이전 JWT를 일시적으로 가렸지만 JWT 자체가 남았고, OAuth 처리 중 보호가
해제된 뒤 카카오 전환이 실패하면서 이전 JWT가 다시 유효해진 계정 전환 경계 문제다.

## 목표

- 심의 계정 로그아웃 뒤 카카오 로그인이 성공하면 선택한 카카오 계정으로 완전히 전환한다.
- 카카오 인증 또는 계정 확인이 실패하면 로그인 화면에 머물며 이전 심의 세션은 복원되지
  않는다.
- 일반·Secure·분할 세션 쿠키가 섞여 있어도 로그아웃이 완결된다.
- 기존 단일 디바이스 세션과 명시적 계정 연결 정책은 유지한다.

## 비목표

- 카카오 계정과 심의 계정을 자동으로 연결하거나 병합하지 않는다.
- `OAuthAccountNotLinked` 정책을 완화하거나 이메일 기반 자동 연결을 허용하지 않는다.
- 심의 계정 또는 카카오 계정의 저장 데이터를 변경하지 않는다.
- 이 작업에서 운영 배포를 수행하지 않는다.

## 선택한 설계

### 1. 로그아웃을 두 단계로 완결한다

우측 상단 메뉴는 Auth.js 공식 `signOut({ redirect: false })`를 먼저 호출한다. Auth.js가
현재 설정으로 해석한 세션 저장소를 직접 정리한 다음, 기존 `/api/auth/logout`을 호출해
일반·Secure·분할 세션 쿠키 변형을 추가로 만료하고 로그아웃 보호 쿠키를 설정한다.

첫 단계는 Auth.js 내부 세션 쿠키 계약을 따르고, 두 번째 단계는 과거 이름이나 분할 쿠키가
남는 상황을 방어한다. 두 요청이 모두 끝난 뒤에만 `window.location.replace("/sign-in")`로
이동한다. 공식 로그아웃이 실패하더라도 정리 API는 시도하며, 정리 API까지 실패하면 메뉴를
다시 열어 사용자가 재시도할 수 있게 한다.

### 2. 로그아웃 보호는 새 인증 성공 뒤에만 해제한다

로그아웃 보호 쿠키 삭제를 `callbacks.signIn`의 사전 승인 단계에서 수행하지 않는다.
Auth.js는 이 콜백 이후에도 계정 소유권 충돌을 발견해 `OAuthAccountNotLinked`를 낼 수
있으므로, 이 시점은 인증 성공 경계가 아니다.

보호 해제는 `callbacks.jwt`에서 실제 로그인용 `user`와 `account`가 전달되고 새 JWT를
발급하는 성공 경로로 옮긴다. Credentials 로그인도 같은 성공 경계에서 보호를 해제한다.
명시적 OAuth 계정 연결 흐름에는 기존 의미를 유지하며 불필요한 단일 디바이스 takeover를
부여하지 않는다.

### 3. OAuth 실패 시 이전 세션으로 리다이렉트하지 않는다

카카오 처리에서 `OAuthAccountNotLinked`를 포함한 오류가 발생하면 로그아웃 보호가 유지된다.
`/sign-in`은 오류 내용을 표시하고 보호 경계 안에서는 남아 있는 JWT를 인증 세션으로
취급하지 않는다. 따라서 물리적으로 제거되지 않은 예외적 쿠키가 있더라도 이전 심의 계정의
게임 화면으로 돌아갈 수 없다.

## 대안과 제외 이유

### 쿠키 삭제 목록만 확대

구현은 작지만 새 Auth.js 쿠키 이름이나 프록시 응답 병합에 다시 의존한다. OAuth 실패 전에
보호를 해제하는 논리 오류도 남으므로 단독 해결책으로 사용하지 않는다.

### OAuth 오류가 나면 세션을 한 번 더 삭제

증상은 막을 수 있지만 실패가 발생하기 전 Auth.js가 이전 JWT를 현재 사용자로 해석하는
문제는 남는다. 오류 종류별 후처리 누락 가능성도 있어 주 해결책으로 삼지 않는다.

## 오류 처리

- Auth.js 공식 로그아웃 요청이 실패해도 잔여 쿠키 정리 API를 계속 호출한다.
- 잔여 쿠키 정리 API가 실패하면 화면 이동을 중단하고 메뉴를 복원한다.
- 카카오 인증 실패 시 기존 오류 문구를 로그인 화면에 표시한다.
- 어떤 실패 경로에서도 로그아웃 보호 쿠키를 인증 성공 전에 제거하지 않는다.
- 비밀번호나 OAuth 토큰, 사용자 ID는 진단 로그에 추가하지 않는다.

## 테스트

### 단위 테스트

- 로그아웃 정리 API가 일반·Secure·분할 세션 쿠키를 모두 만료하고 디바이스 쿠키는 유지한다.
- JWT 로그인 성공 경로만 로그아웃 보호를 해제한다.
- OAuth 사전 승인 또는 실패 경로는 로그아웃 보호를 해제하지 않는다.
- 보호 쿠키가 있으면 이전 JWT만으로 보호 경로에 진입할 수 없다.

### UI·통합 회귀 테스트

- 심의 계정 로그인 → 우측 상단 로그아웃 → 세션 없음.
- 심의 계정 로그인 → 로그아웃 → 기존 카카오 계정 로그인 → 카카오 계정의 사용자 ID와
  서버 저장 데이터를 로드.
- 심의 계정 로그인 → 로그아웃 → `OAuthAccountNotLinked` → 로그인 화면 유지 및 세션 없음.
- 로그아웃 요청 순서가 Auth.js 공식 로그아웃 → 잔여 쿠키 정리 → 로그인 화면 이동인지 확인.

## 완료 조건

- 관련 단위·통합 테스트가 통과한다.
- 타입 검사와 변경 파일 대상 린트가 통과한다.
- 운영 DB나 계정 데이터에는 쓰지 않는다.
- 변경 사항은 현재 브랜치에 커밋하되, 별도 요청 전에는 배포하지 않는다.
