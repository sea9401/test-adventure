# 전투 패턴 교대 순서 보존 설계

## 문제

현재 `교대 사용`은 실제 스킬 발동과 무관하게 전체 공격 차례 홀짝으로 A와 B를
선택한다. 패턴에도 발동률을 적용하는 운영 설정에서 A가 실패하면 다음 차례는 B로
넘어가므로, 성공한 스킬만 보면 `A → B → B → A`처럼 같은 스킬이 연속될 수 있다.
비천무신은 실제 원거리·체술 사용 순서가 교차해야 포획·추격을 얻기 때문에 이 동작은
직업 메커니즘과 충돌한다.

## 결정

교대 진행은 공격 차례가 아니라 해당 교대 행동에서 실제로 발동한 스킬을 기준으로
갱신한다. 각 순서쌍을 `(A, B)` 키로 구분하고 마지막 성공 스킬을 전투 상태에 저장한다.

- 기록이 없으면 A를 선택한다.
- 마지막 성공이 A면 B, B면 A를 선택한다.
- 발동률 실패, MP 부족, 쿨다운, 조건 불충족 때는 기록을 바꾸지 않는다.
- 우선순위가 높은 다른 블록이 발동해도 해당 A/B 기록을 바꾸지 않는다.
- 서로 다른 A/B 순서쌍은 독립된 기록을 사용한다.
- PvE와 PvP가 같은 선택 규칙을 사용한다.

## 데이터 흐름

전투 상태의 스택에 교대 순서쌍별 마지막 성공 스킬 맵을 선택적으로 보관한다.
`resolveV2SkillCast`는 이 맵으로 후보를 고르고, 교대 후보가 실제 발동한 경우에만
상태 갱신 의도를 반환한다. PvE/PvP 호출부는 해당 의도를 자기 전투 상태에 합친다.
전투 종료 후 저장되는 영구 데이터나 API 형식은 바뀌지 않는다.

## 사용자 안내

패턴 화면과 모험 안내서의 설명을 실제 동작에 맞춰, 실패하거나 사용할 수 없는 경우
현재 차례를 유지하고 성공 뒤에만 다음 스킬로 넘어간다고 명시한다.

## 검증

순수 평가기, 실제 발동률 게이트, PvE 전투 상태 연결을 각각 회귀 테스트한다. 기존
패턴·비천무신·PvP 전투 테스트와 TypeScript, ESLint 검사를 함께 실행한다.
