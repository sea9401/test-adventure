# 요리 최초 발견자 현재 닉네임 반영 설계

## 목표

공개 요리 발견 목록의 최초 발견자 이름이 발견 당시 스냅샷에 고정되지 않고, 해당 사용자의 현재 닉네임을 따라가도록 한다.

## 현재 원인

`cooking_first_discoveries`는 최초 발견자의 불변 `user_id`와 발견 당시 `actor_name`을 모두 저장한다. 조회 쿼리도 `users.game_name`과 프로필 저장값에서 현재 권위 닉네임을 가져오지만, 응답 변환은 `actor_name`이 `이름 없는 모험가`인 경우에만 현재 닉네임을 사용한다. 따라서 정상 이름으로 발견한 사용자는 개명 후에도 옛 이름으로 표시된다.

## 설계

- 공개 발견 응답은 `authoritativeActorName`을 공백 제거 후 우선 사용한다.
- 현재 권위 닉네임을 구할 수 없거나 빈 문자열이면 발견 당시 `actorName`을 안전한 대체값으로 사용한다.
- 기존 `user_id` 외래 키와 조회 조인을 재사용하므로 DB 마이그레이션이나 데이터 이관은 하지 않는다.
- 서버 피드와 우편 등 사건 시점 스냅샷은 범위 밖이며 기존 동작을 유지한다.

## 테스트

`GET /api/v2/cooking` 테스트에서 발견 당시 이름과 현재 권위 닉네임이 다른 행을 준비하고, 공개 발견 목록이 현재 권위 닉네임을 반환하는지 검증한다. 권위 닉네임이 없는 기존 행은 저장된 발견 당시 이름을 유지하는 기존 사례로 함께 보호한다.
