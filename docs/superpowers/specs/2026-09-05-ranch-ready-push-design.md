# 목장 생산 완료 푸시 알림 설계

## 배경과 목표

밭 수확, 자동 벌목, 자동 채광은 예약 크론이 브라우저 푸시를 보내지만 목장 생산은 농장 화면 안에서만 확인할 수 있다. 특히 돼지는 비육에 12시간이 걸려 완료 시점을 놓치기 쉽다.

목표는 푸시 알림을 켠 이용자에게 닭·소·돼지 생산 완료를 앱 밖에서도 알리고, 알림을 누르면 농장의 목장 탭으로 바로 이동하게 하는 것이다. 배포와 알림 종류별 개별 설정은 이번 범위에 포함하지 않는다.

## 접근 방식

기존 `/api/cron/push-notifications` 흐름에 목장을 추가한다. 별도 크론이나 DB 알림 행은 만들지 않는다. 크론이 `farm.v2`를 읽어 현재 시각 기준 목장 상태를 정산한 뒤, 수확 대기 회차가 새로 생긴 동물 종류를 찾는다.

다른 선택지는 알림 종에만 동적 알림을 추가하거나, 알림 종과 푸시를 함께 추가하는 방식이다. 알림 종만으로는 앱을 열지 않은 동안 돼지를 잊는 문제를 해결하지 못한다. 둘을 함께 추가하면 별도 읽음 상태와 표시 문구까지 바꿔야 한다. 현재 농장 화면에는 이미 목장 완료 배지가 있으므로 이번에는 직접적인 문제를 해결하는 예약 푸시에 집중한다.

## 완료 판정과 중복 방지

순수 함수가 저장된 농장 상태를 파싱하고 `settleRanch`로 현재 시각까지의 생산을 계산한다. 동물 종류별로 다음 값을 만든다.

- 현재 수확 대기 생산 회차 합계
- 해당 동물의 누적 완료 회차
- 생산물 이름

수확 대기 회차가 0인 동물은 알림 후보가 아니다. 후보 키는 이용자, 동물 종류, 누적 완료 회차, 현재 수확 대기 회차를 조합한다. 같은 완료 상태에서는 키가 변하지 않으므로 크론이 반복 실행되거나 사료 투입 등으로 상태가 다시 저장되어도 같은 알림을 보내지 않는다. 새 생산 회차가 끝나면 누적 완료 회차와 대기 회차가 바뀌어 새 후보가 된다. 수확 후 다음 생산도 누적 완료 회차가 증가하므로 과거 키와 충돌하지 않는다.

여러 종류가 동시에 새 후보라면 푸시는 한 건으로 묶고, 본문에는 그 실행에서 새로 알릴 생산물 이름만 나열한다. 전송에 성공한 후보 키만 기존 `push_deliveries`에 기록한다. 모든 구독으로의 전송이 실패하면 기록하지 않아 다음 크론에서 재시도한다. 기존 보존 기간 정리 정책을 그대로 따른다.

## 푸시 내용과 이동

- 제목: `목장 생산 완료`
- 본문: 한 종류이면 `돼지고기를 수확할 수 있습니다.`처럼 표시하고, 여러 종류이면 `달걀, 우유를 수확할 수 있습니다.`처럼 묶는다.
- 이동: `/town/farm#ranch`
- 태그: 이용자에게 같은 목장 알림이 여러 개 쌓이지 않도록 고정된 `ranch-ready`

농장 화면은 처음 열릴 때 URL 해시가 `#ranch`이면 목장 탭을 선택한다. 일반 `/town/farm` 진입과 화면 안에서 기억하는 마지막 탭 동작은 그대로 유지한다.

## 오류 처리와 호환성

손상된 농장 저장값은 기존 `parseFarmState`와 `parseRanchState`의 보정 규칙을 따른다. 잠긴 축사나 수확 대기 생산물이 없는 축사는 무시한다. 목장 후보 계산 실패가 기존 밭·벌목·채광 후보 판정과 분리되지 않도록 순수 계산만 추가하며, 푸시 전송 실패 집계 방식은 기존 동작을 유지한다.

기존 `farm_ready` 인게임 알림과 밭 푸시 이벤트 키는 변경하지 않는다. 저장 모델과 DB 스키마도 변경하지 않는다.

## 테스트와 완료 기준

- 완료 직전에는 목장 알림 후보가 없고 완료 정각에는 생긴다.
- 돼지 두 마리가 동시에 또는 서로 다른 시각에 완료되어도 동물 종류별 상태 키가 안정적으로 변한다.
- 이미 수확 대기 중인 상태를 같은 시각이나 더 늦은 시각에 다시 계산해도 새 생산이 없으면 같은 키를 만든다.
- 닭·소·돼지가 함께 새 후보이면 푸시 한 건의 본문에 해당 생산물 이름을 모두 포함한다.
- 목장 푸시 성공 시 후보 키를 기록하고, 전송 실패 시 기록하지 않는다.
- `/town/farm#ranch`로 진입하면 목장 탭이 선택되고 일반 진입은 기존 초기 탭을 유지한다.
- 관련 단위 테스트, 타입 검사, 린트와 프로덕션 빌드를 통과한다.
