# 주간 시설 출처 충돌 경보 정리 설계

## 목표

길드 이동 후 기존 길드에 귀속된 주간 시설을 새 길드에서 사용하려는 정상 정책 차단을
실제 보상 지급 실패와 구분한다. 이용 화면은 POST 전 충돌을 알려 반복 요청을 막고,
운영 경보와 보정 후보에는 실제 조사할 실패만 남긴다.

## 확인된 원인

- 주간 시설 원장은 같은 주의 다른 길드 이용을 `weekly_source_conflict`로 거절한다.
- 훈련장과 연금 공방 GET은 원장을 읽지 않아 충돌 중에도 이용 가능한 버튼을 노출한다.
- 두 POST 라우트는 모든 비정상 응답을 `recordRewardFailureSoon`에 전달한다.
- 운영 분류는 `weekly_source_conflict`를 알지 못해 `possible_missing`으로 표시한다.

## 설계

`adventurerAssociation` 서버 모듈에 시설별 주간 선택 전체를 읽는 함수를 추가한다.
기존 source-only 함수는 새 함수 위의 호환 래퍼로 유지한다. 훈련장과 연금 공방 GET은
현재 요청의 source와 guildId를 기존 순수 판정 함수에 넣고 `weeklySourceEligible`을
응답한다. POST는 동일한 트랜잭션 검증을 계속 수행해 동시 변경과 조작 요청을 막는다.

클라이언트는 `weeklySourceEligible === false`이면 가능 수량을 0으로 표시하고 모든 보상
행동 버튼을 비활성화한다. 불투명한 기존 surface 토큰을 사용한 안내문으로 이번 주에는
이전에 선택한 시설만 이용할 수 있고 다음 월요일 00:00 KST에 초기화된다고 설명한다.
이전 서버 응답과의 호환을 위해 필드가 없으면 기존처럼 이용 가능으로 취급한다.

`recordRewardFailureSoon`은 `weekly_source_conflict`를 기대된 정책 거절로 판정해 경제
실패 이벤트와 웹훅 신호를 만들지 않는다. 다른 오류는 기존과 동일하게 기록한다.
관리자 분류는 과거에 이미 기록된 동일 오류를 `policy_rejection`/안내 수준으로 분류하고
보정하지 말고 무시 처리하도록 안내한다.

## 테스트

- 주간 선택 전체 읽기와 다른 길드 충돌 판정을 단위 테스트한다.
- 훈련장 claimable helper와 연금 최대 수량 helper가 출처 충돌 시 0을 반환하는지 검증한다.
- `recordRewardFailureSoon`이 정책 거절은 쓰지 않고 실제 오류는 즉시 기록하는지 검증한다.
- 관리자 분류가 주간 출처 충돌을 정책 거절로 분류하는지 검증한다.
- 관련 테스트, TypeScript 검사, ESLint를 실행한다.

## 범위 제외

- 같은 주 다른 길드 이용을 막는 게임 정책은 변경하지 않는다.
- 기존 무시 처리된 운영 기록을 삭제하지 않는다.
- 운영 배포와 점검 모드 변경은 수행하지 않는다.
