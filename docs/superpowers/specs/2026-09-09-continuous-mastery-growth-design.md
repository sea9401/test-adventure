# 숙련도 소수 보정을 반영하는 독립 성장 설계안

> 최신 MP 조정: [MP 성장량 조정](../plans/2026-09-09-mp-growth-balance.md). 아래 MP 3배 및 기본 3~5는 당시 설계 기록이며, 현재는 숙련도 계수 0.1 및 버전 2 기본 2~4를 사용한다.

상태: 사용자 승인 후 구현. 아래 최종 합의값이 과거 후보안보다 우선한다.

최종 합의: 성장 기준 5,000, 시작 스탯 계수 22, HP·MP 숙련도 보정 3배, 시작 기본 HP 250~350 / MP 120~180. 현재 생애는 보존하고 재전직 때 시작 스냅샷을 갱신한다. 구형 높은 시작값의 영구 보장은 없다.

**최신 검토안:** 시작값과 99회 성장의 합을 기준으로 계산한다. 시작 계수 100 및
기존 높은 시작값의 영구 보장은 철회한다. 시작 계수 22를 총 성장량과 함께 재검토하는
수치안은 문서 마지막 절을 따른다. 과거 후보와 운영 집계는 비교 기록으로 남긴다.
시작 자원 최신 제안은 기본 HP 250~350 / MP 120~180에 숙련도 기반 시작 스탯과 실제 수행 한계 보정을 더한다.

## 목적과 확정된 요구

- 사용자 합의: 성장 기준값은 5,000, HP·MP 숙련도 보정은 최초 안의 3배.
- 재전직 시작 스탯은 누적 레벨 대신 관련 숙련도로 책정한다. 아래 시작 스탯 계수 5와 후속 계수 20 제안은 사용자가 너무 낮다고 평가하여 채택하지 않는다. 운영 현황은 문서 마지막 재확인 기록을 기준으로 한다.

- 레벨업마다 힘·민첩·활력·지능·정신·행운을 각각 독립적으로 굴린다.
- 관련 숙련도가 없으면 각 스탯은 0~1이다. 0도 정상 결과다.
- 관련 숙련도가 증가하면 같은 정수 범위 안에서도 기대 성장량이 증가한다.
- 레벨당 총 3점이나 생애 총 297점 제한을 두지 않는다.
- 수행으로 정한 개별 한계까지 적용한다. 한계 때문에 남은 성장량을 다른 스탯으로 넘기지 않는다.
- 사용자가 제시한 숙련도 2천만 / 성장 8은 수치 확정 조건이 아니다.

## 현재 문제

현재 `statGrowth.ts`는 관련 숙련도 M에 대해 상한을
`1 + floor(log2(1 + M / 10000))`로 계산한다.
7만 이상 15만 미만은 모두 0~4를 굴려 숙련도 상승이 해당 구간의 성장량에 반영되지 않는다.
HP·MP에 추가하는 숙련도 단계도 같은 정수 버림을 사용한다.

## 접근 비교와 권장안

| 방식 | 결과 | 판단 |

## 기본 스탯 공식

관련 숙련도는 각 직업의 직접 기록(`jobCumLevel`)만 프로필 가중 합산한다.
계열 총합(`groups.cumLevel`)은 같은 활동의 집계이므로 더하지 않는다. 견습도 직접 기록만 포함한다.
2026-09-09 중복 합산 수정: 아래 과거 운영 집계는 수정 전 계열+직업 합산으로 산출된 비교 기록이며, 수정 후 개인별 예측값으로 사용하지 않는다.
프로필 비율로 발생한 소수 숙련도도 중간에 버리지 않는다.

```text
U = 1 + log2(1 + M / 5000)
N = floor(U)
P = U - N

매 레벨, 각 스탯마다:
  확률 P로 상한 N+1 선택, 나머지 확률로 상한 N 선택
  선택한 범위 0~상한에서 정수를 균등하게 굴림
  실제 증가 = min(굴림, max(0, 해당 스탯의 남은 수행 한계))
```

범위 선택과 범위 안의 굴림은 서로 독립 난수를 사용한다.
스탯 사이에도 난수를 공유하지 않는다. 한계에 막힌 스탯 때문에 다른 스탯의 난수 배정이 바뀌지 않도록 고정된 순서로 굴린다.
정수 경계의 P=0에서도 같은 난수 소비 순서를 사용한다.

예를 들어 U=4.3이면 70%는 0~4, 30%는 0~5를 선택한다.
여기서 **30%는 +5를 얻을 확률이 아니다.** +5를 얻는 확률은 `30% / 6 = 5%`다.
0~4 각각의 확률은 `70% / 5 + 30% / 6 = 19%`다.

한계에 막히지 않을 때 기대 증가량은 `U / 2`다.
M이 커질수록 증가하며, 정수 경계에서도 연속적으로 이어진다.
수행 한계에 도달한 경우 실제 증가량은 0이며, 한계 근처에서는 위 기대값보다 낮다.
숙련도가 올라 매번 더 높은 결과가 보장되는 것은 아니다.

## 계산 예시

아래는 스탯 하나의 관련 숙련도 기준이다. 수행 한계가 충분하다고 가정한다.

| 관련 숙련도 M | 기본 범위 | 넓은 범위 선택 확률 | 레벨당 평균 증가 |
| ---: | --- | ---: | ---: |
| 0 | 0~1 | 0% | 0.5000 |
| 5천 | 0~2 | 0% | 1.0000 |
| 3.5만 | 0~4 | 0% | 2.0000 |
| 5만 | 0~4 | 0~5 선택 45.94% | 2.2297 |
| 7만 | 0~4 | 0~5 선택 90.69% | 2.4534 |
| 7.5만 | 0~5 | 0% | 2.5000 |
| 100만 | 0~8 | 0~9 선택 65.11% | 4.3255 |
| 1천만 | 0~11 | 0~12 선택 96.65% | 5.9833 |

표시는 반올림하되 실제 판정에는 반올림 전 값을 사용한다.
숙련도 1이 오를 때 기대값은 작게 증가하며, 화면 소수 자릿수에서는 변화가 보이지 않을 수 있다.

## HP·MP에도 같은 원리 적용

기본 자원 범위와 영구 저점·수행 한계의 기존 기여는 유지한다.
숙련도 보정만 정수 버림에서 확률 반올림으로 바꾼다.

```text
B(M) = 3 * log2(1 + M / 5000)
roundRandom(B) = floor(B) + Bernoulli(B - floor(B))

HP 전용으로 각각 독립 추첨:
  S = roundRandom(힘 관련 B)
  V = roundRandom(활력 관련 B)
  HP 증가 = uniformInt(기존 최소 + S, 기존 최대 + S + V)

MP 전용으로 각각 독립 추첨:
  P = roundRandom(정신 관련 B)
  I = roundRandom(지능 관련 B)
  MP 증가 = uniformInt(기존 최소 + P, 기존 최대 + P + I)
```

HP의 S는 같은 HP 굴림의 최소·최대 양쪽에 동일하게 적용한다. MP의 P도 마찬가지다.
6개 기본 스탯에서 나온 실제 증가량이나 범위 선택 결과를 HP·MP에 재사용하지 않는다.
따라서 힘 굴림이 0이어도 HP는 자신의 숙련도 범위로 성장한다.

HP 기대값은 `기존 범위 평균 + B(힘) + B(활력)/2`,
MP 기대값은 `기존 범위 평균 + B(정신) + B(지능)/2`다.
자원 버전 1·2의 기존 차이는 유지하고 그 위에 같은 소수 숙련도 보정을 적용한다.

## 표시와 API

- 스탯별로 기본 범위, 확장 범위, 확장 확률, 한계 적용 전 평균 성장량을 제공한다.
- 관련 숙련도 5만의 힘 예시: `기본 +0~4 · 45.94% 확률로 범위 +0~5 · 평균 +2.23/레벨`.
- 단순히 `+0~5`만 표시하지 않는다. 전체 범위가 균등 확률이라는 오해를 막는다.
- HP·MP는 가능한 전체 범위와 평균을 표시하고 상세 설명에서 숙련도 보정으로 확률이 다름을 안내한다.
- 미리보기 계산은 난수를 사용하지 않는다. 화면 조회로 저장된 성장이나 난수 흐름을 변경하지 않는다.
- 한계에 도달한 스탯은 `한계 도달`을 표시한다. 평균은 `한계 적용 전`임을 명시한다.

## 저장값과 적용 시점

- 기존 성장 스탯·누적 HP·MP를 보존한다. 이전 레벨을 다시 굴리지 않는다.
- 적용 이후의 실제 레벨업에만 새 확률을 사용한다. 100레벨 사냥 자체는 성장 굴림을 추가하지 않는다.
- 구형 HP·MP 저장 방식은 현재 호환 정책대로 재전직부터 독립 자원 굴림을 적용한다.
- 소수 잔여값이나 확정 지급 카운터는 저장하지 않는다. 전직 시 기존 초기화 규칙을 유지한다.
- 사냥·경험치 비약·100레벨 비약은 공통 성장 함수를 사용한다.

## 구현 범위

1. `statGrowth.ts`: 소수 숙련도 강도 계산과 범위 혼합 정보를 제공한다. 기존 정수 상한 반환값을 확률 정보 없이 그대로 소비하지 않도록 호출부를 함께 수정한다.
2. `lifeResourceGrowth.ts`: 자원별 숙련도 보정 추첨을 실제 레벨 굴림에 적용한다. 기존 기록의 누적·정렬·초기화 계약을 보존한다.
3. 사냥 및 두 비약 처리: 공통 확률 정보와 난수 주입을 사용한다. 다중 레벨도 각 레벨에 대해 개별 추첨한다.
4. `stateSections.ts`와 캐릭터 화면: 성장 미리보기 정보를 제공하고 범위·확률·평균을 구분해 표시한다.
5. 매뉴얼·시뮬레이션·회귀 테스트: 새 분포와 예시를 반영한다.

- 기존 성장 누적, 자원 버전, 전직, 만렙 이후 무성장 회귀 테스트를 수행한다.

## 밸런스 영향

로그 곡선 기준은 사용자 합의대로 5,000을 사용하고 HP·MP 숙련도 보정에 3배를 적용한다.
아래 소수 보정 증가분은 같은 5,000 기준의 정수 버림 방식과 비교한다. 10,000에서 5,000으로 변경하는 효과는 별도다.
기존에 버리던 소수 부분을 반영하므로 기본 스탯 하나당 레벨 평균이 0 이상 0.5 미만 증가한다.
6개 스탯 전체로는 레벨당 평균 3 미만이 추가될 수 있다. 99회 성장에서 추가 기대량은 총 297 미만이다.
이는 추가분의 기대값에 대한 비교이며 새 총량 제한이 아니다.
HP·MP도 기존 정수 버림보다 평균이 증가하므로 숙련도별 자원 증가량을 별도로 비교한다.
성장 분포 검증과 실제 전투 밸런스 검증을 구분해 보고한다.


## 재전직 후 1레벨 스탯: 숙련도 기준 통합안

### 현재 남은 의존과 변경 범위

`statFloorLevels`는 사냥·경험치 비약·목표 레벨 비약에서 실제 상승 레벨을 누적하고
`computeStatFloors`가 시작 스탯을 계산하는 데 사용한다. 이 경로의 누적·계산 의존을 제거한다.
직업 해금 등에 쓰는 `cumLevel` / `jobCumLevel`은 이름과 달리 현재 숙련도 데이터이므로 삭제하지 않는다.
과거 저장값의 숙련도로부터 `statFloorLevels`를 역산하는 파서 경로도 새 방식에서는 사용하지 않는다.

### 기본 스탯 시작값 제안 (미채택: 너무 낮음)

```text
M = 재전직 시점의 해당 스탯 관련 숙련도
시작 스탯 = min(수행 한계, 15 + floor(5 * log2(1 + M / 5000)))
```

| 관련 숙련도 | 해당 스탯의 1레벨 시작값 (한계가 충분한 경우) |
| ---: | ---: |
| 0 | 15 |
| 5천 | 20 |
| 1만 | 22 |
| 10만 | 36 |
| 100만 | 53 |
| 1천만 | 69 |

계수 5는 검토안이다. 기본값은 15이며, 시작값에 별도 난수를 넣지 않아
같은 숙련도라면 같은 시작 스탯을 얻는다. 레벨업 성장의 소수 확률 보정과 구분한다.
정수 시작값은 단계적으로 증가하므로 숙련도 1마다 화면 값이 반드시 오르는 것은 아니다.
숙련도 경력은 모든 직업에서 유지하며 현재 직업만 바꾸어 과거 경력을 잃지 않는다.

### 생애 시작값 고정

재전직 순간에 여섯 시작값을 계산하여 생애 시작 스탯으로 저장한다.
이후 능력치는 `생애 시작 스탯 + 해당 생애 레벨업 성장분`을 수행 한계까지 적용한다.
숙련도가 오를 때마다 시작값을 실시간으로 다시 계산하지 않는다.
이렇게 해야 100레벨 사냥으로 숙련도만 올려도 현재 기본 스탯이 저절로 증가하는 현상을 피할 수 있다.
새 숙련도는 이후 레벨업의 성장 확률과 다음 재전직의 시작값에 반영된다.

### 재전직 시작 HP·MP

현재의 별도 기본 자원 추첨 구조를 유지하는 안이다.
시작 HP는 힘의 새 생애 시작 스탯과 활력 수행 한계,
시작 MP는 정신의 새 생애 시작 스탯과 지능 수행 한계로 기존 기본 자원 범위를 계산한다.
HP 150~180 / MP 65~95를 기준으로 위 입력에 따라 범위를 확장하고 재전직 때 한 번 굴린다.
레벨당 자원 보정 3배를 시작 HP·MP에도 중복해서 적용하지 않는다.
시작 HP·MP 자체를 추가로 상향하는 것은 아직 합의하지 않은 별도 수치 선택이다.

### 기존 캐릭터 전환

새 시작값은 다음 재전직부터 적용한다. 전환 직후 현재 캐릭터의 능력치를 재계산하여 올리거나 내리지 않는다.
기존 생애에 시작 스탯 저장값이 없다면 종전 계산의 시작 스탯을 한 번만 고정 저장하고 기존 성장분과 HP·MP 기록을 보존한다.
그 1회 호환 읽기에만 과거 레벨 기록을 허용한다. 이후 누적하거나 새 시작값 계산에 사용하지 않는다.
기존 저장 필드는 일괄 삭제하지 않으며 새 성장의 권위 있는 입력에서도 제외한다.

### 추가 검증

- 같은 관련 숙련도라면 과거 레벨 기록이 달라도 새 재전직 시작값이 같아야 한다.
- 숙련도·수행 한계가 같으면 재전직 기본 스탯은 결정론적으로 같아야 한다.
- 만렙에서 숙련도만 올라가도 저장된 생애 시작 스탯은 변하지 않아야 한다.
- 다음 재전직에서는 늘어난 숙련도가 반영되어야 한다.
- 호환 전환을 반복해도 시작값·기존 성장·HP·MP를 중복 지급하거나 삭감하지 않아야 한다.
- 1회 호환 계산 이후 사냥 및 비약으로 과거 레벨 기록을 더 이상 누적하지 않아야 한다.

### 기존 시작값 보장 (함께 철회)

계수를 올려도 기존 공통 누적 보너스로 얻었던 비주력 스탯이 낮아질 수 있다.
계수 100에서 전체 701개 중 141개, 현재 100레벨 200개 중 87개는 한 스탯 이상 하락한다.
따라서 기존 캐릭터에 다음 영구 호환 기준을 적용하는 안이다.

```text
전환 시 한 번:
  legacyStartFloor[stat] = 기존 재전직 계산의 한계 적용 전 시작 스탯

다음 재전직부터:
  masteryStart[stat] = 15 + floor(100 * log2(1 + 관련 숙련도 / 5000))
  생애 시작값 = max(legacyStartFloor[stat], masteryStart[stat])
  실제 기본 스탯 = min(생애 시작값 + 생애 성장분, 현재 수행 한계)
```

신규 캐릭터의 보장 기준은 기본 15다. 기존 캐릭터의 보장 기준은 단순 정수 스탯 맵으로
고정 저장하고 재전직·수행 초기화로 지우지 않는다. 관련 숙련도로 계산한 값이 이를 넘으면 새 공식이 자연스럽게 우세해진다.
수행 한계를 스스로 낮추는 경우에는 기존처럼 실제 값이 제한된다. 직업·패시브 보너스와 생애 레벨업 성장분은 보장 기준에 넣지 않는다.
과거 레벨 기록은 이 1회 전환 입력으로만 읽고 이후의 누적 및 새 공식 계산에서 제거한다.
현재 생애는 앞서 명시한 시작 스탯 스냅샷으로 보존한다. 신규 공식으로 현재 스탯을 즉시 갱신하지 않는다.

### 수행 한계 및 HP·MP 영향

계수 100은 현재 100레벨 캐릭터 200명의 1,200개 스탯 중 916개(76.3%)가
재전직 시작부터 현재 수행 한계에 도달하는 결과다. 기존 방식은 211개(17.6%)다.
숙련도가 있어도 한계를 확장하지 않으면 해당 스탯의 추가 레벨업 성장은 막힌다.
이는 실제 측정된 설계 효과이며, 시작 수치를 높이면서 수행 한계 자체를 자동으로 늘리지는 않는다.

HP·MP는 기존에 합의한 레벨당 숙련도 보정 3배를 유지한다.
새 힘·정신 시작값이 기존 기본 자원/성장 범위의 입력이 되므로, 그 간접 증가분도 따로 생긴다.
앞서 제시한 HP·MP 표는 영구 스탯 저점·수행 한계가 기본값인 조건이었고,
새 고숙련 시작 스탯까지 적용한 최종 HP·MP와 같지 않다. 구현 검증 시 두 기여를 함께 계산해 보고한다.

## 시작값 + 99회 성장 기준 재검토안

시작 스탯 자체를 과거 시작값 수준까지 끌어올리는 목표를 폐기한다.
시작값은 초반 전투의 바탕으로 두고 숙련도의 보상 대부분을 레벨업 과정에서 받도록 한다.
사용자의 소폭 상향 요청을 반영해 시작 보정 계수를 20에서 22로 올린다.
레벨업 성장식과 HP·MP 숙련도 보정 3배는 유지한다.

```text
B = log2(1 + 해당 스탯 관련 숙련도 / 5000)
재전직 시작값 제안 = 15 + floor(22 * B)
레벨당 평균 성장 = (1 + B) / 2
99회 평균 성장 = 99 * (1 + B) / 2
100레벨 평균 = 시작값 + 99회 평균 성장
```

숙련도가 해당 생애 내내 일정하고 수행 한계가 충분한 경우의 스탯 하나 기준이다.
실제로 사냥 중 숙련도가 늘면 각 레벨업 시점의 범위로 굴리므로 아래 고정 숙련도 계산과 달라진다.
수행 한계가 부족하면 실제 총량이 낮아지며, 개별 캐릭터의 무작위 결과를 보장하는 표가 아니다.

| 관련 숙련도 | 시작값 제안 | 99회 평균 성장 | 100레벨 평균 |
| ---: | ---: | ---: | ---: |
| 0 | 15 | 49.5 | 64.5 |
| 1천 | 20 | 62.5 | 82.5 |
| 5천 | 37 | 99.0 | 136.0 |
| 1만 | 49 | 128.0 | 177.0 |
| 5만 | 91 | 220.7 | 311.7 |
| 10만 | 111 | 266.9 | 377.9 |
| 50만 | 161 | 379.1 | 540.1 |
| 100만 | 183 | 428.2 | 611.2 |
| 500만 | 234 | 542.9 | 776.9 |
| 1천만 | 256 | 592.3 | 848.3 |

예를 들어 관련 숙련도 100만에서는 시작값 183보다 레벨업 성장분 약 428이 크다.
시작 계수 100안은 같은 숙련도에서 780으로 시작해 평균 약 1,208에 도달하므로,
새 검토안은 1레벨 수치와 최종 수치를 함께 낮춘다.

### 전환 원칙 수정

- 현재 생애의 스탯과 누적 HP·MP는 고정하여 보존한다.
- 다음 재전직부터 합의된 시작 곡선을 적용하는 것을 기본안으로 한다.
- 과거의 높은 시작 스탯을 영구적으로 최솟값에 덧씌우지 않는다. 그러면 높은 시작값과 새 레벨업 성장이 중복된다.
- 기존 운영 집계의 136/381/514는 시작값 분포였고, 위 표는 100레벨 기대 총량이므로 직접 비교하여 기존 전투력이 보존된다고 주장하지 않는다.
- 구현 전 전환 검증은 같은 캐릭터의 현재 기본 스탯(기존 시작값+실제 성장분, 한계 적용)과 새 생애 100레벨 결과를 비교한다.
  하락 사례에 대한 별도 보상이 필요하다면 그 결과를 근거로 정한다. 현재 수치안만으로 전환 후 무하락을 보장하지 않는다.
- HP·MP 숙련도 보정 3배는 유지하되, 시작 스탯이 자원 범위에 주는 간접 영향까지 포함하여 계산한다.

## 시작 계수 22와 HP·MP 보정 3배를 합친 자원 예시 (시작 자원 상향 전 비교 기록)

비교 조건: 힘·활력·정신·지능의 관련 숙련도가 모두 M으로 같고 생애 중 일정하다.
각 시작 스탯 F는 `15 + floor(22 * log2(1 + M / 5000))`다.
활력·지능 수행 한계 C는 시작값을 수용하는 최소값 `max(60, F)`로 고정한다.
이 조건은 자원 성장의 비교 기준이며 기본 스탯을 100레벨까지 충분히 성장시킬 한계를 가정한 것이 아니다.
해당 스탯은 한계에 도달하면 성장이 멈추지만 HP·MP는 별도 자원 굴림을 계속한다.
실제 수행 한계를 더 넓히면 자원 성장 범위도 추가로 증가한다.

기존 자원 버전 2 공식에 시작값을 반영하고, 소수 숙련도 보정 3배를 더한다.
`S=floor((F-15)/10)`, `V=floor((C-60)/10)`, `B=log2(1+M/5000)`일 때:

```text
시작 HP 범위: 150+2S .. 180+2S+2V
시작 MP 범위: 65+S .. 95+S+V
HP 레벨당 평균: 10+S+V/2+4.5B
MP 레벨당 평균: 4+floor(.4S)+floor(.4V)/2+4.5B
100레벨 순수 생애 자원 평균: 시작 범위 평균 + 99 * 레벨당 평균
```

아래 100레벨 값은 순수 생애 자원이다. 힘·활력의 직접 HP 기여, 지능·정신의 별도 MP 기여,
장비·직업·패시브·해방 보정은 포함하지 않으며 화면의 최종 최대 HP·MP와 같다고 해석하지 않는다.

### 설계 해석

앞선 새 자원 예시의 수행 한계 `max(60, 시작 스탯)`은 운영 유저의 실제 수행 한계가 아니다.
따라서 그 예시만으로 신규 시작 HP·MP가 기존 운영 값을 보존한다고 판단하지 않는다.

현행 시작 범위와 신규 시작 범위·기대값을 비교한 뒤 제시한다.
이 절은 현황 확인이며 시작 자원 계수를 새로 확정하거나 게임에 적용한 것이 아니다.

## 시작 HP·MP 상향 제안 — 운영 입력 대조

사용자의 시작 자원 여유 확대 요청을 반영한 검토안이다. 게임 코드·운영 저장값에는 적용하지 않았다.

| 항목 | 현행 기본 범위 | 새 기본 범위 |
| --- | --- | --- |
| 시작 HP | 150~180 | 250~350 |
| 시작 MP | 65~95 | 120~180 |

여기에 시작 스탯 계수 22와 실제 수행 한계의 보정을 더한다.
`S=floor(max(0, 힘 시작값-15)/10)`, `P=floor(max(0, 정신 시작값-15)/10)`,
`V=floor(max(0, 활력 한계-60)/10)`, `I=floor(max(0, 지능 한계-60)/10)`일 때:

```text
시작 HP = uniformInt(250 + 2*S, 350 + 2*S + 2*V)
시작 MP = uniformInt(120 + P, 180 + P + I)
```

생애 시작 시 HP·MP를 독립적으로 한 번씩 굴린다.
레벨당 숙련도 보정 3배와 기본 스탯 성장 곡선은 그대로 두며,
이 상향으로 증가하는 순수 100레벨 자원은 시작 자원의 증가분만큼이다.
동일한 새 시작 스탯·수행 한계에서 종전 기본 범위와 비교하면 기대 HP +135, 기대 MP +70이다.
이는 구형 누적 저점을 쓰는 실제 현행 캐릭터와 비교한 증가분과는 다르다.

운영 701개를 읽기 전용으로 조회해 스탯별 관련 숙련도·새 시작 스탯·실제 수행 한계를 적용했다.
현재 Lv.100 200개에서 각 캐릭터의 새 시작 자원 기대값을 현행 재전직 기대값과 비교하면
HP 감소 0개, MP 감소 0개다. 개별 추첨 결과의 무하락을 보장하는 뜻은 아니다.

| 현재 Lv.100 대상 기대값 분포 | 현행 | 새 제안 |
| --- | ---: | ---: |
| HP 중앙값 | 187 | 323 |
| HP 90백분위 | 255 | 360 |
| HP 최대 | 298 | 381 |
| MP 중앙값 | 86 | 156.5 |
| MP 90백분위 | 102.5 | 167.5 |
| MP 최대 | 167.5 | 206.5 |

익명 실제 입력 대조:

| 사례의 직군 숙련도 합계 | 현행 HP → 제안 HP | 현행 MP → 제안 MP |
| ---: | --- | --- |
| 759,828 | 238~358 → 280~470 | 86~116 → 130~190 |
| 578,940 | 244~352 → 282~460 | 81~125 → 130~204 |
| 648,364 | 202~232 → 274~374 | 112~223 → 136~277 |

전체 701개에서는 앞서 확인한 현재 Lv.1의 높은 저점 저장값 1개가 예외다.
그 계정의 HP 기대값은 1,143→936, MP 기대값은 474→466으로 감소한다.
기존 생애의 저장된 시작 자원 1,272/578은 수정하지 않는다.
다음 재전직의 기대값 차이는 구현 전 전환 검증 대상이며 전체 계정 무하락으로 보고하지 않는다.
일반 계정인지 특수 계정인지는 이번 익명 집계로 판정하지 않았다.
