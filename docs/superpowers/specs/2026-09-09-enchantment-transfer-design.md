# 마법부여 전체 이전

사용자가 합의한 로컬 구현 범위. 배포·푸시·PR은 포함하지 않는다.

- 원본 장비를 소모하지 않고 귀속을 유지하며 마법부여만 제거한다.
- 같은 부위의 다른 보유 장비로 단계·줄 수·옵션 종류·레벨을 모두 이전한다. 성공률 100%.
- 양쪽 모두 기존 마법부여 자격(표시 6T 이상, 폭풍 개량 제외)을 만족해야 한다.
- 대상은 귀속된다. 기존 마법부여는 전체 덮어쓴다. 강화·굴림·제작 정보·잠금·장착 상태는 보존한다.
- 원본의 표시 단계 1/2/3별 기본 비용은 15,000,000 / 30,000,000 / 50,000,000 G.
- 원본 옵션 줄 수 1/2/3별 배율은 1 / 1.5 / 2. 따라서 최대 비용은 100,000,000 G.
- 기존 결제 규칙대로 소지 골드부터 사용하고 부족분을 은행에서 차감한다. 재료나 할인은 없다.
- 대장간 마법부여 화면에서 선택한 원본의 이전 버튼으로 진입한다. 같은 부위의 후보만 표시한다.
- 확인창에는 원본→대상, 이전할 단계·줄 수·옵션과 레벨, 기본 비용과 추가 비용 및 총액, 원본 보존/마법부여 제거, 대상 귀속/기존 옵션 영구 소멸을 표시한다.
- 취소에 초기 포커스를 주고, 실행 버튼에 총 비용을 쓴다. 실행 중 선택·확인·취소는 잠근다.
- 서버가 소유·자격·부위·원본 옵션·양쪽 변경 번호·잔액을 다시 검증하고 캐릭터→장비 순서로 잠가 골드와 양쪽 장비, 요청 영수증을 같은 트랜잭션에서 저장한다.
- UUID 재시도는 같은 결과를 반환한다. 같은 UUID의 다른 작업은 거절한다. 서버 오류/응답 유실 시 UUID를 보존한다.
- 마법부여가 없어져도 단조 증가하는 liberationRevision을 보존한다. 기존 저장은 liberation.revision을 기준으로 호환한다. 기존 마법부여 API와 UI도 같은 번호를 사용한다.
- stale 응답은 최신 두 장비를 전달하며 확인창을 닫아 새 내용으로 다시 확인하도록 한다.
- UI 표면은 SURFACE_CARD/INSET/ACCENT를 사용하고 작은 화면에서도 확인창 스크롤을 허용한다.

## 검증
비용 9종, 원본 보존/대상 덮어쓰기/소유/부위/자격/잔액/양쪽 stale/삭제 후 재부여 번호 보존을 단위 테스트한다. API 인증·입력·중복·충돌·동시 요청·롤백을 기존 트랜잭션 테스트 방식으로 확인한다. UI 확인 전 무요청·취소 포커스·옵션과 비용 표시·성공 반영·연결 재시도·stale 재확인을 검사한다. 관련 기존 테스트, 타입 검사, 변경 파일 린트 및 diff 검사를 실행한다.
