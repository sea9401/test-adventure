# 완료 우편 일괄 삭제

건의 #694: 읽고 수령·처리를 마친 받은 우편을 한 번에 정리한다.

- 받은 우편 탭에 `완료 우편 일괄 삭제` 버튼을 제공하고 기존 게임 확인창으로 삭제 범위를 안내한다.
- 서버가 로그인한 수신자의 `readAt != null`, `claimedAt != null`, `recipientDeletedAt == null`인 우편만 처리한다. 보상 없는 쪽지는 기존 읽음 처리에서 완료된다.
- 기존 개별 삭제처럼 `recipientDeletedAt`만 기록해 수신자에게 숨긴다. 발신자의 보낸 우편 및 보상·감사 기록을 유지한다.
- 목록에 표시되는 최근 완료 100개에 한정하지 않고 조건에 맞는 전체 우편을 단일 UPDATE로 처리한다. 목록에 삭제 대상이 없어도 오래된 대상이 있을 수 있으므로 버튼을 제공한다.
- 미확인, 미수령, 미응답 초대, 다른 사람의 받은 우편, 이미 삭제한 우편을 제외한다. 반복 요청은 새 삭제 0건으로 성공한다.
- 응답의 삭제 ID로 화면과 열린 상세를 갱신하고 목록을 재조회해 이전에 표시되지 않았던 보존 우편을 불러온다. 결과 건수 또는 대상 없음 안내를 표시한다. 실패하면 현재 목록을 유지한다.
- 일괄 삭제 요청/확인 중에는 중복 실행과 수령·개별 삭제를 막는다. 보낸 우편 탭에는 버튼을 노출하지 않는다.

화면의 ID를 개별 삭제 API로 반복 전송하는 방법은 최근 100개 제한과 부분 실패 때문에 제외한다. 전용 POST API를 추가해 서버 조건을 원자적으로 적용한다. 스키마 변경, 개별 삭제 정책 변경, 배포는 범위 밖이다.

검증: 실제 Drizzle UPDATE의 수신자·읽음·수령·미삭제 조건 및 반환값, 인증 거부와 0건, 클라이언트 오류, UI 확인 취소/성공/실패/중복 실행/탭 노출을 회귀 테스트한다.
