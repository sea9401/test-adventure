# 전투 리플레이 정리 처리량 개선

## 운영 조사

2026-09-29 KST 운영 점검에서 EC2의 과거 스테이징 덤프와 업로드 사본을
별도 로컬 보관소로 옮겼다. 1,421개 파일을 원본 SHA-256과 검증하고 사용 중인
프로세스·서비스 설정의 참조가 없음을 확인한 뒤 서버 사본을 제거했다.
디스크 사용률은 89%에서 73%, 여유 공간은 2.3GiB에서 5.6GiB로 개선됐다.
최신 운영 백업은 S3 객체와 크기가 일치하며 서버에도 유지했다.
자동 백업의 기존 S3 확인 후 정리 정책, nginx 및 journal 보관 정책은 유지한다.

RDS 조사에서는 `work_mem=4MiB`, `shared_buffers≈413MiB`, 연결 7~11개로
과도한 메모리 설정이나 연결 폭증을 확인하지 못했다. 전투 리플레이 테이블은
약 4.02GB이고, 02:28 KST에 만료된 행이 300,659개 남아 있었다.
77초 통계 차분에서 리플레이 2,170개가 삽입됐다(약 1,691개/분).
현재 cron은 분당 한 번 1,000개까지만 삭제하므로 이 유입량을 따라가지 못한다.
이것은 확인된 보존 작업의 처리량 문제이며, RDS 메모리 경고의 유일한 원인으로
확정한 것은 아니다. 운영 DB 로그 조회 권한과 Enhanced Monitoring은 없었다.
이미 로드된 pg_stat_statements 조회용 확장은 트랜잭션 안에서 생성·조회 후
ROLLBACK했고, 영구 확장이나 설정 변경은 남기지 않았다.

## 선택

- 단일 SQL 배치 크기 확대는 한 트랜잭션의 쓰기량과 잠금 시간을 늘린다.
- cron 중복 실행은 실행 주기와 동시성 관리가 복잡해진다.
- 기존 1,000건 배치를 순차 반복하는 방식으로 트랜잭션 크기를 유지한다.

분당 한 번 실행하는 기존 route가 최대 6배치(6,000건)를 순차 처리한다.
첫 배치 후 부분 배치·빈 배치·잠금 획득 실패가 나오면 즉시 중단한다.
추가 배치를 시작하기 전 경과 시간이 5초 이상이면 중단한다. 이 예산은
실행 중 SQL을 취소하는 제한이 아니며 기존 DB 쿼리 타임아웃은 유지된다.
한 실행의 만료 기준 시각은 고정하고 기존 만료 인덱스, ctid 삭제,
트랜잭션 advisory lock을 그대로 사용한다. 배치 간 잠금은 해제된다.
삭제 합계, 배치 크기, 남은 작업 여부와 잠금 건너뜀 여부를 응답한다.
잠금을 못 얻으면 남은 작업 여부는 보수적으로 true로 보고한다.
오류는 성공으로 숨기지 않고 기존 호출자에게 전파한다.

## 범위와 검증

알림 임계값·중복 억제, 보존 기간, RDS 사양·파라미터는 변경하지 않는다.
운영 DB의 추가 수동 삭제나 배포는 이 로컬 수정에 포함하지 않는다.
기존 SQL 테스트와 추가 배치·상한·시간 예산·잠금·오류 회귀 테스트,
인증된 route 연결 테스트, TypeScript 및 대상 ESLint로 검증한다.
운영 적용 후 만료 적체 감소와 메모리·스왑·응답 지연을 함께 확인해야 하며,
DELETE만으로 테이블 파일 크기가 즉시 줄어드는 것은 아니다.
