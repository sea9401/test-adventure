# 길드 시설 Lv.6~10 확장 (1차) 설계

- 작성일: 2026-10-10
- 범위: 1차 — 공통 틀 + 훈련장·탐사 본부·길드 식당·연금 공방·길드 교역소
- 2차(별도 스펙): 제작소·길드 창고 Lv.6~10

## 1. 배경과 목표

모든 길드 시설은 Lv.5가 최대다. 2026-10-10 운영 DB 읽기 전용 조회 결과:

- 활성 길드 33개 중 6개가 7개 시설을 모두 Lv.5로 마쳤다(시설 레벨 합 35). 그 뒤로 시설 쪽에 성장 목표가 없다.
- 상위 길드 금고는 36억~149억 G로, Lv.5 골드 비용(1.6억~1.9억 G)과 비교하면 사실상 제약이 아니다.
- 상위 길드 길드원들이 가진 최상위 재료(편백나무·아다만타이트)는 길드당 2만~8만 개다. Lv.5 요구량은 500개다.
- 최근 약 1주 상위 길드 시설 이용량: 훈련 130~190회, 원정 귀환 8~13회, 탐사 주간 의뢰 6회, 식사 20~60회, 연성 7~70회, 교역 납품 10~20회, 계약 완료 5회. 활동 로그는 길드당 500행만 남아 14일 조회가 실제로는 약 1주치다.

목표:

1. Lv.5를 마친 길드에 장기 성장 목표를 준다. 활발한 상위 길드 기준으로 시설 하나가 Lv.5→10에 **3달 이상** 걸려야 한다. 5종을 병행하면 각 시설이 약 3.5달에 걸쳐 오른다.
2. 레벨마다 수치만 오르지 않고 새 기능(훈련·원정·메뉴·레시피·교환 품목)이 하나씩 열린다.
3. 쌓여 있는 금고 골드와 생활 재료를 실제로 소모시킨다.

하지 않는 것:

- 제작소·길드 창고의 Lv.6~10 (2차).
- 모험가 협회 공공시설 확장. 협회는 계속 Lv.5가 최대다.
- 새로운 식당 효과 종류(골드·드롭률 등). 이미 연결된 `hunt_exp`·`life_xp`·`all_xp`·`recovery`만 쓴다.

## 2. 공통 틀

### 2.1 시설별 최대 레벨

`MAX_SETTLEMENT_BUILDING_LEVEL = 5` 단일 상수를 시설과 운영 주체에 따라 달라지는 최대 레벨로 바꾼다.

- `settlementBuildingMaxLevel(buildingId, scope: "guild" | "association")`
  - guild + 1차 5종 → 10
  - guild + 제작소·창고·지도 제작소 → 5
  - association → 항상 5
- `clampSettlementBuildingLevel`은 저장값 정규화용이라 상한을 10으로 넓힌다. 시설별 상한은 위 함수가 판정한다.
- 각 시설의 `next…Upgrade(level)`는 표에 다음 행이 있는지로 판정하므로, 1차 5종 표에만 Lv.6~10 행을 추가한다. 협회 쪽 `nextAssociationFacilityUpgrade`는 최대 레벨 함수로 Lv.5에서 `null`을 돌려준다.
- `src/lib/server/adventurerAssociation.ts`에 직접 박힌 `Math.min(5, …)`는 최대 레벨 함수 호출로 바꾼다. 협회 테이블의 DB CHECK(1~5)는 그대로 둔다.
- 화면의 "최대 레벨" 판정도 모두 같은 함수를 쓴다.

### 2.2 Lv.6~10 업그레이드 조건

세 가지를 모두 채워야 관리자가 업그레이드를 완료할 수 있다.

1. **재료 기부**: 기존 `guild_facility_upgrade_donations` 흐름을 그대로 쓴다.
2. **금고 골드와 사용 가능 명성**: 기존처럼 완료할 때 차감한다.
3. **운영 실적** (신규, 2.3절).

1차 5종이 같은 비용 표를 쓴다(Lv.1~5에서 공통 재료 구성을 쓰던 방식과 같다).

| 목표 | 재료 | 골드 | 명성 | 운영 실적 |
|---|---|---|---|---|
| Lv.6 | 참나무·금 각 3,000 · 삼나무·미스릴 각 2,500 · 편백나무·아다만타이트 각 2,000 | 4억 | 4,000 | 200 |
| Lv.7 | 참나무·금 각 3,500 · 삼나무·미스릴 각 3,500 · 편백나무·아다만타이트 각 3,000 | 6억 | 5,500 | 250 |
| Lv.8 | 참나무·금 각 3,000 · 삼나무·미스릴 각 4,500 · 편백나무·아다만타이트 각 4,500 | 8억 | 7,000 | 300 |
| Lv.9 | 삼나무·미스릴 각 6,000 · 편백나무·아다만타이트 각 6,000 | 10억 | 8,500 | 350 |
| Lv.10 | 삼나무·미스릴 각 7,500 · 편백나무·아다만타이트 각 7,500 | 12억 | 10,000 | 400 |

시설 하나의 합계는 골드 40억, 명성 35,000, 편백나무·아다만타이트 각 23,000, 운영 실적 1,500이다. 5종 합계는 골드 200억, 명성 175,000, 편백나무·아다만타이트 각 115,000이다.

### 2.3 운영 실적

- 길드원이 그 시설을 실제로 이용하는 행동이 서버에서 성공할 때만, 같은 트랜잭션 안에서 행위자가 속한 길드의 해당 시설에 적립한다.
- 적립 조건: 시설 레벨이 5 이상이고 최대 레벨보다 낮을 것. 협회 이용과 길드가 없는 플레이어는 적립하지 않는다.
- 시설마다 **주간 적립 상한 100점**. 주차는 월요일 00:00 KST 기준이다(기존 `todayGuildTrainingWeekKey`와 같은 규칙).
- 누적 점수가 현재 목표(다음 레벨 요구 실적)에 닿으면 더 쌓이지 않는다. 초과분은 이월하지 않는다.
- 업그레이드를 완료하면 누적 점수를 0으로 되돌리고 다음 목표로 넘어간다. 주간 적립량은 유지한다(같은 주에 다시 상한까지 쌓이지 않도록).

적립 규칙:

| 시설 | 행동 | 점수 |
|---|---|---|
| 훈련장 | 훈련 1회 완료 | 1 |
| 탐사 본부 | 원정 귀환 보상 수령 | 8 |
| 탐사 본부 | 주간 의뢰 보상 수령 | 3 |
| 탐사 본부 | 사건 선택 완료 | 2 |
| 길드 식당 | 식사 1회(식권 사용) | 2 |
| 길드 식당 | 식재료 기부 | 공동 준비 점수 10점당 1점(내림) |
| 연금 공방 | 연성 | 사용한 연성력 1당 1점 |
| 길드 교역소 | 계약 납품 | 납품 점수 10점당 1점(내림) |
| 길드 교역소 | 계약 완료 | 10 |

계약 완료 점수는 완료를 일으킨 납품 한 번에 붙는다. 위 이용량이면 활발한 길드는 5종 모두 주 100점에 닿는다. 그 경우 Lv.5→10은 15주가 걸린다.

### 2.4 저장

새 테이블 `guild_facility_operations`:

| 컬럼 | 타입 | 설명 |
|---|---|---|
| guild_id | integer FK guilds (cascade) | |
| building_id | text | |
| target_level | integer | 이 점수가 향하는 목표 레벨 |
| points | integer | 목표를 향한 누적 점수 |
| week_key | text | 마지막 적립 주차 |
| week_points | integer | 해당 주 적립량 |
| updated_at | timestamp | |

PK는 `(guild_id, building_id)`이다. 행은 첫 적립 때 만든다. 적립과 업그레이드 완료는 행을 `FOR UPDATE`로 잠근다. `target_level`이 실제 다음 레벨과 다르면(레거시·경합) 점수를 0으로 보고 새 목표로 맞춘다.

서버 헬퍼(`src/lib/server/guildFacilityOperations.ts`):

- `accrueGuildFacilityOperations(tx, { guildId, buildingId, points, now })` → 실제 적립량(상한·목표 반영)
- `readGuildFacilityOperations(executor, guildId)` → 시설별 `{ targetLevel, points, required, weekPoints, weeklyCap }`
- 순수 계산(`src/adventure/data/v2/guildFacilityOperations.ts`): 적립량 계산, 주차 리셋, 목표 도달 판정. 테스트는 여기에 집중한다.

### 2.5 업그레이드 API와 화면

- `POST /api/v2/guild/facilities/[buildingId]/upgrade`: 목표 레벨이 6 이상이면 운영 실적 충족을 추가로 확인한다. 부족하면 `409 { error: "operations_incomplete" }`. 완료 트랜잭션에서 실적 행을 다음 목표로 초기화한다.
- `donate`: 최대 레벨 판정을 2.1절 함수로 바꾼다. 나머지 흐름은 그대로다.
- 길드 정보·시설 목록 API 응답에 시설별 운영 실적을 추가한다.
- 시설 업그레이드 카드(`GuildFacilityUpgradeFund` 주변)에 세 번째 진행 표시를 추가한다: "운영 실적 120/200 · 이번 주 +64/100". 목표 레벨이 6 미만이면 숨긴다.
- 각 시설 패널의 레벨 표기와 "다음 레벨에서 열림" 안내가 Lv.10까지 이어지도록 한다.
- UI 규칙은 AGENTS.md "UI 표면과 가독성"과 `surfaces.ts`를 따른다.

## 4. 위험과 보정

### 4.1 경제

- 강화석(공방·교역소)은 지금 드롭으로만 나와 거래소 시세가 정해진다. 수량을 낮게 잡았지만, 출시 후 2주간 거래소 시세와 강화 시도 수를 관리자 밸런스 탭으로 지켜본다.
- 식당의 사냥 EXP 상단이 +60%에서 +90%로 오른다. 라이브 EXP 배율과 겹치므로 레벨 상승 속도를 지켜본다.

### 4.2 계획 단계에서 보정할 값

- 훈련장 기본 숙련(34/40/50)과 보너스율: 상위 플레이어의 하루 숙련 획득량과 비교한다(운영 DB 읽기 전용 조회).
- 교역 토큰 가격: 상위 길드의 주간 토큰 획득량과 비교한다.
- 운영 실적 적립 규칙: 위 이용량으로 상위 길드 5종 모두 주 100점에 닿는지 다시 확인한다.

### 4.3 동시 작업 충돌

같은 저장소에서 미푸시 브랜치 두 개가 길드 시설 부근을 바꾸고 있다: 길드 이동 시설 이어쓰기(`fix/guild-facility-transfer-on-move`), 토벌전 보스 선택(`feat/guild-raid-boss-selection`). 구현은 `origin/main` 기준 별도 워크트리(`/tmp/guild-facility-lv10`)에서 하고, 통합 때 충돌을 정리한다.

## 5. 테스트

- 순수 데이터 테스트: 최대 레벨 함수(guild/association), Lv.6~10 비용 표, 운영 실적 적립(주간 상한, 목표 도달, 주차 리셋, Lv.5 미만·최대 레벨 미적립), 새 훈련·메뉴·레시피·교환 품목의 해금 레벨.
- 탐사: 단일→배열 상태 파서 호환, Lv.8 동시 파견 2개 제한, 같은 원정 중복 금지, Lv.10 시간 −10%, 사건 순환 목록.
- 식당: Lv.8 지속 시간 배율, 협회 식당은 Lv.5 메뉴만.
- 라우트 테스트: 업그레이드 `operations_incomplete`, 각 시설 행동이 실적을 적립하는지, 협회 이용은 적립하지 않는지, 길드원 전원 지급.
- 협회 회귀: 협회 시설이 Lv.5에서 더 오르지 않는다.
- 마이그레이션: 새 테이블 생성, 기존 데이터 무변경.
- 화면: 운영 실적 막대, Lv.6~10 표기. 라이트·다크 모드에서 배경 비침이 없는지 확인한다.
