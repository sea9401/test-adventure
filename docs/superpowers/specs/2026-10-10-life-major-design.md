# 생활 전공과 명장 단계 (생활 Lv.100 이후 성장)

## 배경과 목표

생활 확장 3부작 중 ③이다(① 생활 축제, ② 숙소 공개). 생활 다섯 축(농사·벌목·채광·낚시·요리)은 Lv.100에서 멈추고, 그 뒤 경험치는 버려진다. 다 키우면 생활 숙련 500이 되는 구조라 특정 생활에 집중할 이유가 없다.

오너의 방향(2026-08-24 커뮤니티 대화): "저 중 하나만 특화되게 하는 것이 목표." 건의 #719(2026-09-24): 생산직이 전문화되어 생산 전문으로도 플레이할 수 있기를 원함.

목표:

- Lv.100 이후에는 **고른 생활만** 더 깊게 성장한다.
- 전공자만 얻는 **명장 산물**로 생산 전문 역할과 거래를 만든다.
- 명장 산물의 최종 쓰임 일부를 **전투 성장 소모품**으로 연결해 비생활 유저의 수요를 만든다.
- 이미 다섯 생활을 모두 Lv.100으로 키운 이용자에게 불이익을 주지 않는다.

## 결정 사항(오너 확인)

- 전공은 **주전공 1 + 부전공 1**. 고르지 않은 생활에는 불이익이 없다.
- 보상은 **효율 + 전공자 전용 산물**.
- 산물 연결은 **생활 공급망 + 전투 소모품**.
- 출시는 **1차·2차로 나눈다**. 이 명세는 둘을 모두 정의하고, 구현 계획은 1차부터 쓴다.

## 용어

- **전공 대상 생활**: `farming`, `woodcutting`, `mining`, `fishing`, `cooking`. 대장 숙련은 별도 체계라 제외한다.
- **주전공 / 부전공**: 이용자가 지정한 생활. 같은 생활을 둘 다로 지정할 수 없다. 부전공 없이 주전공만 두는 것은 허용한다.
- **명장 경험치 / 명장 단계**: 전공 생활에서 Lv.100 상한을 넘겨 버려지던 경험치를 받아 쌓는 값과, 그 값으로 정해지는 1~10단계.
- **명장 산물**: 전공자만 얻는 재료 4종. 1차에 추가한다.
- **명장 제작품**: 명장 산물로 만드는 명장 요리와 단련 촉매. 2차에 추가한다.

# 1차

## 1. 전공 지정

- Lv.100인 전공 대상 생활만 주전공·부전공으로 지정할 수 있다.
- 처음 지정(주전공·부전공을 처음 채우는 것)은 무료이고 제한이 없다. 주전공만 지정한 뒤 나중에 부전공을 처음 채우는 것도 무료다.
- 이미 지정된 전공을 다른 생활로 바꾸거나 해제하는 것을 **변경**이라 한다. 변경은 마지막 변경 후 **30일**이 지나야 할 수 있다(주전공·부전공 공통 쿨다운 1개).
- 주전공과 부전공을 서로 맞바꾸는 것도 변경으로 친다.
- 명장 경험치는 **생활별로 보존**한다. 전공에서 빠져도 사라지지 않지만, 전공이 아닐 때는 오르지 않고 효과도 붙지 않는다.

## 2. 명장 경험치와 단계

### 경험치 적립

- `applyLifeXpGain`의 결과에 `overflowXp = safeGain - appliedXp`를 추가한다. 이 값은 Lv.100 상한 때문에 반영되지 못한 경험치다.
- 해당 생활이 주전공 또는 부전공이면 `overflowXp` 전부를 그 생활의 명장 경험치에 더한다. 부전공도 적립률은 같고, 효과만 절반이다.
- 전공이 아니면 지금처럼 버린다. 지정 이전에 버려진 경험치는 소급하지 않는다.
- 축제 테마 보너스, 길드 식당, 현장 환경 같은 기존 경험치 보너스가 더해진 최종 획득량을 기준으로 한다.
- 경험치를 더하는 곳(농사 수확, 벌목·채광 수동·자동, 낚시 챔질, 요리 조리)은 모두 `applyLifeXpGain` 또는 그 래퍼를 지나므로, 각 경로에서 `overflowXp`를 서버까지 전달해 명장 세이브에 적립한다.

### 단계 곡선

- 생활별 Lv.100 누적 경험치를 `T100`이라 한다(`extendedLifeXpThreshold(100, legacy)`).
- 단계 k(1~10)의 누적 요구치: `M(k) = round(T100 × k × (k + 1) / 110)`. 10단계 누적은 `T100`과 같다(Lv.1→100 전체와 같은 양).
- 단계 k→k+1에 필요한 양은 단계가 오를수록 커진다. 10단계에서 적립은 멈춘다(넘친 양 버림).

## 3. 효율 보너스

생활별 주력 수치에 다음을 더한다. 기존 레벨 보너스·축제 보너스와 같은 합산 지점에 넣는다.

| 생활 | 대상 수치 | 주전공 | 부전공 |
|---|---|---|---|
| 농사 | 수확량 보너스 % | +1%/단계 | +0.5%/단계 |
| 벌목 | 추가 원목 확률 %p | +1%p/단계 | +0.5%p/단계 |
| 채광 | 추가 광석 확률 %p | +1%p/단계 | +0.5%p/단계 |
| 낚시 | 특수 어종 가중치 %p | +1%p/단계 | +0.5%p/단계 |
| 요리 | 걸작 확률 %p | +1%p/단계 | +0.5%p/단계 |

- 벌목·채광의 확률 보너스는 기존처럼 작업 시작(수동 세션·자동 채집 시작) 때 고정한다.

## 4. 명장 산물

### 4.1 산물 4종

| ID | 이름 | 얻는 생활 | 얻는 순간 |
|---|---|---|---|
| `v2_master_crop` | 명장 작물 | 농사 | 수확 1회 |
| `v2_master_catch` | 명장 어획 | 낚시 | 챔질 성공 1회 |
| `v2_master_wood` | 명장 목재 | 벌목 | 벌목 성공 1회(수동·자동 성공마다) |
| `v2_master_alloy` | 명장 합금 | 채광 | 채광 성공 1회(수동·자동 성공마다) |

- 요리 전공은 산물을 얻지 않고 2차의 명장 요리를 만든다.
- 획득 확률: 주전공 `0.5% + 0.15% × 단계`(10단계 2%), 부전공은 그 절반. 단계 0(지정 직후)도 기본 0.5%(부전공 0.25%)를 적용한다.
- 자동 채집 정산은 성공 횟수만큼 독립적으로 굴린다. 한 번에 정산하는 성공 횟수가 많아도 기대값이 같도록 한다.
- 산물은 캐릭터 세이브 `materials`에 들어가고, `V2_MATERIALS` 카탈로그에 등록해 인벤토리 재료 탭과 거래소 거래가 되게 한다. NPC 판매는 등록하지 않는다(유저 거래 전용).
- 1차에서 산물의 쓰임은 2차 제작 재료(예고)와 거래뿐이다. 1차 출시 공지에 "명장 요리·단련 촉매 재료"라고 쓰고 2차를 기다리게 한다. 1차와 2차 사이 간격이 길어지지 않게 한다.
- 표시: 가공재 같은 기존 재료처럼 이름과 공용 재료 아이콘으로 표시하고 새 그림 파일을 요구하지 않는다.

## 5. 저장 구조

개인 세이브 `life-major.v1`:

```ts
type LifeMajorActivity = "farming" | "woodcutting" | "mining" | "fishing" | "cooking";
type LifeMajorState = {
  version: 1;
  major: LifeMajorActivity | null;
  minor: LifeMajorActivity | null;
  lastChangedAt: number | null;   // 마지막 "변경" 시각(ms). 처음 지정은 갱신하지 않는다.
  masteryXp: Partial<Record<LifeMajorActivity, number>>;
  masterProductsEarned: Partial<Record<LifeMajorActivity, number>>; // 통계
};
```

- 순수 규칙 모듈이 단계 계산, 효율 보너스, 산물 확률, 지정·변경 검증을 맡는다.
- 활동 라우트는 생활 활동 사용자 행 잠금 뒤 `life-major.v1`을 잠그고, 적립·산물 지급을 같은 트랜잭션에서 한다. 이 세이브는 활동 라우트의 기존 세이브 잠금들 **뒤에** 잠근다. 축제 세이브와 함께 잠그는 경로는 없다.

## 6. API

- `GET /api/v2/life-major` → `{ major, minor, nextChangeAt, activities: { id, level, eligible, masteryXp, stage, stageXpInto, stageXpForNext, effectText, productChancePct }[] }`
- `POST /api/v2/life-major { major, minor }` → 검증 후 저장. 거절 코드: `not_level_100`, `same_activity`, `change_cooldown`, `invalid_activity`.
- 활동 응답(수확·벌목·채광·낚시·요리)에 `masteryXpGained`, `masterProduct`(얻은 경우 `{ materialId, name }`)를 더한다.

## 7. 화면

- 생활 기록 화면(`/character/life`)에 "생활 전공" 카드를 추가한다.
  - Lv.100 생활이 없으면: 잠금 안내(어느 생활이 몇 레벨인지).
  - 있으면: 주전공·부전공 선택(Lv.100 생활만 선택 가능), 각 생활의 명장 단계와 진행 막대, 효과 한 줄, 산물 확률, 다음 변경 가능 시각.
  - 변경은 확인 창으로 쿨다운을 알린 뒤 진행한다.
- 각 활동 화면의 축제 표시 근처에 전공일 때만 "주전공 · 명장 N단계" 한 줄을 붙인다. 명장 산물을 얻으면 결과 메시지에 표시한다.
- 표면 토큰·공용 부품 규칙(`anti-slop-ui`)을 따른다.
- 매뉴얼 생활 섹션에 "생활 전공과 명장 단계"를 추가한다. 수치는 상수에서 읽는다.

## 8. 1차 테스트

- 순수 규칙: 단계 곡선(M(10)=T100, 단조 증가), 효율·산물 확률(주/부/비전공), 지정·변경·쿨다운·맞바꿈 판정, 세이브 파싱.
- `applyLifeXpGain`의 `overflowXp`: 상한 아래, 상한을 걸쳐 넘는 경우, 이미 상한인 경우.
- 활동 경로별: 전공이면 넘친 경험치가 명장 경험치로 쌓이고 비전공이면 쌓이지 않음, 효율 보너스 합산, 산물 확률 판정과 `materials` 지급. 기존 라우트 테스트는 축제 때와 같이 전공 보너스를 모킹해 시각·세이브와 분리한다.
- API: 지정 성공, Lv.100 미만 거절, 쿨다운 거절, 처음 부전공 채우기 무료.
- 화면: 잠금 상태, 선택 가능 목록, 쿨다운 표시, 표면 토큰.

# 2차

## 9. 명장 요리

- 요리 품질에 `signature`(명장)를 추가한다. 성능 +35(걸작 +20보다 높음), 배달 점수 배율 200, 버프 지속시간 2배.
- 만들기: 요리 주전공 **3단계 이상**만 할 수 있다. 보유한 **걸작 요리 1개 + 명장 작물 1개 또는 명장 어획 1개**를 써서 같은 레시피의 명장 요리 1개를 만든다. 레시피 분야가 `seafood`면 명장 어획, 그 밖(`hearth`·`pot`·`baking`·`medicinal`)이면 명장 작물을 쓴다.
- 요리 ID 형식과 품질을 다루는 모든 곳(파서, 이름, 배달 점수, 거래소 표시, 축제 요리 요건의 품질 순서)에 `signature`를 반영한다. 축제의 "걸작 이상" 요건은 명장 요리도 충족한다.

## 10. 단련 촉매

- 채광 주전공 **3단계 이상**만 만든다: 명장 합금 2 + 명장 목재 1 → 단련 촉매 1. `V2_MATERIALS`에 등록해 거래 가능하게 한다.
- 강화 화면에 "단련 촉매 사용" 선택을 둔다. 사용하면 시도 1회에 1개를 쓰고, 결과표에서 **하락 −10%p를 유지로 옮긴다**(하락이 10 미만이면 있는 만큼). 강화석(붉은·푸른) 선택과 함께 쓸 수 있고, 강화석 변환 뒤에 적용한다.
- 하락이 0인 구간(+0~+4, +10 체크포인트)에서는 사용할 수 없다.

## 11. 2차 테스트

- 명장 요리: 주전공 단계 조건, 재료 차감, 성능·지속시간·배달 점수, 축제 품질 요건.
- 단련 촉매: 제작 조건·재료, 결과표 변환(각 강화석 조합), 하락 0 구간 거절, 시도당 1개 소모.

## 범위 밖

- 생산직 직업 계보와 생활 작업장 Lv.15 전문화는 바꾸지 않는다.
- 대장 숙련, 숙소(②), 새 작물·어종·광맥.
- 운영 배포, 운영 데이터 수정, 새 이미지 발주.
