# 요리 특화

## 배경

요리는 상위 콘텐츠가 있지만 도달하는 길이 막혀 있고, 그 앞 단계의 성장은 이미 상한에 닿았다. 2026-11-13 운영 데이터(최근 7일 접속 276명, 요리해 본 사람 150명) 기준이다.

- 레시피 500종 중 서버 전체에서 발견된 것은 321종이다. 3~5티어 174종 중 145종은 아무도 찾지 못했고, 최근 30일의 최초 발견은 12건이다.
- 보유 음식 37,834개 중 35,195개(93%)가 1티어다. 음식 효과를 켠 22명 중 14명이 사냥 골드 +4~5% 음식을 쓴다.
- 전문 분야를 고른 49명 중 37명이 최고 랭크 5다. 랭크 5는 전문 숙련 1,500이면 닿는데, 이 37명의 누적 숙련은 중앙값 7,210, 상위 10%가 19,870이다. 요리 개편(2026-08-22) 뒤 12주 동안 주당 중앙값 약 600, 상위 10% 약 1,650씩 쌓은 셈이다.
- 일반 작물 약 40만 개, 목장 산물 약 14만 개가 쌓여 있다.

오너 결정(2026-11-13): 기존 전문 랭크를 늘리는 대신, 전문 분야 안에서 제빵·제과처럼 더 좁은 특화를 고르게 한다. 특화마다 전용 요리 3종을 새로 넣고 그 계열 음식 제작에 보너스를 준다. 특화는 14일에 한 번 바꿀 수 있다. 그림은 기존 요리 그림과 같은 화풍으로 새로 만든다.

## 목표

- 전문 랭크 5에 닿은 요리사에게 몇 달짜리 성장 목표를 준다.
- 연구 없이 만들 수 있는 3~5티어 수준의 음식을 열어, 전투에 의미 있는 음식이 거래소에 돌게 한다.
- 전용 요리가 쌓인 작물·목장 산물·어획물을 계속 쓰게 한다.

힌트 없는 연구 구조와 기존 레시피 500종은 건드리지 않는다.

## 2. 선택과 변경

- 전문 분야 랭크 5(전문 숙련 1,500 이상)가 되면 자기 전문 분야에 속한 특화 중 하나를 고를 수 있다.
- 처음 고를 때는 대기가 없다. 특화를 바꾸면 그때부터 14일 동안 다시 바꿀 수 없다.
- 특화 숙련은 특화별로 따로 쌓이고 바꿔도 남는다. 다시 돌아오면 이어서 쌓는다.
- 제작 보너스와 전용 요리 제작은 지금 고른 특화에만 적용된다.

## 3. 숙련과 랭크

- 지금 고른 특화에 속한 음식을 만들면 1개당 `티어 × 10`의 특화 숙련을 얻는다. 기존 전문 숙련과 같은 식이고, 전문 숙련도 그대로 함께 쌓인다.
- 랭크는 1~5다. 누적 요구량은 다음과 같다.

| 랭크 | 누적 특화 숙련 | 중앙값 요리사(주 600) | 상위 10%(주 1,650) |
|---|---|---|---|
| 1 | 0 | 선택 즉시 | 선택 즉시 |
| 2 | 1,000 | 약 2주 | 1주 안 |
| 3 | 3,000 | 약 5주 | 약 2주 |
| 4 | 7,000 | 약 12주 | 약 4주 |
| 5 | 15,000 | 약 25주 | 약 9주 |

특화 숙련은 그 특화의 조리법으로 만든 음식만 세므로 실제로는 이보다 조금 느리다.

## 4. 제작 보너스

지금 고른 특화에 속한 음식을 만들 때 걸작 확률이 랭크당 +2%p 오른다(랭크 5에서 +10%p). 기존 걸작 확률 상한 75%는 그대로다. 성능 상한(걸작까지 135%, 명장 150%)과 음식 식별자는 바꾸지 않는다.

## 5. 전용 요리

특화마다 3종, 총 42종이다.

- 랭크 1·3·5에서 하나씩 열린다. 각각 3·4·5티어다.
- 연구가 필요 없다. 조합법은 누구에게나 공개되고, 그 특화를 지금 고른 사람만 요구 랭크를 채웠을 때 만들 수 있다.
- 연구로는 나오지 않는다. 같은 조합을 연구하면 기존 규칙대로 실패하거나 다른 숨은 레시피가 나온다.
- 음식은 기존 음식과 같은 소모품이다. 품질 판정, 12시간 효과, 거래, 조건 납품, 축제 주문, 명장 요리 전환에 그대로 쓰인다.
- 최초 발견자 보너스는 없다. 전문 분야 보너스(+1~5%)는 기존대로 붙는다.
- 도감 총수(500종)와 발견 수, 요리 도감 숙련에는 넣지 않는다.
- 요리 레벨 조건은 20이다(전문 분야를 고를 수 있는 레벨).

## 6. 전투 영향

랭크 5 전용 요리가 거래소에 풀리면 누구나 공격력 +300(걸작 +360, 전문 보너스 포함 최대 +405) 음식을 쓸 수 있다. 전직 진행자의 공격력 중앙값 약 2,500의 12~16%다. 이 수치는 지금도 5티어 요리로 정의돼 있고 음식 수치 상한(공격력 450)도 그대로다. 달라지는 것은 도달 가능성이다. 랭크 5까지 중앙값 요리사가 약 25주, 상위 10%가 약 9주 걸리므로 5티어 수준 음식의 공급은 천천히 늘어난다. 랭크 1 요리(공격력 +160 수준)는 특화를 고른 날부터 풀린다.

음식 효과의 적용 범위는 기존과 같다. 사냥·숙련의 탑·토벌전·협동 보스·폭풍 원정·미개척지에 적용되고 아레나·챔피언십·거점전·훈련 대련·스탯 합계 랭킹에서는 빠진다.

## 7. 저장

`cooking.v2`의 `CookingStateV2`에 선택 필드를 추가한다.

```ts
type CookingBranchState = {
  current: CookingBranchId | null;
  xp: Partial<Record<CookingBranchId, number>>;
  changedAt: number | null; // 마지막으로 "바꾼" 시각. 처음 고를 때는 null 로 둔다.
};
// CookingStateV2.branch?: CookingBranchState
```

- 마이그레이션은 없다. 필드가 없으면 특화를 고르지 않은 상태다.
- 파서는 모르는 특화 id와 음수·비정수 숙련을 버린다. `current`가 전문 분야와 맞지 않으면 null로 읽는다.
- 전용 요리는 `discoveredRecipeIds`에 넣지 않는다. 만들 수 있는지는 매번 특화와 랭크로 판정한다.

## 9. API

요리 라우트(`POST /api/v2/cooking`)에 동작 하나를 추가한다.

- `choose_branch` `{ branchId }`: 특화를 고르거나 바꾼다.
  - `branch_locked`: 전문 랭크 5가 아니다.
  - `invalid_branch`: 없는 특화이거나 자기 전문 분야의 특화가 아니다.
  - `branch_unchanged`: 지금 고른 특화와 같다.
  - `branch_cooldown`: 바꾼 지 14일이 지나지 않았다.
- `craft`: 전용 요리는 `discoveredRecipeIds` 대신 "지금 고른 특화의 요리이고 요구 랭크 이상"으로 판정한다. 아니면 기존과 같은 `recipe_locked`다.

조회와 변경 응답에 `branch`를 싣는다.

```ts
branch: {
  eligible: boolean;            // 전문 랭크 5
  current: CookingBranchId | null;
  rank: number;                 // 고르지 않았으면 0
  xp: number;
  nextRankXp: number | null;
  xpByBranch: Partial<Record<CookingBranchId, number>>;
  nextChangeAt: number | null;  // 지금 바꿀 수 있으면 null
  masterpieceBonusPct: number;
}
```

특화 정의와 전용 요리 정의는 공개 정보라 화면이 모듈에서 직접 읽는다.

## 10. 화면

주방의 전문 분야 화면에서 "주 전문 분야" 아래에 "특화"를 둔다.

- 전문 랭크 5 미만: 조건 한 줄만 보여 준다.
- 고르기 전: 자기 전문 분야의 특화를 선택지로 나열한다. 선택지마다 속하는 조리법, 전용 요리 3종의 이름과 효과를 보여 준다. 고르면 확인 창을 거친다.
- 고른 뒤: 특화 이름과 랭크, 숙련 진행(현재 / 다음 랭크), 걸작 확률 보너스, 변경 버튼(대기 중이면 가능 날짜)을 보여 준다. 그 아래 전용 요리 3종을 한 카드 안의 줄로 나열한다. 줄마다 그림, 이름, 효과, 재료(보유 / 필요), 수량 입력, 제작 버튼이 있다. 랭크가 모자란 요리는 요구 랭크를 적고 버튼을 끈다.
- 특화를 바꾸는 선택지는 "변경"을 눌렀을 때만 펼친다.
- 표면은 `SURFACE_CARD`·`SURFACE_INSET`, 버튼은 공용 `Button`, 선택지는 `ChoiceButton`을 쓴다.

## 11. 그림

전용 요리 42종의 그림을 기존 요리 그림과 같은 화풍으로 만들어 `public/images/items/cooking/<id>.webp`에 둔다. 생성 방식과 권리 기록은 전투 준비물 아이콘 때와 같다(출처 문서, 권리 대장 갱신).

## 12. 테스트

- `branch`: 특화 14개와 분야별 구성, 랭크 경계(0, 999, 1,000, …, 15,000), 속함 판정(분야·조리법), 선택 조건, 변경 대기 14일(경계 포함), 걸작 보너스.
- `branchRecipes`: 42종, 특화마다 요구 랭크 1·3·5와 티어 3·4·5, 재료 칸 수와 수량 규칙, id·이름이 기존 500종과 겹치지 않음, 조리법이 특화에 속함, 효과 표와 일치, 그림 파일 존재.
- `state`: `branch` 파싱(필드 없음, 모르는 id, 전문 분야와 안 맞는 `current`, 잘못된 숙련).
- 서버 로직·라우트: 선택·변경 오류 4종, 전용 요리 제작 조건(다른 특화, 랭크 부족, 특화 없음), 특화에 속한 기존 음식과 전용 요리 제작 시 숙련 증가, 속하지 않는 음식은 증가 없음, 걸작 보너스가 판정에 들어감, 연구로 전용 요리 조합이 발견되지 않음, 도감 총수 500 유지.
- 화면: 세 상태(조건 미달, 고르기 전, 고른 뒤), 재료 부족·랭크 부족 시 버튼 비활성, 변경 대기 표시.

## 13. 범위 밖

- 전문 분야 랭크 확장, 두 번째 전문 분야.
- 연구 힌트. 3~5티어 숨은 레시피의 접근성은 이번에 다루지 않는다.
- 요리 주전공·명장 단계와 특화의 연계.
- 특화 칭호.
