# 자동 채집 다음 작업 예약

## 배경

2026-11-23 운영 데이터(읽기 전용 조회) 기준이다.

- 6·7차 고참은 최근 30일 접속 163명 중 47명이 7일 넘게 오지 않았다. 남은 고참은 일주일 내내 접속하고,
  하루에 생활 기록이 남는 시간대가 중앙값 5~8개다.
- 지원권 등급별 하루 시간대 수(11-16~22, 숙련도 합 10만 이상 계정): 미보유 평균 6.3 · 일반 9.3 · 프리미엄 8.4.
  최대 스태미나가 세 배인 프리미엄이 더 자주 들어오므로, 접속 간격을 만드는 것은 스태미나가 아니다.
- 그 시간대 가운데 벌목·채광 기록이 있는 시간대가 평균 5.0~7.3개다. 자동 채집은 벌목·채광 통틀어 한 번에 하나만
  돌고(30분 또는 2~6시간), 고참은 하루에 벌목 3번·채광 3번(중앙값) 수령하고 다시 건다.

오너 결정(2026-11-23): 고참의 하루 부담 줄이기는 자동 채집 예약부터 한다. 예약은 지원권 혜택으로 둔다.
스태미나 적립은 근거가 없어 보류했고, 전투 숙제 정산은 숙련의 탑 체크포인트와 던전 일괄 진행이 이미 있어 뺐다.

## 목표

- 한 번 접속해서 자동 채집 두 번 분량을 걸어 둘 수 있게 한다. 수령하러 들어오는 횟수를 줄인다.
- 채집량 규칙(효율, 성공률, 작업 시간, 한 번에 하나)은 바꾸지 않는다.
- 채집지 정비와 명장 단계는 지금처럼 한 번의 길이를 늘리는 보상으로 남는다.

## 1. 규칙

- 자동 채집이 진행 중이거나 정산을 기다리는 동안, 다음 작업 1건을 예약할 수 있다. 벌목·채광 어느 쪽이든,
  어느 채집지와 작업 시간이든 고를 수 있다. 진행 중인 자동 채집이 없으면 예약할 수 없다(바로 시작하면 된다).
- 예약은 월간 모험 지원권(일반·프리미엄) 이용 중에만 걸 수 있다. 건 뒤에 지원권이 끝나도 이미 건 예약은
  그대로 이어진다(거래소 매물과 같은 기준).
- 예약한 작업은 지금 작업이 끝난 시각에 시작한 것으로 계산한다. 지금 작업이 끝난 뒤에 건 예약은 예약한 시각부터다.
  실제로 세이브에 올라가는 것은 지금 작업의 보상을 받을 때다. 그때 시작 시각을 거슬러 잡는다.
- 지금 작업을 중간 정산으로 중단하면 예약한 작업이 그 시각에 바로 시작된다.
- 예약은 1건이다. 다시 예약하면 앞의 예약을 바꾼다. 예약은 언제든 취소할 수 있다.
- 예약한 작업의 작업 시간은 예약할 때의 정비 단계로 굳힌다. 성공률·추가 재료 같은 나머지 수치는 실제로
  시작하는 시점(보상을 받는 때)의 레벨·도구·보조 도구로 정한다. 현장 환경은 시작 시각의 날짜를 따른다.
- 예약할 때 사람 확인이 필요한 상태면 지금의 자동 채집 시작과 같이 사람 확인을 요구한다. 이어서 시작될 때는
  다시 묻지 않는다.
- 예약한 채집지가 없어졌거나 세션을 만들 수 없으면 예약을 버리고 그 사실을 응답에 담는다.

## 2. 알림과 표시

- 예약이 있으면 지금 작업이 끝나도 "보상을 받으라"는 재촉을 하지 않는다. 예약한 작업까지 끝날 시각을
  기준으로 한다. 기기 푸시, 홈의 오늘의 모험 체크, 상단바 생활 상태가 대상이다.
- 상단바: 지금 작업이 끝난 뒤 예약 작업이 도는 동안은 "예약한 벌목 진행 중 · 소나무 · 남은 1:20:00"처럼
  보여 준다. 누르면 보상을 받아야 하는 화면(지금 작업 쪽)으로 간다.
- 채집 화면의 자동 작업 카드:
  - 작업이 있으면 그 아래에 예약 한 줄(무엇을 얼마 동안)과 예약 취소.
  - 다른 쪽 자동 채집이 도는 중이면 지금은 "시작할 수 없습니다"만 나온다. 지원권이 있으면 같은 자리에서
    작업 시간을 고르고 예약할 수 있다.
  - 지원권이 없으면 "다음 작업 예약은 월간 모험 지원권 이용 중에 쓸 수 있습니다." 한 줄만 보인다.
- "보상 받고 다시 시작"(생활 명성 5): 예약이 있었으면 보상을 받은 뒤 예약 작업이 이어지고, 방금 끝난 작업을
  다음 작업으로 다시 예약한다.
- 생활 한 번에 정산(생활 명성 30): 이어진 예약 작업까지 끝나 있으면 그것도 정산한다. 그 뒤 처음 작업을 다시
  시작하고 두 번째 작업을 다시 예약한다.

## 3. 저장과 서버

- 새 세이브 `auto-gathering-reservation.v1`: `{ next: { activity, spotId, planId, sourceId, sourceName, durationMs, reservedAt } | null }`.
- `POST /api/v2/{mining|woodcutting}/auto`에 `action: "reserve"`(spotId, planId)와 `action: "unreserve"` 추가.
  - reserve 오류: `support_required`(403), `no_active_session`(409), `bad_spot`·`bad_plan`(400), 사람 확인 응답.
- claim·cancel 응답에 `chainedAuto: { activity, session } | null`과 `reservationDropped`를 더한다.
  `activeAutoActivity`는 이어진 작업을 반영한다.
- 상태 응답(`/api/v2/{mining|woodcutting}/status`)에 `autoReservation`, `autoReservationAllowed`를 더한다.
  `/api/v2/me/state`의 `autoGathering`에 `next`(예약 작업의 종류·이름·끝날 시각)를 더한다.
- 세션을 만드는 계산(레벨, 도구, 보조 도구, 현장 환경)은 시작과 이어 시작이 같이 쓰도록
  `src/lib/server/autoGatheringSessionBuilder.ts`로 옮긴다. 계산 내용은 그대로다.
- 잠금 순서: 사용자 행 → 자동 채집 두 세이브 → (정산의 기존 잠금) → 예약 세이브. 생활 요청은 모두 사용자
  행을 먼저 잠그므로 서로 엇갈리지 않는다.
- 마이그레이션, 새 테이블, 새 크론은 없다.

## 4. 지원권 혜택 표시

- 혜택 목록(캐릭터 카드, 무슨 코인 상점, 안내서)에 "자동 채집 다음 작업 예약 1건"을 더한다. 일반과 프리미엄이 같다.
- 가격과 다른 혜택은 그대로다.

## 5. 구현 순서와 검증

1. 예약 세이브의 순수 로직(`autoGatheringReservation.ts`)과 상태 표시 — 테스트 먼저.
2. 지원권 혜택 값(`autoGatheringReservations`)과 표시 문구.
3. 세션 계산을 빌더로 옮기고 시작 요청이 그대로인지 확인.
4. 예약·취소 요청, 정산 뒤 이어 시작.
5. 상태 응답, 푸시, 홈 체크.
6. 채집 화면, 다시 시작, 한 번에 정산.
7. 안내서, 변경 기록.

검증: 순수 로직 단위 테스트, 관련 기존 테스트, 타입 검사, 린트, 모듈 예산. 화면은 미리보기로 라이트·다크를 본다.

## 하지 않는 것

- 예약 2건 이상, 프리미엄 추가 예약. 값은 등급별 상수로 두어 나중에 바꿀 수 있게만 한다.
- 스태미나 적립, 낚시 묶음, 농장 예약.
- 채집 효율·작업 시간·정비 비용 변경.
