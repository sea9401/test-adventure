# 보물 탐사 설계 (Treasure Hunt Plan)

작성 2026-06-02. 상태: 구현 진행 중 — PR-1~7 핵심 경로 1차 구현 완료, 밸런스·운영 마감 대기.

낚시(`docs/fishing-content-plan.md`)에 이은 두 번째 사이드 컨텐츠. **의도적으로 낚시와 다른 결** — 낚시가 *민주적 수집*이라면, 보물 탐사는 *희귀도 chase + 플레이어 거래 시장*이다.

## 0. 한 줄 요약

스태미나를 다 쓴 유저가 하는 **단서 추리형 발굴 미니게임**. 낚시·사냥에서 모은 **지도 조각**으로 발굴 지점을 열고, 격자에서 단서로 매장지를 좁혀 파낸다. 발굴품은 **거래 가능한 골동품**(희귀도 + 보존상태)으로, 플레이어 시장에서 사고팔린다.

## 1. 설계 원칙 (확정)

- **전리품 거래 경제** — 발굴품 = 거래 가능 골동품 인스턴스. 낚시의 "순수 평등"을 *의도적으로 버린다*. 대신 봇 저항·경제 관리가 코어 과제(§7).
- **스킬은 효율, 운은 희귀도** — 격자를 적은 dig로 풀면 발굴 성공(효율↑). *무엇이* 묻혔는지(희귀도·보존상태)는 서버 roll이라 반응 속도·캐릭터 스탯과 무관. 신규·약캐도 한 판 풀어 전설을 뽑으면 잭팟 → 상단은 운으로 민주화.
- **스태미나 0 소모** — 낚시와 동일. 메인 루프를 다 쓴 유저용 컨텐츠.
- **파워 경제 밖** — 골동품은 전투 스탯이 0이다(장식/칭호/도감/거래 가치만). v2 아이템 파워 척추 = 제작(`docs/v2-item-crafting-plan.md`, 소비-업그레이드 폐기)과 충돌을 피하고 낚시 DNA(전투 무관)와도 일치.

## 2. 핵심 루프

1. **지도 조각** 모으기 — 낚시 낮은 확률(주경로) + 사냥 소량(트리클). K조각(기본 5) → 보물지도 1장 = 발굴 1회.
2. **발굴 지점**: N×N 격자(기본 5×5). 매장지 1칸 + 묻힌 골동품(희귀도·보존상태)을 서버가 *지점 개방 시 봉인*한다(낚시 cast가 어종을 박제하듯).
3. **dig 예산**(기본 6회). 매 dig가 단서를 반환 — 거리 밴드("바로 옆/가까움/멈") 또는 방향("북동쪽"). 단서는 **서버 계산**.
4. 매장지 적중 → 골동품 발굴(서버가 봉인분 공개·replay 차단). 예산 소진 실패 → 꽝(혹은 소량 부스러기).
5. 골동품 → **유물 보관함 + 도감 등재**. 거래소 상장 가능. 반복.

## 3. 골동품 (유물 데이터)

종류 ×5 희귀도 티어(흔함~전설). 티어는 (a) 발굴 지점 희귀도 추첨 가중치, (b) 보존상태 분포(heavy-tail), (c) 감정가 규모, (d) 분해 시 발굴 코인을 결정한다.

| 티어 | 종 수 | 감정가 base 밴드(골드, 보존 100 기준) | 발굴 가중치 | 보존 heavy-tail k | 분해 코인 |
|---|---|---|---|---|---|
| 흔함 | 6 | 40 ~ 120 | 45 | 2.0 | 1 |
| 보통 | 6 | 150 ~ 400 | 30 | 2.5 | 3 |
| 희귀 | 5 | 600 ~ 1500 | 16 | 3.0 | 8 |
| 영웅 | 4 | 2500 ~ 6000 | 7 | 4.0 | 20 |
| 전설 | 3 | 12000 ~ 40000 | 2 | 5.0 | 50 |

### 인스턴스 모델 (`AntiqueInstance`)

```ts
type AntiqueInstance = {
  instanceId: string;   // 서버 발급 UUID, 재사용 금지
  antiqueId: AntiqueId; // 종류(카탈로그가 권위)
  condition: number;    // 보존상태 5~100 (heavy-tail roll)
  foundAt: number;
};
```

- 같은 종류라도 **보존상태가 달라** 시장 깊이가 생긴다(`EquipmentInstance` 인스턴스 거래 모델 미러).
- **감정 base가** `appraiseValue(antiqueId, condition)` = `round(baseValue × (0.3 + 0.7×condition/100))` — 결정적. **시장가와 별개**로 주간 랭킹·분해 환율의 점수 기준이 되어 조작을 막는다.
- 보존상태 굴림: `cond = 5 + 95 × rng()^k` (k>1 → 양호한 상태가 희박, 온전품은 잭팟).

## 4. 발굴 미니게임 (단서형 격자)

- 5×5, 매장 1칸, dig 6회(전부 다이얼). 스킬러는 ~3-4 dig로 핀포인트, 막굴이면 운.
- 단서·매장 위치·골동품 = 100% 서버. 클라는 **칸 선택만** 전송 → 위조 불가.
- 봇 주의: 추리 자체는 봇이 풀 수 있다(결정 로직). 그래서 방어는 *발굴 횟수*가 아니라 **조각 funnel**에 둔다(§7).
- (PR-3에서 단서 형식 — 거리 밴드 vs 방향 — 확정.)

## 5. 거래소 (전리품 시장)

- 기존 거래소 인스턴스 거래(`marketplace/types.ts`: `ItemKind` + `EquipmentInstance` surface)에 **`itemKind: "antique"` + `AntiqueInstance`** 를 추가(PR-5).
- 골동품은 **골드로** P2P 거래. 매도에 기존 **마켓 세금 15%** 부과 → 골드 싱크(`project-gold-sinks-plan`와 연계). 희귀도 heavy-tail로 전설 골동품은 희소·고가 유지.

## 6. 발굴 코인 & 도감

- **발굴 코인**: 중복/흔함 골동품을 감정사에게 **분해** → 코인(골드 아님). 흔한 발굴만 해도 보상 경로(낚시 4~10등 인클루시브 미러). 희귀품은 골드 마켓行.
- **발굴 코인 샵**: 장식/칭호/발굴도구 스킨(하우징 연계). 전투 파워 없음.
- **유물 도감**(`treasure-codex.v1`): 종별 발견 + 개인 최고 보존상태 박제. 세트 완성 → 칭호·장식. `AdventureLog` + `V2CodexView` 탭.

```ts
type TreasureCodexEntry = {
  discovered: boolean;
  bestCondition: number; // 개인 최고 보존상태 — 영구 박제
  totalFound: number;
  firstFoundAt: number;
  bestFoundAt: number;
};
```

## 7. 봇 / 경제 (낚시보다 어려움 — 거래가치 때문에 봇 인센티브↑)

- ① **조각 funnel이 진짜 throttle** — 낚시(반응 + 벽시계)·사냥(스태미나 게이트)이 이미 봇 저항. 발굴을 봇이 빨리 풀어도 조각 공급이 상한.
- ② 일일 발굴 site 캡 + 쿨다운.
- ③ 희귀도·보존 서버 roll → 속도 이득 0(throughput만, 그건 ①로 캡).
- ④ 마켓 세금 싱크 + **anti-laundering**(제작 거래토큰 패턴·픽업 바운드 윈도우·상장 제한)으로 RMT/부캐 펀딩 차단.
- ⑤ 주간 랭킹은 *시장가 아닌 결정적 감정 base가*로 점수 → 조작 방지.

## 8. 위치 & 진입점

- 글로벌 마을 시설 **"발굴 감정소"**(낚시터처럼 전원 접근) + 낚시 결과 화면에서 "발굴하러 가기" 연동. 보관함 동반.
- `TreasureDigView` + `useTreasure`, 라우트 `/api/v2/treasure/open`·`/dig`. `/dev/treasure` 하니스로 로그인·DB 없이 발굴 UI QA.
- ⚠️ v2 게임은 현재 `/dev/v2-game` 에서만 마운트(prod는 라이브 v1 화면) — 보물도 거기 동작, v2 리워크 라이브 swap 시 동반 공개.
