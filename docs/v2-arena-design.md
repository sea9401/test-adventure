# v2 1:1 아레나 — 디자인 1차

**작성일**: 2026-05-26 · **상태**: 1차 안 (codex 검토 대기) · **PR-8 대응**

## 1. 배경

v2 시스템 재설계 ([[v2-item-skill-design]] 11장) 의 PR-1~7b 까지 마법(INT+MP+액티브)·길드 주문서·거점 점령 영웅 결과 판정이 머지됐다. 남은 PR-8 은 **v2 전용 1:1 아레나**.

설계 동기는 [[v2-item-skill-design]] 의 두 줄이다:

> "v2 전용 1:1 아레나 — 개인 영웅 빌드 명분. 3:3 토너먼트와 병존, 라이브 코드 직접 이식 X."

3:3 토너먼트 / 본 병사 전쟁 / 거점 점령은 모두 **길드·라인업** 기반이라 길드 마스터·라인업 결정자에게 의사결정이 집중된다. 1:1 아레나는 그 반대축 — **솔로 개인의 빌드(스탯·마법·장비) 가 그대로 결과로 나오는 트랙**. v2 마법 시스템(`flame/bolt/meteor` 의 시작-sweep 발동) 의 메타 다양성을 가장 직접적으로 시험할 수 있는 무대이기도 하다.

## 2. 현재 상태 (탐색 보고 요약)

| 항목 | 라이브 (참조 X) | v2 현황 |
|---|---|---|
| PvP 엔진 | `engine-pvp.ts` 재사용 가능 — `applyStartOfBattleSpellsPvP` 가 양측 마법 sweep 처리 | 토너먼트 매치별로 이미 호출 중 (`v2RunTournament.ts`) |
| derive | `derivePlayerCombatV2` — 룬/AP스킬/파라곤 차단, INT·MP·spells 정규화 | 토너먼트·점령·NPC 일기토 모두 이걸 통과 |
| 매칭 | 라이브 시즌제 1:1 — 시즌 점수·랭킹·등급·코스메틱(`pvp-wallet.v1`) | v2 미도입 |
| 상점 | 라이브 PR #530 의 시즌 보상·투기장 코인·상점·시즌 보상 cron | v2 미도입 |
| 자원 | 길드 공용(`stone/scrolls/soldiers`) + 개인 골드(라이브 싱크 살림) | 아레나 보상은 미정 |
| 스태미너 | v2 전역 스태미너 바 (`stamina-global`) | 던전 사냥에서 소비, 아레나 미연결 |

**핵심 제약**:
- **라이브 코드 직접 이식 X** — `pvp/` 디렉터리의 시즌제·랭킹·시즌 cron 그대로 복사 금지. v2 키스페이스(`arena.v2-*`) 안에서 새로 짠다.
- **개인 영웅 빌드 명분** — 3:3 토너먼트는 라인업 멤버 3명 풀세팅 부담 (메모리 [[v2-item-skill-design]] 의 "3명 풀세팅 < 솔로 풀세팅") 인데, 1:1 아레나는 그 손잡이를 직접 솔로에게 돌려준다.
- **유저 풀 작음** — test-adventure 는 staging. 실시간 매치메이킹·대기열 모델은 무의미.

## 3. 설계 원칙

1. **비동기 스냅샷 매칭** — 상대방의 마지막 저장된 캐릭 상태(`character.v2` + `training.v2`) 의 snapshot 으로 매칭. 양쪽 모두 온라인일 필요 없음. test-adventure 인원 풀 작음에 정합.
2. **단판 + sweep + turn-based** — v2 마법은 시작-sweep 1회 발동 모델. 1:1 도 단판이라 일관. 빌드별 카운터플레이가 sweep 데미지/MP 풀 + 일반 턴 공방으로 나뉨.
3. **시즌제·랭킹 시스템 미도입** — 누적 점수·도달 마일스톤 보상으로 1차 시작. 시즌화는 유저 풀 늘어난 후로 보류.
4. **개인 보상만** — 아레나는 솔로 트랙. 길드 공용 자원(`stone/scrolls/soldiers`) 영향 0. 보상은 골드 + 개인 누적 점수.
5. **거점 점령 영향 0** — 점령은 일기토/토너먼트, 아레나는 별개 트랙. 두 트랙이 서로 보상을 침범하지 않음.
6. **라이브 코드패스 영향 0** — 신규 라우트(`/api/v2/arena/*`) + 신규 save key(`arena.v2-*`) 만. 라이브 `pvp/` 손대지 않음.

## 4. 핵심 결정 (옵션 X 안 정리)

### 4.1 매칭 모델

| 옵션 | 설명 | 장단 |
|---|---|---|
| **A: 비동기 스냅샷 풀 ★** | 모든 v2 유저의 마지막 캐릭 snapshot 에서 레벨·점수 근사 매칭 | 풀 작아도 작동. 라이브 영향 0. 첫 PR 단순. |
| B: 자기 보유 길드원 풀 | 자기 길드 내 다른 멤버와 매칭 | 친선전 의미 외엔 명분 약함. 길드원 수에 종속 |
| C: 봇 매치 | NPC 봇 풀 (스탯 등급별 프리셋) | 유저 부담 0, 그러나 "다른 유저와 대결" 명분 손실 |

**1차 안: A + C 폴백** — 풀에 적합한 상대 없으면(예: 레벨 ±10 안에 0명) NPC 봇으로 폴백. 봇 프리셋은 던전 몬스터 스케일(`monsterScale.ts`) 참조, 마법은 INT 분배만.

### 4.2 매치 형식

| 옵션 | 설명 |
|---|---|
| **A: 단판 1전 ★** | engine-pvp 한 번 호출. 가장 단순, 마법 sweep 모델에 정합. |
| B: 베스트 오브 3 | HP 이월 X, 매치별 독립 sweep 재시동 | 길어짐, 토너먼트(3:3)와 형식 중복 |

**1차 안: A 단판**. 짧은 의사결정 사이클이 마법 빌드 시험·반복 횟수에 유리.

### 4.3 진입 비용

| 옵션 | 설명 |
|---|---|
| A: 무제한 무료 | 단판이라 짧음 → 무한 가능. 보상 격리로 인플레 방지 |
| **B: 일일 N회 ★** | 매일 자정(KST) 리셋. 첫 N회만 보상. 추가 매치는 무보상 연습 가능 |
| C: 스태미너 N 소모 | 던전과 같은 풀에서 차감 — v2 스태미너 한 풀에 통합 |

**1차 안: B**. N=10 (튜닝 다이얼). 던전 스태미너와 분리해 한쪽이 다른 쪽 진행을 막지 않음. 메모리 [[project-mobile-ux-batches]] 의 모바일 짧은 세션 친화.

### 4.4 보상 모델

| 옵션 | 설명 |
|---|---|
| A: 골드만 | 라이브 싱크에 자연스럽게 흐름. 단순. |
| **B: 골드 + 누적 점수 + 마일스톤 ★** | 점수는 승패에 따라 증감. 마일스톤(예: 100/500/1000 점) 도달 시 1회성 범용 보상 (단련 포인트 또는 골드 — INT/특정 스탯 권유는 의도적으로 X. 보상이 빌드 판단에 개입하지 않게) |
| C: 신규 화폐 + 상점 | 라이브 "투기장 코인 + 상점" 의 v2 재구현. 구현 비용 큼, 시즌제 도입과 함께 가야 자연스러움 |

**1차 안: B**. 마일스톤이 "점수 = 빌드의 명함" 이라는 결을 만든다. 신규 화폐·상점은 유저 풀 늘어나면 PR-9 이후 검토.

**점수 공식 (1차 안 — 튜닝 다이얼)**:
- 승: +20점, 패: -10점 (점수 0 미만 X)
- 상대 점수 차 보정: 본인보다 높은 상대 승리 시 +5 보너스, 낮은 상대 패배 시 -5 페널티

**골드 보상 (1차 안 — 튜닝 다이얼)**:
- 승: 본인 레벨 × 50, 패: 본인 레벨 × 10 (참가 보상)

### 4.5 매치 풀 / 매칭 알고리즘

**작은 풀 대비 — 컷오프 X, 전원 후보 + 가중 랜덤**:
- 본인 제외한 전 v2 유저 snapshot 을 후보로 둠. 좁은 컷오프(예: ±50점/±10레벨) 안 둠 — staging 초기 풀에선 그러면 매번 봇 폴백으로 떨어진다.
- 가중치 1차 안 (튜닝 다이얼):
  - 점수 차 0 = 1.0, ±200 = 0.3 으로 선형 감쇠 (±200 초과는 0.3 클램프)
  - 레벨 차 0 = 1.0, ±20 = 0.3 으로 선형 감쇠
  - 최근 5매치 상대는 가중치 ×0.2
- 후보 0명일 때만 NPC 봇 풀로 폴백. 봇 풀 1차 안: 본인 레벨 ±5 안 프리셋 (스탯 등급별 5~10개) 중 가중 랜덤.
- snapshot freshness: Open Q (9장 참조) — 며칠 이상 비활성 유저 포함 여부는 사용자 결정.

## 5. 상세 동작 (1차 안)

### 5.1 매치 흐름

```
유저가 "아레나" 진입
  ↓
일일 카운터 확인 (10회 미사용?)
  ↓
매치메이킹 API 호출 → 상대 스냅샷 픽업
  ↓
양측 derivePlayerCombatV2 → engine-pvp 단판
  ↓
결과 (승패·턴수·sweep 로그) + 점수 변동 + 골드
  ↓
마일스톤 도달 시 1회 보너스 지급
```

### 5.2 라우트 (1차 안)

- `POST /api/v2/arena/match` — 본인 일일 카운터 차감 + 매칭 + 전투 시뮬레이션 + 점수 갱신. 응답: 전투 결과 페이로드 (`replayPayload.ts` 형식 재사용) + 점수·골드 변동.
- `GET /api/v2/arena/state` — 본인 현재 점수·일일 잔여·최근 매치 N개·마일스톤 진행도.
- `GET /api/v2/arena/leaderboard` — 점수 상위 N명. **명예 표시 전용** — 시즌 cron/리셋/시즌 보상 X. 라이브 PR #530 의 시즌순위보상 cron 과 명시적으로 구분. PR-8c 옵션, 도입 여부 Open Q.

### 5.3 UI (1차 안)

V2GameFlow 의 메뉴에 신규 진입점 "아레나" 추가. 단일 화면:
- 헤더: 현재 점수 / 일일 잔여 / 마일스톤 진행도
- 본문: "도전" 버튼 → 매치 진행 → 결과 카드(승패·턴수·sweep 마법·점수 변동) → 다시 도전
- 푸터: 최근 매치 N개 리스트(상대 닉네임·레벨·승패만)

V2 디자인 결: 카드 위주, 좌하단 fab 패턴은 [[v2-rewrite-plan]] 의 모바일-first 와 정합.

## 6. 스키마/Save 영향

### 6.1 신규 save key

`savesKv` 테이블 (이미 존재) 에 다음 키 추가:

```ts
arena.v2-state = {
  score: number;
  dailyUsed: number;
  dailyResetAt: ISO;
  recentOpponents: Array<{ userId?: string; botId?: string; at: ISO }>;  // 최근 5개, 반복 매치 가중치 ↓ 용
  milestonesReached: number[];
}
```

JSONB. 마이그레이션 불필요 — 키 신설은 row 추가만. `recentOpponents` 가 반복 매치 방지의 단일 진실원 (PR-8a 에서 즉시 도입).

### 6.2 신규 테이블 (PR-8c 옵션)

반복 매치 방지는 6.1 의 `recentOpponents` 로 PR-8a 부터 작동. 별도 매치 히스토리 테이블은 **leaderboard 가 도입될 때만** 필요:

```ts
arenaMatches: pgTable("arena_matches", {
  id: uuid().primaryKey().defaultRandom(),
  userId: text().notNull(),
  opponentUserId: text(),  // null이면 봇
  opponentSnapshot: jsonb(),
  result: text(),  // "win" | "loss" | "draw"
  scoreBefore: integer(),
  scoreAfter: integer(),
  goldEarned: integer(),
  turns: integer(),
  createdAt: timestamp().defaultNow(),
});
```

도입 여부는 leaderboard 옵션 결정과 묶임 (Open Q #6).

### 6.3 라이브 영향

`pvp-wallet.v1` / 라이브 PvP 시즌 테이블 / `pvp/shop.ts` — 모두 불변. v2 아레나는 별도 키스페이스.

## 7. PR 시리즈 (확정 1차 안)

작게 끊는다. 메모리 [[feedback-codex-review-all-work]] 룰 — 각 PR 머지 전 codex 검토 1회.

- **PR-8a (코어, end-to-end 굴러가는 최소형)**: 아레나 라우트 + 매치메이킹(전원 후보 가중 랜덤 + 봇 폴백) + 단판 전투 + 일일 N회 카운터 + 점수 공식 + 골드 보상 + `arena.v2-state` save + `recentOpponents`. UI 는 진입점 + 결과 카드만 (간소).
  - codex 권고 반영: 8a 가 "API 의미 불완전" 회피 — 카운터·점수·골드까지 묶어 한 번에 굴러가게.
- **PR-8b (UI/UX + 마일스톤)**: 마일스톤 보상(단련 포인트 또는 골드) + 헤더(점수·잔여·진행도) + 최근 매치 N개 리스트 + 결과 카드 다듬기.
- **PR-8c (옵션, 명예 표시)**: `arena_matches` 테이블 + `GET /api/v2/arena/leaderboard` + 리더보드 UI. 명예 표시 전용 — 시즌 cron/리셋 없음. 도입 여부는 Open Q #6.

PR-9 이후 튜닝 다이얼: 점수 공식·일일 횟수·마일스톤 임계값·매칭 가중치 곡선.

## 8. 마이그레이션 / 호환성

- 라이브 영향: 0 (별도 라우트·별도 save key)
- v2 기존 영향: 토너먼트·점령·던전 라우트 손대지 않음. `derivePlayerCombatV2` 재사용만.

- 봇 폴백: snapshot 풀 0명일 때 핵심. 1차 안 봇 프리셋은 5~10개 정도 (레벨대별).
