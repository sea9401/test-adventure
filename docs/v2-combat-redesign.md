# v2 전투 시스템 재설계 — 직업·속성·스탯 개편

**작성일**: 2026-05-30 (2026-05-31 Codex 검토 반영) · **상태**: 설계 결정 완료 · **PR-1 수직 슬라이스 착수 대기**

## 0. 한 줄 요약

전투 **해결 메커니즘(서버 자동 단판)은 그대로 두고**, 그 위에 얹는 **빌드 시스템을 갈아엎는다.** 목표는 "완벽한 밸런스"가 아니라 **소속감(정체성) 기반 다양성** — 직업·속성·세밀한 대항 스탯으로 "다들 같은 빌드"를 깨는 것.

## 1. 배경 / 동기 (사용자 정리)

라이브 서버 운영 경험에서 얻은 핵심 교훈: **선택지를 단순하게 주면 유저는 결국 "제일 좋은 것"으로 수렴해 다들 똑같은 빌드를 한다.** 밸런스는 어차피 완벽할 수 없으므로, 완벽주의 대신 **유저가 "나는 이 직업·이 속성"이라는 애착(정체성)** 을 갖게 하는 방향이 맞다.

그러려면 게임이 조금 더 복잡해져야 하고, 스탯도 **더 큰 숫자에서 세밀하게** 들어가야 한다 (현 "1당 atk 몇"의 거친 해상도 대신). 그래서:

- **직업(class)** 과 **속성(element)** 을 도입하고, **서로 카운터**가 성립하게 한다.
- 스탯을 **대항 축**(적중↔회피, 치명 적중↔저항 등)으로 짜서 단일 최적해를 구조적으로 깨뜨린다.

## 2. 불변(유지) 사항

- **전투 해결 = 서버 자동 단판** (hunt / 일기토 / 3:3 토너먼트 / 아레나). 리플레이 표시. **이 메커니즘 자체는 안 바꾼다.**
- **범위 = v2 전용.** 공유 전투 엔진/라이브 derive 는 안 건드린다 (`derivePlayerCombatV2` 가 이미 분리돼 있으므로 v2 축만 확장). 라이브 영향 0.
- 골드 = 개인 쇼핑 소모 유지. 5층 던전 구조, 거점/토너먼트 메타게임 유지.

## 3. 핵심 설계 원칙

1. **정체성 > 완벽 밸런스.** 모든 빌드가 모든 상황에서 동등할 필요 없음. "내 직업/속성"이라는 애착이 선택을 다양화한다.
2. **카운터로 다양성을 강제** — 그리고 **PvE 에도 적용**(몬스터도 직업·속성 보유). 카운터가 PvP 에만 있으면 사냥은 여전히 단일 최적으로 수렴하므로, **PvE 적용이 다양성의 사활.**
3. **대항 스탯 축** — 공격↔방어, 마공↔마방, 명중↔회피, 치명 적중↔치명 저항, 디버프 적중↔저항. "다 올릴 수 없고, 상대 강점을 받아치는 게 의미 있다."
4. **고해상도 스탯** — 큰 기본 숫자 + 세밀한 단위(현 ×5 스케일을 더 키움). 미세 차별화 여지 확보.
5. **무기는 빌드를 안 가린다** — 무기 위력이 물리/마법 공격력 둘 다 먹임. "잘못된 무기" 좌절 제거, 드랍 다양성 유지.

## 4. 스탯 체계 (6 1차 스탯 + 파생)

> 사용자가 준 두 레퍼런스(직업군 매핑 블록 + 타 게임 메뉴얼 블록)를 "우리 식"으로 통합한 **제안**. 표기·계수는 검토·sim 으로 확정.

### 4.1 1차 스탯 — 6종, 각 **직업군에 1:1**

레벨업 시 **확률적으로 상승**(레퍼런스 핵심) — 해당 스탯을 참조하는 스킬 위력·파생 스탯을 키운다. Codex 우려(RNG 가 정체성·밸런스를 덮어씀)를 **확률 모델 안에서** 완화:
- **직업 앵커 가중** — 그 캐릭 직업의 주 스탯에 상승 확률을 강하게 가중. "내 직업 = 내 주 스탯"이 RNG 로 안 뒤집힘(정체성 보존).
- **분산 상한 / 소프트 피티** — 같은 직업·레벨 캐릭 간 총 스탯 격차에 상한, 기대치 미달 시 보정. "운 나쁜 캐릭" 방지(밸런스 분산 억제).
- 확률의 유니크함·애착은 살리되 계획성·바닥은 보존.

**Codex 논의 반영 확정안** (계수는 PR-1 sim 캘리브 시작값):

| 1차 스탯 | 직업군 | 주 효과 (≈1.0×) | 부 효과 (minor) | 정체성 |
|---|---|---|---|---|
| **힘** (str) | 검술 | 물리 공격력, 최소 데미지 | 명중 0.4, 치명 피해 0.4 | 신뢰성 높은 물리 딜. 자체 방어 없음(VIT 물방이 카운터). |
| **민첩** (dex) | 인술 | 속도(행동 순서) | 명중 0.4, 회피 0.35 | 선공·템포. 회피는 minor만(속도 자체가 보편 가치라 과상승 방지). |
| **활력** (vit) | 체술 | 물리 방어력, **최대 HP**, 회복량 0.8 | 최소 데미지 0.3 | 물리 내구·지속. HP 파생 필수(없으면 dump stat). |
| **지능** (int) | 마술 | 마법 공격력, 디버프 적중(추후) | 최소 데미지 0.5, 마방 0.3 | 마법 딜·제어. **회피 제거**(DEX/LUK 과스택 방지), 마방 소량 자버퍼. |
| **정신** (spi) ★ | 신술 | 마법 방어력, 치명타 저항 | 회복량 0.5, 명중 0.3, 디버프 저항 0.4(추후) | 대-버스트/지원. INT 마법·LUK 치명을 동시 카운터+힐. |
| **행운** (luk) | 궁술 | 치명타 확률, 치명 피해 0.8 | 회피 0.35, 디버프 저항 0.3(추후) | 고변동 정밀 딜. 유틸은 **전부 minor**(만능 2순위 god stat 방지, SPI 치저가 하드카운터). |

**현 v2 6스탯 대비 변경**: 현재 `힘/민첩/활력/속도/행운/지능` → 신규 `힘/민첩/활력/지능/정신/행운`.
- **속도(spd) 를 1차에서 빼고 → 파생 스탯으로** (민첩 등에서 산출). 인술 직업군의 1차 스탯은 민첩이 맡음.
- **정신(spi) 1차 신규 추가** (신술 — 마법 방어·회복·명중·치명 저항의 "대항/지원" 축).
- 힘/민첩/활력/지능/행운 5종은 유지. 즉 실질 변경은 **속도→정신 교체 + 속도 파생화** 한 칸.

### 4.2 파생 스탯 — 1차 스탯에서 자동 산출 (높은 숫자)

| 파생 | 의미 | 주 출처(1차/장비) | 대항 축 |
|---|---|---|---|
| 물리 공격력 | 물리 스킬 위력 스케일 | 힘 + 무기 위력 | ↔ 물리 방어력 |
| 마법 공격력 | 마법 스킬 위력 스케일 | 지능 + 무기 위력 | ↔ 마법 방어력 |
| 물리 방어력 | 물리 피해 경감 | 활력 + 방어구/장신구 위력 | |
| 마법 방어력 ★ | 마법 피해 경감 | 정신(+지능 소량) + 장신구 위력 | ↔ 마법 공격력 |
| 명중 | 공격 명중 확률 | 힘·민첩·정신 | ↔ 회피 |
| 회피 | 공격 회피 확률 | 민첩·행운 | ↔ 명중 |
| 속도 | 행동 순서/선공 | 민첩 − 무게 | |
| 치명타 확률 | 치명 발생 | 행운 | ↔ 치명타 저항 |
| 치명타 피해 | 치명 시 추가 피해 | 힘·행운 | |
| 치명타 저항 ★ | 상대 치명 확률 감소 | 정신 | ↔ 치명타 확률 |
| 최소 데미지 ★ | 데미지 하한(폭) | 힘·지능 | |
| 회복량 ★ | 힐·재생 효율 | 활력·정신 | |
| 디버프 적중 ★ | 디버프 적용 확률 | 지능 | ↔ 디버프 저항 (※시스템은 추후) |
| 디버프 저항 ★ | 디버프 저항 확률 | 정신·행운 | ↔ 디버프 적중 (※추후) |

★ = 신규 축. **최소~최대 데미지 폭**과 **회복량**은 새 메커닉(아래 §8).

### 4.3 anti-meta 설계 노트 (Codex 논의 반영)

- **대항 규칙**: 어떤 1차 스탯도 "공격 축 + 그 직접 카운터"를 **둘 다 주(major)로** 갖지 않는다 (LUK=치명 주 / 치저는 SPI, INT=마공 주 / 마방은 SPI). → 한 스탯 몰빵으로 공·방 양면 못 챙김.
- **속도 함정** ⚠️: 자동 단판에선 선공이 항상 유리 → 민첩(속도)이 보편 1순위가 되기 쉽다. **장비 무게(§7)가 진짜 트레이드오프를 만들어야** 속도 독주를 막는다 (무게 패널티가 약하면 스탯 표가 아무리 좋아도 속도가 지배).
- **분포가 enforcement** ⚠️: SPI(마방·치저)·속성 방어 같은 "대항형" 스탯은 **몬스터 풀의 속성·직업군·공격타입 분포가 고를 때만** 의미가 산다. 쏠리면(예: 마법몹만) 단일 방어 스탯이 정답 → 재수렴. §9 와 직결.

## 5. 직업 (Class)

- **6 직업군**: 검술 · 체술 · 마술 · 신술 · 궁술 · 인술 (각 1차 스탯에 대응).
- 각 직업군 안에 **1차~4차 전직 트리** (4단계 직업 성장).
- **범위 — 일단 1직업만 먼저** (수직 슬라이스). 한 직업을 스탯 보정·스킬·전직·속성까지 끝까지 구현해 검증한 뒤 나머지 직업군으로 확장. **한 번에 다 안 만든다.**
- **직업이 하는 일**:
  1. **직업 전용 스킬** — 그 직업일 때만 사용 가능 (정체성의 핵심).
  2. **공용 스킬** 몇 개 — 모든 직업 사용 가능 (기본기).
  3. **직업별 스탯 보정** — 직업군 주 스탯에 보정(예: 검술 = 힘 보정).
- **전직 + 직업 성장** 시스템. **모험의 서(발견 코덱스, #241)와 연계** — 직업 해금/성장을 모험의 서 진척(발견·도감 완성 등)에 묶는다. (구체 연계 메커닉은 v2 모험의 서 코드 정독 후 설계 — §11.)
- 화면 참고: 캐릭터 카드에 `직업 · 속성` 헤더 + 직업 패널(직업 레벨) — 레퍼런스 이미지대로.
- **commitment = 비용 전직** (Codex 핵심 결정): 직업·속성은 **바꿀 수 있되 비용/쿨다운**. 정체성(소속감) + 탈출구 둘 다 — dead build 에 영구히 갇히지 않으면서, 콘텐츠마다 가볍게 갈아타 최적 수렴하는 건 억제. (무료 자유 전환은 다양성 목표와 정면 충돌이라 배제.) 속성도 동일.

## 6. 속성 (Element)

- **부착 대상**: 캐릭터 · 스킬 · 장비 · **몬스터**(PvE 카운터용).
- **속성 목록**: 무속성 + **5속성 순환** + **빛/어둠 상호 쌍**.
- **상성 (효과 = 데미지 +%)**:
  - 5순환: **물 > 불 > 바람 > 대지 > 번개 > 물** (각 좌가 우를 카운터)
    - 물 > 불, 불 > 바람, 바람 > 대지, 대지 > 번개, 번개 > 물
  - **빛 ↔ 어둠**: 상호 카운터 (서로에게 +).
  - 무속성: 상성 없음(중립).
- **양방향 적용**: 상성 우위 = **데미지 +X%**, 역상성(열세) = **데미지 −Y%** 둘 다. **빛↔어둠도 동일** 방식(상호 +/−). 배율은 sim 캘리브.

## 7. 장비 (위력 / 무게 / 내구도)

장비 데이터 모델을 **공격력·방어력 직접 표기 → 위력 단일 표기**로 통합. 효과는 **슬롯별 분기**:

| 슬롯 | 위력이 주는 것 |
|---|---|
| 무기 | **물리 공격력 + 마법 공격력** (둘 다) |
| 방어구 | **물리 방어력** |
| 장신구 | **물리 방어력 + 마법 방어력** |

- **무게** → **속도 −** (무거우면 행동 느림). 빌드 트레이드오프.
- **내구도** → 닳으면 **장비 효과 비활성**(파괴는 없음). 0 = 위력·옵션 0 → **수리(골드 소모)** = 골드 싱크. ⚠️ 자동전투라 "모르고 0 됨 → 캐릭 조용히 망가짐" 절벽 위험(Codex) → **경고 + 전투 전 수리 프롬프트 + 자동수리 옵션** 필요(§11). 비용 곡선도 §11.
- 무기가 물리/마법 둘 다 먹이므로 **무기는 빌드를 안 가림**(물리/마법 구분은 무기 아닌 **스킬 분류** — §8). ⚠️ 단 그러면 "최고 위력 = 정답"으로 무기 선택이 납작해짐(Codex) → 무기는 위력 외에 **무게(속도 트레이드)·속성·옵션**으로 차별화돼야 선택지가 산다.

## 8. 스킬 / 전투 수식

- **스킬을 물리/마법으로 분류** (이미 `v2Skills.ts` 에 `scaling: "physical"|"magic"` 토대 존재):
  - 물리 스킬 → **물리 공격력** 스케일, **물리 방어력** 으로 경감.
  - 마법 스킬 → **마법 공격력** 스케일, **마법 방어력** 으로 경감.
- **마법 평타 = 마법 탄 스킬**(`int_magic_bolt_t1` 기존). 마법 빌드의 "평타 공백" 해소.
- **INT 계수 정리**: matk 가 이제 "무기 위력 + 지능"에서 합산되므로, 지능 단독 계수(`MAGIC_ATK_PER_INT`=0.35)를 낮춰 **"무기+지능"이 물리쪽 "무기+힘"과 대칭**이 되게.
- **신규 전투 축** (v2 엔진/derive 확장, 라이브 미적용):
  - 마법 방어력 — 마법 피해 경감 분기.
  - 최소~최대 데미지 **폭** — 데미지 floor(힘/지능 ↑) + 변동. 현 단일 공식 → 범위 모델.
  - 치명타 저항 — 피격 측 치명 확률 차감.
  - 회복량 — 힐/재생 스케일(신술·체술).
  - 속성 배율 — 공격 속성 vs 피격 속성 상성으로 데미지 ±%.
  - 직업 보정 — 스탯/스킬 가용성.
- **디버프(상태이상) 시스템은 추후** — 디버프 적중/저항 **스탯 축만 먼저 깔아두고**, 실제 상태이상(스턴/감속/방깎 등) 발동은 별도 후속 PR.

## 9. 다양성 ↔ PvE 밸런스 바닥

카운터로 다양성을 주되, 특정 빌드가 **PvE 고정 몬스터 풀** 상대로 그냥 약해지지 않도록. **(Codex: 이건 "배포 후 튜닝"이 아니라 "설계 계약" — 안 그러면 정체성이 '지옥 매치'로 변질.)**

- **몬스터 분포 = 설계 게이트**: 풀의 **속성·직업군·공격타입을 의도적으로 고르게** 깔고, 신규 콘텐츠 추가 시 분포를 **먼저 검사**. 쏠리면(예: 마법몹만) 단일 방어 스탯이 정답 → 재수렴.
- **승률 floor 계약**: 어떤 빌드도 자기 권장 구간에서 **풀 평균 승률 X% 미만 금지**(목표치 §11). 상성 우위는 "재미있는 우위"이되 "필수 가위바위보"는 아니게 — 상성 배율 **상한 ±X%**.
- `sim-v2-progression` 을 **속성·직업 축으로 확장** → 매 PR 마다 floor 검증을 **배포 전 게이트**로.

## 10. 범위 / 마이그레이션

- **v2 전용.** 신규 축(마방·치명저항·디버프·최소뎀·회복·속성·직업)은 `derivePlayerCombatV2` + v2 전투 경로에만. 공유 엔진은 옵셔널 필드 null-허용을 활용하거나 v2 분기로 처리. **라이브 derive·엔진 코어 무수정.**
- **스탯 마이그레이션**: 기존 v2 캐릭의 `spd` 분배분 → 신규 체계로 전환 필요(속도 파생화 + 정신 신설). **test-adventure 는 리셋 허용**이므로 단순 리셋(또는 단련 포인트 환급 후 재분배)으로 처리.
- **장비 데이터 모델 교체**: `V2_EQUIPMENT` 의 `atk/def/matk/...` → `위력/무게/내구도` 로 재정의 + 슬롯 매핑. 기존 v2 장비 인스턴스는 재생성/마이그.
