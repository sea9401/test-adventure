# v2 DEX 독주 재설계 — 진단 + 재설계안 (설계 문서)

2026-06-20. 엔드게임에서 DEX(+LUK)가 다른 모든 축을 압도하는 문제의 근본 진단과 재설계 옵션.
**이 문서는 설계/진단만 — 코드 미수정.** 다음 세션 결정용. 선례 = [[project-v2-spi-axis-revival]](docs/v2-spi-axis-plan.md) 구조.

## 1. 진단 — sim 실측 (scripts/sim-v2-progression.ts, 7축 × 깊이 sweep, 스킬 OFF baseline)

깊이 1~5(권장파워 50~86)는 전 축 100% wr·균질(초반은 차별 없음). **차별은 깊이 8(파워 212)부터, 독주는 깊이 20+에서 폭발.**

| 깊이(파워) | STR | DEX | VIT | INT | SPI | LUK | BAL | DEX winT | DEX extra% |
|---|---|---|---|---|---|---|---|---|---|
| 8 (212) | 100 | 100 | 100 | 100 | **29** | 99 | 81 | 35.8 | **147** |
| 10 (281) | 100 | 100 | 100 | 100 | 88 | 100 | 100 | 15.8 | **211** |
| 20 (576) | 95 | **100** | **64** | 86 | **3** | 100 | 85 | **9.2** | **610** |
| 50 (1278) | 100 | **100** | **26** | 99 | **0** | 100 | 100 | **4.6** | **1651** |

(wr%, winT=승리 평균 처치 턴, extra%=추가공격 확률 — 100%=보장 +1타)

**읽는 법:**
- **DEX 는 처치 속도가 압도적** — 깊이 50 에서 winT **4.6턴** vs 나머지 19~53턴. DEX 가 4~10배 빠르게 죽인다.
- **DEX extra% 가 무제한 폭주** — 147 → 211 → 610 → **1651**. 깊이 50 DEX 는 한 턴에 **약 +16타**(extra% 1651 ÷ 100). 매 추가타가 크리·딜을 다시 굴리므로 곱연산.
- **DEX/LUK 는 회피 75% 캡 도달**(깊이 20+) — 거의 안 맞는다. 캡이라 과투자 손해도 없음(찍고 공격으로 전환).
- **VIT 붕괴**(64% → **26%**) — HP 는 최대치(d50 maxHp 5869)지만 atk 143·winT 44 로 너무 느려 DPS 경쟁 탈락. def 195 도 무용(아래 §2-3).
- **SPI 사망**(d50 **0%**) — 순수 오펜스 0. (SPI 부활 아크는 지원·대항 정체성이지 솔로 딜이 아니므로 이 표의 솔로 sim 에선 약한 게 의도. 별개 이슈.)

**라이브 실증**: `/admin` 밸런스 탭(#834) `statAxes[].dominantCount`(aggregate.ts:152·199) = 유저별 최고 스탯 집계. 메모리 실측 = 엔드 DEX 100·LUK 위주, STR51·INT33·VIT0.

## 2. 근본 원인 (4가지 — sim + 코드 추적)

### 2-1. 🔑 다중공격 무제한 곱연산 (최대 범인)
- `SPD_PER_DEX = 2.0`(derive:594) → `EXTRA_ATTACK_PCT_PER_SPD = 0.5`(derive:599) ⇒ **DEX 1점당 추가공격 +1%p**. DEX 100 = +100%(보장 1타), DEX 600 = +600%, DEX 1644(d50) = **extra% 1651**.
- 추가타마다 크리·데미지를 **새로 굴린다** → 다중공격은 다른 모든 딜 레버(크리·위력)와 **곱**으로 쌓인다. 선형 스탯(VIT HP·def)은 절대 못 따라옴.
- ⚠️ ATB 재설계가 `extraAttackChancePct=0` 으로 **ATB 경로에선 이 필드를 끔**([[project-v2-combat-atb-redesign]]). 그러나 라이브 사냥은 V2_HUNT_USE_STAMINA 와 무관하게 전투는 ATB — **즉 라이브 다중공격은 ATB 의 "행동 빈도"(속도 타임라인)로 이미 표현**된다. sim 은 레거시 다중공격 모델이라 extra% 로 보이지만, **라이브에선 같은 우위가 "DEX 가 더 자주 행동"으로 나타남**(ATB rate). 두 모델 다 DEX 속도가 곱연산 우위인 건 동일.

### 2-2. 회피 캡이 너무 싸다
- `EVA_PER_DEX 0.1 + EVA_PER_LUK 0.08`, 캡 `EVASION_PCT_CAP 75`(stats.ts). DEX/LUK 는 깊이 20 이전에 75% 도달 → **피격의 3/4 무효**. 캡이라 남는 DEX 는 손해 없이 SPD(템포)·명중으로.
- VIT/SPI 는 회피축이 없어 이 방어를 못 얻음 → "안 맞는 DEX vs 다 맞는 VIT".

### 2-3. damageBetween 가 엔드에서 방어를 지운다 (방어축 동반 붕괴)
- `damageBetween(atk, def) = max(1, atk×0.15, atk−def)`(combatShared:120, DAMAGE_FLOOR_FRACTION 0.15). 엔드는 atk≫def(d50 적 atk≫VIT def 195) → **atk−def 가 atk 에 수렴, def 기여 ≈ 0**.
- 이미 SPI 문서에서 같은 지적("고심도 atk≫def 압축 ×1.1·기존 def 무용화"). **VIT/SPI 의 방어가 엔드에서 작동 안 함** = 탱이 의미 없음 = 오로지 "빨리 죽이기" 경쟁 = DEX 독무대.

### 2-4. 템포 카운터 부재
- SPI critResist(cap 50)는 **LUK 크리만** 완화, DEX 속도·명중엔 무력. "한 턴 16타"를 벌하는 메커니즘이 없음 → DEX 는 나쁜 매치업이 0.

## 3. 왜 다이얼 튜닝이 실패했나 (구조적 통찰)

메모리 실측: **"DEX 는 단일/복합 스탯 다이얼로 제어 불가 — 6레버 전부 DEX 불변·필드만 죽임"**. 즉 CRIT_PER_LUK·EVA_PER_DEX 같은 **계수**를 깎으면 DEX 우위는 그대로고 약한 축(VIT/SPI/필드)만 더 죽는다. 이유: 독주의 본질이 **계수 크기**가 아니라 **곱연산 구조**(다중공격 × 크리 × 회피캡)다. ⇒ **계수가 아니라 구조(메커니즘)를 수술**해야 한다. #826 endgameSoften(d20+ 최대 15% 몹 약화)도 floor 만 살짝 올렸지 독주 미해결(=밴드에이드).

## 4. 정체성 (목표)

- DEX = **속도/연타·회피 = 빠른 글래스캐넌**, 단 "한 턴에 다 끝내는" 무제한 곱연산은 **천장**을 둔다.
- VIT/SPI = 엔드에서도 **방어가 실제로 작동**(damageBetween 수술) → "느리지만 버티는" 빌드가 성립.
- LUK = 버스트 크리(이미 winT 느림 = 템포는 DEX 가, 한방은 LUK 이 — 역할 분리는 비교적 건강).
- 목표 지표: **엔드(d50) 솔로 wr 가 축별 70~100% 밴드**(DEX 100 유지 OK, VIT/SPI 가 ≥60 으로 복귀)·**DEX winT 가 타축의 ½ 이내로 압축**(현재 ¼~⅒).

## 5. 재설계안 (택1 또는 조합)

### 옵션 A — 다중공격 수확체감 소프트캡 (🥇 1차 추천·최저위험·근본직격)
- `EXTRA_ATTACK_PCT_PER_SPD` 선형 → **로그 소프트캡**(ATB rate=log소프트캡·RATE_CAP260 선례 그대로). 예: 유효 추가타 = `softcap(spd, k)` 로 ~+3~4타 천장.
- 또는 라이브 ATB 기준으로는 **속도→행동빈도(rate)에 더 강한 소프트캡**(현 RATE_CAP260 을 더 조이거나 곡선 가파르게).
- **효과**: extra% 1651 → ~300~400(=+3~4타). DEX winT 4.6 → ~10~12(타축 ½ 수준). DEX 정체성(다연타·빠름) 유지하되 "16타 원턴킬" 차단.
- **위험 저**: 단일 다이얼(곡선)·DEX 만 직접 누름(다른 축 불변)·sim 으로 천장 보정. golden = 다중공격 굴림 분포 바뀌므로 sim 재캘리브 필요(골든은 시드 고정이라 스냅샷 갱신).

### 옵션 B — 추가타 위력 체감 (A 보완/대안)
- N 번째 추가타 위력 ×`r^(n-1)`(예 r=0.85). 다중공격 횟수는 유지하되 무한 스택 가치 차단.
- A 와 효과 유사(곱연산 완화)지만 "타수는 화려, 딜은 체감" — 연출 유지. A 와 병용 가능(타수 캡 + 위력 체감 약하게).

### 옵션 C — damageBetween 비율 감산 수술 (🥈 VIT/SPI 동시 부활·근본이나 고위험)
- `atk − def` 선형 → **비율 감산**: 예 `dmg = atk × atk/(atk + def×K)`(또는 atk × (1 − def/(def+atk))). def 가 엔드에서도 **%경감**을 유지 → VIT def·SPI magicDef 가 살아남.
- **효과**: VIT/SPI "느리지만 버티는" 빌드 성립 → DEX 독주의 분모(=방어 무용)를 제거. SPI 부활 아크의 미완(고심도 def 압축)도 동시 해결.
- **위험 고**: **전 전투 데미지 수식 변경** = PvE·PvP·골든 전부 영향. 반드시 별도 PR·sim 전수·골든 재베이스. K 다이얼 민감(과하면 탱 무적·약하면 무효). DAMAGE_FLOOR_FRACTION 0.15 와의 상호작용 점검.

### 옵션 D — 다중공격에 비용 동반 (구조 변형)
- 추가타마다 명중 페널티 누적(후속타 미스율↑) 또는 추가타는 위력의 일부만(타당 명중·크리 분산). DEX 가 "타수 vs 정확/한방" 트레이드오프를 지게.
- A/B 보다 복잡·체감 나쁠 수 있음(미스 연출). 후순위.

### 옵션 E — 엔드 템포 카운터 몹 (SPI 패턴 확장·보조)
- SPI 아크의 atkType/critPct 몹 태그 패턴처럼 "다단공격 취약 완화" 또는 "고빈도 공격자에 반격" 몹을 일부 엔드에 배치. 근본 아님(부분 카운터)·DEX 만 직접 못 누름. A/C 의 보조로만.

## 6. 권고 단계화

1. **PR-1 = 옵션 A(다중공격/속도 소프트캡)** 단독 — 최저위험·근본 1벡터 직격. sim 으로 DEX winT 가 타축 ½ 이내 들어오는 곡선 보정. 배포 후 `/admin` dominantCount·winrate 모니터.
2. **측정** — A 만으로 VIT/SPI floor 가 얼마나 회복되는지(damageBetween 미수술이면 방어축은 여전히 약할 것).
3. **PR-2 = 옵션 C(damageBetween 비율감산)** — A 측정 후, 방어축이 여전히 죽어 있으면 착수. 고위험이라 단독 PR·골든 재베이스·sim 전수·K 신중.
4. 필요 시 **B**(위력 체감)로 A 를 미세보정, **E**(카운터 몹)로 다양성.

## 7. 밸런스 가드
- **계수 튜닝 금지**(§3) — 구조 수술만. CRIT_PER_LUK 등 단일 계수 nerf 는 약축만 죽임.
- DEX 100% 유지는 **OK**(글래스캐넌 정체성) — 목표는 winT 압축(원턴킬 차단)·타축 floor 부양이지 DEX 말살 아님.
- 옵션 C 는 탱 무적화 금지(SPI sustain 게이트 교훈) — K 보정 시 솔로 무한버티기 sim 점검.
- 골든 byte-identity 불가 변경(A·C 둘 다 데미지 분포 변경) → 각 PR 골든 재베이스 + sim 재캘리브를 변경의 일부로 명시.
- ATB 라이브 기준 검증(sim 은 레거시 다중공격 모델) — A 는 라이브 ATB rate 소프트캡으로도 표현되는지 확인.
