# 장비 선택 판매 설계

## 목표

인벤토리 장비 탭에서 사용자가 원하는 개체만 여러 개 선택해 한 번에 판매할 수 있게 한다. 기존 품질 이하 판매와 미장착 전부 판매는 빠른 정리 수단으로 그대로 유지한다.

## 사용자 흐름

1. 장비 탭의 `선택 판매`를 누르면 해당 탭이 선택 모드로 바뀐다.
2. 장비 카드를 누르면 선택/해제가 전환된다. 페이지를 이동해도 같은 탭의 선택은 유지된다.
3. 장착 중이거나 잠긴 장비는 선택할 수 없다.
4. 하단 요약에서 선택 개수와 예상 골드를 확인하고 `선택 판매`를 누른다.
5. 최종 확인 후 판매 대금은 기존 장비 판매와 동일하게 은행에 들어간다.
6. 탭을 바꾸거나 취소를 누르면 선택 모드와 선택 목록을 초기화한다.

## 서버 규칙

- 클라이언트는 선택한 장비 개체 식별자(`iid`)만 전송한다.
- 서버는 트랜잭션 안에서 모든 `iid`가 중복 없이 존재하며 미장착·미잠금·판매 가능 상태인지 다시 검증한다.
- 요청 중 하나라도 조건을 만족하지 않으면 `409 selection_changed`로 전체 요청을 거절한다. 부분 판매는 하지 않는다.
- 한 요청은 최대 100개로 제한한다.
- 기존 슬롯/품질 기반 일괄 판매 요청과 선택 판매 요청을 섞을 수 없다.
- 판매 가격, 은행 입금, 경제 로그는 기존 판매 경로와 같은 계산과 저장 방식을 사용한다.

## UI 및 접근성

- 선택 모드의 카드 버튼은 `aria-pressed`로 선택 상태를 노출한다.
- 선택된 카드는 체크 표식과 강조 테두리를 표시한다.
- 장착·잠금 카드는 배경 투명도 대신 배지와 비활성 버튼으로 선택 불가를 알린다.
- 선택 요약 영역은 기존 불투명 카드 표면을 사용한다.

## 검증

- 순수 선택 계획 함수: 정상 선택, 장착/잠금/누락/중복 시 원자적 실패.
- API: 지정 장비만 판매, 상태 변경 시 409와 저장 없음, 잘못된 요청 거절.
- UI: 선택 모드, 선택 개수·예상 골드, 장착/잠금 선택 차단이 렌더링되는지 확인.
- 관련 테스트, 타입 검사, 린트, 프로덕션 빌드를 실행한다.
