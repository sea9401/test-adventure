## 1. 목표 & 핵심 원리

**"왜 계속 사냥하나"의 엔드 당근을 직업 시스템에 둔다.** 만렙(50) + 환생 루프 위에서, 끝없이
늘어나는 직업 트리를 **해금·정복하며 패시브 풀을 모으고**, SP 예산 안에서 빌드를 갈아끼우는 것이
장기 목표가 된다.

전제(오너): **직업은 계속 추가될 예정 — 결과적으로 수백 개**가 될 수 있다. 따라서 메타는
**수백 직업까지 깨지지 않아야** 한다.

### 🔑 왜 수백 직업까지 버티나 (파워 인플레 방지)
- **파워 상한 = SP 예산**(`calcSpBudget`, 소프트캡 `SP_MAX_SOFT_CAP=40`). 직업 500개를 거쳐
  패시브 500장을 배워도 **동시에 끼는 건 SP 예산만큼**. → 수집은 파워가 아니라 **빌드 선택지(폭)**.
- **내장 보너스 = 현재 직업 1개분**(`V2_JOB_CATALOG[job].jobBonus`). 직업은 하나뿐이라 상한 자동.
- 즉 직업 로스터 자체가 **무한 콘텐츠 트레드밀**: 새 직업 = 새 해금 목표 + 새 패시브 1장 +
  도감 1칸. 파워 폭증 없이 "다 모으고 내 빌드 완성"이 끝나지 않는다.

## 2. 이미 깔린 토대 (재사용 — 새로 안 만듦)

A 메타의 핵심 루프는 **상당 부분 이미 구현돼 있다.** 새 시스템이 아니라 그 위에 얹는다.

| 토대 | 현재 구현 | 위치 |
|---|---|---|
| **직업 정복 → SP** | 직업군 `cumLevel ≥ 250`(`SP_MASTERED_CUMLEVEL`) 정복 1회당 **+3 SP**(`SP_MASTERED_JOB_BONUS`). 환생 보존 → 여러 직업 정복 누적 | `coreLoopConfig.calcSpBudget` |
| **SP 점감 곡선** | cumLevel 45부터 첫 SP, 이후 간격 +25씩 widening(`SP_MILESTONE_*`). 점감 = 자연 상한 | `spMilestonesForCumLevel` |
| **SP 소프트캡** | `SP_MAX_SOFT_CAP=40`(단일직 ~7·broad 베테랑 ~32, 캡은 안전망) | `calcSpBudget` |
| **패시브 휴대·수집** | 학습한 패시브는 영구 보유, 직업 무관 SP 슬롯(오픈믹스) | [[project-v2-skill-loadout-redesign]] |
| **내장 보너스** | 현재 직업 1개분 플랫 스탯(방금 LIVE) | `derivePlayerCombatV2` FromSaves |
| **트리 차수 게이팅** | tier 전직 cumLevel 임계 `V2_ADVANCE_CUMLEVEL_REQ` | `proficiency` |
| **cumLevel 수급** | 킬당 `2 + floor(themeIndex/2)`, 환생 보존·단조 증가 | `proficiency` |

→ **이미 있는 루프**: 직업에 머물며 cumLevel 쌓기 → 250에서 정복(+SP) + 그 직업 패시브 수집 →
환생해서 다음 직업으로. **A 메타는 이 루프를 "수백 직업 장기 목표"로 완성하는 것.**

## 3. 무엇이 비었나 (수백 직업 관점)

1. **소프트캡(40) 이후 동기 공백.** +3/정복, 캡 40 → **~9~10직업 정복이면 SP 캡**. 그 뒤
   직업 #11~#500을 정복할 이유가 **사라진다**(SP는 더 안 늘어남). 수백 직업 엔드의 핵심 공백.
2. **수집 가시성 0.** "몇 직업 정복했는지 / 패시브 몇 장 모았는지" 보여주는 **도감/대시보드 없음**.
   완성형 수집 메타엔 진척 표시가 필수(보물·낚시 도감 패턴 재사용 가능).
3. **트리 성장 경로 미정.** tier 3+ 직업을 어떤 선행 조건(상위 직업 정복 등)으로 열지 — 직업을
   계속 추가하면 자동으로 새 장기 목표가 되도록 하는 규칙.

## 4. 설계 (토대 위에 얹기)

### 4.1 캡 이후 비파워 보상 — "수집 포인트" ✅ (오너 결정: 순수 비파워)
SP 캡(40)은 **유지**(파워 상한 = 메타 건전성의 핵심). 캡 이후의 정복은 **파워가 전혀 아닌 보상**으로
(수백 직업 창렬 방지 — 정복 보상이 파워면 붕괴):

- **수집 포인트(CP, collection point)** = **수집한 직업 패시브 수**(파생값 — 별도 저장 없음). SP 캡과
  무관. 직업을 거쳐가며 패시브를 모을수록 증가(원안 "정복 1회당 1"에서 구현 시 "수집한 패시브 수"로
  확정 — #804). "정복(직군 cumLevel 250 → +SP)"과 이름이 겹치지 않게 **수집 포인트**로 명명(#806).
- 수집 포인트의 용처 = **전부 비파워**:
  - **도감 완성도 / 칭호** — "N직업 정복", 직업 아이콘 컬렉션(순수 수집 욕구).
  - **환생 편의(QoL)** — 환생 시 시작 SP 슬롯 프리셋 저장 수↑, 재학습 골드 할인 등(파워 아님).
- ❌ **파워 보상 없음** — 정복으로 스탯·전투력이 오르지 않는다(오너 결정). 파워는 SP 캡까지가 끝.

### 4.2 트리 성장 — 직업 추가가 곧 콘텐츠
- 상위 tier 직업은 **선행 직업 정복(cumLevel 250) + 부모 cumLevel 임계**로 해금
  (현재 `V2_ADVANCE_CUMLEVEL_REQ` 확장). 직업을 추가할 때마다 새 해금 목표가 자동 생성.
- 수백 직업 = 여러 갈래의 깊은 트리. "이 갈래를 다 정복하면 다음 갈래/특수 직업 열림" 식
  게이팅으로 **방향성 있는 장기 여정**.

### 4.3 수집 대시보드 (도감)
- 캐릭터 메뉴에 **직업 도감**: 전체 직업 그리드 — 해금/정복/미해금 상태, 정복 직업 수,
  수집한 패시브 수, 수집 포인트. 보물·낚시 도감(`V2CodexView`·`TreasureCollectionView`) UI 패턴 재사용.
- "X / 전체 정복", "패시브 Y장 수집" 진척 바 = 완성형 수집 동기.

### 4.4 루프 요약 (엔드)
```
현재 직업에서 사냥 → cumLevel↑ → (250) 정복: +SP(캡까지) · 직군 정복 1칸 · tier3 해금
            패시브 학습 → 수집 포인트↑(= 모은 패시브 수) · 등급 칭호↑ · 도감 1칸
                                  ↓
                        환생(Lv1, cumLevel 보존) → 다음 미정복 직업
                                  ↓
        SP 캡 후엔 파워는 고정, 수집 포인트·도감·트리 해금이 장기 당근 (수백 직업까지)
```

## 5. 안티골 / 리스크
- **파워 인플레 금지** — 정복 보상이 무한 스탯이면 수백 직업서 붕괴. SP 캡 유지 + 캡 이후는
  비파워/강캡. (이미 토대가 이 방향.)
- **그라인드 피로** — 정복 임계(cumLevel 250)가 너무 높으면 수백 직업이 노역. 수집 포인트
  곡선·cumLevel 수급으로 "한 직업 정복 = 합리적 시간" 유지. 실측 다이얼.
- **선택지 마비** — 패시브 수백 장이면 빌드 짜기 부담. 도감 필터·추천 프리셋·로드아웃 저장으로 완화.

2. ✅ **SP 소프트캡(40) 유지** — 파워 상한(1번의 귀결).

**남은 결정(후속 — 구현 단계서):**
3. **정복 임계 cumLevel 250 유지?** — 수백 직업 노역 우려 시 하향 또는 "가벼운 1차 정복 + 깊은 완전
   정복" 2단 분리 검토.
4. **트리 성장 규칙** — tier 3+ 해금을 "선행 직업 정복"으로 게이팅할지, 단순 부모 cumLevel만 볼지.
