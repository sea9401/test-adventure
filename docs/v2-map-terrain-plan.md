# v2 대륙 지도 — 전략 지형 레이어 설계

> Codex 교차검증(2026-06-25) 반영본 — 후킹 지점을 실제 코드와 대조해 P0 3건 수정:
> ① 산맥 `blocksConquest` 제거(settleable=false로 충분) ② 요새터 수비 슬롯 보너스 보류(큐 용량
> 시스템 부재) ③ 교역로 세금 = 발생 단계 재분배(harvest 곱 금지·골드 보존). 상세는 각 절.
>
> 개정(2026-06-25): 지역별 드랍 차등(광맥/숲) 기각(드랍률은 지역 무관 유지) + **호수(lake)를
> 1차로 승격**(수공방어 채널) → 1차 지형 **6종 / 5 채널**. 재료 드랍 개편 머지 완료 → **P1 착수**
> (데이터 레이어 + 산맥·협곡·호수 통행/정착 게이트). 호수의 인접 방어보너스 효과는 P3.

## 0. 배경 / 목표

9×9 자유 타일 보드는 칸이 거의 균질해서 "어디에 정착하느냐"가 입지 싸움이 아니라
빈 칸 찾기에 가깝다. **지형(terrain)** 을 소수 손배치해 칸마다 가치를 차등화하고,
그게 곧 영토·전쟁 전략이 되게 한다.

제약 3가지(설계 전제):

1. **재료(나무/광물/식량) 드랍 개편 진행 중** → 지형은 *생산-무관* 채널에만 후킹한다:
   정복-인접 · 건강도(전쟁HP) · 수비/성벽 · 경제(세금/금고) · 명예. (세금/금고는 유지 확정.)
2. **이동 = 텔레포트** (`/me/move-tile` 가 목적지만 검증, 경로·인접 없음) → "장벽" 지형은
   *이동 차단*이 아니라 **정복 인접 그래프**로 표현한다. 도로/다리/관문이동/매복로처럼
   이동 경로를 다루는 지형은 이동 모델 개편이 필요해 **범위 밖**.
3. **확장성** → 미래에 "타일 던전"(진입형 콘텐츠 칸)을 같은 레이어에 끼울 수 있게,
   피처 모델을 *Passive(보정/차단)* + *Interactive(진입)* 두 부류로 처음부터 연다(§7).

terrain(지도 고정) ↔ trait(정착지 속성)은 **별개 책임**으로 둔다. 기존 `TerrainTrait`
(plain/farmland/mine/lake, settlement에 귀속)은 손대지 않고, 새 지형 레이어는 그 위에
보정/차단으로만 얹는다.

## 1. 핵심 모델 — `TILE_TERRAIN` 레이어

정적 데이터 한 장으로 시작한다(절차생성 X — 균형·기억가능성 위해 손배치 소수).

```ts
// tileConfig.ts (신규)
export type TileFeatureKind =
  | "mountain"      // 1차 — 정복-인접(벽)
  | "canyon"        // 1차 — 정복-인접(길목)
  | "lake"          // 1차 — 수공방어(통행 불가 + 인접 방어보너스)
  | "hotspring"     // 1차 — 건강도
  | "stronghold"    // 1차 — 수비/성벽
  | "trade_route"   // 1차 — 경제(세금)
  // 2차 웨이브: | "ruins" | "marsh" | "beacon"
  // 미래(진입형): | "dungeon"
  ;

export type TileFeature = {
  kind: TileFeatureKind;
  // 정착/소유 가능한 칸인가. false = 빈 칸이지만 found 불가(산맥·호수·던전).
  settleable: boolean;
  // 진입형 콘텐츠(미래 던전)의 진입 정의. 없으면 비-진입 지형(§7).
  interaction?: { kind: string; routeId: string; access: "neutral" | "owner" };
};

// 손배치 — 좌표 키 "col,row" → 피처. 미배치 칸은 평범한 빈 땅.
export const TILE_TERRAIN: Record<string, TileFeature> = { /* §3 */ };

// 헬퍼
export const tileFeatureAt = (col: number, row: number): TileFeature | null =>
  TILE_TERRAIN[tileKey(col, row)] ?? null;
```

- **settleable=false** → `move-tile`/`found` 라우트가 거부(산맥·호수·던전 위엔 못 섬).
  이게 사실상 산맥의 "벽" 효과 **전부**다 — 정복은 *직접 4-인접* 만 보고(경로 그래프 없음),
  산맥 칸은 소유 불가라 인접 사슬의 디딤돌이 될 수 없고, 산맥을 사이에 둔 두 칸은 어차피 거리 2라
  4-인접이 아니다. 따라서 **별도 `blocksConquest` 플래그·인접 차단 코드는 불필요**(Codex 확인).
- **interaction** → 미래 던전 확장점(§7). 지금은 타입에 자리만 두고 미사용.
- **stale 점령행 격리**: non-settleable 지형 칸엔 점령행이 생길 수 없으나, 혹시 모를 합성 점령행
  잔재와 충돌 안 나게 `isKnownOutpostId`/`synthTileOutpost` 경로에서 terrain 칸을 일관 제외한다
  (§8 미결 3 해소).

채널별 수치 보정은 피처 플래그와 분리해 **별도 레지스트리/헬퍼**로 둔다(밸런스 다이얼을
한곳에 모음). 예: `terrainVigorDiv(col,row)`, `terrainFortHpMult(...)`, `terrainTaxMult(...)`.

## 2. 1차 지형 6종 (5 채널) — 사양

각 지형: 효과 · 시작 수치 · 채널 · 후킹 · 밸런스 한 줄. **수치는 전부 한 줄 상수(다이얼)**.

### 2.1 산맥 `mountain` — 정복-인접
- **효과**: 정착·소유 불가. 정복 인접 사슬 차단(이 칸은 누구도 못 가지고, 이 칸을 통한 인접 인정 X).
- **수치**: 없음(구조적). 배치만이 다이얼.
- **후킹**: `settleable=false` 하나로 충분(소유 불가 → 정복 디딤돌 불가·산맥 사이 두 칸은 거리 2).
  별도 인접 차단 코드 불요(§4-①).
- **밸런스**: 너무 많으면 보드가 잘게 끊겨 초반 확장이 답답 → 줄당 3~4칸, 총 1~2줄.

### 2.2 협곡 `canyon` — 정복-인접
- **효과**: 산맥 벽에서 **유일하게 소유 가능한 칸**. 정복이 여길 통해서만 사슬을 연장 = 길목.
- **수치**: 없음(구조적). 옵션: 협곡 소유 시 인접 정복 명예 +10%(길목 가치 부여).
- **후킹**: `settleable=true` — 산맥 줄 한가운데 한 칸(소유 가능 = 유일한 디딤돌). **리베라 인접
  링(거리1) 회피**(§3 · land-less 길드 bootstrap 초크와 겹침 방지·Codex).
- **밸런스**: 협곡을 막으면 뒤가 안전 → 너무 강한 천연요새가 되지 않게 산맥 줄을 *완전 봉쇄가
  아니라 우회 가능*하게 배치(벽이 보드 끝까지 닿지 않게).

### 2.3 온천 `hotspring` — 건강도(전쟁HP)
- **효과**: 인접 4칸에 정착한 길드원의 **건강도(war vigor) 회복 가속**.
- **타일 자체**: `settleable=false` 아우라 타일(호수와 대칭). 온천 *위*엔 정착 못 하고 인접에 버프 —
  "온천에 정착했는데 보너스가 없다"는 혼란을 피하고 *인접 소유* 모델과 정확히 일치(P2 구현 결정).
  수혜 칸 = `HOTSPRING_BENEFIT_COORDS`(온천 4-인접 중 정착 가능 칸·산맥 등 settleable=false 이웃 제외).
- **수치**: 회복 시간 ×0.5(2배 가속). `WAR_VIGOR_FULL_RECOVERY_MS`(현재 7분) → 인접 시 3.5분.
- **수혜 귀속(확정)**: war vigor 는 per-player(character.v2)라, **온천 인접 칸을 보유한 길드의
  길드원**이 recover 할 때 가속(소유=영토 보상답고 구현 단순). 서 있는 위치가 아니라 *소유*가
  기준(Codex 권고).
- **후킹**: `warVigor.ts applyVigorRecovery` 시그니처에 보정 인자 추가 → recover 라우트가
  "수혜자 길드가 온천-인접 정착지 보유?"를 조회해 `fullRecoveryMs ÷ 2` 주입(§4-②).
- **밸런스**: "전선 옆 보급 명당". ÷2 가 과하면 ÷1.5 로.

### 2.4 요새터 `stronghold` — 수비/성벽
- **효과**: 이 칸 정착지의 `fortHp` 최대치 +15%.
- **수치**: `STRONGHOLD_FORT_HP_MULT = 1.15`.
- **후킹**: fortHp 최대 계산(`outpostSiege.ts FORT_*` / 점령행 fortMaxHp)(§4-③).
- **밸런스**: 후반 난공불락 고착 방지 → 보수적 시작. 생산 페널티는 재료 개편 후라 미부여.
- ⚠️ **수비 큐 슬롯 +1 보류**: 현재 `outpost/defend` 라우트에 큐 용량(cap) 개념 자체가 없음
  (Codex 확인). 슬롯 보너스를 주려면 기본 cap·초과 처리·stale row 정리·UI 를 전부 새로 만들어야
  해 지형 perk 치고 과대. **defender capacity 시스템이 생기면 그때 추가.**

### 2.5 교역로 `trade_route` — 경제(세금)
- **효과**: 이 칸 정착지의 영주 세금 수입 +15%. 단, 약탈당할 때 금고 탈취량 +10%(양날).
- **수치**: `TRADE_ROUTE_TAX_MULT = 1.15`, `TRADE_ROUTE_RAID_LOSS_MULT = 1.10`.
- **후킹**: 영주 세금 *발생(accrual)* 지점 + 약탈 금고 탈취(`RAID_TREASURY_STEAL_FRAC`)(§4-④).
- ⚠️ **골드 보존 규칙(필수·Codex)**: +15%는 **활동에서 떼는 세금을 키우는 재분배**여야 한다
  (납세자=사냥꾼이 더 내고 금고가 더 받음). **harvest(금고→영주 지급) 단계에 곱하면 이미 쌓인
  금고에서 새 골드를 찍는 인플레가 되므로 금지.** 실제 세금 발생 지점(예: `dungeon/hunt`
  goldTaxed)에 맞춰 "어디서 +15%인지"를 구현 전 확정.
- **밸런스**: "잘 벌지만 잘 털림" — 분쟁 유발 명당. 리베라 근접 배치 시 초반 snowball.

### 2.6 호수 `lake` — 수공(水攻) 방어
- **효과**: 통행/정착 불가(물). + 인접 4칸 정착지는 약탈·정복당할 때 **공격자 페널티**(방어 명당).
- **수치**: `LAKE_ATTACKER_PENALTY = 0.10`(인접 정착지 공격 시 공성·약탈 효율 −10%). 시작 보수적.
- **후킹**: 공성 데미지(`outpostSiege.ts siegeDamage`)·약탈 금고 탈취에 "방어 측이 호수-인접 보유?"
  조회 후 ×(1−페널티). 호수 자체는 settleable=false 라 못 가짐 — *인접* 보너스(산맥과 대칭).
- **밸런스**: 천연 해자 — 너무 강하면 −10%→−5%.
- ⚠️ **P1 범위**: 통행/정착 불가(settleable=false)만 우선 적용(산맥과 동일 경로). 인접 방어보너스
  후킹은 **P3**(공성/약탈 라우트 손볼 때).

> 채널 분포: 정복-인접 ×2(벽+길목), 건강도 ×1, 수비 ×1, 경제 ×1, 수공방어 ×1 = **5 채널 / 6 종**.
> 각 채널 1~2개만 건드려 밸런스 다이얼이 작고, 전부 기존(혹은 최근 추가) 시스템 위에 얹힌다.

## 3. 배치 (9×9, col/row 0–8, 중앙 4,4 = 리베라)

원칙:
- 산맥 1~2줄(연결 3~4칸) + 줄당 협곡 1칸. **보드 끝까지 닿지 않게** = 우회로 보존.
- 명당(온천·요새터·교역로)은 사분면에 분산. **리베라 인접(거리 1) 회피** = 중앙 snowball 방지.
- 명당끼리도 뭉치지 않게(겹 보너스 입지 방지).

⚠️ **리베라 인접 링 회피**: land-less 길드는 리베라(4,4) 인접 4칸 `(3,4)(5,4)(4,3)(4,5)`에서
정복을 시작한다. 특수 타일(특히 협곡)을 이 링에 두면 bootstrap 초크와 겹쳐 시작 메타를
왜곡한다(Codex). 아래 레이아웃은 그 링을 비워둔다.

예시 레이아웃(좌표는 플레이테스트로 조정):

```
col→  0   1   2   3   4   5   6   7   8
row0  .   .   .   .   .   .   ▲   .   .
row1  .   ♨   ⛰   .   .   .   ▲   .   .
row2  .   .   ⛰   .   .   .   ⛂   .   .     ▲⛰ 산맥  ⛂ 협곡  ≈ 호수
row3  .   .   ⛰   .   .   .   ▲   .   .     ♨ 온천    ✦ 교역로
row4  .   .   ⛂   .   ◉   .   .   .   ⚒     ◉ 리베라(중립)  ⚒ 요새터
row5  .   .   ⛰   .   .   .   .   .   .
row6  .   ✦   .   .   .   .   ≈   ≈   .
row7  .   .   .   .   .   .   .   ⚒   .
row8  .   .   .   .   .   .   .   .   .
```
- 좌측 산맥 줄(col2, row1–3·5)이 협곡 `(2,4)`로만 뚫림 → 좌측 구역 진입 통제. `(2,4)`는
  리베라에서 거리 2라 인접 링과 무겹침.
- 우측 산맥 줄(col6, row0·1·3)이 협곡 `(6,2)`로만 뚫림 → 우상단 구역 분리. `(6,2)`도 거리 4.
- 우하단 소형 호수 `(6,6)(7,6)` = 통행/정착 불가(물). 인접 정착지 방어보너스(P3)·호수 자체는
  못 가짐. 리베라에서 거리 2·3 → 인접 링과 무겹침.
- 온천 `(1,1)` = settleable=false 아우라 타일(통행 불가·P2 실배치). 인접 정착 가능 3칸
  `(1,0)(0,1)(1,2)`이 수혜 zone(산맥 (2,1) 이웃은 소유 불가라 제외). 리베라에서 거리 3 → 인접 링 무겹침.
- 명당 — 교역로 `(1,6)`·요새터 `(8,4)`·`(7,7)` — 사분면 분산, 인접 링 비움(P3).
- 산맥 줄은 보드 끝까지 안 닿게(우회로 보존) → 완전 봉쇄 아닌 우회 가능(BFS 연결성 테스트로 가드).

(개수·정확 좌표는 §6 다이얼. 9×9=81칸 중 특수 ~14칸 = 17% 정도가 무난. **현재 실배치 = 산맥 7 +
협곡 2 + 호수 2 + 온천 1 = 12칸**, 나머지 명당(요새터/교역로)은 P3.)

## 4. 후킹 지점 (구현)

전부 **"현재값 × 지형보정"** 형태라 기존 코드 비침습. 생산(나무/광물/식량) 코드는 무접촉.

- **① 정복-인접** — 정복 발판(foothold) 게이트 `src/lib/server/tileWarfareGates.ts`
  `guildTileFoothold`(+ `areTilesAdjacent4`). 산맥은 소유 불가(`settleable=false`)라 발판도
  타겟도 못 됨 → **추가 인접 차단 코드 불요**(Codex 확인). `found`/`move-tile` 은
  `settleable=false` 거부.
- **② 건강도** — `warVigor.ts applyVigorRecovery`(순수 헬퍼·인자 추가) + `me/war-vigor/recover`
  라우트가 "수혜자 길드의 온천-인접 정착지 보유" 조회 후 `fullRecoveryMs ÷ 2` 주입.
- **③ 수비/성벽** — fortHp 최대 계산(`outpostSiege.ts FORT_*` / 점령행 fortMaxHp). `stronghold`면
  fortHp max ×1.15. **(슬롯 보너스는 §2.4대로 보류 — 큐 용량 시스템 부재.)**
- **④ 경제-세금** — 영주 세금 *발생* 지점 + 약탈 금고 탈취(`RAID_TREASURY_STEAL_FRAC`).
  `trade_route`면 세금 발생 ×1.15(harvest 지급엔 곱 금지 — §2.5 보존), 약탈 탈취 ×1.10.
- **⑤ 수공방어(호수)** — 인접 4칸 정착지 공격 시 공성/약탈 효율 ×(1−`LAKE_ATTACKER_PENALTY`).
  `found`/`move-tile` 은 `settleable=false` 거부(P1·산맥과 동일 경로). 방어보너스 후킹은 P3.

각 후킹은 좌표→피처 조회(`tileFeatureAt`) 한 번 + 다이얼 곱 한 번. 생산 코드는 무접촉.
**P1 은 ①(settleable 거부)만 구현** — ②~⑤ 수치 후킹은 P2/P3.

## 5. 시각화

- 보드 타일을 지형별 색/아이콘으로 구분. **통행 불가(산맥/호수/던전)** 는 명확히 다르게.
- ⚠️ **마커 충돌(Codex)**: 현재 `TileMap.tsx`는 칸 중앙 단일 아이콘 구조라 지형 아이콘과
  소유자 마커가 거의 확정적으로 겹친다. 구현 전 **렌더 레이어 분리** —
  (a) 배경 지형 레이어: 산맥=칸 전체 패턴/색, 명당=배경 아이콘 +
  (b) 그 위 소유자 마커 레이어: 소형·모서리/테두리 배치로 배경을 안 가림.
- 정착 가능한 명당(온천·요새터·교역로·협곡)은 **배경 지형 아이콘 + 소유 시 소유자색 테두리**.
- 호버/탭 시 지형 효과 툴팁(예: "온천 — 인접 정착지 건강도 회복 2배").
- 전투 로그/수확 결과에 지형 보정을 *명시*(체감 약화 방지 — 특히 교역로 약탈손실+).

## 7. 미래 확장 — 타일 던전 (자리 예약)

"타일 하나에 던전" = **진입형(Interactive) 피처**. 같은 `TILE_TERRAIN` 레이어에 `dungeon`
kind만 추가하면 끼게 미리 연다.

- 피처: `settleable=false`(정착 불가) + `interaction: { kind: "dungeon", routeId, access }`
  (§1 모델). `interactive?: boolean` 단순 플래그 대신 **객체**로 둔 이유(Codex) = 던전마다 진입
  라우트(routeId)·접근 정책(access)이 다를 수 있어 확장 여지를 미리 연다.
- 동작: 그 칸을 방문/클릭하면 `interaction.routeId`(가칭 `/me/enter-tile-dungeon`)로 → 기존
  사냥터/던전 시스템 재사용 또는 신규 "필드 던전". 보상 = (개편된)드랍 재료 · 골드 · EXP ·
  발굴 조각 등.
- `access`(미결): `neutral`=누구나 진입(단순·우선) vs `owner`=소유 길드만/소유 시 +%.
- 지금은 **타입·자리만** 두고 미구현. move/visit 라우트에 `tileFeatureAt(...).interaction` 예약
  분기만 남긴다 → 미래 던전은 "kind 추가 + 라우트 1개"로 끝(새 시스템 아님).

이 한 가지 결정(피처를 Passive/Interactive로 모델링) 덕에 던전은 새 시스템이 아니라
"지형 kind 하나 추가"가 된다.

## 8. 롤아웃 순서 / 미결

**순서**
- **재료 드랍 개편 머지 후 착수** — 생산 코드 무접촉이라 충돌 면은 작지만, 정착지 의미가
  바뀌는 시점과 정합 위해 그 뒤.
- PR 슬라이스(Codex 판정 — 산맥/협곡 즉시 착수, 나머지는 후킹 검증 후 별도):
  - **P1 — 데이터 레이어(`TILE_TERRAIN`/타입/헬퍼) + 산맥·협곡·호수(통행/정착 불가) + settle/move
    거부.** 후킹이 `settleable` 하나라 의존성 최소 = 가장 먼저. (호수 방어보너스는 P3.) ← **머지 완료(#1154)**
  - **P2 — 온천(건강도).** 온천 (1,1) = settleable=false 아우라 타일(호수와 대칭) + `HOTSPRING_BENEFIT_COORDS`
    (인접 정착 가능 칸) + `applyVigorRecovery` 분모 인자 주입 + recover/heal 라우트가 길드의 온천-인접
    정착지 소유를 `guildHasHotspringAdjacency`(IN 조회)로 판정해 회복 ÷2. ← **구현 완료(this PR)**
  - P3 — 요새터(fortHp만) · 교역로(세금 발생 ×, 보존 규칙 확정 후) · 호수 방어보너스
    (`LAKE_ATTACKER_PENALTY` — 공성/약탈 라우트).
  - P4 — 시각 폴리시(렌더 레이어 분리·툴팁·로그 표기).
  - 던전 타일 = 별도 에픽(§7 자리 예약).

**미결 / 리스크** (✅=문서에서 확정, ⬜=구현 시점 결정)
1. ✅ **온천 수혜 귀속** — "온천-인접 칸 보유 길드의 길드원"으로 확정(§2.3).
2. ✅ **stale 점령행 격리** — terrain 칸을 `isKnownOutpostId`/`synthTileOutpost`에서 일관 제외(§1).
3. ⬜ **정복 인접 차단 부작용** — 산맥이 보드를 과도하게 끊어 길드가 영구 고립되지 않게 배치
   검증(우회로 보존). 경로 그래프 없으니 손검토로 충분.
4. ⬜ **교역로 골드 보존** — 세금 +15%의 정확한 발생 지점을 실제 세금 라우트에 맞춰 확정(§2.5·
   harvest 곱 금지).
5. ⬜ **요새터 고착** — fortHp ×1.15가 난공불락 만들지 모니터(보수적 시작). 슬롯 보너스 보류.
6. ⬜ **양날 효과 체감** — 교역로 약탈손실+ 등 전투/수확 로그 표기.
7. ⬜ **던전 ↔ 점령/이동** — access 중립 개방 vs 소유 게이트(§7).

**Codex 판정**: 5종 세트·후킹은 구현 가능. 단 P0 3건(blocksConquest 제거 / 요새터 슬롯 보류 /
교역로 보존)을 문서에서 먼저 확정해야 코드 재작업이 없다 — **본 개정본에서 모두 반영**.
