# v2 PoB식 아이템·스킬 아이디어 뱅크

**작성일**: 2026-07-06  
**상태**: 아이디어 뱅크 초안  
**목적**: `pob.cool`/Path of Building 계열 빌드 플래너의 장점을 참고해, v2 장비·스킬·유니크·프리셋 아이디어를 한곳에 모은다. 실제 구현은 기존 v2 데이터 모델(`v2Equipment`, `v2Skills`, 직업 패시브, 세트/시그니처 효과)을 우선한다.

## 1. 참조한 PoB식 핵심

PoB에서 그대로 가져올 것은 아이템명이나 스킬 내용이 아니라 **빌드 사고방식**이다.

| PoB식 기능 | v2에 맞춘 해석 | 구현 후보 |
|---|---|---|
| 공격/방어 계산 요약 | 이 장비·스킬을 끼면 무엇이 얼마나 바뀌는지 즉시 보임 | 장비 비교 카드, 스킬 장착 미리보기 |
| 상세 계산 breakdown | 전투력이 왜 올랐는지 출처별로 분해 | `훈련 / 직업 / 장비 / 패시브 / 세트 / 버프` breakdown |
| 스킬·버프 토글 | 조건부 버프를 켜고 꺼 보며 빌드 확인 | 전투 패턴/로드아웃 프리셋의 조건 토글 |
| 유니크 DB + 롤 선택 | 고유 아이템을 수집 대상이자 빌드 퍼즐로 취급 | 유니크 도감 + 예상 roll range + 시그니처 효과 |
| rare item template | 완벽한 실물 없이도 목표 장비를 가정 | "목표 장비" 슬롯별 템플릿 |
| share code | 빌드를 외부 공유 가능한 단위로 압축 | 로드아웃 프리셋 export/import |

## 2. v2 빌드 축

아이디어는 아래 10개 축 중 최소 1개를 강화해야 한다. 축이 없는 아이템/스킬은 수치만 다른 중복템이 되기 쉽다.

| 축 | 핵심 재미 | 현재 연결점 |
|---|---|---|
| STR 물리 강타 | 높은 단발 피해, 방깎, 처형 | 전사/검계 스킬, 대검 |
| DEX 관통·연타 | 다단, 명중, 방어 관통 | 궁수/도적 일부, 활/단검 |
| VIT 탱딜 | 체력·방어가 피해로 전환 | 방패/무도가/가디언 계열 |
| SPD 행동경제 | 더 자주 행동, 선제권, 회피 후 가속 | ATB, 경갑/신발 |
| LUK 치명·독 | 치명, 독 스택, 처형 | 자객/독술 계열 |
| INT 마법 | 마법 공격, 마법취약, 원소 상성 | 지팡이/마법사 계열 |
| SPI 지원·대항 | 회복, 마법 방어, 치명 대항 | 사제/정신 축 |
| 저체력 | 위험할수록 강해짐 | 광전/혈성기사 |
| 상태 스택 | 독/출혈/마법취약을 쌓고 터뜨림 | `stackPayoffDamage` |
| 세트·시그니처 | 장비 2피스/단품으로 빌드 규칙 변경 | `setTags`, signature unique plan |

## 3. 아이템 아이디어

### 3.1 단품 유니크

| 이름 | 슬롯 | 축 | 효과 아이디어 | 구현 난이도 |
|---|---|---|---|---|
| 깨진 결의의 왕관 | necklace | 저체력/SPI | HP 35% 이하일 때 받피감, 대신 회복량 일부 감소 | 중 |
| 사슬 끊는 장갑 | gloves | DEX/관통 | 3번째 타격마다 방어 일부 무시 | 중 |
| 밤물결 단검 | weapon/dagger | LUK/독 | 치명 시 낮은 확률로 독 1스택 추가 | 중 |
| 침묵한 별의 지팡이 | weapon/staff | INT/마법취약 | 마법취약이 있는 적에게 마법 피해 증가 | 하 |
| 역풍의 발목끈 | boots | SPD/회피 | 회피 성공 시 다음 행동 대기시간 감소 | 중 |
| 묵직한 성문갑 | armor/heavy | VIT/탱딜 | 방어력 일부가 공격력 또는 스킬 피해에 반영 | 하 |
| 붉은 맹세 반지 | ring | 저체력/치명 | HP를 잃을수록 치명 피해 증가 | 하 |
| 늪주술사의 목걸이 | necklace | 독/SPI | 독 피해를 입힌 뒤 소량 회복 | 중 |
| 거울비늘 갑옷 | armor/light | 마법 대항 | 마법 피해를 받으면 1회성 마법 방어 버프 | 중 |
| 무명 검사의 낡은 검 | weapon/greatsword | STR/정밀 | 치명은 낮지만 최소 피해 보정, 안정형 물리 | 하 |

### 3.2 세트 아이디어

| 세트 | 구성 | 축 | 2피스 효과 | 목적 |
|---|---|---|---|---|
| 순례자의 성물 | armor + necklace | SPI/버팀 | 낮은 HP에서 받피감 또는 회복 강화 | 협동 보스·장기전 |
| 독왕의 그림자 | gloves + boots | LUK/SPD/독 | 회피 또는 치명 시 독 스택 가속 | 독술 빌드 완성 |
| 검은 결투가 | weapon + ring | STR/치명 | 단일 적 상대 피해 증가 | 1:1 아레나 |
| 폭풍 사냥꾼 | bow + boots | DEX/SPD | 다단 스킬의 첫 타 명중 보정 | 활 빌드 안정화 |
| 비전 서약 | staff + necklace | INT/마법취약 | 마법취약 스택 상한 또는 효율 증가 | 마법 빌드 엔드 목표 |
| 불굴의 철신 | armor + gloves | VIT/반격 | 피격 시 낮은 확률 반격 | 탱커도 전투가 움직이게 |

### 3.3 제작/템플릿 아이디어

PoB의 rare template처럼 "완성품을 직접 주는 것"보다, 목표 장비를 상상하고 좇게 만드는 쪽이 좋다.

| 템플릿 | 슬롯 | 기본 옵션 | 랜덤 옵션 후보 |
|---|---|---|---|
| 결투용 무기 | weapon | power 높음 | crit, critMult, accuracy, pierce |
| 생존용 갑옷 | armor | hp/def | magicDef, damageTakenReduction, healPower |
| 기동용 신발 | boots | spd/eva | crit, accuracy, magicDef |
| 주문용 목걸이 | necklace | mp/magicDef | magicVuln, healPower, crit |
| 독술 장갑 | gloves | crit/eva | poisonStack, spd, luk scaling |

## 5. 빌드 프리셋 아이디어

아이디어 뱅크는 개별 아이템보다 "이걸 끼면 어떤 빌드를 만들 수 있나"까지 같이 보관해야 한다.

| 프리셋 | 핵심 장비 | 핵심 스킬 | 강점 | 약점 |
|---|---|---|---|---|
| 독왕 질주 | 밤물결 단검, 독왕의 그림자 | 독성 폭발, 그림자 도약 | 긴 전투에서 스택 폭발 | 독 면역/짧은 전투 |
| 성물 탱커 | 순례자의 성물, 성문갑 | 기도문, 방패 가격 | 장기전 안정 | 처치 속도 낮음 |
| 비전 파쇄 | 침묵한 별의 지팡이, 비전 서약 | 비전 각인, 원소 균열 | 마법취약 폭발 | MP 의존 |
| 결투 검성 | 무명 검사의 낡은 검, 검은 결투가 | 사슬 관통, 반격 자세 | 1:1 안정딜 | 광역/다수전 약함 |
| 역풍 궁수 | 폭풍 사냥꾼, 역풍의 발목끈 | 역류, 사슬 관통 | 선제권·명중 안정 | 튼튼한 적에게 장기화 |
| 혈성기사 | 붉은 맹세 반지, 깨진 결의의 왕관 | 피의 서약, 기도문 | 위기 상황 폭발력 | 회복 차단에 취약 |

## 6. 구현 후보 우선순위

### P0 — 지금 데이터 모델로 가능한 것

1. 변칙 옵션 단품 유니크 추가: 기존 `options` 조합만으로 처리.
2. 세트 2피스 보너스 추가: 기존 `setTags`/세트 집계 재사용.
3. 도감에 유니크 빌드 태그 표시: `독`, `저체력`, `마법취약`, `회피` 같은 검색 축.
4. 장비 비교 카드에 "변화량 요약" 강화: 공격/방어/MP/치명/회피 등.

### P1 — 작은 엔진 훅이 필요한 것

1. on-crit 독 부여.
2. on-dodge 속도 증가/회복.
3. HP 조건부 받피감.
4. N타마다 추가타.
5. 독/마법취약 스택 payoff 스킬 확장.

### P2 — 빌드 플래너화

1. 장비·스킬 목표 템플릿 저장.
2. 프리셋 export/import.
3. 조건 토글: 적 속성, 낮은 HP, 버프 활성, 독 스택 수.
4. 계산 breakdown 탭.
5. "이 장비를 끼면 어떤 스킬이 좋아지는지" 역추천.

## 7. 채택 기준

아이디어를 실제 구현 후보로 올릴 때는 아래를 통과해야 한다.

1. **빌드 축이 명확한가**: STR/DEX/VIT/SPD/LUK/INT/SPI 또는 상태 스택/저체력/세트 축 중 하나 이상.
2. **현재 전투 엔진에 붙일 위치가 보이는가**: derive, playerPhase, pvpPhase, 상태효과, 세트 집계 중 어디인지.
3. **카운터가 있는가**: 모든 상황에서 최고면 폐기 또는 수치 하향.
4. **도감에서 설명 가능한가**: 한 문장으로 플레이어가 이해하지 못하면 복잡한 효과다.
5. **시뮬레이션이 가능한가**: 최소 2개 상대군(일반 사냥/협동 보스 또는 PvP)에서 비교 가능해야 한다.

## 9. 참고

- `pob.cool`은 브라우저 앱이라 텍스트 수집이 제한적이었다. 구체 기능 참조는 공개 Path of Building Community README의 기능 목록을 기준으로 삼았다.
- PoB/Path of Exile의 고유 콘텐츠, 아이템명, 스킬명, 수치 체계는 복제하지 않는다. 이 문서는 v2 시스템에 맞춘 독립 아이디어 뱅크다.
