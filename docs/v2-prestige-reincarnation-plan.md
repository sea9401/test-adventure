# v2 환생(Prestige) 재설계 플랜

2026-06-05 설계 세션 합의. "환생 같은 재전직으로 유저가 무한히 성장하는 구조"를
기존 cumLevel→floor 시스템 위에 얹는다. 코드 베이스 = `feat/jobspec-integrated`
(4직군·12계파, 전투엔진 `src/adventure/v2/combat/`).

---

## 0. 목표

- 만렙(Lv100) 도달이 끝이 아니라, **제자리 환생으로 다시 1차부터 올라가며 영구 누적
  성장(cumLevel)** 을 쌓는 루프.
- 직군 정체성(특화)이 환생 너머로 보존·심화되는 prestige 손맛.
- 익스플로잇(싼 저차수 farming)·파워 폭주 없이 자연스럽게 페이싱.

## 1. 현행 토대 (이미 깔려 있는 것)

- **floor(저점)** = `base + 전역항 + 직군항`
  - 전역항 = `totalCumLevel × V2_FLOOR_GLOBAL(0.015)` — 전 스탯 공통.
  - 직군항 = `groupCumLevel × V2_FLOOR_PER_PROF(0.05) × tierMult × weight`.
- **cap = floor 상대** — `effectiveStatCap = floor + V2_CAP_HEADROOM_BASE(45) + 수행이득`.
  floor 가 올라도 cap 이 항상 그 위 → **성장 밴드(45+수행)가 보존**된다.
  → 이것이 환생 루프의 핵심 토대: cumLevel 무한 누적 시 floor·cap 이 같이 올라가
  밴드가 안 깨진다.
- **cumLevel** — 레벨업당 +1, 전직/환생 리셋 불변(영구). 현재 단일 직군 자연 천장 ~250-300
  (레벨캡·차수 유한 때문, "runaway 해소"의 정체).
- **4직군 앵커** — warrior→str / martial→vit / mage→int / rogue→dex.

## 2. spi/luk floor 수정 ✅ (구현 완료, commit e9f10bd3)

- 문제: 옛 앵커-이진 floor 가중(1.0/0.4)이 `mage{int:2,spi:2}` 의 spi·`rogue{dex:2,luk:2}`
  의 luk 을 값2임에도 0.4 로 홀대 → cap(수행, 값 비례)과 모순 + 직군 floor 예산 불균형
  (mage/rogue 1.4 vs warrior/martial 1.8).
- 해결: floor 가중을 **프로필 값 비례**(최댓값 스탯=1.0, 나머지 값 비율)로 통일.
  spi/luk 이 마법사/도적에서 1.0 동급, 전 직군 예산 **2.0 평준화**. 12계파의 사제(spi)·
  자객/독사(luk) 정체성 빌드가 핵심 스탯 floor 를 제대로 받는다.
- floor 는 cumLevel 에서 매번 계산 → save 마이그 불필요.
- 사후: `sim-v2-progression` 재캘리브 권장(값-1 스탯 0.4→0.5, spi/luk 가산으로 미세 상향).

## 3. 환생 루프 구조 (제자리 4차 환생)

### 3.1 차수별 레벨 캡 + 진행 게이트
- 레벨 캡: **1차 50 / 2차 65 / 3차 80 / 4차 100**.
- 각 차수 만렙 도달해야 다음 차수 전직(advance) 가능. 4차 만렙(Lv100)에서만 환생.
- (현행 `V2_ADVANCE_MIN_LEVEL`·`V2_ADVANCE_CUMLEVEL_REQ` 게이트는 레벨캡으로 일원화 검토.)

### 3.2 design A — 직업 변경 = 4차 정점 전용 ✅ 결정
자유 respec(골드0·쿨다운0) **폐기**. 대신 4차 Lv100 에서만 진행 선택:

| 메뉴 | 효과 |
|---|---|
| **종환생** | 같은 직군, 1차 Lv1 복귀, cumLevel 보존 → 같은 직군 cumLevel 무한 누적(특화 심화) |
| **횡환생** | 다른 직군으로(레벨 1 리셋·totalCumLevel 보존). 처음 직군=1차부터 / 과거 만렙 직군=**도달 차수로 복귀**(②A: 차수만 복귀, 레벨은 Lv1부터 재성장) |
| **계파 재선택** | 신전 초기화(specChoice 비우기) 재사용 → 매 루프 계파 변경(빌드 실험 출구) |

**근거**: 4차 미만 respec 불가 →
- 싼 저차수(1차 Lv1→50) cumLevel farming 루프가 **구조적으로 불가능**(4차 풀등반 강제).
- 도달차수 복귀(②A)는 허용하되 4차 정점에서만 → mid-climb snap-back 악용 **불가**(레벨 Lv1 재성장이 throttle, 횡환생이 종환생보다 cumLevel 비효율).
- 빌드 실험 욕구는 환생 3메뉴(종/횡/계파재선택)가 흡수.

### 3.3 환생 시 리셋 / 보존
- **리셋**: 레벨 1, grownStats, active tier→1 → 시그니처(16)·직업특성(12)·키트픽 게이트
  전부 해제(tier 1 = 0픽·특성 inert). 재등반하며 ×1→×2→×3 으로 다시 자람.
- **floor도 현재 차수 tierMult 따름 (①B 결정)** — 환생 시 tier→1 이라 floor 직군항이
  ~33%(tierMult 1.5→1.0) 일시 dip 후 재등반하며 회복. 단 grown 리셋(상한=헤드룸+수행, ~100+)이
  지배적이라 dip(~25)은 부차적, **A안(도달차수 유지)과 4차에서 완전 수렴**. 코드 변경 0(현 floor
  함수가 이미 `g.tier` 사용).
- **보존**: cumLevel(영구), points(숙달), caps(수행이득). floor는 cumLevel·현 차수로 매번 계산.
- 12계파 권능이 차수 게이트라 design A 의 "스킬 잠금"과 자연 정합 — 환생 = 권능 리셋 후
  재구축. **키트픽은 계파별로 기억 → 재등반/부캐 복귀 시 차수 한도만큼 자동 복원 (③A 결정,
  무료 해금이라 마찰 0).**

## 4. 루프 가속 차단 — 불필요 (스태미나가 이미 governor) ✅ 결정

- 수입은 **스태미나 상한**: `HUNT_COST=1`, `MAX_STAMINA=1500`, 30초당 1 회복
  = 120/h ≈ **2880/day**. 처치당 EXP = 몹 고정 exp × XP_RATE × 밴드 → **파워가 올라도
  같은 사냥터 수입 불변.**
- → 루프는 개인 파워로 가속하지 않는다. 옛 아이디어(EXP 요구치에 cumLevel 배수=k)는
  수입 천장 상태에서 비용만 키워 **"끝없이 자라는 벽"** 부작용 → **폐기**.
- 한 루프 비용 = **18.5M EXP 고정**(1→50→65→80→100, Lv100 만렙이 안 변하므로 영구 고정).
  내역: 1차 0.89M / 2차 2.0M / 3차 4.57M / 4차 11.03M.

## 5. 성장감 = 콘텐츠 졸업 (상위 사냥터 사다리)

felt-growth 는 시간을 일정하게 잡아서가 아니라 **위 사냥터로 올라갈 때** 나온다.

- 루프마다 floor↑ → 더 높은 exp/스태미나 사냥터 진입 → 루프가 **38일 → … → 수시간**으로
  계단식 단축. (루프 일수 ≈ `1,150 / (사냥터 몹 평균 exp)`.)
- **무한 확장**: 신규 사냥터마다 exp↑. 붕괴(루프 분 단위화) 방지 규칙:
  **사냥터마다 exp 와 몹 스탯(hp/atk/def)을 한 쌍으로 floor 구간에 묶어 공식 산출.**
  exp 높은 사냥터는 floor 도 그만큼 높아야 진입 → exp 인플레가 난이도 인플레와 상쇄.
- **페이싱 governor = 콘텐츠 파워 게이트**(exp/스태미나 아님). 초반=exp 게이트(루프가 그라인드),
  엔드=파워 게이트(사냥터 정복이 그라인드). 자연스러운 난이도 곡선.
- **핵심 다이얼 = "사냥터당 N루프"** = (다음 사냥터 요구 floor) ÷ (루프당 floor 증가량).
  예: 루프당 cumLevel +~290 → 앵커 floor +~26. "신규 사냥터당 ~5루프" 목표면 사냥터 간
  몹 스탯 갭을 floor +~130 으로.
- 레벨(1→100)은 고티어에서 형식화됨 — **받아들인다**(이층 구조: 레벨=초중반 페이싱,
  cumLevel/floor/사냥터=장기 진행). 레벨까지 영구 빡세게 = 트레드밀=벽 느낌이라 비추천.
- ⚠️ **선결 과제**: 현 라이브 최상위 = 깊은산 exp~30(루프 ~38일), floor 3~8 휴면.
  올라갈 칸이 비어 있어 환생 루프 전에 **상위 사냥터 사다리부터** 채워야 함
  (메모리 "만렙 콘텐츠 공백" 직결).

### 5.1 페이싱 결정 (2026-06-05)
- **K(사냥터당 루프) = 2** — 게이트 간격 ≈ (power/루프 ~20)×2 = 40. 환생이 핵심 활동,
  새 사냥터는 마일스톤(환생 ~2회마다). "재전직 중심·안 길게" 반영.
- **루프 시간 = 프론티어(최상위 사냥터) 기준 ~5일** — 첫 등반/저티어는 더뎌도 OK(온보딩).
  exp ~×6 상향(XP_RATE 4→~24 또는 몹exp ×6) 다이얼. (5일 기준 처치당 유효exp ≈ 1,285)
- **exp 곡선 = 램프 후 플래토** — 저티어 낮은 exp(느림) → 상위로 갈수록↑ → 프론티어에서
  ~5일로 수렴·유지. 무한 가속(분 단위 붕괴) 방지 위해 상단 캡. felt-growth는 "새 몹·더 큰
  숫자·새 사냥터"가 담당(프론티어 루프 시간은 일정).
- ⚠️ 사냥터별 정확한 exp는 사다리(§7 제너레이터) 정의 후 `sim-v2-exp-pacing`로 프론티어
  =5일이 나오게 역산.

## 6. 게임감 결정 — 전부 확정 (2026-06-05)

- **① 환생 시 floor = B (현재 차수 tierMult)** — dip 후 재등반 회복, 4차서 A안과 수렴, 코드 0. → §3.3
- **② 부캐 복귀 = A (도달 차수 복귀, 레벨 Lv1 재성장)** — 제한 불필요(재레벨이 throttle). → §3.2
- **③ 키트픽 = A (계파별 기억·자동 복원)** — 재픽 마찰 제거. → §3.3

## 7. 남은 미결 (수치/콘텐츠 — 다음)

1. ✅ **단일 무한 프론티어 (백엔드 구현)** — 고정 8층 → 깊이(depth) 1→∞ 단일 프론티어로 통합.
   깊이 1=들판·2=깊은산(authored)·3+=프론티어(깊은산 풀 재사용 플레이스홀더), 제너레이터
   (`dungeonLadder`)가 무한 깊이 스탯/exp/추천파워 산출. **수동 푸시**=`character.v2.frontierDepth`
   (최고 도달, 구세이브 기본 2). hunt가 깊이 1~frontierDepth+1만 허용, +1 승리 시 해금. tsc0·
   1204테·Codex SHIP. ⚠️계수 전부 임시.
   **남은 것**: (a) **UI** — state에 frontierDepth 표면화 + 프론티어 깊이 선택 뷰(Codex 위임 후보).
   (b) sim 캘리브(`sim-v2-exp-pacing` 프론티어=5일·`sim-v2-progression` 난이도/spi-luk).
   (c) 콘텐츠 — 깊이 밴드별 테마 몹 세트·재료 드랍(현 빈 풀)·아트(선택, 내 페이스).
2. **(캘리브 전 손볼 것) power 지표 spd 가중** — SPD 死축인데 power 공식에 들어가 도적 게이트 부풀림.
3. **(선택) 하드 power 게이트** — 현재 소프트(난이도)만. 깊이 게이트는 수동 푸시(frontierDepth)가
   이미 함 → 별 이슈 없음. 옛 "들판 50 vs 신캐 43" 온보딩 얽힘은 권장치(소프트)라 무관.

## 8. 구현 베이스 / 작업량

- 베이스 = `feat/jobspec-integrated`(전투엔진 `v2/combat/` 이전됨).
- 환생 액션 = `advance-class` 라우트에 "tier 유지 + 레벨/grown 리셋" 분기 추가
  + 계파 재선택은 기존 신전 초기화(specChoice 비우기) 재사용.
- floor 는 이미 cumLevel 기반이라 스탯 측 추가 작업 적음. 주 작업은 환생 게이트/UI 와
  상위 사냥터 사다리(§5 선결 과제).
