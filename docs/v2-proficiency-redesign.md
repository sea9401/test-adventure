# v2 숙련도(직업 마스터리) 재설계

2026-06-01 사용자 결정. **수동 스탯 찍기 + 레벨/골드 전직**의 어색함을 풀고, **직업을 플레이로 마스터하며 영구 성장하는 루프**로 전환. 레벨·EXP·콘텐츠는 유지하되 그 위 **성장/전직 메커니즘만** 갈아엎는다.

선행: v2 전투 재설계(docs/v2-combat-redesign.md, PR-1~10 + MP-throttle #269 + 교관폐지 #270 머지 완료). 이 문서는 그 위의 **성장축 재설계**.

---

## 1. 핵심 루프

```
직업 플레이(사냥/전투) → 숙련도 적립
   ├ 사용 가능 숙련도 → 수행(스탯 cap↑) · 시그니처 학습
   └ 누적 숙련도 → 스탯 저점(floor)↑ · 전직 게이트 · 콘텐츠 게이트
전직(누적 숙련도 충족) → 레벨 1 리셋 + 스탯 floor부터 재시작 + 다음 차수
   → 더 높은 차수 = 더 높은 floor (prestige 루프)
```

플레이로 버는 영구 마스터리(누적 숙련도)가 진척의 중심. 돈/쿨다운 없음.

## 2. 레벨링 — 랜덤 성장 (cap 제한)

- **레벨 유지.** 레벨업마다 **6스탯이 랜덤 상승** — 직업 앵커 가중(현 직업 주력 스탯이 더 자주/크게). cap 에서 멈춤((c)).
- 각 스탯: **floor ≤ current ≤ cap.** 랜덤 성장은 **cap 까지만**. 시작 cap §10, cap 은 **수행으로만**.
- **HP/MP** — 레벨업 상승폭이 **현재 vit/int 에 비례**((a)): `HP += rand(1, ceil(vit × HP_GROWTH_K))`, `MP += rand(1, ceil(int × MP_GROWTH_K))`. vit/int 높을수록 레벨당 HP/MP 더 크게 → 체술/마술 투자가 자연스럽게 체력/마력으로.
  - HP/MP **floor** 도 vit/int floor 파생: `hpFloor = base + vitFloor × HP_PER_VIT` 식. 체술/마술 숙련↑ → vit/int floor↑ → HP/MP floor 동반↑.
- **모든 전직마다 레벨 1 리셋** + current 스탯 → **floor 로 리셋**(floor 는 숙련도로 높아져 있어 base 아님).

## 3. 숙련도 — 총 / 직업 분리, 적립 동시

전투(킬/승리) 1회 → 현재 직업군 1곳이 적립되고, **총 숙련도와 그 직업 숙련도가 같이** 오른다.

- **직업 숙련도** (직업군별) — `groups[group] = { earned, spent }`. 그 직업군으로 플레이할 때만 오름.
  - **직업 누적**(earned) → 그 직업군 **전직 게이트** + 그 직업 프로필 스탯 **floor**.
  - **직업 사용가능**(earned − spent) → **수행**(현 직업 cap↑) + **그 직업 시그니처 학습**.
- **총 숙련도**(누적) = Σ 모든 직업 earned (= 전체 플레이 합, 별 저장 없이 합산). 안 줄어듦.
  - 용도: **모든 스탯의 일반 floor 베이스**(직업군 바꿔 새 직업 숙련도 0이어도 base 까지 안 떨어지게 — (d) 의 핵심).
- **콘텐츠 게이트**는 숙련도가 아니라 **derive 스탯-파워**((b), §8) — 숙련도와 무관.

저장: `proficiency.v2 = { groups: { [group]: { earned: number, spent: number } } }`. 총 = Σ earned (파생).

> (d) 재전직(직업군 변경): 새 직업군 earned 0 부터. 단 총 숙련도(=과거 직업들 earned 합)는 유지 → 일반 floor 가 받쳐줌. 직업별 floor 는 각 직업 earned 가 따로 기여(여러 직업 마스터 시 여러 스탯 floor↑).

## 4. 수행 (修行) — 스탯 cap(헤드룸) 상승

- **사용 가능 숙련도**를 소모해 **현재 직업 프로필 스탯들의 cap** 상승.
- 직군별 상승치 다름 — **앵커 +2 / 관련 2스탯 +1**씩 (검사 수행: 힘 cap +2 · 민첩 +1 · 행운 +1).
- **cap 은 floor 상대(헤드룸)** — 유효 cap = `floor + V2_CAP_HEADROOM_BASE(45) + 수행이득`. fresh(floor=base15)→60. floor 가 높아져도 cap 이 항상 그 위라 **floor>cap 핀(수행 시 스탯 즉시 점프) 구조적 불가**. 수행은 헤드룸만 늘리고, 실제 스탯은 레벨업 랜덤성장이 floor→cap 사이를 채운다.
- **비용 = 올린 cap 헤드룸 총합 비례**(횟수 비례 아님): `cost = round(8 + 전스탯cap이득합 × 1.5)`.
- **크리티컬 수행** — 1회 비용에 낮은 확률 다중: 1.5% ×5 / +8% ×3 (`V2_CULT_CRIT_TABLE`).

> (수행개편 후속, 2026-06) 점프 버그 수정 + 프로필 3→2 + 가격 cap비례 + 크리. caps 저장 의미가
> "절대 cap"→"수행 이득(헤드룸 추가분)"으로 바뀜 — 배포 전 캐릭의 기존 수행분은 리셋(staging).

## 5. 스탯 저점 (floor) — 영구 진척

두 갈래 합산 — **총 숙련도(일반 베이스, 전 스탯 조금씩)** + **직업 숙련도(그 직업 프로필 스탯, 차수 가중)**.

`floor(stat) = V2_BASE_STATS[stat] + 총숙련도 × FLOOR_GLOBAL + Σ_group ( earned[group] × FLOOR_PER_PROF × tierMult[group] × profileWeight[group][stat] )`

- `FLOOR_GLOBAL = 0.004` (전 스탯 공통 — 과거 직업들 합이 새 직업 재시작 바닥을 받침, (d)).
- `FLOOR_PER_PROF = 0.02`, `tierMult = {1:1, 2:1.5, 3:2, 4:3}`(그 직업군 **도달 최고 차수**), profileWeight 앵커 1.0·관련 0.4.
- 전직/재전직 시 current → floor. **레벨 1이어도 floor 가 높아 강함.**

예: 궁술 earned 2,000·tier3(×2) → 민첩 floor += 2000×0.02×2×1.0 = **+80**, 행운 += +32. 추가로 총숙련도 5,000이면 전 스탯 += 5000×0.004 = **+20** 베이스.

## 6. 스킬 — 숙련도로 학습 (자동부여 폐지)

- #270 의 "시그니처 자동부여" → **사용 가능 숙련도로 학습**(교관은 계속 없음, 숙련도가 화폐).
- 각 차수 시그니처 = **그 차수 도달 + 숙련도 비용** 지불 시 습득. (잠정 비용 §10)
- 학습은 영구. 재전직해도 보유 시그니처는 유지(직업군 바뀌면 못 쓰지만 기록).
- ensureV2ClassSkills 폐기 → 학습 라우트(숙련도 소모) 신설.
- **장착은 수동(2026-06 복귀)** — 자동장착 폐지. 학습한 시그니처를 equip-skill 라우트로 직접 슬롯에 장착. 슬롯 수 = `v2SkillSlotsForLevel(level)`(33렙당+1, 3~6 — 레벨 리셋되면 줄어듦). reconcile 은 PRUNE 만(체인 밖/미학습/슬롯초과 제거), 자동 추가 안 함. **장착한 스킬만 전투 발동**.
- **MP 버스트** — 시그니처는 차수별 MP(12~24, throttle) 소모. MP 는 **전투마다 풀충전**(전투중 회복 없음). 물리(저 maxMp)는 전투당 몇 회 버스트 후 평타. (옛 지속-MP 모델은 1전투 후 영구 고갈→발동 불가였음, 2026-06 수정.)

## 7. 전직 — 누적 숙련도 게이트

- **누적 숙련도 임계**(직업군 earned) 충족 → 전직 해금. **골드 X · 레벨 X · 쿨다운 X.**
- 전직 실행 = 다음 차수 + **레벨 1 리셋** + current→floor.
- 차수별 임계 §10. (1→2→3→4)
- **3·4차는 모험의 서(재료 도감 등재 종 수, #267) 게이트 병존** — 레벨/골드가 아닌 별개 의도 요건이라 유지(설계 §11-8). 숙련도 임계 + 도감 둘 다 충족해야 전직.
- (PR-6 #279) advance-class 게이트를 레벨+골드 → 누적 숙련도로 교체. UI(V2CharacterScreen 전직 카드)도 동반 패치. advanceGoldCost 는 미사용 잔존(차후 청소).

## 8. 콘텐츠 게이트 — 레벨 → 누적 숙련도/파워 (사용자 (A))

- 던전 층 등 **레벨 지표 → derive 스탯-파워 지표**((b) 확정). 레벨 리셋과 충돌 없음(파워는 floor 로 영구 진척).
- 층 요건 `requirement.kind: "level"` → `"power"`. 파워 지표 = `derivePowerScore`(power.ts): `atk + magicAtk + def + maxHp×0.1 + spd×0.5 + maxMp×0.1`(가중치 잠정, PR-9 다이얼).
- (PR-7 #280) **하드 게이트가 아니라 권장 지표** — v2 던전은 원래 레벨 하드락이 없었고(난이도는 몹 강도로 자율 조정), 표시만 "권장 레벨" → "권장 파워". state 가 `combat.power` surface, 층은 provisional min(F1=50/F2=100/F3=180/F4=320/F5=520, PR-9 캘리브). 6~8층 endgame 은 그대로.

## 10. 수치 (PR-9 캘리브 — scripts/sim-v2-proficiency.ts)

- 숙련도 적립: **+2/킬** (누적·사용가능 동시 +2).
- 수행: 앵커 +3 / 관련 +1, cost `8×1.12ⁿ`.
- floor: `누적 × FLOOR_PER_PROF × tierMult × profileWeight`. **PR-9: FLOOR_PER_PROF 0.02→0.01, tierMult {1.5,2,3}→{1.15,1.3,1.5}**.
- 전직 누적 임계: **t2=300 · t3=1,200 · t4=3,000** (직업군 누적 = 킬 150/600/1500).
- 시그니처 학습 비용: **t1=80 · t2=150 · t3=250 · t4=400** (사용 가능).
- 시작 cap: 전 스탯 **60** (base15 → 레벨업 랜덤으로 60까지, 이후 수행 필요).
- 콘텐츠 권장 파워(F1~5): **50 / 110 / 160 / 175 / 220** (PR-9: 옛 50/100/180/320/520 → 측정 곡선 기준 하향).
- EXP: 현 곡선 **×2~3 + 저밴드 가속**. 리셋 루프 보상 — 이미 staging `XP_RATE_MULT=2.2` + 레벨밴드 가속으로 충족(별도 곱 불필요).

### PR-9 sim 진단 (scripts/sim-v2-proficiency.ts)

커리어 경제(킬→earned→학습/수행→전직→리셋) 모델로 6직업 측정. 두 가지 캘리브:

1. **floor > cap 구조 버그 해소** — earned 는 선형(3000까지)인데 cap 은 수행 지수비용(1.12ⁿ)에 throttle → 옛 계수(0.02·tierMult3)에서 4차 floor(207) > cap(141) → 수행이 무의미했다. 계수 하향으로 floor 가 cap 의 ~30~50% 에 머묾(4차 floor 72 < cap 141): 저점<천장 + grown(레벨)이 메우는 여지 회복.
2. **권장 파워 현실화** — 각 차수 6직업 최소 성숙파워(스타터 장비, 전 스탯 cap)는 1차163/2차166/3차175/4차181 인데 옛 임계(320/520)가 과도. 임계를 그 최소 곡선 바로 아래로 정렬(50/110/160/175/220) → 해당 차수 캐릭이 매칭 층을 클리어, sim 경고 0.
   - **한계(향후)**: ① 장비 progression 미모델(스타터만) — 실제 캐릭은 더 높음. ② 파워식이 SPI/탱 빌드 저평가(magicDef 미반영) — 신술이 최약(4차 181 vs 궁술 311). 곡선이 고차에서 압축됨(3→4차 weak class 175→181). 절대치·파워식 class-fairness 정밀화는 라이브 실측 후.

> 전투 WR 캘리브는 sim-v2-progression(별 스크립트) 소관 — 그쪽은 옛 수동분배 모델이라 새 성장(랜덤+cap+floor) 반영 재작업이 향후 과제.
