**작성일**: 2026-06-15 · **개정**: 2026-06-16 · **상태**: 설계 확정(구현 0)  
**연동**: [ATB 재설계](v2-combat-atb-redesign.md) · 엔드 장비/사냥터 재구상

---

## 1. 배경과 목표

현재 시스템은 레벨 슬롯(`v2SkillSlotsForLevel`, 3~6개)으로 장착 스킬 수를 제한한다. 직업 계파 게이팅으로 타 직군 스킬을 배우기 어렵고, 성장 체감이 단조롭다.

**목표**:
- 레벨 슬롯 → **스킬포인트(SP) 예산**으로 전환. SP = 장착 용량(로드아웃 예산), 스킬마다 SP 코스트 부여.
- 여러 직업을 돌며 스킬을 수집하는 **라이브러리 축적 재미** 부여.
- SP는 직업군 숙달 마일스톤에서 **이산적 보상**으로 지급 — "스킬포인트 획득!" 순간이 성장 체감.
- 시그니처만 직업 고정(정체성 닻). 일반 스킬은 배운 것이면 직군 제한 없이 장착 가능.
- 카탈로그 구조는 **직업군 수에 관계없이 확장 가능** — 4개 고정 가정 없음.

## 2. 핵심 용어 정의

| 용어 | 설명 |
|---|---|
| **스킬포인트(SP)** | 로드아웃 장착 용량. 인게임 표기 "스킬포인트 N/총량" |
| SP 예산 (SP budget) | 플레이어가 현재 보유한 총 SP |
| SP 코스트 (SP cost) | 스킬 1종 장착에 소비되는 SP |
| SP 유효 로드아웃 (SP-valid loadout) | 장착 스킬의 SP 코스트 합 ≤ SP 예산인 상태 |
| 스킬 라이브러리 | 한 캐릭터가 환생 순회로 배운 스킬 전체 컬렉션 |
| 마일스톤 | 직업군 cumLevel이 일정 구간을 넘을 때 발화하는 보상 이벤트 |

## 3. SP 획득 — 직업군 마일스톤 모델

### 3-1. 설계 원칙

- SP는 **직업군별 cumLevel 마일스톤**에서 지급된다.
- `proficiency.groups[groupId].cumLevel`이 임계값을 넘을 때마다 **+1 SP** 알림 발화.
- 총 SP = **SP_BASE + Σ 직업군(해당 군의 마일스톤 달성 수) + SP_MASTERED_JOB_BONUS × 숙달 직업군 수**, 소프트캡 적용.
- 직업군이 늘어나면 SP 기여 경로도 자연스럽게 늘어난다 — 4개 고정 아님.
- **🔑 마일스톤 간격은 점감(widening)** — cumLevel이 깊어질수록 다음 SP까지 간격이 넓어진다.
  flat 간격(N마다 +1)은 선형 무한증가라 베테랑이 결국 전 카탈로그를 장착(제약 붕괴)한다.
  점감 곡선은 천장이 굳어 "전부 장착"이 영영 불가능해진다.

### 3-2. 점감 마일스톤 곡선 (등차 임계)

n번째 SP까지 필요한 cumLevel 간격이 `SP_MILESTONE_WIDEN`씩 벌어진다:

- n번째 SP 간격 = `BASE + (n-1)·WIDEN` → 누적 임계 `T(n) = BASE·n + WIDEN·n(n-1)/2`.
- 역(`spMilestonesForCumLevel`): `T(n) ≤ cum`인 최대 n = 근의공식 닫힌형(루프 불필요).
- 기본값(a45 d25)의 단일 직업군 임계 cumLevel:

| SP 개수 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 누적 cumLevel | 45 | 115 | 210 | 330 | 475 | 645 | 840 | 1060 |
| 간격 | 45 | 70 | 95 | 120 | 145 | 170 | 195 | 220 |

새 시스템 한 루프(Lv1→50) ≈ 49 cumLevel 기준: SP1≈1루프, SP3≈4루프, SP5≈10루프, SP7≈17루프.

### 3-3. 상수 (모두 튜닝 다이얼)

| 상수 | 기본값 | 설명 |
|---|---|---|
| `SP_BASE` | 12 | 캐릭터 기본 SP |
| `SP_MILESTONE_BASE` | 45 | 첫 SP까지 cumLevel(≈ 한 루프) |
| `SP_MILESTONE_WIDEN` | 25 | 다음 SP마다 간격이 +이만큼 벌어짐(점감 강도) |
| `SP_MASTERED_JOB_BONUS` | 3 | 직업군 숙달(최고 차수) 시 추가 SP |
| `SP_MASTERED_TIER` | 4 | 숙달 기준 차수 |
| `SP_MAX_SOFT_CAP` | 40 | 절대 천장(점감상 broad 베테랑 ~32라 안전망) |

> **⚠️ 숙달 보너스 = 차수 기반이라 코어루프에서 거의 휴면(미결).** 코어루프 환생은
> `flattenGroupTiers`로 **모든 직업군 tier→1 정규화**한다(advance-class). 그래서 `tier>=4` 기준
> 숙달 보너스는 *현 직업군이 4차에 도달했고 아직 환생 안 한 순간*에만 +3, 환생 직후 0으로 빠진다
> (PR-3 자동장착이 환생 직후 예산을 정직하게 반영). 즉 **cumLevel은 보존되지만 tier는 매 환생
> 리셋**이라, 숙달 보너스가 "여러 정복 직업군 누적"으로 쌓이지 않는다. PR-1 RDS 분석의 +9(3정복)은
> *레거시 tier 데이터* 기준이라 코어루프 실제와 다름. **후속 결정 후보**: 숙달 기준을 tier(휴면) →
> cumLevel(영속, 예: cumLevel≥291=1환생 완주)로 바꿀지. 안 바꾸면 예산 ≈ base + 점감 마일스톤.

### 3-3b. 운영 실측 보정 (2026-06-16, prod RDS 10인)

- **1환생 ≈ 291 cumLevel** — 현행 라이브 차수캡(50+65+80+100) 한 바퀴. p50가 전 직업군 289~291에 군집.
- 베테랑 분포: 단일직 만렙 cum~287, top 베테랑 cum 1062(4직업·3정복).
- **flat 45 vs 점감 a45 d25 (실측 적용):** top 베테랑 43 SP(≈12스킬) → **32 SP(≈9스킬)**. 카탈로그 장착 가능
  60종 중 ~38%만 닿아 제약 영구 유지. 신참은 양쪽 다 첫 SP까지 ~1루프(온보딩 동일), 차이는 꼬리만 굽음.
- cumLevel은 flip 후 보존 → 마이그레이션 불필요. (간격은 새 시스템 루프 길이 49에 맞춰 BASE=45 유지.)

### 3-4. UX — 이산적 성장 체감

- 직업군 cumLevel이 마일스톤(45, 115, 210, …)을 넘을 때 **인게임 알림** 발화:
  "전사 숙련도 마일스톤 달성 — 스킬포인트 +1 획득!"
- 전광판/피드 불필요. 본인 알림만.
- 직업군 이름이 알림에 포함되어 "어떤 직업을 깊이 팠느냐"와 "얼마나 많은 직업을 순회했느냐" 둘 다 보상.

## 4. 스킬 수집 — 라이브러리 축적

- 스킬 배우기 = **마스터리 포인트(숙달포인트) 소비 → 영구 언락**. 한 번 배운 스킬은 캐릭터 라이브러리에 영원히 남는다.
- 환생해도 라이브러리는 초기화되지 않는다. 다른 직업군으로 환생하면 그 군의 스킬을 새로 배울 수 있다.
- 스킬을 배웠다고 자동 장착되지 않는다 — SP 예산 내에서 선택 장착.

### 4-1. 직업군 카탈로그 구조 (확장형)

```
skills/
  [groupId]/         ← 직업군별 폴더. 새 직업군 추가 = 새 폴더 추가
    active.ts        ← 액티브 스킬 목록
    passive.ts       ← 패시브 스킬 목록
    signature.ts     ← 시그니처(직업 고정 캡스톤)
  shared/
    active.ts        ← 공용 액티브
    passive.ts       ← 공용 패시브
```

새 직업군 추가 = 새 `[groupId]/` 폴더 추가. 기존 코드 수정 최소.

## 5. SP 코스트 체계 (루브릭)

| 등급 | SP 코스트 | 예시 |
|---|---|---|
| 기본 (Basic) | 1 | 단순 패시브(+DEF%, +HP%) |
| 표준 (Standard) | 2 | 대부분의 액티브 스킬, 중급 패시브 |
| 강력 (Strong) | 3 | 강화 액티브, 시너지 패시브 |
| 시그니처 (Signature) | 4 | 직업 고정 캡스톤 — 직업군 게이팅 유지 |

코스트는 다이얼이며 밸런스 시뮬 후 조정. 시그니처는 직업군 게이팅이라 해당 직업군을 환생으로 숙달해야 장착 가능.

## 6. 직업 믹스 정책

### 6-1. 기본 정책: 오픈 믹스

- 라이브러리에 있는 스킬은 **어느 직업군 것이든 장착 가능**. 오프-잡 SP 할증 없음.
- **기회비용 = SP 예산**. 강한 스킬은 SP 코스트가 높으므로 믹스하면 전체 스킬 수가 줄어든다.
- 플레이어가 직업을 많이 순회할수록 선택지가 넓어지고, 독특한 조합이 가능해진다.

### 6-2. 시그니처 — 직업 정체성 닻

- 시그니처 스킬(SP 코스트 4)은 해당 직업군 숙달 상태에서만 장착 가능.
- 시그니처를 여럿 끼우면 SP가 빠르게 소진 → 자연스러운 정체성 집중.

### 6-3. 탈출구 (Escape Hatch)

시뮬레이션에서 **정체성 붕괴(identity collapse)** 가 관찰될 경우에만: 타 직업군 스킬에 +1 SP 할증 추가. 지금은 적용하지 않는다. 심 캘리브 후 결정.

### 6-4. 확장성 원칙

- 직업군 수를 4개로 가정한 상수/if-else 금지.
- SP 계산, 카탈로그 로드, 마일스톤 체크 모두 `Object.values(proficiency.groups)` 순회로 구현.
- 새 직업군은 카탈로그 폴더 + proficiency.groups 엔트리 추가만으로 플러그인.

## 8. ATB 통합 노트

스킬 지속시간은 현재 "턴(turn)" 기준. ATB 전환 후 **틱(tick)** 기준으로 변환 필요.

- ATB Phase 3("스킬 지속시간 tick 전환")는 **이 SP 로드아웃 시스템 구현(PR-1~4) 이후** 진행.
- 스킬 발동 = 액터의 행동 1회 소비 (ATB 타임라인의 1 액션).
- 스킬 코스트(SP)와 ATB 발동 비용(행동)은 별개 레이어.
